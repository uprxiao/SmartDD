# M6：页面与 AI 配置体验优化

日期：2026-10-16

所属阶段：一期（Mac Desktop），接续 M5 与 v0.0.3 试用反馈

范围：F14 页面与细节优化、F15 AI 工具检测与配置优化，两项均为必做项

状态：正式接入、本机验收及 v0.0.4 预发布完成；四个构建目标、七个安装包下载核验及下载后 Mac arm64 回归通过，详见实施与验收记录

产品要求以 [PRD §13](SmartDD_V0.2_PRD.md#13-一期-m6页面与-ai-配置体验优化) 为准。用户已审阅独立原型，并于 2026-10-16 授权在现有 `feature/0.0.1` 正式接入、测试后提交 GitHub 并打 tag。本轮保留中央真实终端，使用 [独立原型](../prototypes/m6-codex/README.md) 的布局与样式接现有业务。数据库和 SSH 按用户明确范围验收页面、保存、重开及错误反馈，不以真实服务器连通作为本轮门槛。

实现和测试结果见 [M6 实施与验收记录](M6_实施与验收记录.md)、[正式应用视觉检查](../design-qa.md)；[Codex 界面对标](design/m6/Codex界面对标.md) 和 [原型 QA](../prototypes/m6-codex/design-qa.md) 保留前期设计依据。原型示例与正式 App 的真实数据分别管理。

## 1. 目标与现状

用户已下载安装 v0.0.3，并反馈基本使用可行。M6 解决两项明确的体验问题：

| 需求 | v0.0.3 试用反馈 | M6 交付行为 |
| --- | --- | --- |
| F14 页面与细节优化 | 试用版本界面主要参考 Yoda；用户要求按 Codex 实际界面复刻 | 布局、视觉与微交互按 Codex 实际截图还原，功能使用 SmartDD 自己的 |
| F15 AI 工具检测与配置优化 | 自动检测可显示 Codex，但结果未直接衔接到 AI 配置列表；新建配置默认 Claude Code，需手动配置 | 用户从检测结果方便地添加 Codex 或 Claude Code 配置，随后能在新建任务中选用并提问 |

F15 已接入 `src/renderer/views/settings/ai-profiles.tsx`：检测结果旁可添加基础配置或打开已有配置；`src/shared/detected-profile.ts` 负责选择已有配置和创建最小输入。沿用现有检测及保存服务，不复制或覆盖本机 CLI 凭据。

## 2. F14 的页面范围与设计要求

| 页面／区域 | 本阶段交付范围 |
| --- | --- |
| 应用框架与侧栏 | 窄应用导航、项目／任务列表、选中与悬停状态；移除“空间”，保留“定时任务”时钟入口及规划占位样式 |
| 首页／新建任务 | 中央欢迎区、底部输入框、上层项目／本机环境栏、下层操作及 AI 配置选择，按用户截图布局 |
| 任务页 | 标签栏、任务信息、停止／恢复、状态栏及终端外层布局；保留原生 CLI 终端内容和颜色 |
| 项目与资源页 | 保留概览、代码目录、数据库、服务器、Skill 与 MCP、项目任务六项；项目别名／规则、多目录、数据库及 SSH 完整配置字段、测试／删除／归档操作按统一样式整理 |
| 设置与 AI 配置 | 窄应用导航＋设置分类栏＋内容区，不保留额外项目侧栏；搜索、分组卡片、控件、工具检测和配置流程与 F15 一起设计 |
| 细节操作 | 项目行悬停出现更多／新建按钮、项目详情浮层、任务右键与更多菜单；位置、分隔线、圆角、关闭方式和焦点行为一起核对 |
| 共用组件 | 图标、文字、间距、留白、边框、圆角、按钮、输入框、下拉、对话框、提示和错误状态 |

执行要求：

1. 按用户当前使用的 Codex 实际布局与 UI 复刻，不能只交付“相似的简洁风格”。留存版本、日期、截图与页面对应关系；用户截图优先于安装包静态样式推断。
2. Codex 有直接对应的页面按其图标、布局和细节对标；数据库、服务器等 SmartDD 专属区域采用同一套规则适配。保留已确认的 SmartDD Logo 与现有业务入口。
3. 浅色／深色主题、中英文、800px 窄窗口及长名称均纳入检查。需要截断的文本应可查看全文，主要操作始终可达，键盘焦点可见。
4. 沿用当前 Electron、React、终端和组件基础；已有适用实现优先复用，需要时参考本地 `../yoda` 的模块实现并保留来源说明。
5. 任务的中央工作区已确认保留终端；首页欢迎及输入区需复刻，但启动后不引入聊天消息、工具卡片或结构化输出接入。
6. 菜单操作使用 SmartDD 的重命名、归档／取消归档；2026-10-16 用户追加确认移除会话删除，运行中先“结束并归档”确认，归档可搜索、查看、撤销和恢复。Codex 截图中的分享、分叉等不是新增业务需求；F16 定时任务仅保留入口，实际功能按 PRD §8.3 后续排期。
7. 改版不能丢失现有功能。以当前生产源码形成 [现有功能与原型对应清单](design/m6/现有功能与原型对应清单.md)，核对字段、入口、状态及页面间的数据同步；区分页面存在、原型点验和真实业务验收。AI 参数／环境变量／导入、完整项目资源、能力管理和任务上下文均须保留。英文、错误状态及原生能力尚未完整演示的部分不得默认为取消。

交付物：Codex 对标基线、独立原型、正式应用页面和共用样式、关键状态截图、功能对应表及验收记录。核心布局直接复用已审阅原型样式；资源等专属区域保留 SmartDD 完整表单。逐页视觉结果及原生窗口适配边界见正式应用视觉检查。

## 3. F15 的功能范围与交互基线

目标流程：**检测工具 → 添加或使用已有配置 → 测试状态可见 → 新建任务选择配置 → 在项目目录启动 → 发出问题并收到回复**。

| 环节 | 必须满足的行为 |
| --- | --- |
| 检测 | 展示 Codex／Claude Code 的实际路径、版本及失败原因；保留重新检测和手动指定路径 |
| 添加配置 | 从检测结果进入添加流程，自动带入运行器、路径和合理名称；默认使用已有本机 CLI 配置，避免重复填写已可复用的信息 |
| 已有配置 | 有对应基础配置时可直接进入或使用；重复检测／重复添加不产生同一来源的重复基础配置，同时保留主动创建多套配置的能力 |
| 配置同步 | 保存后立即刷新 AI 配置列表、新建任务下拉及默认配置候选；不静默改动用户已选的默认项 |
| 登录与模型 | 复用现有有效 CLI 登录与配置；缺失登录、接口、模型或凭据时提供具体指引；不会因找到可执行文件就标为模型可用 |
| 状态与错误 | 清楚区分已检测、已添加、测试中、可用、异常／不可用，沿用 F04 的最小调用测试及错误分类；失败允许修复与重试 |
| 数据保留 | 不覆盖现有 CC-work 等配置的参数、凭据、默认选择及历史任务关联；重启后新增配置仍可选用；密钥继续按 F09 加密、脱敏 |

首版建议采用检测结果旁“一键添加基础配置／打开已有配置”的入口，复杂环境变量和启动参数保留在编辑界面；最终文案及位置随 F14 对标确定。检测本身不等于用户已选择添加配置。

首版聚焦本机现有 Codex、Claude Code CLI 的默认配置复用和 SmartDD 已保存配置的管理，不扩展为任意第三方工具或任意 shell 脚本的配置导入器。现有 `.zshrc` Claude Code 多账号导入继续可用。

交付物：检测到配置的页面流程、配置列表及任务选择同步、必要的数据与错误处理、自动化测试和真实页面验证记录。

## 4. 本阶段边界

### 7.2 正式接入授权与本轮边界（2026-10-16）
