# M11：邮件、禅道、Jenkins 接入需求

更新日期：2026-10-16。需求来源：[需求池 F19](需求池.md)。状态：三类集成已确定进入 M11；本文为独立需求初稿，接口环境、各自业务闭环、原型和技术方案待细化，未开始接入。

本文是 M11 具体需求的维护入口，后续原型、技研和交付验收分别引用下列需求项。参考 Claude Code 插件机制组织能力，不等于已决定兼容其插件格式或运行时。

## 1. 目标与业务范围

让邮件中的信息、禅道中的需求／Bug、Jenkins 中的任务／构建结果与 SmartDD 项目任务关联，减少在多个系统间手工搬运。三类集成都属于本阶段，内部实施顺序待定。

| 编号 | 需求 | 已记录的目标与流程 |
| --- | --- | --- |
| M11-R01 | 连接与项目配置 | 配置系统地址／账号／认证，按项目选择连接，展示可用性和错误；不得跨项目串用资源 |
| M11-R02 | 邮件收取与任务关联 | 选择邮件范围，读取邮件及约定附件，提取需求／待办，经核对关联项目并形成任务 |
| M11-R03 | 邮件发送与报告 | 编写或生成邮件、日报／周报，核对收件人和内容后按已确定规则发送，记录实际结果 |
| M11-R04 | 禅道需求／Bug | 拉取指派项，查看并关联 SmartDD 任务，跟踪处理；字段、状态流转与结果回写规则需定稿 |
| M11-R05 | Jenkins 任务与构建 | 查看 Job／构建结果，按项目映射 Job、参数和 SVN revision；构建／部署的可执行范围和结果回收需定稿 |
| M11-R06 | 能力生命周期 | 参考插件化方向管理配置、启用／停用及版本；安装形式、分发、兼容性和是否需要 SDK 待技研 |
| M11-R07 | 结果与失败处理 | 外部目标、请求内容、关联任务和结果可追溯；超时、断网、认证失败、重试及重复发送／回写／构建有明确处理 |

## 2. 规则与边界

- 沿用现有项目、任务、Skill／MCP 和凭据机制；外部系统连接不是新建另一套项目数据。
- 邮件发送、禅道回写、构建／部署分别明确目标、参数或内容，以及何时由用户确认、何时允许自动执行；配置连接不代表所有动作可自动执行。
- 邮件原文、提取出的待办、生成的报告和实际发送记录要能区分；不能把“已生成草稿”显示为“已发送”。
- 禅道本地任务状态与外部状态要有映射和失败恢复，不因请求发出就标记回写成功。
- Jenkins 的触发成功、排队、构建运行、构建结果和部署结果分别解释，不以得到构建编号代替完成。
- 与 M10 联动的定时报告等只有在双方规则明确后接入；M11 不自动增加未确定的全自动项目工作流或插件市场。

## 3. 评审前需要明确的内容

| 方向 | 需要明确的输入 |
| --- | --- |
| 邮件 | 服务与协议、认证、收取范围、附件、项目关联、报告数据来源、收件人、发送与审阅方式 |
| 禅道 | 实际版本、接口、账号权限、需求／Bug 字段、状态映射、现有 Skill 适配、去重规则 |
| Jenkins | 实际版本、认证、Job／参数、SVN revision、触发与部署范围、结果查询和失败恢复 |
| 共同机制 | 集成安装形式、启停、权限、日志、重试与幂等、凭据使用、目标平台、验收环境和内部实施顺序 |

这些是详细设计待定项，不以假设代替已确认业务行为。本次维护文档不连接外部系统或执行发送、回写、构建部署。

## 4. 验收目标

分别验证邮件收取／任务关联／实际发送、禅道拉取／任务处理／回写、Jenkins 查询／已确定的触发与结果闭环；共同覆盖项目隔离、启停、权限、认证失败、超时、重复请求和重试。每类业务要有独立用例与真实结果证据，不能用一种集成通过代表三类全部通过。
