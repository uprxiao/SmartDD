## 维护方式

- 新想法先写在这里；有既有 F 编号就沿用，拆分时保留父编号。已有明确记录不重复建项，取消或合并时保留去向。
- 决定进入某个 M 阶段后，建立 `里程碑/M<n>_<主题>/`，从阶段 `README.md` 进入，在 `需求.md` 展开具体需求；本池只同步简述、安排、状态和链接，不复制详细业务规则。
- M 需求文档作为该阶段原型、技术调研／设计、交付验收文档的共同依据。范围变化先更新该 M 文档，再同步相关产物及本池摘要。
- 本池状态只作概览：待梳理／已安排／执行中／已完成；暂缓、取消或阻塞可另注。详细设计、评审、开发和验收进度从阶段 README 及其关联记录进入。
- 已有调研不等于已进入开发，功能实现不等于验收通过，验收通过不等于已发布。M 编号和应用版本分别维护。
