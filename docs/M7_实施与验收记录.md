## 实现范围

- 参考已确认的 [M7 原型](design/m7/M7_原型验收.md)，保留首页与设置试用的麦克风入口；按最新确认，运行终端使用 SmartDD 全局快捷键，沿用原有终端工作区及业务页面。
- 语音设置提供 Typeless 检测、启用开关、实际听写键、手动覆盖、可录制的全局组合键、保存／撤销、权限指引和失败反馈。全局键默认关闭。
- VoiceService 协调新键注册、设置落盘和旧键释放；注册／保存失败保留原设置；退出释放注册，重启恢复保存值。通用设置 RPC 同样经过此事务，避免绕过协调器。
- 设置录制快捷键前临时注销本应用语音全局键并暂停菜单快捷键，结束／取消／失焦／离页后恢复，并有 60 秒恢复上限。按物理键位识别有效组合后立即完成页面录制；恢复全局键时单独等待物理释放，不依赖渲染进程的修饰键 keyup。禁止与 Typeless 转发键相同，拒绝应用保留键。
- 首页／设置保留光标与选区；终端全局键由原生桥核对前台输入目标；切页、失焦、任务停止或目标变化时取消尚未发送的请求。不会在异步结束时强制拉回焦点或额外提交 Enter。
- 采用 `native/voice/bridge.m`：固定 JSON 协议、固定键码、后台启动、物理修饰键释放检测、前台及 AX 焦点复核，成对发送短按事件。未读取输入正文、剪贴板、音频、Typeless 历史或词库。
- Yoda 键码映射已注明 Apache-2.0 来源，沿用后台唤起、选区保留和短按思路；SmartDD 新增全局键事务及最小原生桥。详见 [Yoda 调研](M7_Yoda语音唤起调研.md)。
- F17-B 的录音、模型接入和自有词库未实施。Windows/Linux 显示语音暂不支持，不注册语音全局键或执行 macOS 桥。

## 权限问题排查（进行中）

用户系统列表中确有开启的“SmartDD”，但当前 QA 的按键桥仍报告缺少辅助功能权限。只读检查自身 TCC 日志发现：临时 QA 的 bundle id 未在 LaunchServices 找到，主应用请求和内部桥请求使用了不同形式的身份（bundle id／主可执行文件路径）。原测试副本只改了 Info.plist，沿用了 Electron 未绑定 Info.plist 的链接器签名，不能据此证明与用户获准条目一致。

已重新打包并刷新隔离副本，补注册 LaunchServices；随后仅对 QA 副本补做 ad-hoc 签名，`codesign --verify --deep --strict` 通过。此举不是 Developer ID 签名／公证，也没有修改 TCC 数据库或绕过授权。生产打包也改用 electron-builder 的 ad-hoc 封装并增加身份一致性检查，11:39 在非同步目录重打通过；尚未以此宣称权限或真实回填问题已解决。同步目录中的 FinderInfo 会在签名中重新附加，当前使用 `pnpm package --output-dir /private/tmp/smartdd-m7-build` 绕开该构建目录问题，而非降低签名校验。

用户确认此前实际选到的是 `/Applications/SmartDD.app`，与 QA 路径不同。已要求暂停另一测试终端的电脑操作，并把 QA 安装到应用程序文件夹，便于按可见名称重新授权。自动审批多次拦截系统设置“添加”动作，最终将完整路径选择与系统解锁交给用户手动完成。安装到 `/Applications` 后，自动审批又拒绝启动临时签名 QA 包，要求单独行动确认；已请用户手动打开同一 QA 包，待实际包可操作后继续验证。不能把“列表开关开启”单独当作当前按键桥已可用。

## 快捷键录制与导航状态修复（2026-10-16 下午）

- 原录制只抑制回调，没有临时注销系统全局键；系统仍可能先拦截该组合。新实现先释放本应用注册，再聚焦录制框，完成或取消后恢复；恢复注册失败会显示冲突，保存配置保持不变。
- 使用 `KeyboardEvent.code` 匹配物理字母、数字、空格和 F1–F20，修复 Shift+数字变为符号、Option 改变字符、输入法 Process 事件等情况。无效组合显示说明，Esc、取消、失焦和超时均退出；取消按钮防止 blur/click 重新进入录制的竞态。
- 安装包实测发现“等待所有修饰键 keyup”可能停留在录制状态，已改为捕获有效组合后立即录入；主进程独立等待物理释放，避免重新注册后误唤起。最终代码通过类型检查和重新打包。
- 根据用户新截图调整应用导航：当前页面实心图标＋圆角选中底，非选中线框，独立悬停／键盘焦点状态；蓝点固定在首页。浅色外框改为中性灰，并调整图标尺寸和分隔线；保留全部现有功能入口，不增加 Spaces。
