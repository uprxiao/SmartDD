# SmartDD 参考项目调研与选型建议（V0.2）

调研日期：2026-10-14（V0.1 初稿同日；本版按一期改为 Desktop、新建 Electron 项目后重写）。

**核验范围**：读取了各仓库的 README、目录树、`package.json`、LICENSE，以及 Yoda 的数据库 schema 和部分源码；读取了本机现有 Skill 的脚本参数与配置字段结构（已脱敏）。**均未安装运行**，所以下文关于“行为”的判断都是读代码和文档的推断，M0 技术探针需逐项实测。本次不对成熟度、效率作评分。

## 1. 结论

1. **新建 Electron 项目，参照 Yoda 的架构、技术栈和主题，按模块搬运；不 fork、不在 Yoda 上二开。** 这是用户的明确决定，本次调研支持该路线。
2. **用 Electron，不用 Tauri。** 三个参考项目都是 Electron，终端 PTY、SQLite、Skill 等代码可直接参考或搬运；选 Tauri 等于全部用 Rust 重写核心后端。
3. **V0.1 提出的“Paseo 插件路线”不再采用。** 一期只做 Desktop，不需要跨端 daemon；Paseo 保留为二期手机端的参考。
4. **一期的技术风险集中在 4 件事（M0 探针）**：原生模块打包、两个 CLI 的 session ID 与 resume、Keychain、Skill 装载位置。

## 2. 候选项目事实

| 项目 | 许可证 | 规模与活跃度 | 技术特点 | 对 SmartDD 的作用 |
| --- | --- | --- | --- | --- |
| [lovstudio/yoda](https://github.com/lovstudio/yoda) | Apache-2.0（含 General Action, Inc. 的部分版权） | 约 72 星；最近发布 2026-09-04；核心作者约 5 人 | Electron、React 19、electron-vite、better-sqlite3 加 drizzle、node-pty、xterm、Tailwind 4；分 `main`、`preload`、`renderer`、`shared` 四层，RPC 通信 | **主要参考**：架构、界面、主题、数据层、会话与 resume 的处理方式 |
| [stablyai/orca](https://github.com/stablyai/orca) | MIT | 约 9.2 万星；体积约 1.3 GB | Electron；工作区、终端、内置浏览器、SSH、手机端 | 二期手机端、终端稳健性参考；体量过大，不适合搬运 |
| [getpaseo/paseo](https://github.com/getpaseo/paseo) | Apache-2.0 | 约 2 万星；12 个包 | 本机 daemon、跨端、插件体系、加密中继 | 二期手机端连接方案参考 |

说明：Yoda 的星数和作者规模较小，意味着它是“可参考的实现”，不是“可依赖的上游”——这也是不二开、只搬运的理由之一。

## 3. Tauri 与 Electron 对比

| 维度 | Electron | Tauri |
| --- | --- | --- |
| 代码复用 | 三个参考项目同栈，TypeScript 可直接搬运 | 无法复用，核心后端用 Rust 重写 |
| 终端 PTY | node-pty 成熟，Yoda 已有成熟用法 | 需 Rust 的 PTY 库，自行封装 |
| SQLite | better-sqlite3 加 drizzle，Yoda 有现成 schema 可参考 | rusqlite 等，自行实现 |
| 原生模块 | 需针对 Electron 重建、打包，**是 M0 的风险点** | 无此问题 |
| 体积与内存 | 较大 | 较小 |
| 二期手机端 | 可与 Node 栈衔接 | 需另行设计 |
| 作者上手成本 | TypeScript | 需要 Rust |

结论：Tauri 的体积优势抵不过“全部重写”的成本。Electron 的唯一显著风险是原生模块打包，在 M0 实测。

## 4. Yoda 搬运清单

依据：目录名、README 与 schema，**行为未实测**。

| 处理 | 模块 | 说明 |
| --- | --- | --- |
| 搬运 | 数据库层（better-sqlite3、drizzle、迁移） | 表结构按 SmartDD 重新设计，不照搬 |
| 搬运 | PTY 终端（node-pty、xterm） | 终端创建、尺寸、数据流 |
| 搬运 | 密钥存储（`secrets`，含 `encrypted-app-secrets-store.ts`） | 改为对接 macOS Keychain，需评估 |
| 搬运 | 侧边栏（`left-sidebar.tsx`、`project-item.tsx`） | 项目 → 会话树的形态 |
| 搬运 | 主题（`theme-provider.tsx`、`index.css`） | 配色、深浅色 |
| 搬运 | MCP 适配（`mcp`，7 个文件） | 识别和管理 MCP |
| 重点参考后重写 | `conversations`（109 个文件，含 `codex-session-id.ts`、`claude-transcript-locator.ts`） | session ID 与 resume 的复杂所在；先读懂，再按 SmartDD 的最小范围重写 |
| 参考后重写 | `skills`（11 个文件，含 `bundled-catalog.json`） | Skill 服务按“标准 Skill、代码与数据分离、按项目装载”重写 |
| 不要 | 第三方工单集成、git 周边、team rooms、ai-lab、maas | 一期无关，且会带入复杂度 |

**Yoda 与 SmartDD 的三个冲突点**：
1. **强制 git**：`projects.path` 唯一，工作区提供者偏向 git/worktree；SmartDD 的项目是 SVN 工作副本，不能依赖 git。
2. **会话必须挂在 task 下**：`conversations.task_id` 为 NOT NULL；SmartDD 是“项目 → 会话”，没有 task 层。
3. **配置模型不同**：Yoda 没有“项目下多环境数据库、服务器”的概念，需新建。

**合规**：Apache-2.0 要求保留版权和许可声明，修改的文件要标明改动。搬运时在仓库根目录建 `NOTICE`，列出来源文件、原版权人和改动说明。正式分发前再核对所固定版本的 LICENSE 与第三方依赖许可。

## 5. 现有 Skill 核验

核验对象为 `~/.codex/skills` 下的 Skill（`~/.claude/skills` 为其软链）。只读脚本参数与配置字段结构，不读密钥。

| Skill | 配置解析现状 | 密码处理 | 一期改动 |
| --- | --- | --- | --- |
| `remote-password-ssh` | 支持 `--config` 与环境变量 `REMOTE_SERVERS_CONFIG`；项目级配置依赖 git 根目录查找，SVN 项目找不到 | 配置要求密码字段明文 | 无需改解析；明文兼容保留，走环境变量指定路径 |
| `project-db-diagnostics` | 仅 `--config`，默认读 Skill 目录 | 支持 `passwordEnv` | 补充环境变量指定配置路径 |
| `operate-databases` | 仅 `--config`，默认读 Skill 目录 | 同上；有写操作的计划与确认机制 | 补充环境变量；审批机制原样保留，Desktop 不介入 |
| `export-zentao-bugs`、`resolve-zentao-bug-round` | 未纳入一期 | — | 二期随禅道一起重写 |

**统一约定**：配置路径解析顺序为 `--config` 优先，其次环境变量，最后才是 Skill 目录内的默认路径。`remote-password-ssh` 已符合；另两个补上环境变量即可。改动要小、统一、向后兼容，不覆盖用户现有 Skill。

## 6. M0 技术探针清单

M0 的目的是用最小成本消除一期最大的不确定性。**以下条目全部未验证**。

| 编号 | 探针 | 实测内容 | 通过证据 |
| --- | --- | --- | --- |
| P1 | 原生模块 | node-pty、better-sqlite3 在 Electron 下重建；`electron-builder` 打包后在干净环境启动 | 打包产物能启动，能创建 PTY 和读写 SQLite |
| P2 | Claude Code session ID | 能否通过 `--session-id <uuid>` 指定，或 SessionStart hook 获取；`--resume <id>` 恢复 | 关闭后 resume 接上原上下文 |
| P3 | Codex session ID | `codex resume <id>`；session ID 是否需扫描 `~/.codex/sessions` 获取 | 同上 |
| P4 | 跨 AI 配置 resume | 用 CC-DS 开启的会话，换 CC-Claude 能否 resume | 记录结论，不假设可行 |
| P5 | Keychain | 存、取、删密钥；打包后是否弹授权框、签名是否影响访问 | 能稳定读取，拒绝时有明确错误 |
| P6 | Skill 装载位置 | 用户级目录、项目目录、运行器参数三种方式的发现效果；写入 SVN 工作副本后 `svn status` 是否受污染 | 选出不污染代码目录的方式 |
| P7 | 配置注入 | 环境变量进入终端进程及其子进程；Skill 是否按约定读到 | Skill 自身记录显示读到的是注入的配置 |
| P8 | Skill / MCP 扫描位置 | 两个运行器实际读取 Skill 与 MCP 的位置和优先级 | 与 F07 的三级状态对应 |
