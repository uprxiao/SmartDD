# M1 骨架说明

日期：2026-10-14
退出条件（PRD V0.2 §2.3）：能启动并保存一项设置 —— **已达成**。

窗口布局、主题、设置、进程间通信的做法均参照 Yoda（Apache-2.0），参照清单见仓库根目录 `NOTICE`。

## 1. 结构

| 位置 | 内容 |
| --- | --- |
| `src/main/index.ts` | 启动：打开数据库并执行迁移、注册 RPC、创建窗口和菜单、退出确认 |
| `src/main/app/window.ts` | 主窗口：1400×900，最小 700×500，`hiddenInset` 标题栏（40px），macOS 关窗即隐藏 |
| `src/main/app/menu.ts` | 中英双语应用菜单；`⌘,` 打开设置，`⌘B` 切换侧边栏（由菜单发事件给界面） |
| `src/main/rpc.ts` | RPC 路由：app、appSettings、sessions、pty、probes 五个命名空间 |
| `src/shared/ipc/` | 类型化 RPC（channel 为 `命名空间.方法`）与事件通道 |
| `src/main/db/` | drizzle schema、打包迁移执行器、会话表仓储 |
| `src/main/core/settings/` | 设置服务 |
| `src/renderer/` | React 19 + Tailwind v4 界面：工作区布局、侧边栏、首页、终端、设置页 |

界面视图：首页（新建会话）、终端、设置。终端视图始终挂载，切换视图时保留 scrollback。

## 2. 设置存储

- 表 `app_settings(key, value)`，每个顶层 key 一行，value 为 JSON。
- 只存与默认值不同的部分；恢复默认值后删除该行。
- 写入用严格 zod schema 校验，坏值直接拒绝；读取时逐字段 `.catch`，库里的坏值回落默认值而不是让整个设置不可用。
- 同一 key 的写入串行执行，一次失败不阻塞后续写入。
- 当前设置项：
  - 通用：界面语言（`zh-CN` / `en`，默认 `zh-CN`），数据目录（只读显示）
  - 外观：主题（跟随系统 / 浅色 / 深色）
  - 终端：字体、字号
- 主题和语言另外镜像到 localStorage（`smartdd-theme`、`smartdd-language`），由 `public/theme-init.js` 在首帧前应用，避免闪烁。

## 3. 数据库迁移

- 迁移 SQL 由 `pnpm db:generate`（drizzle-kit）生成到 `drizzle/`，构建时打包进主进程。
- 启动时按已执行条数跳过已执行的迁移，剩余迁移在一个事务中执行，失败整批回滚。
- SQL 使用 `CREATE TABLE IF NOT EXISTS`，M0 留下的旧库可被直接接管，原有数据保留。
- 库中已执行的迁移数多于程序自带的数量（即库比程序新）时拒绝启动，提示更新版本。
- 迁移失败时弹窗提示并退出，不带着半成品库运行。

## 4. 测试方式

```bash
pnpm typecheck   # node 与 web 两个工程
pnpm test        # ELECTRON_RUN_AS_NODE=1 electron 运行 vitest，可直接加载 better-sqlite3
pnpm build
pnpm probe       # SMARTDD_PROBE=1，输出 JSON，全部通过时退出码 0
```

单元测试（4 个文件，27 个用例）：

- `migrations.test.ts`：空库建表、重复执行无操作、接管 M0 旧库、只执行剩余迁移、失败回滚、库比程序新时报错
- `settings-service.test.ts`：默认值、差量存储、恢复默认删行、跨实例持久化、严格校验、坏值回落、并发串行、失败不阻塞、reset
- `rpc.test.ts`：channel 命名、参数传递、Proxy 非 thenable、错误信息处理
- `codex-session.test.ts`：M0 留下的 Codex 会话解析纯逻辑测试

- typecheck、单元测试、构建均通过。
- 探针：真实库执行 `0000_init` 后全部通过；再次执行退出码 0，迁移记录仍为 1 条。执行前已备份 M0 库到 `/tmp/smartdd-m0-backup.db`。
- 界面（通过远程调试端口驱动真实窗口点击）：
