A0.3 · 2026-11-23 · 开发和验收基线。适用 F35-R1 至 R5、已确认的原型及 M14 任务规则。执行结果逐条记录。[F35 需求与原型基线](F35_Antigravity验证与评审.md#评审规则) · [开发前实验结论](F35_Antigravity验证与评审.md#开发前专项实验结论) · [M14 任务规则](里程碑/M14_统一Agent工作区/需求.md#m14-r06-委派问题与结果回收rc8d4)

## 环境与取证

- 首轮使用 macOS arm64 的隔离打包 App、独立应用数据和测试项目。每条用独立任务、文件标记、配置或会话身份，同一构建复用。既有任务用含 M14 统一任务的历史版本隔离数据，搭配可恢复的原生会话。不能运行历史版本时，I 层可用对应版本的快照夹具，A 层的升级结果按实际执行记录。
- **U** 为单元或前端状态，**I** 为真实服务、存储或 ACP 集成，**A** 为打包 App 界面操作，**S** 为 Finder 等系统层步骤，**R** 为真实模型。隔离模型响应可供 I、A 使用。R 仅以真实网关的回复和工具结果取证。
- **P1** 为智能体设置，**P2** 为供应商设置和模型结果，**P3** 为任务区模型选择和续聊，**P4** 为已有任务关系及审批界面。P4 沿用 [M14 原型与规则](里程碑/M14_统一Agent工作区/原型/原型说明与变更.md)。F35 入口和可恢复快照见[已评审原型](F35_Antigravity验证与评审.md#共享原型)。
- **配置数据**使用两款示例模型 `gemini-4-carbon`、`gemini-4-argon`，不同配置修订和隔离模型服务。用测试 Key 验证保存与隐私。真实网关用用户已授权的配置，证据记录地址归属、模型、HTTP 状态和耗时等必要信息。
- **任务数据**使用带唯一消息标记的 Codex、Claude Code 和 Antigravity 任务。文件场景使用测试 Git 仓库、SVN 工作副本和普通目录。准备同目录别名、未提交文件及仅存在于工作副本的标记文件。
- Electron 页面用已有后台 CDP 驱动执行真实点击和输入，S 层前台核对窗口。I 层用隔离夹具控制回合、断网和迟到回执，可向测试边界提交失效票据或跨任务审批。正常操作以真实界面、进程和宿主回执取证。等待以具体回执或可见状态完成，达到构建配置的时限后记录停在哪一步。每条保存包或源码摘要、开始时间、任务及请求标识、实际状态、必要截图或文件结果和缺陷链接。[真实 App 自动验收流程](真实App自动验收流程.md)
