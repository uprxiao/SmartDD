# M7 语音焦点与权限复核

日期：2026-10-16；分支 `feature/0.0.1`。本轮普通开发，不提交发布 tag。

## 问题与证据

1. 用户在可见的空试用框中仍收到“输入位置已变化”。实际页面复现过该提示；当时系统 AX 快照有时只报告网页容器，填入测试前缀后又能识别文本框。在归档版 QA 中，后续点击成功唤起 Typeless；返回 QA 可见“焦点验收：听得到吗？”。这是间歇性现象，未采到失败当次的原生分支追踪，不能断言每次失败都来自同一分支。
2. 新包安装后，系统辅助功能列表的 `SmartDD M7 QA` 开关已开，当前桥却仍报告权限不足。只读签名检查确认：旧包与新包都采用 ad-hoc 签名，designated requirement 绑定不同的代码哈希。

| 对照构建 | designated requirement 中的 cdhash |
| --- | --- |
| 归档版（`/private/tmp/smartdd-m7-before-focus/SmartDD M7 QA.app`） | `5107c0578fe38e403fa74e03b4123288d3df1334` |
| 第一版焦点修复 QA | `6dd7ded20918d4650ec053b6d06bd5057a5d85a8` |

该差异与重新构建后授权失效相符；相同名称、路径和 bundle id 不等于相同的签名身份。此前已验证过同一构建正常退出、重启后授权保留；不能将其扩大为跨构建保留。

## 实现

- macOS 启动时准备应用自身的 Chromium 辅助功能树，使空输入框不必等待外部辅助工具首次启用 AX；这不授予系统辅助功能权限。
- 原生桥对临时读不到目标、仅得到网页／窗口容器的情况最多读取 8 次，重试间隔 25ms。前台应用改变、读到不同元素或受保护输入框立即拒绝，不跟随新目标，不自动重发听写键。
- 区分 `INPUT_FOCUS_UNAVAILABLE`、`TARGET_CHANGED`、`SECURE_INPUT`，不再把读取失败都描述成用户移动了光标。焦点错误不再引导去改语音配置。
- 每次唤起前仍以原生 `AXIsProcessTrusted()` 与 `CGPreflightPostEventAccess()` 为准。检查不申请授权；只有用户明确选择打开权限指引时才进入系统授权流程。
- 窗口从系统设置返回后自动静默检查当前桥；新检测结果覆盖旧结果，较早返回的异步结果不能反向覆盖新状态。检查确认权限有效后清除历史权限错误与对应浮卡，不自动录音。其他错误仍按历史失败展示。
- 权限已就绪时明确展示“辅助功能权限已就绪”；指引说明当前 QA 名称与临时签名升级的限制。原型同步文案、焦点错误场景，并移除已经不适用的 System Events 自动化授权说明。

## 同包重启与取消补测

- 对上述 SHA256 的同一个安装包执行 Cmd+Q；只读检查精确 QA 主进程已退出，再通过 CUA 以 `/Applications/SmartDD M7 QA.app` 重新打开。语音页仍显示“辅助功能权限已就绪”，手动键 `RightOption`、全局键 `Alt+Z` 及启用状态保留，全局键显示已生效；没有再次要求系统授权。该结论只覆盖同一构建重启。
- 重启前首页已有草稿“M7 语音验收”，重启后为保留用户现场通过粘贴恢复。该操作不属于语音回填证据。
- 取消补测使用独立试用文字“取消验收：保留这段文字。”。第一次操作后 Typeless Status 曾显示 `Thinking`，下一次读取已隐藏，文字未变；未捕获明确取消操作，不据此记为取消通过。
- 后续自动点击出现 `INPUT_FOCUS_UNAVAILABLE`，QA 的 AX 树仍指向试用文本框；同时工具的鼠标坐标操作返回 `noWindowsAvailable`，截图亦有不可用情况。前台及原生失败分支缺少当次诊断，不能确定是自动化焦点限制还是产品残留误判，**焦点稳定性尚未全部验收通过**。权限始终显示就绪，错误提示没有再次要求修改权限或快捷键。
- 已暂停界面操作，请用户用真实鼠标点击麦克风并取消，以区分实际使用结果；该对照结果待补充。没有为重试改动包内容、放宽焦点保护或重新签名。

## 签名边界

同一个已授权安装包正常使用不应每次重新授权。自测阶段继续采用用户允许的临时签名；更新测试包后可能需要重新授权。后续使用稳定的开发者签名身份、保持应用标识与签名要求一致，才能让系统可靠识别跨版本应用身份；公证不代替辅助功能授权。没有修改 TCC 数据库、扩大代码身份要求或跳过原生权限检查。
