## 2. 路由不是仅按扩展名分派

静态调用主干是 `openWorkspaceFile` 导出别名 → `JG` → 文件面板注册回调 → `FVa` → 文本编辑器／artifact／review source；HTML 在若干条件下于入口提前分流。`FVa` 先处理已有标签与显式查看器、附件／artifact 导航、MCP 文件查看器，再尝试文本编辑器和 artifact，最后回退 review source。初始行列、host、打开来源、功能开关、用户指定查看器和已有标签都会改变最终结果，不能写成“所有 .pdf／.html 永远进入同一个组件”。

源锚点：FR1 `JG` L103766–103861、`FVa` L128644–128699；默认编辑类型 `vBi` L103597–103608；review 分类 `PBi/FBi/IBi` L103687–103736。FR16 `readFileMetadata` L61736–61759 先 stat，在 `isFile` 且大小满足 `contentSampleMaxFileBytes` 时读取 `contentSampleByteLimit` 样本，然后交给 `r.Rn` 返回 `contentKind`。本补查未展开 `r.Rn` 的全部内容嗅探规则，不能承诺扩展名错配和所有编码都识别正确。

| 类型 | Codex 发布代码中的分发与渲染事实 | 对独立文件模块的意义 |
| --- | --- | --- |
| Markdown | 扩展集 `markdown/md/mdown/mdx/mkd`；`vBi` 返回 markdown 编辑类型。review 支持 rich/source toggle，有指定起始行时不自动走该富预览。Markdown 编辑库依据沿用前轮 CodeMirror 静态证据 | F22-A 可独立交付渲染、源码、切换与保存；不需要浏览器导航宿主 |
| 文本／代码 | `.txt` 明确 Pierre language=text；其余通过语法识别器，返回 text 的未知扩展不直接进入该编辑器；`.wasm` 明确返回 null。无法进入编辑器可回退 review source | F22-A 独立能力；未知文本与二进制需先分类，不把所有文件强行 UTF-8 解码 |
| 常见位图 | 扩展 fallback 包含 avif/bmp/gif/ico/jpeg/jpg/png/webp；元数据 `contentKind=image` 可覆盖扩展路由。`read-file-binary` → Base64+MIME → data URL → `<img>` | F22-A 可独立；Codex 列表不是 SmartDD 已验证格式列表 |
| TIFF | 底层图片扩展表虽含 tif/tiff，上层 `LBi` 明确把两者列为 unsupported image | 不可因为底层表含扩展就声称 Codex 支持，更不可自动承诺 SmartDD 支持 |
| SVG | 扩展 fallback 返回 toggle；若元数据直接给 image 则 mode 可为 always。图片预览用 `data:image/svg+xml` 的 `<img>`，加白底／padding；源码路径仍可能走代码编辑／review | F22-A 可独立支持“图片呈现＋源码”，这里没有把 SVG 直接注入应用 DOM，也不是地址导航网页 |
| PDF | artifact 映射含 pdf；artifact 读二进制后懒载 `PdfPreviewPanel`，使用页面 canvas／text／annotation 层。review 回退路径也有 PDF 组件，使用 `react-pdf__Page` 和单独 `pdf.worker.min-46513d3652c6.mjs` | F22-A 可用独立 PDF renderer/worker 交付，无需先有完整浏览器。库版本、字体、表单、损坏 PDF 等需单独验证 |
| HTML／HTM | 入口支持源码、浏览器打开、文档沙箱三条路线；见下节。扩展匹配 `/\.html?$/i` | 源码属于 F22-A；隔离文档预览可选；带地址导航的项目页面归 F22-B |
| 未知二进制／归档 | `IBi` 对 binary/archive 等返回 unsupported；满足 `qBi` 条件的本地普通打开可提前转 `target=fileManager`，强制默认面板等分支则可显示不支持预览。无可见通用十六进制编辑器路径 | F22-A 应有明确错误／不支持态、元数据与外部打开；是否提供下载等按来源定，不能承诺任意二进制可编辑 |

上述表是静态事实与迁移推论的区分：第二列为已读代码，第三列为迁移建议。FR2 L109883–109901 定义图片／Markdown 扩展表；FR3 L730–780 执行元数据→不支持→大小→富预览／源码；FR4 L42–85 与 FR5 L7–35 构成图片加载链。PDF 见 FR6 L1448、L2194–2198，FR7 L413–511，FR8 L935–972。FR1 `oD/sD` L43762–43833 是 artifact 类型映射，包含 Office／表格／notebook／TeX，但本轮未把这些扩展为开发承诺。

文本编辑的既有边界仍是 **≤10 MiB 可编辑，>10 MiB 且 ≤20 MiB 只读，>20 MiB 拒绝该文本路径**；不能把它套到所有图片/PDF/artifact 读取上。不同读取接口有独立的 maxBytes 和内存成本。

## 3. HTML 三条路线与真实依赖

### 3.1 本地工作区：源码与浏览器入口分开

FR1 `JG` 中 `browserEnabled` 参数默认 **false**。只有非 cloud/durable 分支、`browserEnabled=true`、有 hostConfig 且 `!Is(hostConfig)`、路径匹配 HTML，且不是 modifiedClick，才在普通文件面板之前通过 `M10` → `jBi` → `Pd.openIn.open` 移交打开。显式 target、openMode=workspace、preferred-target 请求又优先于该分支。`QBi` 不是“任何 HTML 自动开内嵌浏览器”。

未触发浏览器分支时，HTML 可以走源码编辑／review。`browserEnabled=false` 并不取消 HTML 文件本身的查看和编辑。源锚点 FR1 L103766–103806、L103859–103861；`qi` 对应 FR2 `Cxt` L56112、`Nxt` L56185。

迁移推论：F22-A 的 `openFile` 可以先交付 HTML 源码；向 F22-B 只传显式 `openHtmlPage` 请求。真实项目网页的相对资源、脚本、导航、刷新、localhost、窗口与页面生命周期属于 F22-B 或双方共用的 Web 内容基础设施；本轮不实现。

### 3.2 cloud／文本附件：独立的 HTML 文档沙箱

FR1 `TJ` L116274–116287：host 满足 `Ql`、HTML、无 line/endLine/column 时，懒载 `openChatGptTextDocumentPreview`，指定 `previewKind=html`。实际文本组件 FR9 也接收已有内容或自定义 loadText，并非只处理 cloud。普通本地打开没有在此处自动变成该文档预览。

FR9 L40–63 的 cloud 读取会先检查 UTF-8 编码后的大小：**>10,485,760 bytes 拒绝，等于允许**。普通 workspaceFiles.read 也传 `maxBytes=10,485,760`（FR2 `RWr` L118022，经 `nZ` 导出）；自定义 loadText 分支没有本组件中的相同字节检查，不能泛化限额。

FR9 L116–122：已读内容只有 `previewKind=html` 且 **JavaScript 字符串 `.length <= 5,000,000`** 才进入 HTML 沙箱；超过则显示普通文本。这里计量 UTF-16 code units，不是 UTF-8 bytes，也不是 Unicode 码点数。FR13 `Wi` L605–610 对 contents／streamingHtml 再做 `>5e6` 拒绝。

FR10 L10–21：先检查 code-execution-account-policy 的 `status=allowed`，按 networkAccessEnabled 选择 online/offline sandboxDocument，把 `embeddedHtml`、`embeddedFillContainer=true`、`presentation=app-block`、title 交给 visualization renderer。FR11 构建 HTML 文档或包装 fragment；offline 变体 `disableNetworkRequests=true`。这些是 Codex 的账号／执行策略，迁移时需要 SmartDD 自己的明确策略，不能照搬账号耦合。

### 3.3 文档沙箱仍需专用 Web 内容宿主

实际链路是 FR10 → app-initial `Crl` 懒加载 → FR12 export → FR13 `Vi/Hi/Wi/qi` → FR14 元素工厂。FR13 L546–562 的正常 wrapper 将 scheme 设为 FR2 导出 `G8t=$Et=codex-sandbox`（FR2 L57424、L144858）；FR13 L789–796 因此创建 **`webview`**，其他 scheme 才创建 iframe，并在销毁时移除／destroy。FR14 L70–79 给元素设 partition；iframe 分支另设 `sandbox="allow-scripts allow-same-origin"`、`referrerpolicy=no-referrer`。共享 frame 分支及运行时实际使用哪个预热实例，本轮未实测。

因此，“HTML 文档预览不必依赖完整浏览器产品”成立；“只复用 React 文本区域即可执行 HTML”不成立。它需要独立隔离宿主、文档加载、协议／RPC、网络／下载／链接策略以及销毁处理。当前证据没有证明其项目相对资源解析与完整浏览器等价，也没有证明 SmartDD 已有等价宿主。不要把该可选文档沙箱的策略直接移入 SmartDD 主 renderer；也不要把所有 HTML 预览一律延后为 F22-B。

## 4. 两份迁移方案应怎样使用本证据

F22-A 应保留完整文件区域目标，并在 A0 的格式矩阵内分别记录“源码”“静态富预览”“隔离 HTML 文档”“外部／浏览器打开”。文件树、标签、元数据、文本／Markdown、图片／SVG、PDF、错误与不支持状态都可独立设计、实现和验收。HTML 源码属于基本文件能力；隔离 HTML 文档预览作为有独立宿主成本的可选项评估，不能仅因 F22-B 后开发而删除。

F22-B 接受文件模块发起的显式网页打开请求，承担浏览器地址／导航／刷新与项目页面运行。Codex 的 hostId/workspaceRoot/path 属于源包契约；SmartDD 应使用 F22-A 设计的 RootRequest（projectId + dirId 或 taskId）解析可信根，再共享主进程签发的 rootId + relativePath、打开意图、标题和页面标识，不接受 renderer 任意指定 hostId/root。重启后重新解析根权限，不以“扩展名是 HTML”强行让文件 tab 变 browser tab。专用文档沙箱可与浏览器复用底层隔离与协议设施，是否复用同一个运行实例必须另做生命周期与权限验证。

后续验证至少覆盖：扩展名与 contentKind 冲突；带行号打开 Markdown/SVG/HTML；TIFF 和未知二进制；同文件已有不同 viewer 标签；10/20 MiB 文本边界；HTML 10 MiB 与 5e6 code units 各自边界；HTML 禁网／脚本／相对资源策略；PDF worker、损坏与大文档；关闭沙箱后资源释放。以上是开发验收输入，**本次没有运行这些用例**。

本轮未改 App、原型、PRD 或迁移主报告；仅补充本证据文档和来源元数据。未执行网页脚本、未探查用户 cloud 文件、未触发任何写文件／保存业务接口。
