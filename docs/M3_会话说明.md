## 2. AI 配置与密钥

- 环境变量模板中，名称像令牌的（`*_TOKEN`、`*_KEY`、`*_SECRET` 等）自动标为密钥；密钥值存 `app_secrets`，key 为 `ai:<配置ID>:env:<变量名>`，值为 safeStorage 密文（`djEw` 开头）。`ai_profiles.env` 里密钥项的 value 为 `null`。
- 密钥从不发往界面，编辑框只显示“已保存”；日志只记变量名。
- `.zshrc` 导入：先选文件、脱敏预览（令牌显示为 `••••••（N 位）`，覆盖 `sk-`、`github_pat_` 等），勾选后导入；导入后提示原文件仍是明文。已存在的同名配置不重复导入。

## 3. 任务生命周期

- 新建：首条消息作为 argv 传给 CLI（不经 shell）。Claude 带 `--session-id <新UUID>`；Codex 由 session 文件回填 ID。
- 恢复状态：有 session 文件 → resumable（`--resume`）；Claude 未发过消息 → fresh（沿用原 ID `--session-id`）；Codex 未发过消息 → 未开始；无原生 ID → 不可恢复并写明原因。
- **自动 resume**（2026-10-15 用户确认，参照 Yoda）：应用启动不拉起任何任务；打开一个已停止的任务时，自动用原配置恢复，每个任务在一次运行中只自动尝试一次。以下情况仍显示恢复面板：未开始 / 不可恢复、原配置已删除、已归档、自动尝试失败、用户点了“换配置”。
- 换配置恢复时显示跨配置提示（接口、模型、账号可能不同，不一定能接上上下文）。
- 运行中的任务不能归档（提示先结束）；删除只删 SmartDD 记录，不动 CLI 的会话文件。

## 4. 调试用临时数据目录

`SMARTDD_USER_DATA=<目录>` 让应用使用指定的 userData（数据库、设置都在里面），用于 GUI 测试，不碰真实数据；该变量不会传给 CLI。

```bash
SMARTDD_USER_DATA=/tmp/smartdd-m3/userdata ./node_modules/.bin/electron . --remote-debugging-port=9333
```
