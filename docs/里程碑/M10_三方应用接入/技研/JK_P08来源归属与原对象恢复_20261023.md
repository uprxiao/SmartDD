# JK／JL P08 来源归属与原对象恢复

依据已授权 R1.6＋需求§12.21，M10-R07、R07-08–09、R08／P08／T36，2026-10-23。范围内缺口与常规技术选择，未新增业务范围。

原型核对发现全局记录投影默认写成 AIS、来源不分手动／Agent／索引、无失败原对象恢复。新增 `activity-prototype-model.mjs` 与 `PrototypeActivity.jsx`：全局 project=null，手动／索引不生成 task/run；合成 Agent 保留明确任务／run，索引保留 job；原应用／连接／项目交集筛选；固定六条合成记录覆盖两个应用、连接、项目与读／草稿／写、失败／unknown／完成及长错误。字段投影丢弃任意秘密／原始错误字段，固定长错误由枚举重建。仅使用原隔离 localStorage，不读真实邮箱或启动模型。

生产 `activity.tsx` 复用已有连接表单，按原 appId＋connectionId 找到对象；复用已保存草稿查看器，从原 projectId＋draftId 读取。SMTP 发送历史带 draftRevision 时严格读取冻结修订；仅有草稿关联的操作记录读取同一原草稿的当前已存修订，不推定它就是历史发送内容；错 ID／修订拒绝打开。服务端项目／权限、CAS 和发送授权契约继续生效，打开或关闭恢复视图不测试连接、不保存或重发。不存在的原连接仍可使用原有应用入口检查，不选另一个连接替代。

原 `DraftDetail` 仅增加导出，复用原资源查看、状态和显式发送审阅逻辑。恢复入口没有自动触发准备、授权或执行。未知草稿保留未知、无发送入口；历史本身不授予新权限。

JK 包截图发现长错误码横向撑出弹窗；JL 在活动详情 note 内启用换行。新包实际几何与浅深截图复验通过。原型对应样式已同步；没有声称完整 Codex 视觉一致。
