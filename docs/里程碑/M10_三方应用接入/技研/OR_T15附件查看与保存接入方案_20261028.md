# OR：T15 附件查看与保存接入方案

依据 R1.6＋12.21、R06-03／12.6、12.15。沿用既有范围内实现、修复与测试授权，feature/0.0.2；当前正式34/72、T15部分，不发布、不进入M9。

已确认范围仍包含普通附件列表、本机已有附件打开或保存、未下载／不可读原因和大小／类型／路径边界。不能将OQ正文预览代替附件。按依赖先接通资源查看，再接系统保存与原用例全链，不削减原范围。

查看入口复用必要结果：草稿详情的既有附件摘要增加文字内容查看；调用记录中从 application_mail_operation_sources 的原读取 provenance 提取邮件引用，提供“查看原邮件附件”。不是完整邮箱或独立阅读器。历史引用仅定位，不授予新权限；点击时重新执行当前项目mail.read与来源／身份／内容修订／日期窗口验证。原草稿附件必须属于该项目该修订，不能凭附件ID任取同项目其他附件。每个分块继续验证目标成员关系与权限，展示错误与未完成状态。HTML复用OQ安全文字路径；二进制不伪称已分析。

UI专用DTO与方法不改 v1 Agent 工具契约。前端不提交任意文件路径；保存将使用主进程原生选择器，复用既有broker身份／路径／原子复制保护。已核对现有 FileActions／FileRecoveryStore；其恢复配额与界面属于文件子系统，不能直接把M9工作区当M10保存前置。需同时完成输出恢复／清理与只读来源保护，不能仅调用shell.openPath或裸writeFile绕开保护；保存部分实现与验证未完成，保留原用例缺项。

本批准备共享原型附件查看状态，新增主进程目标／分块授权与必要UI，再执行软件、类型、新包及真实UI。先核对当前构建／旧接口边界；不使用被拒绝的replyDraft／attachment.import、不用日常凭据／剪贴板。真实Foxmail对照、系统保存及Claude／钥匙串仍按各自原前置独立补验。

实际结果：原草稿修订与原邮件历史的必要文字附件查看已补，117唯一软件、类型／原型构建、最终OR4包六原生、真实浅深10组及3布局通过。二进制保存与真实客户端对照继续，不改变原范围。见[验收记录](../验收/OR_T15附件文字查看与缓存复核修复_20261028.md)。

保存接续：新 `MailAttachmentTarget` 与 `MailAttachmentViews.view` 可复用确定原成员／文件名／hash；读原邮件与交付资源需保留各自审计身份，不能在同一operation先read再resource引发来源账冲突。现有 `FileActions.copyTo`／原生copy有新目标排他提交、覆盖竞争校验、写入内核范围和恢复记录；恢复配额与已保存历史清理须一并接通，不能直接挂M9工作区或留下不可处理的限额。主进程dialog选择目标、复核源和权限后写入；保护App数据及全部配置的原Foxmail只读来源，默认文件名不含路径。未知结果不自动重试／覆盖。原生文件选择器仍需按系统层取证，程序化回调仅算I；不得用CDP绕过已拒绝的原生回复／导入路径。
