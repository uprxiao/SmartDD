## 来源与统计

官方 [easysoft/zentao-api 固定提交](https://github.com/easysoft/zentao-api/tree/6f57de2ec9647af9f782781eb267b431cba8dbad)，2026-10-14。已静态下载 OpenAPI、版本映射、生成模块与 MIT 许可，未安装或执行 SDK。

入库的[接口矩阵](../调研/证据/zentao-biz13-api-matrix.json)为 **17 条：8 条只读候选、6 条流转研究项、3 条按版本排除默认方案**，包含方法、路径、参数／必填字段、最低版本、JSON pointer 和源码行号。源码及哈希见[来源清单](../调研/证据/zentao-public-api-source-manifest.json)，许可见[MIT](../调研/证据/zentao-api.LICENSE)。原始大文件留本机忽略目录 `release/m10-research/official-zentao-api/`。

OpenAPI 本身不含 minVersion；版本依据为同提交 `scripts/zentao-api-map.json` 经 `scripts/update-registry.ts` 生成的 `src/modules/generated.ts`。SDK 声明兼容只是候选，不能当作目标实例测试通过。

## 1. 读取主路线

| 能力 | v2 路径（前缀 `/biz/api.php/v2`） | 版本声明／复用方式 |
| --- | --- | --- |
| Bug 列表，3 种范围 | `/{scope}/{scopeID}/bugs` | scope=products／projects／executions；SDK 声明 biz13.0，已有 Bug 枚举作为兼容参考 |
| Bug 详情 | `/bugs/{bugID}` | biz13.0；原 v1 详情／历史／附件逻辑继续保留候选 |
| Story 列表，3 种范围 | `/{scope}/{scopeID}/stories` | biz13.0；需要补充本人关系、分页及页面对照 |
| Story 详情 | `/stories/{storyID}` | biz13.0；需要补齐完整字段、历史和文件引用验证 |

范围只在获准产品／项目／执行内选取，不因接口支持就自动扫描全部数据。列表的排序／分页参数有定义；本人筛选需按实际接口验证，必要时规范化 account 后本地过滤，不能把显示名当作账号。

**两个容易误选的接口**：`GET /my/bugs`、`GET /my/stories` 在[生成模块](https://github.com/easysoft/zentao-api/blob/6f57de2ec9647af9f782781eb267b431cba8dbad/src/modules/generated.ts#L11110)标为 biz13.5 起，当前 13.0 不默认使用。公开规范、官网和旧实例记录的 Bug 个人过滤参数存在拼写／行为差异，保留为复验项，不强行统一。

动作级最低版本也不等于参数级版本。最新定义中的 `filters/groupJoin` 等参数没有单独版本信息，不能默认本机 13.0 支持；初次验证优先最小字段与既有分页方式。详情接口返回成功仍须核对正文、验收标准、版本、关联信息、评论／历史及内嵌资源是否齐全。

## 2. 沿用旧 v1 底座

现有 Skill 已实现身份 `/user`、产品 `/products`、Bug 详情 `/bugs/{id}`、文件 `/files/{id}` 及分页／完整性处理，参考[既有能力核对](../调研/企业版13.0现场核对与现有能力复用.md)。本次官方 v2 规范没有列出相应 GET 身份／文件下载，不据此删除已存在的 v1 适配。

旧导出器的“批量导出并保存所有原文”不能原样代替 App 的按需查询。复用接口和校验逻辑，另设计实时查询、独立缓存／引用及 Agent 工具契约；凭据仍由 WillYou 主进程管理，不启用 SDK 明文 Profile 持久化。

## 3. 后续流转研究项

| 对象 | biz13.0 声明的独立动作 | 关键输入候选 |
| --- | --- | --- |
| Bug | PUT resolve／close／activate | resolve 的 resolution 必填；其他字段和权限逐动作验证 |
| Story | PUT change／close／activate | change 的 reviewer、close 的 closedReason 必填；评审、指派及评论等输入按动作核对 |

这些不是本轮已执行或已确认全部交付的动作。`PUT /bugs/{id}/confirm` 标注 biz13.5，列入默认排除。创建、删除、Ticket 及批量自动修复不在本次接口增量清单。

## 4. 下一步验证边界

先复用身份与已知 Bug 样本，按授权范围核对列表／分页／本人归属，再验证 Story 非空详情及文件／历史；当前页面 Story 为 0，空态不能证明详情已打通。数据接口验证后再与用户确定流转动作及审阅方式，准备共享原型和逐条用例。本清单没有触发发布、生产开发或外部状态变更。
