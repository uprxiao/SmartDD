# MS · 缓存损坏原件保留与重建方案

2026-10-27，R1.6＋§12.21，M10-MQ-01及原T17步骤2／4；feature/0.0.2／HEAD f1f1728d68a8595e665d4833dff048189e63e0f8＋工作区。当前实施及本轮实包子集复验完成，沿原clear／恢复授权，不恢复M9、不发布。

复用MR独立cache gate，不放弃主库shared。只有原MailCache.open失败且错误为恢复所需，或已有原授权待恢复intent时，原UI clear才进入独占恢复。读请求不自动隔离；正常cache.clear逻辑保持。独占内以原marker／root／index身份、只读SQLite quick_check的SQLITE_NOTADB／SQLITE_CORRUPT或非ok结果确认损坏，BUSY／权限／格式不支持／源错误不作为损坏。旧非参与host以原index FD preflight前后检查，不能只凭新gate。

恢复不递归删除旧树：在同cache父根创建私有空slot（SQLite version2，原marker＋空objects/staging）；主库既有capability_resource_operations新增专用kind记录store/root、原树digest／inode、新slot身份、原用户clear operationId及prepared/retained/published/committed。原目录整体以既有native anchored RENAME_EXCL移到mail-retained-UUID，原slot原子发布到mail；原件文件inode／字节保持。新format2仅对有原提交lineage的重建根开放，旧程序检查user_version>1会拒绝，避免绕过保留区预算。正常未修复cache继续format1。

阶段之间保存回执并允许仅原intent幂等恢复；pending时普通MailCache.open明确要求继续原清理，不创建空库冒充完成。独占gate在崩溃后由内核释放，恢复仍按原文件／计划身份，不凭PID年龄。目标占用（含空目录）、换root／index、链接及跨卷失败均保留双方。整个旧树不作为active cache，不复用损坏覆盖，原查询须真实重建。

所有mail-retained-/mail-rebuild-保留树只读、无follow计费；未完成注册的自建slot或未知同命名空间内容也保守保留计费，不据名字删除／冒认可删。C提交记录验证已登记retained根身份与新active根lineage。retained字节归auxiliary，计算object可用空间时扣除；它们不挤占原index/control64MiB安全包络，但计入同500MB总额。先预留少量新索引空间再创建，不复制一套旧缓存；不足则明确失败保留。Chromium Cache_Data／No_Vary_Search等非邮件同级目录保持原边界。

旧树保留可能使clear后仍有auxiliary占用，如实返回，不能虚报磁盘释放。草稿／发送及附件业务区、主业务表、源邮箱、会话包引用不参与移动。无新UI入口；原清理确认与占用字段继续使用，若结果说明需补文案则同步原型，不把接口I结果当UI通过。
