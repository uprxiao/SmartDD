## 三断点与一个原场景回归

复用graph-gc-app、原graph-gc-precondition与公共harness；各场景全新独立U/HOME，原资源图为合成无引用H投影＋C应用包，共享当前runtime继续保留，0UI/CLI/model/真实历史/Claude。使用NB原包，不改production或typed资源。

1. **verify-before**：原captureGcTree调用栈内，首次读取精确H投影SKILL.md的原readFileSync执行前暂停。记录原调用栈和未执行原read，实际SIGKILL；此前不得有cleanup-graph日志、资源state或文件变化。正常新宿主不得自动删；由原versions得到可清理计划后显式重试，新的原操作完成。
2. **verify-after**：原verifyGcTree返回后、首次native move调用前暂停；记录精确helper/args、原调用栈、未执行原move、已持久plan及资源deleting/child marked。SIGKILL后普通无wrapper宿主按同operation/plan恢复，不制造新图。
3. **delete-before-removed**：首次精确自有payload的原rmSync实际返回后暂停，确认目录物理缺席而原资源/child仍deleting、尚未登记removed。SIGKILL后普通宿主依据原删除状态补登记同plan并完成；二次重启幂等。
4. 原normal-shared作为默认分支回归，独立U，避免新外部模式破坏原未注入路径。

wrapper只匹配本次root、原目标及指定原调用栈，原返回/错误不替换，pause由本次唯一checkpoint文件证明。先观察原handle/phase，超时不盲重启；故障进程死亡与活进程恢复wrapper分别记录。保留失败点、原始SQL/WAL与physical状态观察；不直接改DB完成标志、plan或所有权。
