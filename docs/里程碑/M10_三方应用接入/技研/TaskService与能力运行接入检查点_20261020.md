# TaskService与能力运行接入检查点

2026-10-20，R1.6（含12.21），独立feature/0.0.2。此文记录DEV003-E实际实施范围；详细业务仍以[需求](../需求.md)为准。[结构化证据](../验收/证据/m10-dev003-e-20261020.json)包含源hash、红测及最终结果。

## 已实现

TaskService的create／open等待能力准备，主进程可注入TaskCapabilityLauncher。此接口只接受宿主派生的项目、任务、原生根、AI配置及原快照，不接受renderer提供的run、PTY或PID。普通RPC仍返回原OpenResult，只是服务过程可等待／取消。相同任务的并发恢复合并，准备中也计入项目运行检查；停止、删除、退出可取消准备。

生命周期依次为prepare→beforeSpawn→原生fork→spawned，退出／停止交给原所有者。PTY沿用预留UUID，PID来自实际node-pty句柄；SQLite保存失败、PID登记期间退出、关闭期间登记和fork失败分别处理。已arm而PID未知的窗口保留占用，不伪造未启动。受管临时T目录不由旧通用dispose／exit清理，等待所有者确认CLI、桥及执行者结束。

原生根及Claude隐式默认配置行为保持原规则；Codex首次ID补写期间禁止另一轮领取不同候选，内存claim防跨任务重复。实际fork时间作为rollout查找起点，避免异步准备／登记时长漏掉已落盘的原生文件。长期版本及会话引用不因一次停止释放。
