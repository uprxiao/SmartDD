# 原生受信输入来源检查点 · DEV003-F

2026-10-20；需求R1.6含12.21，承接R08-01–03、R07-08／11和实际运行生命周期。独立worktree `SmartDD-m10`、`feature/0.0.2`，基础提交`5362772`，原型仍为`8466734`。本批为“明确原生用户指令”路径的来源底座，**不是已经完成的原生授权或生产Agent启动器**。

## 实际写入后采集

复用PtyAccess的真实main-frame、task当前PTY和存活检查，只有owned write成功后才调用主进程observer。窗口、子frame、错误task／PTY、过大输入、原生write失败均不进入来源记录。observer仅收到宿主检查后的taskId／ptyId和实际已写入字节，不透传renderer自行附加的runId等字段。resize和上下文插入的authorize检查不铸造键盘来源。observer失败不改变已经成功写入的结果，避免调用方把它误当输入失败而重复发送键盘字节。

ApplicationService已接observer到NativeUserInputs；运行注册表仅根据实际task／PTY、当前host实例及active状态找到唯一run，再检查原会话和资源占用，不使用renderer提供的run身份。当前生产TaskCapabilityLauncher尚未完成创建／attach注册表，未就绪时来源为空；测试里的attachRuns及受管生命周期不是日常App已经运行此取证链的证据。

## 有界RAM来源与编辑

正文仅保存在RAM，不写SQLite、调用日志、证据或用户目录。最多128个编辑状态、256条已提交记录、合计16MiB UTF-8文本预算；单行／输入片段上限1MiB，已提交来源10分钟过期。预算同时计算未提交编辑缓冲与已提交记录，超过时淘汰最早记录／编辑状态。运行停止、PTY被另一run使用、固定能力选择变化或服务关闭后清除对应记录。记录对外仅含来源ID、项目／task／run／PTY、固定选择hash、文本hash、时间及实际frame编号，不返回正文。

输入重建处理普通Unicode、分块UTF-16对、退格、Ctrl+U／W／C、CRLF，以及分块bracketed paste。粘贴中的换行不当作提交，结束标记后还需实际提交键。未知控制、历史或光标协议使当前重建不可用，清行或下一次提交后才重新开始；不猜测TUI的光标／历史内容。此重建不是对所有CC／Codex实际编辑键的验收；后续必须用原生真实user消息逐字核对，无法核对的字节不能自称已被CLI当作用户指令接受。

一次输入含大量提交行时，先用固定容量环保留最近256行，再生成回执，不在片段内部短暂堆积无界回执对象；这来自提交前源码核对，不虚构此前测试红测。实现避免对每个字符重复计算整行UTF-8长度，大粘贴使用增量字节计数；分块surrogate连接与删除保持正确字节边界。首轮Ctrl+W测试发现词前空格被错误删除，保留原期望，修正重建后复验；没有将不同的重建正文当作原输入。

## 运行、原生身份与消费

来源绑定run、项目／task、PTY及固定选择hash。选择hash只允许首次补写原生sessionId这一已有流程，不把原生ID绑定误判为换包；首次与实际用户消息匹配后固定具体sessionId，已有原生ID不能换成另一会话继续匹配。匹配还要求完整正文一致及有界原生时间，不能只比较“包含发送”等关键词。RAM回执不可变且检查原对象身份，复制同字段对象不能消费；同一来源只能归属一个具体intent，重入同意图幂等，不能拿来批准另一封邮件。

`match`和`claim`目前是主进程内部原语，**没有模型／renderer RPC**；它们不创建mail_user_action_sources、不生成grant、不调用SMTP。调用者目前尚未接读取实际原生user记录的验证器；传入字符串和时间本身也不等于取得原生消息证据。`claim`只登记来源占用，不做授权语义判断。停止或过期后不能继续使用。

## 验证与后续必须工作

验证包括纯来源边界、真实PtyAccess的成功／失败顺序及observer异常、真实私有SQLite／Session／Run注册表的task／PTY归属，以及原Mail CJS链旁路验证：首次原生ID补写前后的来源关联可保留，另一个run不能使用，记录来源后发送仍未授权，来源表为空且SMTP无消息。WebContents、CLI PID身份和cipher仍为明确夹具；没有实际原生键盘／IME、CC／Codex用户消息、真实产品窗口或打包App通过数。
