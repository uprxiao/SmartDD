# OS：T15 系统保存与复制材料生命周期

依据 R1.6＋12.21、R06-03、R08及原T15，沿用范围内实现／测试授权；feature/0.0.2，34/72、余38、目标active，不恢复M9、不发布。OR已完成附件文字查看；普通二进制保存与系统层仍未通过。

复用原生broker的copy／save身份、修订、恢复材料及内核写范围，不另造无保护的文件写入。M10独立管理受控导出记录，不打开M9工作区。源bytes经现有目标成员与hash验证，私有暂存只由主机创建；主进程系统保存对话框给出目标，页面不提交路径。已有目标再按已检查修订明确覆盖，期间变化拒绝；新目标排他安装，不自动改名或覆盖新出现的文件。

原copy会保留事务／恢复材料。新增仅对saved copy且op／fingerprint／目录与文件身份匹配的收尾能力，清理只作用于本次材料，不触碰最终文件、原附件或未知材料。失败／未知保留，重启只检查状态／已有结果，不自动再次复制。恢复材料计入mail业务空间并受project/global预算约束，不能留下不可处理的永久限额。保护App用户数据及全部已配置Foxmail只读来源，默认名去路径。系统取消不写输出；阶段操作正常退出与测试清理分开。

技术顺序：先实现／测试原生saved-copy收尾与主机导出状态，覆盖成功、已有目标／替换竞争、目录／符号链接保护、失败／未知／重开、已保存材料清理；再连UI保存与覆盖确认／结果，补原型及类型／新包。每次分块／源核对仍走OR权限；原邮件read与resource保留不同审计身份。现有Native reply／attachment.import拒绝边界不变，不调用它们准备保存，不用剪贴板、日常凭据或真实邮箱。

真实系统选择器的证据与程序化回调I层分开；若系统权限需要用户操作，登记缺项继续独立用例，不用CDP伪装通过。计划时尚未执行，实现与实际结果见文末链接，原T15不预先升级。

快照位置补充：私有暂存位于mail业务根内，使中断材料仍进入业务空间统计。copy增加主机可选sourceProtected读取排除集合，仅M10自建／身份与hash核对的privateObjects快照显式为空；目标仍使用完整保护集合，既有M9调用不传该字段，沿用原行为。渲染端目标schema不接受路径或sourceProtected，未给Agent新增工具／写权限，也不调用附件导入RPC。
