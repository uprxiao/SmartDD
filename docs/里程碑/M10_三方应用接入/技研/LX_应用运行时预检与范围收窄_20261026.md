# LX 应用运行时预检与范围收窄

依据：已确认 M10 需求 R1.6＋§12.21，R07-10／R08-04–06／R10-10／R10-12；验收 T56。范围内缺陷 M10-LW-01 沿原开发授权修复，无新增业务／UI／发布范围。

## 原因与业务红测

[LW](../验收/LW_T56坏构建原生链与未完成窗口_20261026.md) 的原始未知账继续保留。LV 只拒绝错误 Node 启动，没有在签发票据和预留桥进程前核验运行时。因此原生 Agent 普通回复可完成，桥却从未取得可记录 PID；实际停止后 CLI 退出，桥 armed、run stopping 和活动租约被正确保护。

LX 在改生产源码前，先将坏构建用例与 Skill 成功发现的正控分开，明确预期为：固定 S 仍含 Mail，本轮应用 scope 为空且有 HOST_INCOMPATIBLE 原因；不预留桥、不签发业务凭证，独立 M4 保留，实际停止后本轮生命周期关闭。第一轮新增只读夹具误查不存在的 selection_hash 列，已保留并修正列名；第二轮旧 LV 坏副本在明确生命周期断言业务失败，保留 stopping／armed，不通过改账制造通过。

## 实现

- `embedded-node-runtime.ts` 仅以当前 `process.execPath` 执行无业务权限的 `-e` 自检，环境只含 ELECTRON_RUN_AS_NODE=1；核对随机标记、当前 Node／Electron 版本及 Node 上下文。没有 PATH Node、Python 或备用运行时。最多接收合计 4 KiB 输出，5 秒超时／取消时停止本次子进程并等待退出／管道关闭；启动同步／异步错误均判不可用。
- 成功结果仅缓存于本次宿主实例，失败可重试；同次准备复用同一检查结果。新建快照发布应用投影前、恢复会话预留运行前均检查。无应用选择及原 M4 旧格式不新增运行时要求。
- 失败沿用既有 independent-capabilities scope：固定 S 的包／标准 Skill／MCP 选择、版本和原生身份保持；本轮 App 根和桥不进入运行。受管标准 Skill 与项目上下文 MCP 继续准备，不把整个运行标成 native-only。不可用原因仅记在 App 排除回执和逐能力准备记录，不能据此追加权限。
- `application-run-scope.ts` 的排除原因增加已有错误码 HOST_INCOMPATIBLE。原数据不迁移、不覆盖；旧宿主若不能读取新回执则按既有未知保护拒绝推断授权。
- 运行中检查结果恢复不扩权；须正常停止，再用原 native ID 和固定 S 显式恢复新 owned run，才重新准备应用桥。原 LW 已有未知窗口不会被本修复改成退出。

## 验证边界

新增软件验证包括实际自检子进程、错误输出／超额输出、启动失败、超时、取消及失败后重试；组合层覆盖 Codex／Claude 两种适配计划各自新建／恢复、独立 M4 保留、无桥预留、拒绝 App 调用、租约释放及下一 owned run 恢复。组合层使用既有模拟 PTY、身份和安全存储，不冒充实际 Claude／系统验收。

首轮 11 项中 7 过、4 失败均保留：1 项真实发现同步 spawn ENOTDIR 未转不可用，已修复；1 项为夹具 100ms 在进程写 PID 前超时，改为 1000ms，仍断言物理 PID 退出；2 项误把 Claude 原设计的范围交付回执要求为 undefined，改为明确验证恢复后的 Mail 范围、真实服务授权和新桥。未缩减原验收要求。
