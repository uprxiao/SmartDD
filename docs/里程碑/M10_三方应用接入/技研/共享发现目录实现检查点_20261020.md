# 共享发现目录实现检查点 · DEV003-D

依据：需求R1.6含12.21、[运行时设计6.2／6.8／8.3](应用包与Agent运行时详细设计R1.6.md)。本文件记录实际服务层实现及证据边界，不替代需求规则。源码提交从[DEV003-D证据](../验收/证据/m10-dev003-d-20261020.json)关联；任务启动接线与产品验收尚未完成。

- `discovery-catalog.ts`以显式传入的实际HOME解析规范根和摘要；在`.agents/smartdd-runtime/`保存清单、维护意图与消费者，按完整原Skill内容复制到版本化名称。没有隐式读取日常HOME。来源必须与原包／旧M4树逐文件、执行权限及摘要对应。
- `discovery-catalog-lock.ts`以原子mkdir协调，记录随机token和宿主PID／内核启动身份；释放核对token及目录inode／device。H→C→DB顺序，文件复制／校验不放入SQLite写事务；无年龄／PID超时抢锁。
- 发布先登记H意图和本C操作／完整依赖占用，再在同H文件系统暂存；目标rename及清单更新持H锁完成；最后C标ready，清除自己的门闩。消费者未释放时等待，有界取消不会删除原目录／引用。四个已执行中断点沿相同归属、完整内容和原操作账恢复；本轮不证明物理断电持久性。
- `reserveRun`先登记H reservation，再在本C以相同run／PTY身份登记。`release`只接受本run权威记录的停止／撤销、全部子进程结束及无活动执行者；保留PID空启动窗口和回执丢失。跨store只能读取协调文件决定等待，不访问或清理别人的数据库。
- 0014保持既有resource主键及外键：旧`relative_path`继续作为兼容唯一存储键；H键包含规范HOME、实际相对路径及投影摘要。`scope_identity`／`scope_relative_path`和发现根表给出实际H位置；`ResourceStore.get/directory`返回实际位置。有效H位置另有唯一索引；未发布撤销项保留removed记录和原操作，而不继续占用尚未发布的地址。C资源路径与原hash不变。
- 清单已初始化后丢失即待恢复，不能重新建空集合；链接／损坏记录、同名异store、未知消费者及依赖账损坏均拒绝静默修复。固有版本映射、旧会话选择和用户文件不改名、不覆盖。

验证使用真实临时文件和SQLite、实际适配器生成的Codex启停参数。进程退出／复用由明确夹具模拟；多store同进程，不把OS mkdir原子性或这些U/I结果说成真实多App并发通过。全部29条目录测试、迁移与受影响回归、类型检查的日志和源摘要见证据。
