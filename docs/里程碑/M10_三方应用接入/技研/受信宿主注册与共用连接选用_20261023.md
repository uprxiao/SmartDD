## 实现与复用

- 新增主进程 `HostApplicationRegistry`：宿主编译期明确登记应用、来源槽、配置schema、认证类别／模式、权限映射及切换前停止策略；重复、缺项、未知版本、未登记槽和额外契约字段拒绝。没有 RPC、用户路径加载器或公开安装入口。生产默认仍是禅道／邮件以及原三个来源类型。
- `ApplicationConnectionService` 直接复用原候选测试、独立回执、CAS提交／丢弃、秘密日志与恢复、启停／断开和历史契约影响检查；新应用使用同一个类和同一个 SQLite／SecretsStore，不复制生命周期。配置、账号身份、持久化来源及 API 版本必须与当前宿主一致，显示和凭据解析均重新核对，不让一类来源的配置取得另一类连接的秘密。
- `ApplicationSelectionService` 从同一受信定义读取项目槽和停止策略，保留原全局添加／启用、每项目显式单选、槽修订／policy、变更日志、停止及回滚流程。没有健康连接自动回退。生产外层 RPC／表单 schema 仍拒绝实验应用，fake 不进入产品目录。
- `0026_registered_application_hosts` 在原库中增加身份外键元信息并重建五张原表，保留行和列字节、连接身份／修订、秘密引用、候选日志、绑定和发送意图引用。新元信息行不授予执行能力，每次使用仍需当前编译的定义。FK重建仅在独立事务外临时关闭本连接检查，提交前完整核查，异常回滚并恢复原FK开关；原来已损坏的数据保持原样并报告，不能丢弃以强行通过。
