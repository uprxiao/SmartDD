# Claude静态投影来源与原完整插件归档 · 2026-10-22 AV

依据M10 R1.6含12.21及已有开发授权，承接AU。当前仍第5步：新增原生目录交付需要的不可变来源与归档；**原Claude主入口红测仍失败，canonical交付／占用与恢复尚未接线，REVIEW-01未关闭。**

## 已实现

SessionCapabilityProjector可将原S中的健康原应用完整Skill目录及全部原标准Skill保存到C内的独立不可变来源目录，带完整原选择摘要、task、原sourceHash、原名称和实际Skill路径。来源完整树复制保留二进制文件、执行位及相对资源；不写canonical插件路径、不改S、不删原引用。读取经过完整OwnedBundle／逐文件哈希、依赖、所属会话引用及读取后的资源登记复核。

已有完整canonical插件可先按其真实已登记的原hash归档。源应用包后来缺失或被标不可用，不妨碍保存该已校验的完整静态插件；源状态、原资源和引用保持原样。原目录缺失、被用户增改、符号链接／执行位异常或另一个任务的目录均拒绝，不能凭包元数据补造旧完整插件。归档保存全部原字节并核对原hash；新视图和原归档有明确view／archive角色。

静态来源使用既有C发布／完整树校验，不新增运行或发现回执。来源与归档均**不被接受为显式原生投影根**；归档没有执行依赖或业务授权。阶段长引用可以保存两类静态产物，读取仍验证原S和实际身份；主启动与诊断的既有新旧资源分派能识别它们，真实canonical路径仍须独立成立，不能以静态副本代替原生加载证明。

原claude完整构建提为共用构建过程，完整情况下保持旧hash。测试保留AU提交5783feb的真实生产projector兼容夹具，仅增加来源注释并调整相对import路径，已核对原SHA256。先由旧生产实现对同一个S生成实际完整插件，再核对新来源相同hash、字节与路径；不是仅比较新实现的两个分支。原生ID首次绑定后规范化选择及来源身份不变。
