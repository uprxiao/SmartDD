# NU 启动升级前运行恢复补验

2026-10-27，沿R1.6＋§12.21授权，原T54/T65启动恢复及已批准的异常恢复边界；正式仍32/72，40条未全验，现用NT包。先核对NL/NK原失败及当前代码，不重启或修改原otC54B数据库／默认／S／引用。

NL原现场含armed却无PID的桥接记录，身份未知必须保护；不能仅凭10个有登记旧PID已退出就清掉未知消费者，也不把本轮恢复工作解释成已找到第五run来源。原M10-NK-01保持未定因。

另一个具体待验证实现缺口：openManagedDatabase在新分发激活前恢复UI/index消费者和H发布，但run.recover要到稍后服务创建才执行。以独立原生SQLite／真实资源和包／受控内核身份账构造三种最小历史：所有登记进程确认退出、尚有活子进程、已armed无PID。只有第一种应按现有run恢复协议停止并释放短期占用，允许升级；其余继续保留并拒绝维护。保留原S、长期引用、旧包和业务数据，不通过改default或伪造退出求绿。

先用现有runFixture／managed-client测试创建真实登记和准备状态，运行原代码找红测。若证实缺陷，提取复用已有恢复/完成逻辑，在完整schema下、独占启动维护权内、激活预检之前恢复可证明的记录；不初始化业务服务、不放松维护检查、不停止任何实际Agent，不把unknown当stopped。补原run和managed-client必要回归、类型及新打包App实际故障恢复；初始红测、原现场边界、源码、包及结果分层归档。0日常凭据／发送／UI／Claude，不发布。
