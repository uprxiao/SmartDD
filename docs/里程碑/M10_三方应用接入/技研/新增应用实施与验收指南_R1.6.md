# 新增应用实施与验收指南 · R1.6

2026-10-23 BL增量：主进程 `HostApplicationRegistry` 接受随宿主编译的应用／provider定义，连接候选／秘密恢复及项目选用已由原公共服务参数化，`0026` 在原SQLite登记身份外键并保留旧引用。默认产品仍仅两应用；不是动态插件加载或manifest授权。两fake应用／连接／项目及迁移软件验证见[受信宿主注册与共用连接选用_20261023](受信宿主注册与共用连接选用_20261023.md)。完整发现、执行context、Data API、工具调用权限与日志实验仍待接续，T39／T40不计整条通过。下面保留2026-10-20的阶段事实，涉及连接／项目选用的旧硬编码说明以本增量及实现为准；其余未知项未因此解决。

2026-10-20。依据[需求](../需求.md) M10-R09、R10及第11、12节；核对生产代码基线 `1f1390baf52c980c3e8f265f18700f22e30fed72`。本指南是当前实现的扩展落点及未来开发步骤，不是插件 SDK，也不表示本期已接通 Jenkins。早期候选接口及14项合成实验保留在[历史V2方案](多应用适配与Jenkins扩展方案V2.md)，不能直接当作当前 TypeScript 接口。

当前交付目录仍只有禅道、邮件两应用；新增应用须先安排需求、确认原型和范围，再修改受信宿主并随应用构建。以下使用虚构新应用的只读能力作纸面推演；没有地址、秘密、真实请求或 Job。未来写操作、平台、调度的具体范围分别评审，不因列出落点而成为 M10 交付项。

## 1. 先区分三层“登记成功”

| 层 | 当前事实及验证入口 | 不代表什么 |
| --- | --- | --- |
| 完整包声明／资源安装 | `src/shared/applications.ts` 的 `ApplicationManifest`、`manifest.ts`、`PackageRegistry` 支持合法的通用应用 ID、完整文件与不可变版本；同 ID 同版同内容幂等，同版异内容拒绝 | 不保证该应用有宿主连接、工具执行器或 UI |
| 可信分发／固定工具执行 | `CapabilityBundleSource` 与 `BuiltinPackageRegistry` 保留具体分发索引依据；`ApplicationAdapterRegistry` 只执行已批准原包中的纯 CJS 分派器，注入版本化 Data API | 不是用户路径加载器；VM 不是不可信代码安全沙箱；安装一个测试包不能提升为可执行插件 |
| 当前产品业务 | `application-connections.ts` 的 app/provider/config/项目槽和 `application-adapter-registry.ts` 的方法命名空间明确限制为当前两应用；`ApplicationService`、Data API及页面显式接线 | 不是 manifest 新增一行即自动获得新认证、资源、项目选用、权限或动态表单 |

包里的 `connectionContracts[].authModes` 是原版兼容元信息，字符串合法不等于宿主支持该认证。当前配置 schema 才决定可接收的认证；认证测试和身份回执由真实 verifier 产生。旧 V2 的 `ProviderDefinition`、`effect`、`reconcile` 是研究示意，不能复制为现存 SDK 调用。当前工具效果由原包 annotations、固定 operations.json 的 read/write 与 retry、宿主执行器共同核对；外部业务结果独立记录。

## 2. 按顺序实施

以下路径均相对于仓库根。负责人是职责角色，不是已经分派的人员；同一开发者可以承担多项。

| 步骤／责任 | 可复用入口 | 新应用必须补什么／进入下一步的证据 |
| --- | --- | --- |
| 1 范围与协议；需求／适配开发 | 本 M 需求、原型、验收格式；R09边界 | 冻结 app/provider/对象／权限名、目标平台、外部版本、只读与写入边界及异常恢复；先建立新阶段，不向本期目录放未来能力 |
| 2 完整应用包；资源／适配开发 | `resources/applications/definitions.mjs`、`resources/applications/adapter.cjs`、`resources/applications/<appId>/<version>/`；`scripts/applications/build-bundles.mjs` | 新定义至少含完整 Skill、连接与工具输入／输出 schema、权限、原版运行时绑定、许可；不得只交元信息或覆写既有1.0.0内容 |
| 3 连接及身份；宿主／provider开发 | `src/shared/application-connections.ts`、`connection-service.ts`、`providers/connection-verifier.ts`、`SecretsStore` | 扩充明确的 app/provider/config/身份类型、providerApplication映射和 verifier 分派；补无业务副作用的认证／身份测试。不能让新 kind 落入现有 Foxmail 分支；秘密不出主进程 |
| 4 项目选用及兼容；宿主开发 | `selection-service.ts`、`package-config-views.ts`、session/run registry | 定义明确槽、无选择语义、连接角色／修订影响、原包配置兼容转换；新身份必须重新选用；旧会话仍固定原包，不能改用最新版本 |
| 5 工具与业务；适配／宿主开发 | `application-adapter-registry.ts`、`business-data-service.ts`、`tool-service.ts`、`private-broker.ts` | 扩充方法命名空间与固定路由，注册受信 Data API处理器和相同执行语义；新增具体对象／参数／分页／进度／外部写规则，不复制整个 broker。客户端不得提交项目、包或授权自报来扩大身份 |
| 6 来源、资源及持久化；业务／数据开发 | `data-resources.ts`、`application-data.ts`、业务服务和数据库迁移入口 | 设计连接＋对象＋修订身份和私有定位；增加资源 provider。kind可扩展，appId与权限仍受当前类型和context限制；不能用任意 URL／路径代替来源校验；预算、内容哈希、撤销及读取后的再校验需要测试 |
| 7 入口与调用来源；主进程／UI开发 | `execution-context.ts`、`application-service.ts`、控制器、`src/renderer/features/applications/` | 新增具体可见入口、表单、项目选用及业务视图；声明受信UI动作和权限。既有调用记录骨架可复用，业务进度和状态映射需单独做。P09、终端来源联合类型、提示示例也需显式扩展 |
| 8 校验、验收与交付；开发／测试／文档 | 本指南第6节、共享真实App驱动及阶段用例账 | 合成实验→单元／集成→新打包App→目标外部环境／系统层，分别留证；完整包哈希、源提交、许可、平台与未决项可追溯后才能给出完成结论 |

上述 `*.ts` 服务简写均位于 `src/main/core/applications/`。扩展前同时检查数据库的应用／provider／资源／审计约束，按实际需要新增迁移；不能仅让 TS 编译通过就认为持久层兼容。页面名称、图标和品牌按根 AGENTS 维护。

## 3. 主流程与应用职责的边界

| 方面 | 共用流程 | 独立实现／拒绝条件 |
| --- | --- | --- |
| 连接 | 候选测试→回执→提交／丢弃、CAS、秘密恢复、启停／断开、健康状态 | 实际认证协议、服务／账号稳定身份、读权限测试、重定向／证书／本地格式；测试通过不等于业务动作成功；不支持的认证显式拒绝 |
| 发现与调用 | 原会话固定包、实际 run/PTY与内核进程身份、受信分发、原输入输出schema、当前策略重验 | 对象范围／API差异；每次调用仅原路由一次Data API；schema失败／无权应在业务调用前拒绝 |
| 权限与写入 | 宿主不可伪造的 context、操作／调用身份、撤销、审计 | 实际动作审阅与明确意图绑定；manifest或模型自报 approved不能授权。新写能力必须补自身授权与外部结果核实，不能直接套邮件语义 |
| 错误与取消 | `ApplicationError`、工具调用账、AbortSignal／deadline、有界执行、持久回执 | 当前只读可按语义有限重试；write retry必须never。取消本地等待不等于远端取消；提交后超时／断线保留unknown，刷新／重启不自动重放写入 |
| 业务状态 | 调用结果与独立业务记录可关联，原连接／对象／修订保留 | 邮件服务器接受不等于送达；未来队列／构建结果另建契约，不能把工具完成统一映射为外部成功；旧审计不重新执行动作 |
| 资源与恢复 | 不透明句柄、项目／应用绑定、内容修订、分块／字节预算、当前策略复查 | 外部定位、分页／日志游标、未下载／不可读、HTML惰性呈现；完整业务恢复规则由该应用定义，不能靠通用重试补写 |

对应当前实现可分别追踪禅道 `zentao-data-service.ts` 与邮件 `mail-read-data-service.ts`、`mail-draft-service.ts`、`mail-execution-service.ts`、`mail-send-data-service.ts` 等实际业务文件；准确文件名以下方源码导航为准，新增服务无需复制这些业务分支。

## 4. 版本、数据迁移与保留

应用版本、包内容 hash、工具 contractMajor、host/data API、连接 configApiMajor／identityContractMajor、runtime hash／协议、Agent adapter版本及外部服务版本分别记录，不能互相代替。完整文件、原Skill及原工具契约随包固定；新默认只影响后续新会话。

`PackageRegistry` 接收宿主注册的 `ApplicationDataMigration`（appId/id/checksum/run）。声明的迁移必须连续且checksum匹配，缺宿主实现时不激活；包中的 SQL 文件不会自动获得执行权。迁移和默认切换失败回滚，保留旧默认与历史资源。应用数据迁移和程序数据库结构迁移分别实现、验证。

共享 C/H 原件、派生投影、runtime／adapter依赖均沿用 `ResourceStore`、session refs及run leases；新服务不能私自删除正在用或历史引用的资源。当前已做版本占用及无派生占用C原件清理；完整共享派生／依赖GC与修复仍在M10开发中，不能承诺已全部可复用。身份未知或原件损坏失败关闭，不重算为最新包。

构建流程需要同时核对新旧包原文件和索引。运行时或公共adapter输入变了会影响包内容；使用新版本并保留旧版，不能悄悄更新既有1.0.0 pin。实际命令为：

```sh
# 在开发worktree执行，输出到本轮独立临时目录；不安装、不启动窗口。
node scripts/applications/build-runtime.mjs /private/tmp/<本轮唯一根>/runtime
node scripts/applications/build-bundles.mjs /private/tmp/<本轮唯一根>/bundles /private/tmp/<本轮唯一根>/runtime/mcp-bridge.cjs
```

随后用 `scripts/applications/verify-bundles.cjs` 导出的校验器与该包声明的 appVersion核对；生产打包入口 `pnpm package` 已做相应准备和原生校验。包含依赖或复制源码须更新 `NOTICE`／对应许可，不引入未核验的 SDK。此处是操作模板，本轮文档评审没有重新构建或发包。

## 5. M11调用契约与未来Jenkins推演

当前受信producer只有 UI／management、Agent及受约束索引来源；`ApplicationExecutionContexts` 使用主进程私有WeakMap登记。**当前没有scheduler producer，也没有已实现的M11调度API。** 未来M11需在其范围批准后新增主进程受信 producer及不可伪造的任务／触发身份、项目与连接选择、权限／修订、运行占用、operation/request幂等身份、取消／deadline和审计来源。不能构造JSON冒充Agent，不能把计划任务伪装UI或借mail索引context发起写操作。

M11可复用原包／Data API和调用账的结构，具体producer入口与数据字段尚未实现；也不能直接把 `ApplicationToolService.call(runId,...)` 当作脱离真实run的调度API。共享服务应先确定受信调用上下文，执行前及异步返回后重验，失败／unknown不重放写操作。原需求、M11需求和未来实施用例共同冻结后才开发，当前纸面可追踪到这些明确的扩展点。

| 推演对象 | 复用内容 | 必须另做／当前缺项 |
| --- | --- | --- |
| 未来Jenkins只读 | 包／Skill／schema、连接候选与秘密、项目选择、固定Data API／资源、当前权限和调用账 | 新app/provider/config／认证测试、命名空间、Job等对象与外部版本兼容、只读查询／资源、UI、数据迁移及实际环境验收；当前均未接入 |
| 未来触发／取消 | 调用身份、写不重试、独立业务结果／审计结构 | 具体动作范围、参数、明确授权、queue/build身份、结果核实、远端取消语义和未知恢复；先评审，不随只读自动开放 |
| 未来定时触发 | 公共执行服务和不可变能力包 | M11受信producer、调度身份／数据／恢复、权限变化和重复触发测试；当前无API，不承诺已经可调用 |

V2第4–5节的Jenkins官方材料与外部版本是2026-10-17研究时点；本轮未重新联网核实，不能视为目标实例事实或最新版本。当前推演不需要真实地址、账号或Job，不创建这些资料。
