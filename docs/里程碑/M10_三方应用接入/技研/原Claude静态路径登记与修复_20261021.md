## 实现

- `LegacyOriginalPlugin`从最初持久的任务／manifest／原路径、C资源库身份及已验证完整plugin来源生成原静态目录；不搬到新格式目录、不改原Skill／MCP名，也不重建旧context／数据库连接临时文件。现存完整旧运行目录保持只读核验，不在恢复中删除其临时内容。
- 复用资源发布器登记`legacy-static-plugin`资源、对原档案的依赖、长期session ref及操作／占用记录；引用与初始登记在同一事务，物化在私有staging，复查后发布ready。已登记内容缺失时保持同资源身份／hash，修复增加generation；发布后已捕获的失败可沿原操作恢复，原任务／原生ID／快照选择和长期引用保留。
- 归属限定为原任务证据指向的本store规范C路径，核对C根storeId和每层目录；不改签另一资源登记、不跟随别名或软硬链接、不覆盖用户文件、未知空目录或不同字节。读取AJ的共享C来源证明，发布前短事务重查来源与目标身份、维护状态、本任务运行及目标资源占用；原生运行active／orphaned或租约待核查均拒绝，**不清除其记录、不声称旧CLI／桥已经退出**。只结束本次已知安装操作的占用。
- `ResourceStore`增加内部同步发布前置条件，并在安装、缺失修复、恢复和最终发布重复调用。目标存在性改为逐层no-follow检查，修复了dangling目标和C根父目录被替换为别名时可能误判“空路径”的缺口；其他发布者也得到该保护。
- 来源读取、会话引用、迁移和运行／诊断核验认识新派生资源。迁移服务在旧临时清单已清理时登记／恢复该目录，重放不更换原schema2快照；原加载规划可继续核对原路径。修复诊断投影分类遗漏，避免已验证原路径被误报未恢复。诊断不因此标Agent发现／使用，亦不新增应用能力。

这里是迁移服务中的C恢复，`TaskCapabilityLauncher`只补资源核验分派，**主启动链仍未调用自动迁移，legacyBinding的原生能力仍未激活**。未核实owner的staged／verified中断仍保守等待，不把本轮捕获异常后的恢复当作所有真实崩溃场景已完成；H共享目录也未改动。
