## 实施约束与顺序

1. 先提取可复用的有界原生日志只读机制，保持现有用户输入来源校验行为。支持版本以现有实际格式为准；Claude缺环境时不能假定格式通过。
2. 区分发现与读取。仅准备路径、MCP握手、工具成功、命令中提到Skill均不是发现/读取证明；读取不自动冒充目录发现。
3. Codex读取需同run时间范围、原生session/cwd匹配，成功工具结果与对应调用绑定，精确目标投影路径、完整返回正文与当前已核验不可变投影内容一致。截断、未知命令、缺输出、重复call_id、来源变化、旧run或旁项目一律保持unverified。对任意shell文本不求值、不执行日志中的命令。
4. 产品只传状态、证据时间、所属run和脱敏原因，不把日志正文/用户prompt传给renderer。状态不是安全授权，只读诊断不授权任何业务。
5. UI使用实际状态；历史证据与当前run分开，停止/resume不沿用旧run的成功。补单测、集成、前端及打包原生复验；更新共享原型对应已确认状态。
