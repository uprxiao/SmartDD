# JQ 单次邮件日期范围契约缺口与实施

2026-10-23，feature/0.0.2，依据已授权R1.6＋需求§12.3、§12.21／M10-R05-01／T14。源码复核：当前1.0.3工具和host查询schema均没有单次queryDays，用户明确1–100天请求不能直接执行；不是“仅余测试”。回到正式开发，旧JL包不能证明此功能。

## 方案和边界

在query、read、resource_read及读取原来源的reply_create/draft_create/draft_update/attach_import输入增加可选queryDays，严格整数1–100；缺省沿用保存配置。只替换本次目标的配置副本，不写连接或全局默认；无匹配不自动扩大。后续正文/资源/原来源复制须明确传同一单次范围，否则按当前默认重新校验；来源URI不是扩大日期范围的授权。持久草稿/稳定附件已经脱离来源的正文保持原规则。

分页checkpoint由宿主保存单次范围：省略继续沿原值，显式不同值拒绝；配置/身份/项目变动仍按已有守卫处理，不静默切范围。查询/读取回执保存单次参数供重放重新核对；不同范围的增量缓存和生产任务键保持隔离。输出与来源引用格式不改，不把range加进长期身份，也不改已存草稿hash。

提供新mail1.0.4工具/Skill；旧1.0.3定义及资源保持原字节/严格参数规则，新host继续支持旧调用。App版本、分支/tag不改，内部包固定版本规则持续有效。新增参数仅属当前已确认功能，不增加邮箱、发送或写动作权限；无需新页面，配置UI/P原型仍表示默认值，Agent单次范围由新工具/Skill表达。
