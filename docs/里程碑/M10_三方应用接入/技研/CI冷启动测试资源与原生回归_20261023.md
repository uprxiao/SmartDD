## 可复用的冷启动准备

在项目根目录运行：

```sh
pnpm install --frozen-lockfile
pnpm test:prepare
pnpm typecheck
pnpm test
```

`test:prepare`构建当前平台原生文件Broker、内核进程探针、MCP运行时及完整受信资源索引，并实际校验新探针协议／自身PID的就绪；不下载Office／TeX资源、不启动App、不授应用权限，也不生成安装包。测试仍由Electron自带Node执行，以匹配原生ABI。应在一批测试开始前准备，不在另一批读取`out/`时重建。

需要独立空目录验证可运行`node scripts/prepare-test-resources.mjs <本次独立输出目录>`；默认输出是`out`。只有构建就绪不能证明任何正式用例通过。App验收仍按公共流程构建完整应用，使用本次包及其哈希。

Markdown两种原生集成来源分别留证，不能混写为App界面验收。仓库中的未签名构建与包内经过签名处理的原生文件具有不同二进制摘要，各记各的实际hash；不能因源码相同沿用旧原生hash。

## 本轮原型环境缺项

已编制T27／T29／T32表单、取消、隔离存储批量驱动的未验证实验；可见窗口第一次输入前被焦点检查拦下，后续只读系统状态确认`CGSSessionScreenIsLocked=Yes`。没有通过CDP恢复该App输入，也不重复要求用户解锁。

另一独立headless Chromium原型尝试没有系统窗口、没有连接App或日常浏览器；停在页面导航超时，原因尚未确认，同样没有执行表单操作或增加P通过数。两次原始记录与尝试驱动保存；不将环境／驱动未就绪计为产品表单缺陷或通过。尝试源和恢复方式见[原型实验保留记录](../验收/证据/prototype-forms-bq-20261023/restore-experiment.json)，未作为已通过的公共驱动接入。本轮优先继续不依赖屏幕的原生／服务验证。

正式M10目标继续；Claude Code真实分支按既有跨机交接补验，钥匙串、可见App及真实外部资源缺项保持原边界，未发布。

CI固定两worker并为包含完整原生／IO与随后应用构建的job保留45分钟上限。此次10文件实测约13.1分钟；该上限不让每项测试主动等待45分钟，也不放宽生产调用期限。原报告、后续定向结果和未选中项均保留。
