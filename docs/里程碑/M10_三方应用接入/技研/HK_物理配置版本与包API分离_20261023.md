# HK 物理配置版本与包API分离

依据R1.6 §5.8和T59。HostProvider新增独立正整数configSchemaVersion，省略时保持原schema1；configApiMajor保持宿主对外API，不再当作物理schema。ConnectionService将声明版本明确写入已有config_schema_version列并返回，按物理版本核对解码；修改版本计入configRevision。保存计划即使没有历史包引用也绑定sourceSchemaVersion，因此候选测试后宿主物理版本变化会被拒绝。实际包视图使用连接返回版本选择转换器。

扩展宿主真实SQLite生命周期21项＋连接22项共43通过，node类型通过。新增测试证明schema2写入／更新／同宿主重开且登记API仍1，不匹配schema1宿主拒绝读；候选测试后改宿主schema2，提交CONFIG_PLAN_STALE且不落连接。使用私有假加密／受信扩展定义，非系统钥匙串或真实外部服务。

[当前源码及日志](../验收/证据/config-version-hk-20261023/manifest.json)。本批schema2生命周期夹具沿用相同字段形状，只证明版本持久化分离；HE有不同字段2→1纯转换实验，尚未将两者串成原会话完整调用。不得拼接两段宣称完整T59通过。

仍待：非内置provider/目标Schema注册、同身份实际跨格式转换与配置视图／认证handle全链、升级前后持久历史与两版打包。当前内置生产格式仍schema1，不擅自迁移真实账号。正式16/72（22.22%），T59开发中，GT旧包不代表本批。
