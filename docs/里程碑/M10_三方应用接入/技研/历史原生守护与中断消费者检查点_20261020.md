# 历史原生守护与中断消费者检查点（DEV003-I）

依据：需求R1.6（含12.21）、运行时设计9.3／8.3、基础提交6191f0d。独立`feature/0.0.2`，应用仍0.0.5，M10保持开发中。

## 已接路径

没有v2指针且确为无快照／格式可识别但能力来源尚未核实的旧任务，不再一律阻止原生入口。schema0 hold继续保留未知来源；主进程只登记独立native guard，复用Run的资源闭包、真实PTY PID／启动窗口、撤销、实际退出及保守恢复。guard的生命周期权限与业务权限分开：`assertActive`／bridge preparation／bridge reservation均拒绝，PTY输入不生成M10用户授权来源，不能获得应用凭据或发送能力。

Codex使用完整当前H清单为受管Skill生成false覆盖，保留用户Skill启停及原生MCP；不追加WillYou应用／项目上下文桥。即使目录为空，也先把精确HOME登记进本数据根，再写H消费者意图。已验证不消费H的CC保留原生入口；未知版本保守登记目录占用。不能安全保留当前配置并隔离已有受管目录时，明确拒绝交接，不以空配置替代。此处短暂加载计划不写为v2会话或作为迁移／应用授权证据。

旧任务`runtime_snapshot`在打开、自检、首次Codex ID写回及退出路径均原文保留。当前运行的“历史能力未知”只作为内存诊断提供；不把guard状态写成新的固定能力快照。非空损坏／不支持的旧数据拒绝；已有v2登记却丢失任务指针时不降级、不改原保留状态或原快照。已标记损坏的schema0依据也不能借原生守护重新授予能力。

## 中断与关闭

主进程启动先执行Run恢复，再遍历本C登记的确切H根，验证canonical HOME与homeId一致后恢复消费者；根错误记安全代码供诊断，不擅自重建其来源。每条只处理本storeId、同U fingerprint的消费者；原宿主PID／birth仍活或unknown均保留。C中Run必须已经终止、revoked、所有子进程／activity结束才删除本次消费者文件；活子进程继续保护。H preparing意图已写而C-only reserve回调从未提交的情况，只在原所有者已证明停止且phase仍preparing时释放；其他不完整状态保留。其他数据根文件不清理、不改签，不按文件时间抢占。

关闭并行等待Run撤销、子桥监督与broker关闭；某个owned PTY stop失败仍撤销私有通道。实际子进程和租约保持active／stopping，不能将发过停止请求当退出；后续同一owned退出才释放。这里只实现消费者恢复，不代替完整资源GC、遗留T清理或死锁／发布意图的全套维护恢复。
