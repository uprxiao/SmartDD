# M10 原静态Skill路径保留与留存重开 · AI · 2026-10-21

当前按AGENTS.md第5步正式开发，依据R1.6＋12.21的R10-06／09／11／19–20及既有授权。此次完成DEV-02的一部分：避免旧M4原Skill路径在普通运行清理中被删除，并支持之后只读重开来源回执。完整M10仍在开发，目标active；原T/H归属、缺失修复、自动迁移与原能力激活尚未完成。

## 实现与边界

- `CapabilityService`为本宿主实际创建的普通M4运行保存原清理闭包及固定快照指纹。来源意图持久化后先保留整个原T；C原插件、原manifest与根标记、依赖及引用事务核验成功后，将后续清理切换为仅删除已知临时配置／自检文件，原plugin及Skill的路径、字节、模式、inode保持不变。来源中断时不删除最后的完整现场；重试提交后可完成原清理。`dispose`复用同一闭包。
- 清理前核对原根inode、完整已知文件集及内容、根标记和单链接普通文件。原目录被替换、别名、软硬链接、Skill／临时文件改动、额外文件或空目录时保留；不覆盖用户内容。Codex原H投影继续保留；正常无长期引用的T沿用清理行为，受影响回归覆盖。
- `LegacyPluginSources.verifyOriginalPlugin`只读核对C留存与原静态目录的完整文件集、原标记、路径、hash、依赖和有限读取预算。`LegacyTaskRetention`允许已完成留存、仅剩原静态plugin的任务重开来源回执，不重建旧context、改原任务JSON或增加新业务能力。损坏C来源、改动原静态树、未知目录仍拒绝／诊断并保留。
- 该进程内闭包只证明谁有权清理自己创建的目录，**不证明CLI／桥／执行器已经退出，也不接管历史未知owner**；静态字节匹配同样不授予所有权或启动授权。未知旧T/H、原路径缺失修复和持久占用协调仍属于DEV-02后续。此次没有接通`legacyMigration.migrate`或取消legacyBinding的临时降级。
