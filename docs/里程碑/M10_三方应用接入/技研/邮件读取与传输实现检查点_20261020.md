# 邮件与禅道 provider 实现检查点

依据：M10需求R1.6含12.21；2026-10-20开发授权。本文记录DEV005-A实际技术选择和验证边界，不替代需求、原型或正式产品用例。

## 真实实现

- 禅道：将本仓库已复验的`my_work_client.py`契约落实为Node HTTP客户端。保留部署base path，登录仅POST凭据；当前用户识别后读取`v2/my/work`的Bug／Story本人指派列表，Bug详情用v1、Story详情用v2。每条返回校验当前指派；分页缺项、重复、预算耗尽／中途失败明确不完整，已收到的有效页保留。数字ID不能安全表示时拒绝，字符串ID保真。单次传输无重试，后续统一执行器控制总预算；不跟随重定向。
- SMTP：精确引入`nodemailer@10.1.7`，使用其MailComposer及传输层；plain／STARTTLS／隐式TLS显式选择，不猜端口、不降级。连接测试只认证，不发送邮件。准备阶段先生成CRLF规范化的固定MIME字节，再摘要绑定信封（包括BCC）、Message-ID和原始字节；提交只尝试一次，断线未取得可靠回执记录unknown。真实发送仍须接入持久草稿／意图／授权与当前配置校验，本检查点未开放发信入口。
- Foxmail：选单个账号目录或其中的`messages.db`，非整个多账号根；路径、原生文件ID、来源物理身份／schema／选定账号均核验。SQLite元数据由短命macOS原生读取器执行固定SQL，MIME使用`postal-mime@4.0.11`。重CPU、JSON和MIME处理在Worker；主进程仅监督可取消的原生进程句柄和消息。所有文件以只读／no-follow方式打开，来源链接或重复原生ID不声称完整。
- 当前日期口径：列表展示和范围判断都使用原始RFC邮件的`Date`，转换为当前本机时区最近N个自然日，包含当天，1–100天。尚未把未确认语义的Foxmail整数`date/mail_receivedate`当UNIX秒直接解释；其值仍保留为内部元数据。Date缺失／无效或未下载文件导致范围无法确认时返回不完整，不把它们当空结果。后续真实Foxmail验收继续核对列表对照，不宣称当前已覆盖全部Foxmail版本。
- 重复查询复用身份及文件stat修订不变的内存邮件头；读取正文和普通附件有字节、解码量、MIME层级／部件数和Worker时间／内存预算。直接读取和附件请求也重查当前来源／日期范围；附件引用绑定内容hash。扫描前后重核元数据及文件清单／stat；确认移除的源对象不再返回。没有引入自动唤起Foxmail、收信或修改服务器删信设置。

## WAL／SHM的实际发现与修复

`better-sqlite3`虽提供readonly，SQLite仍可能创建或更新SHM；本机该依赖编译为`SQLITE_USE_URI=0`，不能靠拼接URI参数声称启用了不可写VFS。原生读取器首个immutable尝试在测试中漏掉WAL内已提交记录，2条红测保留。不能用忽略WAL换取源文件哈希不变。

最终采用本项目的只读SQLite VFS：拒绝写／截断／删除，不映射或创建SHM；让SQLite在私有堆内重建WAL索引，读取已提交页。对数据库／WAL／SHM／回滚日志保留读取前后设备、inode、大小及纳秒mtime／ctime；任何变化使整份观察结果失效。该方式是一份经稳定性核对的短时观察，不能宣称对持续写入的任意邮箱提供强事务快照；来源持续变化／热回滚日志则返回忙碌或未完成，后续由有界重试策略处理。测试已验证有SHM的活WAL及无SHM的隔离WAL镜像都能读取最新已提交记录，所有源文件前后SHA256相同。

依据：[SQLite WAL只读行为](https://www.sqlite.org/wal.html#read_only_databases)、[SQLite VFS接口](https://www.sqlite.org/c3ref/vfs.html)、本机SQLite实现及受控夹具。没有复制SQLite源码或Foxmail实现，也不改源库journal模式／checkpoint／标记。macOS链接系统SQLite；其他平台正向支持未验证。
