# SE P04 未添加、归档与旧多选边界补验

依据：R1.6＋§12.21，M10-R02-09、R01生命周期及T22既有批准范围。当前feature/0.0.2，HEAD f1f1728；保留既有工作区。

1. 未添加应用：P缺少A已有的“先添加…应用”恢复入口，先组件红测，补齐同一导航。按钮只打开详情，不自动添加、启用或配置。
2. 复用SD已验包：A及合成P分别在浅／深、常规／最小窗口检查两个应用的禁用选择、终端及明确详情导航。未添加状态是独立测试前置，原服务／公共原型数据准备，不冒充点击移除／添加验收。
3. A归档前置用原projects.setArchived准备，真实UI检查归档项目不在picker、无伪造项目卡、可明确选另一个项目；绑定与连接保持。此项不替代归档系统操作验收。
4. P旧多选用公共合成模型准备，原单选／确认UI逐槽显式修复，其他槽／项目不变；不以P证明生产SQLite迁移。
5. 原严格读取遇到异常旧表／身份失配拒绝，但select也调用严格读取，因此“明确重新选择”的可执行恢复尚缺。现代约束禁止重复槽；不为测试移除约束，不把SQL恢复写成用户恢复通过。单列缺陷与后续方案，不在本批放宽业务授权。

验证：定向组件与模型／类型、P构建；生产输入和SD包19pin不变则复用，不重新构建。所有失败与最终结果保留。正式72条核心504字段及48通过＋1历史替代＋23待收口保持，T22只补实际子集。
