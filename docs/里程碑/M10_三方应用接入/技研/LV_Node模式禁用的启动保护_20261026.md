## 范围内修复

在`src/main/index.ts`的首个应用初始化动作之前识别保留的Node意图。正常Electron Node启动直接执行所要求的CJS，不加载该browser入口；若此入口仍看到`ELECTRON_RUN_AS_NODE=1`，输出固定的`WillYou application bridge unavailable: HOST_INCOMPATIBLE`并exit1，且不调用数据身份／scheme初始化或main。仅环境意图缺失时维持正常入口。没有读取CLI参数内容、选择外部Node／Python或伪造MCP握手。

修复前负控已证明browser入口确实能观察到`1`，不基于猜测增加fuse扫描依赖。显式同时门闩main调用，即使app.exit返回也不排队正常启动。静态模块导入仍执行；最终负控必须证明没有数据根／数据库及正常窗口初始化，不能只根据几行代码宣称已通过。

公共harness仅为本次私有负控增加受限开关：必须明确私有App／userData、Node意图及准确CJS／bootstrap三参数，默认仍清除继承的Electron Node环境；startup错误仅在该模式附加自有进程终态。新负控driver白名单化环境，普通服务driver给每次新窗口标A／隔离区域；两者均为仓库外部验收驱动，不改变App界面或鉴权。初轮代码及原始红测保留，最终修改后的环境边界单列。
