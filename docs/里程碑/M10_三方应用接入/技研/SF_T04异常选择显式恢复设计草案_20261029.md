# SF T04 异常选择显式恢复设计草案

状态：已实现及本批分层复验完成，T04恢复通过；目标M10仍验收中。承接[SE发现M10-SE-02](../验收/SE_P04未添加入口修复与归档旧多选边界复验_20261029.md)。需求仍R1.6＋§12.21／M10-R02-09，同批准范围缺陷修复，无新外部操作或发布。SE现阶段正式47＋1历史替代＋24待收口，T04保持待复验，不能将本设计记为通过。

## 已核对事实

- `selection-service.ts` 的 `projectSettings` 是业务严格读取；`select` 初始和停止后、提交也调用它。不能直接取消严格检查，否则旧Agent/能力调用可能使用未确认连接。
- `ApplicationService.projectSettings` 仅UI管理读，调用 `selections.projectSettings`。可增加独立只读视图解析，不把宽容解析作为业务授权。
- 现代 `application_project_bindings` 有复合主键和provider/app FK，禁止重复槽；`identity_revision`不在FK内。旧多选用原TEMP影射I夹具验证；真实App后续可在本次U的单行identity_revision制造可撤销失配前置，保留现代约束、记录故障与恢复，不冒充真实旧库迁移。
- `ApplicationImpactService` 的switch影响读直接取原始绑定/当前修订，不依赖严格settings，能列多条旧禅道连接与受影响真实运行；不得绕过影响读/停止失败。
- 服务现有management write会作执行审计及策略失效。复用 `application.project.select`，不增加未审计写入口。
- P现有合成多选可逐槽显式选择，其他槽保持；ZenTao需确认，取消不改。SE实际P20已证，目标生产尽量复用此交互；新差异同步原型，不另做自动清空入口。

## 推荐实现（正式修改前复核）

1. 保留严格业务 `projectSettings`：其可调用新的私有解析器，但只要有异常槽仍拒绝，不向业务返回可用空选择。新增 `projectView` 仅供主进程UI管理读，返回合法槽当前连接、异常槽未确认（null仅作为DTO占位，须附明确异常标记），及 `repair:{slots,fingerprint}`。原始记录不改；未知slot、缺失/异常slot修订、缺失设置等不能无条件提供恢复，先明确不可兼容。避免重建修订0导致旧授权ABA。
2. 正常 `select` 契约/结果保持。显式恢复输入可增 `repair:{slot,fingerprint}`，公共schema及泛型HostRegistry均严格校验slot属于本应用和指纹格式。仍完整提供connections；服务器要求除目标slot外所有槽均与只读视图一致，enabled不变，防借恢复切应用开关/其他账号。无当前异常、指纹不匹配、旧revision、pending均拒绝；不能把传入flag当受信标记。
3. 指纹覆盖project/app、设置启用/总修订/策略修订、全部raw绑定/slot修订，以及被引用连接的修订和身份修订；稳定排序/规范JSON。pending和updated_at可排除，但始终单独检查pending，并在停止后只接受本operationId。连接配置/身份改变、另一个槽修复、其他项目token复用皆须失效。只读返回不含秘密，不能靠UI自报原绑定或身份授权。
4. 恢复写只修改**明确点击的一个slot**：事务CAS并保留原raw绑定于变更journal，删该slot旧行并插入明确id或清空，增加binding_revision和该slot版本；其他合法/异常槽原行、其他slot版本、其他项目/连接逐字保持。不使用现有全量DELETE/规范化重插来丢弃另一异常槽。普通commit路径不变。
5. ZenTao异常非空旧选择也先登记pending、列影响并停止相关运行，再次核对原指纹/修订/pending/当前运行后提交；不能因为视图中异常槽为null就跳过stop。停止失败/并发冲突保留原raw选择，pending/journal按原流程清理，不自动重启/换源。Mail不增加停止Agent。
6. 恢复返回UI视图；若其他槽仍异常，继续显示其警告/未确认radio，严格业务读仍拒绝，不强行调用strict读造成“已写但报失败”。普通select仍返回原严格结果。原业务引用按现有slot/current identity检查，不改来源身份/秘密/健康。
7. P04每异常fieldset显示与原型一致的警告，不将None显示checked；实际点击None或候选携带当前fingerprint和slot，经原UI action→原RPC→事务。ZenTao沿原确认/影响读；切项目/缓存/迟到保护和焦点沿现有逻辑。应用开关和终端在异常期间的可用性须与现有错误保护/原型对齐，不能为恢复放宽业务权限。原型已有立即逐槽恢复可复用，必要增量先记录。
