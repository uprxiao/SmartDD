# OZ：T11页面取消链与迟到隔离

依据R1.6＋§12.17／12.21，原T11步骤3／4／7／8，feature/0.0.2，HEAD f1f1728d68a8595e665d4833dff048189e63e0f8＋保留工作区，原34/72、余38。上一批OY已有进展，本批不重复启动已超时的钥匙串路径。

代码核对：现有TanStack查询隔离了旧类型／项目结果，但queryFn没有消费AbortSignal、IPC没有对应取消端点。实际主进程读取可能继续到总预算结束，不能将“页面不显示旧结果”称作取消生产者通过。补受信只读requestId及本窗口／原frame所有权取消，原withUi AbortSignal用于停止HTTP／退避和交付前检查；新查询不复用requestId，跨窗口或旧frame不能取消别人的读取，重复／迟到取消不得重放业务。保留30s／首次＋2次原owner预算，不改变Agent层、不接入写操作。

原型无新增可见入口／布局：沿用现有Bug／研发需求切换、项目切换、关闭详情／离开页面触发取消；只同步实现核对与用例，不发明额外按钮。资源读取以可选signal向后兼容，非禅道调用不接入新取消RPC。前端先红测切换触发取消及迟到隔离，后端验证实际HTTP取消、退避不再请求、同window/原frame绑定、重复请求和清理。

生产改动后生成独立OZ包、六原生及必要真实Codex回归；不重复等待钥匙串。可用真实App在原资源锁前等待的I门闩验证切换取消UI／IPC／主进程注册的链路：预置无秘密合成连接，无safeStorage override，原协调锁阻止触及provider；释放后取消请求拒绝交付。该结果明确为pre-IO取消，不当作真实HTTP分页／认证或完整T11；如无法安全形成该夹具，保留软件和真实包边界，继续独立用例。

执行补充：175唯一软件／纠正后完整类型、新包六原生、当前pre-IO浅深取消2／资源8／实际Codex18回归通过；原两fixture失败与旧包缺requestId红保留。锁的作用点改为元数据和明确AUTH_REQUIRED完成后，再锁住实际UI重试，避免首次元数据也被阻塞；未改变生产3秒锁等待或30秒读取deadline。同步钥匙串无法由JS abort强制中断，继续保持原系统前置；完整HTTP页面和原T11其余条件不计通过。详见[执行记录](../验收/OZ_T11页面取消链与真实App复验_20261028.md)。
