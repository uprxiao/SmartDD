## 必须进入实现契约的发现

1. **Codex选择路径要到SKILL.md文件。** 当前0.162.1填目录不报错，但关闭另一版本无效；参数被接受不等于真正筛选成功。
2. **工具语义注解影响模型调用路径。** 不带准确只读等注解时，直接MCP RPC能执行，但真实模型在never审批策略下会拒绝。补注解后通过；不能靠放宽审批掩盖问题，也不能把注解当服务端授权。
3. **会话固定版本由启动层履行。** resume仍须从原快照重新传同一Skill路径／选择清单和对应MCP实现；原生ID恢复本身不替应用锁版本。
4. **新原生根需要初始化协调。** Codex首次同时初始化空根曾发生一次SQLite初始化失败；先初始化再并发通过。这是一次观察，需要后续故障复验，不能泛化为所有并发都失败。
5. **隔离不能冒充兼容。** CC空setting-sources隔离实验中未保留合成用户Skill，生产必须单独验证合并行为。cdsh只是Claude Code的模型配置，不代表已适配DSH。
6. **默认发现范围按版本登记。** 后续保留普通setting sources的共享HOME实验中，CC 2.1.303保留`.claude/skills`用户Skill及用户MCP，没有发现本轮放在`.agents/skills`的Codex版本；Codex按其目录正确筛选。混合模型调用亦通过。该结论只适用于当前版本／所构造目录，不能假定未来CC或其他Agent永远不发现共享目录。

## 本轮补验后的前置结论与后续边界

真实用户配置和同名冲突、实际原生根下自有历史恢复已补齐；CC的插件／MCP同名覆盖、Codex的同名路径并存及新增目录强制扫描默认启用均有实测证据。原生resume不会替WillYou锁包，因此守卫、完整SKILL.md选择和受管目录冻结按[详细设计6.9](../../应用包与Agent运行时详细设计R1.6.md#69-真实用户配置合并与名称冲突预检)成为实现要求。没有剩余必须另定架构的前置问题；守卫生产实现本身由开发阶段完成。

边界继续保留：互动TUI／PTY、真实WillYou启动参数与原生业务长历史、用户hooks执行、未配置的profile及其他CLI版本没有被本轮穷举；正式宿主桥恢复／撤销、broker权限、目录锁／资源协调和升级仍在开发后按对应完整用例验收。实际默认根与隔离目录的证据组合不冒充同一轮全局生产安装实验。
