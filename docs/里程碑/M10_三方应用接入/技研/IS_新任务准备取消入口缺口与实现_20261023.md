# IS：新任务准备取消入口

依据R1.6 M10-R10-20及T54步骤9，属于已批准的可取消维护等待范围。核对发现：TaskService.create在spawn完成后才写任务记录，首页发送按钮在launching时禁用；既有kill需要任务ID，客户端此时拿不到。IQ仅证明等待超时后清理，不能证明用户主动取消。

当前新增可选launchToken及tasks.cancelCreate：主进程生成真实任务ID，token只关联该次准备；限定发起webContents，重复token拒绝，结束后token失效。取消复用已有launching AbortController/kill路径，不删除用户配置或历史任务。调用方没有token时保持既有行为。一次取消不能被用于停止已完成创建的任务。

定向服务测试已验证新任务未fork、已有任务继续、无新任务记录、准备运行停止；补充不同sender拒绝，整文件13项回归全部通过。node类型检查通过（sender边界测试追加前的结果）。

尚未完成：首页取消按钮和本次token接线、共享原型状态同步、前端交互测试、取消/完成竞态补验、当前代码重建与真实App主动取消。当前只是后端入口实现，不称T54通过。IJ及后续复用IJ的证据不包含本次生产修改，下一真实App验证必须重建。正式16/72。
