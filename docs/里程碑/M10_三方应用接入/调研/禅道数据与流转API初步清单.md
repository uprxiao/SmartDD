## 1. 已核对的官方文档

官方说明 [REST API v1 的产品版本要求](https://www.zentao.net/book/api/1397.html)；v1、v2 文档并存。API 文档版本不等于禅道产品版本，本轮未确认 v2 的最低可用版本或本机目标实例支持范围。

| 业务 | 官方文档中的 v2 形式 | 确认事实与限制 |
| --- | --- | --- |
| 产品 Bug 列表 | `GET /api.php/v2/products/:productID/bugs`；`browseType=assigntome` | [Bug 列表](https://www.zentao.net/book/api/get-products-productid-bugs-2194.html)给出个人指派筛选及 `recPerPage/pageID` 分页；跨产品／分支、个人身份和实际计数仍需验证 |
| 产品需求列表（若为 Story） | `GET /api.php/v2/products/:productID/stories`；`browseType=assignedtome` | [Story 列表](https://www.zentao.net/book/api/get-products-productid-stories-2172.html)个人筛选拼写与 Bug **不同**；不能拼接一个通用参数覆盖两类对象 |
| Bug 详情 | `GET /api.php/v2/bugs/:bugID` | [Bug 详情](https://www.zentao.net/book/api/get-bugs-bugid-2197.html)列复现步骤、状态／指派、关联对象与 files；未据此证明操作日志、所有评论、图片和附件内容均完整返回 |
| Story 详情 | `GET /api.php/v2/stories/:storyID` | [Story 详情及目录](https://www.zentao.net/book/api/get-stories-storyid-2175.html)列 spec、verify、files 等；用户“需求工单”是否为 Story 仍未确认 |
| 独立流转动作 | 官方动作文档有 Bug resolve、Story close／activate 等 PUT 端点 | 本轮实际打开相应正文并核对存在独立动作；目标实例可用性、权限、字段及结果尚未验证。不能仅修改 status 代替业务流转 |

官方目录分别存在 Epic、Requirement、Story、Ticket 等对象。正式需求及 UI 暂用用户语言“需求工单”，待版本及实际页面对应后再选接口；不把它直接等同于 Story，也不把研发 Task 当作需求。

## 2. 数据先行的统计项

下表为下一步接口／样本验证清单，不是已实现的字段契约。

| 数据层 | 需逐类核对 | 当前覆盖 |
| --- | --- | --- |
| 身份与范围 | 当前账号身份、可见产品／项目／分支、权限不足与禁用范围 | 未验证目标实例 |
| 我的列表 | 两类对象、真实类型／ID、标题、本人指派语义、分页／总数、状态与基本字段；跨范围合并和重复 | 仅查公开列表接口，未对照页面 |
| 详情正文 | Bug 复现描述；需求描述及验收内容；富文本／嵌入图片、自定义字段和关联对象 | 文档已列部分结构，未验证真实完整性 |
| 评论与历史 | 评论／操作日志、变更历史、当前版本及可审阅的处理背景 | 未确认是否需独立接口 |
| 文件与图片 | 附件元信息、授权下载、内嵌图片、缺失／未下载情况和本地引用 | 有 files 结构不等于文件可读，待验证 |
| 引用与恢复 | 连接＋真实对象类型＋外部 ID、来源链接、更新时间；重复读取与失效处理 | 本项目待设计，不声称远端幂等或增量支持 |
| Agent 输入 | 可查询／引用完整工单、说明缺失项；可选关联项目，不强制进入自动修复流程 | 工具契约、CLI 加载与真实查询未验证 |

“完整详情”应按实际页面与工作需要定义字段／关联资料，不能只因详情端点返回 200 就标记完整。数据范围确认后再编制分页遗漏、跨产品、空列表、附件缺失、自定义字段和权限异常的用例。

## 3. 流转后细化

按每种真实对象分别统计：当前状态→页面可见动作→动作 API→必填字段→账号权限／前置条件→执行结果→回读核实→失败／冲突恢复。下一轮评审再确定本期必须交付哪些动作及何时需要确认／允许预授权。

例如 resolve、close、activate 是不同业务动作，不能将旧 Skill 中的“修复完成”直接映射为关闭，也不能承诺 API 覆盖页面全部定制工作流。
