# ChatGPT 命名包与宿主工具桥接静态补查

日期：2026-10-19。依据：[M10 需求 R1.5](../需求.md) 的 M10-R02、R07、R10，以及用户本轮授权“使用 REA，逆向 Codex／ChatGPT 作为多 Agent 参考”。本报告只补充目标身份、随包插件声明及 Codex／ChatGPT 共用工具桥接；Codex ASAR 内部 Skill 分发由本轮主调研单独记录。本报告不代表正式开发授权。

## 结论与证据边界

本机目录名为 `/Applications/ChatGPT.app` 的安装包，实际 `CFBundleIdentifier` 是 **`com.openai.codex`**，版本 **26.1013.40934（20770）**。其主程序为 arm64 Mach-O，带 Electron ASAR、Codex CLI、Skill 和插件资源。不能仅凭目录名将它当成独立的传统 ChatGPT 客户端，更不能把同一 ASAR 重复计作两套产品证据。

在 `/Applications` 与 `/Users/liubu/Applications` 两个标准安装目录内，按应用 bundle 的 `Info.plist` 核对身份，本次没有发现独立的 `com.openai.chat` 应用；另有 `com.openai.atlas` 的 ChatGPT Atlas，不属于本次分析目标。这一负面结果只覆盖上述目录，未扫描全部磁盘、其他挂载位置或远端产品。

可以确认当前随包资源采用“插件版本＋Skill 目录＋MCP 配置＋资源”的组合组织；可以在外置 `codex-app-tools/server.mjs` 读到 Codex 与 ChatGPT 两种调用者进入同一本地工具桥的具体代码。**该桥不负责证明 Skill 已装载；ChatGPT 的远端 Skill 部署、模型上下文装载及升级策略仍未知。** 本轮未启动或操作目标 App、未请求模型、未访问聊天、账号、凭据或日志。

## 随包插件所能证实的组织方式

声明和资源可以独立核对：例如 `computer-history` 的 manifest 指向同目录下的 `skills/`、`.mcp.json`；后者提供本地命令及相对工作目录。`latex` 包含 3 个 Skill，证明这里的模型允许一个插件包含多个 Skill。不同插件可使用独立版本号，例如桌面版本 26.1013.40934 与 `visualize` 1.0.50、`codex-app-tools` 0.1.6 并存。它们的**交付版本可独立表达**；本轮没有因此认定插件具备独立在线升级能力。

`Resources/plugin-signatures/openai-bundled/` 下有 13 组归档／签名描述／公钥。对每个 `plugin.tar.gz` 计算 SHA-256，均与对应签名描述中的声明摘要相同。这只证明本地归档与声明摘要一致；未验证 RSA 签名，也未追踪安装器是否实际执行签名检查。

`codex-app-tools` 的 `.mcp.json` 声明宿主 pipe、Node 路径等允许传入的环境变量，启动脚本按候选顺序选择 Node 并启动随包 server。此处可借鉴“同包工具定义＋运行时定位”，但 `enabled: false` 等配置仍只代表文件声明，不应据此推断用户当前是否启用。

## Codex 与 ChatGPT 的共用工具桥

从完整函数体可读出以下静态处理顺序：

1. MCP 收到工具调用，解析工具名称及 `_meta`。
2. 以显式 `interactionClientId` 或调用元数据确定 thread；缺失 thread 时返回错误。
3. 组装 `threadId`、`turnId`、`callId`、namespace 与参数，并据是否有 `interactionClientId` 设置调用者来源。
4. 通过同一个 `requestHost` 请求本地宿主；底层 `NativePipeClient` 连接环境变量指定的 pipe，使用 JSON-RPC 消息与长度前缀帧。
5. 将宿主结果转换为 MCP 文本、图像或音频内容。

这是可以迁移的**客户端适配器→统一宿主能力服务**模式。它没有将业务实现复制到每个调用者，也没有证明调用者直接查询数据库。当前证据仅涉及工具调用；“同一份 Skill 如何被各客户端发现和注入”需要另查 Skill 装载器，不能从这个桥推导。

## 对 WillYou 的建议与尚待验证项

以下是设计建议，不是声称 Codex／ChatGPT 已采用的全部实现：

- 应用包维护稳定应用 ID、版本、Skill 目录、工具定义及资源清单。一个应用允许多个 Skill；Skill 中的脚本和引用文件一起交付，不只复制 `SKILL.md`。
- Codex、Claude Code 等客户端只负责原生 Skill 发现方式和工具入口适配；工具继续访问同一宿主应用服务，由服务定位本地 SQLite 中的连接、项目和业务记录。
- 每个会话固定应用版本与内容摘要，并带会话／项目身份访问宿主；“文件分发完成”“Agent 发现”“本轮读取”分开记录。新版本安装与旧会话持有版本不能只用全局开关表达。
- SQLite 与应用包分离符合用户已确认方向，但不能以本轮插件清单证明数据库升级保留、迁移回滚或热重载。它们需要 WillYou 自己的迁移设计与验收。

## 分析限制与本地复核

最初 `inspect_plist({path})` 在没有活动 target 时返回 `target_unavailable`，没有生成 Evidence；随后用本地格式解析器核对身份，没有为此改动 REA 配置或打开原生目标。没有活动原生会话需要本分支关闭。

REA 首轮将语义节点上限设为 25000，出现截断；对 `CODEX_APP_TOOLS_PIPE_PATH` 的字面追踪无匹配（`ev_cba6bd93a405d65c638d166e247c47812dd172409571028525a5d3e73e79d99d`），工具明确说明这不是缺失证明。为补足尾部桥接代码的分析范围，只对同一文件提高至 150000 上限作一次针对性补查，未再截断，但静态语义未知仍保留。没有用无匹配结果推断功能不存在。
