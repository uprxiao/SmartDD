# JJ T35 草稿与模拟发送完整验收

2026-10-23，feature/0.0.2，已授权R1.6＋§12.21；T35原六步及发件变更/旧批准补充。约定层级仅原型状态/交互；Mac arm64，私有静态原型，未运行实际Claude/Codex或连接SMTP。

## 补齐开发及缺陷

承接CE原型修复与部分驱动，补固定长草稿/附件摘要、原Agent持冻结批准继续提交的合成操作。批准固定项目/草稿/修订/发件及槽修订；并发内容/SMTP变化后拒绝旧批准，明确采用新发件修订才能新批准。默认正文仍由固定fixture重建，不存用户邮件。

源码核对同时发现无运行Agent时交接会覆盖已有首页输入，已改同项目追加并保留前缀，跨项目输入拒绝覆盖/改选，仍须用户手动启动。浏览器已验证对应正负路径。

首轮完整浏览器在模拟服务器接受后失败：页面隐藏了“不等于送达/已读”说明，并残留旧“尚未发送”。修复为全结果持续说明，提交时清旧提示。截图又发现长主题挤压标签，补标签不收缩/不换行，最终UI用Range几何确认标签单行。原失败及改前/中间源码、布局观察图保留。

| 原步骤 | 实际结果 |
| --- | --- |
| 1 无SMTP草稿/重开 | 在默认停止任务的smartdd项目启用邮件，无SMTP生成/保存；列表主题/项目/修订/更新时间/状态和长预览可见。保存失败保持原状态；实际reload重开同ID/修订及长fixture |
| 2 查看与交接 | 长主题/正文/固定收件人/合成附件摘要可查看；无运行Agent时保留首页输入且不启动；已有同项目合成Agent时保留终端前缀，只插同草稿ID/修订，焦点回终端，Enter/任务数/发送数不增；另一项目待输入拒绝覆盖 |
| 3 并发与保存失败 | 另一Agent模拟r1→r2；旧审阅CAS拒绝且状态不变；重开再保存r3；合成失败不保存 |
| 4 发送及记录 | 显式选SMTP A并采用r4；确认后另一Agent改r5且项目切B，旧审阅/批准不发。重开明确采用B得r6，新批准才提交；捕获sending快照，接受/明确失败/unknown分别保留结果；接受说明持续显示不等于送达 |
| 5 unknown不重发 | unknown没有发送按钮，查看记录/返回/实际reload后原对象及发送计数不变，仍unknown |
| 6 已发送另存修改 | 接受的原ID/r6、正文重建结果、sender和发送记录保持；另存新ID再改r2，不覆盖原记录 |

补充项目范围：ais/smartdd分别创建草稿，切项目列表/审阅不串对象；SMTP切换期间只变当前项目设置，旧草稿不自动改发件。新旧修订/批准检查同时有模型独立场景。

最终15组浏览器检查全过，45模型/构建/Sites4项通过；T34受影响原型回归全过。浅深查看draft/accepted/failed/unknown不修改任何状态或发送计数。已人工查看长主题/接受态截图，标签单行可读；完整Codex视觉仍按T22。所有观测HTTP请求仅本次静态origin，所有实例结束关闭。

## 夹具和适用边界

两个全局SMTP连接仅在隔离localStorage准备公共合成元数据，创建这些连接不属于本例验收动作；项目选用、模拟并发改发件、测试/保存/确认/继续/发送/查看等均从真实原型UI操作。示例密码未持久保存。附件是明确标注的合成摘要占位，未读取真实文件。Agent事件、批准和发送都是模型/计时器，不是实际Agent/SMTP回执；载体App不是本例生产业务通过证据，真实链路仍由T18/T19承担。

T25/T26的目录/配置和T33对象分支未改；T38菜单/路由/M9隔离未改。App回调新增的首页输入保护由本批正负路径实测，T34入口回归通过；保留其他已通过用例的既有适用证据，不无原因重跑全部App。
