# VC：T18 本机回环——回复全部＋附件真发送，及不发送步骤（2026-10-31）

环境：macOS arm64，package4（最终源码，临时诊断已撤）；全部使用 127.0.0.1 本机回环收件端，不联网、不用真实邮箱或凭据。夹具：`scripts/applications/fixtures/loopback-send-native.mjs`（T18/T18B 变体）、`t18-mail-sink.mjs`、`t18b-nodata.mjs`。证据：`证据/t18-loopback-20261031/`。

## 真发送（用户追加批准3次，本例用第2、3次；第2次发送成功但夹具在“发送后编辑”断言失败，保留）
- Agent经MCP：`mail_query`→`mail_read`→`reply_create`（reply-all）→`attach_import`（邮件资源附件）→`draft_update` 得 r2；`reply_create`／`attach_import` 因对外可见属性需Codex宿主批准，测试中Codex为“询问”模式，由脚本按回车批准。
- 回复全部收件人：to＝source、recipient，cc＝cc，发件身份本人被排除；界面审阅→授权→发送，状态 `server-accepted`，1次DATA，接收端信封3收件人，`In-Reply-To`/`References` 指向原邮件，正文及附件（2033字节，sha256 f52e8a09…）与冻结意图一致，Message-ID与记录一致。
- 发送后编辑：已发送草稿 `draft_update` 被产品以 `DRAFT_LOCKED`（retryable=false）拒绝；`draft_copy` 得新草稿后修改，旧发送记录仍绑定原草稿 r2、原rawHash；正常重启后发送记录、冻结MIME哈希、保留的附件副本、草稿修订保持，仍1次DATA。证据：`t18-reply-all-attachment-final.json`、`t18-sink-events.json`、`t18-sent-result.png`、失败保留 `t18-first-send-edit-assert-failed.json`。

## 不发送步骤（发送端不上膛，DATA不可能发生；`t18b-nodata-final.json`）
- 步骤2/3：真实界面审阅后点关闭弹窗＝取消意图（产品行为：持有审阅的页面关闭即cancelSend），意图 `canceled`，Agent读取为canceled，0执行、0 DATA。
- 步骤8：来源邮件附件被改动后，已保存稳定副本仍为旧哈希；稳定存储不可写时导入附件返回受控错误（CAPABILITY_UNAVAILABLE），无半成品附件、草稿修订不变；主动换附件形成 r3，r2仍指向旧附件；删除来源邮件后对旧引用回复返回 `SOURCE_UNAVAILABLE`，无半成品草稿。
- 步骤13：草稿绑定SMTP A后，项目发件槽显式换B，旧草稿发送准备被 `INTENT_STALE` 拒绝（“草稿发件人与项目当前选用不同，请明确选择后更新草稿”）；明确更新草稿发件账号得 r4，生成绑定B的新意图（未授权、未发送）。
- 步骤14：仅清空读取来源（重启运行后）：草稿列表可用，读取返回 `AUTH_REQUIRED`，发送准备仍可；仅清空发件槽：草稿列表与读取可用，发送准备 `AUTH_REQUIRED`。

Agent调用被夹具范围守卫（只放行UI）拦截；守卫把UI取消当成发送权限；回环收件端缺SMTP 220问候；先建多余草稿；关闭弹窗的等待条件。M10-VC-01（Agent读取界面建立的意图泛化错误）同属夹具守卫。
