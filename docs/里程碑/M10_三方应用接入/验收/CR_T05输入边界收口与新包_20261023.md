# CR：T05输入边界收口与新包

2026-10-23，feature/0.0.2，495af7cf＋本次代码；需求R1.6＋§12.21未变。T05原定层级为协议单测＋集成，不将本例通过当全部真实业务／UI完成。

## 缺陷与修复证据

SDK ReadBuffer主动吞掉SyntaxError，原桥stderr为空；单纯添加server.onerror亦未能观察坏JSON，原失败均留存。桥入口增加256KiB上限的帧检查，只将可解析JSON交给SDK；固定INVALID_JSON／INPUT_TOO_LARGE／INVALID_PROTOCOL诊断各在单进程最多记录一次，不输出异常文本。无效JSON后合法请求继续；超大帧关闭本输入与桥通道。首次关闭仅pause导致进程未退出，现destroy输入，实际子进程退出验证通过。

最终直接stdio测试覆盖：初始化前tools/list及call、先伪造通知、initialize响应后尚未通知、合法握手、未知方法／缺字段／错型、三条坏JSON仅一次脱敏诊断、之后合法工具计数、带／不带换行的超大帧关闭且不增加业务计数、stdout可解析及秘密不进入stderr、CLI／桥释放。桥文件5项在本批扩大回归通过。

## T05原七步对应

1. CR直接stdio序列＋CP私有socket认证／字段／超大参数，错误明确且适配器零调用。
2. CR坏JSON后合法调用、stderr脱敏、超大帧退出；CP有界请求超时及合法后续socket。
3. CP无Agent配置及项目草稿测试：停止两个模拟run、有效宿主sender、连接验证器夹具、SQLite任务前后相同；未选项目与跨项目拒绝。
4. CP controller／broker／tool-service／business-data检查真实宿主产生作用域；伪造callerKind、run／project、批准及权限／对象身份无法获得调用权限。
5. CP业务服务的Agent-run与UI走同Data API，内部index-job具有独立父操作记录。
6. CP索引上下文不能发送、不能升级为项目草稿actor；跨项目引用拒绝。
7. CP撤销／ABA后交付拒绝、原配置来源记录与固定包路由；CR更换运行时后扩大回归再次验证。
