## 修改建议

1. **F01**：用 `fileURLToPath(import.meta.url)` 获得原生模块路径，与规范化的 `resolve(process.argv[1])` 比较；保留“被导入时不启动构建”边界。实际入口执行后应核对桥接输出已生成。测试覆盖 Windows 盘符、空格／非 ASCII 路径及模块导入，最终在 Windows runner 复验。
2. **F02**：一起修 readTree 与 names。只对可信磁盘遍历结果使用 `relative(root, file).split(sep).join('/')`；磁盘访问继续 native join。外来清单仍严格拒绝反斜杠／绝对路径／穿越，不能对外来输入宽松替换。覆盖单层／嵌套路径、精确库存、相同字节的跨平台资源 hash。
3. 不顺手改 runtime manifest 字段／字节或替换固定 pin。先核 Windows 真实 runtime hash 与既有 pin，再判断是否涉及独立应用版本变化。

## 风险／待确认点

- **低 · R01 可执行位的未来契约。** verifier 对 true 严格要求 `(stat.mode & 0o111) === 0o100`，writer 却始终0600；未来 true 会不一致，标准0755的三执行位也不符合这个精确 marker。当前生成项都是 false，不能把该未来问题写成本次 Windows 根因。未来需要可执行资源时，先明确可移植 marker 与权限策略，再成对修改 writer／verifier；不直接跳过安全校验。
- **低 · R02 跨平台实际 runtime 字节仍缺。** Windows 在生成 bridge 前失败，日志没有可比较的 runtime bytes/hash。build-runtime 第5行直接读取许可文本写 banner；若 checkout 行尾或工具链产出不同，固定 pin 会正确拒绝。本范围没有许可原文、锁文件与 `.gitattributes`，不能确认实际存在 CRLF 差异。修复后需要 Windows runner 的真实输出；Mac 成功不能代替。
- **低 · R03 manifest 形状不可顺手变更。** runtime 文件条目目前没有 executable 字段，即便增加 false、bridge bytes 不变，完整 manifest hash 也会变（纯探针已演示）。避免路径修复夹带此变化；实际 released bytes 必须变化时按独立应用版本契约处理并保留旧会话所需版本。
- **可能未穷尽。** 只审五份冻结源码和一份完整实际 Windows job 日志；未审其他生产消费者、依赖实现、Windows ACL／打包后权限。日志中发布 helper 为14通过／1项Mac专用跳过，不能证明能力 bundle 的 Windows 构建通过。本组新增正式 M10 整例0。
