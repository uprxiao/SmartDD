## 首页首条问题的来源

原路径会把首页首条问题通过 `buildRunnerArgs` 作为一个参数交给所属启动进程；既有 `NativeUserInputs` 仅观察后续PTY输入，无法证明这个首条问题来自受信入口。本轮在主进程补齐该来源，不改变用户输入内容、参数转义或启动行为。

`createTaskController` 先执行原真实IPC sender检查，再把Electron事件作为独立主进程参数传给 `TaskService.create`。renderer请求体／额外参数中的sender不能替换它；公开RPC参数格式仍只有原CreateTaskRequest。内部代码直接create而未提供真实sender时，照常创建任务，但不登记用户来源。

`TaskService` 固定trim后的首条文本并按原规则生成argv；只有new模式、有非空首条文本及主进程sender，在所属PTY成功创建、沿用预留ID、`launch.spawned`完成所属进程身份登记后，才调用可选 `initialInput`。恢复／重新打开不把SQLite中的旧firstMessage重新登记或发送；spawn失败没有来源；之后任务落库失败走原撤销／停止流程，run信号清除已登记来源。来源观察失败不重复启动或重发已交给进程的参数。

`NativeUserInputs.observeLaunch` 再检查受信sender、当前task／PTY／run、固定选择和mail.send能力；文本直接登记为 `transport=launch-argument`，不解释成键盘控制字符，不附Enter，不改正在编辑的终端行，每个编辑器run仅登记一次。后续键盘来源为 `transport=terminal`。两种回执都只在RAM，仍须与正确版本、当前原生会话中的user记录双重匹配；均不产生邮件发送grant。

主要修改在 `src/main/core/tasks/{controller,task-service,capability-lifecycle}.ts`、`src/main/core/applications/{task-capability-launcher,native-user-inputs}.ts`。没有新增外部MCP命令或前端可提交的授权字段。

## 长会话核验成本

旧读取器对每条可解析user记录调用current guard，交付前还逐条重新打开及核对已匹配记录；在真实宿主，guard可能做内核进程与固定资源检查，不能让调用次数随日志行数增加。本轮先使用本次已核对的run快照做RAM候选匹配，读取完成后对原范围再读并逐字节比较，核对原路径设备／inode、大小、元信息、数据根／cwd，最后一次重新取得所属run，批量重验回执。

预算继续为4MiB尾部、1MiB单行、8192条、4096目录项、64条／4MiB proof；失败不返回来源。领取具体proof时仍单独重开原行并核对hash／身份／UUID及当前回执，不因批量读取而跳过执行前重验。`NativeUserInputs.match` 先筛选文本／hash／时间／项目／任务／run候选，只有候选存在才计算固定选择摘要。

两种格式各以3000条不匹配user行＋1条匹配记录验证：读取器的current guard调用为2次，随后verify再调用2次；这不是系统调用总数、实际CLI支持结论或跨机器耗时承诺。异步IO期间run撤销仍不能交付来源。

## 实验及证据边界

本轮相关12文件200项及最终类型检查通过；135项和此前子集与这200项重叠，不相加。用例包含受信IPC事件不可由请求体／额外实参替换、两种原生格式的首页来源／原生ID生成、内部无sender创建、spawn失败、任务SQLite落库失败撤销、观察异常不重发、长日志与run撤销。

真实OS集成使用实际 `PtyManager`、macOS进程身份helper及原CJS-MCP子桥，CLI为本轮私有合成程序。实际argv回执记录首条问题、CLI／桥PID；以该真实接收文本准备合成Codex user日志，再经原生ID发现和来源读取匹配。正常退出释放后恢复同任务，实际新进程末参数为原session ID而非首条问题，新run无原问题来源；grant为0。受信sender是受控测试对象，原生role日志为隔离前置，**不是实际CC／Codex模型、真实Electron首页UI或完整原生角色格式验收**。原始回执保存为actual-argv-and-resume.json，未记录日常凭据、完整环境或桥票据。

首轮类型检查被新测试的闭包变量断言写法阻止，调整断言后通过。第二轮133通过2失败，原因是新测试误把假PTY中尚未fork的armed桥预期为全部退出；生产保留unknown窗口的保护没有放宽。修正夹具分层：假PTY只检查来源失效和stopping保留；退出／恢复移到真实OS、确实启动并结束的工具桥。首测源、修正夹具、原始红／绿日志分别保留，不删除场景或用改业务预期掩盖失败。

新macOS arm64包、原生检查及包内main字节核对通过；最终source、package hash见[执行记录](../验收/执行与缺陷记录.md)及[结构化证据](../验收/证据/m10-initial-input-i-20261020.json)为准。没有UI变更：首页原输入、提交动作和CLI参数约定沿用8466734确认基线；本轮只补主进程来源与核验实现，没有操作原型或App界面。
