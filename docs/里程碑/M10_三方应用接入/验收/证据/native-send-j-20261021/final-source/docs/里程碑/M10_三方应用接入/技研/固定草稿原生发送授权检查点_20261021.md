## 已接通的业务路径

复用P07/P09既有的`mail-draft://`固定草稿引用，包括draftId、revision和contentHash。主进程必须同时找到实际所属PTY或启动参数的受信输入，以及当前原生会话文件中完全匹配的user角色记录；模型、RPC或工具参数不能提交批准标记来生成授权。在原发送服务冻结目标、正文、普通附件、SMTP身份／配置／权限与项目选用修订后，宿主解析本次真实用户文字并核对完整草稿修订。

当前支持含一个精确引用的直接发送祈使句，例如在既有引用后追加“请原样发送此草稿”，或“Please send this draft as-is”。引用默认的“读取并继续处理”不授予发送；问题、分析、条件、引号中的示例、修改收件人／内容的指令、多引用、错误／过时的ID／修订／hash均不能走该路径。此语法是本轮实现覆盖，**不增加产品必输格式或缩减需求**；“把刚才确认的回复发给张三”等唯一上下文、更多自然语言、消歧和补充确认仍待实现及验收。

授权可以在prepare后立即生成，也可在既有冻结意图的execute时发现随后到达的明确指令。原界面审阅确认仍使用相同冻结发送服务；原生授权不额外弹出一次界面确认。存在原unknown执行时，本轮简单指令解析不会批准复制草稿再次发送，仍须核实原执行及明确新动作。

## 来源、身份与执行重验

`NativeUserInputs`给实际完成的用户turn分配递增序号。后续非空提交、未知行提交、Ctrl+C、部分传输不确定、超长已接收传输、run结束／替换和过期使旧来源不能继续授予权限；空Enter与同一CRLF不制造新指令，粘贴内容需单独提交。历史来源仍可以核对，权限只使用当前最新的live来源。启动参数来源为该run的序号0，下一次用户提交使其失效。

实际输入回执只附当时非秘密的SMTP身份／配置／权限／项目选用摘要及全局／项目应用权限摘要。冻结时须与review相符；取消选用再选回、撤销后再启用也不能把旧指令变成新授权。同身份密码轮换不纳入邮件内容身份摘要，沿用原发送服务下一次认证取当前有效秘密的规则；不在回执保存秘密。

原生文件核验和所属进程检查在异步阶段执行；领取与发送事务内用原receipt／proof对象、run取消信号及最新序号做RAM守卫，应用权限摘要仅查本地SQLite，不在新增同步守卫中读取原生文件或检查进程。执行前再次异步核对原行字节／设备／inode／元信息和当前原生身份，随后C事务同步复验，覆盖核验后到提交前到达的取消。

持久证据使用receiptId、intentId和reviewHash派生稳定身份，保存来源hash、原生记录hash、输入来源元信息及解析动作，不保存完整用户输入、邮件正文或SMTP秘密。只有仍在RAM且受信的原对象可授权；仅修改SQL、宿主重启或复用旧来源均不能生成权限。一个来源仅领取给一个具体意图。源登记与原发送grant去重，同一意图仍只有一个实际执行；来源核验迟到时读取已有原执行，不再次提交SMTP。视图将已失效的授权显示为待明确授权，历史证据保留。
