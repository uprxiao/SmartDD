# 原生用户消息来源检查点 · 2026-10-20

依据需求R1.6（含12.21）、M10-R08-01–03及12.5；开发基线 `48714c7351c6f9ec0befa9916b8c88dfbd9aa9f4` 加本轮可恢复源快照。M10继续开发，整例验收不因本检查点增加通过数。

## 实现

新增 `src/main/core/applications/native-user-messages.ts`，复用既有 `NativeUserInputs` 和当前 `CapabilityRunRegistry`。读取入口只有主进程；没有新增 RPC、MCP 工具或声明授权的参数。受管 launcher在实际版本检查、固定资源准备完成后，以原run及其终止信号登记本次CLI版本；不从renderer、原创建版本或显示用诊断记录推导来源权限。

当前格式分支按已有适配版本名单限定 Claude Code 2.1.303、Codex 0.162.1；本轮在隔离文件夹具验证格式，不将它写成真实CLI已经接受新读取器的结论。CC仅接受本会话、正确cwd的user记录，拒绝助手、工具结果、meta及sidechain；Codex先核对首行session_meta的ID／cwd，再接受response_item的user／input_text，忽略event_msg镜像及助手／工具记录。多块文本按明确换行连接，与宿主实际接受字节再做精确匹配。

精确native ID从当前固定会话读取。CC仅检查当前cwd及其realpath对应的项目文件夹；Codex有界遍历日期目录查找唯一原session rollout，支持resume文件仍位于旧日期。数据根只在入口解析；根内目录／文件不跟随链接，拒绝重复候选、未知格式、身份不符和不完整元信息。目录预算4096项，读取尾部最多4MiB、单行1MiB、元信息64KiB；末尾未完成JSON行不参与证据。

每条候选还必须匹配实际被受信PTY接受并提交的用户输入回执，核对项目／任务／run／固定选择／原生ID、完整文本与时间。仅粘贴但未提交、别的run／项目、过期输入不能匹配。主进程以原对象身份保存不超过64条／4MiB来源证明，不接受复制JSON冒充；run结束或服务关闭清除。交付给下一阶段前及claim时重新核对原文件设备／inode、行范围／换行、原行hash、Codex元信息、根及cwd的realpath和当前运行／输入回执；追加记录可保留，替换、截断或原行变化失效。

`MailSendDataService`的发送准备在当前配置预检后读取原生来源，异步返回后仍核对context。结果只作为下一步具体意图解析所需的RAM来源，没有写入`mail_user_action_sources`／grant，也没有将含“发送”的文本当作语义授权。文件晚到、未匹配或源不可读不会伪造发送许可；原界面审阅路径仍可用。来源服务本身缺失不得阻止普通Agent启动。

## 实验与边界

本轮对两格式覆盖已提交中文／Unicode、多行、旧日期文件、未提交粘贴、部分行、损坏及超大行、错误角色／身份、复制proof、旧版本／过期、原文件修改／替换／追加、链接、run撤销及服务关闭。实际主进程／SQLite／原固定CJS工具＋本机SMTP夹具验证：发送准备确实读取匹配的原生user文件，仍没有用户授权、秘密解密或DATA提交。生产launcher另核对登记的是当前CLI版本及所属run信号。进程身份读取器及版本程序是合成前置，不冒充真实CC／Codex模型路径。

首轮来源测试在快照前置校验即失败，原因是新夹具未声明固定应用业务桥；补上正确桥后通过，没有放宽生产schema。保留原日志；首轮失败源码未同期单独留hash，不能补称已同期采集。后续最终源及完整日志另行固定。

最终测试、包与原生结果以[执行记录](../验收/执行与缺陷记录.md)及[结构化证据](../验收/证据/m10-native-user-h-20261020.json)的实际结果为准。
