## 实际票据重放

复用LN标准包及固定Codex0.162.1，从真实TaskService经PTY启动原生Agent，实际读取固定Mail Skill并经生产MCP保存一份无收件人／SMTP的本地草稿。对原宿主和宿主正常关闭后同ID恢复的两个run分别验证：

| 场景 | 实际结果 |
| --- | --- |
| 观察已消费票据 | 在本次隔离App主进程观察真实broker写出的0600单次文件；匹配当前run及ledger内active bridge的准确ID，核对受限目录0700／当前uid、文件已由真实Codex桥消费。只保留原内容于RAM，报告记录文件／秘密SHA256 |
| 原秘密直接再交换 | 向该App当前endpoint发送原exchange，返回AUTH_REQUIRED及持久审计ID；原桥仍connected，原run／进程、S、草稿和发送意图逐行保持 |
| 原文件已缺失 | 精确当前打包可执行文件＋原固定缓存CJS＋原路径启动，exit1、stdout为空、stderr仅`WillYou application bridge unavailable` |
| 显式还原已消费文件 | 在原目录按wx／0600临时重建**内容和有效期均未修改、尚未过期**的已消费文件，登记新inode。精确同一运行时消费文件后仍因spent secret无法取得授权；exit1及相同纯净输出，文件再次移除；没有修改broker签发表或鉴权 |
| 宿主重启后的旧票据 | 新宿主／新run采用新hostGeneration及新秘密；把旧宿主票据送到新endpoint仍AUTH_REQUIRED。已有旧运行token重放也拒绝，旧endpoint关闭且其私有目录已清理 |
| 原业务继续 | 两轮负控都不改原run／子进程／S／草稿／发送意图；原正式桥保持connected。随后实际原生resume的工具查询仍取得原草稿，不重复创建、不修改修订 |

四个负向CJS进程使用空PATH目录，命令固定为当前打包可执行文件，没有选择其他Node／Python；没有启动普通App回退数据目录。它证明这些负向启动路径不依赖其他运行时，**不等于已执行关闭RunAsNode的构建负控，也不外推正常握手的完整空PATH矩阵**。

两轮产生5条新票据拒绝审计：原run直接重放／重建文件，恢复run同样两条，加旧宿主票据一条；均为exchange／AUTH_REQUIRED，未经认证的run_id／bridge_id为空，不采信调用方身份。3个直接wire响应逐一对应审计ID；另有旧运行token拒绝1条，原driver核对其持久记录。没有把一次性文件恢复为可重用凭据。

新驱动在冻结重放基线前只读等待Task.nativeSessionId已绑定进S，且诊断snapshotHash与SQLite对应；没有直接写S。首次Skill读取为实际原生shell读取，模型选择由私有Responses合成服务明确给定；resume后只执行草稿查询，不宣称再次读取Skill或真实模型自主推理。

## 当前包断桥降级

另建一套HOME／CODEX_HOME／userData／项目，仍使用同一LN包。新建及宿主关闭重开、同native ID／固定S恢复后，查询本run唯一active bridge的PID／启动时间，用包内内核helper核对一致，再仅向该桥发送SIGTERM。

当前原生Agent及PTY继续，run仍active，诊断bridge.connected=false／RECOVERY_UNSUPPORTED；随后真实Codex工具调用报告Transport closed，普通回复仍完成，草稿数量1及原修订保持。没有自动停止／resume Agent、冒充恢复成功或重放草稿写入。最终清理后，两套App合计4个run均stopped／revoked，登记CLI／bridge进程均exited／canceled，每套草稿1、发送意图0、app_secrets0。

这是当前标准LN包的实际复验，更新DF旧候选包的适用边界；DF当时“尚未合入”的文字保留为历史时点，不能再当作当前feature没有恢复监督实现的事实。当前源码确有BridgeSupervisor及正式宿主接入，内置真实Agent独立重载能力仍unverified，没有改为supported。

## 观察与故障作用点

新增`scripts/applications/fixtures/bootstrap-replay.mjs`及外部driver开关`WILLYOU_BOOTSTRAP_REPLAY_CHECK=1`，要求同一标准包的host replay／restart前置。临时主进程观察器只在原fs.writeFileSync完成后解析指定broker目录／uuid单次文件；原参数、写入、返回／异常原样传递。现有Socket.write观察器同样原样转发。写后观察带来小额观测开销，没有改变认证、响应字节、时间常量或恢复策略；每个阶段重放前已恢复原方法和builtin导出，finally也执行清理。

故障注入仅为本次broker原路径的已消费文件重建，使用准确内容／inode／权限，未改主进程签发表；finally仅允许清理自己的重建inode。断桥故障只针对另一轮当前run的已核验桥。原App／运行／数据均为本批新建，不连接日常实例或复制日常凭据。

第一轮检查两个临时bootstrap秘密在296个本次根内、每个不超过1MiB的常规文件、当前3个自有PID argv及App日志中均不存在。排除3个原生CLI临时软链接与约2.95MB的原生state_5.sqlite-wal，明细在报告；不宣称完整磁盘／所有WAL脱敏已通过。包内与缓存CJS逐字节相同，报告只保存秘密哈希，未归档bootstrap内容、数据库或完整HOME／userData。T01/T08系统安全存储仍待原钥匙串前置。
