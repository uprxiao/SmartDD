## 格式2构建的准确含义

JQ标准版Foxmail连接当前仍为物理schema1。测试私有副本静态编译了合成演进：

```json
{"kind":"foxmail","storage":{"path":"<private source>","account":"receiver@example.test"},"range":{"days":30},"access":"local-readonly"}
```

配置视图将其等价映射为固定API1的`sourcePath/account/queryDays`；认证为本地只读。迁移事务只递增连接／配置修订，保留connectionId、identityRevision及已核实身份，前后视图摘要相同。严格保留原有三个标准转换器及hash，只增加编译的schema2入口。`protected-local-v2`是无法向旧契约表达的合成安全设置，实际转换注册表拒绝，不将它删除后当成功。

私有宿主启动及迁移均校验真实路径必须为本次`/private/tmp/willyou-m10-config-upgrade-*/userdata`。源码JQ App不被改动；私有ASAR重新写入完整性摘要、临时签名，并保留原生文件权限。缺转换器故障仅在私有编译配置视图入口使用空的实际注册表；其他故障改本次独立数据库。每轮恢复并校验原配置，未替换safeStorage、权限、凭据或业务RPC返回值。

因此，这证明通用兼容链路在**明确标注的合成物理格式2测试构建**下可工作；不宣称正式Foxmail格式2已发布，也不宣称所有未来Data API均兼容。当前两版工具Data API都为1，数据库迁移27→29不能单独证明Data API2兼容。
