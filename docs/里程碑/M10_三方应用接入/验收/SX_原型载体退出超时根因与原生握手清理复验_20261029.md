# SX：原型载体退出超时根因与原生握手清理复验

2026-10-29，R1.6＋§12.21／T22现有PB、SW外部验收夹具；feature/0.0.2／f1f1728d68a8595e665d4833dff048189e63e0f8＋1505选定源。**正式48/72通过、剩余24、66.67%，新增整例0**。23待收口＋T45历史替代1，M10仍验收中，未发布。

## 原因与修正

SW两批P“正常退出未结束”不是已证明的产品退出缺陷。生产before-quit向当前原生renderer发送files:close-request，等待save和commit原回执；P通过Page.navigate把原App页面换为独立静态原型，它没有安装installFileCloseHost，不能以此页面代原生文件保存宿主。生产协调器30秒保守超时，旧PB夹具15秒等待已经先失败。

通用preload **electronAPI在P页面仍存在**；退出宿主不等于桥对象存在。文件controller仍有原可信主界面及owner核验，本轮没有调用伪造answerClose、替换closer、放宽信任或删除退出监听。初版诊断错误地预期桥不存在，实际true导致夹具失败，保留原记录；不将它称为信任规则被绕过。

新增外部helper捕获本次唯一隔离窗口原始file: URL和userData；P结束后验证当前页面属于本次精确回环origin且为原型，再真实导航回最初原生页面，等待原UI／桥及挂载完成，然后按原App退出。PB/SW驱动的P结果单列prototypeCleanup；A原退出路径保持。本轮没有生产／原型源码、依赖或构建改动。

这是**测试载体清理**，不抵扣T24、M9文件保存／恢复或原型产品正常退出验收。SW旧超时事实保留，不能因新清理code0就倒改历史通过。P清理失败现在单独失败并返回非零，不再把它藏在页面passed内。
