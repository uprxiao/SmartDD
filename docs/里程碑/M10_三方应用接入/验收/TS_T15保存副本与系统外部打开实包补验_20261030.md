## 实现及缺陷

本轮检查发现：原附件只有文字查看及保存，二进制的外部打开确实未开发，不能仅归为系统工具阻塞。先补共享原型的合成状态，再接入生产。新增“保存并打开…”及保存历史的“打开已保存附件”；只有确认保存成功且临时材料核对完成才允许选应用。普通保存、取消、失败、unknown 均不自动打开。保存意图绑定具体操作和项目／目标，切换或迟到回执不串到新附件。

复用现有 M9 的 NativeFileBroker／NSWorkspace 打开方式发现和文件引用 URL，不使用 shell.openPath 或命令字符串。前端只提交保存 operationId 和本次不透明列表／应用 ID；主进程复核原权限、草稿成员／修订、副本 inode／device／hash／大小和应用身份，列表限制窗口／项目／操作及十分钟有效期，副作用前消费防重放。原生分发前再次校验预期修订；已有 M9 不带此字段的调用保持原语义。可执行扩展／MIME／魔数拒绝从此入口启动。外部应用取得用户选择的独立保存副本，原来源与不可变 blob 不交给编辑器；只提示“系统已接受打开请求”，不声称完成阅读／分析。

两个原 UI 缺入口红测留存；保存并打开意图串到后续操作及旧目标迟到风险由代码检查发现，新增对应验证，不冒充已捕获实包红测。沿用既有 AppDialog、字段及主题样式，无新视觉方向；没有宣称全页面浅深或像素一致。
