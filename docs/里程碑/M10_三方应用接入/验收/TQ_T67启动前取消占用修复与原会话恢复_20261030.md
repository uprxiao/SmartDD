## 2. 发现与修复

实际缺陷 `M10-TQ-01`：`TaskService.spawn()` 在 `await beforeSpawn()` 返回后才进入原 `cancelBeforeFork` 保护。用户取消、准备异常或宿主退出发生在 arming 的异步阶段时，CLI／bridge 已 armed、OS fork 尚未尝试，却只执行普通 stop；记录停在 stopping、租约保留。

修复：

1. `forkAttempted` 移至整个启动闭包；所有启动前失败都先提供原宿主 `cancelBeforeFork` 回执，成功后移除无 PTY 的内部运行项。宿主已关闭时同步解除无运行项的退出监听。
2. 原 registry 允许这份回执在原窗口已 stopping、或 reserved 窗口已被 stop 取消后幂等完成。仍校验原 owner、run PID 空、所有登记进程归当前 owner 且仅 reserved／armed／canceled、子 PID 空；实际 attach、unknown、已收到实际 exit 的窗口保持拒绝。
3. OS fork 已尝试后的失败沿用保守 stop，不使用 no-fork 回执，不重试或伪造原生退出。

生产改动仅 `src/main/core/tasks/task-service.ts`、`src/main/core/applications/run-registry.ts`；原型及业务流程不变。
