**交互规则（与需求一致）：**

1. 发件身份由真实选用的连接及其**修订**推导，不是手选的演示值：Foxmail 账号目录名为邮箱且与发件地址一致→自动确认；为邮箱但不一致→拒绝，**没有**任何确认入口；未选用 Foxmail 或目录名不是邮箱→用户确认，确认记录绑定发件账号、Foxmail 来源及其修订，任一变化即失效并提示重新确认。读取与草稿在任何状态下都不受影响。
2. 「Foxmail 账号目录名样例」开关只改变本区的合成显示，用于演示“目录名不是邮箱”；产品从来源所在账号目录读取目录名，不使用手填账号字段。
3. 运行计划场景（合成）：①Codex 0.166.0 已声明版本：禅道生效入口 CLI；②未声明版本：CLI 不交付，禅道降级为只读 MCP；③用户沙箱无法证明等价：不注入 CLI，同样降级。邮件始终为 MCP，写能力不允许降级入口。`L2`（已验证发现／读取）与 `L3`（聊天原话授权）在 0.166.0 上始终显示「未验证」，页面写明发送使用页面授权。
4. 「无降级入口的能力本次运行不可用」状态的模型与文案已实现（`runPlanForApp` 的不可用分支），当前三个场景中没有应用触发它，因此**页面上尚不能操作到该状态**，仅由模型测试覆盖。

- **模型层** 11 项单测通过（`tests/m11-preview-model.test.mjs`）；原型工程中与集成、连接、草稿、活动、清理、邮件、应用相关的已有测试加上述 11 项共 106 项通过，无回归。
- **构建**：安装依赖（`pnpm install --frozen-lockfile --ignore-scripts`，补装 `docx-preview` 等 5 个包，不入库）后，`vite build` 通过（仅有包体积警告）。此前的构建失败原因就是该依赖缺失，与本次改动无关。
- **浏览器检查（真实 Chrome 无头模式，隔离临时用户目录，合成数据）**：驱动 [`验证/m11-proto-check.mjs`](验证/m11-proto-check.mjs)，**28 项断言全部通过**，覆盖：
  - 项目「应用」页：未选 SMTP；真实点击选用 SMTP 后 Foxmail 目录与发件地址一致→自动确认且无确认按钮；不一致→拒绝，文案含「不能用确认覆盖」，且页面上**没有任何确认类按钮**；取消 Foxmail 来源→需要确认；真实点击确认→已确认；刷新后确认保留；SMTP 修订变化→失效；真实点击重新确认→已确认。

**本轮检查中发现并处理的问题（保留记录）：**

1. **产品设计缺口（已修）**：历史会话没有固定能力快照，运行计划区原先在此情形下什么都不显示，用户会误以为功能缺失。已改为明确说明「本会话没有固定的运行计划：历史会话不补造入口或适配等级」，由断言 S0 覆盖。
2. **样式问题（已修）**：首版截图显示发件身份与运行计划区块内文字间距过大（`.m10-note` 自带 16px 外边距与 grid 间距叠加）；已统一清零内部外边距并收紧能力行，修复后 28 项断言仍全部通过并重新截图。
3. **驱动错误（非产品缺陷）**：第二轮运行中邮件未出现在运行计划里，原因是驱动没有切到 AIS 项目（工作台默认项目 WillYou 的邮件应用未启用），改为真实操作选择项目后通过。
4. **检查盲区（已补）**：原断言没有覆盖「发件身份已确认时发送可用」，补充 S9b、S9c。
