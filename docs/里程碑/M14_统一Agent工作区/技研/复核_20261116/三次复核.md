## 4. 不影响关闭、开发时注意的事项

1. **用户可见的行为变化**：父 Agent 委派一个会写文件的子任务后，界面上的顺序是：父回复“已排队”并结束本轮 → 子任务运行 → 父自动续跑并读取结果。父子不会同时写同一个目录。这是方案 B 的直接结果，原型阶段要把这个过程画清楚。
2. 目前每次交出写入权都要等父进程退出、再恢复会话，会多花几秒。进程存活时交出写入权是开发阶段的优化项，届时需要补真实验证。
3. `max_tokens` 映射为“受限”，但需求 R02 的“受限”指额度／限流。界面文案要区分“输出长度到上限”和“额度用完”，原型阶段定。
4. `t3-baseline.mjs` 中 `fork` 的删减理由写成了“R10: …”，R10 是旧代码清理，引用不对，改成“本期无线程分叉”即可。
