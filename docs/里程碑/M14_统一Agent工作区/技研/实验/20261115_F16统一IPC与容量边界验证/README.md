## 实际运行

Electron 42.11.14、macOS arm64，独立 userData／sessionData，两个隐藏 BrowserWindow；无真实账号、模型调用、项目正文、网络服务或日常 App。当前 SmartDD preload/index.ts 仅擦除 TypeScript 类型与转换 import，执行行为保持；主进程服务、渲染器状态机为候选。Python 真实 SQLite／WAL 的 Host 从既有同步探针按 AST 抽取原方法，未重新实现 CAS／事务／重放逻辑。该数据库是同步／草稿局部关系，不是最终 C1.9 全库接线；共同命令原子合同沿 F01。

[最终 IPC 结果](result.json)为 attempt-Nx4Jrp，9／9；[缓存结果](budget-result.json)为 4／4。预期断连错误日志是 I04 的注入，不是运行未通过。子进程正常退出 0、SQLite integrity_check=ok、窗口订阅全释放；未测系统断电。沙箱内首次 Electron 启动退出 134、未运行用例；经自动审批允许的相同隔离启动后取得真实结果。

| 检查 | 实际证据 |
| --- | --- |
| I01 丢尾 | 提交一条终态且不发通知；显式调度到 4999 ms 不查询，5000 ms 经实际 IPC 查询水位／补拉恢复。时间由夹具推进，不是墙钟延迟测量 |
| I02 慢消费者 | 2001 条新增事件期间不 ACK，主进程仅发一条、保留一个最新水位；最多 8 页后走快照，终态 seq=2002 未丢。错误 token 不释放，正确 ACK 才再发最新水位 |
| I03 迟到回执 | 主进程已提交 send 后暂扣 ACK；渲染器切至 B 并编辑，再释放 A 回执，B 草稿保持；相同 operation 重试 outbox 仍仅一条 |
| I04 有限失败 | 3 次已结算的断连错误后暂停，后续 tick 不再调用；显式恢复成功。原首败见下文 |
| I05 裁剪 | 已裁剪事件不能靠旧游标重放，权威快照恢复持久终态 |
| I06 坏批次 | 缺号、UTF-8 超单事件上限、129 条页均整体拒绝，cursor 不部分推进 |
| I07 真实窗口销毁 | A 的发送已提交但 ACK 未返回时创建 B；销毁 A 撤销其订阅，迟到回复不清 B 草稿；B 窗口继续查询 |
| I08 挂起调用 | 水位响应扣住，到逻辑 15 秒截止暂停并轮换 epoch；在途未结算时点击恢复不新增请求，迟到回复不解除暂停，结算后显式恢复成功 |
| I09 字节分页 | 40 条带中文的事件，原始批次超过 1.2 MB；宿主按 256 KiB 信封裁页，连续补拉到末序号，不按字符数误计 |
| B01–04 | 实际 2000 项／8 MiB 缓存阈值、旧页 epoch、tombstone 防复活、冲突整批拒绝、32 KiB 精确编码边界及 base64 范围余量 |

## 失败与修正

首批实际 IPC 的 I01–03 成功，I04 失败：先前补拉超限转快照成功后没有清零连续失败计数，导致第三次故障注入尚未执行就提前暂停；手动恢复又吃到残留故障。第二批只增加状态诊断，确认 attempts／recovering；之后在成功快照处清零计数，原检查通过。不是放宽三次失败的判据。首败源码、两份 failure.json、成功七项旧批次和最终九项批次均在[原始档案](evidence.tar.gz)，由[文件摘要](archive-manifest.json)核验。

补充 I08／I09 是既定“恢复有界／字节队列”范围内的边界，不新增研究项。I08 使用实际扣住的 IPC 响应与显式时钟，不证明 Chromium 后台计时精度；协议规定恢复可见时立即核水位。缓存探针没有 DOM，编码预算不等于 JavaScript 堆占用或 RSS。

## 设计与复用边界

现行[技术方案 §4.5.1](../../技术方案.md#451-f16统一-ipc-与缓存的固定初始预算)固定帧／队列／页／读取／缓存／artifact 数值与超限路径，§10.3 固定输入、审批、切换、恢复及组合状态的允许操作。配额是首期宿主政策，独立探针仅验证上述关键边界；SDK 内部峰值、总吞吐、全局并发公平性、实际产品桥与安装平台仍由 A43／44／45／52 验证，未声称已经全面达标。

[来源审计](source-audit.json)核对当前 preload、旧同步算法及 T3 引用。T3 实际分页合并／流预算模块保持；SmartDD 的旧 controller／tasks-store／控制服务器等已变，不沿用它们的旧整链结论。其独立算法证据仍可复用，当前入口由 F09 与本批 preload 限定支撑。[分页实验](../20261114_历史分页与实时合并验证/README.md)的 16 项、[同步实验](../20261114_同步与草稿合同验证/README.md)及[输出实验](../20261114_长输出缓冲与存储故障验证/README.md)的持久化／存储故障各保留原范围；F07／F10 保留原输入／产物租约合同，不因此次 UI 缓存淘汰删除数据。

档案解压后可运行 `node budget-probe.mjs`；Electron IPC 使用本机已安装的 Electron 执行 `main.cjs`，创建新 attempt，调用 `/usr/bin/python3 worker.py`。前置 Electron 42.11.14、Python 3、Node 26.5；无需安装项目依赖或启动真实产品。测试合成时序／接口，不计界面验收。正式产品用例全部未执行，视觉、IME、滚动、语音焦点及实际服务接线的验证留在原 A 账。
