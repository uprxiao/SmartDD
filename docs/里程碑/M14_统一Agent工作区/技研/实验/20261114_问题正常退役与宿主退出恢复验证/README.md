# 问题正常退役与宿主退出恢复验证

日期：2026-11-14。关联 D06、Q11／26／27。修正上轮研究驱动将正常收尾也写成取消的局限；只改临时研究候选，没有修改产品代码。

## 结果

最终同库 SDK 场景六项通过：保留同文子问题隔离、父候选指针变化、取消兄弟隔离和同 native session 新代次旧回应拒绝；新增正常／取消差异与事务失败回滚。三处真实宿主 SIGKILL 恢复检查也通过。

| 分支 | 实际证据 |
| --- | --- |
| 正常 B／A2 完成 | 实际 MCP 收到答案，native 退出 0；实际 run stopped 后，问题 expired、cancel_requested=0、答案 submitted；等待入口结束，close_evidence 仍为空，消费不作通用确认 |
| 主动停止 A1 | 先记录取消并关闭发送 gate，再 interrupt；native 退出 1，cancel_requested=1，未记录用户答案；不影响 B |
| 错误退役 | 活跃 run 不准退役，复制出来的句柄被拒绝；正常退役重复执行幂等，晚到新回答被拒绝 |
| 事务故障 | 在退役证据插入后、活性更新前触发 SQLite 错误，证据与活性整体回滚；重试只退役，不重发答案 |
| 退役前宿主退出 | 原生子进程均已退出；新宿主将旧 open 入口置 expired，保留 submitted 与无取消意图，不重建回调 |
| 退役事务中宿主退出 | SQLite 回滚未提交证据及活性变更；恢复与上一分支一致，没有半条提交 |
| 退役后宿主退出 | 保留已提交 runtime-ended 证据、expired 与原决定；重复恢复结果相同，不生成 native resolved 或自动重试 |

三个退出检查点均先核对实际 PID／出生身份，旧宿主仍运行时恢复被拒绝；只终止驱动捕获的研究宿主。每个宿主的三个原生进程在 SIGKILL 前已退出。三份恢复库及最终正常库外键／完整性通过。首次正常实验六项通过后增加退出检查点，最终版本再跑六项通过；不把重复执行另算新覆盖。

## 设计决定

请求活性与取消意图分开。运行结束只证明旧回调失效；没有精确原生请求关闭证据时，保守记 expired 并附 runtime-ended 原因，而非伪造 closed／resolved。正常提交的答案继续保留 submitted；显示层由取消意图、退役原因、投递事实分别构造状态，不能把 expired 一律显示为“已取消”。

候选在实际 run 活跃时，以原生回调的私有句柄绑定真实注册器和原运行句柄；退役复核原 task／run／snapshot、实际 stopped 状态和原生 PID 出生身份已停止。在同一事务保存退役原因并结束旧等待入口。恢复仍要求旧问题宿主确认停止，不复造活句柄或自动重发。原生结束和业务副作用结果保持分离。

这是固定 Claude SDK 0.3.321／native 2.1.321 与本机合成模型／MCP 的独立研究。父子关系和回应账仍为候选；没有真实用户审批、实际父 Provider 切换、Codex 混合委派、完整 delegate／outbox、业务在途写或 UI。退出实验发生在所有原生进程已结束后，不覆盖原生仍活跃、发送未确认或外部副作用未决的宿主退出；那些分支不能由本轮结论放行。
