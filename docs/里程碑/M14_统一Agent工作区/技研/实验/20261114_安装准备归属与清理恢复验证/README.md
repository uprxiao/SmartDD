# 安装准备归属与清理恢复验证

日期：2026-11-14。关联 R11／Q56。对前轮复制中断半成品遗留的独立候选修正验证，不是产品功能实现。

## 候选变化

实际 ResourceStore 和进程身份组件保持当前源码。临时安装器新增 attempt 表：安装请求与每次准备分开，复制前记录专用路径、原 owner 内核身份、父目录和 stage 物理身份。状态分为 planned、copying、prepared、cleanup-deleting、removed、consumed。发布／激活继续沿用前轮合同。

登记计划后创建目录；只有物理身份写入 copying 才能开始复制。恢复先确认旧 attempt owner 已停止、路径和身份一致，且部分文件属于清单限定的路径／类型／大小范围，再记录清理意图、清理、记录完成。新准备使用新 attempt，旧行不被覆盖。对已登记 stage 的普通复制失败也保留现场，避免未经归属核对的自动删除。

## 实际检查

| 编号 | 中断／异常 | 结果 |
| --- | --- | --- |
| T01 | planned 已提交、目录尚未创建时退出 | 对账为无剩余材料，记录旧 attempt removed，以新 attempt 完成 |
| T02 | copying 身份已提交、尚未写入首字节时退出 | 清理已确认的空准备目录并重建 |
| T03 | 文件部分写入时退出 | 旧半成品有归属，清理后新准备完整发布；不留下未关联目录 |
| T04 | 目录已创建、物理身份尚未提交时退出 | 保持 planned／不明现场，拒绝自动删除或继续 |
| T05 | cleanup-deleting 已提交、删除前退出 | 沿原 attempt 重新检查并完成清理／新准备 |
| T06 | 目录已删、removed 尚未提交时退出 | 用原清理意图对账缺失，不误认为未登记材料 |
| T07 | 半成品中混入未知文件 | 拒绝自动清理，未知文件及原默认不变 |
| T08 | 原路径换成新目录 | 拒绝清理新目录，原材料和替换目录均保留 |
| T09 | 完整 prepared 的内容损坏 | 继续按完整性失败处理，不能套用半成品清理规则 |

9 项检查通过。21 个受控 worker 均有终态：11 次预定 SIGKILL、6 次成功、4 次预期拒绝。最终 6 个 consumed、5 个 removed；2 个 copying、1 个 planned、1 个 prepared 均是上述拒绝场景保留的记录，不被计作可用安装。

## 边界

本轮改善了 §4.85 的已登记复制中断路径。目录分配后但物理身份尚未落账的窗口仍保守保留，不能宣称所有安装中断均可自动恢复。半成品的完整内容摘要尚不存在，清理依据是私有目录归属及允许的文件集合，不是任意字节来源证明；不适用于用户目录或外部程序目录。

没有证明最后身份检查到删除之间对同用户恶意并发替换的原子隔离。没有断电／内核崩溃耐久性测试；进程退出恢复不能替代文件及目录 fsync 顺序验证。真实包、网络中断、资源租约／GC、在用原生会话和其他平台仍需联合。产品和共享原型未改。

## 复现与证据

执行 `node probe.mjs`，需已记录 Node／SQLite／zod 与 Mac 进程身份工具。实际模块由前轮当前源码构建，本轮先复核 379 个源码摘要与 bundle；归档保留实际 bundle、构建脚本、候选改前／改后文件及所有原始 worker 记录。路径仍含本机依赖绝对路径，不是独立发行包。
