# 历史复制提交与旧根占用验证

日期：2026-11-14。关联 R08／R10、Q13／Q49。当前 SmartDD 的 copyClaudeSession、CapabilitySessionRegistry 和 SQLite 实跑；Task 指针为合成事务回调，M14 迁移及修正守卫为临时候选。

## 七项结果

| 检查 | 实际观察 |
| --- | --- |
| H01 伪造复制收据 | 没有进程内可信身份，实际注册器拒绝，元数据不变 |
| H02 复制后源文件变化 | 真实收据失效，元数据不变；恢复合成源文件后重新复制取得新收据 |
| H03 Task 指针回调抛错 | 同一 SQLite 事务内的快照、身份、历史版本、引用与合成指针全部回滚；磁盘副本保留，未自动激活 |
| H04 有效收据重试 | 实际 adoptLibrary 成功提交；原目录、其符号链接别名及当前目录均拒绝另一任务认领，相同原生 ID 保持 |
| H05 早期 M14 候选负例 | 迁移把不同 selection 的旧根版本保存为 unmapped，却仅检查当前 identity_root；旧 claimBinding 允许另一绑定认领旧根，负例后回滚该插入 |
| H06 候选修正 | 在同步事务中核验保留历史的 Schema／摘要／所属任务／规范根，并关联原绑定后，拒绝旧根、别名及当前根，未插入新绑定 |
| H07 独立身份与别名 | 不同原生 ID 可建立新绑定；同一 ID 经目录别名第二次认领被拒绝 |

最终七项通过，两套数据库完整性与外键检查均通过。没有原生 Agent、模型请求、用户数据、真实 TaskService 或 SVN 项目复制。实际历史复制仅包含该 ID 的合成 JSONL 与同名子树。

首轮 H04 因驱动匹配了不同中文错误消息而失败；实际返回 NATIVE_IDENTITY_CONFLICT 正确。改按稳定错误码断言后重跑，失败和当时驱动完整保留，不把它归为产品缺陷。H05 则是确实成立的旧研究候选缺口，不是现役注册器的缺陷。

## 设计影响与边界

保存旧历史正文不等于保留其身份占用。M14 在迁移不同 selection 的历史版本时，须同时保留规范根／原生 ID／执行器的占用与原 binding 的关联；新旧入口及别名统一检查。禁止把同 task 的另一个 binding 自动视为同一占用者。

本轮候选扫描保留旧版本验证合同，未交付最终索引化身份表。生产设计应采用可核验的持久占用投影与迁移事务，避免每次认领扫描全部历史；来源损坏／歧义不能当作空闲。删除旧版本必须保留所需占用，释放须有单独规则。

进程内收据不可序列化为重启后的权限证明。提交回调异常不是宿主 SIGKILL 或断电实验；磁盘副本保留后，重启对账、跨进程复制、最终 Task 指针／多 binding 同事务、旧根回退与回收仍待验证。原子提交的本次范围是当前注册器和合成回调，不扩张为整个应用恢复通过。

## 复现

固定依赖具备时执行 `node build.mjs`、`node probe.mjs`。build 只读取当前 SmartDD 源码并写临时 bundle，启动前后核对 379 条构建来源与产物；原迁移候选来自归档内 migration.mjs／candidate.sql。全部现场位于独立临时目录，保留终态 SQLite 及文件目录位置。
