# 历史恢复并发接管与覆盖防护验证

日期：2026-11-14。关联 D01、Q13／Q49。真实双恢复进程、实际复制函数／会话注册器／资源锁／进程身份，复制账、恢复 claim 与 Task 指针均为临时候选。

## 三项检查

| 检查 | 结果 |
| --- | --- |
| R01 旧候选负例 | 恢复 A 完成旧快照与文件检查后暂停；B 完成恢复提交，驱动向目标追加合成“后续历史”；A 恢复执行，先覆盖副本，之后实际注册器才以 RESOURCE_STATE_CHANGED 拒绝元数据提交。新增内容丢失，说明只在最终提交检查不足 |
| R02 排他恢复 | 候选在 SQLite 同步事务登记精确 pid／出生身份／generation；A 已领取时 B 被拒绝且没有执行复制，A 提交时同时完成 claim；新进程重查 committed，不重放 |
| R03 中断接管 | generation=1 的恢复者领取后被精确 SIGKILL；新进程证明其已退出，取得 generation=2，重新取得真实复制收据并提交 |

三个检查通过，其中 R01 是必须保留的失败行为反例，不表示旧候选安全。10 个 worker 全部终止：4 次预定 SIGKILL、4 次成功 exit 0、2 次预期拒绝 exit 1；三份 SQLite 完整性和外键检查通过。负例文件覆盖只发生在合成夹具，不涉及用户历史或产品代码。

## 候选约束

领取在同一 SQLite 事务复核 copied 状态、原 Task 指针、原 owner 活性和上一恢复 claim；活跃或未知恢复者不允许按时间过期接管。持有者在实际资源锁内、复制前复核 claim 代次／身份、当前快照与文件；提交回调再次核 claim，并与复制账／Task 指针同事务改为 completed。先验文件校验和最终快照 CAS 之间不能留下无归属的文件写入窗口。

这只是参与相同恢复规则的宿主之间的排他。它不提供 OS 全局目录锁，不能宣称阻止任意编辑器或非受管进程写文件。合法后续 Agent 续写、复制过程中退出、最终多 binding／身份占用投影、实际 TaskService、旧根回退及断电耐久性仍待联合。合成追加没有经过真实 Agent 或运行来源账，不作为正常续聊兼容的通过证据。

## 复现

固定依赖具备时执行 `node build.mjs`、`node probe.mjs`。baseline-worker.mjs 保留前批复制恢复候选；本批 worker 的 guarded 开关只用于同场景负对照，产品没有该开关。归档包含当次驱动、进程事件、覆盖前后字节、终态 SQLite 和 379 条构建输入摘要。
