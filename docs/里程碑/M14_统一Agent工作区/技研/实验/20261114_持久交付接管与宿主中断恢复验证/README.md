# 持久交付接管与宿主中断恢复验证

日期：2026-11-14。补 R02／R08／R10、Q13／Q48。**技术研究与隔离实验，没有修改产品或共享原型代码。** [组合结果](result.json)十项限定检查，由两个尝试按确切来源组成；[原件](raw-evidence.tar.gz)、[文件清单](evidence-manifest.json)、[审计](audit.json)、[构建](build.json)和[源码基线](source-review.json)可复核。

## 本批组合了什么

在同一隔离库中复用统一候选的 binding／capability revision／历史引用迁移，增加版本化的 delivery receipt 和成员表，合并历史、首次准备、交付准备、未释放 run 租约成员的 GC 读取。实际运行注册器签发句柄、核验资源并结束运行；实际 MacProcessIdentityReader 读取本次宿主 PID 与出生身份，实际 recoverCapabilityRuns 处理宿主退出。资源锁和数据库事务使用现有实现，应用包及 runtime 的物理清理也执行真实服务。

**重要限制：**真实注册器仍走 legacy reserve；夹具把该 run 关联到迁移出的 binding／revision 并设置 generation。未改为完整程序化 reserve，也没有启动 SDK／原生 Agent、投影目录或执行业务调用。profile 与包都是合成数据。此次 receipt 是交付占用合同的独立候选，不是完整新版 application run-plan。历史快照仍是合法 v2，旧 refs 保留，不能声称所有多绑定迁移分支已联合完成。

## 持久记录与释放语义

receipt 包含 store、task、binding、capability session、source snapshotHash、run、generation、配置 ID／修订、精确资源及代次；规范 JSON 摘要与关系字段互验，资源行须与计划完全一致。复合外键关联源修订和具体 run。所有者记录使用实际宿主 PID／出生身份及实例 ID，不用时间推断退出。

prepared 表示交付引用正在保留；adopted 表示 run 成员已提交而准备引用尚在；released **仅表示准备占用已释放**，实际 run 租约继续独立保留；abandoned 表示原 run 经恢复已终止且没有未收口进程／活动／运行租约，放弃该交付准备。released／abandoned 仍保留审计 JSON 和资源行，不要求已不再使用的文件永久存在。

正常接管核实际拥有的 run 句柄、当前政策、配置修订与资源；相同 receipt 的重复 adopt 不重复插入成员。准备释放还要验证每个成员存在且匹配。恢复不会通过序列化 receipt 重新获得运行权限，也不会自动重发任务：先核旧宿主确已停止，再由实际 run recovery 处理原进程记录，最终在锁内重读精确关联和终态才结束准备占用。宿主仍活、身份未知或原 run 未排空时保留。

## 十项检查

| 项目 | 证据 |
| --- | --- |
| D01 | 历史包 A、交付包 B、默认包 C 共存；B 没进入 source 历史 refs，准备转入 run 成员后仍不可清理；run 结束后实际删除 B，A 及交付审计保留 |
| D02 | 复制真实 run 句柄、过期 token 拒绝；重算 JSON 摘要后替换 binding／run／generation 仍因关系不匹配被拒绝，损坏活动 receipt 使 GC 保留。没有穷举所有关系篡改或双绑定真实运行 |
| D03 | 未接管不能释放准备；相同 receipt 再次 adopt 只保留一条成员。raw SQL 删除目标成员后拒绝释放，准备保护仍在；补回成员后成功 |
| D04 | 当前运行政策撤销或配置修订变化使 adopt 拒绝；同机活宿主不能被恢复路径回收。政策为实际 registry 的受控回调，不是完整配置服务联合 |
| D05 | 插入成员后故障使事务回滚，准备记录保留；之后接管／释放准备使此前可清理的旧计划失效。本项还改变交付记录，并非“仅成员改变”的独立证明；单独成员证明见前批 H08 |
| D06 | 准备提交后杀死独立宿主：先保持占用；实际 run recovery 将未派发进程取消并结束 run 后，候选结束准备引用，实际清理 B |
| D07 | 接管事务内写完成员和 adopted 状态但未 COMMIT 时杀宿主：SQLite 回滚为原准备状态，run 成员没有落盘；按实际恢复结果结束准备并清理 B |
| D08 | 接管 COMMIT 后、准备释放前杀宿主：双方保留的重叠状态持久存在；实际 run 恢复完成后再结束准备并清理 B |
| D09 | 准备释放后杀宿主：receipt 已 released，run 成员仍保护 B；实际 run recovery 结束 run 后才可清理，不能把 receipt 的 released 当作全局资源释放 |
| D10 | 接管后将 CLI 登记为 armed、尚无 PID 时杀宿主：实际恢复得到 orphaned，候选继续持有交付准备及运行占用，不自动重试。夹具没有真的调用 OS spawn，恢复方仍不能用这个外部事实伪造未派发证明 |

四个可收口窗口均再次确认源历史包存在。五个窗口使用独立 Node 宿主、精确检查点和捕获的 ChildProcess SIGKILL；包括 D09 修正复验共六次宿主终止。没有按进程名称查杀，也没有真实供应商请求。正常用例的数据库备份在 finally 结束 run 后生成，须连同中途断言阅读；D10 的未知登记保留在隔离数据库中，不代表有一个实际残留 Agent。

## 驱动修正与证据复用

attempt-y5cth9 的 D01–D08 完成，D09 因驱动统一期待 receipt 为 held 而失败，实际为 released。源码与该场景的原要求均表明这里仅准备占用已释放，run 成员仍必须保护；不是资源清理放宽。修正该状态断言，保留 GC 不可清理及实际 run recovery 后才能删除的断言，attempt-k8Hp9O 仅执行 D09–D10，均完成。候选逻辑、Schema、构建及其他十四个输入文件字节相同，D01–D08 复用原证据，没有重跑或冒充单轮十项全绿。两个尝试原件均保留。

## 尚需继续验证

- 将 receipt 合同纳入完整程序化 run-plan／新快照和实际启动服务，验证多绑定、多次启动、投影、原生 Agent 与业务资源；不能靠夹具事后填关联字段代替。
- 本批同一宿主中的正常准备取消未实现独立入口。宿主仍在但配置／业务授权已经撤销时，须允许可信启动闭包撤销自己的确定未派发准备；不能复用需要当前业务许可的 adopt 检查来阻塞清理，也不能用序列化 token 或 armed 无 PID 伪造未派发。当前 actual cancelBeforeFork 依赖拥有该启动闭包的调用方证明没有尝试 fork。
- 活动／未知的真实子进程与业务在途共同排空、接管和取消竞争、完整资源种类，以及迁移／双宿主并发仍待联合。D10 只证明未知被保留，未证明未知最终可自动恢复。

本批没有业务 invocation；实际 run stopped 不代表外部业务结果已经核对，未知业务及其保留依据仍须按既有合同单独处理，不能沿用本批无业务夹具直接释放。

本批确定了可持久追踪的交付状态及退出恢复顺序，未完成 SDK 迁移，也没有进行产品验收。
