# M14 保留实验的仓库外复跑

日期：2026-11-16。现行需求 R1.0／T1.0。每个保留目录的 `复跑.md` 和[机器目录](实验目录.json)由[编制脚本](编制复跑目录.py)生成；原 README 是该实验形成时点的记录，当前产品合同见[实施方案](../技术方案.md)。范围外迁移、受管 native 安装和方案 C 实验在历史，不要求修复其复跑。

## 1. 依赖与环境

先按[_运行环境](_运行环境/README.md)说明校验／解包到一个新目录，再用其中的锁文件分别准备 Node 和 Electron 依赖。运行器接受 `M14_*` 路径或等价 CLI 参数，不读取或复制认证文件。Node 22+；环境包 restore 使用其说明要求的 Python 版本。

```bash
python3 "$M14_EXPERIMENTS/_运行环境/restore.py" --extract "$RESTORED_NEW_DIRECTORY"
```

| 变量 | 指向与准备 |
| --- | --- |
| M14_EXPERIMENTS | 当前仓库 `docs/里程碑/M14_统一Agent工作区/技研/实验` 的绝对路径 |
| M14_ENV_ROOT | restore 的新根，含 tmp、bin、deps |
| M14_OWNER_ROOT | 独立 owner 依赖目录，按 `_运行环境/deps/willyou-m14-owner-probe/package-lock.json` 用 npm ci 准备，不向旧临时根写依赖 |
| M14_SDK_ROOT | 独立 SDK 依赖目录，按 `_运行环境/deps/m14-sdk/package-lock.json` 用 npm ci 准备；这是历史复现版本，不代表产品重新采用受管下载 |
| M14_NODE_MODULES | 本次运行的依赖根：Node 入口选 Node ABI，Electron 主进程入口选独立 Electron ABI；better-sqlite3 的原 owner 绝对路径也优先映射到这里。构建用 esbuild 仍从 owner 根取得 |
| M14_T3_ROOT | 固定到 fe59fa44d0 的本机 T3 检出，用于源码对照和链接识别；当前回放不追踪上游最新 |
| M14_ELECTRON_BIN | 与历史浏览器实验相符的 Electron 可执行文件；本轮 42.11.14 |

`process-identity` 可用补交二进制（仅原 macOS arm64 基线），或在新目录编译补交源：

```bash
xcrun clang++ -std=c++17 -O2 -mmacosx-version-min=12.0 -arch arm64 "$M14_ENV_ROOT/bin/process-identity.cc" -o "$M14_OWNER_ROOT/process-identity"
```

新编译哈希与旧二进制不同要记录，不能沿用原二进制身份。原 env.txt 提供编译依据；其他平台仍需其实现与验收。

## 2. 五类适配

1. **路径**：原归档保持字节；复跑器只在新副本把旧源码／依赖／工作根换成参数给定路径。显式 owner、SDK 依赖优先于恢复包中 source-only 根；每轮写 preparation.json。禁止把输出放仓库或覆盖已有目录，入口路径不得越出副本。
2. **内容寻址资源**：bundles、mcp-bridge.cjs、actual*.cjs 不重定位；复制后逐一验证 SHA。不通过改写包字节修复路径。需要当前源码版本时，在副本重建并使用新清单／资源身份，原结果不覆盖。
3. **当前源码构建**：所有 named esbuild build 导入经过同一包装，加入 node-pty 替身（程序化实验不会用 PTY）；bridge、driver、profile 各构建均覆盖。实际副本构建与包装核对见 portability-guards.json 和 portable-execution.json。
4. **Electron／ABI**：浏览器 main.mjs 用 Electron，better-sqlite3 必须在独立目录用 `@electron/rebuild` 针对该 Electron ABI 编译。Node 协议实验使用 Node ABI 的另一份；不反复覆盖同一模块。M14_ELECTRON_BIN 缺失时拒绝，不能回退 Node。Electron-as-Node 的 SQLite 冒烟只证明 ABI，不算页面或 App 验收。
5. **模式／输入参数**：plugin-exceptions 显式传 deny、uninstall、incompatible，各模式独立新输出目录。其他入口先按目录内原 README 的前置准备及构建顺序执行；不省略其输入，仅做 prepare 不代表实验运行。

复跑器解开两个压缩帧文件供原 K01–K34 回放使用；Python 交接和同步实验不需 Node 依赖。构建输出、数据库、HOME、端口和日志只在新副本；真实模型探针另需用户已授权的登录／环境 Key，不能把秘密写入文档或库。

## 3. 命令与结果

各目录 `复跑.md` 给出精确目录名、实际入口、构建入口、runner 和模式；公共入口为：

```bash
python3 "$M14_EXPERIMENTS/复跑.py" "<实验目录名>" --out "$NEW_RUN" --prepare-only
python3 "$M14_EXPERIMENTS/复跑.py" "<实验目录名>" --out "$ANOTHER_NEW_RUN" --run "<相对入口>"
```

如需先构建后执行：prepare 后进入回执的 experiment 目录，按本目录列出的 build 脚本顺序运行，再运行 probe；使用相同副本的构建身份。复跑器的一步 `--run` 只执行指定入口，不伪装成运行了整个目录的所有实验。

[外部准备审计](20261116_复核修订验证/results/portability.json)核对所有保留旧实验的入口、不可变资产与替身包装；[守卫](20261116_复核修订验证/results/portability-guards.json)核对新根、旧根及越界输入；[实际复跑](20261116_复核修订验证/results/portable-execution.json)记录本轮真正执行的代表组。它们与原复核的 22 组执行范围分开，均不计产品通过。
