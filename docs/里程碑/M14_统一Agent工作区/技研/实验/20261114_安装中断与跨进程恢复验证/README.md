# 安装中断与跨进程恢复：技术研究记录

2026-11-14；R02／08／10／11，Q01／03／48／51／52／53／54；技术方案 §12.1、验证账 §4.52。这里只是独立实验，没有产品代码、共享原型或正式产品验收。

## 验证对象

实际 SmartDD ResourceStore、C 协调锁、MacProcessIdentityReader 与独立 SQLite；临时增加安装请求、进程 owner、阶段和激活回执表。准备／发布候选继承上一批流式资源验证。每个 worker 都是实际 Node 子进程；暂停点通过 stdout 确认 PID 与内核出生身份后，驱动只用捕获的 ChildProcess 发送 SIGKILL，确认停止后由新进程恢复。

请求固定清单、来源路径、预期默认修订和请求摘要。接管前检查原 owner 已停止，锁内再次核对完整原记录；存活／身份未知不能接管。准备目录重新完整校验后获得新进程内句柄，发布恢复保留原 ResourceStore operation ID。默认指针与成功回执在同一 SQLite 事务提交；重试返回原操作收据，不能把收据当作当前默认版本、有效缓存证明或运行授权。

## 初次未完成记录与修正

attempt-k5kX17 没有终态结果，保留独立库快照及[复核记录](interrupted-attempt.json)，不计通过。源码复核发现驱动为无需暂停的 worker 也创建了 checkpoint rejection，而 complete() 没有消费该 Promise。该缺陷可导致正常子进程退出后主驱动出现未处理拒绝；原日志缺失，不能断言它就是当次唯一退出原因。

后续确认原记录的内核身份 stopped，且只读进程清单不存在相关实验进程，才重新启动。修正驱动只为暂停场景建立该等待，同时增量记录捕获 PID／事件／退出状态，finally 只清理自己捕获的 ChildProcess。本轮没有修改产品 ResourceStore 来使实验通过。

## 设计结论与未覆盖范围

T3 的版本目录和独立激活指针提供分层参考；WillYou 还需结合现有 ResourceStore 的原操作、归属和持久占用。安装操作与资源发布操作、默认选择与历史收据不能混为一条布尔 installed 状态。重新打开准备目录必须重新验证，不能序列化旧进程的 WeakMap 句柄作为信任凭证。

本批只覆盖已记录阶段之间的 worker 退出。准备文件复制中途、准备完成但目录路径尚未写入时可能留下无关联准备目录，仍需预登记／扫描及保留策略验证；不能由 I01–I07 推导所有指令窗口均恢复。HTTP 下载中途死亡、下载／解包到安装的统一恢复记录、真实 run 租约／GC、在用升级、完整 App／系统重启、原生签名及跨平台尚未完成。恢复时新 owner 的身份和故障结果应可诊断，失败后不自动替换版本、删除未知遗留或接管仍活着的进程。

激活表、安装任务表及驱动都是临时实验 Schema，不代表已决定正式表迁移。当前入口为 worker --version，不是产品 UI／业务调用路径，更不是正式安装验收。
