# SVN 目录协调与运行范围清理实验

日期：2026-11-14。SmartDD `40ea344a930aec37e36a803b7c621d3632d2d75a`；T3 `f313d0a6cb843551fb60e57a454a71e71a3a8c04`。关联 Q31–34／Q04／Q27。

## 实验对象

创建真实本地 SVN 仓库和工作副本，提交三个小型路径；不读取公司项目，不复制 10GB 项目。直接转译实际 pathIdentity／inspectDir；使用先前 O 实验构建的真实 CapabilityRunRegistry、ResourceStore、CapabilitySessionRegistry、TS migrator 与 MacProcessIdentityReader。目录租约 Gate 是新的独立候选类，使用真实 SQLite；不称其已成为产品服务。

## 8 项检查通过

| 用例 | 对象与结论 |
| --- | --- |
| W01 | 实际目录检测识别 SVN；pathIdentity 合并符号链接；svn info 的 WC 根与候选描述一致 |
| W02 | 同 WC 的两个子目录和符号链接入口被候选租约归到同一 WC 范围，拒绝第二写者 |
| W03 | 普通目录祖先／后代冲突；other 与 otherish 不因字符串前缀误判为同目录 |
| W04 | 第二数据库连接看到首连接已提交租约，不因另一个项目标识绕过；不是并发压力测试 |
| W05 | 候选 beforeFork 重读 realpath／dev／ino，拒绝获取租约后被重新指向的符号链接 |
| W06 | 现有 pathIdentity 对不存在目录回退字符串，候选写入路径不接受这种猜测，直接拒绝 |
| W07 | 真实父 Agent／工具桥进程接入现有 owner；主进程退出、桥仍活时保持 stopping，候选拒绝交棒；桥退出后再启动子写进程，实际写日志次序核对 |
| W08 | 反例：主进程自己 spawn 未登记后台子进程。主退出后现有 run 为 stopped，后台仍活并实际写入。候选要求独立 scopeDrained 凭据才能释放目录；通过专用继承控制管道让该自有子进程退出，再核验内核身份为 stopped |

W08 是**边界反例通过**，不是现有注册器已解决后台进程清理。被测注册器原本只承诺已登记进程／桥／业务，实验说明迁移到可产生任意 shell 后台工作的程序化执行范围时，需要补宿主生命周期合同。

W07 的能力快照由原 fixture 在自己的临时项目目录创建，进程执行 cwd 由实验选为 SVN WC；它证明注册器生命周期和候选目录门槛可以组合，不证明完整 launcher 已将快照 cwd 与实际 cwd 正确绑定。该一致性在产品接线中必须校验，不能照搬测试设置。

## 设计影响

1. 共享 SVN 按规范化 WC 根串行，普通目录按祖先／后代重叠处理；跨 projectId 共用一个宿主范围登记。初始化／fork 前重新检查物理身份，未知路径不降为字符串锁。
2. run stopped 与执行范围排空是两件事。不能只在外层目录表看 stopped 就释放；新的程序化路径必须把 ExecutionScope 的宿主清理凭据也接入 capability 运行完成与资源租约释放，避免库／脚本等资源也被过早回收。
3. T3 的 Claude 包装另有启动门闩、独立进程组、宿主失联监视、Agent scope／后代跟踪；只读了这些源码，未在本实验运行。可参考它的职责划分，不能把 root ChildProcess.exit 当成所有后代已退出。
4. scopeDrained 在本原型是测试传入的布尔值，生产绝不能让模型／renderer 自报。应由持有原 launch 身份、内核出生身份与执行范围控制句柄的宿主产生，并验证 run／generation／scope 对应关系。
5. 已知后台工作、清理失败或范围不明必须保持占用。进程组之外的逃逸、外部 IDE／手工 SVN 不属于“目录数据库锁”可强制阻止的范围；没有实际约束证据时不开放并行只读，也不声称操作系统全局独占。

## 未覆盖

没有测试真实 SDK 后台 Bash／原生子 Agent、进程组停止／setsid 逃逸、宿主崩溃恢复、PID 复用、外部修改、大小写敏感文件系统、跨卷、junction、Windows／Linux。符号链接复核只覆盖两次检查之间的显式改向，不解决检查与实际 fork 之间的所有 TOCTOU。

候选 gate.release 的状态读取与写表不是完整跨服务事务，缺真实 scope 凭据和并发启动闸门；它仅用来验证门槛与反例。W08 不以伪造 PID 结束进程，后台进程通过自身继承管道处理 exit 指令，最后 helper 核验退出。真实辅助进程均清理，工作副本与临时资源库已删除。

没有全盘扫描／复制逻辑；fixture 很小，不能从这些结果推断 10GB 多文件项目性能。依赖原实验编译模块的来源见相邻 `20261114_运行所有权验证` 的 build.json／构建脚本，本次不重录为新源码实现。
