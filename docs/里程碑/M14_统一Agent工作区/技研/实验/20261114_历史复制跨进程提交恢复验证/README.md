# 历史复制跨进程提交恢复验证

日期：2026-11-14。关联 Q13／Q49、D01。使用当前实际 copyClaudeSession、CapabilitySessionRegistry、ResourceStore、SQLite 与 macOS 进程身份助手；复制账和 Task 指针为临时候选，源／目标均为合成历史。

## 故障与结果

| 检查 | 注入及恢复观察 |
| --- | --- |
| C01 复制完成、元数据未提交 | 原宿主尚活时，另一恢复进程拒绝接管；精确 SIGKILL 后，新进程核验 copied 账、原快照、指针、目录身份及内容，重新复制取得新的进程内收据，再执行实际 adoptLibrary |
| C02 元数据事务内部 | 在实际 adoptLibrary 的同步 commit 回调中完成指针和复制账更新、事务尚未返回时 SIGKILL；新进程读到旧快照／旧指针及 copied 账，重新核验并复制、成功提交 |
| C03 提交完成后 | adoptLibrary 返回后 SIGKILL；新进程读到 committed 账与一致的新快照／新指针，不再复制、不重放提交 |
| C04 提交前副本变化 | 原宿主退出后改动合成目标文件；恢复拒绝，外部改动与 copied 状态保留，旧指针未前移 |
| C05 提交后副本变化 | 原宿主退出后改动合成目标文件；恢复拒绝，保留外部改动及已经提交的新指针，不自动回滚旧入口 |

五项通过。C01–C03 各增加一次新进程重复恢复，均识别 committed，不重放。14 个 worker 全部终止：5 次预定 SIGKILL、6 次成功 exit 0、3 次预期拒绝 exit 1。五份终态 SQLite 的完整性／外键检查通过，原 owner 均已证明停止。

恢复没有把 JSON 重新包装成可信 ClaudeRestoreReceipt。提交前恢复先验证实际旧会话与保留记录，再调用真实复制函数取得当前进程的新收据；副本或源身份／内容不匹配则保留现场。真实注册器处理元数据事务，宿主初始选择政策仅为固定空应用夹具；这不证明产品授权服务已完整接线。

## 设计影响与未覆盖

复制完成、原子提交完成与运行准入是三个事实。复制账和 Task／binding 指针必须进入同一元数据事务，恢复按数据库状态及实际文件身份分支，不能凭副本存在或旧进程内收据继续。提交后损坏不自动降级为“复制未完成”并重放旧输入。

本轮只覆盖复制已经完成后的三个提交窗口。未覆盖文件复制中途、两个恢复者同时接管、最终多 binding／身份占用投影、真实 TaskService、Agent 已经续写历史后的恢复、提交后镜像尚未完成的窗口、系统断电或目标文件系统的耐久性。after-commit 已包含实际 adoptLibrary 的镜像处理，不标成“事务提交但镜像尚未写”。

本批没有启动后续 Agent，文件变化为明确注入。不能将原复制摘要永久作为所有后续启动的硬门槛：合法续聊会写入新历史，后续须依据已提交 binding、运行与历史修订对账。此处拒绝只说明没有合法后续写入证据时保留现场，不证明所有历史追加都应拒绝。
