# 复制中断与版本回退验证

日期：2026-11-14。关联 R11／Q56。独立技术研究，不是产品升级验收。

## 实际执行

复用先前持久安装／激活候选，只增加 onChunk 观察停点。实际 ResourceStore 由当前源码重新构建；旧 bundle 的八个源文件摘要已过期，预检拒绝后未执行它。旧基线差异及本次构建闭包均保存。

在独立资源库安装合成 A，再复制合成 B 的 8 MiB payload。第二个块进入 transform 时暂停，实测私有 stage 已有部分字节且未满；仅对捕获的安装 worker PID 发 SIGKILL，并核对内核出生身份已停止。所有操作都是私有临时资源，不涉及用户安装或真实原生程序升级。

| 检查 | 观察结果 |
| --- | --- |
| C01 复制中途退出 | B 的安装记录仍 requested、prepared_path=null；没有 ready／发布资源，默认仍是 A，A 内容不变 |
| C02 新 worker 恢复 B | 重新复制并完整校验 B 后激活；原半成品目录仍在，而且不被新 prepared_path 关联 |
| C03 显式回退 A、随后重放 B 安装请求 | A 原目录 inode／内容保持；B 返回历史成功回执，但不重新激活，默认仍是 A |

三项观察检查通过；其中 C02 **确认了未解决缺口**，不表示安装恢复完整通过。五个 worker 有终态：一个预定 SIGKILL、四个 exit 0。没有调用模型、启动 Agent 或运行真实租约／GC。

## 设计影响与未解决项

候选流程只有 prepare 完成才写 prepared_path；因此复制过程中退出的目录没有持久归属。恢复成功不会自动清理它。不能靠 requested 状态推断从未创建文件，也不能按目录名／时间扫描删除所有相似目录。

正式方案须在首个数据字节写入前固定安装 attempt／owner 与专用准备目录的归属；目录分配前后的中断也必须可对账。copying 与完整 prepared 分开，半成品不得得到 ready 身份。已确认旧 owner 退出后，重试选择重新准备或经过验证的续传；原 attempt 的临时材料有独立保留／清理记录，不能用新路径覆盖掉旧路径证据。现有完整 prepared 的损坏应继续拒绝，不能混作普通未完成复制。

本轮仅验证旧版本保留、完整重复制和显式回退语义，并暴露缺口；尚未实现上述目录登记／清理候选，也未验证断点续传。真实原生版本、在用会话、网络／磁盘故障、下载中断、跨平台以及原生 GC 仍按其他证据或待验条件分别管理。
