# 原生运行资源安装的复用边界

2026-11-14，R02／08／10／11／12，Q01／03／46／48／51／52／53／54；技术方案 §12.1、验证账 §4.49。本批仍是隔离技术研究，没有安装到产品、修改原型或进行正式验收。

## 需要纠正的复用假设

现有 `RuntimeRegistry` 管理应用业务桥，不是通用 Agent 原生程序安装器：入口必须为 .cjs、单文件最多 64 MiB／总量最多 256 MiB、安装文件权限 0600，校验拒绝执行位。本次已安装的 Claude native 大小 323686048 字节，Codex 为 271011440 字节；二者均不能直接用该合同交付。R01 用 64 MiB＋1 的无业务内容缓冲区实际触发预算拒绝，并只读取真实程序的 stat；没有读取或复制数百 MiB 程序进入实验归档。

因此保留旧业务桥合同，Agent 原生程序需要独立资源类型／清单。可复用更底层 ResourceStore 的发布身份、内容路径、准备／校验／就绪状态、归属和恢复原则，但“类型字段能存进去”不表示 GC、租约、执行计划、诊断或安装 UI 已支持该新类型。

## 实际检查

`attempt-l3u46x` R01–R08 通过，全部使用当前 SmartDD 模块，仅构建时展开静态资源 glob，没有替换业务源码行为。

| 项 | 结果与边界 |
| --- | --- |
| R01 | 真实文件大小超过桥合同；实际 validateRuntime 拒绝超过单文件预算的合成缓冲区 |
| R02 | 小型合成 bin/codex 入口也因非 .cjs 被拒绝，不只是容量问题 |
| R03 | 正常桥安装为 0600；改为 0700 后实际 verify 拒绝，恢复权限后再次通过 |
| R04 | 通用 ResourceStore 用独立合成类型和专用校验器可发布带执行权限的文件；未执行该文件，也不是完整安装器 |
| R05 | 同宿主两个并发 publish 最终同一 resourceId，一次 materialize、一条资源记录；不等同跨进程竞争已验证 |
| R06 | 新版本 materialize 注入 ENOSPC 后为 recovery-required，旧 ready 内容与字节保持；不是实际耗尽磁盘或在用升级 |
| R07 | rename 后故障注入改字节，最终 verify 拒绝就绪；没有覆盖损坏现场 |
| R08 | 既有 resourceId 不能指向另一内容／路径，原身份保留 |

回调观测表明本路径 materialize／verify 均未在 SQLite 写事务内执行。源码另显示最终 verify 在 C 资源协调锁内同步执行；不能据此声称 SQLite 事务包含整文件散列，也不能忽视几百 MiB 同步校验对宿主事件循环和资源锁的影响。本批没有大文件耗时测量，性能是明确待验项。

失败的 C／D 候选保留 recovery-required 数据与文件作为证据，不强制清空或重标 ready。旧版本仅证明仍可读取，没有实际 run 占用、默认选择指针切换、回退、GC 或死亡安装宿主恢复。

## 对照参考

SmartDD Office／LibreOffice 是构建期准备固定引擎：锁定来源／大小／摘要、离线缓存、随后随包交付；不是应用运行时已有的通用下载服务。不能把构建脚本替换输出目录的做法直接套到在用 Agent 资源。

T3 CodexInstallation 的源码提供另一参考：流式下载并校验大小和 SHA256、独立临时目录、版本目录、程序 --version 检查及独立 active.json 激活。包完整性还检查 codex、codex-code-mode-host 和 rg，表明运行资源不能只记录主程序一个文件。这里是源代码审阅，没有运行 T3 安装器，不推定其与 WillYou 的资源／业务租约合同一致。

## 设计决策与未决项

新增原生资源合同，SDK JS 仍由应用依赖锁固定；清单包括 driver／平台架构／SDK／native／适配器组合、包来源摘要、解包文件清单及模式、入口与必要辅助程序。受管目录按不可变内容区分版本；下载／展开／大文件校验在宿主业务锁和 SQLite 写事务外准备，最终归属及就绪发布继续核验，不能为了性能删除晚变更防护。

新的流式准备和短发布方案尚未实际验证；直接把异步 Promise 塞入当前同步 materialize／verify 合同是错误接入。最终可放到独立安装 worker，但跨进程归属、取消、失联、租约和激活必须接回已有资源状态，不靠 UI 是否仍打开判断安装成败。

完整原生清单 Schema、分发方式、安装／激活事务、在用升级与退回、下载中断／损坏／离线、真实磁盘故障、大文件校验与各平台安装仍有缺口。随包和按需资源应汇合到相同的解析／校验／租用接口，自定义程序单独记录身份，不因路径失效自动改走 PATH 或受管默认项。
