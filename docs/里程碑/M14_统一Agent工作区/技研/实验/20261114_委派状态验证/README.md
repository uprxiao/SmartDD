# 委派与共享目录交棒的候选状态验证

日期：2026-11-14。关联 Q19–20、Q23–25、Q28、Q31。T3 本地基线 `f313d0a6cb843551fb60e57a454a71e71a3a8c04`，SmartDD `40ea344a930aec37e36a803b7c621d3632d2d75a`。

## 先区分证据种类

本次读取 T3 OrchestratorMcpService、orchestratorMcp contracts、Orchestrator 的结果投递分支及既有测试，未运行 T3 测试。T3 默认异步委派，提供 wait；shared／worktree 属于工作区选择，不能据此推断具有 WillYou 所需的 SVN 单写者交棒。

另用 Python＋真实 SQLite 编写独立候选 Host，17 项通过。attempt-1 的 D01 仅验证一个父目标到四个子目标；attempt-2 扩充为四个目标互换主／子角色的 16 种组合，17 项仍全部通过。原件分别保留。所有执行器均为记录调用参数的合成目标，没有运行真实 Codex／Claude 互相委派，也没有 MCP transport、操作系统写入隔离或生产权限检查。该原型是状态语义夹具，不是生产调度器或对 T3 正确性的证明。

## 通过项与边界

| 用例 | 断言 |
| --- | --- |
| D01 | 四个合成目标互换主／子角色的 16 种组合均经同一路径，包括同类、跨类、同 runtime 多配置和未来 driver；不是 16 种真实供应商组合 |
| D02 | 两个先后打开的数据库连接重复创建返回同一 receipt，同键异内容拒绝；不是并发压力测试 |
| D03–04 | 已接受的重复请求返回原 receipt，不重新选择目标；创建前或启动前修订变化阻断新执行 |
| D05 | 父 turn 结束不等于进程／后台写入排空，仍返回 waiting_parent_release；可信排空回执后才启动 |
| D06 | 第一个子任务已有结果但 owner 未排空，第二个共享目录写任务继续排队 |
| D07–08 | 结果修订去重；同修订不同内容拒绝；父忙时不领取投递，领取后不可再次领取 |
| D09 | 尚未投递的结果归属父逻辑任务，可在父空闲且排空后切 Provider，再投递给新的绑定代次 |
| D10 | 投递 sending 恢复为 unknown，禁止盲重放与切绑定绕过 |
| D11 | 派发登记后、合成外部调用前后两个注入窗口恢复均保留 unknown，不自动再次调用 |
| D12–13 | 排队取消不执行；运行中取消不释放 owner；晚到旧代次结果不复活取消任务 |
| D14 | 转单模式先禁新委派，保留已有子任务；子任务与结果收口后才完成切换 |
| D15 | 宿主深度／数量边界和不存在的目标拒绝；这些限制参数为测试配置，不能暴露给模型自行增大 |
| D16 | 父 turn 结束、子结果完成、owner 排空、父收到结果分别推进；全部投递后只是 idle，不擅自宣布用户目标完成 |
| D17 | 错误接收者／代次 ACK 拒绝；取消已完成子任务不抹去结果 |

## 设计约束

共享目录下，父进程如果仍有写能力，阻塞等待子写任务会形成调度死锁。因此 delegate 接受后立即返回 waiting_parent_release 等明确原因，父结束当前回合后由宿主完成真正的进程／业务排空并交棒；工具不能一直占着父运行阻塞 wait。已有 O07／O08／O12 证明 WillYou owner 会等待在途业务／桥退出，但尚未将该证明接入本原型。这里只调用可信测试入口 drained，不是真实进程已退出的证明。

capabilities 给出实例及配置修订；delegate 冻结明确目标、模型和上下文摘要。没有指定实例时，可以由宿主按可解释规则解析，但必须在接受委派时固定下来，重试不得重新挑账号。首期 RPC 要求 clientRequestId；键作用域至少包含可信调用运行与操作。身份由工具接入层提供，原型 caller 字符串只是夹具，不证明身份认证。新请求与读取旧 receipt 均先检查调用权限。

结果使用持久父 taskId 路由，源 child／run／revision 保留；在 claim 时锁定实际接收 binding／generation。父忙、共享目录仍被子运行占用或待人工答复时排队；sending／unknown 不因切 Provider 清零。用户界面的查看只读；Agent 主动读取结果与自动投递需要明确的同一观察账，避免查看页面就吞掉唤醒。当前原型没有实现“Agent 主动读取已观察”的分支。

## 尚未覆盖

- 真实 MCP 调用身份、主／子双向 SDK 工具可达性、递归子树取消、问题／审批、唤醒合并与持久 outbox worker。
- 多个真实目录／祖先路径／符号链接／跨项目冲突、操作系统只读限制、外部 IDE／SVN 修改与大项目性能。原型只代表一个规范化目录。
- 配置修订校验提交后、实际 spawn 前的竞争。生产需冻结不变启动材料并持有资源引用，在 fork 前复核，不能启动时从可变默认配置再读账号。
- D11 是故障点返回后执行恢复方法，不是杀进程断电实验；未证明外部 exactly-once，也未实现 unknown 的自动解歧。
- 源码的所有 `drained`／caller／代次输入均由测试直接控制，不是完整安全边界；不能把该 Python 类暴露为工具服务。
- 磁盘故障、跨进程高并发、任意树深度、子任务自动重试产生的新结果修订和全应用重启。

复验：`python3 probe.py <不存在的新结果目录>`。仅使用临时数据库，测试结束即删除。原始结果与脚本哈希见 result.json，归档完整性见 SHA256SUMS.json。
