# 同步、快照与草稿合同验证

日期：2026-11-14。用途：收口 M14 Q43／Q44；仍是设计与独立实验，不改变正式业务代码。源码基线与引用文件哈希见 `source-evidence.json`。环境为 macOS arm64，Python 标准库 sqlite3（实际 SQLite 版本见结果文件），无模型、真实 IPC、用户配置或业务写入。

## 方法及复现

候选 Python Host／Replica／DraftView 使用独立临时 SQLite 文件、WAL 与两个连接；以确定顺序插入写入、通知和回复，没有 sleep 或真实 IPC 计时。通知只保留最高水位；从持久事件表分页补拉。读快照时故意在另一连接写入，核对读事务一致性。输入模型单独验证宿主 revision、选择 revision 与本地 editRevision。

把所需 attempt 的 `probe.py` 复制到可写临时目录，执行 `python3 probe.py`；脚本创建并关闭隔离数据库，写出 `result.json`。脚本不依赖项目 node_modules。`attempt-2` 预期非零退出，保留它用于复现发现的两项错误；`attempt-3` 是修订后候选，不作为可直接粘贴进入产品的实现。

## T3 对照及差异

本地 T3 `EventSink.ts`、`LiveStreamBudget.ts` 先订阅再取得水位，拼接持久重放与有限 live 缓冲；`ThreadStream.ts` 将过大重放转成快照，契约区分 historyCursor 与 snapshotSequence。`threads.ts` 对旧事件按 sequence 去重，未知事件可记日志后跳过。这里只读源码，没有运行 T3 测试或服务。

WillYou 拟议的是完整任务内连续序号，通知只传高水位，由 IPC 有界补拉；不能直接照搬 T3 跨任务过滤后的全局序号做 `+1` 检查。关键状态未知时阻断是 WillYou 的设计选择，不是声称 T3 已如此实现。源文件哈希只证明引用版本，不证明当前项目执行了其逻辑。

## 结论边界与剩余项

- 候选 schema 为极小夹具；没有迁移真实表，没有权限／Schema／凭据集成。没有生产接口接线。
- 正式要求数据库恢复／替换时轮换 databaseId；实验只创建新实例，没有跑真实备份恢复程序。
- S10 仅重开连接，不是进程崩溃／断电；S11／D08 是显式异常回滚。
- watermark 核对由测试显式调用，未证明 IPC 存活检测、定时调度、失联恢复时限或用户无感效果。
- 分页限额使用两条事件便于制造分页；不是吞吐、字节限额或前端性能证据。未验证大历史窗口、并发历史页与 live merge、artifact 预算或虚拟滚动。
- DraftView 为候选状态机，不是现有输入框；没有 IME、语音、插件引用、来源授权及真实附件接收。
- 草稿事务的 outbox／回执／草稿一致性单独验证，尚未与规范事件表组成一条原子产品链路。outbox 未被 SDK 消费，不证明实际消息只发一次。
- Q43／Q44 仍为部分，Q45／Q52 没有因此通过。正式用例未建立，不统计产品整体通过率。
