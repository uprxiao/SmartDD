# 原生资源流式准备、复用与默认激活

2026-11-14；R02／08／10／11／12，Q01／03／46／48／51／52／53／54；技术方案 §12.1，验证账 §4.50。本批是隔离技术验证，未修改产品或共享原型。

## 核心路径

在现有 ResourceStore 外增加临时清单、异步流式准备和激活候选。清单固定 driver／版本／平台架构、入口及完整文件路径、大小、SHA256、执行位；拒绝路径逃逸、大小写同名、父子文件冲突、非执行入口及不匹配平台。准备在 C 资源协调区外逐文件流式复制、累计大小与摘要；完成后设置不可写权限并记录文件身份。传给现有同步 materialize 的工作是同文件系统 rename；最终 verify 核对文件集合和 dev／ino／size／mtimeNs／ctimeNs／mode，无网络或异步 Promise。

此文件身份策略只获得当前 macOS 文件系统上的限定证据，不是跨平台内核执行封存承诺。准备句柄仅在内存 WeakMap 中，尚无持久安装操作／恢复协议；默认表也是临时 SQL。不能把这份实验模块直接当生产安装器。

## 真实资源与检查

完整本地 Codex 0.167.1 平台目录包含 41 个文件、366515155 字节，含 codex、code-mode-host、rg 以及 voice 辅助资源／声明。本批按清单流式准备并发布到新的内容目录，读块最多 262144 字节；从发布后的路径运行 `--version` 得到 codex-cli 0.167.1。收尾审计重新读取全部 41 个文件核对摘要和权限。

这证明大资源不必通过旧 RuntimeBundle 的单个大 Buffer 交付；不证明整个进程 RSS 上限、UI 响应耗时或安装服务性能达标。来源是既有隔离依赖缓存，不是联网下载／上游压缩包解包，也没有启动 app-server 或模型任务。

## 负对照与针对性补验

attempt-2HWzph 的 S09 原先直接写 mode 0500 文件，收到 EACCES，故未触发预期故障；这是驱动错误。改为在本轮私有目录创建同大小／同权限文件并 rename 替换后，故障生效且被校验拒绝。

attempt-JLwD9X 的 S12 是有效候选缺口：新 stage 与现有 ready 目录内容相同，但 inode／时间不同；直接用新 stage 的身份校验原目录导致误拒绝。修正为在协调区外重新流式验证已有目标的清单／大小／摘要／模式及读取前后身份，然后固定这次观察到的目标身份，交由实际发布入口最终复核。已有目录不被覆盖，完成后删除本次未使用的私有 stage。

补充 cache-gZ7ily 的 C01–C03：已有文件内容被替换则 TARGET_HASH_CHANGED；目标散列成功后、实际 publish 前再替换文件则 FILE_IDENTITY_CHANGED；恢复正确内容后重新校验成功，目标 inode 保持，不靠跳过校验解决重装问题。

三轮实际 Codex --version 均有捕获 PID 的 code 0 退出；缓存补验没有新原生进程。所有轮次、失败与修正留存。故障后的未知／recovery-required 发布记录仍保留，未伪造 ready；部分未消费准备仍只在临时目录中，跨宿主垃圾回收不在本批证明范围。

## 设计含义与剩余问题

同内容可有不同物理身份：内容摘要决定版本，当前文件身份用于防止校验后被替换，不能混用。新准备与已有 ready 复用需要不同的身份来源；已有目标仍须验证其内容，不应为了幂等就信任 ready 行。

下载／校验完成、资源 ready、默认版本激活、某次任务固定选择、真实运行租用属于不同状态。激活采用明确预期修订，晚到的操作不能覆盖更新后的选择；已接受任务沿其固定资源，不因默认更新换版。默认回退不等于旧任务历史格式一定兼容，仍按 SDK／native／协议／业务适配组合验证。

未覆盖：公网请求、代理／重定向、上游包解压限制、完整安装与激活崩溃事务、跨进程竞争、实际 run 租约与 GC、清理所有遗留准备、真实磁盘耗尽、Claude native 包、Windows／Linux 与 Electron 安装签名。产物没有作为发行包分发。当前流式输入采用本机文件路径，后续网络／解包适配不得绕过相同清单与发布核验。
