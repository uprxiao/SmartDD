# 按需读取依据与外部变化验证

日期：2026-11-14。关联 R09／Q33。独立技术验证，不是产品验收。

## 实际路径

使用未改的 FileSourceResolver、FileService、FileRootsService、FileRecoveryStore 和原生文件代理，在本机新建 SVN 仓库及工作副本。SQLite 为合成 task 来源；没有 Agent 进程、真实用户数据或网络模型。复用前轮服务 bundle，但执行前核对全部源码及产物哈希；原生文件代理也与先前原始构建和源码摘要一致，没有测试故障注入编译开关。

| 检查 | 实际结果 |
| --- | --- |
| R01 同大小、恢复相同 mtime 的内容修改 | 目录列表完全相同；文件内容摘要改变，旧 chunk 拒绝、旧 baseHash 保存冲突，外部内容保留 |
| R02 相同内容的原子路径替换 | hash 相同、inode 不同；旧 chunk 拒绝，旧文档保存冲突，刷新可见新身份 |
| R03 文件不存在、后创建、后删除 | 初次打开失败；重新列目录发现新增／删除；旧文档删除后不可继续读取 |
| R04 复核后外部再次修改 | 先前读取不锁住外部写入；保存时再次检查并冲突，重读得到新内容 |
| R05 整个根目录被另一目录替换 | 旧读取返回 STALE_ROOT，旧租约撤销；新旧目录内容分别保留 |
| R06 按需范围 | 文件内容请求只涉及 src/item.txt 和 src/new.txt，没有请求读取 unrelated/unread.txt；不代表 I/O 性能测量 |

6 项检查通过；原生代理请求 28 次。所有写入均为合成夹具。这个小 SVN 工作副本只证明非 Git 目录路径可运行，不代表 10GB／高文件数项目性能、SVN update 并发或全项目快照。

## 对设计的约束

FileRevision 的内容 hash 与 device／inode 不能互相替代，size／mtime 也不足以证明内容未变。目录结果只有成员、身份等信息；本次 R01 直接证明列表一致不等于子文件内容一致。目录／glob／搜索结论还包含查询范围、过滤、截断和不存在判断，不能仅记录返回文件的 hash。

当前文件服务不是通用 Agent 读取账：原生 Read、shell、Skill 或第三方 MCP 的任意读取不会因此自动全部登记。M14 必须标明读取依据的覆盖范围，未知／截断不得显示为完整验证；按需重跑相关查询、重读变化文件，不用全库 hash 填补未知。复核后的外部变化仍可能发生，实际写入口必须保留最后冲突检查，raw shell／第三方服务没有同等约束时不能宣称受此保护。

没有实现新的共享目录准入、读取账或多文件原子事务。Q33 保持部分；端到端只读、目录并发完整性、持久化接线与代表性大项目继续待验。
