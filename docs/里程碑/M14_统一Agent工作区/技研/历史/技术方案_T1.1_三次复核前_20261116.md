## 1. 整体设计与实现依据

宿主维护逻辑任务、规范时间线、原生绑定、运行身份及业务授权；适配器只负责 Claude SDK、Codex app-server 或 ACP 的协议差异。一次任务可挂多个原生会话，切换时恢复目标原生会话并补交缺少的上下文。宿主 MCP 委派复用同一任务与运行服务；目录使用方案 B。右侧文件／浏览器及 M13 业务服务继续复用。

本机程序由现有发现服务或用户显式路径提供。应用锁 SDK 库，不分发 SDK 自带的运行程序。旧任务不迁移、不恢复、不复制历史；新列表只展示新任务，旧数据原样保留。详细历史推导及原失败保存在[旧整稿](../历史/技术方案_T0.1_20261116.md)与[历史验证账](../历史/全局设计验证账_V0.3_20261116.md)，现行研究判定仅在[验证账](../全局设计验证账.md)维护。

## 2. 数据模型与数据库升级

以下为拟新增表及既有表改造；ID 为宿主生成的 UUID，时间用 UTC，秘密仅引用既有凭据服务。创建任务只创建任务和草稿，不隐式启动。新任务在同一事务写基础 `tasks` 与 `agent_tasks`，列表通过 `agent_tasks` 成员关系查询；旧 `tasks` 行不回填。`tasks.runner` 等旧摘要字段不再作为原生身份权威。

`capability_runs.task_id` 现有 FK 指向单任务快照，不能支持多个绑定。结构升级将其改为基础 tasks 归属，新增绑定／能力会话关联及复合归属校验；旧行各字段和外键引用原值保留，新行必须有完整新关系。旧单任务快照表保留作旧数据，不进行原生历史转换。数据库迁移器保留版本守卫、校验和、备份、事务回滚及 `foreign_key_check`；新表以后仍正常升级，旧包读到高版本应拒绝启动，不承诺应用版本降级。

删除／归档新任务先检查请求、后台、业务操作、子任务和被读产物；活动／未知引用保持保留。旧任务关联业务数据、原生文件及配置不进入本期删除流程。`pty_id` 改读运行身份的逐文件影响见[清理清单](../旧代码清理清单.md)，这与旧任务转换无关。

## 3. Driver、运行与公共接口

Driver 定义是不可变注册项；每次 attach 创建独立实例，持有流式缓冲、原生关联、工具映射和待回应回调。任务／编排层无品牌配对枚举。统一接口均验证 task、binding、run、generation 和宿主 caller；客户端不得自报 PID、nativeId、parentRun 或真人来源。

| Driver 方法 | 入参／出参 | 责任 |
| --- | --- | --- |
| discover／probe | 显式 binaryPath 或 M13 发现结果 → executable identity/version/capabilities | 记录 realpath、版本和探测；不安装、不自动换程序 |
| open／resume | 冻结 profile、cwd、权限、配置根、能力交付、可选 native 引用 → ChildProcess/connection 与确认身份事件 | Claude SDK 使用 pathToClaudeCodeExecutable 与 spawn 回调；Codex 启动本机 app-server；ACP initialize→session/new/load |
| startTurn／steer | 冻结 inputId、blocks、模型／推理／权限 → native turnStarted／accepted | 等原生开始信号后才确认；可选 steer 不支持时使用明确排队 |
| respond | requestId＋原生选项 ID／结构化回答 → 原生确认 | 保留问题、URL、表单和业务 source；不压成 boolean |
| interrupt／close | 精确运行／节点 → terminal evidence、后台与 owner 排空 | 发送即停止先置 cancelPending，原生 turnStarted 到达后立即 interrupt；关闭不冒充回合完成 |
| events／history | 原生流／已确认记录 → §4 规范事件／只读历史 | 未识别关键必需事件标协议不兼容，未知通知保留诊断 |

MCP、IPC 和输入框调用同一 TaskCommandService；副作用在事务外执行，调用前后重核 profile 修订、能力、工作目录和当前政策。幂等只保证宿主接受，不推断 Provider 对同一 ID 不重复执行。

| 公共命令／查询 | 主要输入 → 输出 |
| --- | --- |
| task.create／task.archive | projectId、directoryId、initialDraft、clientCommandId → task/revision |
| draft.save／selection.preview／selection.apply | expectedRevision、draft 或 profile/model/permission → 新修订或冲突；apply 用预检 token，派发前再核 |
| input.submit／input.steer | clientInputId、draftRevision、selectionRevision、blocksRef → durable receipt、queued/dispatching；不能直接指定来源类型 |
| request.respond | requestId、revision、完整 scope、原生选项／业务 reviewHash/displayReceipt → accepted/rejected/retired |
| delegation.create／observe／cancel | 绑定 MCP caller、targetProfile、task、idempotencyKey；cancel 明确 turn/subtree → 子任务／结果修订／取消收据 |
| run.interrupt／background.stop | task/binding/run/generation、可选 node/revision → stopping/terminal；超时保存事实与未知占用 |
| task.subscribe／events.read／snapshot.read／history.page | taskId、afterSeq／cursor、请求 token → 已提交水位、有界事件／投影／历史页 |
| message.openLink／turn.changes | taskId、itemId、href、modifier；turnId → 经授权路由结果／差异引用 |

### 3.1 IPC、草稿与容量

Electron 本地采用单一 taskSeq：先订阅并获确认，再读取一致快照和水位，随后补拉 `(afterSeq,throughSeq]`。重复忽略、缺号补拉，裁剪或游标超前则重取快照；窗口恢复／重连查询最新水位，解决尾通知丢失。页面切换取消旧订阅和旧请求，闭包绑定窗口／task／requestToken；不叠加数据库、视图、历史等多重 epoch。数据库替换关闭所有连接后重建订阅。分页使用稳定 ordinal＋revision 和不透明 cursor，页不能推进事件水位，旧 revision 不能覆盖新数据；删除标记压制迟到页。

初始限制复用 F16 的已验证边界：事件 32 KiB、预览 4 KiB、IPC 请求 1 MiB／响应 256 KiB、事件页 128 条且 256 KiB、历史页 100 项且 256 KiB、正文范围读取 128 KiB；每 run 归一队列 128 项或 16 MiB、宿主合计 64 MiB；renderer 每 task 2000 项且 8 MiB，最多 4 个任务且合计 32 MiB。超限正文转 artifact，关键请求不截断；存储失败停止确认并保留草稿，取消使用独立控制通道。流式合批初值 50 ms／32 KiB；这些是拒绝／恢复边界，不是 App 性能承诺。

公共信封包含 itemId、taskId、turnId、binding/run/generation 或独立 nodeId、source、ordinal、revision、occurredAt、startedAt/endedAt、terminalState 和有界 payload/ref。运行级字段对宿主任务级条目可空，不能伪造。条目来源以 T3 [orchestrationV2](https://github.com/pingdotgg/t3code/blob/fe59fa44d0f12ba1e58b1cccc2c888ac99e743da/packages/contracts/src/orchestrationV2.ts) 为基线，逐个定义纳入、改名或删减政策；`dynamic_tool` 改名 `tool_call`，额外 `provider_switch` 表达配置切换。固定源码的 25 个联合成员由 TypeScript AST 读取（含 spread 字段，排除 fork 内嵌的 source.type），不是手写基线清单。

T3 其余三个条目本期排除：`fork`（本期无线程分叉）；`secret_request`（不提供模型请求后写密钥文件的流程，凭据走现有 WillYou 服务，已有业务 secret 表单仍按原服务处理并脱敏）；`link_request`（本期无远程机器连接）。这些是显式范围删减，不声称全量保留 T3 功能。未知新增类型仍令覆盖检查失败。

Claude 带 `parent_tool_use_id` 的 user、assistant、stream_event 和内部工具结果均归属对应 `subagent` node；item 键包含 node 身份，不在顶层伪造用户输入。子结果产生该节点的 notification，不能结束父回合；来源为原生子工作而非真人授权。

ACP 将 agent/user/thought chunk、tool_call/update、plan、request_permission 映射到同一条目；session option/mode/usage 更新交能力和计量区域。stopReason：`end_turn`→completed，`cancelled`→stopped，`max_turn_requests`／`refusal`→failed；`max_tokens`→limited（output_tokens，保留部分输出，手动继续，没有额度重置时间，不自动重试）。未知原因→failed 并报警；握手只产生绑定事实。

流式片段和 final 更新同一 item/revision；迟到 delta 不复活已结束条目。一个回合内命令、搜索、工具、计划更新及完成的原生子工作聚合成可展开的“工作了 Ns”；用户消息、最终回答、交接、切换、待处理请求、错误及宿主子任务卡片保持可见。耗时取宿主观测到的工作区间并集，重叠工具不重复累计，待用户处理的时段单列；后台跨回合工作保留 node 的起止时间。

明确不展示的诊断：account/updated（账号设置拥有）、remoteControl/status（本期无远控）、readState（阅读游标）、moderationMetadata（内部元数据）、goal bookkeeping、ACP 握手与响应元数据。使用量、启动失败、hooks 结果和审批不可归入这一隐藏清单。未知原生类型写诊断并触发覆盖报警，未知必需请求停止回应；不以兜底 diagnostic 声称全覆盖。

真实 Claude／Codex 事件、一次切换及委派原件的脱敏录制和逐条分类见[回放结果](../实验/20261116_复核修订验证/results/timeline-replay.json)、[来源清单](../实验/20261116_复核修订验证/fixtures/recordings-manifest.json)。其中 host 切换／交接信封由真实录制的 actor 转换和规范历史构造，验证显示模型，不冒充已录制的生产 UI。

## 5. Provider 切换、交接与输入

选择预检返回目标、配置／凭据来源修订、程序版本、能力及兼容身份；应用及派发前再次核对。首次目标新建 binding 并交全量摘要；兼容目标恢复原 native 会话，只补其 coverage 未包含的规范内容。配置根、账号、cwd 或必要能力不兼容时新建绑定并保留旧绑定；不复制旧任务原生历史。仅在父运行空闲、无在途发送／回应且业务准入允许时切换。子结果始终按父逻辑任务收回，不随当前 Provider 丢失。

交接保存 exact payload/ref、来源条目、覆盖水位、遗漏／截断理由及预算。输入、附件、Skill、历史与子结果都有 sourceKind；只有可信当前 UI 提交可取得真人来源证据，恢复或观察历史不会重建实时授权。文字初值 256 KiB，附件按实际二进制与目标能力计预算；不足返回部分覆盖，不静默吞内容。原消息原文保留。

插话是可选能力：当前执行器／版本／模式须同时通过协议探测和真实模型接受验证；Codex 用匹配 expectedTurnId 的 turn/steer，Claude 用 SDK 仍开放的 AsyncIterable 输入流。宿主记录提交时回合／工具状态、原生接受和后续回答的关联；不能以写入 stdin 成功认定已接受。无证据或状态不匹配一律走排队，不自动改成新回合发送。真实验证及其局限见[二次复核实验](../实验/20261116_二次复核修订验证/README.md)。

投递状态只有 prepared、sent、accepted、not_sent、unknown。能证明没发出才允许重试；发送后断线／宿主崩溃且不能确认消费才 unknown；恢复先读原生记录及业务操作账，不自动复发 unknown。原生同一 clientId 的幂等差异保留在适配器能力中。

## 6. 委派、方案 B 与后台结果

宿主 MCP 暴露目录查询、创建、观察及取消；父 caller 从桥绑定取得，不接受模型指定 parent 身份。主／子目标来自已接入配置，接受时冻结修订，启动时重检。持久创建子任务、来源、队列及收据同事务；相同 requestKey 返回原收据，不新建第二子任务。结果修订写入一次，通知只带引用；父忙排队，父空闲观察／领取后再唤醒，旧 run token 不可读取新代次结果。

方案 B 的队列键取授权根的 realpath／物理目录身份；别名合并，父子重叠的项目目录采用同一登记工作根，未知归属拒绝启动而非全盘扫描。写入资格由宿主权限／可信角色政策决定：只读档位且所有写入入口受限才为 read，其余为 write；模型自报“只读”无效。原生只读不约束外部 MCP，业务、插件和可写 Skill／shell 必须同时受只读政策约束；不能证明时按 write 排队。

只读运行请求写操作时先阻止该步执行，转为写入排队；等当前回合结束并排空后，取得目录槽才可执行。不能延后该工具的目标拒绝本步并提示在写入回合重试，不能沿用 read 资格执行。不可约束的用户扩展按 write 管理。

同一根最多一个 write，多个 read 可并行；读取结果需在写入前复核文件版本。**写入型委派固定为异步：wy_delegate 持久创建并立即返回 queued 收据，父继续当前回合；子等父回合自然结束并排空后才启动。** 父不得持槽在 MCP 调用中阻塞等待子结果。只读子在可信只读约束下可立即并行。本期不启用同步等待写子；旧同步探针只证明目标可调用，不作为方案 B 调度证据，因此本期没有对外承诺的同步 MCP 等待／默认超时预算。

写入槽释放必须同时满足：原生回合确定终结；无在途工具／原生子工作／后台进程；宿主业务租约排空；宿主冻结该 owner 的新输入和写业务准入。终态与排空是不同证据，失败终态也不自动证明进程已排空。三类适配器分别落实：

| 执行器 | 自然回合边界 | 排空与不能证明时的处理 |
| --- | --- | --- |
| Claude SDK | 匹配本次输入／session 的 result（success 或明确错误） | 逐个 tool_use/tool_result 对账；原生 Agent／后台任务终态与业务账清空；SDK 输入流不再接收新写输入。不能证明无后台时关闭本次 query，独立观察实际 ChildProcess 退出及登记后代／业务排空，后续 resume 原 session |
| Codex app-server | 匹配 threadId/turnId 的 turn/completed | item/started/completed 对账，commandExecution／MCP／原生子工具均无 pending；thread/status 的后台活动及宿主登记进程／业务清空；阻止新 turn/start。仍有 background 则保持槽；不可靠时关闭该 owner，确认实际进程及后代／业务排空后 resume 原 thread |
| ACP | 本次 session/prompt 的 stopReason 确定响应 | tool_call/update 的 terminal status 逐个对账，session 声明的后台节点及宿主业务清空，冻结新 prompt；无可核对后台协议时关闭准确 owner 并观察退出及排空，再按实际 resume/load 能力续跑；不支持恢复则明确提示限制，不静默换会话 |

上述“owner 存活时的自然回合释放”是待开发合同，**当前真实模型证据只验证更保守的 owner 退出后释放**；不把 native pause 或 `pausedNoWrites` 布尔值当证明。回合未结束、工具未排空、退出不明或业务仍在途时都继续占槽。父释放后子按 FIFO 启动；子结束也经同一边界排空；父收到 notification 后重新入队，取得槽才恢复原 native 会话并读取结果。新的父写输入与待启动子共享同一队列，不能插队占回槽。排队可取消；超时／失联保留占用事实，不自动放给下一个写者。

[W1/W2 真实模型实验](../实验/20261116_二次复核修订验证/README.md)覆盖 Codex 可写父→Claude 可写子及反向：同一 cwd、原生文件工具、queued 前后继续写入、turn 完成及实际 owner 退出、子派发、结果送回、原父身份恢复后读随机 child.txt。宿主顺序与原生记录分别留证；不是生产调度器或 App 验收。

后台／原生子 Agent 生命周期独立于父回合，按 node 身份接收迟到结果；能力不足以定向停止时只提供停止所属 run。宿主子树取消撤销所有后代桥权限并观察各自排空；一个 Provider 的失败不终止无关配置。运行可记录不同 cwd，为方案 C 留接口，本期不创建／删除 worktree、不自动管理 SVN 副本。

| 根外／symlink 越界／不存在／已删除 | 不打开，提示具体原因；不自动扩大文件根 |
| 无项目任务 | 文件仍须已有授权根；浏览器提示先关联项目，不伪造 projectId |
| 已打开／未保存 | 定位既有缓冲，保留 dirty 内容、光标和保存冲突；不从磁盘替换文档 |
| Cmd/Ctrl+点击 | 在同样根／存在性检查后请求系统外部编辑器打开；无配置时说明失败／选择入口 |
| PDF／特殊文件 | 走 WillYou 现有文件查看器，保留 M9 合同，不因 T3 默认改走新的 PDF 浏览器路径 |
| javascript/mailto/其他协议、伪文件路由 | 拒绝协议；普通 API 路由不存在则提示，不自动发网络请求 |

点击是用户的打开动作，不改变 Agent 权限，不把模型输出当访问凭据。[12 类样本与真实输出回放](../实验/20261116_复核修订验证/results/links.json)验证识别与路由；真实右侧 UI、系统修饰键及未保存状态按 A57/A58 验收。

## 11. 每轮改动与差异查看（C16、D5）

Git 项目使用独立 GIT_INDEX_FILE，读取当前工作树建立 before／after tree，commit-tree 保存无分支提交，update-ref 写 `refs/willyou/turns/<turnId>/before|after`；不移动 HEAD、不写用户 index、不产生用户分支提交。SVN／普通目录用私有裸 Git 的 GIT_DIR＋工作副本 GIT_WORK_TREE＋私有索引，同样存隐藏引用。显式排除 `.svn`、`.git`、产品受保护路径及项目忽略项；二进制和超大差异只显示元数据／不可预览原因。

写入 run 取得方案 B 槽后捕获 before，完成或停止并排空写入后捕获 after；未完成快照标 incomplete，不能用下一轮状态补造上一轮差异。区间内的外部／用户写入只声明观察到的变化，不归责给模型。差异用树间比较，打开时重验授权根和快照身份；未保存编辑缓冲不被差异结果覆写。M9 `syncFileConflictDiff` 提供展示组件和既有限额，新增独立只读差异文档适配，不借原编辑器保存基线作回退。

[10 GiB 实测](../实验/20261116_复核修订验证/results/shadow-git-10gib.json)：20,481 文件、10,737,418,240 实际分配字节，首次 70.1361 秒、无改动 0.1835 秒、三文件增删改 0.1171 秒；影子库约 70.7 MB。样本为高可压缩的独特文本，每文件正常写入，非稀疏；SVN 仅 seed 已提交，其余未版本化。结果证明这一合成样本上增量可行，不证明企业全量已版本化／高熵二进制项目的性能。

初始上限采用实际验证规模：可捕获文件总量 10 GiB、最多 20,481 个内容文件；首次后台准备预算 120 秒、增量 5 秒，影子存储预算 1 GiB，始终预留至少 2 GiB 空闲磁盘。超过规模先提示未在验证范围内，不在 UI 线程递归扫描；计量在后台捕获中累计，超限／取消保留旧完整引用并标本轮不可用。高熵数据可能先触及存储预算，不能按文本压缩比预测容量。首次捕获未就绪时任务可继续，首轮差异明确缺失，下一空闲边界重新准备。用户自行扩大上限属于后续评审，不宣称当前支持更大规模。

保留引用和已打开差异读租约防止清理在读数据；按任务归档及保留政策清理本方隐藏引用／私有影子库，不执行 reset、checkout、revert 或 svn revert。界面没有回退按钮，IPC 没有回退命令。
