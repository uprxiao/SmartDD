# M14 统一 Agent 工作区、Provider 续聊与多 Agent 协作需求

版本：R0.2，目标与范围基线。日期：2026-11-14。来源：[需求池 F32](../../需求池.md)。状态：核心目标与实施前提已由用户确认；详细交互、技术契约、原型和验收待整合评审。本次设计研究与独立验证已按[最终审计](技研/全局设计验证账.md#77-最终研究关闭审计2026-11-15)关闭，未开始正式开发。

## 1. 目标与实施前提

将 WillYou 的任务交互升级为统一任务 UI，通过 Claude Agent SDK、Codex app-server 等对应程序化运行接口接入执行器；支持同一逻辑任务切换 Provider 继续对话，并支持单 Agent 和宿主多 Agent 协作。参考 T3 Code 的具体实现，按 WillYou 的 Electron／IPC／现有存储和业务体系适配。

**保留已交付的浏览器、文件目录／编辑／查看、插件系统、Skill／MCP、项目与配置、凭据、数据库／SSH、邮件、语音及导入导出等业务，是实施前提。** 保留数据、入口、授权、生效和生命周期语义；允许必要的任务／运行适配，受影响功能必须回归。既有需求中尚未交付的内容按原状态记录，不当作现有实现。


### 1.1 最新确认：先对标 T3 跑稳通用基座

用户于 2026-11-14 明确同意：先对标 T3，把基座跑稳；设计考虑扩展性，后续需要协作模板时容易接入。本次确认调整 R07 的首期产品边界，不撤回统一 UI、同任务续聊、单／多 Agent、通用接入及现有业务保留目标。

M14 的交付目标为：在 WillYou 现有桌面业务体系内，通过统一任务／运行契约接入首批 Claude、Codex，提供一致的任务 UI、同任务跨 Provider 续聊及宿主多 Agent 委派；协作方法可复用已有 Skill。角色与品牌不绑定，后续 Agent 和协作模板可接到同一服务，不另建任务内核。

“跑稳”须有可判定证据：连续工作、停止、恢复、重启、Provider 切回、子结果回收、待审批与未知投递不串身份、不重复触发外部操作；既有业务保持数据和授权语义；大型 SVN 项目不依赖整库复制；资源／版本不兼容时准确说明并保持原数据。

本阶段不交付独立团队模板管理、模板编辑／分发、通用强制阶段流程或可视化工作流编辑器。它们保留为后续扩展方向；首期只定义和验证所需的公共边界，不提前实现模板数据库、流程调度器或为未确定字段铺设空框架。对标 T3 是参考执行和编排机制，技术栈及 SVN／业务集成按 WillYou 实际约束设计。

三项核心能力（统一 UI、Provider 续聊、宿主多 Agent）均属本阶段完成范围，不能以单 Agent 聊天上线代替整体交付。首轮可分别验收空闲切换和固定主 Agent 的委派；任务树运行中切主 Provider 的组合行为须明确支持边界后验证。

### 2.1 通用底座与自由组合（2026-11-14 用户澄清）

Codex、Claude Code／DeepSeek 是使用与验证示例，不是固定组合清单。执行器、模型供应商、账号配置和角色分开：同一执行器可使用不同配置／模型，不同执行器可互相委派；主 Agent 与实现／分析／评审等角色不绑定某个品牌。新执行器完成适配后应复用统一任务、切换、委派及业务能力，后续模板同样通过这些公共入口工作，避免为每一对 Agent 单独编排。

“自由组合”的范围是已接入、配置有效且具备所需能力的目标。主 Agent 需要能够调用宿主委派入口；目标执行器需要支持所需运行与权限方式。实际可选项由宿主能力目录及任务政策决定；不可用时说明原因，不静默换供应商、账号或模型。首批执行器范围与长期通用架构分开，未适配的工具不因已安装 CLI 就视为已支持。

验收应覆盖同执行器不同配置、跨执行器以及角色互换，并证明没有硬编码固定搭配；不要求穷举所有外部模型组合。

### 2.2 首期协作复用与后续模板边界

首期对齐 T3 的宿主委派机制：Skill／指令保存协作方法，Agent 使用可用能力目录和委派工具执行；用户无需每次重新输入完整团队提示词。具体 Skill 的选用／调用入口在统一 UI 设计中细化，复用现有体系，不为此默认增加独立团队配置页面。

执行器、供应商、账号和模型配置继续由已有配置服务管理。协作指令不得复制 Key，不以某个品牌固定承担某个角色。允许目标、并发／深度限制、任务身份、授权和写入协调由宿主程序实施；Skill 中的步骤与验收文字不等于程序强制阶段门禁。

为后续模板预留以下职责边界，暂不建设独立模板产品：

- 编排调用入口接受明确目标、任务输入、来源、幂等标识及约束；自然语言、Skill 和未来模板均调用同一服务。
- 角色选择与实际执行目标分离；当前不建立固定角色枚举，未来模板可以保存映射。
- 输入来源与规则引用可追溯；如后续要求固定模板修订，须一并核对引用的 Skill 内容、脚本和相对资源。
- 任务树、状态、审批、取消、结果回收及恢复属于基座，不交由未来模板重新实现。

首期仍验证 Skill 能实际加载并调用宿主工具、重开后可继续选用，以及失效目标不会静默替换。模板版本库、模板依赖图循环校验、模板升级和模板管理 UI 的完整实现与验收移至后续，保留已有研究证据，不记为本期已通过。

### 2.3 长期扩展目标

用户已明确后续持续接入更多 Agent。新增执行器通过统一契约登记配置、运行资源、能力和事件转换；统一任务与业务服务不因每个品牌另建一套。允许 SDK、子进程协议或服务接口，不强制每个 Agent 都有 CLI。必需、可选及不支持／未验证能力分别声明；新增公共能力时显式修订契约并回归已有适配器。

复用现有运行器、能力交付、原生证据和资源版本机制，区分旧适配资源与新任务运行协议。第三适配器验证包含单任务运行、接续、主／子角色及能力缺失分支；夹具通过不代表未适配的真实品牌已交付。独立安装第三方运行适配器不作为首期前置，先建立明确的注册与版本边界。依据见[验证账 §6.3](技研/全局设计验证账.md#63-通用接入的现有基础与新增验证边界)。

### 2.4 现有业务及 Skill 依赖

T3 委派机制、Skill 与 Provider 原生 Workflow 的区别见[验证账 §6.5](技研/全局设计验证账.md#65-t3-委派机制skill-与协作模板的边界)。WillYou 的当前 Skill 库交付与扫描展示可复用；M13-R03 的完整第三方纳管按实际交付接入，不因需求已写就视为可用，也不自动转入 M14 实施。

M14 对协作规则的来源记录，不改变既有业务 Skill 的生效和实时授权语义。现有插件、Skill／MCP 和其他业务的保存、使用、停用、更新及资源释放按原合同适配验证；新增多绑定不得削弱旧身份检查。

## 3. 不包含与依赖

- 定时任务仍为 F16，顺延至 M15；不在本阶段实现调度或无人值守授权。
- 独立团队／协作模板管理、模板编辑／分发、通用强制阶段流程及可视化工作流编辑器留待后续；远程协作、移动端及所有额外 Provider 不作为首轮必要交付。
- SVN 自动 checkout、分支、提交／合并及全量源码快照不作为本阶段前置；用户已有独立工作目录可作为候选增强评估。
- M13 的插件、配置、权限与能力管理按其实际交付状态复用。配置身份与原生恢复接口等依赖必须核对，不能以需求稿替代实现。
- 原 M13 单原生会话的兼容校验继续有效；M14 通过新的逻辑任务多绑定支持跨 Provider，不直接删除原保护。对 M13 的其他既定规则如需改变，应单列影响与依据。

## 4. 必须在依赖开发前收口的细节

1. task／ProviderBinding／能力快照／原生会话／run／资源引用的映射及旧数据迁移。
2. SDK／app-server 的 Skill、插件根、MCP、业务 CLI、配置与凭据交付、诊断和释放合同。
3. 浏览器 run 授权、插件／邮件审批、文件引用目标与窗口生命周期；父子任务不得混用身份。
4. 切换／委派／投递的公共命令、状态、幂等、事务和异常恢复；单／多模式转换与停止范围。
5. SVN 共享写入交棒、防循环等待、实际只读能力、读取依据失效及大项目性能判据。
6. 首批平台／执行器／供应商／版本矩阵与原型、逐条用例。以现有桌面产品为对象，各平台按实际证据声明支持，不将单机结果推广到其他平台。

7. 运行资源来源与配置来源分离；固定 SDK／程序／适配器组合，核对没有全局 CLI、已有 CLI、首装／离线／升级失败和旧任务恢复。安装策略应让用户无需自行解决版本匹配。

8. 新 Agent 接入契约、能力目录、版本协商、公共事件及错误语义；第三适配器的正常与缺失能力验证，明确复用旧适配机制的边界。

具体证据与建议见[源码复核](../../review/WillYou_统一任务迁移调研_R0.1_Review_20261114.md)，技术实现细节在[现行技术方案 T0.1](技研/技术方案.md)维护；当前为研究收口稿，产品原型／用例评审及实现另行推进。

## 5. 完成标准与资料关系

新能力及受影响既有业务均需有可判定用例，并覆盖正常、拒绝、取消、并发、失效、恢复和旧数据。协议／服务检查与同一候选包的真实界面／实际执行器证据分别记录；目前未执行本阶段验收，不预填通过率。

现有[迁移调研](../../WillYou_统一任务UI_Provider续聊与多Agent委派迁移调研.md)保留为依据；[R0.2 方案](../../统一Agent工作区优化方案.md)是待整合技术基础，旧单绑定范围不再作为本阶段排除项。现行技术设计见[T0.1 研究收口稿](技研/技术方案.md)；需求、原型、技术方案、验收分别维护唯一来源，由[阶段入口](README.md)导航。
