# M14 统一 Agent 工作区、Provider 续聊与多 Agent 协作需求

版本：**R2.0（评审定稿）**。日期：2026-11-17。来源：[需求池 F32](../../需求池.md)、[复核报告 §1、§7](技研/复核_20261116/复核报告.md)。这是现行需求基线：R1.2 的 2026-11-17 各条勘误与用户原型评审意见已并入正文（R2.0）；此前 R1.1 及其 2026-11-16 各轮补记（原型 P0.4–P0.13 反馈、第 4 项插件档位、第 6 项工作副本／目标／计划）与[整体评审](../../review/review-20261116-2313.md)的处理结论已合并为一套现行规则。D1–D3、D5 不变；D4 的现行委派和独立任务并行规则见 R06。用户已于 2026-11-17 完成原型评审；正式生产开发须用户明确授权，产品验收尚未开始。

## 1. 目标、范围与依赖

在同一逻辑任务内提供统一界面、跨 Provider 续聊和宿主多 Agent 委派。本期只接入并验收 Claude Agent SDK 和本机 Codex app-server。OpenCode（含 ACP 接入）、Cursor、Kiro 不在本期范围。执行器、供应商、账号、模型、角色分别管理，已接入且能力满足的目标可以互换主／子角色。

**M13 已交付的项目、AI 配置、凭据、插件、Skill／MCP、文件、浏览器、数据库／SSH、邮件、语音及导入导出是保留的硬约束。** 入口、数据、实时授权及生命周期继续有效，按[技术方案业务对照与回归清单](技研/技术方案.md#8-m13-业务交付与回归)核验；本期对其中两处既有规则作明确修改：插件写操作跟随权限档位（R08）、交互式任务请求不设界面超时（R01）。本期不增加独立团队模板管理、强制阶段工作流、定时任务、SVN 工作副本自动管理、额度到点自动继续或文件回退。Git 项目的写入委派使用宿主自动管理的工作副本（R06）。定时任务 F16 仍属 M15。

运行程序使用本机已安装的 CLI；SDK 库随应用锁定版本。缺程序时提示安装位置／检测结果，提供重新检测与显式路径选择；本期不提供受管下载和运行程序版本管理。首期真实研究平台为 macOS arm64；其他平台按逐平台包与业务证据声明，不能沿用本机结果。

## 2. 需求与验收合同

### M14-R01 统一任务界面与手动终端（RC3、RC7）

任务区参照 T3 的消息时间线、可折叠工作过程及新任务空白页；左侧栏沿用现状，底部保留 WillYou 输入框。消息、思考、计划、命令、工具、审批／问题、子任务、切换与交接都进入统一模型。工作条目按回合聚合。每轮在回复顶部只显示一个工作入口，运行时更新「工作中」耗时，正常结束后显示固定的「用时」，默认收起中间说明和工具记录。最终回复始终可见，耗时不累计重叠工具时长。2026-11-23 确认了以下回复区规则。

- Markdown 表格默认左对齐，短列保留可读宽度，长内容可以换行。单元格有留白及行分隔线。窄区只在表格内部横向滚动。
- 2026-11-24 参照 T3 Code 调整聊天排版，区分标题、段落、列表与行内代码。分屏时正文随栏宽换行。
- 最终回复底部依次显示复制全文、点赞、分支到新聊天及回合完成时刻。2026-11-23 确认四项在回复完成后默认可见。点赞保存在本机，允许取消。分支从选中的最终回复截取文字对话，继承项目和目录，新建独立会话。打开新会话后由用户发起下一轮，前序消息以历史来源交接。

2026-11-23 确认：进行中的请求在底部请求面板处理。回合结束后，展开本轮工作过程可查看「用户处理耗时」，工作时长扣除这段时间。

2026-11-24 确认，工作过程显示时只在计时标题下方保留一条横线。启动时大脑图标与「思考中……」同一行。单条命令和连续多条命令都可独立展开查看详情，在最终回复出现前也可收起。展开时分别显示脚本、输出及已有的退出码，输出在限定高度内滚动。整轮收起时仍显示最终回复。

2026-11-24 日用修复。Claude Bash 命令运行时显示已运行时长，收到原生心跳后显示距最近心跳的时间。有运行日志时按实际输出更新命令详情。异步子 Agent 依据原生任务状态结案，主回复结束后仍在运行的子 Agent 保持可见。仅剩后台工作时，时间线末尾显示活动中的子 Agent 和命令，停止操作标明其当前范围。

2026-11-24 确认，输入框和已发送消息按图片、普通附件、文字的顺序显示。图片按原顺序显示缩略图，点开查看原图。普通附件独立成行，长名称截断时保留文件后缀，发送前可以移除。点击已发送的文件在右侧打开对应回合的只读预览。项目内文件使用原路径，项目外文件使用已保存的附件副本。文件缺失时提示原因，保留文件名和重试入口。重开任务后仍可从对应回合预览。

输入框具备目标／模型切换、发送、运行中排队与具备能力时的插话、停止、待处理请求、@文件、$Skill 与 /命令选用（命令只列当前执行器公布或支持的项）。运行中用发送键或 Enter 提交时，消息在输入框上方以单行排队。本轮结束后自动按顺序发送。队列行提供「插入当前轮」和删除。原生确认后，插话按接收时点进入原轮次，后续过程和回复排在插话之后，同一轮次只显示一个计时。重开任务保留同样的顺序。此操作须有该执行器、版本和模式的协议探测及真实模型接受证据。执行器缺少该能力时，「插入当前轮」置灰并说明原因，消息按原顺序等候。2026-11-22 用户确认。草稿按任务持久保存。草稿跨窗口发生修订冲突时暂停自动保存，用户选择“保留当前”后按冲突提示中的修订保存，或经再次确认后“用另一份”替换本地文字和附件。引用插入只改草稿，不自动发送；发送前复核目标、模型、权限及草稿修订。首页与任务内输入框都支持 ⌘V 粘贴图片和文件，附件照 Codex 显示为输入框上方的缩略图／“预览＋文件名”卡片（悬停移除）；项目内文件按路径引用，项目外文件复制为附件，不放开 Agent 对项目外的读取；从文件树拖入为路径引用。附件随所属输入一起冻结，排队和发送都处理整份输入。

**技能选用（2026-11-24）**：每次打开 `$` 菜单时读取当前任务可用的纳管技能，与执行器公布的技能按名称合并。全局纳管技能和当前任务目录的适用项目技能可在已有任务中查找，名称精准和前缀匹配优先于包含匹配。每项单行显示名称、可用说明及来源，选中后把技能引用插入草稿。

**首页输入框（2026-11-24）**：新建任务前输入 `$`，可查找所选执行器在当前配置和项目目录下的本机技能，以及 WillYou 已启用的全局和当前目录纳管技能。两边的候选按名称合并，并标明来源。选中时插入草稿。「＋」菜单可多选图片或文件，准备好的附件随首条消息发送。

2026-11-23 用户确认任务输入栏采用 T3 Code 的主操作图标。输入栏最右侧保留一个主按钮，空闲时用上箭头发送，运行且草稿为空时用方块停止，运行中有草稿时用列表加号加入下一轮队列，同时在任务状态旁提供停止入口。现有队列行用弯箭头标记插话。允许在聚焦输入框或主按钮时按 Esc 停止，优先处理输入法、弹层和待处理请求。停止确认后，空草稿而且有可继续的队首或支持的暂停目标时显示三角形；继续队列按原顺序派发。草稿含新内容时以发送为主。

**待处理请求统一在输入框位置**：命令审批、Agent 提问、插件业务审批、M12 跨任务网页授权、子任务的请求用同一种面板——标题与来源、必要详情、带编号选项（数字键选择、Enter 确认）、可写原因；多个请求时 1／N 切换；命令审批不提供“拒绝并停止本轮”。邮件审阅正文及手动修改放在时间线，底部是批准发送、手动修改、让 Agent 按说明修改和拒绝的请求操作。跨任务网页授权在同一请求面板显示目标任务名称、页面地址和观察／控制的权限说明。不在页面里做通知卡片；窗口在后台时用系统通知提醒（设置可关）。交互式任务的请求不设界面超时，一直等待用户处理，Agent 在等待期间可以先做别的事；批准时宿主重新校验内容、账号和当前授权。业务等待写入资格时，用户可停止任务或撤销批准。取得资格后重新校验并开始计算执行时限；任何等待（排队、父任务排空、依赖安装等）都不计入，执行时限一律从宿主放行业务执行的时刻起算（2026-11-18 用户确认，技术方案 §8.1）。**修改 M12 R06.3 的“60 秒无人处理按拒绝”，仅对交互式任务**；无人值守任务（M15）仍默认拒绝。

任务中打开网页默认使用 WillYou 的本任务浏览器能力，用户可指定外部浏览器。浏览器审批沿用统一请求面板。收到成功的开页回执后显示「查看网页标签」，点击定位到原标签。开页回执确认标签已创建，网页实际内容取决于页面加载或网站验证结果。用户明确要求打开浏览器或展示网页时，使用已有的显示操作把同一张标签切到右侧。仅为查资料而浏览时在后台运行。2026-11-22 用户确认使用内置浏览器及开页回执，日用反馈补齐明确打开浏览器时的展示指引。

**右侧统一面板**：面板打开时，具体文件、网页、终端、差异与「+」共用窗口标题栏。从文件树单击不同文件，各自在顶栏新增并保留标签；再次单击已打开的文件时激活原标签。关掉最后一个文件回到「文件」目录标签。文件标签打开时，目录树和文件内容区域并排显示。未打开文件时，文件面板只呈现目录树和筛选框，内容区域收起并释放宽度（2026-11-23 用户确认）。目录树面板默认 250 px，可以拖动外侧分隔条调整宽度。仅目录树与打开文件后的宽度偏好分别保存。网页用标题区分，可以单独关闭。最大化／还原、终端抽屉和收起排在右端。「+」菜单提供查找文件、新建网页、打开终端和查看差异，各入口保留快捷键。全部关闭后显示「打开面板」列表。文件预览、编辑、保存和网页导航沿用 M9 与 M12 的行为。任务页的项目与任务名称、状态、插件、更多、终端和右侧面板入口同处窗口标题栏。改动卡片的“查看差异”在差异标签只读打开。**新建任务页**每次进入时右侧面板默认收起，主工作区占满可用宽度。窗口标题栏右侧提供文件夹和底部终端抽屉按钮。单击文件夹打开当前项目的文件面板（2026-11-23 用户确认）。面板最大化时占满当前工作区，暂停底层任务页交互，保留窗口控件和左侧导航；还原恢复分栏、活动标签、编辑状态及终端。最大化时打开底部终端先还原分栏。右侧面板可开文件、终端（项目目录），浏览器、差异属于任务，创建前置灰并说明原因。**进入子任务视图时，右侧文件与差异切换到该子任务的工作目录**（Git 写入子任务即其工作副本，标注“工作副本 · 分支名”），回到主任务时切回；各自的未保存缓冲互不覆盖（2026-11-16 用户决定）。

**多 Agent 的界面**：WillYou 委派的子任务（运行中或已完成）都能点开，在主任务区查看完整时间线。执行器自带子 Agent 点“查看过程”从任务区右边缘向左滑出只读抽屉。“任务关系”是任务区右上角的“任务关系 · N”胶囊，只在有子任务时出现，默认收起，点开为按内容定高的悬浮卡片（主任务、子任务、Git 项目的工作副本或 SVN／普通目录的写入队列）。卡片只由该胶囊（或卡片上的 ×）展开／收起；点卡内主任务或子任务行只切换任务区显示的主／子任务，卡片保持展开并高亮当前项；从主任务时间线或请求面板进入子任务时卡片自动展开并选中该子任务，便于点“主任务”返回。任务关系卡与抽屉打开时任务区整体左移，与其并排、不重叠；抽屉不加遮罩，左侧任务照常可操作。

用户可在任务内手动开 shell，参照 T3 终端抽屉；手动终端与 Agent 运行分离，使用单次登录 shell 初始化，抽屉先呈现再连接 PTY；返回任务可继续使用已有进程和输出，支持设置的字体及 Powerline 符号回退。保留 `pty-manager`／`pty-access` 所需能力。具体尺寸、浅深色、长文本、焦点和微交互以共享原型评审为准，不把文字合同当视觉完成。

### M14-R02 程序化运行与生命周期

任务“更多 → 运行诊断”保留常规 Hook、MCP 启动结果和配置提示。宿主必需 MCP 未就绪导致的实际启动失败、阻断回合的 Hook、权限警告和请求继续在主时间线显示，按已确认的会话和回合归属，迟到结果修订原条目。发出消息进入当前轮后即显示「工作中 0 秒」和「思考中」，执行器启动过程中的诊断在诊断面板查看。有实际工具活动后显示相应条目。普通短答完成后移除活动提示（2026-11-22 使用反馈）。

task、原生绑定、实际 run、回合和后台节点分别记录身份。运行登记真实进程及出生身份后才允许业务桥使用；后台工作、在途业务和原生阻塞请求（命令／文件审批、Agent 提问）未排空前不释放写入资格；已返回“等待你批准”的插件写、发送邮件等业务请求不占写入资格，回合结束、执行器退出或切换时保留，批准后由宿主执行并通知任务，只有用户停止、撤销或内容／账号变化时作废；跨任务网页授权在任务没有运行时获批，先保留为待生效，下一次运行开始并重新核对后才可用，期间停止或撤销则作废。连续对话、发送后立即停止、拒绝本步、正常完成、失败和进程退出都有确定终态；用户不再通过审批选项停止本轮，停止统一用停止键（请求面板出现时停止键仍可用）。

**停止与强制停止（2026-11-18 用户确认）**：等待执行器响应时持续显示已等待的秒数。宿主发出中断后，当前执行器持续 10 秒未响应时才显示“强制停止”，并提示“可能内存不足，强制停止会结束它的进程”。到时只显示按钮，进程继续等待；用户点击后仅结束这次停止所对应的原运行，实际观察到进程退出前保留占用。

界面状态为工作中、等待你处理、已完成、已停止、失败、受限；排队显示在工作中状态的子说明中。受限必须区分额度／限流和输出长度上限：前者照 T3 把该轮标为“已暂停”并保留工作过程，输入框上方提示具体原因及可用重置时间、不自动换账号，由用户手动继续（T3 另有“到点自动继续”，**本期不做**，2026-11-16 用户决定）；后者保留部分结果、提示手动继续。**本期不做主动的额度与上下文用量展示**（无额度条、用量环或“建议先压缩”）；上下文压缩由执行器决定，界面只显示“压缩中”与“上下文已压缩”分隔线，`/compact` 仅在执行器公布时提供。停止／失败的轮次末尾写“已停止／已失败 · 共工作 N”，正常完成的轮次不重复。仅在发送后断线或宿主崩溃导致是否接收无法判定时保留结果未知，核对原生记录与业务账后再允许后续操作，不自动重发。

本机离线时在输入框上方提示，检测到网络恢复后收起（2026-11-24 用户确认）。各执行器在时间线使用同一套重试和压缩状态。收到原生开始事件时显示进度，后续的次数、恢复、完成、失败或停止更新同一条记录。次数与等待时间取自执行器回报。

**目标（/goal）**：只对声明支持的执行器开放（Codex、Claude Code）；不支持时命令菜单不显示，手动输入提示不支持。时间线末尾显示目标条目：目标、状态、时长与轮次（不显示 token），可清除；Codex 另可暂停／继续，停止键＝停止本轮并暂停目标；Claude 目标不能暂停，只提供清除。主任务等子任务结果时，宿主自动让主任务停在等待状态而不清除目标，子任务结果唤醒时自动继续，全程不需用户操作——Codex 通过暂停／恢复目标，Claude 通过宿主停止回调（均照 T3，研究见 V16）。子任务不设目标；无人值守任务（M15）不用目标。目标运行中的请求照常等待用户处理。

**写入委派按目录类型分流（D4，2026-11-16 用户修改；Git 部分 2026-11-18 用户改为方案 C）**：
- **Git 项目**：写入型子任务有两种模式，由父 Agent 委派时选择（委派工具参数；未选择时默认共用目录；用户可用自然语言指定），任务关系卡和子任务卡片标明所用模式。派出前宿主**不自动提交，也不等待**同一仓库的其他任务。

  - **独立工作副本**：用于与父任务并行开发互不相关的功能。由**宿主程序**建工作副本（worktree），不绑定 Agent 用 shell 自建的工作副本。宿主步骤：从父任务当前提交（HEAD）在 `~/.willyou/worktrees/<项目段>/<分支>` 下建工作副本和分支，主目录未提交的改动不带入；委派回执和子任务启动说明写明所基于的提交，主目录有未提交文件时回执写明“主目录有 N 个未提交文件，没有带进子任务”，委派工具说明提示“需要子任务基于你的改动时，先提交你改过的文件”（`<项目段>` 为项目名英文简写加项目 ID 前 6 位，如 `smartdd-a1b2c3`；主任务在仓库子目录时子任务落在工作副本中的同一子目录）（照 T3 的 `~/.t3/worktrees`；路径不含空格，Agent 输出的工作副本绝对路径才能按 T3 链接规则识别），分支名 `当前分支名_willyou_英文简述`（全小写，重名加 `-2`）→ 按锁文件安装依赖（pnpm／npm／yarn，Maven 跳过；失败照常启动并告知子任务；不设设置项）→ 在该目录启动子 Agent。子任务结束时宿主把其改动提交到子分支，子 Agent 只改文件。主任务与独立工作副本中的子任务各写各的目录，不加锁、不排队。分支只在本机，不推送；合并后不删，由用户或 Agent 删。
- **SVN 与普通目录**：不建工作副本，一律按方案 B。**方案 B**（也用于 Git 共用目录模式）串行——父子共用目录，同一规范目录同时最多一个参与写入委派的 writer；写入型委派异步返回收据，父回合自然结束、工具／后台／业务排空且冻结新写入后释放写入权，子任务随后启动；父恢复先重新排队取得写入权再读取子结果；目录别名映射到同一队列。放行时宿主把上一位持有者改动的文件写进启动说明，要求先重新读取。
- **只读子任务**在所有目录类型下都在主目录并行。写入类型由宿主角色政策及权限档位判定，不由模型自述。
- **写前版本校验**：宿主管理的文件保存按基线版本校验。文件已被更改时拒绝覆盖并保留本地编辑，提示处理冲突。普通 shell 在获得写入资格后仍收到重读提示。

**独立工作副本的合并由主 Agent 完成，照档位（照 T3）**：子任务完成后宿主唤醒主 Agent，告知分支、提交与建议步骤（先提交当前改动，再用 `git cherry-pick -x` 拣入子任务提交；冲突逐文件解决、保留两边意图；不用 `reset --hard`、`checkout -- .`、`clean -fd`、强制推送）。主 Agent 写 `.git` 的命令按任务档位：请求批准逐条由用户批准，帮我批准由 Codex 自动审核批准，完全访问直接执行；宿主不代替主 Agent 合并。主 Agent 这一轮结束后宿主核对：子任务提交已进入当前分支（祖先、补丁等价或带 `-x` 来源记录之一，无法证明则为待核实）、无未完成的 cherry-pick／合并、无冲突标记、当前分支未变；不通过则提醒主 Agent，连续两次不通过在任务里标“需要你处理”。宿主不执行 reset／checkout／clean。

**复核与打回（照 T3）**：主 Agent 可给自己派出的子任务再发消息——已完成的子任务在原会话、原工作副本接着改，运行中的子任务插话或排队；要修改就发回原子任务，独立复核另派新的子任务。

方案 B（SVN、普通目录及 Git 共用目录模式）下捕获区间归属已取得委派写入资格的 run，Git 独立工作副本中的子任务按其工作副本单独捕获；期间其他独立任务、用户或外部程序的修改标为“该区间观察到，来源未独立证明”，不冒充 Agent 独占写入证据。二进制、大文件、删除和重命名分别说明，不覆写未保存编辑器缓冲。**没有回退按钮或回退接口**（D5）；用户用 git／svn 命令自行回退，Git 独立工作副本中的子任务结束时提交到子分支。

2026-11-24 用户确认参照 T3 Code 优化差异。默认单栏、自动换行，按文件显示可折叠的变更片段、行号与增删标记，可切换并排、关闭换行及打开文件列表。已取得文本补丁时可单独展示片段，无完整文件上下文时说明原因。

**快照与附件的保留**（2026-11-18 用户确认，参照 T3 Code）：
- 差异列表可查看全部轮次，点开改动卡片显示对应轮次。
- **Git 项目**：进行中和已归档任务的快照全部保留，不设轮数上限；删除项目或永久删除任务时删除对应任务的隐藏引用。只删引用，不在用户仓库执行 `git gc`。
- **SVN／普通目录**：私有影子库平时保留；接近 1 GiB 时，先回收已归档任务的快照，再回收进行中任务最旧的轮次，回收后仍超限才把本轮标为空间已满；被回收的轮次显示“快照已清理（空间回收）”，正在查看的轮次不回收；删除项目时释放该项目任务的快照。
- **附件副本**：任务存在期间保留（含已归档），永久删除任务或删除项目时回收对应副本；从草稿移除、输入取消时立即删除；准备后 24 小时未被引用的删除。
- **清理失败与归属**：删除时清理失败的项目登记后由后台重试；只删除 WillYou 自己登记过的引用和快照。
- **本期不提供删除单个任务**，长期使用的 Git 项目的 `.git` 会随轮次增长，用户已接受。

### M14-R10 新任务与旧代码清理（RC1、D1）

新版本只认新任务，新任务界面完整替换旧终端任务。侧栏及任何入口都不再列出旧终端任务，也不设“旧任务”分组或只读查看页，不自动恢复、不转换任务、不复制历史；旧任务数据库、原生会话文件和关联业务记录保留不删。项目、AI 配置、凭据、插件、Skill／MCP、数据库／SSH、邮件、浏览器数据继续可用；新表今后的数据库升级仍需版本守卫和事务。

**删除项目**（2026-11-18 用户确认，参照 T3 Code）：
- **一并删除，不可恢复**：该项目的全部新任务（含已归档），包括任务、对话、请求、委派、差异记录、附件副本和本方快照。
- **保留**：代码目录、子任务的 Git 工作副本目录与分支、Codex／Claude 自己的会话文件，以及应用调用记录（显示“已删除项目”）。
- **拒绝删除**：有任务正在运行、有待批准的请求、子任务未交回结果或工作副本正在准备时，拒绝删除并写明具体任务。
- **确认框**：写明将删除的任务数（含已归档）且不可恢复，列出保留的代码目录、工作副本路径和原生会话文件，并提示想保留记录可改用“归档项目”。

**新任务的归档与恢复**（2026-11-18 用户确认，参照 T3 Code）：
- **侧栏**：项目下的任务悬停时提供置顶和归档。右键提供重命名、置顶／取消置顶、归档与永久删除。置顶在本项目内保存，取消后按原顺序显示，关联的子任务保留在父任务下。重命名同步更新侧栏和任务标题。
- **永久删除任务**：确认框显示目标任务名称。确认后按任务 ID 清理 WillYou 的该任务记录、对话、差异和对应附件副本，保留项目文件和原生 CLI 会话文件。运行未结束、有待处理请求、手动终端未关闭或存在关联委派的任务无法永久删除。
- **设置页“已归档任务”**：按项目分组列出已归档的新任务，已归档项目下的任务也列在这里。每条可以“恢复”，不提供删除；已归档任务只随删除项目一起清理。
- **只读查看**：点开已归档任务，只读显示时间线和差异，顶部有“已归档 · 恢复”。恢复后回到原项目下面，下次发消息时沿用原会话。
- **撤销**：归档后的提示带“撤销”。
- **父子任务**：归档父任务时子任务一并归档，恢复时一并恢复；单独归档的子任务恢复后回到父任务下面。

M14 新界面开发完成且测试通过后，按[逐文件清理清单](技研/旧代码清理清单.md)清理“终端即任务”及本阶段替代的 `legacy-*` 兼容层，随 M14 发版；当前设计修订不删除生产代码。既有服务的 `pty_id`／`ptyId` 改为运行身份是必需接口改造；手动终端相关代码保留，M10 插件数据兼容层逐项核对，不按名称批删。清理后必须再跑受影响业务回归。

### M14-R11 本机程序与版本适配（RC2）

沿用 M13 程序发现和用户显式路径，核实可执行文件、版本、平台及能力。SDK 库版本随应用锁定，剔除其自带平台程序；Claude 指向本机 `claude`，Codex 使用本机 `codex app-server`。缺失、已知坏版、协议不兼容各自显示原因与升级／重检路径，不改用户安装。

能力采用最低已验证版本、已知不兼容列表及启动探测。低版本只关闭缺少的可选能力；核心协议不可用时才阻止该目标运行。不以精确版本相等判定可用性，不静默选其他版本、供应商或账号。程序升级后重检，新 run 重新协商；在用进程不替换。

项目数据库与 SSH（2026-11-23 确认）由任务启动流程按当前项目、标准 Skill 开关和任务授权准备，Claude Code 与 Codex 共用同一规则。每次新运行及恢复重新读取当前项目配置。项目上下文 MCP 随独立开关及执行器能力接入，重名或未就绪时提示状态，已启用的数据库和 SSH 诊断继续可用。只读委派不下发可由 shell 直接使用的连接凭据。

项目启用浏览器后，Codex 和 Claude Code 的新运行按本机程序的 MCP 能力接入内置浏览器。升级执行器后重新检测。Claude Code 在第一条消息前确认能发现开页、导航和读取快照工具。连接通道无法确认时，对话仍可继续，宿主说明浏览器入口的状态。宿主 CLI 涉及已核验的进程与沙箱策略，沿用独立的检查。

### M14-R12 可扩展接入（RC6）

### M14-R13 消息与文件／浏览器联动（RC4、D2）

按固定 T3 版本识别显式 Markdown 链接、裸绝对路径及代码中的合格文件路径（含行列和目录）。裸写的相对目录（如 `docs/`）、裸写的 `file://` 和只有文件名（包括行内代码）保持纯文本；显式链接中的 `file://` 仍按授权根校验。网址仅自动识别带 http(s) 协议或以 `www.` 开头的形式。**WillYou 中文场景特例（2026-11-18 确认）**：除固定 T3 分隔符外，全角冒号、逗号、顿号、括号等中文标点后的绝对路径也识别，例如 `路径：/Users/demo/a.ts:12`。当前项目授权文件根内的文件在右侧打开并定位行列，目录在文件树定位，http(s) 在内置浏览器新标签打开。已打开文档复用现有缓冲，未保存内容保留；不存在、已删除、越出授权根及未知协议显示原因并停止打开。

无项目任务不能绕过浏览器的项目要求，提示先关联项目。Cmd/Ctrl+点击明确请求外部打开，经同一根与存在性检查后调用系统打开；无已配置编辑器时给出选择／失败提示。PDF 复用 WillYou 已有文件预览器；不因 T3 的浏览器默认值改变 M9 文件查看合同。点击只是用户打开动作，不授予 Agent 新的文件或浏览器权限。

Agent 在任务内通过实际可用的宿主入口开页、导航、读取快照和操作页面。CLI 与 MCP 共用浏览器标签、页面引用、项目授权、任务审批和操作回执。后续调用复用返回的页面 ID，结果未知时先查原回执。两个浏览器 Skill 随可信应用资源交付，托管 Codex 的隔离目录可发现这两份 Skill。内置入口不可用时向用户说明，改用外部浏览器需要用户同意。

## 3. 校验、错误与持久化

目标选择只接受已登记 profile／driver 与宿主冻结修订；路径以授权根和物理身份校验；请求回应包含 requestId、请求修订和所属运行；草稿保存使用修订比较，冲突保留本地编辑。所有持久化接受均在回执成功后显示；重启恢复任务、草稿、规范历史与可证明的原生绑定，不重发接收未知的输入。账号、路径、模型失效有明确错误出口；请求秘密不进入消息历史或普通日志。

详细字段、状态和预算仅在[技术方案](技研/技术方案.md)维护；逐条操作与平台／本人前置在[测试用例](验收/测试用例.md)维护，结果在[执行记录](验收/执行与缺陷记录.md)维护。原型继续共用 `prototypes/m6-codex/`，增量见[原型说明](原型/原型说明与变更.md)。

三核心能力、R13 联动、每轮差异、手动终端及受影响 M13 回归都需完成。原型评审、实现、真实打包 App 验收、清理后复验及发版分别记录；技术实验不计产品通过。需要账号本人登录、系统授权和主观视觉／操作体验的项目集中列出，其余界面动作由 Agent 自主验收。跨平台未经执行保留未验结论。
