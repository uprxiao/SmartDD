# M14 统一任务 UI 原型说明与变更

版本：P0.1，2026-11-14。依据：[需求 R0.2](../需求.md)、[技术方案 T0.1 §10](../技研/技术方案.md#10-统一-ui-与交互落点)、[验收用例](../验收/测试用例.md)。**本稿是交互与迁移说明，尚未制作可操作 M14 页面、冻结截图或获得视觉评审通过；没有修改产品或共享原型代码。**

## 1. 目标与保留范围

在现有 WillYou 外层布局中替换中央任务交互，支持单 Agent、同任务切换 Provider 续聊和宿主多 Agent 委派。项目／任务侧栏、AI 配置、应用／插件、Skill／MCP、文件／浏览器及已有业务页面保留。共享原型继续使用 prototypes/m6-codex；M6–M13 现有页面与已验收样式不因 M14 被覆盖。旧“中央仅终端”的约定对旧路径保持，本阶段统一任务 UI 按用户新需求设计。

首版不增加团队模板库、流程编辑器或定时任务页面；协作 Skill 复用已有体系，M15 定时任务保持原顺序。新增演示必须标明合成，不接真实账号、CLI、文件、邮箱、语音或网络。

## 2. 页面落点与组件边界

| 区域 | M14 的设计职责 | 保留／避免混淆 |
| --- | --- | --- |
| 左侧项目／任务 | 保持任务导航、搜索、重命名与归档；子任务可从父关系进入，并显示实际目标／待处理状态 | 不恢复已取消的横向任务标签；归档与运行完成分开 |
| 任务标题／更多菜单 | 保留新建网页、应用、文件、信息、关闭与主题；停止／恢复从宿主动作投影获取 | 浏览器入口仍遵守任务属于项目的规则，不扩大原浏览器范围 |
| 中央历史 | 规范消息、工具调用、结果、来源及 Provider 切换记录；每条保留实际执行目标 | 切目标不改旧消息标签；原生完成、工具成功、子树完成分别显示 |
| 输入区 | 同一任务草稿、引用／附件、明确提交；选择配置／模型及单／多模式的主要操作入口 | 例如 Claude Code 使用 DeepSeek，分别展示执行器与配置／模型；不把 DeepSeek 写成另一执行器 |
| 右侧文件／浏览器 | 沿用 task／project 作用域、标签、尺寸、未保存保护及现有操作 | Provider 切换不重建资源身份；子任务浏览器授权不继承父 run |
| 任务信息／能力 | 沿用会话应用、Skill／MCP 加载与版本状态；明确当前实例和实际运行 | 不仅按 ptyId 判断运行；未知版本、需重启、不可用保留原因 |
| 请求区 | 原生问题、插件／邮件／浏览器请求统一排布，显示来源、所属任务与具体审阅内容 | 同样的按钮外观不意味着共用批准权限；子问题不能由父 Agent 冒充用户回应 |

## 3. 状态合同与操作

| 状态 | 可见事实与操作要求 | 关键回退／保护 |
| --- | --- | --- |
| S01 空任务／准备 | 可以先编辑草稿；首次发送展示排队／准备，允许取消已明确范围 | 创建及首次发送同一意图；重复点击不建第二任务 |
| S02 消息／工具流 | 草稿独立编辑，历史保持滚动锚点；工具失败保留失败原因 | 回合完成不覆盖业务失败；引擎连接存活不等于正在工作 |
| S03 请求与审批 | 显示来源／目标／待答数量，允许定位子任务；回应固定请求修订 | 切任务后不把旧批准应用到当前任务；过期项停止提交 |
| S04 Provider 切换 | 展示目标、恢复或新建原生绑定、历史遗漏及需要的边界 | 交接未知保持待核对；打开新目标失败不显示旧运行已恢复；草稿保留 |
| S05 协作 | 父子目标、状态、结果待投递分别呈现；Skill 入口复用现有能力 | 父空闲不等于子树结束；多转单先禁新委派并收口已有工作 |
| S06 目录与停止 | 展示 SVN 写入等待、当前占用与停止／清理中；允许查看子任务 | 不为 10+GB SVN 自动复制全目录；进程退出不等于后台／业务已排空 |
| S07 未知与恢复 | 明确未发送、结果未知、恢复要求和连接失效；提供核对原操作入口 | 不提供会盲目重发的通用“重试”；打开页面不启动旧 CLI |
| S08 既有业务 | 文件／浏览器／插件／项目入口与保存／关闭流程保留；引用只插入草稿 | 需要迁移插件目标选择器，不能只替换终端插入按钮；失败保留原视图 |
| S09 配置／版本 | 沿用配置权威，显示实例能力、运行资源、来源与失效原因 | 不静默换账号、模型或凭据；已安装 CLI 不等于任意 SDK 版本兼容 |

状态展示拆开“需要用户处理”“当前执行活动”“子任务／结果”“业务调用结果”，不压成一个 running 布尔值。待答请求、清理／未知及后台任务可同时存在。每个动作的可用性最终由宿主复核；UI 禁用只是提示。关闭父任务／归档时必须显示活动子树和停止影响，具体确认选项尚待原型评审，不沿用 PTY 空值自动放行。

## 4. 新旧入口与输入保护

新任务页面打开以读取持久历史／运行投影为基础。旧任务保留现有自动恢复规则；新路径不得调用旧 TasksStore.show→autoResume 作为缺省打开策略。自动暖启动若后续需要，必须走新运行服务的身份、幂等及未知状态守卫，不自动发送消息或切换原生控制者。

文件与插件引用、语音、首次发送共用新草稿目标身份和修订保护；旧 PTY 仍使用旧插入入口。插件动作保留原声明及宿主 prepared action 的来源复核，新增目标转换兼容层，不要求用户重装插件。语音新入口需明确 task-composer 合同，不能伪造终端或首页；shortcut-sent 不表示转写成功。Provider 在唤起期间变化的焦点与目标行为需实测。

## 5. 当前证据与下一步

[UI 入口与语音复核](../技研/实验/20261114_UI入口与语音迁移复核/README.md)取得十二个入口文件的源码证据和九项现有服务隔离检查；[UI 引用边界验证](../技研/实验/20261114_UI引用边界验证/README.md)覆盖旧文件引用组件。两者都不是 M14 页面验收。

当前验证阶段只完善本说明；后续原型阶段在共享原型新增隔离 M14 入口与模块，沿用既有布局／字体／颜色资源，完成上述九组状态、浅深色、窄窗、焦点／IME、长历史与弹层交互。原型更新前核对其目录规则；通过真实浏览器操作保留截图及状态映射，再提交用户评审。新增外观是 WillYou 待评审设计，不宣称与 T3 或 Codex 逐像素一致。没有截图、交互结果和批准基线时，A52 继续未执行。
