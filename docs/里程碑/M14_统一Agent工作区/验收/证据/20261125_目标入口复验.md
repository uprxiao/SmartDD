依据 [R02](../../需求.md#m14-r02-程序化运行与生命周期) 和 [A69](../测试用例.md#m14-a69-目标goal)。构建基线为 `9d77148d8` 加本轮目标入口和原生接入。macOS 26.6.1 arm64，WillYou 0.1.7，`app.asar` SHA-256 为 `b803a89ee94b44b63cf4adf8bf0802e803b25f3a46523f1bcf3a45f5737c41e6`。

## 打包 App

通过 CDP 操作独立打包 App 的控件，并核对任务快照、原生进程和模型请求。验证使用 Codex 0.171.0、Claude Code 2.1.331 和 agy 1.5.14，三个执行器分别连接本机回环模型夹具。启用 Gemini 的第二个测试实例用 Electron mock Keychain 保存合成 Key。两轮通过的 App 均正常退出，私有监听已关闭。

| 操作 | 观察结果 |
| --- | --- |
| 任务页「＋ → 目标」 | 菜单显示指定的两项。进入和退出模式都保留草稿，发送后原生 Codex 设定目标并发起实际模型请求。目标卡展示同一目标。通过。 |
| 「图片和文件」 | 点击后收到实际文件选择请求，CDP 回填测试文件后附件准备完成，随普通 Claude 回合提交。通过。 |
| 首页「＋ → 目标」 | 显式发送创建一条任务，Claude Code 回报原生目标设定并显示目标卡。通过。 |
| 手输 `/goal` | 原生 Claude Code 回报目标设定。通过。 |
| 不具备目标能力的配置 | 首页和任务页均只提供文件入口。通过。 |
| Gemini 原生续跑和完成 | agy 收到原目标，普通结束文案后由原生 Stop hook 再请求一次模型。分段完成标记收口后，界面显示已完成。通过。 |
| Gemini 运行中清除 | 观察到当前回合中断、同会话收到独立取消指令、取消确认后移除目标。下一条普通消息只发起一次主模型请求。通过。 |

首轮验收遇到旧驱动的菜单、正文和附件定位。保留失败结果后修正驱动，复用同一哈希的包。Gemini 供应商夹具初次保存时触发系统钥匙串授权，改用上述隔离存储配置完成两项产品验证。

## 软件与原型

- 类型检查、Agent 与受影响界面测试、三条真实 agy 测试以及原生打包组件检查通过。界面测试另行确认不支持目标时手输目标会保留在草稿中。
- 原型构建和 M14、M9、功能映射及 M13 模型检查通过。Headless Chromium 在深浅主题分别操作两处「＋」、文件选择、编辑和退出目标模式、发送和展开模拟目标卡。另复验活动目标锁定其他执行器、清除后恢复可选，以及离开后返回同一任务仍保留目标和未送出的目标草稿。
- 实包层覆盖本机 macOS arm64。测试模型使用合成响应，系统钥匙串认证与跨平台安装属于其他验收。
