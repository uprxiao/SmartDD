## 后续最小实包复验

1. 复用 A16 的私有 Codex 协议替身和 A27 的隔离故障边界，分别控制发送 ACK、前台 in-flight 工具/阻塞请求、四种终态。使用真实 App 及真实按钮，分别记录 native requestId/turnId、宿主请求类型、准确 PID／出生身份与 SQLite 终态。保留已证的强停、旧代次拒绝和重启对照，无需重跑整套。
2. 一次隔离模型设置小批可串行覆盖默认模型、设置未公布／公布、额度／短期限流／输出长度与 maxTurns。若只能注入协议，明确记录真实产品 App 与原生协议替身的边界，仍保留非占位业务处理器和实际页面判据。
3. 本地宿主请求在普通 Provider 失败／maxTurns 后仍保留的独立组，可复用 G01 的合成草稿。核对原 operationId、失败后仍可批准及实际效果次数。对照 A37 已验的 waiting_user 停止作废。
4. 迟到子结果需用已过期的旧身份做真实调度负对照；A28 的合法旧来源案例保留正对照。
