# M14 验收测试用例

版本：A1.0。日期：2026-11-16。依据：需求 R1.0、技术方案 T1.0、复核 §9。本稿为现行计划；生产实现与产品验收未执行。旧 A0.1 全稿保存在[历史](../历史/测试用例_A0.1_20261116.md)。编号保留，范围变更在各条注明；实际结果只在[执行与缺陷记录](../执行与缺陷记录.md)维护。

## 1. 环境、层级与批量顺序

U=产品单元／前端状态；I=实际 IPC、SQLite、服务／原生协议集成；R=真实模型；A=真实打包 App 的后台 CDP 界面操作；S=原生／系统层。研究候选或录制回放按其层级进入验证账，不抵产品 U/I/R/A/S。各条所有约定层级满足才算整条通过。

统一数据：独立 HOME／userData、P1 Git／P2 SVN／P3 普通目录、两份不同账号的 Claude 配置 C1/C2、Codex 配置 X1、OpenCode ACP O1；只用合成文件、账户与服务，程序版本和源／包哈希在开跑时冻结。旧数据夹具包含旧 tasks 行、原生文件与插件／邮件／浏览器关联，前后逐项 hash／行数核对；不复制日常凭据。目录、端口、数据库与运行互相隔离。

先执行无需 UI 的协议／业务组，再使用同一冻结包串行执行后台 CDP 页面组；原生选择器、系统修饰键、IME、剪贴板及真实焦点独立进入前台模式。登录、验证码、系统本人授权和主观体验集中到最后；其余由 Agent 完成。每条保存实际数据身份、操作、断言、截图／日志和收尾。受影响 M13 回归清单唯一维护在[技术方案 §8](../../技研/技术方案.md#8-m13-业务交付与回归)。
