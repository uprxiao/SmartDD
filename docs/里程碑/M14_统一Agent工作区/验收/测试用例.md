# M14 验收测试用例

版本：A0.1，待评审基线。日期：2026-11-14。依据：[需求 R0.2](../需求.md)、[现行技术方案 T0.1](../技研/技术方案.md)及[设计验证账](../技研/全局设计验证账.md)。这是本阶段验收用例的唯一维护位置；尚未批准为开发定稿，也不构成生产开发授权。

## 1. 使用与判定

用例 ID 与设计问题 Q 的数字保持对应，但用途不同：Q 记录设计研究证据，A 规定正式产品应如何验收。A21／A22 不建立，它们对应已确认延后的独立模板产品；本期 Skill 复用仍由 A08／A19／A23 验收。A36 检查 SVN 可选增强的能力边界，不把 SVN 核心能力排除。

每条用例列出的路径、矩阵与故障分支都属于该条的必验集合；不能只完成正常分支就整条标通过。新增需求或重大缺口追加稳定 ID 并评审，不靠缩减子矩阵提高通过率。未支持的平台／供应商不得隐去：按已批准支持矩阵说明不适用依据，否则保持未验。

实际结果、状态、构建、证据及缺陷只在[执行与缺陷记录](执行与缺陷记录.md)维护；本文件不复制状态。设计实验、旧里程碑结果、mock／直接 API 的局部结果不能自动使任何 A 用例通过。总数与进度以执行记录统计为准。

测试分层：契约／服务验证最小逻辑；集成验证实际 SQLite、进程、IPC 与业务连接；真实 App 使用同一候选安装包及隔离 userData；真实供应商验证另外标明授权及成本。协议成功不能代替真实页面，页面正常也不能代替身份／副作用证据。

### M14-A11 原生审批／问题的完整形态

- 关联：M14-R01／M14-R02／M14-R08；Q11；技术方案 §4、§9、§10；原型状态 S03 S05（待落到实际原型）。
- 层级：协议／服务／真实 App。
- 前置／数据：F02、F03、F04、F05；命令／文件审批、多问题／secret、完整声明支持的表单和 URL／外部证明；父／子各一条待响应；同 Driver 两实例、可为空的 turn、相同数字／字符串 RPC ID 与同 item 不同 callback。
- 操作顺序：按原生选项执行单次／会话／策略批准、拒绝、取消与超期；逐项测试问题及表单必填／类型／枚举／多选／默认／格式，未知形态不得降成批准；首期 URL 走明确 cancel；仅未来已声明支持导航／完成的组合执行打开后等待匹配完成。增加 MCP 原文含 pattern、宿主 callback 缺失该字段的反例，以及缺可信原文关联的普通外部表单。切任务／换 generation、伪造选项、原生连接丢失、回应后 ACK 丢失、重启恢复和双实例同 ID 分别执行。
