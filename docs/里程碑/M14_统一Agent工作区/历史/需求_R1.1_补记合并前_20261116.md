# M14 统一 Agent 工作区、Provider 续聊与多 Agent 协作需求

版本：**R1.1**。日期：2026-11-16。来源：[需求池 F32](../../../需求池.md)、[复核报告 §1、§7](../技研/复核_20261116/复核报告.md)。这是现行需求基线；用户已确认的 RC1–RC9、D1–D5 均已合并。原型评审、正式生产开发与产品验收尚未完成；本次授权为设计修订与技术验证。

## 1. 目标、范围与依赖

在同一逻辑任务内提供统一界面、跨 Provider 续聊和宿主多 Agent 委派。首批接入 Claude Agent SDK、本机 Codex app-server，以真实 OpenCode ACP 验证扩展性；Cursor、Kiro 是后续接入目标，不宣称本期已交付其产品支持。执行器、供应商、账号、模型、角色分别管理，已接入且能力满足的目标可以互换主／子角色。

**M13 已交付的项目、AI 配置、凭据、插件、Skill／MCP、文件、浏览器、数据库／SSH、邮件、语音及导入导出是保留的硬约束。** 入口、数据、实时授权及生命周期继续有效，按[技术方案业务对照与回归清单](../技研/技术方案.md#8-m13-业务交付与回归)核验。本期不增加独立团队模板管理、强制阶段工作流、定时任务、自动 SVN 管理、Git worktree 并行写入或文件回退。定时任务 F16 仍属 M15。

运行程序使用本机已安装的 CLI；SDK 库随应用锁定版本。缺程序时提示安装位置／检测结果，提供重新检测与显式路径选择；本期不提供受管下载和运行程序版本管理。首期真实研究平台为 macOS arm64；其他平台按逐平台包与业务证据声明，不能沿用本机结果。

## 2. 需求与验收合同

### M14-R01 统一任务界面与手动终端（RC3、RC7）

任务区参照 T3 的消息时间线、可折叠工作过程及新任务空白页；左侧栏沿用现状，底部保留 WillYou 输入框，右侧复用既有文件与浏览器组件。消息、思考、计划、命令、工具、审批／问题、子任务、切换与交接都进入统一模型。工作条目按回合聚合，可展开查看；运行耗时不累计重叠工具时长。

输入框具备目标／模型切换、发送、运行中排队与具备能力时的插话、停止、待处理请求、@文件和 Skill 选用。排队与插话明确区分；插话须按具体执行器／版本／模式探测，并有真实模型接受证据后才启用。证据缺失、探测失败或当前状态不允许时一律用排队，显示原因，不把排队输入冒作插话。草稿按任务持久保存，引用插入只改草稿，不自动发送；发送前复核目标、模型、权限及草稿修订。

用户可在任务内手动开 shell，参照 T3 终端抽屉；手动终端与 Agent 运行分离，保留 `pty-manager`／`pty-access` 所需能力。具体入口、尺寸、浅深色、长文本、焦点和微交互由共享原型评审确定，不把文字合同当视觉完成。

### M14-R02 程序化运行与生命周期

task、原生绑定、实际 run、回合和后台节点分别记录身份。运行登记真实进程及出生身份后才允许业务桥使用；后台工作、在途业务和待处理请求未排空前不释放写入资格。连续对话、发送后立即停止、拒绝本步、拒绝并停止、正常完成、失败和进程退出都有确定终态。

界面状态为工作中、等待你处理、已完成、已停止、失败、受限；排队显示在工作中状态的子说明中。受限必须区分额度／限流和输出长度上限：前者展示具体原因及可用重置时间，后者保留部分结果、提示手动继续，不显示额度耗尽或重置倒计时。具体文案由原型评审确认；恢复不能自动换账号。仅在发送后断线或宿主崩溃导致是否接收无法判定时保留结果未知，核对原生记录与业务账后再允许后续操作，不自动重发。

### M14-R03 同任务切换 Provider

覆盖同配置换模型、同执行器换供应商／账号、跨执行器。逻辑 taskId、历史与草稿保持；新目标首次使用时新建原生会话，切回兼容目标时恢复其原生会话。切换在父运行空闲且无在途发送／回应的边界生效；子任务可继续独立运行，迟到结果按原子任务身份回收。目标失效时说明原因，不静默替换。

“默认模型”是选择状态，不是可发送的模型名；从指定模型切回默认必须恢复执行器的默认选择。选项必须等执行器公布后才应用；未公布的旧设置显示跳过原因，不声称已经生效。

### M14-R04 上下文接续与来源

新原生会话交付全量可用摘要；恢复已有会话只交付其缺少的增量。交接、附件、遗漏范围和目标覆盖水位可追溯，原消息不被摘要覆盖。预算不足时列明遗漏及可继续读取的来源；投递失败和未知接收分别处理。

真人输入、文件引用、历史、Skill 指令、交接和子结果分别标来源；交接与子结果不产生新的真人写入授权。持久化失败先保留草稿／可恢复输入，不能显示发送成功。

### M14-R05 单／多 Agent 共存

普通聊天与宿主委派共用同一任务基础。时间线展示父子关系、目标、排队、请求和结果。关闭新委派后，现有子任务收口再进入单 Agent 模式；父回合完成不等于任务树完成。Provider 原生子 Agent 与宿主子任务分别标识，可停止范围由已声明能力决定。

### M14-R06 委派、问题与结果回收（RC8、D4）

Agent 经宿主 MCP 选择兼容目标；宿主持久创建子任务、独立运行身份和结果收据。创建、观察和回父按请求标识去重；父忙时排队，父空闲后投递。子问题／审批回到准确的子任务卡片，旧运行的批准不能作用于新运行；用户可取消排队、单回合或子树。

首期固定方案 B：父子共用工作目录；同一规范目录同时最多一个写入型 Agent，只读型可并行。写入类型由宿主角色政策及权限档位判定，不由模型自述。写入型委派采用异步收据，父回合继续执行并自然结束；父回合结束、工具／后台／业务排空且冻结新写入后才释放槽，写入子任务随后启动。只读子可立即并行；本期不支持父阻塞在 MCP 中同步等写入子结果，不依赖原生暂停能力。父恢复先重新排队取得槽，再读取子结果续跑。Git／SVN 用同一规则，目录别名映射到同一队列。保留“运行可绑定不同目录”的扩展接口，方案 C 本期不实现。

### M14-R07 协作规则复用

已有 Skill／指令可重复选用，并实际调用公共委派能力；Skill 的相对脚本和资源可用。角色不绑定品牌，规则不复制凭据，不扩大宿主权限、深度或并发限制。后续模板通过同一服务接入；本期不实现模板库、依赖图编辑器或强制业务阶段门禁。

### M14-R08 既有业务接入（RC5）

### M14-R09 Git／SVN 与每轮差异（RC8、RC9、D4、D5）

### M14-R11 本机程序与版本适配（RC2）

沿用 M13 程序发现和用户显式路径，核实可执行文件、版本、平台及能力。SDK 库版本随应用锁定，剔除其自带平台程序；Claude 指向本机 `claude`，Codex 使用本机 `codex app-server`。缺失、已知坏版、协议不兼容各自显示原因与升级／重检路径，不改用户安装。

能力采用最低已验证版本、已知不兼容列表及启动探测。低版本只关闭缺少的可选能力；核心协议不可用时才阻止该目标运行。不以精确版本相等判定可用性，不静默选其他版本、供应商或账号。程序升级后重检，新 run 重新协商；在用进程不替换。

### M14-R12 可扩展接入（RC6）

Claude SDK、Codex app-server、ACP 是并列协议适配族。OpenCode／Kiro 优先 ACP；Cursor 按其 SDK 能力另写适配器。新增适配器登记能力、配置发现、事件及 Skill 发现目录，复用任务、切换、委派、业务桥、请求和差异服务；MCP 可经 ACP 注入。扩展性主证据使用真实 ACP Agent，合成适配器仅用于故障注入；未验证的 Skill 或权限能力显示未验证，不按品牌猜测支持。

### M14-R13 消息与文件／浏览器联动（RC4、D2）

按固定 T3 版本的路径识别规则识别 Markdown 链接、绝对路径、`file://`、含行列的相对路径和目录；**只有文件名的行内代码不做链接**。当前项目授权文件根内的文件在右侧打开并定位行列，目录在文件树定位，http(s) 在内置浏览器新标签打开。已打开文档复用现有缓冲，未保存内容保留；不存在、已删除、越出授权根及未知协议显示原因并停止打开。

无项目任务不能绕过浏览器的项目要求，提示先关联项目。Cmd/Ctrl+点击明确请求外部打开，经同一根与存在性检查后调用系统打开；无已配置编辑器时给出选择／失败提示。PDF 复用 WillYou 已有文件预览器；不因 T3 的浏览器默认值改变 M9 文件查看合同。点击只是用户打开动作，不授予 Agent 新的文件或浏览器权限。

## 3. 校验、错误与持久化

目标选择只接受已登记 profile／driver 与宿主冻结修订；路径以授权根和物理身份校验；请求回应包含 requestId、请求修订和所属运行；草稿保存使用修订比较，冲突保留本地编辑。所有持久化接受均在回执成功后显示；重启恢复任务、草稿、规范历史与可证明的原生绑定，不重发接收未知的输入。账号、路径、模型失效有明确错误出口；请求秘密不进入消息历史或普通日志。

详细字段、状态和预算仅在[技术方案 T1.1](../技研/技术方案.md)维护；逐条操作与平台／本人前置在[测试用例](../验收/测试用例.md)维护，结果在[执行记录](../验收/执行与缺陷记录.md)维护。原型继续共用 `prototypes/m6-codex/`，增量见[原型说明](../原型/原型说明与变更.md)。
