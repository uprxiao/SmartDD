# M12 需求与 WillYou 现有实现的冲突核对

日期：2026-11-03。依据：需求 [R0.4](../需求.md)；WillYou `feature/0.1.1`（基于 `19a5663f`，工作区有未提交的 M12 文档／原型改动，生产代码未改）；Orca 链路见 [Orca 浏览器 CLI 与 Skill 链路](Orca浏览器CLI与Skill链路_20261103.md)。方法：只读源码，**未运行**。“已核实”＝主会话亲自对过源码行；其余为子代理读取，进入技研前按需复核。

本文件只列事实和建议。会改变需求的条目标为“待用户决定”，用户决定后再改 `需求.md`（R0.4 → R0.5）；本文件不直接改需求。

## 1. 总判断

- **整体方向不冲突。** WillYou 已经有一套和 Orca 思路一致的做法：HTML 预览和 MCP 扩展界面都是“主进程建一个独立页面视图（`WebContentsView`）＋独立会话分区＋`webContents.debugger`”（`src/main/core/files/html/service.ts:56-80`、`src/main/core/files/mcp/ui-view.ts:38-58`）。M12 照这个模式做，只把 Orca 的 `<webview>` 换成主进程持有的页面视图，agent-browser 照样通过每页一个 CDP 代理来操作。
- **WillYou 在两处比 Orca 更严，不该退回 Orca 的做法**：调用方身份（WillYou 查进程树＋可执行文件哈希；Orca 只比令牌）和任务归属（WillYou 由运行身份决定；Orca 按当前目录推断、推断不出就不限范围）。
- **真正要动的地方集中在 M11 网关**（令牌时长、结果大小、参数形态、模块注册），以及 M9 文件工作区的挂载方式。下表逐条列出。

## 2. 冲突与约束清单

## 4. Claude Code（按用户要求记录，不纳入 M12）

- Orca 的机制对 Claude 和 Codex 是同一套（一个 CLI、一份 Skill），区别只在 Skill 放 `.claude/skills`、账号目录用 `CLAUDE_CONFIG_DIR`、权限按 Claude 自己的 Bash 确认。
- WillYou 现状：Claude 走“每任务插件目录 `--plugin-dir`＋MCP”，**没有 CLI 入口**（`capability-delivery-adapters.ts:334-337`）。M11 的 CLI 沙箱注入只为 Codex 0.166.0 写。
- 以后给 Claude 加浏览器，需要的增量是：M11 为 Claude 开 CLI 入口（Claude 默认无网络沙箱，socket 连接问题比 Codex 小，但每条命令会走 Claude 的权限确认，要考虑预放行 `Bash(willyou-app browser:*)`）；Skill 正文可与 Codex 共用，放进现有插件目录。浏览器服务本身不需要为 Claude 改动。
