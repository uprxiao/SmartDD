# M12 原型说明与变更

依据：[需求 R1.3](../需求.md)。当前状态：R1.2范围已确认并授权S1及后续S2–S6开发，依据需求§9；原型层P与实际App验收分别记录。2026-11-04用户确认下载路径澄清：普通页面下载进系统目录、专用CLI显式路径优先；不改变现有页面与交互，原型源码与原确认快照继续沿用。旧阶段说明见[历史](../历史/原型说明_R1.2_下载路径澄清前_20261104.md)。

## 1. 工程、入口与边界

- 共享原型工程 [prototypes/m6-codex](../../../../prototypes/m6-codex/README.md)，遵守其本地 `AGENTS.md`：只用合成数据、不访问真实网络／账号／浏览器数据、保留全部既有入口。
- 计划入口：`?preview=m12`，打开一个示例任务并展开右侧工作区，直接显示网页标签。
- 新代码放在独立模块（暂定 `BrowserWorkspace.jsx`、`browser-prototype-model.mjs`、`browser.css`）。对 M9 的 `FileWorkspace.jsx` 只增加**可选属性**（网页标签列表、当前是否显示网页、点文件标签时的回调），不传时 M9 行为完全不变。M9 大部分已验收（2026-10-30 为 416/419，余 3 条平台用例），标签栏属已验收部分，改动后须跑 M9 原型的既有测试确认无回归。
- **网页内容是合成的**：用原型内置的示例页面（模拟一个带登录页的测试站点、一个 Bug 复现页）代替真实网页，不发起任何网络请求。
- **视觉依据**：没有 Codex 浏览器的运行时截图（F22-B 调研只确认了结构）。原型沿用 M9 文件标签栏与工具栏已按 Codex 复刻的样式，做到“Codex 风格的结构”，不宣称与 Codex 浏览器逐像素一致（需求 D8、C9）。
- **Agent 行为是模拟的**：原型没有真实 Agent，用一个明确标为“演示”的控制面板触发“Agent 正在操作”“跨任务请求”“下载”等状态。

## 3. 原型变更记录

### 3.1 第一批（2026-11-03，B01–B04、B09、B10、B15）

**新增文件**（均在 `prototypes/m6-codex/`）：
- `src/browser-prototype-model.mjs`：纯逻辑。地址栏规范化逐条对齐 Orca `normalizeBrowserNavigationUrl`（本机地址补 http、带点域名加端口补 https、`*.localhost` 补 http、本机路径转 `file://`、`javascript:`／`data:`／`mailto:` 判无效、`looksLikeSearchQuery` 决定搜索回退）；7 类加载失败；合成站点映射；按任务的标签与历史；Agent 活动标记（命令结束后保持 20 秒）；暂停语义（拒绝新命令、立即结束只读等待、写命令执行完当前一条）；只持久化地址。
- `src/BrowserWorkspace.jsx`：网页标签内容区。工具栏（后退、前进、刷新／停止、地址栏、安全状态、“项目登录态”标识、暂停／恢复 Agent、演示开关、菜单）、合成页面、失败页、无效地址页、Agent 横幅与暂停横幅、“演示 · 合成”控制条。第二批功能在菜单中占位并标明“第二批原型（尚未制作）”。
- `src/browser.css`：只用现有主题变量，深色自动跟随；网页标签复用 M9 的 `fw-tab` 规则。
- `tests/browser-prototype-model.test.mjs`：15 个单元测试。

**修改文件**：
- `src/FileWorkspace.jsx`：6 处，全部为**可选属性**（`webTabs`、`webActiveId`、`onWebSelect`、`onWebClose`、`onWebNew`、`webView`）：标签栏追加网页标签与“新建网页标签”按钮；网页标签激活时文件标签不显示为选中；网页层盖在文件内容之上（文件区保持挂载，状态不丢），并拦截键盘事件避免触发文件区快捷键。不传这些属性时 M9 行为不变。
- `src/App.jsx`：新增 `?preview=m12` 入口与窗口导航“M12 · 浏览器”按钮；按任务保存网页标签（`willyou-m12-prototype-v1`，只存地址与当前标签序号）。

**入口**：`?preview=m12`，打开“检查多平台安装包”示例任务，右侧工作区显示网页标签“登录 · 测试环境”。所有页面为合成内容，不发起网络请求；Agent 行为由底部“演示 · 合成”控制条模拟。

**验证（2026-11-03，原型层 P，非打包 App）**：
- 隔离的无头 Chromium（Playwright 缓存的 headless shell，临时用户目录，不接触日常浏览器）经 CDP 驱动 Vite 开发服务器，1600×1000；点击、输入、回车均为真实输入事件。主题切换走任务页“更多 → 主题”的真实入口。
- 11 组检查连续两轮通过、页面无报错：B01 标签栏与新建／切换／关闭、B02 前进后退与加载中“停止”、B03 地址规则（无效、搜索、本机地址补全、首次点击全选、无效输入保留并全选）、B04 七类失败（含“服务起来后自动重载”与“网络恢复后自动重载”）、B09 活动标记（标签蓝点、页面发光边框、20 秒保持倒计时）、B10 暂停（拒绝新命令返回 `browser_paused`、只读等待被立即结束、运行结束清除）、R01.9 重启只恢复地址、B15 浅色与深色。
- M9 原型既有测试 297 个全部通过（改动前后一致），新模型测试 15 个通过，`vite build` 通过。
- 证据：[截图／驱动／结果／源码哈希](截图/批次1_20261103/)。

**验证过程中发现并修复的问题**（均已复验）：
1. 地址栏首次点击不能全选，输入会接在旧地址后面（例如变成 `https://qa.example.test/react%20hooks`）——改为与 Chromium 一致的“首次点击全选”。
2. 提交后地址栏会短暂显示未规范化的输入——提交时立即写入规范化地址。
3. 输入无效地址后，原输入会被旧地址覆盖而焦点仍在地址栏——改为保留输入并全选，方便直接重输。
4. Agent 发光边框被页面内容遮住、浅深色下都几乎看不见——改为不随滚动、不被内容覆盖的叠加层。
5. 新开标签会继承上一个标签的“加载中”状态——加载状态改为按标签记录。

另有 4 处驱动脚本自身的问题（选择器与应用左上角“前进”重名、回车事件缺少 `text`、等待条件返回 DOM 节点、恢复网络后的预期写错），已修正，未计为产品问题。

**未覆盖／边界**：视觉只与 M9 现有样式对齐，未与 Codex 浏览器对照（无参考截图，D8）；只在 1600×1000 一种尺寸下截图；没有打包 App 验证；中文输入法、系统剪贴板等系统层未涉及。

### 3.2 第二批（2026-11-03，B05–B08、B11–B14）

**新增文件**：`src/BrowserPanels.jsx`（下载条、页内查找条、站点权限与外部应用提示条、HTTP 基本认证对话框、跨任务授权对话框与授权列表、登录态管理、Cookie 导入流程、浏览器设置）；`tests/browser-prototype-batch2.test.mjs`（8 个单元测试）。

**修改文件**：`src/browser-prototype-model.mjs`（下载文件名清洗与重名编号逐条对齐 Orca `browser-download-filename.ts`；项目／任务登录态的新建、克隆、删除回落；证书例外与站点权限的记忆与撤销；跨任务请求判定；Cookie 导入结果；证书错误与基本认证合成站点）、`src/BrowserWorkspace.jsx`（接入上述面板、菜单改为真实入口、登录态标识可点开管理、⌘F／⌘L 快捷键）、`src/browser.css`、`src/App.jsx`（按项目保存登录态元数据 `willyou-m12-prototype-profiles-v1`：只存名称、站点与选择，不存 Cookie 或密码；全应用浏览器设置）、原型 `AGENTS.md`（M12 约定）。

**各项实现要点**：
- B05 证书错误：非本机地址给出“我了解风险，继续访问”，按站点记在当前登录态；被拦截或按例外访问的页面，地址栏一律显示红色“证书不受信任”图标，不显示为安全连接；提示写明 Agent 无法放行。
- B06 提示：基本认证对话框（取消后为 401 页，可重新登录；不保存账号密码）；站点申请位置的提示条（允许／拒绝按站点记住，再次申请自动沿用）；外部应用链接提示条（不会真的打开）。
- B07 下载条：进行中进度、完成、失败、取消；打开、在文件夹中显示、移除；重名自动编号 `订单导出 (1).csv`。
- B08 页内查找：⌘F（地址栏内、点击页面正文后均可），回车下一个、⇧回车上一个、Esc 关闭；显示“第 i / n 个”。
- B11 跨任务：同项目请求弹窗（仅观察／可以操作，“允许本次运行”）；授权列表可撤销；跨项目与无人值守请求直接拒绝并返回 `SCOPE_DENIED`，不弹窗；运行结束清除授权。
- B12 登录态管理：项目登录态（默认，不可删）＋任务独立登录态（C1），新建、克隆、用于当前页面、删除（确认后使用它的页面回落到项目登录态）；各自的证书例外与站点权限列表可撤销；显示导入来源。
- B13 Cookie 导入：选 Chrome／Edge 及其 profile 与目标登录态 → 风险确认（全部 Cookie 除 Google、Agent 可读会话令牌、钥匙串授权）→ 模拟钥匙串（允许／拒绝／超时／无法解密）→ 结果摘要；拒绝和超时不写入任何 Cookie。Agent 没有入口。
- B14 浏览器设置：默认搜索引擎（立即影响地址栏搜索）、浏览器身份（标明重启后生效）、下载位置说明。

**验证（2026-11-03，原型层 P）**：同第一批的隔离无头 Chromium＋CDP 方式。第二批 9 组检查在最终代码上通过、页面无报错（证书拦截与继续访问、证书页图标；基本认证取消／重登／通过；位置权限记住；外部应用提示；下载进度／重名／失败／移除／在文件夹中显示；⌘F 从正文与地址栏打开、计数、下一个、Esc；跨任务允许与撤销、跨项目与无人值守拒绝；登录态新建／隔离／改用／撤销／删除回落；导入拒绝不写入与成功摘要、来源记录；搜索引擎切换生效与身份重启提示；深色 4 张）。在同一最终代码上重跑第一批驱动 11 组仍通过；M9 原型测试 297、模型测试 23（15＋8）、`vite build` 均通过。证据：[截图／驱动／结果／源码哈希](截图/批次2_20261103/)。

**第二批验证中发现并修复的问题**（均已复验）：
1. 点击页面正文后 ⌘F 无效（正文不可聚焦，快捷键收不到）——改为窗口级只处理焦点在页面正文的情况，网页区域内由自身处理，不抢终端与文件区的快捷键。

4. 确认导入与设置提示里出现字面反引号——改为代码样式。

**未覆盖／边界**：同第一批（无 Codex 浏览器视觉对照、单一尺寸、非打包 App、无系统层）。另外：页内查找只计数、不高亮匹配位置；下载、钥匙串、外部应用都是模拟；跨任务授权使用合成的“同项目示例任务”，因为原型示例数据中当前项目只有一个任务。
