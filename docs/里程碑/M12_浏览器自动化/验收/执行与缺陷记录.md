## M12-D01 CLI 运行令牌 30 分钟后失效，任务仍在运行也一样（2026-11-03）

- 来源：链路调研 [冲突核对 K10](../调研/WillYou冲突核对_20261103.md)。M11 设计要求令牌“有过期、可撤销”（M11 `技研/架构设计.md` §6.3），实现只在启动时签发一次，到期计时器直接撤销，没有续期。环境变量里的令牌在运行中的 Agent 内无法更换，所以不能照搬 MCP 的换令牌续期。
- 复现（红）：`src/main/core/applications/__tests__/cli-gateway.test.ts` 新增用例“keeps an active run usable past the token TTL (M12-D01)…”。在修复前的代码上运行，第一次超过有效期的调用就返回错误，断言 `status:'ok'` 失败（1 failed／16 passed，2026-11-03）。
- 修复：`src/main/core/applications/cli-gateway.ts` 把有效期改为租约。到期时（计时器触发或调用时发现已过期），运行仍活跃就顺延一个有效期，运行已不活跃就撤销该运行的令牌并返回 `TOKEN_EXPIRED`。停止任务时立即撤销的原机制不变。
- 测试合同变化：原 `rejects expired …` 用例要求“运行活跃、时间超过有效期即拒绝”，这正是本缺陷的行为，因此改为“运行已不活跃且超过有效期即拒绝”。错误码 `TOKEN_EXPIRED`、不调用业务、不读密钥、不读对端身份这几项断言不变。
- 验证：见下方“测试运行”。

## M12-D02 `willyou-app` 不能从标准输入传值（2026-11-03）

- 来源：需求 C5（密码走标准输入）、冲突核对 K13／K14。`willyou-app` 只接受 `--键 值`，值先按 JSON 片段解析（`--cursor 123` 会变成数字），也不读取标准输入，所以密码只能写进命令行参数，纯数字文本也传不成字符串。
- 复现（红）：`native-cli.test.ts` 新增用例“reads one field verbatim from stdin…(M12-D02)”。在修复前的 `cli.mm` 上，`--stdin cursor` 被拒（退出码 2），断言失败（1 failed／6 passed）。
- 修复：`native/applications/cli.mm` 新增 `--stdin <字段>`。规则如下：
  - 标准输入的全部字节原样作为该字段的**字符串**值，去掉末尾一个换行（`\n` 或 `\r\n`），与 Docker `--password-stdin` 的惯例一致。
  - 只能用一次。字段名的规则与普通字段相同；`json`、`stdin` 和保留字段（如 `token`）不能用。
  - 不能和同名字段同时给出。
  - 标准输入是终端时拒绝；超过 256KB 返回 `TOO_LARGE`；不是完整 UTF-8 时拒绝。
  - `--help` 增加一行用法示例。
- 验证：同一用例在修复后通过（7／7）；用例同时断言输入内容不会出现在命令的输出和错误里。

## M12-D03 写命令断连时 `willyou-app` 不输出请求编号（2026-11-03 登记，开发 S1 修复）

来源：[Review review-20261103-1518](../../../review/review-20261103-1518.md) R04。现象：`native/applications/cli.mm:64` 在请求已发出、结果未返回时调用 `failure(...)`，输出里没有本次请求的 `requestId`（也没有 `operationId`），Agent 无法查询这次写命令是否已生效。影响：R06.2“结果未知时可查询”无法闭环。处理：S1 先写失败测试（native-cli 用例：发送后断连，断言输出含 `requestId` 且退出码 5），再改 `cli.mm`；查询入口为新增的 `browser operation get`（需求 R06.2 R0.9）。状态：**已修复（2026-11-03，S1 第一项）**。
- 红测：`native-cli.test.ts` 的断连用例增加断言“输出的 `requestId` 等于已发出请求的 `id`”，修改前失败（`expected undefined to be '<id>'`）。
- 修复：`native/applications/cli.mm` 的 `failure()` 增加可选的 `requestId`；“已发出、未收到结果”分支传入本次 `capabilities/call` 请求的 `id`。未发出时不输出。
- 验证：`native-cli.test.ts` 7/7 通过（测试每次从源码重新构建 `willyou-app`）；`pnpm typecheck` 通过。浏览器侧的 `operation get` 查询随浏览器模块实现，见 S1 后续项。
