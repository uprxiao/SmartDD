## 问题清单

**中 R01：失败dispatch污染tracked状态，与固定Orca不一致。**

- `helper-dot6/cli/src/native/actions.rs:8348–8394`直接改写传入MouseState的位置、active_button_mask、buttons、last_click和click_count。
- `input_mouse:8424–8453`、`mousemove:8552–8573`、`mousedown:8576–8596`、`mouseup:8599–8619`均先build写入当前state，再await `dispatch_owned_mouse`。该函数8413–8418才核browser/session并发事件；Err向上传递，顶层1612–1619仅转换错误回包／drain，没有回滚。
- 固定Orca `agent-browser-bridge-pointer-commands.ts:49–65`在build前快照，catch还原；`pointer-input.test.ts:343–377`明确覆盖失败press不留held、失败move不迁移、失败press不影响双击计数。

因此确定未发出的失败也可能使下一次wheel使用失败move坐标、使后续move带上虚假的held，或使下一成功press计为第二击。这里只是源码路径证明，未执行故障注入，不声称发生了真实点击／拖动。旧`.5`发送失败同样没有还原，是历史参考缺口；不新增host click/find同步要求。

## 修改建议

按协调者已决定的最小修复：四个可变handler先复制MouseState，在临时副本build；dispatch成功或真实dialogOpened后提交，Err不提交。这里必须把dialogOpened当已发出的输入保留held，而不是走失败回滚，更不能自动补up。本执行者未修改代码，下一冻结基线须再核，实际验证由统一租约执行。
