# Review Report

## 摘要

仅核 mouse move/down/up/wheel 及其与 host click、Helper find click 的状态边界。固定 Orca 对象 `bd9455b61655b9e76504349a6c8571f74f14954f` 全部经 `git show` 提取；WillYou 使用 source009，manifest `41ddb00334c453d56a8965cebc82de278b3c7b83a4c2e501ca8227e0f97b35e4`。未运行 Native、App、浏览器、监听、构建或测试，未修改公共文件。

确定差异是：公开 mouse wheel 路径在 .5 中仍发 `(0,0)`，没有继承 move 坐标或 held-button mask；固定 Orca 明确在 tracked pointer 坐标滚动。跨 host click/find click 自动同步这份状态没有明确 M12 合同，参考也不保证，不能当作新缺陷。

## 问题清单

1. **中：固定参考与当前 wheel 执行行为不同。** M12 技术方案§0 P1写“命令与执行沿用Orca”；但 R04.1 本身只列命令，未展开 wheel target。Orca [`pointer-commands.ts:186–209`](../../orca/src/main/browser/agent-browser-bridge-pointer-commands.ts) 的 wheel 发 `state.x/y/buttons`，其固定测试144–155行明确“tracked pointer position, not origin”。WillYou [`commands.rs:2417–2428`](../../helper-dot5/cli/src/commands.rs) 只生成 delta；[`actions.rs:5371–5393`](../../helper-dot5/cli/src/native/actions.rs) 从 cmd 取 x/y，缺失默认0，且不读 `mouse_state`。这是可证参考差异；是否依P1直接作为范围内兼容缺陷，由协调者处理，不能声称R04.1另有未写明的坐标字段。
2. **低：旧T062的通过不证明wheel目标或held-buttons。** 原用例108行要求观察坐标、按键与滚动量；历史 `P004/attempt008` judge26行仅验证 wheel dx11/dy173，既有 raw 的 `$.mouseWheel.events` 明确记到 wheel `(0,0)`，同时 move/down/up在 `(350,350)`。旧夹具只记 `event.button`，没记 `event.buttons`。所以保留它已验证的三个显式按钮、move/down/up坐标、delta与顶层scrollY173，不能扩称已验证嵌套滚动目标或按住按钮滚轮状态；历史Helper是 `.1`，不是本轮`.5`。

## 修改建议

不改公共合同、代码或旧结果。先由协调者按P1确认wheel参考口径；补测只需下述最小T062子段。原始通过与本次新增事实并存，不靠改原预期掩盖差异。

## 风险/待确认点

**最小必要实测，尚未执行：**同一真实CLI隔离夹具放两个独立滚动区域，原点与目标区域分离。先move到非原点目标，wheel同时断言原始事件clientX/Y、target、delta与两个区域实际scrollTop，不能只验delta。再在目标处显式left down→wheel→up，记录 `event.buttons` 和CDP发送载荷，确认held=1、release后=0；小数/负delta可合入这一组，不重跑既有无关矩阵。

**条件性诊断，不先定新预期：**若协调者决定统一默认up或跨动作状态，再用right down→省略button up，以及move A→host click B→down/up、move A→find click B→down/up各一条观察指针状态；当前静态实现预期仍用A，不应先要求跟随B而判红。固定Orca这条跨路径不自动统一的事实也应保留。

本报告仅穷尽上述四命令及指定混用边界，未扩成整个鼠标／输入系统审计，不涉及真实设备、触控、页面迁移或所有平台。正式用例通过数增量为0。
