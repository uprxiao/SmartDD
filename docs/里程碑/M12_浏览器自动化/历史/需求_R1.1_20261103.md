## 1. 目标与使用场景

**目标**：让 WillYou 里的 Agent 能在应用内的浏览器里打开、观察和操作网页，并带着登录态完成实际工作。

**典型场景**（用户 2026-11-02 提供）：
1. 从禅道拉回 Bug，读出其标明的环境与账号；
2. 打开浏览器复现：复现成功则分析修复，修复后再次复现验证；
3. 复现不了时，本阶段只产出“未复现说明”交用户处理。禅道写能力不可用，见 R08.2。

M13 定时任务开启后，同样的流程也在无人值守下运行，约束见 R08.4。

## 5. 需求细则

### 5.1 M12-R01 内置浏览器视图

**R01.0 位置与隔离**
- 网页标签位于右侧工作区，与文件标签并列；标签集合按任务隔离，切换任务即恢复该任务自己的网页标签。
- 网页运行在独立沙箱：无 Node 集成、上下文隔离、保留网页安全策略。
- 只新增标签类型，不改 M9 文件标签现有行为。

**R01.1 地址栏输入规则**（对标 Orca `browser-url.ts`）

| 输入 | 处理 |
| --- | --- |
| 空、`about:blank` | 新标签页（启动页，R01.11） |
| `localhost`、`127.x.x.x`、`0.0.0.0`、`[IPv6]`，可带端口和路径，未写协议 | 补 `http://` |
| 带点的域名加端口，未写协议（如 `test.corp.com:8080`） | 补 `https://`；`*.localhost` 补 `http://` |
| 完整的 `http://`／`https://` 地址 | 原样打开 |
| `javascript:`、`data:` 等其他协议 | 不在标签内打开 |
| 本机绝对路径 | 转为 `file://` 打开 |
| 含空格或不像网址的文字 | 用搜索引擎搜索 |
| 无法识别 | 标签内显示“请输入有效的 http(s) 或 localhost 地址”，不留白屏 |

补充说明：
- **搜索还是网址**：不含空格但带点的输入（如 `a.com`）视为网址，不带点的单词视为搜索词。
- **搜索引擎**：可选 Google、DuckDuckGo、Bing、Kagi，默认 Bing，在设置页修改。搜索词做 URL 编码，不写入日志。
- **哪些途径能打开本机文件**：用户在地址栏输入、Agent 的 `goto`／`tab create --url`、本机文件页里的链接。网页发起的跳转与重定向一律不能到达本机文件（R01.6）。

**R01.2 导航控制**
- 按钮：后退、前进、刷新、停止、强制刷新（绕过缓存）。加载中，刷新按钮变为“停止”；加载失败时，刷新等于重试。
- 快捷键（焦点在网页内时由宿主拦截，不能刷新或关闭 WillYou 本身）：
  - ⌘R 刷新；⌘W 关闭网页标签；⌘T 新建；⇧⌘T 重开最近关闭的标签；
  - ⌘F 页内查找；⌘L 聚焦地址栏；⌘[、⌘] 后退、前进。
- 焦点不在网页内时，App 菜单行为不变。
- 页内查找：⌘F 打开查找条，回车跳到下一个，⇧回车跳到上一个，Esc 关闭；显示“第 i / n 个”。

**R01.3 加载与页面信息**
- 显示加载中状态。
- 标题、图标、地址随跳转和重定向同步更新。
- 导航失败时，地址栏不保留失败的目标地址。

**R01.4 加载失败页**：按原因分类，显示中文提示，并附 Chromium 错误名。

| 类别 | 提示 | 恢复 |
| --- | --- | --- |
| 本地服务未启动 | `{主机:端口}` 上还没有服务在运行 | 轮询，服务起来后自动重新加载 |
| 连接被拒绝 | `{主机}` 拒绝连接 | 手动重试 |
| 域名解析失败 | 找不到 `{主机}` | 手动重试 |
| 离线 | 当前处于离线 | 网络恢复后自动重新加载 |
| 超时／连接中断 | `{主机}` 响应太久／连接被中断 | 手动重试 |
| 其他 | 无法访问 `{主机}` | 手动重试 |

Orca 的“被扩展拦截”“SSH 主机路由失败”两类不适用，不做。

**R01.5 证书错误**（与 Orca 不同：Orca 只允许本机地址继续访问）
- 证书错误页对任何主机都提供“继续访问”，并明确提示风险。
- 只有用户在界面上点击才能放行，Agent 无法放行。
- 放行按主机记在当前 profile 内，可在登录态管理里查看和撤销。
- 按例外访问的页面，地址栏显示“证书不受信任”图标。

**R01.6 弹窗、新窗口与外部应用**（对标 Orca 的弹窗与导航策略）
- `target=_blank` 和普通无名弹窗：在新网页标签中打开，沿用来源标签的 profile。
- 页面脚本在没有用户点击的情况下反复开新标签，超出预算后阻止并提示。
- 网页发起的导航或重定向指向 `file:` 时直接拦截。
- 自定义协议：弹出“是否用外部应用打开”提示，由用户决定。
- `javascript:`、`data:` 不弹提示：网页发起的 `data:` 顶层导航直接拦截；`javascript:` 链接按普通网页行为在页面内执行。
- **带名称的弹窗（`window.open` 指定了窗口名），以及 OAuth 等依赖 opener 的弹窗**：
  - 以独立小窗口打开，与来源页面属于同一任务、同一 profile；
  - 不进入网页标签栏；`tab list` 以 `kind: "popup"` 列出，带自己的 `browserPageId` 和 `openerPageId`；
  - Agent 可用 `--page` 观察和操作它；
  - 窗口关闭后，OAuth 回调经 opener 回到来源页面；
  - 来源页面关闭、所属任务被删除、所属 profile 被删除时，子窗口一并关闭；任务切到后台时，子窗口随来源页面一起隐藏。

**R01.7 下载**
- **位置**：保存到系统“下载”目录，不弹保存框。Agent 触发的下载同样保存在这里，结果里返回实际保存路径。
- **入口与浮层**：
  - 有下载记录时，工具栏显示“下载”按钮，下载进行中时按钮上带小圆点；
  - 新下载开始时，下载列表以浮层形式从按钮下方弹出，盖在网页上，不挤压网页；
  - 鼠标不在浮层上时，最后一次变化 6 秒后自动收起；点击浮层以外的任何位置、按 Esc 或点关闭按钮也立即收起；
  - 点按钮或菜单里的“下载”可再次打开。
- **每条下载的操作**：取消、打开、在文件夹中显示、移除记录。移除只删记录，不删文件。
- **文件名规则**（对标 Orca）：
  - 只取最后一段；
  - 去掉控制字符，`<>:"|?*` 替换为 `_`；
  - 去掉结尾的点和空格；空名用 `download`；
  - 同名文件追加 ` (n)`，最多尝试 1000 次。

**R01.8 HTTP 基本认证与站点权限**
- 基本认证：页面要求时，在浏览器区域弹出账号密码框，由用户填写；不自动提交，也不保存。取消后显示 401 页，可重新登录。
- 站点权限（摄像头、定位等）：弹提示由用户选择；允许或拒绝都按站点记在当前 profile 内，可查看和撤销。Agent 不能授予权限。

**R01.9 保存与恢复**
- 重启后恢复每个任务的网页标签列表、顺序、地址和当前标签；不恢复页面内状态（如表单内容）。
- 关闭的标签可以重开（最近 10 个）。
- 网页标签单独保存（每个任务一条记录），不写入、不改动 M9 文件标签记录。
- 关闭网页标签不影响终端进程和文件标签。

**R01.10 不纳入的 Orca 周边功能**：见 §2“不包含”。

**R01.11 新建标签页入口与启动页**（依据用户提供的 Codex 截图）
- **入口**：
  - 任务标题栏右侧有“新建标签页”按钮，快捷键 ⇧⌘B；点击后打开右侧工作区（未打开时先打开），并新建一个网页标签。
  - 只在有所属项目的任务里显示。
  - 焦点在本身就使用 ⇧⌘B 的编辑器里时（如 Pages 预览编辑），由编辑器优先响应。
  - 右侧工作区工具栏上的“新建网页标签”保留。
- **启动页**（新标签页的内容）：
  - “工具”区：只放“文件”（⌘P），点击切回文件视图。Codex 的终端、侧边聊天、新建页面属于 Codex 独有功能，不做。
  - “推荐”区：本项目最近访问过的网站，按访问时间从新到旧排列；同一网站只列一条，最多 8 个；不含搜索结果页，不跨项目，重启后仍保留，关闭标签不影响。点击在当前标签打开。没有访问记录时显示提示文字。

**R01.12 浏览器弹框的范围**
- 涉及的弹框：基本认证、跨任务授权与授权列表、登录态管理、Cookie 导入、浏览器设置。
- 遮罩只覆盖右侧浏览器区域（工具栏加网页），弹框在该区域内居中，大小随区域收缩。
- 左侧终端与侧栏不被遮挡，仍可操作。

**R01.13 浏览器设置**：默认搜索引擎；浏览器身份（R05.8，重启后生效）；下载位置说明；浏览器生成文件的占用空间与“清理全部浏览器文件”。

### 5.2 M12-R02 Agent Skill＋CLI 入口

**R02.1 CLI 入口**（P1 混合方案）
- Agent 在自己的受管终端里运行 `willyou-app browser <命令段…> --参数 值`，经 M11 网关鉴权：运行令牌、调用进程身份、运行计划放行。
- 不另建全局命令或令牌文件。
- 浏览器动作由 agent-browser 经每页 CDP 代理执行。

**R02.2 Skill**
- 内容：随每次运行生成的中文指南，包括：
  - 工作循环：`goto` → `snapshot` → 按引用操作 → 再 `snapshot`；
  - 引用规则：引用只属于一个标签页；导航、切换标签、收到 `BROWSER_STALE_REF` 后都要重新 `snapshot`；
  - 异步变化后用 `wait`，不用固定等待；
  - 多个页面时先 `tab list`，之后的命令都带 `--page`；
  - 标签只用 `tab` 专用命令管理；
  - 自定义输入框先 `focus` 再 `inserttext`；
  - 长文本用 `inserttext`；
  - 密码一律用 `--stdin`；
  - 错误恢复：R02.7 的错误码与 M11 网关错误码各自怎么处理；
  - 文件位置：截图等在任务数据目录，下载在系统“下载”目录；
  - `browser identity set` 影响全应用、需重启，非必要不用；
  - `intercept` 三条命令只记录；
  - 剪贴板是用户的系统剪贴板，只在用户要求时读写；
  - 不推荐 `--limit`；`wait` 最多 90 秒；
  - 外部 Chrome、Safari 或其他应用窗口不属于本 Skill（指向 F26）。
- 生成方式：WillYou 按本次运行放行的命令渲染 Skill，版本天然一致，不照搬 Orca 的“桩＋`skills get`”写法。

**R02.3 命令集**
- **总数**：对标 Orca 的 80 条（9 组：identity 2、nav 11、interact 25、tab 8、profile 7、cookie 3、capture 7、env 11、storage 6）：
  - `open-url` 不适用，不实现（单机上与 `tab create --url` 等价，用户已确认）；
  - 另新增 3 条：`wait fn`（R04.4）、`access request`（R06.3）、`operation get`（R06.2）；
  - **共实现 82 条，读 21、写 61**。
- **命名**：命令名、参数名沿用 Orca。统一改写如下：
  - `--worktree` 改为 `--task <任务ID>`；
  - 去掉 `--json`，输出总是 JSON；
  - Orca 中不带值的开关（`--focus`、`--reset`、`--show-profile`、`--secure`、`--httpOnly`、`--mobile`）一律写显式值，如 `--focus true`，因为 `willyou-app` 的每个参数都必须跟一个值。
- **参数规则**：
  - 不支持位置参数；
  - 参数值按 JSON 解析，`--value 123` 会被解析成数字；文本参数接受字符串、数字、布尔，宿主统一转成字符串；对象和数组报 `INVALID_INPUT`。
- **能力发现**：用全局 `willyou-app --list`。
- **逐条用法**：见[命令映射](技研/命令映射/README.md)（由脚本生成）。

**R02.4 输出**
- 总是 JSON。成功时返回结果字段；失败时返回错误码、说明和建议的恢复动作。
- 主要结果字段：
  - `snapshot`：`browserPageId`、`title`、`url`、`snapshot`（树文本）、`refs[]`（每项 `ref`、`role`、`name`；`ref` 为宿主分配的引用，见 R03.2）；
  - `tab list`：`tabs[]`，每项含 `index`、`browserPageId`、`active`、`title`、`url`、profile；子窗口另带 `kind`、`openerPageId`；
  - 截图、整页截图、PDF：文件信息（R03.4）。

**R02.5 目标与作用域**
- 命令默认作用于调用方任务的当前活动标签。任务归属由运行身份决定，不由当前目录推断。
- `--page` 指定同一任务内的某个页面。
- `--task` 指向同项目的其他任务，需要授权（R06.3）。
- 以下命令不针对单个页面：`tab list`、`tab create`、profile 管理、identity、`access request`、`operation get`。

**R02.6 元素引用**：见 R03.2。

**R02.7 错误码与退出码**

| 错误码 | 含义 | Agent 应当 |
| --- | --- | --- |
| `BROWSER_NO_TAB` | 当前任务没有打开的网页标签 | `tab create --url …` |
| `BROWSER_TAB_NOT_FOUND` | 指定页面不存在 | `tab list` 后重选 |
| `BROWSER_TAB_CLOSED` | 页面在执行中被关闭 | `tab list` 后重选或重建 |
| `BROWSER_STALE_REF` | 元素引用已失效 | 重新 `snapshot` |
| `BROWSER_TIMEOUT` | 等待条件或命令超时 | 看页面状态后调整，不盲目重试 |
| `BROWSER_PAUSED` | 用户已暂停 Agent | 停止重试，告知用户并等待恢复 |
| `BROWSER_UNAVAILABLE` | 浏览器能力当前不可用 | 向用户报告原因 |
| `BROWSER_EVAL_ERROR` | `eval` 脚本出错 | 读说明后修正脚本 |
| `BROWSER_TAB_CHANGED` | 执行期间页面被替换 | 重新 `snapshot` |
| `BROWSER_ERROR` | 其他错误 | 读说明处理 |

补充规则：
- 错误码一律大写，经 M11 网关的错误通道返回（原生 CLI 只接受大写，小写会被替换成 `INVALID_RESPONSE`）。浏览器失败不放进 `status: ok` 的结果里。
- **未开始与未知**：
  - 宿主把命令交给 agent-browser 之前的检查失败，记为**未开始**（`effectState: not-started`），退出码 2。这些检查包括：目标任务与页面、授权、暂停、引用身份、`exec` 白名单、参数与长度。
  - 命令交给 agent-browser 之后，失败可能为**未知**（`unknown`），退出码 5；写命令提交后断连也是这种情况。
  - 读命令一律为 `read-only`。
- M11 网关自己的错误码（如 `SCOPE_DENIED`、`ENTRY_NOT_ACTIVE`、`PERMISSION_DENIED`、`PEER_MISMATCH`）同样写进 Skill。

**R02.8 等待与超时**
- `wait` 默认 25 秒，`--timeout` 上限 90 秒，超出返回 `INVALID_INPUT`。
- 单条命令的宿主超时为 90 秒。
- M11 单次调用上限约 120 秒，不支持流式返回。
- 预算关系：宿主必须在“等待超时＋5 秒”内返回 `BROWSER_TIMEOUT`（最长 95 秒），始终早于网关的 120 秒，让 Agent 收到的是等待超时而不是通道断开。Orca 原本的“等待超时＋30 秒”余量与 90 秒上限叠加会达到网关上限，所以不沿用。

**R02.9 取消与终止**
- CLI 进程被终止时，宿主取消该条在途命令。
- 写命令已提交后断连，结果为未知，不自动重试。

**R02.10 同页串行**：同一页面的命令串行执行，不同页面可以并行。

**R02.11 `exec` 透传**
- `exec --command "<agent-browser 命令>"` 只放行[白名单](技研/命令映射/exec-allowlist.json)中的页面操作子命令，以及每个子命令列出的参数。
- 其他子命令，以及未列出的、以 `-` 开头的参数一律拒绝（`INVALID_INPUT`，未开始），agent-browser 不会被调用。
- 必须拒绝的负例：
  - 改变连接或会话的：`connect`、`batch`、`close`、`tab`、`session`；
  - 写磁盘或开服务的：`stream`、`auth`、`record`、`trace`、`profiler`、`state`、`inspect`、`chat`、`dashboard`、`install`、`upgrade`、`doctor`、`profiles`、`skills`；
  - 有专用命令负责交付文件的：`open`、`screenshot`、`pdf`、`download`、`network har`；
  - 全局参数：`--cdp`、`--session`、`--session-name`、`--provider`、`--executable-path`、`--profile`、`--args`、`--ignore-https-errors`、`--init-script`、`--extension`、`--proxy`、`--config`、`--allow-file-access`。
- 第二道防线：每页 CDP 代理只转发属于本页的请求，连不到其他页面、停放窗口或 WillYou 界面。

**R02.12 与终端的关系**：网页标签、终端、文件区互不重建对方的进程。浏览器能力由 M11 运行计划放行给本次任务（R06.1）。

### 5.3 M12-R03 页面观察与元素引用

**R03.1 `snapshot`**：返回当前页的无障碍树文本，并给可操作元素分配引用。`refs[]` 每项含 `ref`、`role`、`name`。

**R03.2 引用的生命周期、身份与绑定**
- **绝不能静默操作别的元素。** agent-browser 自己的引用（如 `@e4`）是按“角色＋名称”重新定位的：按钮被换成同名新按钮后，旧引用会点中新按钮（E4 实测）。而且不同页面都会产生 `@e4`，只凭它分不出来源（review3 F02）。所以 Agent 拿到的是**宿主分配的引用**，宿主再把它翻译成内部动作。
- **引用格式与有效范围**：
  - 引用形如 `@k2s3e4`：带页面短码、该页快照代际和序号，由宿主生成，Skill 说明引用是不透明字符串、原样传回。
  - 只有某页**最新一次** `snapshot` 的引用有效。同页再次 `snapshot`、导航、页面关闭后，旧引用一律返回 `BROWSER_STALE_REF`。
  - 引用与 `--page` 不一致（例如把 A 页的引用用到 B 页）返回 `BROWSER_STALE_REF`。
- **快照时绑定（防止“快照到绑定之间”页面被替换，review3 F01 窗口一）**：宿主先经该页 CDP 读一次无障碍树，再让 agent-browser 做快照，然后再读一次；只有两次读到的节点编号（`backendDOMNodeId`）相同的元素才绑定为可用引用。连续变化的元素，最多重试 2 次，仍在变化就标为不可用，对它的动作返回 `BROWSER_STALE_REF`。
- **动作时绑定（防止“核对通过到真正点击之间”被替换，review3 F01 窗口二）**：
  1. 带引用的动作执行前，宿主再查一次节点编号，不一致就返回 `BROWSER_STALE_REF`，不发出动作。
  2. 一致时，宿主给该节点设一个一次性属性 `data-willyou-ref=<随机值>`，让 agent-browser 按这个属性选择器执行动作，动作结束后删除属性。若节点在两步之间被替换，新节点没有这个属性，agent-browser 找不到目标，宿主返回 `BROWSER_STALE_REF`，而不会点到新节点（E4c 实测）。
  3. 属性选择器够不到的位置（封闭的 Shadow DOM、跨站 iframe）：宿主改为自己经 CDP 对已核对的节点执行动作（滚入视野、取位置、发送输入），发送前最后核对一次节点编号。这条后备路径的剩余窗口与正确性由 S1 红测验证，未通过前不能宣称这两类位置满足本条。
- agent-browser 的报错 `unknown ref`、`ref not found`、`element not found`、`Could not locate element with role=` 一律归为 `BROWSER_STALE_REF`。agent-browser 版本固定，这些报错文字与绑定流程都有合同测试，升级时必须重跑。

**R03.3 覆盖范围**：iframe（含跨站）与 Shadow DOM（含封闭）里的元素也要列进快照，并可操作。每页 CDP 代理下的验证见 S1。

**R03.4 `screenshot` 与大结果**
- `screenshot`（`--format png|jpeg`）存成文件，返回路径、格式、宽高、字节数、SHA-256，不内嵌 Base64。文件保存在任务数据目录，随任务删除。
- 文本类结果（`snapshot`、`console`、`network`、`get`、`eval` 等）序列化后不超过 512KB 时直接返回；超过时写成文件，返回路径和前 4KB 预览。

**R03.5 `full-screenshot`**：整页截图，交付方式同 R03.4。

**R03.6 `pdf`**：导出当前页为 PDF，包含背景，并尊重页面 CSS 指定的页面尺寸；交付方式同 R03.4。

**R03.7 `eval`**
- `--expression <JS>` 在页面上下文执行，等待 Promise。返回值转换：对象转为 JSON 字符串，原始值转为字符串，没有返回值时给出说明文字；结果带 `origin`（当前页地址）。
- 出错返回 `BROWSER_EVAL_ERROR`；执行期间页面被替换返回 `BROWSER_TAB_CHANGED`；取消时终止页面内的执行。
- `eval` 是写命令。

**R03.8 读取类命令**：`get --what <text|html|value|url|title|count|box> [--element]`、`is --what <visible|enabled|checked> --element`，不改变页面。

**R03.9 超时、稳定性与长输入**
- 单条命令的宿主超时为 90 秒；同一页面连续 3 次超时后，重建该页的 agent-browser 会话；同一页面的命令串行执行（R02.10）。
- `type --input`：逐键输入，每次最多 16384 个字符。
  - 宿主按每块 2000 个字符依次执行；回执记录 `confirmedChars`（已确认完成的字符数）和 `inFlight`（正在执行的那一块的起点和长度）；
  - 超过上限返回 `INVALID_INPUT`（未开始），提示改用 `inserttext`；
  - 中途失败时结果为未知。页面实际字数只能确定在 `confirmedChars` 到 `confirmedChars＋inFlight 长度` 之间；目标元素可读时，宿主再读一次实际值，记为 `observedChars`（附读取时间）。Skill 要求先 `get value` 核对，不重发整段（review3 F03）。
- 依据：E4 实测逐键输入越长越慢，65536 个字符失败；`inserttext` 写 65536 个字符约 10ms。
- 单次 CLI 请求最大 256KB（含 `--stdin` 读入的内容）；宿主内部的剪贴板文本上限为 16MB。

**R03.10 状态外显**：只做活动标记，不画动画光标（O15，见 R07.2）。

### 5.4 M12-R04 交互、等待与取证

**R04.1 点击与指针**：`click`、`dblclick`、`hover`、`drag --from --to`、`scrollintoview`、`scroll --direction [--amount]`、`highlight`、`mouse move|down|up|wheel`。成功只返回简短确认，不附带动作后的页面状态；Agent 需要再次 `snapshot`。

**R04.2 输入**
- 命令：`fill`（含 contenteditable）、`type --input`、`inserttext`、`keypress`、`clear`、`select-all`、`focus`、`select`、`check`、`uncheck`。
- `type` 的上限与分块见 R03.9；长文本用 `inserttext`。
- 敏感值（密码等）用 `--stdin <字段>` 从标准输入读取，如 `fill … --stdin value`。

**R04.3 `find`**
- `find --locator --value --action [--text]`。
- locator 可选：`role`（可配 `--name`、`--exact`）、`text`、`label`、`placeholder`、`alt`、`title`、`testid`、`first`、`last`、`nth`。
- action 可选：`click`、`fill`、`type`、`hover`、`focus`、`check`、`uncheck`。
- 已知限制，写入 Skill：不进入 iframe；`nth … focus` 不可用。

**R04.4 等待**
- `wait`（读）：条件为 `--selector`、`--text`、`--url`、`--load`、`--state hidden|visible`，可以组合；`--timeout` 见 R02.8；满足时返回 `{waited:true}`，超时返回 `BROWSER_TIMEOUT` 并说明等了多久。**不接受 `--fn`。**
- `wait fn --fn <js> [--timeout]`（写）：条件脚本可能修改页面，并且会被反复执行（E4 实测），所以单独作为写命令，不自动重试；只有“观察”授权时拒绝执行。

**R04.5 上传与下载**：`upload --element --files`、`download --selector --path`。路径不限制（O7）；`download` 返回实际保存路径。

**R04.6 对话框**：`dialog accept [--text]`、`dialog dismiss`。

**R04.7 取证**
- `console`、`network`：读取记录；接收 `--limit` 但忽略。
- `capture start`／`stop`：录制 HAR，存成文件。
- `intercept enable|disable|list`：只记录，不阻断、不改写；`enable` 传入多个模式时只使用第一个，其余忽略，并在结果里说明（对标 Orca，Skill 写明）；`list` 读取的是网络请求记录；实测匹配的请求照常完成。经 `exec` 的 `network route --abort` 可以阻断请求，所以 Skill 只说“这三条命令只记录”，不说“无法阻断”。

**R04.8 约束**：所有交互命令受同页串行（R02.10）、取消（R02.9）、错误码（R02.7）约束。

**R04.9 不做动作后回读**：对标 Orca，动作只返回确认，由 Agent 自己再观察。旧引用误点的风险由 R03.2 的身份校验解决。

### 5.5 M12-R05 登录态与环境隔离

**R05.1 profile 模型**
- 每个 profile 独立保存 Cookie、localStorage、缓存，互不泄漏，存在各自的持久分区中，重启后保留。
- 字段：`id`、`scope`、`label`、来源（手动或导入）、所有者（项目或任务）。

**R05.2 profile 命令**
- 7 条：`tab profile list`、`create --label [--scope isolated|imported]`、`delete`、`set (--page | --task) --profile`、`show`、`use-default`、`clone`（复制一个 profile，**包含登录态**）。
- 另外，`tab create --profile` 可以在新建标签时指定 profile。
- 页面绑定 profile 后，该页面上的命令都使用它的登录态。

**R05.3 归属**
- 每个项目一个项目 profile，在第一次打开网页时自动创建；同一项目的任务共用它，不同项目互相隔离。
- 任务需要的账号与项目登录态不同时，Agent 为该任务新建独立 profile 登录，不改动项目登录态（C1）。
- `use-default` 把页面切回当前项目的 profile。

**R05.4 Cookie 导入的来源与范围**
- 来源只支持 Chrome 与 Edge。读取方式：经 macOS 钥匙串（`Chrome Safe Storage`／`Microsoft Edge Safe Storage`，会弹授权窗，30 秒超时）取得口令，再解密 Cookie 库。
- 导入所选浏览器 profile 的全部 Cookie，只排除 Google（`google.com` 及子域，以及设备绑定的会话 Cookie）。没有域名选择。
- **按域名整体替换**（对标 Orca `browser-cookie-import-clear.ts`）：目标 profile 中，属于导入范围内域名的现有 Cookie 先全部移除，再写入导入的 Cookie；同一域名下目标原有、来源没有的 Cookie 也会被移除。不在导入范围内的站点不受影响。R1.0 曾误写为“只替换出现的 Cookie”，按源码更正。
- 导入默认进入当前项目的 profile。流程与失败恢复见 R06.4。

**R05.5 Cookie 命令**：`cookie get [--url]`、`cookie set --name --value [--domain --path --secure true --httpOnly true --sameSite --expires]`、`cookie delete`。`cookie get` 返回明文 value（O11）。

**R05.6 存储命令**：`storage local|session get|set|clear`，作用于当前页面的来源。

**R05.7 环境模拟**
- `viewport --width --height [--scale] [--mobile true]`
- `geolocation`
- `set device`
- `set offline`
- `set headers`
- `set credentials --user`：密码用 `--stdin pass` 传入；`--pass` 保留但 Skill 不推荐
- `set media`
- `clipboard read`、`clipboard write`：读写的是用户的系统剪贴板（O17）

**R05.8 浏览器身份**
- `browser identity get|set --mode clean|native [--reset true]`，作用于整个应用，重启后生效。
- `clean`：兼容导入的登录态。
- `native`：部分 Cloudflare 保护的站点需要，但 Google 登录不可用。

**R05.9 删除**

| 操作 | 处理 |
| --- | --- |
| 删除任务 profile | 正在使用它的页面先切回项目 profile 并重新加载，再清空它的存储、缓存和站点设置 |
| 删除项目 profile | 不允许 |
| 删除任务 | 一并删除它的任务 profile 和网页标签记录 |
| 删除项目 | 删除项目 profile 及其下所有任务 profile |
| 任务只是结束 | 全部保留 |

**R05.10 profile 的归属检查**
- 宿主按运行身份给出的调用方任务和项目，判断可见的 profile：项目 profile、调用方任务的 profile，以及经授权的其他任务的 profile。
- 所有带 `--profile` 的命令和 `tab profile list` 只接受、只列出可见范围内的 profile。范围外的一律返回 `SCOPE_DENIED`，不区分“不存在”和“无权”。
- `clone` 只能复制可见范围内的 profile，结果归调用方任务；`create` 的结果归调用方任务，`--scope imported` 只建空 profile（导入 Cookie 只能由用户在界面完成）。
- 任务 profile 只有其所有者任务，或持有 control 授权的任务可以删除。

### 5.6 M12-R06 授权与安全边界

**R06.1 浏览器作为 M11 的一个应用**
- `appId` 为 `browser`，实现为受信模块（无连接）。
- 每条命令是一个能力，标识为 `browser.<组>.<命令>`，带输入、输出 JSON 契约（由脚本生成）。
- 项目选用该应用后，运行计划才放行；未选用时调用得到 `ENTRY_NOT_ACTIVE`／`SCOPE_DENIED`。
- 新项目默认选用；升级前已有的项目不自动开启，提示用户自行开启。

**R06.2 读写语义与回执**
- **读（21 条，`safe-read`，可有界重试）**：`browser identity get`、`snapshot`、`screenshot`、`full-screenshot`、`pdf`、`wait`、`get`、`is`、`console`、`network`、`tab list`、`tab show`、`tab current`、`tab profile list`、`tab profile show`、`cookie get`、`storage local get`、`storage session get`、`intercept list`、`clipboard read`、`operation get`。
- **写（61 条）**：其余全部，包括 `eval`、`exec`、`wait fn`、`access request`。写命令一律带 `operation-receipt` 保护，不自动重试，不逐次审批（D4）。不归为 `external-write`，但这不等于这些动作没有外部影响。
- **回执**：
  - 宿主按（运行，`requestId`）持久保存每条写命令的状态（已受理、执行中、成功、失败、未知）、结果摘要和进度，保留 7 天；
  - `willyou-app` 在“已发出、未返回”时输出 `requestId`（M12-D03）；
  - `operation get --request <requestId>` 只能在同一运行内查询，返回 `succeeded`／`failed`／`unknown`／`not-found`；
  - App 重启或运行结束后，新运行查询旧请求返回 `not-found`，历史在界面的活动记录里查看；
  - 结果为 `unknown` 时 Agent 不得重发，先观察页面再决定。

**R06.3 跨任务授权**
- 默认只能操作调用方自己任务的页面。`--task` 等于自己的任务时，视同省略。
- **申请**：`access request --task <任务> --mode observe|control`。
  - 宿主只检查：目标任务存在、与调用方同项目、不是调用方自己；不要求已有授权。检查通过后在界面弹窗，由用户允许或拒绝。
  - 60 秒无人处理按拒绝处理。跨项目申请直接返回 `SCOPE_DENIED`，不弹窗。
- **授权范围**：绑定当前运行，限定目标任务与模式；运行结束、终端退出、用户撤销时立即失效，不持久化，新运行不能沿用。
- **使用**：
  - 带 `--task` 的命令需要持有该任务的授权，否则返回 `SCOPE_DENIED`；
  - observe 只放行读命令，写命令和 `wait fn` 都拒绝；
  - 命令执行前再检查一次授权，撤销后已排队的命令返回 `SCOPE_DENIED`；
  - 审计记录标明授权来源。
- 无人值守（M13）时无法弹窗，默认拒绝，见 R08.4。

**R06.4 Cookie 导入流程**（只在界面中进行，Agent 没有入口）
1. 入口：浏览器菜单或登录态管理，选择目标 profile，默认当前项目的 profile。
2. 选择来源：本机已安装的 Chrome、Edge，以及其中的某个 profile。
3. 风险确认（必须）：说明将导入全部 Cookie（Google 除外）、Agent 能读取这些站点的会话令牌、系统会请求钥匙串授权，用户点确认后才继续。
4. 系统钥匙串弹窗，30 秒超时。拒绝或超时即失败，不写入任何 Cookie。
5. 导入与恢复：
   - 先把来源全部读出、解密、逐条校验，任何一步失败都不开始写入；
   - 写入前生成完整变更集：导入范围内将被移除的每个现有 Cookie 的原值，每个将写入的 (name, domain, path) 的原值或“原本不存在”，以及新值；用 `safeStorage` 加密后写日志，文件权限 0600，先写临时文件、`fsync` 后改名；
   - 写入中途失败当场恢复；进程中断则在下次启动、任何页面使用该 profile 之前恢复。恢复规则：被移除的原 Cookie 写回、新写入的撤销，但**页面优先**：从开始写入到恢复结束，宿主监听该 profile 的 Cookie 变化事件，凡是页面在此期间改写或删除过的 (name, domain, path)，恢复结束后按页面最后一次的结果重新应用并列为冲突，不让旧值覆盖页面期间的登录或登出（review3 F04）；
   - 恢复失败时，该 profile 标为“需要处理”，使用它的页面显示提示，Agent 命令返回 `BROWSER_UNAVAILABLE`，日志保留。用户在登录态管理里可以：**重试恢复**；或**清空该 profile 的登录态**（需确认，清空 Cookie、存储与缓存后恢复可用，项目 profile 也可清空但不能删除）。处理完成前，该 profile 不能再次导入；
   - 同一 profile 同时只允许一次导入；导入期间不能删除该 profile，`tab profile delete` 返回 `RESOURCE_BUSY`；页面自身的 Cookie 读写不受阻。
6. 结果摘要：总数、已导入、已跳过、跳过的 Google 数、保留数、冲突数、涉及域名。
7. 失败原因分为：钥匙串被拒、超时、找不到浏览器或其 profile、Cookie 库无法读取、无法解密（`cookies-undecryptable`）、其他。
8. 导入完成后给出通知。

**R06.5 脱敏**
- 活动记录与诊断日志对以下内容只记“已脱敏”和长度：`set credentials` 的密码、`cookie set` 与 `storage set` 的值、密码框的 `fill` 值、认证类请求头、`cookie get` 返回的 value。
- 完整内容只出现在本次命令的返回中。

**R06.6 审计**
- 每条浏览器命令记录：运行、任务、页面、命令名、状态（成功、失败、未知、未开始）、耗时；截图等记录文件路径。
- 授权请求与 Cookie 导入分别记录发起者、时间、结果。

**R06.7 本阶段不覆盖**：域名白名单／黑名单、写操作逐次审批、上传下载路径限制（D4、O7，见 §6）；Windows、Linux 的 CLI 身份实现（D1）。

### 5.7 M12-R07 用户与 Agent 共用页面

**R07.1 同一个页面**：Agent 操作的就是用户在右侧工作区看到的网页标签和同一个 profile。Agent 新建的标签立即出现在该任务的标签栏。

**R07.2 活动标记**
- 页面被 Agent 驱动期间，标签显示标记，页面边框发光。
- 最后一条命令结束后保持 20 秒再清除。
- 状态由主进程决定，界面只负责显示。不画动画光标。

**R07.3 Agent 光标**：不做（O15）。

**R07.4 “先显示、再操作”的握手**：随光标一起不做，因此没有额外延迟。

**R07.5 切换任务与后台页面**
- 页面由主进程持有，按任务常驻。切换任务、收起工作区、关闭文件面板都不销毁页面，也不中断在途命令。
- 任务切到后台时，页面移入停放窗口：已显示但完全透明、不可聚焦、不接收鼠标、不出现在任务栏和窗口菜单。页面保持原尺寸继续绘制，切回时再挂回右侧工作区。这样做是因为页面不绘制时点击会变慢、截图会卡住。
- 用户看不到、也点不到停放窗口。Agent 只能看到目标页面，看不到停放窗口和 WillYou 界面。

**R07.6 暂停**
- 本任务的页面被 Agent 驱动时，工具栏显示“暂停 Agent”，暂停后改为“恢复 Agent”。
- 暂停作用于该任务的全部网页标签，包括经授权从其他任务过来的命令。
- 暂停时：
  - 清空待执行队列，排队的命令立即返回 `BROWSER_PAUSED`；
  - 之后到达的命令同样返回 `BROWSER_PAUSED`；
  - 正在执行的写命令执行完当前这一条；
  - 正在进行的只读等待立即结束，返回 `BROWSER_PAUSED`；
  - 命令执行前再检查一次暂停状态。
- 暂停只在本次运行内有效，运行结束、终端退出、App 重启即清除。
- 暂停期间用户可以手动操作页面，完成后点“恢复 Agent”。不做“请求用户接管”命令。

**R07.7 停止**
- 停止任务、终止终端或 CLI 进程时，宿主取消在途命令。页面保持当前状态，不回滚、不关闭。
- 活动标记按 R07.2 清除，跨任务授权随运行结束失效。

**R07.8 不抢焦点**：`tab create` 新建的标签默认**不成为该任务的当前标签**；`tab create`、`tab switch` 都不把用户的界面切走；`tab switch --focus true` 才切换右侧工作区。

**R07.9 需要用户处理的提示**
- 基本认证、站点权限、外部应用、证书错误都由用户处理，Agent 不能代答；JS 对话框除外，用 `dialog` 命令处理。
- 等待用户处理期间，命令按超时规则返回 `BROWSER_TIMEOUT`；Skill 要求 Agent 告知用户“页面在等待你处理”。

### 5.8 M12-R08 与禅道流程衔接

**R08.1 复现并验证 Bug**
1. 用户要求 Agent 处理某个 Bug。
2. Agent 用 M10 的禅道只读能力读取 Bug：`work_list`（列表）、`object_get`（详情，`fields` 含 `os`、`browser`、`hardware`、`openedBuild`、`product`、`module`、`severity` 等）、`resource`（分块读取正文、历史、附件）。
3. 从重现步骤正文或自定义字段中找出环境地址和测试账号。没有固定字段（O16）；找不到或有歧义时停下来问用户，不猜。
4. 在项目 profile 中打开环境：
   - 需要登录且 Bug 写明了密码时，Agent 用 `--stdin` 自己登录（C2，应用不保存密码）；
   - 没写密码时，由用户先暂停 Agent 再手动登录，或使用已导入的登录态；
   - 登录后，Agent 用 `snapshot` 核对页面上的账号与 Bug 一致；
   - 账号与项目登录态不同时，为本任务新建独立 profile 再登录，不在项目 profile 里换号。
5. 按重现步骤执行，用 `screenshot`、`console`、`network`、`capture` 取证。
6. 复现成功：在终端分析并修复。未复现：见 R08.2。
7. 修复后，在同一 profile 按同样步骤再验证一次并取证。本机服务由 Agent 重启后验证；共享环境需用户先部署。
8. 向用户报告：结论、环境、账号、步骤、证据路径。

**R08.2 未复现**
- M10 禅道只读，Agent 不能在禅道里打回、备注或附证据。
- Agent 产出一份未复现说明，内容包括：环境、版本、账号、步骤、实际结果、证据路径。说明放在会话里，由用户自己到禅道操作。
- 本阶段不预留禅道写接口，也不做占位命令。

**R08.3 SOP**
- 浏览器应用提供“复现 Bug” SOP，内容为 R08.1 的步骤与注意事项。
- M11 的 Skill 模板只能写本应用自己的调用方式，所以 SOP 用文字引导 Agent 使用会话中的禅道 Skill；禅道未选用时，请用户提供环境与账号。

**R08.4 与 M13 的衔接约束**（本阶段只记录，不实现）
- 无人值守时：
  - 登录过期只能靠 Bug 写明的密码重新登录；Bug 没写密码时，任务失败并报告原因；
  - 跨任务授权默认拒绝；
  - 暂停不会发生；
  - 后台页面必须继续工作；
  - Cookie 导入、权限、证书例外都需要用户事先在界面准备好。

**R08.5 验收夹具**
- 用本地测试站点和合成 Bug 数据，覆盖六条路径：复现成功、未复现、环境缺失要询问、需要用户登录、账号不一致、修复后验证。
- 真实禅道只做只读读取。

## 6. 已接受的风险

以下为用户决定对标 Orca、不做限制的部分。验收只核对行为与 Skill 说明一致；以后如需护栏，作为独立需求追加。

| 编号 | 风险 | 缓解 |
| --- | --- | --- |
| D4 | Agent 可以导航到任意地址（包括误开的生产环境）；页面内的点击、提交、删除没有二次确认 | Skill 文字约束、profile 隔离、暂停（R07.6）、停止（R07.7） |
| O7 | Agent 可以把本机任意可读文件（如 `~/.ssh`、浏览器登录数据、项目外文档）上传到任意网站，也可以把下载写到任意路径；被网页内容诱导时尤其危险 | 同上 |
| O11 | 导入的全部站点会话令牌 Agent 都能用 `cookie get` 读到明文 | 导入前的风险确认；只有用户能发起导入 |
| O12 | Agent 可以改变全应用的浏览器身份 | 重启后才生效；Skill 写明非必要不用 |
| O17 | Agent 可以读写用户的系统剪贴板 | Skill 写明只在用户要求时读写 |

## 7. 验收条件

全部约定用例见[测试用例](验收/测试用例.md)，各用例标明了对应的需求条目。核心要求：
- 能打开并操作真实页面；
- Agent 能完成“打开 → 复用登录态 → 观察 → 操作 → 等待 → 取证”的闭环；
- 旧引用不会误点；
- 不同 profile、不同项目的登录态互相隔离；
- 重启后标签和登录态按设计保留；
- Cookie 导入、证书放行、站点权限只能由用户在界面完成；
- 跨任务操作须弹窗批准，且只限同一项目；
- 暂停后命令返回 `BROWSER_PAUSED`，排队的命令零执行；
- 错误码与退出码原样经过真实原生 CLI；
- 未复现时只产出说明，不写入禅道。
