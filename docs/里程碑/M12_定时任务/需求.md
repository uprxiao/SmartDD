# M12：定时任务需求

阶段资料入口：[README](README.md)。需求、调研、原型、技研、验收及交付按本阶段目录归档。

更新日期：2026-11-01（原始需求初稿：2026-10-16）。需求来源：[需求池 F16](../../需求池.md)。状态：阶段主题已确认；独立需求初稿待细化，正式调度未实现。现有时钟入口和占位样式来自 M6，不代表定时任务已交付。

本文是 M12 具体需求的维护入口，后续原型、技研和交付验收据此展开。

## 1. 目标与范围

用户为项目任务指定执行时间或周期，系统按计划选择项目、代码目录和 AI 配置运行任务，并提供可追溯的结果。复用已有 CLI、Skill、任务历史与终端，不另建一套项目和 AI 配置体系。

## 2. 需求项

| 编号 | 需求 | 已记录行为与需要展开的规则 |
| --- | --- | --- |
| M12-R01 | 创建和编辑计划 | 名称、项目／目录、AI 配置、任务说明、执行时间／周期和时区；字段校验和周期类型待设计 |
| M12-R02 | 管理计划 | 查看计划及下一次执行时间，暂停、恢复、删除；变更对已开始执行的影响需明确 |
| M12-R03 | 调度与执行 | 到时使用正确的项目及配置发起真实任务；避免错误归属和重复触发 |
| M12-R04 | 运行记录 | 展示触发时间、运行状态、对应任务入口、结果或失败原因；每次运行与计划关联 |
| M12-R05 | 异常与恢复 | 应用退出、电脑睡眠、错过时间、配置不可用、重叠执行、失败重试和时区变化有明确策略 |
| M12-R06 | 提示与操作边界 | 无人值守时允许的行为、需用户处理的情况及通知方式在评审前定案 |

核心流程：配置计划 → 校验并保存 → 展示下次执行时间 → 到时触发 → 关联实际任务 → 查看结果／失败原因 → 按规则继续、暂停或重试。

计划状态与运行状态分开：计划的启用／暂停不等于某次运行的等待／运行／成功／失败。具体状态枚举、取消语义和恢复机制在技研后与需求同步定稿。

## 3. 待定业务规则

- 首版时间规则：一次性与重复周期支持哪些，时区与夏令时如何解释。
- 应用关闭、睡眠及错过执行时是补跑、跳过还是等待确认；当前未承诺应用退出后仍执行。
- 同计划前次未结束、多个计划同时触发、配置被改动／删除时的处理。
- 自动重试次数、重复执行防护、记录保留与通知；计划删除是否保留历史。
- CLI、凭据和外部操作的可用条件；M10 的禅道／邮件能力按最终联动规则调用；Jenkins 不作为本阶段前置要求。

## 4. 验收目标

按最终规则验证准确触发、项目／配置归属、下一次时间、暂停／恢复／删除、重启、睡眠／错过时间、重叠与重试，以及记录与实际任务对应。正常和异常用例均需明确前置时间、操作及可判定结果，不能只检查计划列表能显示。
