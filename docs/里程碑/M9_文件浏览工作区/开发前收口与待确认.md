## 2. 产品决定：D01 与 D07 均已确认，待决 0 项

### D01：终端与文件视图独立（2026-10-17 用户确认）

用户原意：“右侧的文档区域基本就是‘是啥就是啥’，打开的时候直接读取磁盘上最新的文件”；终端生成文件，目录刷新后即可看到，二者没有专门的修改审批关联。这不是对原 A/B 候选的选择，而是纠正了候选中额外添加的审阅链。

当前规则唯一依据为[需求 R07.5、R07.14、R07.19 与 D01](需求.md)：终端 CLI 按自身权限、批准模式及用户指令直接操作文件；WillYou 不额外设置 AI 修改审批。右侧打开时重新读取磁盘，目录刷新/监听更新新增、修改与删除；已打开且无未保存编辑的内容同步重读。只有右侧存在未保存手工编辑时，保留普通文件冲突保护，避免静默丢稿；这不是要求批准终端已经发生的写入。

文件/选区引用仍可插入终端输入（不自动回车），插入结果仅表示上下文交接，不跟踪 CLI 任务完成，不按变化归因修改者，不进入“保留/还原”专用流程。右侧能展示的根与文件仍按文件工作区自己的授权范围；不把终端“可操作文件”解读为应用突破系统权限。

`@路径` 与图像输入兼容性仍由工程实测，不额外变成用户决策。图片加入输入属于既有完整范围，不能用路径文本冒充图片附件；真实适配、失败/取消和不支持状态仍须与 V05/V06 对应。

### R05.14：拖文件到终端插入完整路径（2026-10-17 用户追加确认）

核对现有代码：只有复制完整路径、相对路径上下文托盘及文件标签排序，缺少“文件→终端输入区”的拖放。本轮纳入 M9 需求及合成原型：文件树条目/已打开文件拖到当前终端，直接插入完整绝对路径；图片同样只插路径，不上传附件，不读取整份内容。已有输入保留，路径后可继续语音/打字，由用户自行提交；拖放不自动回车、不启动任务。入口与实现约束见[需求 R05.14](需求.md)，新增正式用例 Y33–Y40；现为425条/23组、102个子需求，全部正式用例未执行。

这项属于用户本轮明确提出的范围增量，不再另列待选择。它与 V05/V06 的真正图像附件是不同操作；拖路径无需等待图像通道。接续时不得以“有托盘/复制路径”误称已经满足拖放。

### D07：仅本机文件工作区（2026-10-17 用户确认 A）

用户明确：“我现在规划的文件区都是本地的，就跟 IDE 一样，只看本地文件就可以”“只是做本地文件就行……就是你的 A”。因此本期采用左侧终端、右侧本地文件树/文件查看器：本地浏览、搜索、各种格式渲染、已约定的编辑保存、磁盘同步和拖本机完整路径均保留。

本期不接 SSH/SFTP 远程文件树、远程读取/搜索/编辑/保存/监听，不自动挂载、下载或同步服务器目录。原有终端可以按自己的权限和指令操作资源，但不会自动改变右侧文件区的本地范围。若未来需要远程文件工作区，保留在需求池 F22-A 的后续边界，未分配新 M，重新确定范围；不把它设为本期前置。

远程研究和稳定编号保留，纯远程用例列“用户确认后续，非本期”；混合用例只执行本地与拒绝非本地来源的分支。实际结果仍是未执行，后续项不算通过、不进入本期完成率。具体统计以[用例索引](验收/用例覆盖索引.json)及[范围映射](验收/需求与用例映射.md)为准。

先前 A/B/C 的选择已结束，不能继续向用户重复询问远程范围。**两个产品决定已完成，并不表示所有开发前原型/技研工作已完成。** 下面仍由工程继续处理本期适用项，达到可评审条件后再交整体设计确认。
