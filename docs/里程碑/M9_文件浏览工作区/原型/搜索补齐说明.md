## 2. 模块接口与候选边界

```js
const rows = rankFileCandidates(query, mockSessionCandidates);
// 保留候选原字段，并给出：
// file_name, score, indices, fragments, matched, matchMode, longPattern?
```

候选需为对象数组。`file_name`优先，其次适配原型用的`label`，最后从`path`取最后一个正/反斜杠分量。显式`file_name`不会被路径替换。结果是新对象，不修改输入或原生`score/indices`数组。

| 字段/规则 | 合同 |
| --- | --- |
| score | 非匹配0；匹配至少1；空query0。非空query按score降序、原始大小写file_name的JS码元序、原index排序 |
| indices | **本次独立basename matcher的UTF-16位置**；不是原生相对路径的indices。不能用这些位置直接标亮含目录的整条路径 |
| fragments | `{start,end}`半开区间，UTF-16；供原型标亮和测试，不属于已证实的原RPC响应扩展 |
| matched | 当前basename matcher是否命中；wildcard-only可命中但indices为空 |
| matchMode | `primary`、`path-basename-fallback`、`none`或`empty`；用于原型诊断，不应当作产品界面常驻技术字段 |
| longPattern | 实际命中的pattern是否超过100单位并走简单匹配降级；不是原始query的独立长度限制 |
| 零分 | 保留，不能在排序后用`score>0`再筛掉；原生路径命中但basename未命中的候选仍可能有意义 |
| 候选生成 | 不在此模块内。未遍历文件系统、不接RPC、不过滤`.git`等目录、不设置候选上限、不模拟原生nucleo的完整路径权重 |
| 空query | 保留输入次序。界面应回普通目录树，不能将空query评分结果当原目录排序 |

原型接入必须分两步：先由**明确标为mock的候选提供器**决定输入集合，再调用本模块重排。若先用本模块`matched`生成候选，再重排，会错误丢掉路径命中的零分文件；若直接把所有`FILES`都当非空搜索候选，则不匹配的文件也全部出现。两种做法都不能被称为真实搜索。现有路径段排除规则应保留在候选适配层，保持普通树包含隐藏文件/依赖目录、文件名搜索排除指定段的差别。

## 4. 树与搜索键盘状态模型

下表是给界面接入者的状态转移合同，不把缺少的UI代码藏在评分器内。应分开维护`focusedPath`、`selectedPaths`、`anchorPath`、`expandedPaths`和当前可见rows；不能让“文件已打开”同时代表焦点、范围选择和菜单target。每个值要包含root/task scope，收起目录或改变query后以可见rows重新校正。

| 输入 | 静态已确认的树行为 | 当前原型/接入要求 |
| --- | --- | --- |
| ↑↓、Home/End | 只移动可见项焦点 | 原型已有基本移动；需保持focused状态和滚动可见，不依赖每行永久Tab可达 |
| → | 当前目录未展开则展开；已展开目录或文件则移下一可见项 | 原型只对目录设置expanded，已展开目录/文件不会前进 |
| ← | 已展开目录则收起；其他项聚焦父节点 | 原型只有目录收起，叶文件和已折叠目录不回父级 |
| Shift+↑↓ | 从anchor扩展可见范围选择并移动焦点 | 原型仅普通箭头移动，未扩选 |
| Ctrl/Meta+Space | toggle focused selection | 原型未专门处理，会落入原生button点击，可能错误单选/打开 |
| Ctrl/Meta+A | selectAllVisiblePaths，含目录；宿主打开回调只处理首个文件 | 原型过滤掉目录；不要因此引入批量文件操作 |
| Shift+点击 | 可见范围与anchor计算，库支持modifier组合 | 原型范围只保留文件；切query/root/task后旧anchor未校正 |
| Ctrl/Meta+点击 | toggle selection | 原型已有文件toggle，目录点击始终展开/收起；与库统一选择模型有差异 |
| Enter/普通Space | 目标宿主没有明确的完整专门keydown分支，受DOM默认激活影响 | 原型显式Enter固定标签属于当前设计，不能宣称已静态证实目标同样固定；须保留动态未确认 |
| F2／字符即搜索 | 宿主renaming未开启、tree search:false | 不接F2重命名、不恢复库自己的typeahead；使用独立文件名框 |
| ContextMenu/Shift+F10 | 库自己的条件菜单与宿主外层菜单有边界 | 运行行为未确认；若原型补键盘菜单，应标为原型可访问性设计，并验证焦点返回 |
| 文件名框↓/Escape | 本次完整目标键盘路径尚未动态确认 | 原型↓聚焦首结果、Esc清query是已有设计；IME组合态必须先退出键处理，不能在候选确认中跳焦点 |
| 全文dialog↑↓/Enter/Esc | 选择/打开/退出；query首条/无结果时↑浏览历史；mask拦截自己的上下键 | 原型已有基本逻辑；结果列表滚动、焦点圈定和关闭后还焦点仍缺验证 |

模型建议：键盘处理返回可测试的intent（`focus`、`expand`、`collapse`、`select-range`、`toggle-selection`、`select-visible`），DOM层只执行focus/scroll与业务打开；不要在评分函数或全局window快捷键中混入这些操作。目标静态依据在app-initial格式化124435–124548，包含sticky行的特殊焦点/滚动处理；普通列表intent不能自动证明sticky虚拟化行为等价。
