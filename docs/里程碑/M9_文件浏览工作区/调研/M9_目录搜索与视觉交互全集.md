# M9 目录、搜索与视觉交互全集

修订 R1a-20261017（补齐客户端文件名评分算法）。范围是已安装 Codex 的文件目录树、文件名筛选、全文搜索、路径导航及这些区域的图标和微交互；不含浏览器。与[文件类型与编辑状态全集](M9_文件类型与编辑状态全集.md)、[项目会话与文件生命周期](M9_项目会话与文件生命周期.md)共同构成 M9 全量研究。

结论：这些能力可用标准 Electron 文件服务、React 和可合法复用的 `@pierre/trees` 迁移。实际产品的目录树是浏览与选择器，不是完整文件管理器：其宿主没有启用库的重命名和拖动功能，也没有新增、删除文件菜单。文件内容编辑另属查看器，不能据此删掉编辑需求。普通目录、文件名模糊搜索和全文搜索是三个不同数据路径，不能用一个前端 `filter` 冒充全部功能。

## 3. 普通目录树和多根

| 条目 | Observed：静态业务逻辑 | 迁移约束 |
| --- | --- | --- |
| 根来源与当前根 | roots为空不显示普通树；一个根不显示根切换条；多个根显示“Choose file tree root”菜单。默认当前文件所属根，否则roots[0] | SmartDD由项目目录+task cwd提供可信roots；不能让renderer任传绝对路径 |
| 嵌套根 | `dca/Eht` 选择包含文件的**最长 root**；当前活动文件仍属于当前根时保持当前根；跨根时跟随活动文件 | 去重、大小写和边界比较须与操作系统一致；`/a`不能误命中`/abc` |
| 根菜单 | 文件夹图标、basename截断、完整root tooltip、当前项checkmark、点击切根；`data-tab-preview-pin-exempt`避免误固定文件预览 | 菜单焦点、方向、屏幕边缘翻转待运行核对 |
| 懒加载 | 查询根 `directoryPath:null` 和已展开目录；不是启动时递归读全树；结果Set合并，目录path以`/`结尾 | 数据模型区分目录/文件；懒加载错误不能伪装空目录 |
| 查询 | `workspace-directory-entries({hostId,workspaceRoot,directoryPath,includeHidden})`，带abortSignal；5秒stale，placeholder保留前值 | 切根时取消并拒绝迟到回调；后端权限/真实路径检查见生命周期研究 |
| 隐藏文件 | 普通树与breadcrumb均直接传`includeHidden:true`；本宿主未见“显示隐藏文件”切换 | 别擅自做默认隐藏；隐藏文件不等于搜索排除目录 |
| 选中/打开 | 单选文件打开`isPreview:true`；双击`false`固定。目录选择不当文件打开；多选回调仅取第一个文件路径 | 批量操作不是已接入功能；预览标签状态见类型/编辑研究 |
| 当前文件定位 | 展开祖先，恢复选中，scrollToPath nearest；breadcrumb弹层用center | 程序定位不夺取编辑器/终端焦点应独立验收 |
| 展示 | 普通树`flattenEmptyDirectories:false`；stickyFolders:true；虚拟化列表；search:false（库自带搜索关闭） | 必须区分宿主文件名框与树库自带搜索 |
| State | scope=`hostId/environmentId/includeHidden/root`，保存`expandedPaths,selectedPath,scrollTop,searchQuery`；100ms debounce，卸载flush | 这是Codex原scope；SmartDD需再加task scope，避免不同会话互串 |
| 恢复 | resetPaths保留expanded；滚动恢复最多60个RAF重试 | 不是承诺60帧动画；目录未就绪时的重试边界 |
| 状态 | loading、root错误、empty、ready；展开预取错误catch | 原代码未将所有子目录错误呈现为独立行；SmartDD错误补充要标为设计增强 |
| generated | changed-files分支在识别到linguist-generated后才显示“Filter generated files”，激活计数1；与diff过滤相连 | 属于变化文件浏览上下文，不是普通树隐藏文件按钮，也不等于Git提交管理 |

**没有宿主接入的库功能：**树库含 `add/remove/move/startRenaming` 方法，支持 F2 和 dragAndDrop，但是 BaseFileTree 构造没有提供 `renaming`、`dragAndDrop`，库检查二者存在且不为false才启用。当前树菜单没有新建、删除、重命名、剪切、粘贴、拖拽移动。不能仅搜索到方法名就把它们列为 Codex 已提供功能。外部文件新增、删除、重命名后的同步仍属于必须覆盖的生命周期状态。

## 4. 文件名筛选

1. 左侧有搜索图标，输入标签 `Filter files`，placeholder `Filter files…`；非空时出现“Clear file filter”按钮。`autoFocusSearch`决定打开时是否主动聚焦。
2. 普通本地环境`environmentId==null`展示；remote environment分支隐藏输入并把query置空，禁用文件树上下文菜单。远程能力是否另有入口不能由本组件推出。
3. 非空query触发模糊文件搜索 session，不受目录是否展开限制。controller优先`fuzzyFileSearch/sessionStart({sessionId,roots})` → `sessionUpdate({sessionId,query})`，接收`sessionUpdated/sessionCompleted`；退出或根变更停止session。旧callback通过token拒绝。不支持session RPC时fallback至`fuzzyFileSearch({query,roots,cancellationToken:'vscode-fuzzy-file-search'})`。会话更新报支持性错误时有重建路径。
4. 结果字段来自`{file_name,match_type,path,root}`，转换成`{label,matchType,path,relativePathWithoutFileName,fsPath}`；当前树不传`includeDirectories`，默认只保留file。
5. 前端明确过滤任一完整路径段：`.git`、`.hg`、`.next`、`.pnpm-store`、`.svn`、`.turbo`、`.yarn`、`build`、`coverage`、`dist`、`node_modules`。**普通树能展开node_modules，不等于文件名筛选会列出其文件。**排除是路径段精确比较，不能泛化为所有点文件都排除。
6. 按文件label的客户端fuzzy score降序，再原始大小写label的JavaScript字典序，再原index稳定排序；显示路径和真实fsPath分开，多根时补根标签。客户端具体评分已重建，详见§11；原生候选生成与其路径评分仍有独立证据边界。
7. 搜索结果以压平空目录的树呈现，祖先初始全部展开，resetKey=query；单击预览、双击固定。缓存最后非空query结果，仅同query可复用，减轻闪空；loading、无匹配状态单独处理。输入空白恢复普通树及原展开/滚动。
8. 本模块未见正则、大小写、whole-word或排除目录可配置选项；不能为“完整复刻”自行添加这些按钮。中文IME composition、拼音匹配和输入debounce的实际效果仍待验证。

## 5. 全文 Find in files

该入口位于文件顶部工具栏，不是文件名框的另一种筛选方式。只有hostId存在、非durable、root和onSelectFile存在、宿主`workspaceSearch`可用时出现。mousedown preventDefault保留原内容选择；点击发送host消息`find-in-files`及`{hostId,root}`。

| 项目 | 已定位实现 |
| --- | --- |
| 请求 | `workspaceSearch.search({hostId,roots,query,fileMask,priorityFolders})`；订阅match/done/error，cleanup执行cancel；50ms debounce |
| 空query | 不搜索；保留输入/历史交互；query与fileMask都maxLength256 |
| 结果 | 刷新时可保留旧结果并标aria-busy；spinner延迟500ms；完成显示最多前100条匹配行的提示。后端实际限制/rg参数见主进程研究 |
| 一行 | 左侧monospace文本片段，匹配`mark`背景token；右侧相对文件名+行号，最多占1/3宽；重名basename补更长路径以消歧 |
| 打开 | 传hostId、cwd=root、workspaceRoot=root、line、column，打开后关闭搜索dialog并记历史；不是只开文件却丢命中位置 |
| fileMask | placeholder `*.ts`，有历史datalist，Enter保存并把焦点返主query；mask自身上下键阻止外层截获 |
| 历史 | localStorage `files-content-search-history`，scope是JSON[hostId,roots]；query最多30，mask20，scope20；去重；mask trim |
| 键盘 | ↑↓浏览结果，Enter打开，Esc关闭；query在首条/无结果时ArrowUp进入query历史，ArrowDown返回并恢复当前草稿 |
| 页面 | 标题Find in files，placeholder Search text in all files，footer显示导航提示、mask等；错误/无结果/延迟loading均有分支 |
| 未见按钮 | 未见regex/case-sensitive/whole-word开关；不应凭常见编辑器习惯补成“参考事实” |

Unknown：多字节列号到编辑器position的动态映射、symlink搜索、权限拒绝的具体文案、真实取消时延与根/文件更新的竞争条件。静态布局不能证明这些通过。

## 6. 右键菜单分两套

**树文件右键（BaseFileTree `Me/Oe`）：**通过composedPath找`data-item-type=file`及path；本adapter只识别文件，目录右键返回无target。菜单先外部首选App及Open with子菜单，随后分隔、Save as（仅`workspaceFiles.saveCopy`存在）、Copy path、Add to chat（hostId可用）。App列表加载时禁用Open并给“Loading available apps…” tooltip；beforeopen预取；失败日志。选择外开不自动修改首选（`persistPreferred:false`）。Add to chat发送`add-context-file`，不是把文件内容直接写进终端。

**Breadcrumb/通用文件菜单（`hsa/gsa`）：**文件和目录都可用，根据`openMode`区分。能力项有首选外开/其他App、Open in GitHub（解析得到远端定位链接才显示）、Copy path；文件另可Save as与Copy file contents；本地host有Reveal in Finder / Open in Explorer / Open in File Manager。文件引用在其他调用参数下还可Open file、HTML View in browser，但后者属于明确排除的浏览器能力，不因此放进M9。

因此不能将一种菜单复制给所有区域。Save as是用户选择目标的另存副本，不是覆盖原文件保存；Copy file contents不等于普通树必有该选项。外开App列表和系统菜单条目会随平台、安装状态与host能力变化。

**SmartDD设计建议（不是Codex事实）：**Add to chat保留“添加到当前任务引用”的等价能力，先把文件身份/路径/选区映射为可审阅引用，再经现有任务提交入口送终端；不能一点击便自动执行shell命令，也不能直接删除该项以迁就终端架构。具体引用格式和发送时机纳入PRD设计评审。

## 7. 面包屑、焦点与键盘

Breadcrumb是可选择文本的路径段，而不是一整块不可选标题。最后段medium/default色，前段secondary；分隔符tertiary。容器overflow-x:auto、hide-scrollbar、flex-row-reverse，优先留住文件名端。完整复制显示路径时转换为完整真实路径，部分选中时只拼选中段（`/`连接），没有li时保留原选择字符串。

有hostId/root/onSelectFile且段映射有效时，点击段打开opaque的大号目录popover：320px目标高度（h80按4px spacing推导）、sideOffset1；当前项选中居中，父级段默认展开active目录。选文件预览并关闭弹层。弹层有Loading、Couldn't load folder contents、This folder is empty。按钮hover变默认文字色，focus-visible使用2px ring。根或不可映射段保持文本，不虚构可导航入口。

| 键/手势 | 树库中已定位 | 宿主结论 |
| --- | --- | --- |
| ↑/↓、Home/End | focus前后/首尾可见节点 | 可复刻，焦点与选中差异要逐态测试 |
| → | 目录展开，否则移下一节点 | 静态已见 |
| ← | 收起目录，否则移父节点 | 静态已见 |
| Shift+↑/↓ | 范围扩选 | 库可见；文件打开回调仍只取首个路径 |
| Ctrl/Meta+点击；Ctrl/Meta+Space | toggle selection | 不产生批量文件操作 |
| Ctrl/Meta+A | 全选可见项 | 不能据此声称有批量删除/外开 |
| Shift+点击 | range/additive规则 | scope是树当前可见节点 |
| F2 | 仅renamingEnabled时触发 | **宿主没开，不列为可用功能** |
| 输入字符自带搜索 | 仅searchEnabled时触发 | **宿主search:false**，使用独立文件名框 |

### 11.2 输入、大小写、路径与长query

| 规则 | 源码事实及迁移含义 |
| --- | --- |
| trim与空值 | query先trim；为空时`QXc`保留传入候选次序，不重排。独立`A2`空query返回零分函数 |
| 大小写预处理 | `Array.from`逐Unicode code point取小写；仅小写前后UTF-16长度相等时接受转换，否则保留原字符。普通ASCII输入大小写因此被消除；不属于Unicode完整casefold |
| 匹配模式 | 主/备用matcher都传`IGNORE_CASE`；候选原始大小写仍参与degree的精确字符奖励。**能忽略大小写匹配，不等于大小写候选分数相同**；也不存在用户输入普通ASCII大写就提高大写权重的路径 |
| 普通query | 编译为`*query`，允许首次匹配不从文件名开头开始；前缀命中另有大额奖励 |
| 含路径分隔符 | `/`和`\`在pattern中各变成`*NUL*`，候选的同类分隔符归一成NUL；主matcher仍只收到`label`。主匹配失败时，可用最后一个非尾部分隔符后的分量创建**没有前导星号**的备用matcher，因此basename必须从其开头匹配该分量 |
| 路径退化边界 | 普通文件名没有分隔符，`src/foo`的完整路径pattern通常无法在label上命中，于是尝试前缀`foo`。这不是“目录分+文件分”。分量提取对每类分隔符只看lastIndex；若最后出现位置就是结尾则忽略该类分隔符，不能笼统说所有尾斜杠都会退成最后目录名 |
| 长pattern | 编译后的pattern长度大于100，转为简单不区分大小写的substring（有前导`*`）或prefix（无前导`*`）匹配，先去除全部`*`。此分支中的内部空格为字面空格；阈值包括插入的`*`/NUL，例如普通100个UTF-16单位query编译后101就进入降级 |
| Unicode | 单词边界依赖ASCII字母数字检测，并结合大小写/数字转换；长度扣分使用UTF-16单位。没有客户端拼音、重音归一化、编辑距离容错的实现证据；中文字面连续匹配与“拼音搜索”不是同一能力 |

`*`及内部空格在正常长度matcher中被当作wildcard；这不表示支持regex。输入边缘空格已trim。泛型类中还有`FIRST_LETTER/MATCH_CASE`、uppercase/mixed-case分支，但当前入口固定IGNORE_CASE并对普通字母小写化，不能把未激活分支列为产品现有选项。

### 11.3 分值公式与连续命中

以下用命中的fragment集合`F`、首个fragment起点`start`、候选文件名`name`表示；值来自静态实现，非运行时反推。无匹配sentinel为`-2147483648`，对外变成`score=0`；零分候选**仍保留**，`QXc`没有再过滤它们。

匹配成功时，`score = max(1, 10 × (D + prefixBonus) − name.length)`，其中`prefixBonus`在首fragment从0开始时为10,000，否则0。`name.length`是UTF-16长度，不是字节数、字素数或绝对路径长度。

| D 的组成 | 精确条件／数值 |
| --- | --- |
| 初始位置 | 起点为0，或`isWordStart(start) && !isWordStart(start−1)`，加1,000；否则0 |
| 字符贡献 | 按下表逐个命中字符累加；有条件优先级 |
| 分片数 | 减去fragment数量，不是减去匹配字符数 |
| 跳过单词 | 后续fragment前跳过的word-start计数，每个减10；扫描器对数字还有逐位前移规则，不能简单换成空格分词数量 |
| 硬分隔符 | 首fragment之前没有配置的`/`或`\`，加2；普通basename通常满足。路径预处理用NUL替换分隔符，不能由该项凭空推导额外目录层级惩罚 |
| 首尾 | 首fragment从0开始加1；最后fragment恰好到文件名末尾再加1 |

字符贡献按此优先级取一项，不能叠加：

1. 非首fragment的新起点、又是word start、且pattern字符小写：−10。
2. 候选字符与pattern字符完全相同：pattern为大写则+50；否则若候选位置0且调用方开启startMatch则+150；否则该位置是word start时+1，其他0。
3. 字符仅大小写相容但不完全相同：处于word start，或pattern为小写且命中大写延续标志存在，取−1；其他0。

实际`f4o`调用degree的startMatch为false，+150分支未启用；普通ASCII pattern已小写，+50分支也不会因用户输入大写而启用。`isWordStart`要求当前字符为ASCII字母/数字，并满足起点0、前一个字符不是ASCII字母数字、大写接小写、或数字接非数字之一。这里“word”不是自然语言分词。

**连续命中没有另一个固定“每连续字符+N”的项。**匹配器先尝试最长连续fragment，必要时拆片递归，记忆失败状态；分片少、跳过word-start少、避开−10的后续小写分片惩罚，会间接提高分值。首命中可通过前导星号落在词中；后续片段通常从word start寻找，前一pattern字符为`*`或当前为分隔符时可放宽。query含点号时有跨点跳跃约束；连续query数字不能跳过候选中的另一个数字。词中片段拆分最短通常为3，词首为1，但整个剩余pattern已连续命中会提前成功，不能误写成“词中短于3一律不匹配”。这些条件是匹配资格本身，不能只复制上面的公式、把任意子序列都算作命中。

手工代入源码公式的例子：query为`foo`，`foo`得110,037，`foo.ts`得110,024，`Foo.ts`得110,004。后两者相差20来自首字符+1与−1之差再乘10。它们是**静态算例，不是执行目标代码所得golden test**；移植后仍需独立实现的单测与真实结果对照。
