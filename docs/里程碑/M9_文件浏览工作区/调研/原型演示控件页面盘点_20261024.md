# 原型演示控件页面盘点

记录时间：2026-10-24。依据：当前原型 r184-P-v1、本轮真实 App 验收包 r182-v1 及其冻结源码。用户要求先盘点，同时继续 M9 测试；本次未删除控件、调整需求或改变验收预期。

**截图红框是原型专用的场景／故障控制，不属于正式产品应呈现的业务界面。已定位 7 个主路由位置、8 个另带专属控制的格式子视图，以及 10 个独立演示面板。三种统计有包含、共享关系，不能相加成 25 个页面。当前 App 源码依赖核对未发现这些面板被引入。**

当晚续核当前 r185：原页面盘点及 App 依赖检查的源码输入仍适用，唯一源码差异是灯箱禁用按钮的 opacity／cursor 样式，不改变场景面板及导入关系。[当前基线逐文件核对](../验收/证据/并行测试/M9-20261021T005835Z-9de5-12b28f/M9-G218/attempt-002/result.json)已归档；此为静态证据续核，仍未宣称全部页面实机验收。

## 截图中的位置

[FileWorkspace.jsx:1111](../../../../prototypes/m6-codex/src/FileWorkspace.jsx#L1111) 的“M9 交互样例”按钮展开 `demo && .fw-demo`；`demo` 初始为 false，展开后出现截图中的删除、权限、过大、解析失败、冲突、保存状态、附件、目录、搜索及能力切换等合成控制。

这个通用面板跟随文件工作区显示，不限定文件格式。下表的 8 个格式子视图，是在它之外还含有专属演示控制的视图，不表示通用面板只影响 8 种格式。它们与真正的编辑、保存、重试等业务按钮需要分开识别。

## 正式 App 是否引入

独立复核本轮 App 冻结源码的静态导入、重导出、字面量动态导入、`require` 及 CSS 导入。441 个非测试代码文件中，直接引用原型目录的只有下面 3 处，传递涉及 11 个原型文件；没有发现非字面量动态导入。执行者另外扫描的 500 个非测试源码包含样式等文件，两种扫描口径不同。

| 正式 App 引用 | 实际用途 | 与演示控制的关系 |
| --- | --- | --- |
| `src/renderer/features/files/markdown/image-host.tsx:6` → `ImageGalleryRoute.jsx` | 图片灯箱；:109 由 `enabled && gallery` 打开，使用真实归属资源和业务回调 | 未引入 `FileMarkdown` 的图片能力场景控制 |
| `src/renderer/features/files/recovery-dialog.tsx:5` → `FileRecoveryView.tsx` | 展示真实 `recovery / inspectRecovery` 结果；由 `open` 控制 | 未引入固定示例包装 `FileRecoveryPrototype` |
| `src/renderer/features/files/text-editor.tsx:23` → `file-code-theme.css` | 代码主题样式 | 样式不提供场景控制面板 |

正式构建入口为 `src/renderer/index.html` 和 `m9-diagram.html`，没有以原型 `App.jsx` 为入口。上述共享组件及传递依赖不包含这次列出的场景面板模块。**因此，当前证据支持“原型多处有演示控制，但未发现它们随这些复用进入本轮 App”**。这次没有逐页启动实机检查，不能把源码核对写成所有正式页面的视觉验收通过，也不代表所有历史安装包均已检查。
