# 附件来源与文本分派接入

2026-10-18，依据R3.4-P1 / R06.2、R06.11、R06.16，关联F04/F07/F21/G12及D20。沿用既有开发授权、只读附件和会话回调约定，不新增云来源或产品页面。

当前缺口：`openAttachment`只传`readOnly`，没有MIME元数据；renderer仍只按文件后缀选择Markdown/HTML。因此附件MDX错误走普通Markdown分支，无扩展HTML/Markdown附件没有回退，HTML主进程也仅接受html/htm。普通CSV/TeX默认源码、附件默认document和Notebook分派已存在，不能为修复MIME回退改变这些默认值。

方案：在既有open IPC增加只读附件hint。主进程仅在`readOnly=true`接受此hint，结合实际FD样本类型及文件名计算文本呈现类型；hint不改变根授权、内容分类、写能力或限额。已知后缀先于MIME，未知扩展不由MIME覆盖，只有无扩展文本允许MIME回退。普通Markdown仍包括mdx，附件Markdown集合只含md/markdown/mdown/mkd。已确认`text/markdown`与HTML/plain能力；工程兼容`text/x-markdown`，完整Codex别名集合仍缺直接证据，不预称精确复刻完成。

主进程将结果随文档元数据返回并在read/refresh后重新核对，生命周期与只读能力绑定；HTML仅对主进程已确认的只读文本HTML映射放行无扩展名，仍沿用独立WebContentsView、资源allowlist及输入/网络隔离。Related文件保持只读来源，但不继承父文件MIME。renderer复用既有真实Markdown/HTML/CSV/TeX/Notebook组件及源码切换；来源回调不持久化。

验证顺序：先保留真实文件服务红测，再实现主进程契约、renderer分派和相关单元/集成回归；随后打包复验。MIME/后缀组合、内容类型冲突、只读写入拒绝、read/refresh、回调身份、关闭/持久化、普通文件回归分别留证。现有产品没有已接通的附件来源host入口，不能用直接调用store或模拟UI证明用户端到端；F04/F07/F21/G12的完整A仍保留，后续按已确认来源接线继续，不以单测计通过。
