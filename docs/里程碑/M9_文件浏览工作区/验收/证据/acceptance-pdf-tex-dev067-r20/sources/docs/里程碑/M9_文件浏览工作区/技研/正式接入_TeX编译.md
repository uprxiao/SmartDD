# TeX 编译正式接入

2026-10-17；依据R3.4/R3.4-P1 R06.6/R06.17/R08、F16及工程预算。生产服务、原生编译和界面已接入，完整阶段验收未完成。沿用[开发前09](开发前_09_引擎资源.md)的固定Tectonic/离线资源路线，不执行项目命令，也不依赖用户PATH中的TeX。

## 生产路径

普通`.tex`默认源码，显式“编译并查看PDF”先经过现有dirty保存/冲突门禁。`FileTexService`绑定文件ref、owner及baseHash，解析本地字面量依赖，交由原生broker通过根目录FD读取并复核版本。动态宏生成路径不自动扩大映射；缺包、越界或损坏明确失败，源码保留。生成结果按1MiB分块返回，渲染端再次检查总大小和SHA-256后交给现有PDF viewer。取消、换标签和卸载撤销请求并忽略迟到结果。

`scripts/files/prepare-tex.py`只在构建时准备已锁定Tectonic 0.17.0、3685个TeX资源及许可证/来源，逐文件和最终ZIP校验；运行时只读随包ZIP。固定ZIP SHA-256为`1b0b496b02feab81da01514bd9913b7ad99a7eb4c400ee79e14ee8cc638b3d1d`。Mac包内可执行文件经签名后字节会改变，运行时验证包含它的App完整封装及实际FD身份；开发环境验证原始引擎hash。资源清单、源代码包及原许可随包保存，不能把资源集合统称单一MIT许可。

编译在私有job目录、独立home/cache/tmp和固定参数中执行。macOS原生限制禁止网络、shell escape及执行其他程序，项目只读快照；没有用户凭据注入。进程组取消并wait/reap，编译前后重核原始输入版本。主进程与后续Office重任务共用单并发队列，最多16个排队任务；单窗口仅一个TeX任务，全应用最多四份预览。

## 预算与恢复

- 源码10MiB、快照128MiB、最多1024文件/4096引用/32层；PDF输入兼容检查40MiB，输出40MiB/2000页。
- 解析/兼容处理在128MiB Node Worker内，单请求5秒；准备与编译合计60秒。
- 引擎冷启动30秒、后续15秒；CPU软/硬25/27秒、FD128、文件输出40MiB。RSS每次观测到超过768MiB则停止，此为观测式预算，非OS硬内存上限。
- 正常结束、失败、取消经原生FD清理私有job并释放结果。每个job先写入目录身份/owner PID的0600标记；编译进程持有该标记的独占锁。启动恢复只清理owner已退出、锁已释放且身份一致的job；孤儿编译仍运行时每15秒重试。活跃owner、坏标记、符号链接、跨卷或未知对象保留并记录。目录树先完整预检，再descriptor-relative删除，最多1024个job、每job8192项/64层；不是按文件名直接递归删除。
- 仅已打包并验证的macOS arm64有本批证据；其他平台缺少资源时明确不可用，不把本机结果外推。

## 空白PDF图片兼容

实际Tectonic对没有`Contents`的合法空白PDF页不兼容。使用固定`pdf-lib@1.17.1`仅为缺失Contents的页面添加空白绘制流，保留页面属性、现有绘制和原文件字节；正常PDF不重序列化。修改仅发生在编译私有副本，记录警告及副本hash/size。原始PDF的FD身份和hash仍参与编译前后复核；不能覆盖项目图片。3项兼容单测及真实引擎/PDF.js独立回读通过。
