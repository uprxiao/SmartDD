## 1. 目标、使用者与范围

用户在项目任务中查看、定位、编辑和保存真实项目文件，随时回到正在运行的终端。文件工作区完整呈现 Codex 参考区域的结构、操作、状态、视觉及微交互；不能因先实现了 Markdown 或静态原型，就把完整文件工作区视为完成。

目标使用者是当前 WillYou 用户，文件区使用其已登记的本机项目目录或可验证为本机的任务实际 cwd，按IDE式本地文件树及各种格式渲染/编辑工作。来源限于实际本机路径及已落地的本地文件；M9不建立远程文件工作区，不主动SSH连接、挂载或下载文件以补足来源。已有项目/服务器配置、任务、AI配置和终端能力保持可达，不因文件区范围调整受限。M9不新增组织权限、多人协同、远程账号或文档审批业务。Windows、Linux仍按项目既有实验性支持边界单独验收，Mac结果不证明其它平台通过。

## 2. 工作区结构与主要流程

### 2.1 信息结构

左侧保持项目/任务导航，中央保持当前任务终端。文件工作区在旁侧，顶部为该任务独立的文件标签；标签下为路径与操作工具栏，内容区为当前查看器，右侧为可开合的文件树。文件标签不替代任务会话，也不恢复已排除的中央聊天界面。

切换任务只是切换对应的文件工作区状态。终端进程、文件标签、文件内容模型、目录树、搜索请求、监控与持久化各自有生命周期；关闭文件不得结束任务，改变面板宽度不得重建PTY。

**R3.2 用户确认：终端与文件视图独立。** 终端内的 Claude Code/Codex 按用户指令及其自身权限机制直接读写文件，WillYou 不增加第二次 AI 修改批准。右侧根据真实磁盘打开、刷新和监听文件，不等待 CLI 完成，不建立专门的 AI 任务审阅/保留/还原流程。上下文引用可以插入终端输入，交接以投递结果结束；只有右侧手工编辑尚未保存且磁盘外改时，执行普通文件冲突保护。

**R3.3 用户确认：文件区仅本机。** 左侧终端继续运行原有CLI，右侧只浏览、渲染、编辑本机真实文件。远程任务/服务器记录不产生远程文件根；若当前任务没有可验证的本机目录，显示无可用本机根及原因，不主动连接或下载。用户既有终端中的远程命令能力不受此文件区限制影响。

### 2.2 主要用户流程

1. 在已有项目任务打开文件区域 → 取项目目录及任务cwd → 确定当前根 → 展示根层文件 → 展开目录 → 单击预览 → 双击或显式固定。
2. 文件名输入筛选 → 搜索未展开目录的文件 → 键盘或鼠标选择 → 打开并定位 → 清空筛选回普通树及原位置。
3. 工具栏“在文件中搜索” → 输入文本及可选file mask → 增量结果 → 打开具体文件/行列 → 返回原任务终端。
4. 编辑文本/Markdown → dirty反馈 → 自动或手动保存 → 保持光标/滚动；保存中继续输入不能被误标为已保存。
5. CLI或其他程序修改文件 → 目录刷新/监听同步变化 → 文件打开、重新激活或刷新时核对并读取最新磁盘内容；已打开的clean内容自动更新，无需批准。只有本地尚有未保存手工编辑且磁盘内容也变化时，保留两版并暂停保存 → 用户按普通冲突流程选择保留本地/使用磁盘/继续编辑。
6. 关闭文件 → clean直接关闭；dirty先尝试保存 → 失败时继续查看或明确放弃 → 可持久route支持撤销关闭；重启恢复固定标签，缺失文件显示占位。
7. 查看Office/Notebook/媒体/PDF等 → 使用各自真实支持的控件 → 不支持、过大、损坏、权限和能力缺失分别可解释；外部打开/另存副本保持可达。
8. 文件/选区/评论加入引用托盘 → 用户插入终端输入（不回车）→ 显示 inserted/failed/unknown 等投递结果；之后是否提交、CLI如何操作文件由终端内的用户与CLI处理，文件视图继续按磁盘事实同步。
9. 将右侧文件树中的文件或已开文件标签拖到当前终端输入区 → 插入该文件完整绝对路径一次，路径后附一个分隔空格且不回车 → 终端获得焦点，用户继续打字或沿既有语音入口补充问题 → 用户自行提交。图片、文档和其他真实文件使用同一路径规则，不识别CLI品牌。

PDF/Office等查看器的评论或Request edits入口按同一上下文交接边界适配，不另接AI完成状态或批准链；PDF的`review fallback`只是查看器路由名称，文档红线与普通手工编辑差异查看也各有原有用途，不据此恢复专用CLI审阅流程。

### M9-R02 目录树与多目录

| 子项 | M9 设计要求 | 参考事实／验收要点 |
| --- | --- | --- |
| R02.1 根映射 | 使用项目已登记本机目录；经核实为本机的任务实际cwd单独作为可信来源/fallback。任务快照与后来项目改址不同须显示来源，不能静默换根；远程cwd/服务器记录不冒充本机根 | main解析projectId+dirId/taskId并验证本机来源后才签发root，不让renderer自选任意磁盘路径或host。非本机来源显示不支持且不连接/挂载/下载；不为UNC网络路径建立访问能力。操作系统已提供、可按本机路径解析且获授权的挂载路径不一概禁用，仍执行真实根/权限/断开检查，不据此承诺网络或跨主机能力 |

| R02.3 懒加载与普通树排序 | 初次只读根层，展开再读子层，折叠不丢当前已确认缓存；查询有取消、loading/error/empty状态；普通树目录优先，同类按name.localeCompare排序，比较相等时保持稳定次序，测试记录实际运行locale | 参考query stale5s，结果Set去重；目录排序依据[既有文件证据 VL](调研/Codex文件工作区实现证据.md)，与R03.3模糊结果的UTF-16比较不同；不能“全部递归后一次显示”造成大项目阻塞 |

| R02.5 选中/定位 | 单击文件预览，双击固定；目录展开；活动文件展开祖先并可见；焦点与选择分别维护 | 普通树不压平目录；搜索结果压平；程序reveal不应失控滚动 |
| R02.6 键盘 | 箭头/Home/End、Ctrl/Meta与Shift选择按参考对齐；Tab焦点可见；无目录时可退出树 | 通用库有多选，不意味着批量文件操作；F2/drag未启用是参考宿主事实，不据此虚构文件管理。它不阻止用户明确新增的R05.14文件→终端路径拖放；标签拖排序保持 |

| R02.8 装饰 | 文件类型图标及其浅深色、目录箭头、选中/hover/焦点全部对齐；参考中的Git颜色/状态徽标及generated过滤纳入条件功能 | 纯文件条件展示与Git管理分开；数据供应方式依§7评审，不用虚构git后端 |

**名称结果工程预算（2026-10-19，R03.5/C13）：** 面板显示最多5000个已评分匹配，保留真实total/truncated并提示缩小关键词；先对完整可信候选评分排序再截断显示。缩小词重检完整候选，不在枚举前截断；原native 200000项枚举保护另行保留。此为本机工程显示预算，非Codex动态测量，验收以5000±1及尾部恢复判定。

**暂定对齐阈值（设计基线，不是全局统一大小）**：文本≤10MiB可编辑，(10,20]MiB只读，>20MiB拒绝文本编辑器；非PDF artifact>40MiB拦截；媒体宿主给binary read传128MiB，但本地协议URL可跳过这次read查询，协议端限额须另定与验收；review source前置256MiB。PDF/TeX不能因本层绕过40MiB便称无限大；须定义真实内存/worker/后端限额。HTML存在UTF-8 bytes和UTF-16 code units两种限制，不可混用。等于与大于边界、解析后真实bytes都要测；若选型达不到参考，记录明确差异并评审调整，不能未经说明把所有文件降至较小阈值。尚未冻结的数值属于工程探针待定参数，必须在对应实现与验收前确定，不能让用例以“合理范围”代替判定。

**媒体工程冻结（2026-10-17 正式接入）：** 本期本机 protocol 与 binary 两条媒体读取路线分别以 128 MiB（含等于）为上限，协议端在主进程及原生 FD 读取前独立校验，不能仅依赖 renderer 参数。单分块 1 MiB，单媒体最多 4 个读取，单窗口最多 4 个媒体引用；本地加载/缓冲 15 秒超时可重试。它们是本次工程预算，不代表已测得 Codex 协议限额；实际边界和剩余入口见[媒体正式接入方案](技研/正式接入_音视频预览.md)。

**HTML工程冻结（2026-10-17 正式接入）：** 文档预览同时执行源字节≤10 MiB与UTF-16码元≤5,000,000两道门槛，超限保留既有源码入口。资源映射最多128项、单项8 MiB、总计40 MiB、深度8、每次解析512个引用；单窗口一个活动文档、全应用最多4个，加载15秒。运行期间每2秒检查，连续5秒不响应或观测到进程工作集>512 MiB时停止；这不是操作系统硬内存上限。每宿主最多512次资源请求、8个响应流，单次输出块64 KiB。数值是本次工程预算，不声称来自Codex动态测量；具体隔离/取消及未验边界见[HTML正式接入](技研/正式接入_HTML文档.md)。

R06.2 的原位编辑基线：参考由 CodeMirror 文档、selection、decoration/widget 构成；焦点/选择覆盖相应标记时显露源码，保持实际文字、行尾及source range，Mod-S走当前文件保存。frontmatter只在解析有效时将开头范围替换为metadata呈现，选区与编辑应能回到源码；无效或未闭合结构不得吞正文。数学为惰性KaTeX（strict=ignore、throwOnError=false），公式选中可回源；Mermaid仅有render回调且完整小写mermaid fenced block才创建widget，改变内容/卸载清理渲染和ResizeObserver。图片引用解析的前131072 UTF-16 units扫描边界不是文件读取上限。精确条件、失败回退与原型差异见R2补充研究。

R06.2 的 R3 实现基线（原型）：渲染使用 CommonMark 解析（markdown-it）的块级 token 与源码行范围，块内编辑只替换该块的源文本；公式使用 KaTeX、图表使用 Mermaid（strict 安全级别，按需加载，失败显示可读错误块且不残留节点）；原始 HTML 一律转义；链接与图片目标保留作者原文用于路径解析，图片源仍受白名单限制；任务项勾选只改写其所在源码行；frontmatter 以 YAML 解析并报告错误。这是原型选型，**不等价于参考的 CodeMirror 装饰/选区行为**，高亮的代码围栏、公式内选区、跨块选区仍属待验。

R06.11 的 R3 实现基线（原型）：Notebook 的 Markdown 单元使用与文档相同的 CommonMark 渲染（原始 HTML 转义、链接不导航、图片白名单、公式按 KaTeX），代码单元与 JSON 输出用 highlight.js 子集高亮（python/javascript/typescript/json/bash/sql/xml/css/yaml/markdown，未知语言按纯文本）；HTML 输出仍在无权限 sandbox 的 iframe，不运行单元。浅/深色高亮色已配置，**逐色与参考的对齐未验**。

## 5. 非功能要求及验收口径

- 性能：万级文件树仍按需加载和虚拟化；输入搜索可取消，主线程不做无界全量解析；大文件有明确限制/反馈。首屏/搜索/滚动的量化耗时预算应在基线探针后定稿，当前不编造“已达50ms”。
- 可靠性：文件不会因切标签/模式/任务、外改、保存失败、窗口关闭或迟到回调静默丢修改。草稿落盘失败、恢复冲突明确显示；外部写竞争的未消除窗口记录在风险与测试里。
- 隔离：主应用不执行不可信SVG/HTML/Notebook脚本；自有HTML文档沙箱有明确执行/网络/文件权限，worker和Office解析失败不能破坏终端/其它文件。
- 可移植：worker/字体/原生watch及外开需在安装包中实测；依赖不得默认从公网CDN加载。来源声明、许可证和版本必须随实际引入资产保留。
- 回归：项目编辑、导入导出、AI配置、Skill、M7语音、任务恢复、终端输入输出保持可达且行为不变。M9文件关闭不能触发任务归档/结束。

## 9. 开发前工程基线 P1（2026-10-17）

本节是现有需求的可执行工程约束，原型页面和功能范围不变，102子项及425稳定用例编号不增减。正文规则以本文件为准，具体接口/实验/预算在各技研专项维护。

- **R03 搜索**：普通树保留隐藏/排除目录；名称与初始全文实现按R03.2固定目录段排除，显式不继承gitignore/用户rg配置。全文字面量、区分大小写；用户mask不能重新纳入强制排除目录。初始搜索单文件20MiB、前100匹配行、协议单帧2MiB；未扫描/超限须明确，不冒充整个项目无结果。具体进程与位置契约见[06](技研/开发前_06_文件树与搜索.md)。这些是当前WillYou工程选择，不冒充已观察到的Codex动态规则。
- **R06.17 PDF预算**：固定统一输入**工程候选**256MiB、每窗口1session、15秒deadline、200ms销毁握手、单页16Mi pixels/边16384、总canvas目标32Mi pixels。256MiB来自既有review门槛，新增artifact/协议统一防护须在生产接入验证；不是所有复杂PDF可打开的保证，也不擅自把未知能力写成无限大。Notebook沿用40MiB，窗口/HTML/图像及长期内存的可判定目标见[05](技研/开发前_05_PDF与Notebook.md)；未测目标不算通过，若必须改变已确认功能范围再评审。
- **R06.2/R07 编码与换行**：原始bytes、编辑source与EOL映射分开；未编辑CRLF/CR/LF保持，新增换行采用原文最多的形式，数量相同时按CRLF、CR、LF固定优先级，原文无换行则LF。撤销重做同步EOL元数据；未知/不能无损往返的编码禁止静默转码覆盖。详见[03](技研/开发前_03_Markdown编辑器.md)、[08](技研/开发前_08_保存与恢复.md)。
- **D06/R07.17 存放与恢复**：独立草稿/日志放本机userData，不写入普通项目导出；受原子交换约束的同卷staging/displaced由可信broker登记、核验、保护和清理，不能直接照搬实验项目内的`.m9-recovery`布局。跨卷、导出/搜索过滤及坏记录处理按[08](技研/开发前_08_保存与恢复.md)落实；未解决记录不因年龄或一次关闭而删除。
- **R05/R06.18 交接**：普通文件与图片拖动一律完整路径+空格、不回车，与显式真图片附件分支分开；CLI待发送附件标记不等于模型接收。扩展写回是明确供应的自定义契约，不是MCP标准或所有viewer通用能力。按[07](技研/开发前_07_文件终端与扩展接入.md)的身份/代际/幂等/unknown契约实施。
