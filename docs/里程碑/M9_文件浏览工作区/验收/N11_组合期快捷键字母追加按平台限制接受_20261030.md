# N11 组合期 ⌘+字母 追加按平台限制接受（2026-10-30）

用户于 2026-10-30 确认：N11 测的是 ⌘S／⌘F 这类快捷键在输入法组合期的表现；macOS 拼音输入法在组合期把 ⌘+字母 的字母并进候选，是平台行为，ChatGPT/Codex 里同样如此，**接受为平台限制，放宽 N11 的原预期**。本文是变更记录，不删用例、不改旧结果。

## 事实依据
- 真实系统拼音输入法（用户在场）：⌘S → 候选 `zhogn wen s` → 上屏“中文说”；⌘F → `zhong wen f` → “中文发”。可信组合会话全部为真实输入法事件。
- 机制：有标记文本时，keydown 以 `keyCode 229` 到达页面，输入法已把字母并入候选（`compositionupdate` 在其后 0.4ms），页面层 `preventDefault` 为时已晚。
- 已尝试且无效：10-28 的页面层组合期 F/S 守卫（G376/G378）；原生菜单隐藏快捷键项（G388，已撤回，`menu.ts` 恢复为 HEAD）。
- 对照实验（G389）：组合期按 ⌘A／⌘C／⌘Z（“编辑”菜单里的正式原生快捷键）同样被追加成“中文啊／中文吃／种文字”，所以应用层与原生菜单都截不住。
- 参考产品：用户提供的 ChatGPT/Codex 截图显示同样现象（候选 `zhogn wen s`）。

## 放宽后的 N11 预期（只含 App 自己能控制的部分）
1. 组合期间 App 不触发保存（无写盘）、不打开查找／跳行／菜单；
2. 组合期间不丢失、不被 App 提前提交（鼠标点击按钮时由系统结束组合并按原始字母上屏，属系统行为）；
3. 键盘事件不泄漏到终端（接收器 0 字节、0 条命令）；
4. 组合结束后，脏状态 ⌘S 恰好保存一次，⌘F 打开一个查找框，跳行可用，内容与磁盘一致。

## 保留的限制与更正
- “组合期 ⌘+字母 被输入法并入候选”**不是被修复，而是被接受**；不宣称 App 能避免它，也不声称其他 ⌘+字母 键不受影响。
- 更正：此前 G387／G388 记录里“平时 ⌘S 保存、写盘正常”的说法无依据——当时每次写盘都是组合结束约 0.7 秒后的自动保存，两次平时 ⌘S 落在已干净的缓冲区、没有写盘。保存一次的结论改以 G389 的脏缓冲区测试为准。
- 仅 macOS 系统拼音输入法、darwin/arm64；P 为原型开发服务提供的隔离工作区；未做 Codex 像素对照。
