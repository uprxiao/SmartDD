# 输入待确认与草稿时序：DEV041 实施差异

2026-10-18，依据已批准需求 R3.4 的 R07.3、H05/H06，以及[开发前 CodeMirror 路线](开发前_03_Markdown编辑器.md)。用户已授权 M9 范围内缺陷修复；本记录不修改需求范围。

生产采用 CodeMirror EditorState/transaction，未移植 Pierre 对象或同名 API。原先仅事务落地后 dirty，真实 EditorView 的 beforeinput/composition 与 MutationObserver 事务之间没有保存门禁。合成 DOM 事件接真实文件服务及包内 broker 的复现表明，等待输入时 save 可提前返回 true；进一步发现，已进入 EditorState 的未确认候选在 view 卸载后可能被旧自动保存计时器写入源文件。失败和修复证据见[H06](../验收/证据/m9-acceptance-h06-20261018.json)。这不是物理系统输入法或安装 App 端到端结果。

## 接入契约

- 每个实际 EditorView 注册 owner，由公开 domEventObservers 观测 beforeinput、compositionstart/end。只观测、不 preventDefault、不修改输入、不合成候选确认事件；只有原生 CodeMirror 事务可以改变源文本。
- beforeinput 的潜在编辑立即保护 dirty。实际 docChanged 同步接收并解除短等待；没有 docChanged 时 550ms 解除。正常输入没有新增 550ms 延迟。
- 活动 composition 的保护持续到 compositionend，不因 550ms 到期解除。结束后的实际事务或 550ms 尾部等待完成后，才能读取保存快照。候选变化不触发落盘确认。
- save/checkpoint 先等待，再重新核验 disposed、dirty、冲突和 inFlight；关闭/模式切换沿用此真实保存链。同版本 checkpoint 复用、写入串行、新输入不被旧回执清除的既有规则保留。
- 500ms 草稿和 3000ms 自动保存仍由实际文本事务调度，与 550ms 潜在输入门禁独立。H05 的真实恢复目录与源文件时序验证见[H05](../验收/证据/m9-acceptance-h05-20261018.json)。撤销回到 clean 时保留内存 CodeMirror history，清除过时内容草稿；没有声称 undo 栈跨 App 重启持久化。

## 中断与恢复

owner 卸载或 buffer 销毁会取消其等待者，旧回调不能解除新 owner 的输入保护。若 composition 候选已进入 EditorState，但组合未完成或仍处于结束尾部等待，卸载 view 会保留源文和 history、取消自动计时，并阻止旧 inFlight 完成后重新排自动写入；不清除已有 durable checkpoint。显示“输入已中断，请返回编辑器继续输入或撤销后再保存”，保存菜单禁用，普通关闭保持 blocked，继续查看保留 buffer。

返回后真实普通编辑/Undo 可以解除中断；新的中文组合须实际提交不同内容后解除，空组合或取消不能把旧候选当成确认。用户明确选“使用磁盘版本”可以替换本地状态并解除中断。没有把未确认候选写入原文件，也没有新增候选专用持久化格式；突然退出时仅已有确认草稿可恢复，不扩称未确认 IME 候选跨进程恢复。

原型增加“输入中断（模拟）”场景，保留示例候选、显示同文案、禁用保存、继续编辑/Undo 解除。原型模型验证和真实 Chrome DOM 中断→Undo 检查已完成；额外原型关闭操作被自动审批拒绝，未绕过、未计通过。生产组件/Store 的关闭阻止分支在 jsdom 已验证。真实 App/系统输入法复验归主代理统一新包执行，r4 包不包含 DEV041。
