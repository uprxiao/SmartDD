## 1. 可信文件身份与供应

主进程从登记的本机项目目录或核实的本机任务 cwd 签发 `rootLeaseId + generation`，绑定真实根身份。renderer 只持有 `fileRef`，不能自行提交任意绝对路径让宿主读取。请求附 `taskId/windowId/documentSessionId/requestId`；换根、切任务、关闭或身份改变后旧代际失效。相同显示路径的新 inode 不自动继承旧文档的可写身份。

拟实现接口为 `listDirectory/readFile/openStream/subscribe/cancel/dispose`，由主进程统一执行大小、身份、目录 fd/句柄与版本核对；这是目标接口，不是现有 RPC 的名称。读取结果含字节、编码信息、权威 revision、文件身份与监听 coverage。资源 URL 使用不透明会话 ID，生命周期受 lease 限制；不把 renderer 的 URL/path/size 当可信授权。切源销毁 Worker 和端口，读取累计 bytes 仍须受限。

文本阈值沿用10MiB可编辑、20MiB文本读取；非PDF artifact沿用40MiB。PDF统一入口采用第05项 **256MiB工程候选**，按真实句柄 fstat、累计读取及版本重核，不只信 HTTP HEAD；每窗口1活动 session，换源先销毁。此数值为待生产集成验证的明确预算，不代表任意256MiB复杂PDF已支持，也不把它套到所有MCP资源。MCP自定义适配器当前解码资源上限20MiB，行帧按 `20MiB×4/3+256KiB` 推导；能力不足时转内建文件供应并解释，不偷偷截断数据。

根目录逐级无跟随、目录替换竞争、元数据与保存恢复统一采用[第08项](开发前_08_保存与恢复.md)的原生 broker。此次固定夹具读取仅验证协议，不能替代生产根锚定安全验证。

## 2. 终端投递契约

原有 App 已有可信 sender/frame、task→PTY归属和运行实例校验，沿用 R3.4 的40项相关测试、6项真实 Electron 探针，不重复累计。本次不修改该生产入口。

上下文插入使用独立的受控 RPC，字段为 `taskId, ptyId, terminalInstanceId, rootLeaseId, generation, dropId, payloadKind, fileRefs/body, expectedDocumentRevision`。主进程再次校验当前运行实例与身份；路径由 fileRef 解析为最新可信绝对路径。文件已消失/切根/旧PTY/不匹配路径则整体拒绝，不能投给碰巧占同一 UI 位置的新终端。

| 载荷 | 处理与成功含义 |
| --- | --- |
| 普通文件/图片拖路径 R05.14 | 插入完整绝对路径及分隔空格，保留现有输入、恢复目标焦点；按已有约定处理包含空格/引号的路径，整体拒绝控制字符/超限路径。绝不追加 Enter，不读取正文、不上传图片，不把图片路径自动转换成附件 |
| 选区/评论正文 | 走现有正文清理规则，最多8000字符；根据目标终端实际括号粘贴模式包装，不将 ESC/终端控制内容原样注入；一次投递、不回车 |
| 真图片附件 V05/V06 | 与普通拖路径分开的显式能力；只有命中版本/输入方式已验证的适配器才按对应方式准备；图片内容与身份核对后才交接，不能把 SDK 接口或自建接收方视作真实 CLI 支持 |
| 回执 | `idle → inserting → inserted/failed/unknown`；1.5秒无确认进入unknown，保留内容、不自动重发。`dropId + targetInstance + payloadHash` 去重，同键改内容拒绝；inserted只说明PTY写入，不能推断CLI已读取、模型已执行或文件已更新 |

带空格的路径在真实 Claude Code 编辑框中作为文本完整保留。普通shell对空格的命令解释、CLI附件识别和纯文本路径展示是不同层；不能通过自动回车或偷偷改成上传来“修好”输入。终端繁忙、切任务、语音追加与完整拖放 UI 留到 App 接入时逐条验收。

### 真实 CLI 接收证据

本机 **Claude Code 2.1.302**，真实 PTY，独立临时目录与配置，`--bare`、禁工具/MCP/Chrome、合成无效API key，系统 sandbox 明确禁止网络。没有读写系统剪贴板、没有访问用户项目/凭据、没有提交模型请求。输入框出现前的主题/提示确认单独记录；第二轮进入输入框后5次分步输入事件均无 CR/LF。

1. 单独输入 `preexisting ` 并等待画面更新，然后另一次写入中文与空格的完整txt路径；原输入与路径均完整保留。
2. 再以纯文本追加同一自有16×16 PNG的完整路径；原文字仍在，**没有`[Image #1]`**，证明普通图片路径不会走附件转换。
3. 清除当前行的合成PNG路径，以显式括号粘贴重交同一PNG；CLI产生 **`[Image #1]`** 附件标记。
4. 再另一次追加“帮我看一下这张图”，附件和先前文字仍在，未回车。

这证明该版本 **原生括号粘贴文件路径→附件待发送** 的路线；不证明模型收到/理解图片，不证明原生剪贴板图片粘贴，也不证明 Codex/OpenCode/未来CLI兼容。普通图片拖路径必须使用纯文本分支，不能复用上述附件转换分支。

## 3. MCP viewer 的供应、订阅与写回

沿用真实官方PDF viewer 2.0.3只读最小闭环18/18；配置了MCP服务不等于完整viewer。只有显式适配清单及隔离UI映射通过的供应才加载；清单外工具、模型消息、任意网络或文件访问不转发。

MCP的标准 [resources协议](https://modelcontextprotocol.io/specification/2025-06-18/server/resources)支持声明订阅能力，**不定义本产品的ifMatch写回接口**。本轮使用官方SDK2.0.0、独立本机stdio适配器，读取真实临时文件；唯一自定义写工具 `willyou_write_resource_if_match` 经原生交换保存实验落盘。参数含严格会话URI、generation、opId、ifMatch和内容；错URI/工具/代际拒绝，旧revision保留外部修改。同opId同内容返回原回执，不再执行；同opId换内容拒绝。

真实watch通知只表示失效，收到后重读；解除订阅停止推送，dispose后迟到通知无效，关闭传输后子进程确实退出。原生监听错误须转poll/none并报告coverage，不得让未处理error把宿主崩掉。本轮native与poll各12/12；首轮EMFILE导致退出的失败保留，经异常处理及降级后复验。

[原生结果](../验收/证据/predev-provider-native-result.json)、[降级结果](../验收/证据/predev-provider-result-2.json)、[首轮失败](../验收/证据/predev-provider-result-1.json)、[源码](实验/predev-provider-probe.mjs)。这证明官方传输+自定义适配契约+磁盘保存闭环，不能把自建适配器说成任意第三方viewer均可写。生产尚需隔离宿主、可靠持久幂等记录、会话lease、权限、流量限制、订阅重连和安装生命周期；保留第08项提交后unknown与冲突恢复语义。

## 4. LSP 发现与能力

已有TypeScript language-server4.3.4/TypeScript5.9.3的11项证据沿用。本轮直接启动已有 **pylsp1.10.0** 与 **Apple clangd17.0.0**，独立临时项目/HOME，握手、didOpen、emoji之后UTF-16位置的definition与hover、shutdown均通过；另测无配置返回no-match、不自动安装。固定initialize10s、请求5s、关闭3s、帧1MiB。

生产入口按显式语言→可执行文件/参数配置发现，核对版本与serverCapabilities后才启用对应菜单；没有能力时说明原因，不伪造结果、不代用户安装任意服务。位置编码按协商值转换；URI经可信文件服务确认，不能直接跟随服务返回的任意路径。macOS `/var` 与 `/private/var` 同一文件的canonical identity要一致；首轮探针直接字符串比较导致C++失败，修正为真实文件身份比较后 **3/3**，原失败保留。
