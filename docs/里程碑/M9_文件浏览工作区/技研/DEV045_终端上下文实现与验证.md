生产入口已补齐：文件/选区/指令引用托盘、受控投递与回执、树/标签/真实图片拖入绝对路径，以及当前可见任务终端的目标登记和焦点回交。托盘位于文件区状态栏上方，复用已确认样式；填写与预览仅在内存准备引用，成功表示 PTY 接受写入，不跟踪 CLI 执行或修改结果。右侧文件读写继续走独立文件服务。

## 主进程契约与实现差异

- `files.terminalBind/terminalPrepare/terminalInsert/terminalRelease` 由既有 `createFileController.owner(event)` 取得可信窗口文档 owner。`FileTerminalService` 绑定 task、实际 PTY UUID、root lease/generation 和主进程签发 token；重用 `PtyAccess.authorize` 的 sender/frame、活动 task→PTY 和存活检查。原始键盘 `pty:input` 未作为文件投递入口。
- 文件来源是现有 `FileRef` 或根内路径能力；`FileService.terminalSource` 经原生 broker 校验真实文件、原 inode/device 及捕获身份，绝对路径由已授权 canonical root 解析。不接受 renderer 的绝对路径文字作为授权，不读出正文或上传文件；底层 stat 仍可能为 revision/hash 读取字节，不声称零底层读取。
- 每次异步 inspect/模式等待后重新验证 owner、binding、root、PTY 和来源。最后一次同步验证与 `writeControlled` 之间没有 await。关闭 owner、导航、切目标/根使旧绑定失效，旧回执不更新新目标。
- `operationId + payload SHA-256` 在绑定内保留；相同请求复用 Promise/回执，变载荷拒绝，不通过淘汰旧键允许重放。绑定最多 1,024 次投递记录、256 个准备引用，托盘最多 64 项；达到限制明确拒绝。
- 原规划考虑手写 VT 状态机；最终复用已锁定 `@xterm/xterm 6.0.0` 的公开 parser/modes，避免错误推断 OSC/DCS/ESC 语义。主进程不开 DOM、不把 parser 的任何响应接回 PTY；write callback 排空已收到输出再读取真实 bracketedPasteMode，退出/清理释放等待。没有新增依赖。
- 正文格式沿用原型相对路径/行号、@ 样式、引用评论与缩进选区。4,000 UTF-16/200 行截断且不拆代理对；格式化总长 8,000 限额。清理 CR、ESC、C0（保留 TAB/LF）、DEL/C1、双向控制字符和孤立代理项；括号模式保留多行，非括号模式折成空格，永不追加 Enter。
- 路径投递是精确绝对路径加一个空格，始终纯文本，不转附件、不猜 shell 引号；含控制字符、非法代理项或超限时整体拒绝，不改成另一个路径。
- 回执明确分层：准备阶段或 main 确认尚未进入 write 的拒绝为 failed；native write 抛出可能已经部分接收时为 unknown 并缓存；已派发 RPC 的断链/错 operationId 也为 unknown。1,500ms 未确认保留引用、不自动重发；有效迟到回执只完成原投递。unknown 不能通过再次点击插入自动复制输入。

## 界面、原型与验证边界

`terminal-context/{store,context,selection}` 是独立模块。实际 EditorView 的选区同时绑定 view、buffer instance/version、范围、输入是否已确认；IME 候选与旧指令对话框不能混入另一文件。拖放 DataTransfer 仅含临时不透明 token；非终端落点、取消、旧任务、换根和同次重复事件不写入。标签原有排序 MIME 保留，MCP 菜单/宿主及输入中断错误条保留。

原型继续复用已确认托盘/拖动交互，本批仅修复 4,000 位置的 emoji 截断，不拆 UTF-16 代理对；引用/拖动模型 18/18。未新增原型 DOM 或截图验收，不宣称本批全部视觉状态与 Codex 像素一致。

最终定向 54/54：9 项主进程服务/真实文件链（其中 4 项实际 raw PTY 或 zsh/sh）、9 项 renderer 投递状态、4 项真实 EditorView 组件、3 项实际 xterm parser、4 项清理/限额和25项原 TaskService 回归。复用本批已通过的原 PtyAccess 7项、TextEditor 3项以及并行 MCP 集成后 panel 7项；完整 typecheck exit0。测试的 Electron sender 元数据为可控夹具，不能称为真实窗口端到端；原生文件操作使用 r5 包内同哈希 broker，生产 JS 是当前源码，并非旧 r5 已包含新功能。
