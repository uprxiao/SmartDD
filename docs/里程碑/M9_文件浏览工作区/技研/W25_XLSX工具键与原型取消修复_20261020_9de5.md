## 两处实际问题

App 的工作簿 grid 把 `/` 当普通字符，直接开始编辑单元格，与 O36 静态事实和已确认原型不一致。原正常 r127 App 和组件均复现。首修只让外层菜单识别 `/`，菜单虽出现，子 grid 却已经创建输入，prepare 又将 `/` 提交进模型，严格的“原内容保持 Label”断言继续失败。

最终由 `range-menu.tsx` 接管适用的 `/`、ContextMenu 和 Shift+F10；`preview.tsx` 让已消费事件和无修饰工具键在普通字符处理前避让。原输入框／组合输入、只读、菜单准备和版本化编辑规则保留，没有通过更换预期让 `/` 成为普通文字。

共享 P 的输入取消也出现真实问题：Escape 清编辑状态并把焦点还给根时，旧 input 同步触发 blur，再次提交了刚取消的 `x`。`FileOfficePreview.jsx` 在恢复焦点前用同步 session ref 标记本次编辑已经结束，旧 blur 不再提交；原模型仍保留。没有新增 UI 入口或改变设计范围。

## 验证工具与原始失败

初始组件查询误把独立缩放 details 的 Fit 菜单算入对象，改为精确查询“单元格操作”；原五个失败报告及原测试源保留。修正查询后只剩真正的 slash 红测；首修仍有内容被改变的真正红测，最终 63 项通过。

首个 r128 App 驱动在“已清除且 dirty”等待时返回 DOM 节点，CDP 无法序列化，产生 `Object reference chain is too long`。改为布尔完成条件，业务断言不变；同包最终四组通过，旧失败留存。

既有 W27 verifier 只允许 A1 文字内容变化，不适用于实际 Delete 清空后的子树结构。新增独立只读 Python verifier，明确只允许 A1 值的删除／重新输入；目标样式及未知元数据、其它单元格／公式、ZIP 名称顺序和所有无关部件保持严格，只有实际公式缓存／calcPr 按既有语义归一化。五个控制样本允许原包／目标清空，拒绝其它单元格、opaque 部件、A1 样式破坏。首次控制夹具在 ZIP 关闭前调用导致 BadZipFile，修正调用时序，未改 oracle 预期；此控制不计作产品五项通过。
