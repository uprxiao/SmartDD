## 正常 App 的实际结果

原正常 r121，独立 userData、两条任务和两个本次生成文件；目录及特殊文件名含中文、空格、emoji、引号、括号、分号、反引号、美元符号。浅/深色 × 文件树/已固定标签 × 普通/特殊文件，共 8 组通过。

T1 使用既有隔离夹具真正 exec `/bin/zsh -d`，HOME/ZDOTDIR 仅指向本次目录；T2 是原输入接收器。没有启动模型。每组先输入已有中文指令，以明确 Ctrl-X/Ctrl-T 测试 widget 只读抓取真实 ZLE `BUFFER`、`CURSOR` 和完成序号；再用原 Chromium 指针 dragstart 载荷拖到终端。核对原专用 RPC、原 node-pty 单次写入为完整绝对路径和一个尾空格；再次抓取真实 ZLE。其后不点击/重新聚焦，输入“请总结”，再用真实浏览器 keyDown/keyUp 输入 ASCII `j`，逐次核对原文、路径、后续文字与行末光标。

8 组共 32 次 ZLE 抓取，原 96 次 PTY write 中 64 次是显式抓取用的 Ctrl-X/Ctrl-T，另外 32 次为测试文本/路径/ASCII 输入；所有原写入返回且前后 hash 一致，没有 CR/LF。T1 PID、task→PTY 标识始终未变；T2 零写入。两个源的字节、inode、mtime、ctime 不变，原五个 RPC handler、spawn 与两个原 write/监听均恢复；App PID 79359 正常 code 0 / signal null 退出。

这里只证明正常 App 的真实输入程序承接语义。中文经 CDP 文本输入到达真实 zsh，不等于系统 IME；指针载荷是真实浏览器拖放，不等于物理 OS 拖拽。没有 Enter、语音口述或目标指令求值；测试 widget 自身的读取动作单列，不能笼统写成“未运行任何 shell 代码”。M7 真实语音接续和最后用户手动提交尚未执行。
