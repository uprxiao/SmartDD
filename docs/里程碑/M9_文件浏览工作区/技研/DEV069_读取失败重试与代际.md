# DEV069 读取失败重试与代际

依据 M9 R3.4-20261017 / R3.4-P1，R07.1/R07.19/R08.1/R08.2，正式 H01；沿用范围内开发及缺陷复验授权，不增加业务、平台或发布范围。

## 实测与原因

r21 真实 App：首次打开因本地文件权限失败，错误占位没有“重试”。独立生产 store/FileService/原生 broker 集成表明：恢复权限后重新选中标签、树中重开、显式刷新均不再调用 open；首次 read 失败后的 buffer.refresh 也直接返回。另一个真实 native 读取竞态：旧刷新已读到 B 并延迟交付，新 load 已安装 C 后，旧 B 仍覆盖 C。第二轮原生红测 4 通过/5 失败；两项独立 buffer 单测均红。

首次驱动曾将“原 inode 恢复”和“另一个同名新文件”混为一谈；后者正确触发现有 CHANGED，要求关闭旧标签后重新打开，不是本缺陷。原始红测/截图保留，修正后的样本分别验证两条路径，`file-service.ts` 身份保护不改。第二轮原包 App 已完成前6个外部读/恢复场景，明确在错误占位缺重试处失败。

## 实现

- `workspace-store.ts` 的 retryTab 复用原标签，空 buffer 且未 loading 时重新打开；标签选中、树中既有路径、显式刷新、匹配目录的更新走同一入口。已有打开请求合并，不创建重复标签；关闭/根消失的旧请求仍按原 epoch/sequence 释放迟到 capability。
- `file-buffer.ts`：失败且无编辑器时刷新重试 load；内容已装载而草稿元数据失败时，仅重试恢复元数据并按现有刷新规则核对磁盘，避免覆盖期间的手工编辑。成功读回清旧 loadError；新的显式 load 同时使旧 refresh 失效。
- `workspace-panel.tsx`：错误占位接既有设计中的 `fw-pill`、RotateCcw 15px、“重试”；loading 隐去入口，使用现有 spinner。共享原型 FileWorkspace.jsx 已有对应 missing/unreadable 重试状态，本批补齐生产入口，未新增设计或原型源码。
