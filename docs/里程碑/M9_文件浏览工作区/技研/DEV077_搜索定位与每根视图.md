## 缺陷与实现

B09：生产树原先没有接续活动文件的展开/选中/滚动处理。实际原生搜索得到深层结果并打开后，原生 I 定向红测找不到 a.txt，1失败/5未选定。初两轮夹具误调用 search 和缺进度接收端的失败另列，不能当作业务红测。

显式打开/激活文件在 Store 生成一次性 reveal，绑定 root lease/generation、tab ID、buffer instance，并按可信文件元数据展开祖先。仍容纳文件的导航根保持；源 route/ref 不重定向。树等待所需真实目录与前方行稳定，只对 identity 与当前文件 device/inode 一致的 file 行定位；目录替换、错误/失踪和过期请求不冒充成功。零高度视口保留请求，实际可见后再消费；复用原型 nearestTreeScroll 至共享模块，保持已可见行，仅移动受遮挡边缘。选择与 DOM 焦点分别维护，不把焦点从搜索/编辑器拉到树。

reveal 只属于一次显式文件意图。滚轮、指针、树键盘操作、折叠、切根和新筛选词均可取消；普通刷新、watcher、初始化和 workspace 远端恢复不会重新创建请求。clear filter 可接续从该筛选结果发起但尚未显示的 reveal；会话卸载/销毁清理未消费请求。未新增 IPC、路径授权或持久化文件能力。

B12：r29 真实 App 复现切回 A 后筛选词 foo 恢复，但结果滚动从577回0。FileNameFilter 原来把列表 cursor/top 存在单一组件并在切根时归零。现按 issued root 分实例，nameSearchViews 保存该根 query/top/cursor；结果到达且视口可见后再恢复，用户滚轮/选择优先，新查询重置位置。普通树 scroll/treeViews 与筛选结果视口分别维护，原多选、焦点、展开不被筛选列表覆盖。该缓存是窗口会话状态，不宣称实现重启后的筛选滚动恢复；durable filters/expanded 等仍沿用既有 workspace 契约。

共享完整原型同步一次性 reveal、用户浏览优先、普通/筛选视口分开、切根延迟恢复，移除输入筛选词即清空原多选的偏差。普通原型页面及此前阶段入口保留，没有新增视觉设计/字体/图标。原型测试通过 syntheticFiles 自身持久化入口初始化数据，只按键/指针/滚轮操作实际共享组件；不是 native IO 或 Codex 完整像素证明。
