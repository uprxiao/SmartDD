# DEV072 单根重试与来源隔离

依据 M9 R3.4 / R3.4-P1 的 R02.1、R02.2、R02.7、R04.1、R08.2，关联 A01/A05/A06。属于已授权范围内缺陷修复，不调整419条本期范围。

初次打开根目录时，如果路径是文件、已删除或权限不足，主进程正确返回 unavailable，但 renderer 把初始化当成已完成。原“刷新”没有根可用时不重新申请，原错误卡片也没有有效的目录重试入口。不能直接重新调用整个 `files.roots(scope)` 修复：该调用会撤销本 scope 的既有租约，影响其他根的打开文件和未保存内容。

## 实现

- `retryRoot` 严格接收 scope、来源类型和来源ID，不收 renderer 路径、host 或 owner。路径继续从真实项目目录/任务cwd快照解析；重试前后核对来源ID、路径、项目及本机边界。
- 每个 owner/scope/source 的请求分别取消和验证。关闭作用域、关闭owner或同来源新重试使旧请求失效；DB来源在原生检查途中变化时，不签发旧路径权限。
- 仅更新该来源。仍可信的已有根复用租约；真正需要新根时只替换该来源的能力。其他健康根及其 buffer/ref/dirty内容不变。
- `releaseRoot` 仅撤销明确的 owner+lease+generation。组件销毁后迟到的结果按精确能力释放，不用 `closeScope` 误伤新组件。renderer 只发送严格的两字段请求，来源/路径等公开根字段不混入释放请求。
- renderer 合并单根结果，恢复根层读取及此前该来源失败的标签；重复点击合并为同一请求。顶端错误条显示来源、明确原因及“重试目录”，在存在其他活动文件时也可达。失败继续显示原错误，不切到home或上次根。
- 原型复用既有根不可用状态、错误条和重试语义；增加同名动作，根不可用时不画普通树。只是原型合成状态，不作为原生权限测试。
