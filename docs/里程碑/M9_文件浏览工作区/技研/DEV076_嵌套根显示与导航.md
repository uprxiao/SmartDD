# DEV076 嵌套根显示与导航

依据：R3.4-20261017 / R3.4-P1，M9-R02.2、R04.4；用例 A13、D21，受影响 P03/P06。2026-10-18，同一开发授权内的缺陷修复，未新增需求或发布。

## 事实与方案

既有参考 [项目、会话与文件生命周期](../调研/M9_项目会话与文件生命周期.md) §2 的 `Aii` / S231370 使用最长包含根生成显示路径；树的当前根仍能容纳文件时保留该根。源码原先把面包屑固定在打开来源上，缺少最长显示根及显式切回文件时的导航处理。新原生 I 红测为3失败、4纯路径单测通过，原始结果保留在本批证据；不是把后补测试写成开发前已有记录。

新增共享纯函数 `src/shared/file-root-location.mjs`，原型与生产共同使用。按本机 POSIX 完整目录段匹配，区分 `/a` 和 `/abc`、大小写，保留 Unicode 和反斜杠文件名；支持根目录 `/`。canonicalPath 优先，等深度别名保留发起来源；拒绝非本机 host、URI、NUL、空段和 `.`/`..`。它只计算展示位置，不能签发 lease、授权 IO 或替代主进程文件身份。

三个位置分别维护：

- **打开来源**：稳定 route、原 root lease、FileRef 继续承担读写、恢复和 Git 目录定位；不把 root 选择或显示路径写回原 route。
- **显示位置**：最长包含根的 label 和相对路径；面包屑弹层通过“来源根中的显示根前缀”读取，父目录操作限在显示根内。
- **树导航**：显式打开或激活文件时，保留仍包含文件的当前树，否则取最长包含根。手动选根增加独立意图序号；较早文件读取不能在返回后抢回导航。初始化/远端 workspace 恢复、后台刷新不会自动跟随文件覆盖用户保存的树位置。

面包屑的相对路径复制使用显示位置；Git 链接仍用真实打开来源路径。终端引用若当前树能容纳该文件，通过当前树的已签发 lease/相对路径重新打开，并由原生身份校验；没有可用终端仍只可收集引用，未执行终端插入。复制的单测接收端为替身，未复验系统剪贴板，T34 阻塞不变。没有更改同文件去重或保存实现：原逻辑已依据 main 的 device/inode 复用 buffer，并在成功保存后的新 inode 更新 documentKey。

共享原型同步最长面包屑、根切换跟随及跨嵌套根选中；其根弹层标题/复制目录路径也跟随显示根。仅合成路径，不冒充原生身份。未增加视觉设计、字体或图标；既有终端及其它阶段入口保留，完整 Codex 像素/参考动态仍未核验。
