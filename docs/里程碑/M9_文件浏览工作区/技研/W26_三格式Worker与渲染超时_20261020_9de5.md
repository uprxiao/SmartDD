## 故障与 oracle 边界

启动故障只在自有进程内一次性重定向被测 Worker 的 entry 到私有不存在文件，Worker options、源、认证、原错误及结果不变。触发后恢复原入口，UI 重试继续使用原包。消息故障只拦住真实原成功消息，等待原 15 秒截止后让新请求重试，随后原字节不变地投递迟到消息；没有伪造成功或修改 Store／DOM／编辑器业务状态。损坏文件是有效 ZIP，仅指定核心 XML 部件换为不闭合标记；恢复是关闭对应 tab 后显式替换本次测试源。

初始 I 三项红测保留。XLSX 第一次独立结构比较失败，实际 XML 显示公式与数组成员的旧 `<v>` 缓存被移除；公式、静态值、样式及其他结构未变。新增显式可选 `--allow-absent-cache` 只归一化真实公式／声明数组成员的缓存节点，原读取器默认行为不变，结果仍明确显示缓存待重新计算，不能称公式已刷新。实际保存候选通过；另外五个破坏公式、静态单元格、样式、无关部件与 ZIP 顺序的负控均拒绝。PPTX 初始测试误假设首个带文本对象必为 `kind=text`，已改用独立源 XML 的原 shape ID；未改变产品、源或预期。

最初 I 的 afterEach 删除临时源发生在失败快照逻辑补充之前，因此初次失败的最终源字节没有保存，只保留原报告和当时测试输入／源码；不得以之后的实际候选冒充该次源。后续诊断及最终 I 都保存失败阶段、原 Worker trace 与实际源，分层归档。

## 渲染超时诊断与未决项

缺陷 `M9-W26-20261020-RENDER-TIMEOUT`：正常原包 DOCX／PPTX 在原 Worker 重试之后，LibreOffice 原生渲染没有在原 20 秒内产生 PDF。当前原因未证实，保留失败，未改生产超时、原生安全策略或渲染结果。

只读精确自有 PID 的采样发现排版进程仍存活、输出缺失，但采样本身发生长间隔，不以此推定系统休眠。电源事件查询没有捕获该时段睡眠／唤醒记录。当前控制台只读布尔结果为 on-console 与 login-done；未取得当前屏幕锁定字段，缺失不等于已解锁，也不能据旧锁屏记录解释本轮失败。没有尝试解锁或更改系统配置。

另在 `/private/tmp` 编译两个诊断副本，未改生产源／包。第一份仅增加 stderr 的 spawn／每秒 tick／输出文件 stat 和原子进程 stderr 转发，原认证、签名、资源清单、sandbox、20/30 秒截止及业务结果不变。记录到原 LibreOffice 子进程连续约 20 秒仍运行、没有 PDF，并有 HIServices／ClientCallsAuxiliary 连接错误。第二份仅为私有因果对照，额外允许实际日志所示的精确 HIServices 系统服务查找，其他策略不变；该特定提示消失，但仍无 PDF、仍超时。**该对照没有解决问题，不将权限变更应用生产，也不继续凭提示扩大权限。** 两份都仅是诊断，不能当正常 A 通过；源码、编译参数与二进制哈希已记录，诊断二进制留私有临时目录。

下一步须在有可核对变化的环境条件下做同包／同源受控对照，再决定产品修复与受影响回归。先继续其余独立用例，确需用户系统操作的部分集中最后。既有 W07 同包／同复杂源的历史成功原证据保留，本轮更新为渲染可靠性未决，最终交付前补受影响复验；不能因旧成功忽略本轮红测。
