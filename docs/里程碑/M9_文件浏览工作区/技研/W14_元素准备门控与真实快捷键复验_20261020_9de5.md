## 问题与修复

1. 共享原型 `FileOfficePreview.jsx` 显示层级快捷键，但实际按键没有改变模型。新增选中元素、可编辑、非输入／合成、主修饰键及非重复事件的保护，绑定四种层级动作；没有可准备对象时不显示对象菜单。
2. App 的 `PptxElementMenu` 在异步选区准备完成前即打开，准备返回 false 时也继续显示修改动作。改为等待真实结果，失败／异常保持关闭；权限撤销、卸载或取消后的旧结果失效。把操作忙碌状态和编辑权限分开，避免合法输入提交期间的 busy 变更使成功准备失效。`pptx-objects.tsx` 传回真实准备结果。
3. App 对象菜单多了未经此状态基线确认的“删除”。归档 O26 与共享原型都是四个层级项，现收敛为置于顶层、上移一层、下移一层、置于底层，快捷文字分别为 `⌘⇧F`、`⌘⌥⇧F`、`⌘⌥⇧B`、`⌘⇧B`。原键盘删除与幻灯片菜单删除保留。原拒绝删除回归由已移除菜单入口改走既有键盘 Delete，继续断言原拒绝信息、对象内容及选中状态，不删除失败保护断言。

这是已授权范围内的缺陷修复，没有新增业务入口、修改依赖／厂商文件／安全策略／资源验证或延长超时。

## 驱动与原始失败

r125 正常 A 在进入元素动作前遇到原 30 秒传输超时，实际点一次重新预览又触发原 native 20 秒超时。W26 仍失败，后续成功轮不消除该间歇性问题。

r126 浅色菜单、四快捷键、保存重开已完成，随后域文字测试发现普通 CDP Meta+A 没有执行 textarea 全选，实际草稿为新文字加原文，驱动的“完全替换”断言失败；下一次补焦点仍停在选区前置。最终使用 CDP 官方 `Input.dispatchKeyEvent.commands=['selectAll']` 编辑命令，先真实点击并读出焦点／全选范围，再输入原断言文字。最终两主题保留的草稿均精确为 `FIELD_DRAFT_MUST_NOT_COMMIT`；原生返回“包含域…尚未应用”，没有假造拒绝、替换回包或直接设置 DOM 值。该输入不等于系统键盘／IME／剪贴板验收。

另保留 P 初始查询误计隐藏缩放菜单、原生 I 夹具缺 root 目录、PDF 组件 mock 签名及清理遗漏的错误。外部 renderer API 比较曾使用默认 development 模式和未清理的目录，结论无效，不当作生产等价、产品失败或自然性能证据。最终独立 r127 全构建及包内逐文件匹配为交付依据。
