# 文件类型与降级接入

2026-10-17；依据 R3.4/R3.4-P1 R06.1/R06.14/R08，关联 F08/F10/F13/F25/F26/F27。此为生产接入记录；显式viewer、附件/历史来源和Office真实provider继续实施，不把当前扩展名+内容判断当作完整路由完成。

主进程通过原生broker已授权的FD取得最多4096字节样本，样本与stat的revision核对后返回。renderer收到主进程产生的类型提示，不能用自造contentKind获得额外文件权限；样本不作日志或持久化。完整文本仍由严格UTF-8解码和保存保护验证，类型提示不证明文件完整可解码。

- Office artifact（DOCX/PPTX/XLSX/XLSM）先于归档容器判断，不能被ZIP通用状态吞掉；真实Office接入仍待完成。
- 旧Office/RTF/TIFF及不支持的媒体有专用说明、字节数和完整路径，共用外开/另存入口保留；不将可读ASCII当作可编辑文件。
- 已知PDF/Notebook/媒体后缀保留具体解析器和损坏错误；PNG/JPEG/GIF/BMP/ICO/WebP/PDF/SVG签名可识别误命名或无扩展名文件。SVG只探测前512字节，仍走图片隔离，源码不插入主DOM。
- 27个归档后缀按已有机器索引登记，复合后缀和大小写处理；不在预览中执行或自动解压。
- WASM、NUL和其他二进制控制字节不进入自由文本编辑。控制字节判断参考 [WHATWG MIME Sniffing §3/§7](https://mimesniff.spec.whatwg.org/)，允许TAB/LF/FF/CR/ESC；这属于当前实现选择，不冒充已从参考产品动态验证的全字节行为。UTF-16仍由已有编码门禁说明不能无损写回。
- 干净文本在磁盘变为二进制后移除编辑器；再变回文本可恢复读取。脏文本继续普通冲突保护，不因分类变化自动丢弃。

实现：`src/shared/file-classification.ts`、`native/files/broker.mm`、`file-service.ts`、`file-buffer.ts`和`workspace-panel.tsx`。79项相关测试通过（含50项真实Mac原生边界测试及CSV回归）；类型检查通过，日志`/private/tmp/willyou-m9-classification-tests.log`、`/private/tmp/willyou-m9-classification-typecheck.log`。实际App因Mac锁屏待验；对应正式用例尚未计通过。
