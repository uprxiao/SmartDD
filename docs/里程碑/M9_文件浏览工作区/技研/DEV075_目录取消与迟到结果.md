## 缺陷与实现

原目录 pending 仅按 lease/path 合并。折叠后重开或显式刷新继续等待旧请求，既不能重新获取新目录内容，也不能取消旧原生进程；旧 finally 还会无条件删除该路径的 pending 状态。真实SQLite/FileService/原生目录读取后控制投递的两项测试在旧代码下均失败。

- 目录 list 新增严格、可选 UUID requestId，旧 PathRequest 调用保持可用，不接受 renderer 自选路径根、owner或host。复用现有 owner/requestId 资源取消机制，含提前取消墓碑、重复ID拒绝、原生AbortSignal和完成后的取消核对；关闭owner继续释放。请求ID随原生目录请求用于追踪，监听内部的快照不使用UI目录ID。
- renderer 每次读取持有独立请求对象、ID及已确认缓存。普通重复读取仍合并；强制刷新使旧请求失效并取消，旧成功/失败/finally均不能覆盖或删除新请求。根租约/代际与store epoch仍参与接受判定。
- 折叠目录取消该目录和在途后代；切根取消其它根的目录请求；最后视图卸载、根行折叠及dispose也取消。已确认缓存保留，未确认loading删除，重新展开可新读。根行隐藏时树组件不自动补回已取消读取。文件内容和根权限不因目录取消而撤销。
- 原型已具备子目录折叠取消及AbortSignal回调保护；补根行折叠取消、可选合成fixtureProvider，便于在真实原型组件验证完成结果逆序投递。默认样例供应仍沿用原实现，无真实文件IO。
