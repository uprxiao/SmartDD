# 文件标签持久化接入修复

依据M9 R3.4-P1的R04.2/R04.7/R07.10/R08.6；2026-10-18正式开发范围内缺陷M9-DEV-013。

## 复现与证据

cell-r2实际App中未完成公式已独立保存草稿，但强制退出后新固定标签未恢复；手动重开后可恢复公式。原有localStorage.setItem没有主进程提交回执，磁盘LevelDB仅保留此前preview快照。该观察不证明所有浏览器写入都会丢失，也不把进程崩溃测试称为断电测试。

## 实现契约

- 标签与布局仍按project/task scope保存，路径只是恢复提示；实际打开仍须重新核对当前目录来源并取得root lease与document能力。临时preview不加入固定route列表；原顺序、active、模式、树根/展开/筛选及宽度沿用。
- 复用本机应用SQLite的app_settings键值表，独立`fileWorkspace.v1:<scope>`键；全局SettingsStore按固定键访问，不读取或重置这些scope键。无需迁移表结构，不进入项目导出。草稿字节继续在独立恢复仓库。
- 主界面可信IPC执行严格schema验证和4MiB总状态预算，数据库同步提交完成才回执。渲染端去重并串行提交不可变快照；失败不阻断后续重试，不吞错误、不清除内存。错误条提供重新保存标签。
- 首次数据库无记录时读取既有willyou-files-v1浏览器记录并提交；数据库存在记录时优先使用，读取失败不回退陈旧浏览器副本、不以空状态覆盖。浏览器旧记录保留作迁移依据，不再写入。
- dirty预览仍自动固定。文本/Office的checkpoint先保存独立内容，再等待对应route提交确认；route失败时内容仍可恢复并显式报错。Office同版本重试不重复写信封，但仍重试route确认。
- 4MiB超限、数据库错误、无效schema保留最后成功提交及当前内存，未宣称满盘/断电保证。跨窗口同scope的标签顺序沿用最后提交者语义，不合并文档buffer；文件写回仍按既有跨窗口比较保存规则处理。

## 2026-10-18 M9-DEV-036：版本校验与跨窗口回声

L11 的两个生产 store 和独立 SQLite 连接复现：另一窗口提交新固定 route 后，数据库已更新，但先开的窗口只在启动时读取一次，未接收外部状态。原始失败保留在 [L11–L13 专项证据](../验收/证据/m9-acceptance-lifecycle-persistence-20261018.json)。上文“最后提交者语义”是 DEV-013 当时实现边界；本次按已批准的《REA调研与迁移方案》§7.2 补齐 expectedRevision/opId，不再允许旧快照静默覆盖。当前相邻目录没有 `../yoda`，本次未声称重新核对其源码。

- 路由 JSON 保持 schemaVersion 1。复用该 SQLite 行的 updatedAt 作为主进程版本，每次实际提交取当前时间与上一版加一的较大值；事务内校验 expectedRevision，冲突回传当前完整状态与版本且不写入。相同快照不增加版本。mutationId 标识本次广播回声，不是文件授权。
- 仅可信应用主 frame 可读取／提交；按完整 project/task scope 登记读者并广播。closeScope、主 frame 导航、进程消失、窗口销毁释放登记。某个接收窗口发送失败不使已经提交的写入变成失败回执。
- 渲染端在读取前订阅，自己的回声、重复及旧版本不插入标签、不再次持久化。合法外部版本复用当前 buffer，新 route 仍通过当前已授权根的 lease 打开；相同 SVG 从图像切源码时初始化编辑器。保留 clean preview、仍存在的用户 active 和编辑器实例。
- dirty、saving、恢复冲突或尚未处理的草稿，本地未提交布局，以及外部删除当前用户选中固定标签时，保留本地标签、内容与选择并显示冲突。不自动三方合并或猜测排序。
- 冲突条提供“保存当前窗口标签”（明确采用本窗口布局，先重读版本再 CAS）与“读取最新标签”（无受保护 buffer 时可用）。回读期间用户又修改或选择，不应用迟到结果。路由操作不写源文件，文本／Office 草稿仍走独立恢复仓库。
- 原型 `FileWorkspace.jsx` 增加隔离的“模拟标签持久化冲突”状态与对应两动作，使用合成标签，既有草稿禁用回读；没有连接真实存储或把模拟标成 App 行为。

验证覆盖真实注册 RPC handler 的两个 sender 上下文、生产 store／FileService、独立 SQLite 连接及包内 native broker；另验证真实 panel 的冲突按钮与禁用状态、受影响焦点及标签回归。这里的两个 sender 是集成测试上下文，非两个真实 Electron 窗口；新包和真实 App 界面复验由批次验收追加，不沿用旧包宣称本修复已打包验收。
