2026-11-24，macOS arm64，Electron 42.11.14。驱动读取与旧包同提交的浏览器页面注册、登录态、任务账本、宿主请求及数据库迁移。使用真实 WebContents 和独立 SQLite、HOME、userData。前置、登录确认小样及后续运行登记由隔离驱动提供。 [实验结果](证据/60e7f6545-登录接续与报表夹具.json) · [隔离实验入口](../../../../../scripts/browser/m15/run-login-study.mjs)

| 场景 | 实际结果 | 设计结论 |
| --- | --- | --- |
| 在通用校验里直接要求登录完成 | 仍在登录页时触发 `reconcile()`，已有宿主逻辑将请求置为 `retired`。 | 用户是否已登录由确认动作独立核验。后台等待期只校验任务、页和身份等归属。 |
| 用户过早确认，随后原页登录并恢复 | 过早确认返回继续等待，请求和 revision 保留。原轮退出过程中保持等待，宿主请求服务重新构造后仍可查。原页登录成功后，两次并发确认有一次被接受。新运行两次尝试绑定，恢复动作只发出一次，旧 revision 拒绝。 | 确认前检查业务标记，批准确认沿现有请求 CAS。新运行登记后再匹配绑定和原页。保留启动通知和最终结果的各自身份。 |
| 批准后、完成绑定前登录态再次失效 | 重新加载回到登录页，绑定失效，零恢复动作。 | 新运行真正接手前重新检查当前业务页。 |
| 批准后、完成绑定前停止任务 | 请求落为 `retired`，新运行没有恢复动作。 | 停止和撤销继续复用现有宿主请求的退休路径。 |
| 同一真实页面两次执行报表，第二次回包中断 | 经失效入口和帮助页面到达工作台。验证真实 DOM 旧按钮被替换并保留两个重名候选，作为旧引用失效前置。两次均实际只提交一次。第二次读回同记录号后下载。两份 CSV 已真实落盘并核对记录号和月份。标签 WebContents 与登录身份保持一致。 | 报表可作为 R03/R04 的共同夹具，原结果的只读核验与实际产物都有固定判据。 |
