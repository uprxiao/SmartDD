## 隔离 Electron 实验

从上述提交导出只读源码，打包现有 `BrowserWorkspace`、`BrowserPageRegistry`、`BrowserCdpProxy`、`BrowserOperations` 到独立驱动。Electron 42.11.14 / Chromium 148.0.7778.280，临时 HOME、userData、内存库和本机 HTTP。登录由驱动在实际网页上提交合成表单。场景使用真实 WebContents，包括主进程路由与浏览器分区。本次不运行任务区 Renderer、启动真实 Agent 或连接生产站点。 [脱敏结果](证据/60e7f6545-electron.json)

| 实验 | 操作与观察 | 设计依据 |
| --- | --- | --- |
| E01 先有标签，再加载内容 | 服务端先接收请求，扣住响应。调用 `BrowserWorkspace.create` 返回时实例尚未创建，已带目标地址与 `loading`。单次返回约 3.3 ms，请求到达一次。扣住响应期间没有挂载已提交内容视图。放开后原 ID 装载真实业务标记，驱动观察就绪约 330 ms，含夹具安排的停顿。 | 可复用现有早回执模式。R01 的判据应是右侧先出现加载中的标签，然后再等待网页可操作，分别测量。单次测量仅说明顺序。 |
| E02 同标签登录续接 | 首次登录后核对业务页标记。同一身份的另一页直接进业务页，另一身份进入登录页。服务端让会话失效，原页重新出现登录表单。再次提交后，原 tab/profile 和 WebContents ID 保持一致，另一身份仍无会话。 | Electron 分区和页面身份足以承接任务登录接力。宿主提醒、跨轮唤醒和真实 SSO 仍是独立链路。 |
| E03 写入后回执不明 | 本机站点计数加一，回包只发送部分正文，使客户端读取失败。操作账本从 running 恢复为 unknown，原请求编号再次登记命中原记录。用原页只读查询发现恰好一条业务结果。 | 可把宿主回执和业务确认分开。实验通过账本和合成失效夹具搭接，仍需在 Agent 和实际命令层联通全链路。 |
| E04 单页 CDP 与 Playwright | 单页代理只列出一页，可读真实 AX 树，阻止浏览器级全局下载设置。Playwright `1.57.0` 与 `1.63.0` 默认通过 WebSocket 连接均因 `Browser.setDownloadBehavior` 被拒绝。 `1.63.0` 的 `noDefaults: true` 握手成功，`pages()` 为零。 | 现有代理足以支撑受控页面工具。现有两版 Playwright 的默认连接无法直接运行依赖 `Page` 的脚本。 `noDefaults` 文档说明其作用是跳过默认上下文设置。 [Playwright 官方文档](https://playwright.dev/docs/api/class-browsertype#browser-type-connect-over-cdp) |

原始驱动、两个尝试和固定源码保存在本机 `/private/tmp/willyou-m15-predev.MPfm4Y`。最终结果 SHA-256 为 `3e2ac94362252112f25acc7559b134619325af0d9d14c714319dd432269cda32`。首次 E03 的注入只断开连接，驱动没有观察到约定的客户端失败。留存首次记录，换成明确截短响应正文并读取正文，使用全新 userData 复跑。库、文件和浏览器都在隔离实例释放后结束。研发资料仅归档脱敏结果，临时目录不作为长期来源。
