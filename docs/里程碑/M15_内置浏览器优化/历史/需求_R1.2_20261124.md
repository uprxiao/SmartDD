# M15 内置浏览器任务自动化优化

R1.2 开发评审定稿，2026-11-24。来源为 F34。2026-11-23 用户已确认阶段顺序和四项范围。2026-11-24 用户授权补齐开发前评审资料，正式开发由用户另行确认。目标平台为 macOS arm64 打包 App，登录、身份管理和右侧任务区分别接续 M12 和 M14。 [需求池](../../需求池.md) · [M12](../M12_浏览器自动化/需求.md) · [M14](../M14_统一Agent工作区/需求.md)

## 用户目标

用户给出站点和业务目标后，Agent 在 WillYou 右侧浏览器中找页、操作和核对结果。有可复用的标签就继续在同一页做，明确要求另开或没有合适标签时新建。需要本人登录时保留原页，完成后接着走。重复测试可以将同样的业务步骤写成脚本执行，并核对页面或产物。

## R01 复用标签并及时显示

- 一次开页可按目标匹配或新建，并处理展示意图。目标为网址或指定标签，使用任务选用的浏览器身份。按当前任务、同一身份和完整网址匹配，保留路径、查询参数和锚点。指定标签要核对归属和身份。没有合适页或明确要求另开时创建。并发复用请求共用同一待加载页。相同请求编号只返回原回执，改动目标、身份或开页意图须用新的请求。
- 用户明确要求打开或展示时，当前任务右侧先选中目标标签，新页先显示加载状态，再在同一标签更新就绪或失败。纯后台取资料时保留当前视角。发出展示意图后，用户切任务、面板或标签会使旧展示失效，即使随后切回原处。迟到结果留在原任务，可通过「查看网页标签」进入原页。
- 区分已接收、加载中、可操作、失败和取消。页面可操作以原标签的主文档已打开且约定的业务条件可核验为准。停止任务、撤销授权、关页或用户在同一标签改址使旧导航失效，迟到结果不得恢复旧页。失败后可在未关闭的原标签重试。

## R02 登录接力和继续执行

- 优先使用任务为该页选定的身份。同身份已有会话可直接开始。遇到首登、过期或站点要求本人验证时，提示在原页或该页的认证弹窗处理，并保留当前任务、标签、登录身份及已确认进度。依赖该页的步骤持续暂停，原运行结束后也保持等待。
- 本人从任务卡点击「已登录，继续」后，核对原任务页已回到业务范围且具备可读的业务标记。弹窗已登录时仍需核验原业务页。过早确认保留同一张卡和确认版本，并说明原因。原执行轮结束时，核验通过后绑定可接手的运行，同一确认只继续一次。密码、验证码等由本人在站点表单或现有认证框输入。
- 用户取消、停止、关页、换身份或撤销授权后，此次继续入口失效。App 重启时，仍待确认的请求保留等待状态。已确认且能证明尚未派发的请求，在重新核对原任务绑定、标签、身份和业务状态后可自动继续一次。若只是认证过期，原卡进入新版本并请本人重确认。用户已停止的任务保持停止。派发结果不确定时转入 R03 的只读核对。

## R03 探路和核对业务结果

- 通过页面结构、可访问名称等信息在已授权范围内寻找入口。路径失效、跳转、弹窗或元素变化时，重新读取现场，再选替代路径。必要时可参考用户允许访问的帮助资料。关键能力覆盖实际页面变化和从备选路径完成任务。
- 分别反馈页面观察、工具动作和业务结果。业务完成须通过状态、记录编号、页面内容或实际下载文件核实。下载场景至少核对文件存在和用例规定的内容。失败、取消和结果未决均能定位到原步骤及已留存的回执。
- 写入可能已派发时，按原编号和任务归属只读查询原回执或业务结果，后续运行沿用同一检查点。网站响应丢失和工具回执丢失分别核对。无法判定时显示「结果待核对」，暂停依赖操作并保留原步骤。旧回执过期或详情找不到时仍保持未决。这次操作不得被再次派发。

## R04 对当前页执行可复跑脚本

- Agent 可写版本化、多步骤的浏览器脚本，在任务获准的一个标签、身份和业务站点范围内执行。首版用结构化步骤调用已有页面操作，支持读页、等待、业务表单填写或选择、点击、断言和下载。步骤、失败点、断言及产物均可追查。
- 每次派发核对当前标签、身份、业务站点和授权。明确超出站点范围的计划在派发前拒绝。站点自己触发的越界顶层跳转使脚本停在当前步骤，后续脚本动作停止。合法认证转移按 R02 暂停并由本人接力。原业务页通过核验后再继续。
- 按审阅的计划和授权执行。重放同一执行编号返回原计划摘要和结果，同号更改计划会被拒绝。结果未决时按 R03 停在原步骤。变更计划或有意再次执行时，使用新的执行编号并核对当前授权。审批记录与任务历史不保存凭据和完整表单值。
- 首版为受控步骤脚本。通用 Playwright 及任意 CDP 脚本待独立适配验证，定时触发另见 [M16](../M16_定时任务/README.md)。

## 交付与验收

第一批用同一条需要登录、入口可调整且结果可核对的站内流程验证 R01–R03。第二批用同一流程验证 R04，对照 Agent 逐步操作与脚本复跑。一次工具调用可开页并按意图展示，既有手动链接、CLI、MCP 入口及权限继续按实际运行计划验证。显示顺序、身份和站点范围、同一确认只续接一次、未决写入的防重是硬性判据。

四段时延为开页授权就绪至右侧可见、同口径站点请求至业务标记可读、业务操作至结果核对、整轮任务。显示顺序实验和配对测速使用各自约定的响应条件。性能门槛、实包用例和正式登录前置分别见技术方案与验收用例。 [技术方案](技研/技术方案.md) · [原型状态说明](原型/原型说明与变更.md) · [验收用例](验收/测试用例.md)
