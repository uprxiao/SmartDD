# M15 内置浏览器验收用例

A1.1 开发前评审稿，2026-11-24。共 28 条。依据 R1.1、T1.1、P1.1。表内状态为候选包正式验收状态。开发前基线和夹具的结果见执行准备。 [需求](../需求.md) · [技术方案](../技研/技术方案.md) · [原型状态](../原型/原型说明与变更.md)

## 环境与准备

- U 为单元，I 为主进程、浏览器服务或真实 Electron 组件集成，A 为 macOS arm64 隔离打包 App。每条须完成标注的全部层级。A 层从任务区和右侧界面走真实交互，使用当前隔离包 UI 驱动。允许读取服务回执、数据库副本与证据文件作断言。
- 使用统一的合成本机「报表站点」。账号 A 的业务页有「报表中心」标记，B 身份独立。登录后可使会话过期，首页的旧报表入口可调换或失效，替代入口在业务页面和站内帮助中可找到。提交十一月报表会生成唯一记录号与 CSV。每条或每组使用独立记录标识。站点能保持响应、按约定截短回包、返回错误、开启站内弹窗并统计真实提交及下载次数。
- R01–R03 与 R04 分两批执行。先把 S1 开页、S2 登录接力、S3 探路和核对组成连续流程，再跑 S4 脚本。同一候选包内可批跑正常用例，权限、重启、故障注入使用独立任务与身份。界面状态覆盖浅／深色、窄窗、长网址与键盘可达性，截图记录包版本和尺寸。
- 完整流程由启用内置浏览器的任务执行。确定性场景可用受控执行器触发真工具，Agent 自主探路和整轮延迟使用实际支持的执行器，记录 CLI/MCP 入口、Agent/模型与输入。真实站点使用用户授权的独立验收账号，由用户完成需本人处理的登录或认证。验收前记录站点、登录流程、成功标记与可操作范围。
- 用例通过需要观察到规定的状态和结果。网络、操作超时必须有条件观察和上限。截图、下载摘要、操作回执、服务端计数和性能事件在执行时入账。现有基线回归和独立实验见 [合并后复验](../技研/实验/合并后复验_20261124.md)。

## 执行准备

本机合成夹具只监听回环端口。每个场景用唯一标识对应服务端访问记录、登录计数、写入记录、下载计数和 CSV 内容。脚本入口保存在仓库，现场的包、数据库和临时运行材料用独立目录。 [报表夹具](../../../../scripts/browser/m15/report-fixture.mjs) · [夹具自测](../../../../scripts/browser/m15/report-fixture.test.mjs) · [旧包 UI 驱动](../../../../scripts/browser/m15/baseline-app.mjs) · [登录实验驱动](../../../../scripts/browser/m15/run-login-study.mjs)

| 适用用例 | 启动与取证准备 |
| --- | --- |
| A01、A05、A08 | `create(key)` 后给 `controls.openGate` 设置受控 Promise，等服务端记录 `open` 后检验 UI 与事件，再放行。用 `openFailure` 制造失败并恢复。停止、关闭的证据核对实际页面请求、同一标签的事件和当前页。 |
| A02–A04、A06–A07 | 用同一 `open` 加月份查询和锚点，分别在测试任务和两个浏览器身份内准备标签。通过隔离 App 的真实任务栏与面板按钮切换。A06 服务集成层可延迟选中事件，App 层以实际批准前后和用户操作时间取证。记录新旧标签、选中项、身份和真实请求次数。 |
| A09–A11、A13–A14 | `desk` 在无会话时转到 `login`。登录后等 `#business-ready`，可用 `expire()` 令原身份真正失效。需要重启时保存独立 App 的请求 ID、revision、绑定、标签 ID 和已确认进度，使用同 userData 启动新进程。记录过早确认、取消、停止、关闭、换绑、重启与恢复计数。 |
| A12、A18 | 从 `auth-start` 的真实网页链接开认证弹窗，`basic` 返回鉴权挑战。已登录 `desk` 的详情链接打开业务弹窗。单独准备另一个身份和无关标签；对照所属原页、认证后业务标记及其独立计数。 |
| A15 | 确定授权站点、测试身份、首次登录入口、过期引导、允许的只读业务标记和记录留存范围。真实账号凭据只触达该站点。若站点要求 SSO/MFA，由用户本人完成，继续核验原标签和标记。未具备条件时记录具体缺项。 |
