## 1. F16 目标、范围与评审基线

让用户预先配置任务提示词、运行时间和智能体，WillYou 在应用实际运行期间按计划发起普通 Agent 任务，并可查到每次执行的真实任务、回合和结果。**新增的是计划和调度管理，不是另一套 Agent、工具、审批或对话系统。**

- 包含：创建、编辑、启停和删除计划，立即执行，各类日程和时区，项目可选与工作区，任务／会话去向，普通任务的三种 Agent、Provider、模型、推理强度、委派及工具能力，冲突处理、补跑与恢复、运行历史和通知。
- 不包含：独立后台常驻进程、真正退出或关机后执行、唤醒机器、Webhook（F37 单列）、新的 Agent／插件体系、计划专属目标模式 `/goal`、自动合并或推送计划工作树、跨项目隐式授权。
- 依赖：M12／M13／M14／M15 已确认的浏览器、扩展、Agent／Provider、单／多 Agent 及项目工作区合同。F36 同属 M16，但为独立浏览器承载重构；联动验收以 B12 为准，不把 F36 的独立工作算进 F16。
- 平台：本项目现有桌面平台。macOS 的隐藏/退出合同是首要验收目标；Windows、Linux 沿用各自真实关闭行为，发布覆盖以实际平台验收为依据。本轮隔离专项仅在 macOS arm64 执行，不代表其他平台已通过。
- 基线：2026-11-25 七轮用户明确确认的 F16-R0.3 业务决定，经 E01–E09 专项形成 R1.0 完整评审稿。下列时间边界、内部归属与故障恢复的细化基于技术实验；本轮提交用户整体评审，**尚未授权正式开发**。

| M16-R02 | 管理计划 | 列表、搜索／筛选、启停、编辑、立即运行、删除与修正入口；管理操作与运行状态独立 |

| M16-R04 | 运行历史和定位 | 计划时点／实际时间、触发来源、状态、耗时、原因、重试及真实任务／回合／工作区定位，保留原记录 |
| M16-R05 | 异常与恢复 | 睡眠、退出、时钟／时区变化、宽限、同计划／同任务冲突，启动失败、未知／已产生效果、配置和工作树失效 |

核心流程：配置与预览 → 存储计划及下次时点 → 到期或手动领取 → 创建或续接实际任务 → 执行并归账 → 查看结果、处理请求或修正计划。计划状态与逐次运行状态严格分离。

## 3. F16 现行规则

### 3.1 运行机制（第一轮；R03、R05）

- 调度在 WillYou 主程序和任务服务启动完成后运行；应用打开、最小化、处于后台以及 macOS 红色关闭按钮隐藏窗口期间，启用计划继续调度。界面或 renderer 重载不重建调度器、不重复领取。
- 真正退出（如 macOS Command + Q，其他平台实际退出）后停止调度，保留数据。原有运行任务、退出确认、工作区关闭处理不变；用户取消退出则恢复正常调度。睡眠或关机期间不保证执行，设备唤醒或重新启动后依 §3.5 判断，不新增常驻服务。
- 到期后正常运行且主机未挂起时 **5 秒内进入派发**为本期验收目标，测量实际应到时点到持久领取／进入真实任务准备流程（不包括 Worktree 依赖安装、CLI 冷启动后的模型回答耗时）。没有启用计划时不空轮询；多个到期计划不因另一模型长时间工作而阻塞。

### 3.2 项目与工作区（第二轮；R01、R03、R04、R06）

- 项目可选。关联项目时选择该项目实际已登记且可用的目录；不关联项目时系统分配稳定独立目录（默认，首个实际运行时创建），也可选择本机已有目录。空或不可用显式目录不能保存或派发；不会把其他目录默认为替代。未关联任务显示在既有任务侧栏的“未关联项目／通用任务”分组，历史、搜索与普通任务一致，不为每个计划／运行创建普通项目。
- 定稿选择真正空项目归属（`project_id/dir_id=NULL`）与显式通用作用域，复用实际 cwd、文件和任务服务。有明确工作目录，可使用适用的全局 Skill／MCP 及普通 CLI（即使显式选择的目录物理上等于某个登记项目目录，也只按通用 scope 授权，不继承项目工具）；通过现有 profile 服务为通用任务提供独立浏览器身份，复用同一真实任务时保留该身份，新建任务有独立任务身份，不能自动取得其他任务或项目的浏览器标签、连接、凭据和授权。显示和作用域依据技术方案；不能以新建假项目实现。
- 工作区和会话是两个不同维度。Git 登记目录支持现有目录（默认）、计划专属 Worktree（首次实际执行时建立，后续沿用）、每次新建 Worktree（每次从选定基准分支建立）。SVN／普通目录、无项目只使用现有或受管理普通目录，不提供计划 Git Worktree。
- Worktree 归属原项目和实际 Git 仓库，沿用 `~/.willyou/worktrees/` 登记根。源仓库与选定基准引用校验后，创建时记录当时解析的实际提交、分支、路径及计划／运行／任务关联；原目录当前未提交更改不复制，不套用子任务自动提交策略，不自动合并或推送。
- 首次准备前预留稳定身份并记录实际步骤，中断后核对已登记路径、仓库和分支／提交；确认为同一准备结果才复用，未知不另建重复副本。工作树或基准分支失效给出具体修正入口。暂停／删除计划不删除工作树或分支，用户明确清理时沿用原管理机制。

### 3.3 任务去向及配置（第三、六轮；R01、R03–R06）

| 工作区 | 每次新建任务（默认） | 持续复用同一任务 | 继续指定任务 |
| --- | --- | --- | --- |
| 现有或通用目录 | 支持，独立新会话 | 支持，首次创建后绑定、续聊 | 支持，须同一归属并沿用任务实际 cwd |
| 计划专属 Worktree | 支持，各新任务使用同一工作树 | 支持，首个运行建立树并绑定 | 不另外创建或迁移树；指定已有任务直接沿用其实际 cwd |
| 每次新建 Worktree | 支持，各有独立树和新会话 | 不支持，禁止不合法组合 | 不支持 |

- 名称及任务提示词非空；创建／编辑复用普通任务 Agent＋Provider 配置和模型／推理档位，模型目录及实际支持的档位由现有服务决定，不固定某个 CLI 版本或擅自换账号。默认权限“请求批准”；支持的权限档位沿现有执行器（Codex 可含“帮我批准”，不对不支持的其他 Agent 伪造该选项）。默认新任务、现有目录、单 Agent；可开启现有多 Agent 委派。编辑已保存计划时权限变化须由本人明确查看并确认后保存，沿原完全访问确认机制；取消确认保持旧档位，正在执行的快照不提权。提示词使用普通任务支持的 Skill／文件引用与工具，不以计划文本自动设置 `/goal`。
- 每次新建任务：每个运行有新任务、新原生会话和独立输入；只传计划及允许工作区内容，不注入上一回合聊天。连续复用：第一次实际运行创建并持久绑定，随后恢复原生会话并续接上下文；指定已有任务则绑定用户选定的有效任务；两种均使用 M14 已有的运行和会话恢复机制。
- 已绑定任务使用其实际 cwd、当前 Agent／Provider 及权限；同一 Agent 和 Provider 兼容身份内模型、推理档位可跟随当前值。Agent、Provider 或其兼容运行身份（端点／账户等）、cwd、权限或影响绑定执行的委派配置变化时，计划进入需重新确认状态，展示差异，用户明确确认后按新配置执行；不静默改回原配置或提权。实际任务归档、目录或配置失效时标“需修正”，不生成替代任务或切账号；修正后按未来日程执行。对绑定目标的校验在保存和每次派发前都进行。
- 独立计划可同时执行，即使同项目；同一计划／实际绑定任务有未收口的运行、等待本人或普通任务占用时，自动触发跳过，立即运行提示原因且不产生第二次任务执行。不得把定时输入塞进既有排队入口等待迟到执行。用户在普通任务中的发送沿用现有队列，调度不能抢占。

### 3.4 日程、时间校验与预览（第四轮；R01、R02、R03、R05）

| 日程 | 规则 |
| --- | --- |
| 固定间隔 | 至少 1 分钟、正整数且在可表示范围；从首次保存或语义改变的间隔起算，不因运行耗时、手动运行、暂停／恢复或展示时区变化而漂移 |
| 每天／工作日 | 指定时分；工作日为周一到周五，不引入法定节假日历 |
| 每周 | 至少选择一个星期，可多选 |
| 每月 | 选择 1–31 日或最后一天；月份没有指定日时跳过，不自动提前至月末；最后一天按实际月份长度含闰年 |
| 仅一次 | 选定有效未来日期和时分，保存时解析为绝对时刻；跟随本机只影响初次解释和展示，之后改变时区不改变绝对时刻 |
| 自定义 Cron | 五字段（分、时、日、月、星期），支持数字、英文月/星期名称、列表、范围、步长；星期日 0/7；月日/星期均为非通配限制时任选其一匹配，否则同时符合；不支持秒、L/W/#、@ 宏，非本期 Webhook |
| 立即运行 | 独立手动触发身份，任何有效的非删除计划均可手动运行（包括暂停及已结束的单次计划）；不改变自动日程、不消耗还未执行的单次时点 |

- 日历日程默认跟随本机时区，也可指定有效 IANA 时区；无效时间、日期、表达式、没有未来时点（日历检索覆盖至少含世纪跨越的闰日间隔）或非法组合提示原因，不能创建不可运行的计划。创建／编辑显示接下来至多三次有效执行时间；宿主与预览使用同一计算合同。
- 经 E01 验证的时间边界：夏令时不存在的周期墙钟时分跳过（仅一次选中不存在时刻时拒绝保存）；重复墙钟时分运行第一次，固定绝对间隔不受夏令时影响。周期跟随本机时，在系统时区更改后重算未来时点，不追派旧区历史；同一墙钟周期时点不得二次领取。手动改变系统时间、重启及唤醒都通过持久发生身份去重；固定时区日历不随本机变动。
- Cron 是用户确认的首版定制日程；E01 选择以上常见五字段方言与 DST 口径作为此次整体评审的技术细化，不声称七轮已另行逐项批准。

### 3.5 调度、补跑与异常恢复（第五轮；R03–R05）

- 宽限可选不补跑、10 分钟、1 小时（默认）、12 小时；应用退出／睡眠／长时间阻塞后，若多个历史时点已到，只考虑最近一次，记录被合并跳过的范围。当最近一次距当前时间未超过宽限则派发，否则记录超宽限跳过；不补跑时恢复不迟补（正常在前台或后台即时计时的 5 秒派发容差不等于恢复宽限）。时点恰等于期限仍有效。暂停期间不积累待跑任务，恢复仅计算未来日程。
- 到期领取需原子校验计划修订、是否启用、对应发生身份和同计划／真实任务占用状态；每一发生身份仅一条稳定运行记录。手动请求也具有唯一请求身份，重复提交返回原结果。创建／提交前持久化稳定任务／输入身份，实际接受回执、对应回合及工作树身份可核对；重启、重复事件、 renderer 重载不重复运行。
- 启动阶段故障只有能证明原输入未被接受且原触发仍有效时自动重试一次，保留同一运行／任务／输入身份与尝试记录；不能证明时进入“结果待核对”，暂停该计划／绑定会话的后续派发并核对实际任务/原生记录。已接受、已发生部分操作后的失败不自动重试，用户修正后可发起一次新手动运行；保留原记录、工作现场和失败原因。额度、限流按 M14，不换账号/执行器；用户主动停止不自动重试。
- 配置失效与绑定重新确认分别提示具体原因，保存有效新配置后才继续，历史及正在执行的快照不变。故障恢复依据持久接受回执和实际业务效果，不用模型文字或单纯超时认定成功／失败。

### 3.6 权限、工具与通知（第六、七轮；R03、R04、R06）

- 计划来源由宿主真实登记，不当真人提交/批准；定时任务调用普通 Agent、Skill、MCP、CLI、内置浏览器和现有项目/通用作用域，单／多 Agent 执行沿用原负责人与子任务收口逻辑。
- 插件读及写沿用项目和连接/能力授权，按已有权限档位和操作声明上限裁定。**不采用无人值守插件写操作一律拒绝。** 授权范围内读取按原规则；支持直接写且实际权限和能力上限均为完全访问时直接执行并留账；请求批准、帮我批准或能力上限要求审批时进入原实际审批请求，未获真人批准不执行等待中的操作。Agent 不冒充用户，也不把“立即运行”等同批准。
- 发送邮件沿用现行逐次本人审阅和确认的特殊合同，无本人批准不发送。无人值守任务申请新增跨任务网页授权默认拒绝（M14 A37），并区分已有合法本任务身份/授权及后续普通真人任务；工具系统和 F36 浏览器宿主均不为定时任务重造。M14 移入 A72 使用新权限合同，原普通任务验收保留。
- 系统通知默认提醒实际失败、等待处理／审批、配置失效及需核对结果；正常完成默认不通知，可单独开启；开始、正常跳过不通知。按真实请求 ID 或同一运行状态转换去重；同一运行后来产生的新请求仍可通知。点击定位实际任务、对应回合／等待请求，任务不可用显示可理解原因。系统通知关闭或无权限时保留应用内待处理和历史入口，不能把通知发送当成业务完成。

### 3.7 计划管理及结果（第七轮；R02、R04–R06）

- 计划列表显示名称、项目/未关联项目、智能体（Agent、Provider、模型与推理强度）、频率、下次执行、最近结果、启停入口，支持搜索、按计划状态筛选。计划详情展示全部配置及运行历史。计划状态启用、暂停、需修正／确认、已结束、已删除，独立于运行状态待派发／准备、工作中、等待处理、已完成、失败、已跳过、已停止、结果待核对。一个运行需要多 Agent 子任务时持续跟踪所属工作，直到该次任务树及结果通知收口；不是仅主回合结束或任意当前 task 全局状态就判定成功。
- 编辑对未来生效，已实际接受的运行持有派发时的配置快照；领取及准备但尚未真实接受输入的旧修订，在接受前再次核对计划。若已编辑、暂停自动计划或删除，则本次无实际提交，记录因变更跳过及已准备资源；手动执行在暂停或已结束时仍可按有效配置发起。暂停停止后续自动触发，恢复未来日程，保留手动运行能力，均不自动停止已接受的运行。停止本次运行通过原任务/回合/相关委派身份操作，不等于暂停，也不得误停更晚的普通回合。
- 删除计划停止后续派发，不自动停止已经领取并开始的运行；不删除已产生的实际任务、记录、目录、工作树或分支。历史和当前运行终态仍可查看和结算；若实际任务另被归档／删除，显示真实不可用原因，禁止链接错误会话。
- 每一运行记录包括计划标题和修订、触发来源、预定时点、实际开始和结束、耗时、状态、原因、尝试次数、实际 Agent/Provider/模型/推理/权限配置、真实任务/输入/回合、工作目录/工作树与基准分支提交。历史列表显示结果摘要或真实状态原因，不以内部任务 ID 作为结果。点击运行记录或对应应用内通知进入独立运行详情页（非大弹窗），保留定时任务导航；支持返回原计划及同计划上一条／下一条。抬头显示运行状态、Agent/Provider/模型与时间耗时；技术字段默认折叠于「本次运行配置」。
- 运行详情提供「运行结果」和「执行过程」：完成默认查看本次回合真实最终回复及实际产生的成果文件／链接；待派发、运行中、等待处理默认展示实际任务提示词、过程事件、工具结果及已有输出，待处理显示原请求入口；失败、停止保留真实原因和部分输出并标注非最终结果；跳过显示原因而不虚构任务，结果未知仅显示原回执核对入口。无输出、无已确认回合或原任务不可用均如实提示。查看结果不重新运行、不重新请求模型，也不取该 task 后续无关回合的输出。
- 「查看完整任务」仅在真实关联可定位时跳到原统一任务区并聚焦本次回合／request；复用同一任务仍精确定位该次回合。停、重试、审批入口沿现有真实操作。失败后新建手动运行记录，原失败不覆盖；未知先核对，不提供盲重试。
- 仅一次计划在预定触发获得终态（完成、失败、停止、错过跳过等）后保留为已结束，无后续自动时点；手动提前执行不消耗原时点，已结束允许查看历史、手动运行或明确编辑新未来日期再启用。旧运行终态不终结已经另行改期的新时点。

## 6. F36 内置浏览器单窗口承载重构（R1.0）

**需求版本：F36-R1.0，2026-11-25 开发前评审定稿。** 根据用户确认的底层重构、保留现有 UI 的方向，以及 BE00–BE08 和 Ultra Review 的分层实证，将 R0.2 及后续澄清合并为现行需求；本节是 F36 业务规则的唯一维护位置。待 M16 整体评审及正式开发授权，不代表已实施或验收。父需求为 F25／M12 浏览器自动化、F34／M15 内置浏览器优化，沿用 [M12 现行需求](../M12_浏览器自动化/需求.md)、[M15 现行需求](../M15_内置浏览器优化/需求.md)的已确认合同，除本节明确纠正的缺陷外不改变原业务。

### 6.1 背景、目标与边界

- 问题：普通网页的透明后台窗口可能出现在 macOS 调度中心或独立全屏空间，产生黑框；关闭旧标签后新请求可能沿用失效目标，或后台开页成功但未及时显示到右侧。已复现若干旧代码竞态，未取得用户原始现场的完整事件链，不将实验复现认定为全部现场问题的唯一根因。
- 目标：以 Electron BaseWindow＋WebContentsView 建立可长期维护的单主窗口承载层，借鉴 Orca 的页面生命周期与按需绘制思想，让普通网页在主窗口内保活，前后台切换、重开、并行任务、宿主隐藏和恢复行为一致。不是简单隐藏旧后台窗口，也不迁移到 WebView。
- 范围：主窗口与可信界面适配、页面生命周期与原生层级、后台绘制保活、标签关闭重开及 Agent 展示链路、现有工具和数据兼容、异常收尾、受影响工作区和系统回归。
- UI：沿用 M12／M15 已确认的浏览器与工作区页面、布局、字体、主题、入口和正常交互，不进行视觉改版或新增独立页面；仅纠正加载、关闭重开、展示、失败、错误提示、焦点与其他故障状态。允许为此变更 renderer 的宿主适配及状态协调逻辑，最终按现有界面对照验收。
- 不包含：更换 agent-browser／CDP／应用能力体系、浏览器插件市场、Computer Use、修改外部网站、扩张网页／业务权限、变更 F16 调度规则。必要且合法的用户可见登录子窗、系统对话框等不属于本次取消的普通网页背景窗。
- 平台：首先完成 macOS arm64 真实打包 App 验收，继承 M12 的 macOS x64 兼容与真机验收边界（原 T141 曾因无 Intel 真机暂缓，按实际条件登记）；Windows／Linux 不新增首版验收承诺，维持现有跨平台代码约束。不能以本机探针推定其他平台通过，改变已确认交付边界须在评审中明确。
