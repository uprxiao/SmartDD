## B. F16 定时任务技术设计草案 D0.2

依据：[F16-R0.3 需求 R01–R06](../需求.md)、[T3 Code／Orca 与 WillYou 源码核对](../调研/F16_T3Code与Orca定时任务源码对照_20261125.md)，2026-11-25 七轮用户决定，代码起点 `feature/0.1.7`、`a0acddb3a`。以下为设计草案：框架和业务约束已确认且可追溯，具体接口名、表结构、选型及阈值需隔离实验；未授权正式生产开发，不将原型模拟结果当成技术验证。

### B1. 背景与目标

让用户预先确定提示词、执行日程、工作目录、任务去向与智能体配置，WillYou 运行期间到期发起实际任务并记录结果。**新增的是调度与计划管理，不是第二套 Agent、工具、权限或对话系统。** 计划可不关联项目；不纳入独立常驻后台服务、退出后执行、Webhook（F37）或计划任务的 `/goal`。F36 的浏览器宿主改造保持独立，使用其通过验证的通用能力完成联动。

### B2. 整体设计思路

```text
定时任务 UI ──计划管理／预览／查询──> 宿主计划服务
                                          │
应用启动／唤醒／下个到期时间／立即运行 ──> 调度与运行领取
                                          │
                              工作区、绑定任务、配置校验
                                          │
                              现有 AgentTaskService
                                 创建任务或追加回合
                                          │
            原执行器、委派、Skill、MCP／CLI、浏览器、插件
                                          │
                                  原任务事件／审批／结果
                                          │
                 计划运行账 <── 状态及关联 ──> 原任务页面
```

1. **宿主生命周期**：调度放主进程；界面仅配置及展示，隐藏、最小化不停止调度，真正退出停止新触发并按现有任务收尾。参考 `src/main/app/window.ts`、`src/main/index.ts`。启动及恢复时核对未收口记录、重新计算日程，按需求宽限处理最近一次。
2. **定义与运行分离**：保存一份计划定义，另记每次触发／跳过／派发及真实结果。用稳定触发身份保证重复计时或进程恢复不产生重复任务；计划修改不改写已有运行的依据。
3. **执行与展示复用**：用普通任务创建、回合队列及现有事件驱动实际运行，历史只保留本次关联与必要摘要；中央任务区、请求入口、业务回执、文件和网页能力继续由原模块维护。
4. **工作区与会话分离**：项目只是业务归属，实际工作目录是运行位置；工作树不产生新项目。新建／复用任务和目录策略按已确认兼容关系裁决。

### B4. 详细设计

#### B4.1 调度与实际任务交接

| 步骤 | 处理及约束 |
| --- | --- |
| 计算日程 | 结构化日程支持需求已确认类型；固定间隔使用持久起算基准，日历及 Cron 使用选定时区，单次保存明确时刻。预览和宿主调度使用同一计算规则。Cron 方言、间隔起算／编辑边界、夏令时重叠及不存在时刻，待 E01 选择并定稿。 |
| 到期领取 | 按启用且到期的计划查询，事务内重新核对计划修订、时间、暂停状态，领取唯一触发并登记运行。恢复按最近一次及宽限判断，其他过期时点不补发；记录跳过及原因。手动立即运行使用独立请求身份，不改周期。 |
| 冲突判断 | 同计划已有未结束运行、或绑定会话忙碌时跳过。跨计划竞争同一会话需在任务实际接受处原子检查，不能仅凭 UI 状态；独立任务继续并行。 |
| 准备目录 | 取得计划对应目录／已登记工作树，必要时才创建；冻结实际身份和基准、核对当前路径有效。准备失败不启动其他目录作为替代。 |
| 解析配置 | 新任务按计划选择；绑定任务跟随允许的模型和推理强度变化，Agent、Provider、目录或权限档位变化须重新确认；核对实际执行器能力及当前连接，不隐式换账号或放行。 |
| 创建／提交 | 先持久保留任务创建及输入的稳定标识，再调用宿主已有创建／提交能力；现有 `clientTaskId`、`clientInputId`、选择修订和事件回执作为复用点。宿主需区分定时触发、普通真人输入与系统通知。是否需把领取和任务接受置于同一持久边界由 E02/E03/E08 确定。 |
| 跟踪执行 | 标明计划／运行来源，关联真实任务、输入、回合及执行器运行，跟踪子任务与在途审批。消息接受不等于工作完成；在原运行确有终态且相关工作收口时结算。 |
| 恢复 | 首次派发结果未知先核对已有记录。只有确认输入未实际提交、属于可重试的临时启动失败且原触发有效时，复用原运行身份重试一次；不能把部分执行的任务整个重发。 |

#### B4.2 工作目录、会话与通用工作区

| 情况 | 设计职责及证据 |
| --- | --- |
| 已选项目／目录 | 复用现有项目 ID、登记目录 ID 及 cwd 实际校验；读取当前项目启用的业务能力及配置。 |
| 计划专属 Worktree | 首次实际运行准备，登记计划与工作树的稳定关联，后续复用该路径／分支；丢失、改动或身份不符时提示修正，不新建替代目录冒充原会话。可独立新建会话。 |
| 每次新建 Worktree | 每次为该运行分配独立工作树，记录基准分支／提交及实际位置，绑定新任务。不把原目录未提交内容带入、不自动合并推送。 |
| 不关联项目 | 用户可使用系统分配的独立目录或选择本机目录。现有任务表 `tasks.project_id`、`dir_id` 可空而 cwd 必填；普通新任务 IPC 依旧要求项目。当前无项目任务不注入项目业务能力，所以需通过 E06/E09 比较真实空归属与系统受管理通用工作区，确认文件面板、普通任务归类、独立浏览器身份和工具授权；不创建普通项目或继承他项配置作为捷径。 |
| 保留与清理 | 复用登记根 `~/.willyou/worktrees/`；现有工作树服务按子任务记录身份，需适配计划和顶层任务。保留工作树与分支，开放已登记路径的明确定位及原管理机制，用户主动清理；不套用写入委派子任务的自动提交策略。 |

绑定已有任务时不迁移其 cwd，只使用其实际目录与会话。复用会话沿用原生恢复和 M14 递增交接；每次新建任务只继承计划及允许访问的工作目录内容，不导入前次聊天上下文。

#### B4.3 接口职责（拟议，不是现有 RPC 名称）

| 接口目的 | 输入 | 输出／状态 | 对应 R |
| --- | --- | --- | --- |
| 日程预览 | 日程、时区、参考时刻 | 校验结果、接下来执行时点 | R01 |
| 计划管理 | 计划定义、保存修订；启停／编辑／删除指令 | 持久保存后的计划、下次执行状态 | R01–R02 |
| 列表／详情与历史 | 计划、查询筛选及分页 | 计划摘要、运行记录、任务和工作区定位 | R02、R04 |
| 立即运行 | 计划、唯一手动请求身份 | 已登记运行或忙碌／无效原因 | R02–R03 |
| 内部领取／派发／结算 | 计划修订、触发身份、实际任务及输入身份 | 进度、接受回执、结果状态 | R03–R05 |
| 用户处置 | 原计划运行或具体真实任务／请求 | 继续／停止／重试／审批结果；复用原任务接口 | R04–R06 |

用户处置按 B4.6 的已确认管理合同，具体接口名及回执结构由实验定稿。统一审批不经计划管理 RPC 直接代答。

#### B4.4 持久化与状态（候选数据职责）

沿用宿主 SQLite，新增计划定义及逐次运行存储是设计候选；表名、字段类型、索引、迁移和事务边界待实验后冻结，现有任务、Agent 回合、原生会话及业务账本不复制。

| 记录 | 关键字段职责 | 约束／写入时机 |
| --- | --- | --- |
| 计划定义 | 计划 ID、名称、提示词、日程、时区、宽限、启用／结束／删除状态、通知偏好、修订与下次时间 | 保存与启停时更新；到期索引仅使用有效启用计划；删除不级联清除运行账；日程与修订变化及崩溃恢复可追溯 |
| 计划执行配置 | 可选项目、目录身份、工作区策略、基准引用、绑定任务、Profile／模型／档位／委派设置 | 不保存账号密钥，按有效配置 ID 与修订重校验；固定绑定失效不能静默换目标 |
| 逐次运行 | 运行 ID、计划修订、定时或手动触发身份、计划时点、准备／执行／完成时间、真实任务／输入／回合关联、实际配置摘要、结果状态／原因 | 唯一触发领取、派发前保存稳定标识、回执后更新；重试留在原运行记录，终态保留实际任务关联 |
| 工作区关联 | 原仓库／目录身份、计划或运行、任务、实际工作树路径、分支、基准提交 | 复用/扩展现有 `agent_workspaces` 等记录；依赖准备及失败恢复有证据，不能仅通过目录名推断归属 |

状态分离：计划的启用／暂停／需修正／已结束／已删除与单次运行的待派发／准备／工作中／待处理／已完成／失败／跳过／停止／结果待核对分开。一次性计划终了保留、删除保留历史的业务规则已确认；内部枚举与原任务的对应关系由 E02/E03 定稿。已有任务运行状态与业务操作回执是事实来源，不能由计划状态臆测。

#### B4.5 工具、权限与异常

第六轮已取消无人值守插件统一禁写，参照需求调用原工具系统。计划输入来源由宿主登记，权限使用现有档位、插件能力上限和适用连接。原 `AgentBusinessTools`／插件项目策略及邮件审阅流程继续作为裁定边界；生效档位为完全访问且能力允许的普通写操作直接执行，其他进入真实审批流程。未经本人逐次批准不发送邮件；跨任务网页新授权默认拒绝，保留已确认的特殊授权和登录边界。多 Agent 按原继承规则。立即运行仍不冒充真人审批。通知与停止见 B4.6。

| 异常场景 | 处理方向 |
| --- | --- |
| 休眠、退出或时钟跳变 | 恢复时按计划时点及宽限只补最近一次，其他跳过；不由调度唤醒关机或完全退出的应用。 |
| 多次触发、同计划／同会话忙 | 唯一运行身份和实际任务接受边界去重；跳过并解释原因。 |
| 配置、目录、工作树失效 | 明确需修正原因，待用户按有效配置重新确认；不以默认目录、模型或身份补位。 |
| 启动临时失败／结果未知 | 已确认未提交且原触发有效时重试一次；已执行或未知接收保留现场，通过现有记录核对，避免重复业务效果。 |
| 等待审批、用户停止、子任务未结束 | 原任务状态及其请求／子任务关系可追溯；无本人批准不产生相应效果，停止不自动重跑。 |
| 浏览器后台、身份或登录异常 | 复用 M12/M15/F36 及已授权页面，后台运行不抢当前任务界面；需要本人操作时按现行合同报告，不自行扩大授权。 |

#### B4.6 计划管理、结果入口与通知

| 操作／事件 | 技术设计职责 |
| --- | --- |
| 列表／详情 | 从计划定义与运行账组合显示下次执行、最近结果及当次配置；历史按独立运行定位，复用任务页面，不能用同一任务最后一条消息冒充所有定时运行的结果。 |
| 编辑／启停 | 新修订只影响后续执行；已开始的运行冻结原依据并按原身份归账，尚未接受的旧领取校验是否仍有效。暂停区间不产生自动触发，恢复按有效日程重算；暂停计划可手动运行。需验证编辑／暂停与领取的竞争。 |
| 删除 | 关闭未来触发及使旧领取失效，保留计划历史关联、实际任务、工作树和结果；已经开始的运行不自动停止并继续结算。用户主动停止必须定位该运行，不能停止同一会话后来无关的普通回合。 |
| 手动再次运行 | 用户主动启动新运行，关联原计划和必要的失败记录，保留旧结果；不改变周期。结果未知的原运行按 B4.5 先核对而不重复发送。 |
| 单次计划 | 原计划时间对应运行结束后标记已结束（包括明确跳过等终态），保存实际结果，停止周期派发；提前手动运行不消耗原计划时间，用户可改日期或再手动运行。 |
| 系统通知 | 复用 M14 现有系统通知与用户设置：失败、等待处理、配置异常默认提醒；正常完成可单独开启，开始和正常跳过仅记账。来源为真实状态转移，去重并定位实际任务／运行／审批。锁屏、无窗口前台、系统通知关闭或任务入口已失效均按实际用户界面与记录验证。 |

### B5. 影响范围、兼容与未决项

- 新增计划调度与存储、时钟入口页面及原任务来源展示；适配现有任务创建、事件、工作目录和配置校验，不重做 Agent 驱动或业务能力。数据库迁移保护既有项目、配置、历史及凭据，不把老任务自动变成定时计划。
- 参考产品的机制仅作选型依据（T3 5 秒周期、Orca 默认 60 秒、各自时区及工作区规则）；WillYou 的精度、空闲资源和恢复需实际测试。动态计时＋有界复核为候选，暂不指定未经验证的库或宿主协议。
- 七轮业务规则已确认；需代码分析／实验：时间计算边界、计划领取与任务接受事务、通用工作区范围、不同执行器真实入口、系统睡眠与退出平台行为、任务树终态、管理与通知接线。若技术结果需要调整规则，再专题提交用户确认；实验后统一定稿需求与原型，不以本草案开始生产开发。

### B6. 开发前专项实验与验收映射（均待执行）

| 编号 | 验证范围 | 关键证据／成功判据 |
