## A. F36 内置浏览器单窗口承载重构

### 1. 背景与调整目标

在保留 M12／M15 业务能力的基础上，解决独立透明后台窗口泄漏到 macOS 调度中心、关闭旧网页后重复使用失效标签、后台开页和右侧展示不同步的问题。目标不是调整窗口标题或只隐藏黑框，而是让普通浏览器页面的承载、身份、绘制和展示在一个可长期维护的宿主模型内收口。

产品范围及非目标以 [R07–R14](../需求.md) 为准。保留现有 M12／M15 页面、布局及正常交互，仅适配内部宿主、状态协调和已知故障行为；不引入第三方网站权限扩张，也不在本子项决定 F16 调度规则。

### 2. 整体调整思路

**采用 BaseWindow＋显式 AppShell WebContentsView＋普通网页 WebContentsView 的单窗口组合，继续由主进程持有页面。** 学习 Orca 的稳定生命周期和绘制保活思想，不照搬其 WebView 网页组件。

```text
                         单一原生主窗口 BaseWindow
  ┌──────────────────────────────────────────────────────────────┐
  │ 顶层：当前展示的原生网页／文件或 MCP 视图（由布局拥有者裁决） │
  │ 中层：AppShell WebContentsView（现有可信 UI、菜单、工作区）   │
  │ 底层：其他任务／标签的网页 WebContentsView（按需绘制）        │
  └──────────────────────────────────────────────────────────────┘
                 ↑ 布局、焦点、绘制许可与资源生命周期
             主窗口宿主适配 ＋ 浏览器页面注册表／工作区
                 ↑                     ↑
       UI IPC／展示意图          现有 MCP／CLI → BrowserService
                                          → 页级执行／回执
```

四条设计主线：

1. **承载与展示解耦。** 页面从创建到关闭始终归同一浏览器注册表；切换工作区改变可见层次或几何，不变更原生页面身份。主窗口隐藏不等于退出，普通后台页不再依赖另一个 BrowserWindow。
2. **页面状态与绘制分离。** 保留页面逻辑、会话及合法在途操作；显示或截图所需的绘制按使用者取得、释放相应保活占用，背景内容不可交互于用户界面。后台闲置策略须通过真实页面计时、资源及画面回验，不以简单切断渲染实现节省资源。
3. **业务目标与展示意图分离。** 开页的逻辑目标、产生的 pageId、任务和身份不变；用户是否正在看这一页由单独的展示意图及当前界面选择裁决。关闭旧页使旧目标失效，新的用户请求有独立身份与展示生命周期。
4. **最大限度复用。** BrowserService、BrowserWorkspace 持久状态、既有应用能力、agent-browser／页级 CDP、操作回执、权限、下载与身份分区等继续作为业务基础。只替换承载通路、适配窗口及生命周期，补齐重开／展示契约，不建设第二套浏览器业务。

#### 2.2 2026-11-25 隔离候选技术结论

[专项验证证据](实验/BE01_BE08_20261125/README.md)冻结同一开发提交 `a0acddb3a`、Electron 42.11.14，分别构建实际旧版和实验候选。结论支持本方向，不需要重做现有 UI，也不需要迁移浏览器引擎。原生层从旧版的两个系统窗口变为一个原生主窗口，背景网页稳定附着；实际旧/新壳、后台点击和菜单遮挡对照、关页重开后实际 native 前景、程序化主窗隐藏恢复、冷隐藏实际注册表及固定 helper、旧标签／Cookie、文件 HTML 预览均有运行证据。两类缺陷分别归因并验证，不以更换窗口承载掩盖 renderer 展示竞态。

本轮实证仅为 E/U/I 与实际开发构建 UI 层级。候选保留原 UI 代码的布局和样式，renderer 改动限状态协调；其承载先以持续 paintable 验证关键路径，最终按需绘制持有、系统体验及正式产品回归仍需完成。证据目录保留实验补丁、真实新旧运行、三类红测与回归、资源采样、失败和复验。按 [实验计划](浏览器单窗口承载实验计划.md)判断门槛，不将实验检查数换算成正式产品用例。

### 4. 调整方案概要

#### 4.1 创建、展示和回收

1. App 创建或恢复唯一主窗口宿主，建立显式 AppShell，加载原有可信 renderer。普通页面由 BrowserPageRegistry 所有，不需要等待右侧组件挂载；如果后台任务触发时主窗口尚未显示，由同一宿主进行非激活初始化（已在实际注册表/固定 helper 的隔离原生实验验证，完整 App 冷启动的服务握手仍待验证）。
2. 现有 BrowserService 接入，按原授权和 profile 解析页面目标；注册逻辑页与原生 WebContents，并装配现有 CDP／事件／helper／队列。实际 ready 与 UI 展示状态分别发布。
3. 在当前右侧槽位显示页，校验 rect 及当前用户选择；将其置于 AppShell 上方、按本次缩放转换定位。其他页在 AppShell 后方，绘制与交互标记独立。
4. UI 关闭面板或切换任务时取消可见布局，保留页面资源；需要在后台操作时持有绘制占用，结束后只释放自己所属占用。程序不能把后台内容推到前台。
5. 显式关页或真实资源结束时按关闭链释放该页，不影响其他标签。App 真正退出时关闭全部受管业务 WebContents、壳内容、helper 和窗口；主窗口普通隐藏不触发此链。

### 5. 详细设计

#### 5.1 主窗口宿主与可信界面

- 将主窗口创建需使用的窗口几何、标题、原生菜单、macOS 交通灯／全屏、显示器变更、关闭隐藏及真正退出契约保留。以 BaseWindow 管理外层，现有 AppShell 加载路径、preload、主题和 renderer 由独立 WebContentsView 承载。壳视图随内容区尺寸改变，并保留现有 UI 消息和缩放行为。
- 所有依赖旧 win.webContents 的调用改用明确的壳内容引用；需要原生窗口的调用使用真实 BaseWindow（如既有 API 仅支持 BrowserWindow，先做兼容实验并确定正确传参，不做不安全强制类型转换）。文件选择、下载相关对话框、复制／预览、菜单、通知、快捷键、焦点及退出均需回归。Electron 42.11.14 的补充探针实际确认了 `BrowserWindow.fromWebContents` 可返回没有 `.webContents` 属性的 BaseWindow，`BrowserWindow.fromId` 对同一宿主返回空；原生窗所有权与可信壳 WebContents 身份必须分别维护。隔离候选验证 `getMainWindow()`、`getMainShell()`、`getMainWindowContents()` 及 `mainWindowForContents()` 这一小型引用边界可让窗口、壳及父窗口调用清晰分开；与 App UI IPC 信任检查分职责，不把映射函数当作授权。应保持该模块无主窗构建资源／图标等重依赖，避免将主进程构建依赖意外引入 Web 类型树。见[原始记录及 API 核对](实验/BE01_BE02_20261125/README.md)。按本机类型声明，原生 dialog 已接受 BaseWindow；原 BrowserWindow 的 `ready-to-show` 需通过显式壳就绪生命周期适配，不能假定现有调用不变可用。
- isMainRenderer 的信任判断仍只接受当前可信壳 WebContents 的 mainFrame 与当前允许的页面 URL，不把任意网页视图、旧壳或弹窗当作可信 UI。保持现有主壳安全配置；普通网页继续 sandbox、contextIsolation、无 Node integration、按原会话策略配置，不启用通用 WebView。
- 壳重载／崩溃时，窗口与页面注册表不随 React 组件销毁。检测可信壳主 frame 非同文档导航、壳失效或宿主重建时，撤销旧壳布局/overlay 代际并安全降层，保留仍有效的网页和任务；等待新可信壳 document 加载、IPC 订阅建立、当前 snapshot/选择同步后才准许新布局。原 `browser:open-presentation` 订阅前事件不重放，renderer 内存 intent 在重载时丢失，不能盲重放旧 show 事件；保留持久操作回执/页入口及新明确意图，如果不能证明仍是当前用户位置则不抢前景。新壳读取最新 snapshot，区分可恢复页与旧布局。若宿主或页面实际销毁，按保存数据重建原生实例并使旧引用/回调失效。实际旧候选重载时页面盖住回到首页的壳；最小隔离补丁降层后页面及未提交表单仍在，回选正常。
- Cold init 和真实退出必须串行化创建／清理：BrowserService 当前早于 createMainWindow 组装，改造须支持唯一宿主就绪握手。用同一次创建的共享就绪 Promise/明确失败和取消衔接页面初始化；隔离候选的短轮询 `ensure` 仅为实验，正式不以反复建窗或延长等待代替宿主状态。BE01／BE02 的先后实验已验证真实主壳可加载/退出、从未显示的 BaseWindow 上实际 `BrowserPageRegistry`、固定 helper 和截图均可工作，关闭后可清场。仍须在最终 App 打通后台请求、壳就绪握手、执行链和错误恢复。BaseWindow 关闭不会自动保证子 WebContents 回收，明确先停止新请求、结算／关闭各页，再释放壳和主窗口；普通 macOS 隐藏窗口与真实退出分开。 主宿主内部区分 initializing、native-ready、shell-loaded、ui-bound、failed、committed-shutdown（运行态非持久字段）；对可能不需要 UI 的纯后台通路按原授权只等待必要 native/page 就绪，对可见窗口展示等待真实壳成功加载，再与当前 UI 订阅/选择握手。多个并发请求共享本代际创建，任何取消只结束自己的等待；壳加载失败先阻断发布，并按实际 owner 收尾页面队列、helper 及所有子 WebContents，清空失败宿主后允许新代际重试。退出采用现有 busy／save／discard／commit 回执，commit 未确认或用户取消退出不先销毁页面/helper、恢复原正常状态；commit 后停止新请求、结算关闭 owner，再销毁壳与窗口。真实退出处理器依赖替身五场景及宿主红绿已复验；正式接通服务和 native 对话框复验。
- 若 native popup 是用户可见、具有原生 opener 的必要窗口，仍允许按原规则创建；不为普通后台页、闲置页或恢复任务创建额外假窗口。

#### 5.2 视图组合、尺寸和绘制占用

保持同一 BaseWindow 中显式 z-order。背景页不得占到 AppShell 或当前用户查看视图之上；当前需要展示的网页或文件视图由右侧工作区所有者定位，以可信 renderer 的布局和壳 zoom 换算实际窗口坐标，复用已有边界校验。主窗口 resize、跨屏 DPR／zoom、导航变化时重新校验几何和版本。

| 逻辑状态（拟定运行态，不是新持久化枚举） | 进入条件 | 原生视图和绘制 | 退出／异常 |
| --- | --- | --- | --- |
| 未加载 | 已保存标签或新建空白标签尚未导航 | 原有启动页／占位；不必分配网页引擎 | 首次有效导航按身份初始化 |
| 初始化／加载 | 受理合法创建、恢复或身份切换 | 同一宿主分配新视图和页级执行上下文；显式展示的页保持加载状态 | ready、failed 或取消；失败／关闭时清理已分配内容 |
| 前台展示 | 当前任务、标签、面板与最新布局匹配 | 前景层正常显示，只有这一可见页与合法原生浮层接受相应交互 | 用户切换／收起转后台，不销毁 |
| 后台闲置 | 页面已存在、非展示且无绘制占用 | 放在 AppShell 后方；优先验证可暂停绘制但不破坏页面逻辑的方式 | 有绘制需要则取得占用；若隐藏导致业务计时／导航退化，按实验结论调整策略 |
| 后台绘制 | Agent／截图或既有业务操作需要绘制，且页面有效 | 同一页在壳后维持可绘制状态，原尺寸保持；不激活窗口、不接受用户鼠标 | 各持有者完成后独立释放，最后一个释放才可回到闲置 |
| 关闭中／关闭 | 用户关页、任务/身份退役、真正退出或原生页失效 | 禁止新操作，撤销旧展示、queue／引用；等待必要收尾并解除 view、关闭 WebContents、helper | 不能被迟到的加载／截图／展示回执重新挂回 |

绘制占用借鉴 Orca 的 paint hold，用一页多持有者/可靠释放的形式实现（详细 API 表见后文；实现复用现有队列和 abort）。由一次集中式布局裁决区分**展示身份、绘制许可、页面存活**，不可用一个 `visible` 布尔量替代三个概念。隔离候选中 `addChildView(view, 0)` 可在已有 BaseWindow 内重排同一 view；无需先拆离或转移到其他原生窗口，实证可保持原文档、表单、WebContents 和像素。正式实现建议以下不变量：

| 状态数据／操作 | 约束 |
| --- | --- |
| 主宿主、pageId、原生代际 | 绑定唯一原生宿主与当前有效 WebContents。页重建生成新代际；注册、mount、demote、dispose 都按这一身份，不使用全局当前焦点作为所有者。 |
| 展示槽与布局版本 | 每次布局由可信 UI 实际所有者在发起时产生本次 host/renderer generation、surface instance、单调 sequence 及 taskId/pageId/rect；同页重新挂载也换实例，迟到 null 只能解除自己仍占有的槽位，不能撤销 B 或已重新挂载的 A。接收顺序不是用户意图顺序；原生层级事务串行、await 后再核代际及前景责任，过期事务不能发布前景。旧页保持逻辑身份和合理 viewport。 |
| 绘制占用 token（内部、非公开 RPC） | `acquire` 记录本页/宿主代际、唯一 acquisition 与原因（前景、需要 frame 的命令／导航、截图或保留占用），复用真实队列和取消边界；返回可幂等释放的本次 token。最后一个占用结束且无底层未结算操作后才允许 idle。不具有绘制需求的纯读取不得无条件提升前景。 |
| 画面恢复与 idle 策略 | 前景必然可绘制；后台恢复在 AppShell 后方先确认有效 viewport、代际及正确层级，再等实际新帧/业务回执（按具体操作判定，不假定固定 sleep）。无占用时以 `setVisible(false)` 为实验支持的 native idle 起点，保留同一 WebContents/session，仍有 rAF、CSS、timer、异步页面行为；不承诺暂停或 CPU 节省，不擅改 backgroundThrottling。不满足当前画面或原 M12 资源门槛时据实调整策略。最终真实 service 多持有者及异常恢复正式复验。 |
| 关闭及退出 | 先阻断新占用、撤销当前页的布局 / 旧回执；关闭该代际的队列、引用与 helper，解除 view，等待真实 WebContents 销毁（实验确认 close 回执不代表销毁事件已同步）。宿主退出显式管理所有 owned view 与壳，不假定 BaseWindow 自动释放。 |


- 前台显示是一个独立的占用来源；后台命令、截图、冻结脚本等需要绘制时也取得占用。每次占用和原生页面身份绑定，不允许旧页面的 release 影响新页面或其他任务。
- 需先确保正确 layer order、size 和可绘制状态，再运行需要真实 frame 的操作；用页面计数与截图像素验证可用性，不只依赖 IPC 返回成功。不要用 Page.bringToFront 或系统激活来证明后台执行通过。
- 以底层操作明确完成、失败/取消已结算或原生页关闭为释放条件；外层等待超时不能假定底层截图已结束。对多个同时运行的命令、取消、导航变更、dispose 逐一验证，释放动作幂等，不留孤立 hold。
- 前台 native view 可能仍盖住 DOM 浮层；保留现行 overlay（多 owner hold、截图背景、收起当前页）可用性，重构为同一窗口内层级调整。HTML／MCP 预览与下载、权限、认证、菜单等只有通过 BE06 的替代方式才简化。遮挡期间不能把真实网页的交互交给后台视图。 每次 owner 的 overlay.open 获取独立 instance token；capture/close 绑定该 token 和当时页面代际，取消或旧实例返回不再发布图片、不再降层当前页，不能释放同名 owner 的新实例；有效 owner 全部释放才复位。
- 原生层级变化只能在宿主协调的布局入口发生；其他模块不自行重排背景页；单个右侧槽位的前景拥有者、有效 rect、任务及关闭状态必须一致。现有 `workspace.placement` 在 `ensure` 后核对版本，而注册表切换本身仍可能等待旧页下沉。正式实现应在宿主就绪后串行处理同一原生根的有序布局事务，或在每个异步边界后重新核对 host/page 代际及最新布局版本；只有完整生效的当前事务能改变前景引用。HTML/MCP 等共用前景也服从此裁决。避免旧 `placement(null)`、旧 overlay 关闭或迟到 `capture` 把后选新页掩盖。

#### 5.3 标签、身份与在途操作

以 BrowserWorkspace 的保存标签/当前选择和 BrowserPageRegistry 的原生页为两个层次，不增加第三个持久化页面清单。

- pageId 是业务逻辑标签标识；原生 WebContents 和 documentGeneration／引用范围是实际执行上下文，配合既有 opening、closing、AbortController、队列及 placementVersion。页面重建（身份切换、应用恢复、engine 销毁）使用新的原生代际，拒绝旧事件、旧引用和旧权限；是否需新增内部 epoch 字段由实验确认，不写入 v1 持久结构。
- ensure 同一逻辑页只建立一份原生实例。close 被受理时即同步标记 closing（在任何 await 之前），从合法 lookup、URL 匹配与新操作排除，取消旧展示；重复关闭复用同一终态事务，仅写一次关闭历史，不以物理完成作为逻辑不可用的起点。实际 native dispose 由唯一 owner 执行，原生关闭回调不得重复入队或自等待；数据状态提交/失败需有确定结果，保留旧 ID 不可用直至收尾完成或明确失败恢复，不能晚到回调复活。UI dispose 仅释放自己的布局责任。
- close 之后以相同 URL 新开时，从当前任务且同一有效 profile 的仍存在 tabs 匹配，找不到则生成新 pageId。旧 ID 不复活；同请求编号重复只回原 operation receipt，新请求有新的 requestId；失效目标不向其他任务或其他身份降级匹配。 同 URL 同时合法请求可共享创建，但各 operation/取消独立；一个请求取消不影响另一个有效等待者，全部取消则该创建代际立即不再接受新请求，停止发布，底层结算后回收未被用户接手的本次自动建空白页（不新增人为关闭历史；用户已有的页/显式接手的页不擅自删除），新请求另分配有效创建。显示、选中、显式 ID 与实际归属均按此前后顺序处理，不复用已废弃的 loader；正式验收旧占位回收、关闭自等待及真实 UI/CLI 并发。
- popup 延续原版的 opener／session 约定，明确普通新标签和真实可见子窗各自宿主；身份切换、Cookie 导入暂停、任务／profile 删除均保留既有生命周期锁、队列和清理，不跨任务共享 WebContents。

- **页级 helper 终态**：实际20次动态循环证明 live daemon/endpoint/queue 可清场，但当前旧／新 shared helper 的 `.version` 和空私有 home 逐页残留。保持可重新连接的 `BrowserHelper.close()`（超时/重导航/取消后仍复用），独立 terminal dispose 只在页面不可恢复、queue/proxy/client/daemon 确认结算且路径归属确切时幂等清理该页专属端点元数据与 helper home；未知文件、未结算或归属不明的资源留诊断和可核验延迟回收，不触及兄弟页/共享/用户目录。独立文件系统契约通过；正式接入 registry 的终止链并在长期和重启恢复测试核对自然清场。

#### 5.4 开页契约和展示事件闭环

当前问题分为调用参数/失效页错误与 renderer 展示竞争，两者独立于原生窗口承载。通过[BE04/BE05 红测与复验](实验/BE01_BE08_20261125/software/reopen/README.md)已证实一种可造成“后台开页成功、右侧没显示”的实际组件竞态，尚未取得用户原始现场全链路脱敏日志，因此不声称是所有现场唯一根因：

- 关闭最后一页后，旧的空 snapshot 返回晚于新的用户展示意图。组件 effect 自动清理空面板，误把它当作用户手动选择并提升展示撤销版本；新 `open-presentation` 在首个 guard 被拒绝，未 select。
- 另一个交错是首个 guard 已放行且 select 在途，此时自动收尾提升版本，导致第二个 guard 拒绝，后端/renderer store 已有新的 activeId，右侧仍是旧面板。
- 反向场景：先有旧展示意图，用户随后显式关页，原代码直到异步清理才撤销，旧展示事件可能先到达而抢占界面。三条旧红测在隔离候选同预期复验通过。

1. 在浏览器命令定义的唯一生成源表达 url 与 pageId 二选一（当前主进程已校验）；指定 pageId 沿用原身份，不与 new 或新的 profileId 同时使用。BE04 软件实验确认当前主进程已经拒绝冲突参数或失效目标；本地诊断表明通用 JSON Schema 能表达互斥，但当前生成工具 schema 没有该限制。进一步源码核对：[命令映射生成源](../../M12_浏览器自动化/技研/命令映射/gen_command_map.py) 的 `browser.tab.open` 将两字段放进 `obj(..., [])`，因此目前 required 为空；[应用 definition](../../../../resources/applications/browser/definition.mjs) 将整个 command.input 展开并补描述，[tool-service](../../../../src/main/core/applications/tool-service.ts) 读取有界 object schema，[bridge-runtime](../../../../src/main/core/applications/bridge-runtime.ts) 的 tools/list 只移除内部 contractMajor 并转发 schema。源码表明内部投影没有在这些环节主动剥离组合关键字；实际生成/安装契约校验、provider 的 MCP schema 投影及旧冻结会话仍须复验。若受限，在实际发送给 Agent 的说明明确约束，并保持严格宿主校验。不能只手改 generated JSON。按现有应用包版本与会话兼容规则发布变更，不覆盖旧冻结会话的契约。
2. browser Skill、错误反馈及入口说明统一：每次使用回执中的当前 pageId；失效时先重新查询标签；新的用户开页意图可按 URL 新发请求；明确指定已关闭页的动作返回原有 BROWSER_TAB_NOT_FOUND／相应参数错误，不隐式重开旧页或重复写操作。旧会话仍有可读、正确的恢复错误。
3. UI 发送新输入时记录该用户请求的展示身份；主进程在接受开页时登记页、回执与展示意图关联。R12 要求的 show 开页应先发出可核验的加载/标签状态，再发布就绪或失败，后台模式不强制打开面板。
4. 复用 browserOpenPresentationEvent，在渲染端核验 taskId/pageId/clientInputId/operationId 和最新用户选择。将真实手动切换、显式关闭与旧异步空标签清理分开：前者可撤销其后仍在途的旧展示，后者不得错误撤销在其之后新发起的展示。具体采用软件候选已复验的最小职责拆分：显式点击关标签入口同步撤销旧展示；空标签自动清理只关闭对应空面板，不提升用户意图版本；`AgentBrowserSurface`／`workspace-panels` 明确区分 `onClose`／`onAutoClose`，`Panels.close` 接受内部自动标记。两个展示 guard 均保留、仍检查最新用户选择与真实页。正式真实 Agent 流程还须记录受理、异步 snapshot/select、guard 与 panel.open 的对应事件；不因为修了此竞争取消后台/在途/跨任务保护。
5. 成功从当前任务进入目标页时，activeId 和实际显示页一致；用户已切走、旧页已关闭或请求来源失效时，禁止自动打开／抢焦点。保留成功结果和对应标签的主动“查看网页标签”入口，页面不存在时显示明确失效原因。直接 MCP 调用与需要批准的 host business 回执都要覆盖。
6. 收敛展示状态的诊断：在隔离实验/必要诊断收集经过脱敏的关联标识与状态转移、失败类别，不记录账号密码、网页输入、站点内容或私人 URL。不把日志当成授权或绕开真实 UI。

#### 5.6 数据、兼容及异常处理

| 现有数据／字段 | 来源 | 调整与兼容要求 |
| --- | --- | --- |
| app_settings 的 browserWorkspace.v1:<taskId> | workspace.ts / shared/browser-workspace.ts；version=1、tabs（id,url,title,profileId,favicon）、activeId、closed（最多10） | 继续使用原结构；不保存原生 handle、层级、绘制占用或 renderer 内部版本。读取旧记录、关页／重新打开、重启恢复须验证。 |
| browserProfiles.v1 与 persist:wy-browser-<id> | profiles.ts | 不改变 profile ID、scope/owner、partition；保留原身份、Cookie／会话及隔离数据。不得用清库或重建身份解决重构。 |
| browser_operations | operations.ts：run_id/request_id/task_id/page_id/command/state/effect_state/progress/summary/error_code/时间 | 继续使用原回执和幂等约定；旧运行／关闭页只能按原授权查询，不以新请求重放。 |
| 当前运行对象 | page-registry.ts、workspace.ts、refs、queue、认证等 | WebContents、原生布局、绘制状态仅为运行态；重建时旧对象及引用、回调失效。 |

计划不新增 SQLite 表或改变原 v1 schema。BE07 在正常退出旧版的真实合成数据上，使用完整资源归属与 profile 分区复验，原逻辑标签、关闭状态、profile 和 Cookie 均能由候选读取（本地站点未重发 Cookie）。首次试验只复制 DB/Partitions，原有数据库归属校验正确阻止不完整数据启动；补齐完整合成数据并保持正常 guard 后通过。正式升级直接沿用原完整数据根和校验，不为重构拆分、重置 DB / owner / partition。若实验发现确需迁移，必须说明真实原因、字段、升级与回滚，再回到阶段评审。在进程重启后只承诺既有持久化恢复能力，不宣称所有未持久化网页状态在整进程退出后仍保留。 Ultra 实际旧→候选写入→旧版读取候选页→候选受控异常 `app.exit(23)`→候选恢复，旧站点 Cookie 未重发，已主动关闭页未复活、另一任务不变；三个完成的独立数据根正常退出后 WAL=0、SQLite integrity=ok、owner 匹配。受控异常不是断电或 OS kill，全量旧真实数据/打包迁移仍按 BE09 复验。

| 异常／竞争 | 拟处理 | 验证 |
| --- | --- | --- |
| 宿主未就绪／渲染壳失效 | 按唯一宿主初始化/可信来源等待或清晰失败，不用独立透明窗口兜底；恢复时重绑 current UI | BE01、BE02、BE08 |
| 初始化中关页、取消、删除身份 | 阻断迟到发布，释放该代际 view／helper；旧回执不复活 | BE04、BE08 |
| 多个绘制持有者、捕获超时 | 独立释放、底层结算后清理；未知效果查询回执，不盲重试 | BE02、BE08 |
| 旧 UI rect／overlay owner 关闭迟到 | 作用于同一任务、页及有效布局版本；不覆盖新选择 | BE03、BE05、BE06 |
| 标签关闭后旧 ID 或参数冲突 | 现有错误码与明确恢复提示；新 URL 经当前任务/profile 新匹配或新页 | BE04 |
| 新页 ready、用户已选其他面板 | 保留页及回执，禁止抢占用户的后选位置；仍当前的新展示须可见 | BE05 |

| 退出/崩溃、资源释放 | 按身份明确清理，自然退出与失败收尾分别观察；重启恢复按持久化记录而非旧句柄 | BE08 |

### 7. 风险与边界

- **宿主兼容**：BaseWindow 与 BrowserWindow API 并非完全等价。文件 dialog 父窗、main IPC 验证、MCP/HTML zoom／focus、macOS 原生窗口行为必须作为最早门槛。
- **渲染保证**：实际开发构建已补壳重载和旧 null 原生竞争绿测、程序化 hide/minimize/restore 及真实 enter/leave-full-screen 事件、稳定自有系统窗合成对照（候选一个、旧版两个系统窗；非动画过渡）；完整冷启动 service、物理系统输入、Mission Control、多屏交互细节、真实 Agent/正式包仍待验。AppShell 截图不等于系统合成；不能以窗口计数代替 Mission Control。
- **按需绘制**：独立五页两组短测和各 30 分钟真实长测均完成实际操作/画面和清场。按需隐藏／恢复满足三项同形状探索判据；持续绘制组有趋势项未满足。支持以按需绘制占用为生产实现首选，而非始终强制各逻辑页都 paintable；单组比较不证明 CPU 节省或 renderer 内存增长已经解决。 [原始及资源比较证据](实验/BE01_BE08_20261125/README.md)。正式候选须实现完整占用、释放及重入，并按实际 M12 资源约束复验。不能凭截图回执或 CSS 看不到就判断绘制、资源或鼠标穿透正确。 Ultra 复杂 Canvas/CSS/异步页实际显示隐藏状态仍推进；短动态循环与独立多 holder 契约支持上述设计，未证明实际 CPU 节省或长期无泄漏；helper 终态 metadata 独立清扫列为正式 S2/BE08 阻断缺陷，不能用独立实验的外部清场替代产品自然清理。
- **兼容安全**：现行任务／profile／授权、网页隔离、登录与用户批准、页级代理和回执保持；相关真实凭据的测试由已确认本人操作完成；合成页验证不冒充真实业务网站或登录态通过。平台适用沿需求约定执行。
- **无人值守**：F36 不引入退出后持久进程或新的自动化许可；App 隐藏/最小化不等于进程退出。
