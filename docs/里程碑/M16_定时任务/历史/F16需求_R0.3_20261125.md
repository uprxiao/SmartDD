## 1. F16 目标与范围

用户为任务指定执行时间或周期，系统按计划使用对应项目（可选）、工作目录和 AI 配置运行任务，并提供可追溯的结果。复用届时已交付的任务运行、Skill、历史和交互能力，以及已有项目和 AI 配置体系；与 M14 新运行入口的具体联动在本阶段设计时明确。

## 2. F16 需求项

| 编号 | 需求 | 已记录行为与需要展开的规则 |
| --- | --- | --- |
| M16-R01 | 创建和编辑计划 | 名称、可选项目、工作目录／Git 工作树、AI 配置、任务说明、执行时间／周期和时区；按第 3 节已确认的类型及组合校验 |
| M16-R02 | 管理计划 | 查看计划及下一次执行时间，编辑、暂停、恢复、删除、立即运行；编辑及启停／删除只改变未来调度，停止当前运行使用独立操作 |
| M16-R03 | 调度与执行 | 到时使用正确的项目（有归属时）、工作目录及配置发起真实任务；避免错误归属和重复触发 |
| M16-R04 | 运行记录 | 展示触发及实际执行时间、运行状态、耗时、对应任务与结果／原因；每次运行与计划关联 |
| M16-R05 | 异常与恢复 | 应用退出、电脑睡眠、错过时间、配置不可用、重叠执行、失败重试和时区变化有明确策略 |
| M16-R06 | 提示与操作边界 | 复用普通任务权限、工具和审批；失败、待处理及配置异常通知，正常完成通知可选；详见下文 |

核心流程：配置计划 → 校验并保存 → 展示下次执行时间 → 到时触发 → 关联实际任务 → 查看结果／失败原因 → 按规则继续、暂停或重试。

计划状态与运行状态分开：计划的启用／暂停不等于某次运行的等待／运行／成功／失败。具体状态枚举、取消语义和恢复机制在技研后与需求同步定稿。

## 3. F16 业务规则（逐项评审中）

### 已确认：运行机制（2026-11-25，用户选择方案 A；R03、R05）

- 首版调度依赖 WillYou 主程序运行，不设置完全退出后仍运行的独立后台常驻服务。应用正常打开、最小化、处于后台时，启用的计划继续自动调度。macOS 沿用现有红色关闭按钮隐藏窗口的行为，隐藏期间继续调度。
- 真正退出（如 macOS 的 Command + Q）后停止调度，保留计划和已有运行记录。系统睡眠、关机期间不保证执行；设备唤醒或重新启动 WillYou 后按第五轮确认的错过执行规则判断是否补跑。其他平台区分隐藏／退出的行为沿用既有窗口约定并在技研及验收中核对。
- 复用现有任务和应用能力架构，设计时考虑后续独立调度的扩展空间；本次确认不包含独立服务实现，也不构成正式开发授权。实际调度、生命周期与恢复仍须隔离实验验证。P0.1 原型参照此方向，暂不涉及界面增量。

### 已确认：项目可选及工作区管理（2026-11-25，第二轮评审；R01、R03、R04）

- 创建计划时可以关联已有项目，也可以不选择项目。关联时从原项目已登记目录选择；不关联时可由系统分配独立工作目录（默认），也可自行选择本机已有目录。无项目任务在用户界面归入未关联项目／通用任务，不为每个计划或运行创建普通项目。内部是否采用系统管理的通用工作区或空项目归属及其能力契约待技研；不隐式继承其他项目的连接／权限，工具边界见第六轮。
- 有项目时，默认使用现有目录；Git 项目目录还支持两种工作树模式：计划专属 Worktree（第一次实际运行才创建，后续复用）和每次新建 Worktree（每次实际运行从指定基准分支建立独立工作树）。SVN 或普通目录不提供新建 Git 工作树。未关联项目使用普通工作目录；计划管理的新工作树须有明确的原项目／Git 仓库归属，不为此自动创建普通项目。
- Worktree 始终归属原项目和源仓库，复用现有 `~/.willyou/worktrees/` 工作副本目录及管理机制，不将每次生成的工作树另行注册为普通项目。基准分支由用户选择，实际创建时记录基准提交、分支、路径及计划／运行／实际任务关联。新工作树不带入主工作目录未提交的改动；不因调度自动合并或推送。实际任务及定时计划详情可以定位工作树和分支。
- 暂停、删除计划不自动删除已产生的工作树或分支；工作树由用户主动清理。工作目录复用与 Agent 会话复用是不同维度，兼容组合及绑定规则见下节。基准引用的解析、仓库身份、已有工作树失效、恢复及依赖准备等需实验验证。
- P0.1 的项目必选校验、两种工作区选项与此次决定不一致，待业务规则讨论收口后统一调整原型、技术方案及验收用例。

### 已确认：任务去向、会话与上下文（2026-11-25，第三轮评审；R01、R03、R04、R05）

- 每次触发都有独立的计划运行记录。任务去向支持：每次新建任务（默认，新会话、不继承历史）；持续复用同一任务（首次自动创建，之后续接上下文）；指定已有任务（绑定用户选定的任务，续接其上下文）。复用适用现有会话及历史接续机制，不改变 M14 的原生会话与上下文合同。首版不额外支持同一个任务每次开启全新上下文的模式。
- 使用现有目录及计划专属 Worktree 时均可选择每次新建任务或持续复用任务；每次新建 Worktree 只允许新建任务。绑定指定已有任务沿用其实际工作目录，不替其新建或迁移工作树。
- 每次新建任务按定时计划配置的 Agent／Provider／模型和推理强度运行。复用已绑定任务则沿用其配置，同一 Agent 与 Provider 下模型及推理强度变化可以跟随；Agent、Provider 或工作目录改变时提醒重新确认计划，不擅自切换回原配置。具体绑定校验、状态提示及恢复路径待技研。
- 被绑定任务不可用／忙碌、并发派发及异常恢复等处置见第五轮确认规则；无人值守下的权限及能力边界见第六轮。

### 已确认：日程与触发方式（2026-11-25，第四轮评审；R01、R02、R03、R05）

- 首版提供固定间隔（最低 1 分钟）、每天、工作日（周一至周五，不引入法定节假日历）、每周指定星期、每月固定日或最后一天、指定日期时间仅执行一次、自定义 Cron；另支持手动立即运行。每月所选日不存在时跳过该月，月底执行使用“最后一天”。立即运行不改变原有定时计划的下一次执行时间。
- 支持跟随本机时区（默认）与固定指定时区。保存前展示下次执行时间，自定义 Cron 实时预览近期几次执行；常用日程无需书写 Cron。表达式契约、起算／时间调整及夏令时边界在专项技研明确并与用例对齐。
- Webhook 外部事件触发不纳入 F16 首版，单独留需求池 F37 后续规划；本期仅考虑调度派发接口的扩展空间，不实现外部接收服务。

### 已确认：调度、并行及异常恢复（2026-11-25，第五轮评审；R03–R05）

- 错过执行后的宽限期可选择不补跑、10 分钟、1 小时（默认）、12 小时。休眠唤醒、退出后重开等恢复时，只考虑最近一次符合宽限期的计划触发；超过宽限则跳过，不积压并补跑多个历史触发。跳过及补跑原因可追溯。单次计划终态及记录见第七轮，日程计算边界由专项技研明确。
- 不同计划绑定不同任务时允许并行，即使归属同一项目，也沿用 M14 的独立任务并行机制。一个任务会话不能同时接收不同计划的执行输入。计划前一次尚未结束、或绑定任务正在处理其他用户任务时，本次周期跳过并记录原因，不打断任务、不无限积压；立即运行遇同计划已有未结束运行时提示且不重复启动。
- 临时启动故障在能证明尚未实际提交任务输入、原触发仍有效时自动重试一次。已实际执行部分操作后失败保留现场，供用户手动处理；额度、限流沿用 M14，不自动更换账号或执行器。配置或目录失效给出修正入口，不能擅自替换；用户主动停止不自动重试。接收或执行结果未知时，先核对实际任务与原生记录，不盲目重发。
- 每次触发有持久化运行身份、计划时点、对应任务／输入及结果状态，防止调度重复、重启或异常恢复造成同一次触发重复执行。对未知结果不伪造成功或失败。
- 技研比较按下次执行时间触发并做周期复核的机制，兼顾准确性、低空闲资源占用及独立计划并行；正常唤醒运行状态下到期后 5 秒内开始派发为初步验证目标（与模型响应时间区分），具体指标由实验验证和最终方案收口。

### 已确认：复用现有 Agent、工具与权限体系（2026-11-25，第六轮评审；R01、R03、R06）

- 参考 T3 Code、Orca 的普通任务派发方式，定时任务复用 WillYou 已有 Codex、Claude Code、Antigravity、Agent／Provider／模型／推理强度配置、Skill 引用、MCP／CLI、内置浏览器与任务执行体系，不另建定时任务专属工具或执行器。沿用 M14 不为计划任务设置 `/goal` 的规则。
- 复用普通任务的单／多 Agent 与委派配置，运行完成判定需考虑其子任务工作是否收口。权限复用现有执行器支持的档位（默认请求批准）和审批入口，不另设一套权限等级；计划及绑定任务的权限配置变更须重新确认，不能隐式提升。
- **取消无人值守插件写操作一律拒绝的旧规则。** 普通与计划任务均按 M14 已有插件权限档位及操作自身最高允许档位执行，项目、连接及能力授权校验保持不变。授权范围内读取按原规则；允许完全访问的写操作在生效档位为完全访问时直接执行并记账；请求批准或帮我批准下的插件写操作、最高档位要求审批的操作沿用现有请求与实际用户批准。后台未获批准时处于等待处理，不自动批准或冒充真人输入。记录、通知和停止见第七轮确认规则。
- 发送邮件仍按现行特殊合同每次由本人审阅并批准，无本人批准不发送；不因取消统一禁写而扩大其他既有授权。M12／M14 的跨任务网页新授权在无人值守时默认拒绝，现有身份、登录和其他需要本人操作的规则保持；本任务内已授权浏览器能力复用，不开发专用 MCP、CLI 或浏览器系统。
- 不关联项目的计划以通用能力和独立工作区为方向，支持适用的全局 Skill/MCP 和独立通用浏览器身份（内部实现待技研）；不自动继承其他项目的连接、凭据或授权。项目专属能力仍依据显式范围处理。
- 本次决定更新 M14-R08 未来无人值守范围及移入 M16 的 A72 判据；A37 的跨任务新授权判据继续有效。旧决定及既往普通任务验收按历史保留，不追认任何定时任务尚未执行的结果。

### 已确认：计划管理、运行历史与通知（2026-11-25，第七轮评审；R02、R04–R06）

- 计划列表展示名称、项目／未关联项目、智能体（Agent、Provider、模型）、执行频率、下次执行、最近运行结果和启停入口。计划状态（启用、暂停、已结束及需修正等）与单次运行状态独立；计划详情展示配置和每次运行记录。
- 编辑计划对后续执行生效，不改写当前运行的依据。暂停停止后续自动触发，不中断正在执行的任务；恢复后恢复有效日程。暂停计划仍可立即运行，手动触发不改变原定时日程，并继续遵循忙碌、权限和去重规则。
- 停止本次运行使用现有 Agent 任务停止机制，关联实际运行身份；不把停止当前任务等同暂停计划。删除计划停止其未来触发，不自动停止已经开始的运行，不删除已产生的任务、执行记录、文件、工作树和分支；保留历史定位，当前运行终态仍可归账。若实际任务被用户另行删除，显示入口不可用及原因，不自动更换任务。
- 每次运行单独记录计划时点、实际执行时间、触发来源、状态、耗时、任务／回合定位以及失败、跳过或需处理原因；工作目录和工作树关联可查看。复用同一任务时仍能准确定位本次对应对话。失败后允许用户再次运行，新建运行记录，不覆盖原失败；结果未知时先按第五轮核对，避免重复执行。
- 仅一次的计划在其预定执行结束后不自动删除，保留为“已结束”与实际结果；错过且最终跳过等不再生成周期触发。允许查看历史、编辑日期或再次手动运行；提前手动运行不改变原定时日程。
- 复用现有系统通知与待处理入口：默认通知执行失败、等待人处理／审批和配置失效；正常完成默认不通知，可单独开启；开始运行和正常跳过不通知，保留记录。点击通知定位对应任务、运行或实际待处理请求。通知去重、真实系统权限及后台提示需验收验证。

### 开发前专项技研及定稿待完成

- 无项目模式的内部归属表示及项目能力边界，工作区、会话绑定及上下文接续的技术验证。
- 日程表达式、定时计算的时区／夏令时边界及触发精度的技术验证。
- 调度并行、重复执行防护、启动重试、重启恢复及既有工具／权限接线的技术验证。M10 的禅道／邮件调用遵循上述规则；Jenkins 不作为本阶段前置要求。
- 计划状态／运行状态的服务层映射、管理操作和通知的实际接线及验收。七轮业务规则已经确认；专项实验如发现需要调整产品规则再明确评审，不重新待定已确认范围。完成实验后统一收口需求、原型、技术设计及完整验收用例。

## 4. F16 验收目标

按最终规则验证准确触发、项目／无项目和工作区归属、配置／会话、下一次时间、暂停／恢复／删除、重启、睡眠／错过时间、重叠与重试，以及记录与实际任务对应。覆盖普通 Agent 与委派、工具复用、插件写操作的原权限档位和上限、等待／批准及未经批准不产生业务效果、跨任务网页授权拒绝。正常和异常用例均需明确前置时间、操作及可判定结果，不能只检查计划列表能显示。
