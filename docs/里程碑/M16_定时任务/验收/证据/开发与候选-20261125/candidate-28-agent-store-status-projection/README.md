# C28 回合状态摘要与事件追加分配优化（2026-11-27）

任务侧栏刷新会计算每个任务的状态。原实现每次读取完整回合历史的十列数据，快照构建期间也会再次读取。事件追加每次还会重新编译两个内容固定的 SQLite 语句。C27 的正式长测显示主进程末段 RSS 增长，以上两处是可独立复现的重复分配。

本次将状态计算使用的数据库结果限制为是否存在待处理回合、是否正在派发或运行，以及最后一个未取消回合的标识和状态。查询每次读取实际数据库，保留接受时间与 rowid 排序。历史快照仍返回完整的原约定内容。事件序号查询与写入语句在同一 AgentStore 实例中复用，事务、回滚、跨任务序号与提交后通知保留原行为。

## 定向验证

恢复后以同一源码再次执行九次独立 SQLite 对照。使用真实 Electron Node ABI、原表结构和两条实际源码查询，五个合成任务，每个八轮。120 次示例状态查询和额外 864 次固定历史查询均逐次比较实际状态与合成预期。这里没有测量真实 App 的状态查询调用次数。

新增两条回归在修改前实际失败，任务列表读取完整历史 9 次，事件序号语句编译 7 次。修改后通过。环境恢复后再次运行定向范围的全部相关软件测试，681 条通过，10 条既有默认跳过。普通沙箱中两条既有 Gemini 本机合成中继用例因 127.0.0.1 监听权限失败，获准的同一夹具单独复验均通过。Typecheck 成功。

原 C28 临时包曾完成普通任务、自然到期的定时任务及结果页面的真实回归。之后首次资源预检发现真实同组的 Apple Metal 编译服务未被旧采集器分类，未进入 30 分钟正式阶段。环境恢复过程中临时包、原始日志和私有驱动已丢失。此次已重新比对 153 个生产输入的全部哈希，源码与原 C28 相同，使用标准流程在 Git 忽略的独立目录重建。重建后的 asar 哈希不同，两个原生工具哈希一致。六项原生自检及严格签名校验通过。真实 App 和长测需依据这次新包的独立记录。

短诊断只能确认减少重复查询与分配，仍需通过 B11 原正式长测才能判断实际长期资源要求。当前主用例数无新增。
