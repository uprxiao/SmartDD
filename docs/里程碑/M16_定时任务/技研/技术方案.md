# M16 技术方案：定时任务与内置浏览器单窗口承载重构

更新：2026-11-25。依据：[M16 需求](../需求.md)，F36-R0.1／M16-R07–R14；F16 R01–R06 仍待规划。**状态：F36 方案草案，用户已确认方向，专项实验与详细设计待评审；未进入生产开发。**

## A. F36 内置浏览器单窗口承载重构

### 1. 背景与调整目标

在保留 M12／M15 业务能力的基础上，解决独立透明后台窗口泄漏到 macOS 调度中心、关闭旧网页后重复使用失效标签、后台开页和右侧展示不同步的问题。目标不是调整窗口标题或只隐藏黑框，而是让普通浏览器页面的承载、身份、绘制和展示在一个可长期维护的宿主模型内收口。

产品范围及非目标以 [R07–R14](../需求.md) 为准。不重做整个浏览器、不引入第三方网站权限扩张，也不在本子项决定 F16 调度规则。

### 2. 整体调整思路

**采用 BaseWindow＋显式 AppShell WebContentsView＋普通网页 WebContentsView 的单窗口组合，继续由主进程持有页面。** 学习 Orca 的稳定生命周期和绘制保活思想，不照搬其 WebView 网页组件。

```text
                         单一原生主窗口 BaseWindow
  ┌──────────────────────────────────────────────────────────────┐
  │ 顶层：当前展示的原生网页／文件或 MCP 视图（由布局拥有者裁决） │
  │ 中层：AppShell WebContentsView（现有可信 UI、菜单、工作区）   │
  │ 底层：其他任务／标签的网页 WebContentsView（按需绘制）        │
  └──────────────────────────────────────────────────────────────┘
                 ↑ 布局、焦点、绘制许可与资源生命周期
             主窗口宿主适配 ＋ 浏览器页面注册表／工作区
                 ↑                     ↑
       UI IPC／展示意图          现有 MCP／CLI → BrowserService
                                          → 页级执行／回执
```

四条设计主线：

1. **承载与展示解耦。** 页面从创建到关闭始终归同一浏览器注册表；切换工作区改变可见层次或几何，不变更原生页面身份。主窗口隐藏不等于退出，普通后台页不再依赖另一个 BrowserWindow。
2. **页面状态与绘制分离。** 保留页面逻辑、会话及合法在途操作；显示或截图所需的绘制按使用者取得、释放相应保活占用，背景内容不可交互于用户界面。后台闲置策略须通过真实页面计时、资源及画面回验，不以简单切断渲染实现节省资源。
3. **业务目标与展示意图分离。** 开页的逻辑目标、产生的 pageId、任务和身份不变；用户是否正在看这一页由单独的展示意图及当前界面选择裁决。关闭旧页使旧目标失效，新的用户请求有独立身份与展示生命周期。
4. **最大限度复用。** BrowserService、BrowserWorkspace 持久状态、既有应用能力、agent-browser／页级 CDP、操作回执、权限、下载与身份分区等继续作为业务基础。只替换承载通路、适配窗口及生命周期，补齐重开／展示契约，不建设第二套浏览器业务。

### 4. 调整方案概要

#### 4.1 创建、展示和回收

1. App 创建或恢复唯一主窗口宿主，建立显式 AppShell，加载原有可信 renderer。普通页面由 BrowserPageRegistry 所有，不需要等待右侧组件挂载；如果后台任务触发时主窗口尚未显示，由同一宿主进行非激活初始化（冷隐藏是待实验门槛）。
2. 现有 BrowserService 接入，按原授权和 profile 解析页面目标；注册逻辑页与原生 WebContents，并装配现有 CDP／事件／helper／队列。实际 ready 与 UI 展示状态分别发布。
3. 在当前右侧槽位显示页，校验 rect 及当前用户选择；将其置于 AppShell 上方、按本次缩放转换定位。其他页在 AppShell 后方，绘制与交互标记独立。
4. UI 关闭面板或切换任务时取消可见布局，保留页面资源；需要在后台操作时持有绘制占用，结束后只释放自己所属占用。程序不能把后台内容推到前台。
5. 显式关页或真实资源结束时按关闭链释放该页，不影响其他标签。App 真正退出时关闭全部受管业务 WebContents、壳内容、helper 和窗口；主窗口普通隐藏不触发此链。

#### 4.2 模块分工（拟定；名称和最小接口以 BE01 验证后定稿）

### 5. 详细设计

#### 5.1 主窗口宿主与可信界面

- 将主窗口创建需使用的窗口几何、标题、原生菜单、macOS 交通灯／全屏、显示器变更、关闭隐藏及真正退出契约保留。以 BaseWindow 管理外层，现有 AppShell 加载路径、preload、主题和 renderer 由独立 WebContentsView 承载。壳视图随内容区尺寸改变，并保留现有 UI 消息和缩放行为。
- 所有依赖旧 win.webContents 的调用改用明确的壳内容引用；需要原生窗口的调用使用真实 BaseWindow（如既有 API 仅支持 BrowserWindow，先做兼容实验并确定正确传参，不做不安全强制类型转换）。文件选择、下载相关对话框、复制／预览、菜单、通知、快捷键、焦点及退出均需回归。重点核查 BrowserWindow.fromWebContents 的旧路径不能在 BaseWindow 下返回空后错误使用焦点窗口。
- isMainRenderer 的信任判断仍只接受当前可信壳 WebContents 的 mainFrame 与当前允许的页面 URL，不把任意网页视图、旧壳或弹窗当作可信 UI。保持现有主壳安全配置；普通网页继续 sandbox、contextIsolation、无 Node integration、按原会话策略配置，不启用通用 WebView。
- 壳重载／崩溃时，窗口与页面注册表不随 React 组件销毁。界面恢复前旧壳 IPC 失效，普通页面按原任务/权限继续或明确停止；新壳从 snapshot 重新绑定已存在的标签和显示状态。若原生宿主本身丢失或页面被销毁，按保存数据恢复新原生身份并让旧引用／在途回调失效。
- Cold init 和真实退出必须串行化创建／清理：BrowserService 当前早于 createMainWindow 组装，改造须支持唯一宿主就绪握手。无需显示窗口即可接后台请求的可行性由 BE02 验证。BaseWindow 关闭不会自动保证子 WebContents 回收，明确先停止新请求、结算／关闭各页，再释放壳和主窗口；普通 macOS 隐藏窗口与真实退出分开。
- 若 native popup 是用户可见、具有原生 opener 的必要窗口，仍允许按原规则创建；不为普通后台页、闲置页或恢复任务创建额外假窗口。

#### 5.2 视图组合、尺寸和绘制占用

保持同一 BaseWindow 中显式 z-order。背景页不得占到 AppShell 或当前用户查看视图之上；当前需要展示的网页或文件视图由右侧工作区所有者定位，以可信 renderer 的布局和壳 zoom 换算实际窗口坐标，复用已有边界校验。主窗口 resize、跨屏 DPR／zoom、导航变化时重新校验几何和版本。

| 逻辑状态（拟定运行态，不是新持久化枚举） | 进入条件 | 原生视图和绘制 | 退出／异常 |
| --- | --- | --- | --- |
| 未加载 | 已保存标签或新建空白标签尚未导航 | 原有启动页／占位；不必分配网页引擎 | 首次有效导航按身份初始化 |
| 初始化／加载 | 受理合法创建、恢复或身份切换 | 同一宿主分配新视图和页级执行上下文；显式展示的页保持加载状态 | ready、failed 或取消；失败／关闭时清理已分配内容 |
| 前台展示 | 当前任务、标签、面板与最新布局匹配 | 前景层正常显示，只有这一可见页与合法原生浮层接受相应交互 | 用户切换／收起转后台，不销毁 |
| 后台闲置 | 页面已存在、非展示且无绘制占用 | 放在 AppShell 后方；优先验证可暂停绘制但不破坏页面逻辑的方式 | 有绘制需要则取得占用；若隐藏导致业务计时／导航退化，按实验结论调整策略 |
| 后台绘制 | Agent／截图或既有业务操作需要绘制，且页面有效 | 同一页在壳后维持可绘制状态，原尺寸保持；不激活窗口、不接受用户鼠标 | 各持有者完成后独立释放，最后一个释放才可回到闲置 |
| 关闭中／关闭 | 用户关页、任务/身份退役、真正退出或原生页失效 | 禁止新操作，撤销旧展示、queue／引用；等待必要收尾并解除 view、关闭 WebContents、helper | 不能被迟到的加载／截图／展示回执重新挂回 |

绘制占用借鉴 Orca 的 paint hold，用一页多持有者/可靠释放的形式实现（详细 API 表见后文；实现复用现有队列和 abort）。

- 前台显示是一个独立的占用来源；后台命令、截图、冻结脚本等需要绘制时也取得占用。每次占用和原生页面身份绑定，不允许旧页面的 release 影响新页面或其他任务。
- 需先确保正确 layer order、size 和可绘制状态，再运行需要真实 frame 的操作；用页面计数与截图像素验证可用性，不只依赖 IPC 返回成功。不要用 Page.bringToFront 或系统激活来证明后台执行通过。
- 以底层操作明确完成、失败/取消已结算或原生页关闭为释放条件；外层等待超时不能假定底层截图已结束。对多个同时运行的命令、取消、导航变更、dispose 逐一验证，释放动作幂等，不留孤立 hold。
- 前台 native view 可能仍盖住 DOM 浮层；保留现行 overlay（多 owner hold、截图背景、收起当前页）可用性，重构为同一窗口内层级调整。HTML／MCP 预览与下载、权限、认证、菜单等只有通过 BE06 的替代方式才简化。遮挡期间不能把真实网页的交互交给后台视图。
- 原生层级变化只能在宿主协调的布局入口发生；其他模块不自行重排背景页；单个右侧槽位的前景拥有者、有效 rect、任务及关闭状态必须一致。

#### 5.3 标签、身份与在途操作

以 BrowserWorkspace 的保存标签/当前选择和 BrowserPageRegistry 的原生页为两个层次，不增加第三个持久化页面清单。

- pageId 是业务逻辑标签标识；原生 WebContents 和 documentGeneration／引用范围是实际执行上下文，配合既有 opening、closing、AbortController、队列及 placementVersion。页面重建（身份切换、应用恢复、engine 销毁）使用新的原生代际，拒绝旧事件、旧引用和旧权限；是否需新增内部 epoch 字段由实验确认，不写入 v1 持久结构。
- ensure 同一逻辑页只建立一份原生实例，初始化停机/关闭竞态下不能发布用户已经关闭的页。不把路由切换或 UI dispose 视为 page.close；真正 close 先取消待导航/展示，对在途命令和效果按已确认回执收尾，关闭子页/引用/helper，最后删保存标签或放入原关闭列表。
- close 之后以相同 URL 新开时，从当前任务且同一有效 profile 的仍存在 tabs 匹配，找不到则生成新 pageId。旧 ID 不复活；同请求编号重复只回原 operation receipt，新请求有新的 requestId；失效目标不向其他任务或其他身份降级匹配。
- popup 延续原版的 opener／session 约定，明确普通新标签和真实可见子窗各自宿主；身份切换、Cookie 导入暂停、任务／profile 删除均保留既有生命周期锁、队列和清理，不跨任务共享 WebContents。

#### 5.4 开页契约和展示事件闭环

当前问题分为已证实的调用参数与失效页错误，以及尚需复现的展示事件丢失。两者独立修复，不认为换承载层就必然解决展示问题。

1. 在浏览器命令定义的唯一生成源表达 url 与 pageId 二选一（当前主进程已校验）；指定 pageId 沿用原身份，不与 new 或新的 profileId 同时使用。需代码分析／实验：当前生成器、应用契约校验器和 MCP schema 是否支持合适的互斥表示；若受限，在实际发送给 Agent 的说明明确约束，并保持严格宿主校验。不能只手改 generated JSON。按现有应用包版本与会话兼容规则发布变更，不覆盖旧冻结会话的契约。
2. browser Skill、错误反馈及入口说明统一：每次使用回执中的当前 pageId；失效时先重新查询标签；新的用户开页意图可按 URL 新发请求；明确指定已关闭页的动作返回原有 BROWSER_TAB_NOT_FOUND／相应参数错误，不隐式重开旧页或重复写操作。旧会话仍有可读、正确的恢复错误。
3. UI 发送新输入时记录该用户请求的展示身份；主进程在接受开页时登记页、回执与展示意图关联。R12 要求的 show 开页应先发出可核验的加载/标签状态，再发布就绪或失败，后台模式不强制打开面板。
4. 复用 browserOpenPresentationEvent，在渲染端核验 taskId/pageId/clientInputId/operationId 和最新用户选择。将真实手动切换、显式关闭与旧异步空标签清理分开：前者可撤销其后仍在途的旧展示，后者不得错误撤销在其之后新发起的展示。通过 BE05 记录事件、guard 匹配、select、panel.open、snapshot 和实际渲染顺序，定位现场根因后定具体实现（现有 openingTabs 只追踪部分 UI 开页，存在需要验证的竞争）。
5. 成功从当前任务进入目标页时，activeId 和实际显示页一致；用户已切走、旧页已关闭或请求来源失效时，禁止自动打开／抢焦点。保留成功结果和对应标签的主动“查看网页标签”入口，页面不存在时显示明确失效原因。直接 MCP 调用与需要批准的 host business 回执都要覆盖。
6. 收敛展示状态的诊断：在隔离实验/必要诊断收集经过脱敏的关联标识与状态转移、失败类别，不记录账号密码、网页输入、站点内容或私人 URL。不把日志当成授权或绕开真实 UI。

### 7. 风险与边界

- **宿主兼容**：BaseWindow 与 BrowserWindow API 并非完全等价。文件 dialog 父窗、main IPC 验证、MCP/HTML zoom／focus、macOS 原生窗口行为必须作为最早门槛。
- **渲染保证**：BE00 只测试合成页及明确原生层级，未验证完整 App、关闭最后页、冷隐藏启动、Mission Control 实际系统空间、持续运行和生产级 agent-browser；不能把初步成功外推。
- **按需绘制**：隐藏后的页面行为以及真实输入操作、截图、计时资源曲线需测。不能凭截图回执或 CSS 看不到就判断绘制和鼠标穿透正确。
- **兼容安全**：现行任务／profile／授权、网页隔离、登录与用户批准、页级代理和回执保持；相关真实凭据的测试由已确认本人操作完成；合成页验证不冒充真实业务网站或登录态通过。平台适用沿需求约定执行。
- **无人值守**：F36 不引入退出后持久进程或新的自动化许可；App 隐藏/最小化不等于进程退出。
