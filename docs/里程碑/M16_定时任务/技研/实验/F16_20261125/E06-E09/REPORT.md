Worktree candidate explicitly borrows the existing child-oriented preparation function by supplying the first existing real top-level task as both its required identifiers. The experiment-only SQLite table experiment_plan_workspaces proves stable lookup and reuse by later new tasks. The old interface needs adaptation: agent_workspaces has RESTRICT references to task IDs; GitWorkspaces.workspace is child-task indexed; normal create controller resolves cwd to the original registered directory; FileSourceResolver labels a top-level task by actual cwd but only special-cases delegated children for workspace branch display. A dedicated plan must own persistent worktree identity independent of any individual task lifecycle. The first actual task should use the actual prepared cwd; a subsequent new task must point to the same plan workspace independently. Per-run worktree record needs the actual run identity; selected base reference and resolved commit are separate from the repository's currently checked-out branch. Source mismatch or missing original worktree are explicit invalid states. Existing delegated auto-commit behavior is not used for scheduled top-level work.

Source baseline confirms home UI and agentTask controller currently require a project and registered directory. Active sidebar lists agentTasksStore.of(project.id); search and archived-task grouping have more general task visibility, but no active unassociated task group has been verified. Existing browser workspace.project() and renderer openNewBrowserTab hard-require projectId. Product needs a distinct typed standalone scope and explicit root/task/profile mapping; the prototype's string-key bridge is metadata feasibility.

The private host browser candidate uses a run ID in a synthetic provenance table to find the policy seam only. Production must bind provenance to a durable scheduled occurrence and its accepted original turn and inherited delegated/follow-up work. Source_kind=system covers other host messages too, and Agent sessions can be reused for later manual turns. On every new cross-task request, the trusted host must resolve the currently executing origin and distinguish a later ordinary user turn in a reused session. An existing valid scope/approval keeps ordinary semantics under its frozen review. Preserve the same native Agent selection, plugin policy maximums and actual human approval requirement.

The experiments establish feasibility and identify concrete wiring changes. No claim that a user-visible F16 schedule, actual standalone native browser, unattended execution across sleep or system notifications is production-ready or final App acceptance. F36 BE10/B12 must exercise the browser execution and notification conjunction after both features are implemented. No GUI resources used.
