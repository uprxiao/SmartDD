# M16 F36 浏览器单窗口承载实验计划

更新：2026-11-25。依据：[F36-R1.0／R07–R14](../需求.md)、[T1.0](技术方案.md#a-f36-内置浏览器单窗口承载重构-t10)、[A1.0](../验收/测试用例.md#f36-浏览器单窗口承载验收用例-a10)。BE00 和 BE01–BE08（含 Ultra Review）开发前研究已收口，BE09／BE10 为正式候选及联合验收。本文保留原研究方法、步骤与证据索引，不是另一套现行产品判据；正式候选以 A1.0 和原 M12/M15 受影响合同为准。原实验索引链接中的 R0.2/R0.4 依据可由 [需求历史](../历史/F36需求_R0.2_20261125.md)、[方案历史](../历史/F36技术方案_R0.4_20261125.md) 恢复；[实验计划定稿前历史](../历史/F36实验计划_定稿前_20261125.md) 保留。

## 1. 实验目标与共同约定

验证目标为一套长期可维护的 BaseWindow＋WebContentsView 单主窗口宿主：普通后台网页不占独立系统窗口，真实浏览器操作、会话状态、既有业务和安全边界不退化。实验先针对最可能否定方案的条件，避免先重构整个 App 再定位底层问题。

- 基线：2026-11-25 旧版代码基线 2e45d9eae（feature/0.1.7）／50b8ea211（bugfix），等价 Git Tree f68808df2c803640e312675791d6d53fdfaa67e0；项目 Electron 42.11.14。本轮后续实际旧版与实验候选均冻结于 `a0acddb3a2325c6bf732adaa7e954ce4d767a2c3`，同锁和 Electron；具体源码哈希、依赖补齐及资源复用见[冻结记录](实验/BE01_BE08_20261125/snapshot/frozen-source-metadata.json)。正式候选仍须另冻结实际源码、锁和依赖、平台及测试夹具；变化必须记录。
- 运行：以 feature 工作区为来源，在隔离临时目录或实验 worktree 运行，独立 HOME、userData、测试项目、回环站点、任务、profile、数据库及调试目标。优先复用 [真实 App 自动验收流程](../../../真实App自动验收流程.md)、仓库 scripts/browser 现有夹具及 harness。生产代码、日常 App、用户账号与数据不用于破坏性实验。
- 数据：本地合成页具唯一页面标记、按钮实际点击计数、文档/计时器身份、未提交表单、可控制延迟与错误、可验证截图颜色；每个任务/身份独立。涉及真实站点登录等只在后续具备授权和本人前置时验，不构造真实凭据或把合成成功当成真实登录通过。
- 判据：实际页面事件、内容像素、页面/标签/原生身份、用户所见界面与持久化数据一致；不以仅有 IPC/CDP 返回、DOM visibility 或 CSS 隐藏判通过。记录点击、截图时延及资源数据，适用 M12 原门槛（T107、T110、T111 等），不把 BE00 单次速度当生产 SLA。
- 取证：每个 BE 单独保留脚本/fixture 基线、源码及依赖哈希、隔离路径/进程身份、前置和时序、期望/实际、失败与复验、必要截图或审计。浏览器事件取脱敏关联 ID 和状态，绝不收集私人 URL、账号密码、真实网页输入或用户会话内容。
- 分层：E=技术探针、U=单元、I=集成、A=隔离真实打包 App、S=原生系统／需要本人确认的验收。系统焦点/调度中心是真实 S 项，后台 CDP 不能代替。实验结果与正式 M16 用例账分开；BE00 不计入产品用例通过数。

## 3. 实验方法、环境与原始判据

BE00–BE08 以下保留开发前研究方法和历史验证口径，含指向正式阶段的建议；现行生产实现以 T1.0、正式用例以 A1.0 为准，不能以历史隔离实验代替该层级。

### M16-BE00：已完成的基础对比

本机 macOS arm64／Electron 42.11.14，隔离应用窗口和固定本地合成页面。第二轮明确使用 BaseWindow 的独立壳与网页 view 根层级；对比正常显示、主界面覆盖、其他页覆盖、退出闲置后恢复、窗口隐藏/最小化，以及基于 WebView 的透明/遮挡近似模型。对实际点击计数和截图颜色作核验。

实际结果与局限、原始脚本、JSONL、汇总和合成页截图全部保存在 [BE00 记录](实验/BE00_20261125/README.md)。单次技术探针支持选择单窗口原生组合，但不证明真实 App、冷隐藏、系统空间、长期性能、其他 Electron 版本或 Orca/T3 完整产品。

### M16-BE01：主窗口宿主&壳适配门槛

**前置与数据：** 当前 Electron 依赖、干净隔离 App；使用原 renderer/preload、合成项目/任务、可授权的临时文件、基本 HTML/MCP 合成资源。保存现有 BrowserWindow 行为作为对照。

**步骤：**

1. 单独建立 BaseWindow＋AppShell WebContentsView 候选；加载相同 renderer、主题和 UI 事件，检查内容区缩放、原生标题栏、窗口 resize；在不修改浏览器业务的前提下，将窗口和可信壳身份分别获取。
2. 走真实 UI 新建任务/切换页面、文件打开/保存或选择、系统菜单／快捷键、浏览器/文件/终端或 MCP 入口。重点检查原窗 API 调用、BrowserWindow.fromWebContents 替代、父窗绑定、IPC sender/mainFrame、壳 zoom 和焦点。
3. 在合成普通网页、子窗及不再有效的旧壳中验证不被当作可信主 renderer；壳 reload 或失效后恢复时检查合法 UI 仍正常。此处只验证既有安全边界，不扩张权限。
4. 对主窗口正常退出/关闭隐藏、恢复及重新激活路径做最小独立验证。在解释新的宿主方案时明确 BaseWindow 子视图负责显式释放的差异。

补充复验：并发 cold-init 共用一个 host、加载中 show 不暴露未就绪壳、load fail 全 owner 收尾可重试；native-ready、shell-loaded、ui-bound 分离，订阅前丢失/重载旧 intent 不抢界面；退出 busy 取消、save/discard/commit 拒绝、再次正常退出。真实壳 reload 立即降层、返回同页。

**通过判据：** 相同功能入口、窗口操作和可信界面消息可用；窗口/壳引用绑定准确，非可信页得不到原 UI 能力；无新窗口兼容阻塞或有已验证且不削减原要求的修正。记录 API 差异、必要改造路径与未通过项。若该门槛失败先解决主壳，不开始大规模 browser 迁移。

**已有证据：** [BE01／BE02 补充探针](实验/BE01_BE02_20261125/README.md)核实 BaseWindow 和独立壳的 API 实际身份；[实际旧/新壳与候选代码验证](实验/BE01_BE08_20261125/README.md)已覆盖真实壳、启动、相关 IPC/类型及正常退出的部分路径。补齐原生父窗、系统操作、壳异常及相关回归后才能判定整组。原生窗口查询和可信壳身份须独立判定，不以 TypeScript 返回类型或同宿主身份证明可信。

### M16-BE02：背景绘制、实际输入、冷隐藏

**前置与数据：** BE01 最小候选，两个独立测试任务及合成按钮/截图/文档标记，可控制加载延迟；使用现有页级 agent-browser／CDP 通路与既有焦点保护。

**步骤：**

1. 分别运行普通显示、网页下沉至 AppShell 后方、另一网页前台时、后台闲置后取得绘制占用、收起浏览器面板、切换任务、恢复前台；对同一逻辑 pageId 和原生身份各执行前台与后台输入/截图采样。参考 M12-T107/T108 原步骤，核实际点击计数与截图像素。
2. 冷启动后主窗口从未 show、先隐藏再创建新页、主窗口已装载后 hide、minimize 等分别验证，避免只证明“先显示后隐藏”的旧探针条件。测试后台页加载、等待、点击/快照/截图及 UI 返回。
3. 同页并发绘制持有者、截屏进行中切换面板/标签、上层等待超时，按原页代际独立释放，底层完成后查看占用状态；闲置与持续网页计时、未提交表单、登录态保持一并验证。
4. 取得原 baseline 与候选多次重复测量：实际命令结果、时延、尺寸、文档、焦点归属和截图准确性；不得通过系统前台激活或改 DOM 代替用户操作。

补充复验：真实 CSS animation、rAF Canvas、timer、延迟异步 payload 在 hide/restore 的文档和实际新帧像素；双持有者、乱序/幂等释放、前景与截图交叠、外层 cancel/timeout 时底层未结算、关闭及旧代际释放隔离。不能假定隐藏使逻辑暂停或资源降低。

**通过判据：** 原受影响的 M12 后台实际输入/截图及状态保持门槛均满足，冷隐藏可用或明确存在经用户确认的边界；常态只有主宿主，背景页不抢交互。根据结果确认闲置策略、绘制持有/释放点，并保存失败重现与修正。

**已有证据：** [BE01／BE02 补充探针](实验/BE01_BE02_20261125/README.md)覆盖合成冷隐藏；[隔离候选实际注册表和 helper](实验/BE01_BE08_20261125/README.md)已覆盖从未显示的宿主、两个项目页面、快照、背景实际点击、PNG 像素及关闭回收；[实际开发构建](实验/BE01_BE08_20261125/README.md)覆盖工作区切换与原生层级。完整 service 命令、按需绘制持有并发、超时和系统隐藏/最小化仍按原受影响契约验证，不另造新的性能标准。

### M16-BE03：原生系统窗口与调度中心

**前置与数据：** 同一隔离候选包，普通测试网页，实际 macOS 显示器配置（当前探针见 3 屏，以执行时为准）。

**步骤：**

1. 打开普通网页后查看普通窗口、Dock／应用切换、调度中心及窗口菜单；记录原生窗口身份和实际系统缩略图。候选不含命名为 WillYou browser background 的普通后台窗。
2. 主窗口进入全屏、切换 Space 及不同显示器，保持一个后台 Agent 合成页命令执行；退出/恢复主窗口并检查页面、尺寸和回执。另测最小化、关闭隐藏及重新打开。
3. 显式打开合成需要真实原生子窗的场景，仅校验该合法子窗可见和可关闭，不把它计为后台黑框。比较目标窗口与已有 App，系统操作只针对本轮隔离窗口。
4. 纯页面用后台驱动；Mission Control／全屏、原生真实窗口、跨屏焦点和物理点击按 S 层实际证据验证。无法自动观察或需本人时登记后完成其他可自主步骤。

补充复验：严格等原生 enter/leave-full-screen 完成事件、确切本轮 PID/title/稳定窗口几何；只截本轮自有窗口，避免动画帧。新旧对照窗口数和复原后文档/实际点击；Mission Control、真实系统键鼠/焦点、显示器切换仍按原系统步骤另证。

**通过判据：** 普通网页不增加独立后台系统窗口／独立 Space，不误抢系统焦点/鼠标、不破坏主窗全屏/切换及后台自动化。参照 M12-T109/T110 受影响的系统判据；必须拥有实际调度中心证据，不能只检查 Electron 隐藏属性。

### M16-BE04：开页契约、关闭最后标签及数据身份

**前置与数据：** 两任务／两 profile 的本地测试站点，有相同与不同完整 URL（查询、锚点），可延迟加载；使用现有 MCP/CLI 入口/应用契约与现有回执模型。

**步骤：**

1. 打开网页取得旧 pageId，真实 UI 关闭最后标签；确认 closed 保存记录与原生生命周期收尾。对旧 ID 发送指定页的合法格式请求，应明确失效，不发生新访问。
2. 分别验证同时传 URL 和 pageId 的实际工具契约与宿主错误、缺目标、关闭 ID、不同任务／身份、合法 URL、已有活页 reuse-or-new、明确 new。检查失败不产生意外导航/效果，合法的新请求返回新 ID。
3. 同一 requestId 重试只能读原回执；关闭/撤销后迟到导航不恢复旧页。新用户再次要求开页使用新的输入/请求标识，不强制绑定前一轮的旧目标。
4. 从实际生成的能力契约检查互斥表达和 Skill 指引；验证已冻结的旧会话收到可读错误，新会话正确选择有效页。若生成器/校验器只支持部分 schema，保留严格宿主校验并验证 Agent 可见说明确实覆盖恢复流程。

补充复验：close 受理同步排除匹配/explicit ID，重复 close 只一次底层/历史，真实 UI 与 service 同时关闭及回调不自等待；同 URL 一方取消、全部取消后新请求，旧自动建占位按用户是否接手处理，旧 loader/迟到回执不复活；故障和失败保留原回执与历史。

**通过判据：** 已关闭 ID 始终不可访问，用户新开页不需已存在标签，匹配正确、不跨身份；错误有明确恢复说明，回执/审计一致。复用 M15-A02/A03/A04/A08 及相关用例。

### M16-BE05：新展示意图和旧面板清理竞争

**前置与数据：** BE04 的网页，隔离真实 App，至少覆盖 Claude 与 Codex 的可用真实宿主工具调用（不使用用户业务日志或真实凭据）。对渲染事件设定可控的延迟/失败夹具，正常流程与注入分别记录。

先在当前已冻结的旧版基线上复现并保存关页、新展示意图与空面板清理的失败时序，再在新候选中验证同一红测。现有源代码中的 revision、`openingTabs`、`onCloseSurface` 等仅为需定位的路径，不提前认定是现场失败的唯一根因。

**步骤：**

1. 复现现场主流程：打开一个网页 → 关闭最后网页 → 确认右侧为空 → 同一任务发起新的明确展示请求。分别立即响应与扣住站点响应，观察先加载后 ready 的同一 pageId 及右侧状态。
2. 记录脱敏时间线：新用户输入与记住意图、tab open 受理/回执、host 事件发送、renderer guard 判定、select、panel.open、refresh snapshot、实际可见标签。确定原“后台已成功、前景空面板”的失效点，区分真实用户选择与旧空标签收尾，不用推测替代证据。
3. 分别在旧关闭响应尚在途、重复渲染/迟到空 snapshot 时发新请求；在新请求之后用户明确切换面板/任务或关闭新页，放开旧/新事件。已失效事件不得抢回界面，仍有效的新展示不能被旧程序清理误撤销。
4. 纯后台 mode 不抢当前页面；直接 MCP 与 host business 批准等路径保留成功页主动查看入口；点击查看对应页仍在当前任务且存在时正确选择，关闭后返回明确失效。
5. 保留 M15-A01、A06、A07、A08 原判据，新开页失败也要有明确状态。必要时以独立单元/集成重放实际失败事件时序，并用真实 App 验证。

补充复验：壳主 frame reload/首次订阅前事件，保留实际网页和结果入口；不能验证旧意图仍当前则不自动抢显示，新明确意图与最新 snapshot 照常。真实旧 native null 与新的 A→B→A 实例清理、事件和页面选择对应。

**通过判据：** 正常新请求能在右侧显示目标/加载/失败；关闭后重开不漏展示；切换/关闭后旧事件不恢复用户已撤销的页面或抢占 UI；成功回执和可见页的身份相符。记录确证的根因、新的状态契约及回归证据。

### M16-BE06：右侧组合、原生浮层与键盘焦点

**前置与数据：** 同一隔离包中准备浏览器、文件/HTML、MCP UI、差异、终端等合成可验证资源；浅/深色、窄窗、不同 zoom 及至少两个背景页。

**步骤：**

1. 相邻/切换原生预览与普通浏览器，核对 rect、缩放、最大化、调整面板宽度、标签/tooltips。打开浏览器地址栏、查找、设置、下载、认证、权限、JS 对话框等浮层，保持可点击且层级正确。
2. 多浮层分别关闭和在途截图取消，观察各 overlay owner 恢复作用于正确页，浏览器真实页面没有穿透到受遮挡区域；切换后无残留悬浮或空白。
3. 从浏览器、任务输入框、终端、文件树分别触发已有快捷键/聚焦，测试 Agent 合成点击时背景页面不会夺取用户正在输入的界面。真实系统输入/文件选择按相应 S 层验证。
4. 对 BaseWindow 下 HTML、MCP、文件 chooser/复制等调用检查父窗、zoom、焦点与资源释放，同样比较旧包。不得为通过窗口重构而删掉既有工作区功能。

补充复验：UI 发起布局时的 host/page/surface 实例代际及序号（非主进程到达顺序）、旧 A null 到 B 和新 A、await 中 A→B→A、同 owner overlay reentry 后旧 close/capture 返回；同时核最终及瞬时 native 层级、共用 HTML/MCP 前景和其他浮层。

**通过判据：** 所有受影响入口布局／交互及主题保持，无原生页盖住应用浮层或背景交互抢占。在相同页面、主题、尺寸与缩放下对照 M12／M15 旧包与候选，只有需求确定的既有故障状态纠正，非目标视觉／交互保持；保留对照证据及受影响模块、必要兼容变化和回归清单。

### M16-BE07：旧数据、身份、登录/弹窗和业务兼容

**前置与数据：** 独立测试库及 profile 分区，采用 current v1 标签结构和旧版生成的合成会话/记录；本地站点 Cookie 唯一值、未提交表单、下载/权限/JS dialog 及 opener 回调夹具。真实外部登录单独按本人批准范围补验。

**步骤：**

1. 在旧版隔离实例生成多个 task/profile、保存标签及操作回执，正常退出并备份测试数据；新候选读取同一隔离数据，验证无需清库或隐式身份迁移。核对 namespace/partition、显示与禁跨身份数据。
2. 后台与前台切换、应用隐藏、正常重启、身份切换／复制／删除、导入暂停恢复，检查页面保持或按原规则重建、旧引用失效。重启后保留原约定的持久数据，不将未保存表单跨进程退出作为新增承诺。
3. 验证既有合规本地弹窗、子窗/新标签及 opener 对应、请求批准、下载、证书/权限提示、登录接力、脚本及结果回执。原任务、身份、原页关联必须保持；正常会话及失效路径各覆盖。
4. 测试普通网页不能取得 App UI IPC 能力，页级操作限于原授权目标；本人验证/授权仍为现行机制，不以新的承载层扩张能力。

补充复验：旧实际合成数据生成正常退出→候选读写关闭/新页→旧版读取候选写入→候选受控异常退出→候选恢复；站点不重发 Cookie，其他任务不变，旧页不复活，结束后按完整数据根核 owner 和 SQLite integrity；首次测试过期夹具须重新生成，不能放宽预期。异常退出范围记清，正式候选保留升级/回退和真实身份生命周期。

**通过判据：** 表结构、profile、原权限、记录与有效操作仍兼容；旧无效身份或页面严格拒绝；不能恢复旧 cookie/数据时以具体差异阻断候选决策。涉及真实站点或本人前置未验的项明确留缺。

### M16-BE08：异常回收与长期资源

**前置与数据：** 与前序同基线候选，多任务多页合成站点，有加载门闩和可独立关闭的生命周期；仅在隔离实例进行故障注入。

**步骤：**

1. 测试打开中关闭／取消，排队执行中关页、身份退役、渲染壳 reload/crash、原生页崩溃、App hide 与真实退出等路径。核对迟到事件、等待超时、回执 unknown、旧 view/队列/引用/helper 的处置，不强杀日常实例。
2. 对绘制持有者并发和底层截屏未结算时的超时，验证有界等待及真实完成/取消后的收尾，不错误释放别的持有者；检查下一次安全恢复。
3. 按 M12-T111 已确认条件做资源压力：5 个任务页面、30 分钟、按原节奏真实命令与 RSS/CPU 采样、确认实际点击/截图。比较同环境旧包和候选；记录原生窗/页/renderer/helper 数、采样曲线与结束清场。必要时用独立小实验定位内存/CPU 或绘制占用持续增长。
4. 在正常退出后验证 App 无额外普通浏览器窗口、无残留本轮运行进程、原生内容与本轮监听/辅助进程；重启隔离候选读取保存记录确认不会恢复旧已关闭页。

补充复验：同一长寿命宿主保持 anchor 和不同任务，动态新页实际 helper 点击/异步任务/关页／同 URL 再开，逐批核 WC、owner、queue、client/daemon、socket 及 metadata/home；区分可重连 close 与终态 dispose，未结算/未知/共享资源不误删；自然清场与外部实验清理分开，保留原 T111 长测与异常重启。

**通过判据：** 受影响队列/回执/清理契约满足，恢复和关闭不会让旧工作复活；资源达到现有 M12-T111 门槛，差异若有须核因而非随意放宽阈值。记录原始数据和实际收尾结果，故障注入不冒充正常产品测试。
