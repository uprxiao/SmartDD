## 2. 现有实现：已从代码确认

### 项目“Skill 与 MCP”页

这页包含不同来源，不能把整页都叫自动扫描：

- 上方标准 Skill 是 WillYou 管理的内置资源及版本；项目上下文 MCP 是 WillYou 的配置开关。
- 下方按所选 AI 配置、工作目录和相应配置层读取 Skill／MCP，进入页面时查询，支持重新扫描。它是静态发现，不启动 MCP、不调用模型，结果的会话加载状态默认未核验。
- 扫描范围依 runner 而异，含用户／项目路径、配置覆盖与部分插件来源；不能据一次扫描声称已经覆盖所有版本、格式或实际执行状态。

源码：[页面](../../../../src/renderer/views/capabilities.tsx)、[预览聚合](../../../../src/main/core/capabilities/capability-service.ts)、[静态发现](../../../../src/main/core/capabilities/discovery.ts)。

### 现有“应用”

现有应用包含 Skill，但并非只靠 Skill 完成：已有应用包与资源校验、配置及凭据、项目选用与权限、MCP／CLI 能力路由、统一 Skill 库等实现。Skill 指导 Agent 调用，真实业务由受控工具及服务执行。

目前 `modules/index.ts` 静态导入禅道、邮件、示例和浏览器；`ApplicationModuleRegistry` 明确以编译注册为权威，单改 manifest 或数据库不能注册新业务模块。`BuiltinPackageRegistry` 只接受宿主已支持的应用。因此“内置应用改名为插件”和“新增外部插件无需改宿主源码／重打包”是不同的改造深度。

源码：[静态模块入口](../../../../src/main/core/applications/modules/index.ts)、[模块契约](../../../../src/main/core/applications/modules/registry.ts)、[内置包约束](../../../../src/main/core/applications/builtin-package-registry.ts)、[统一 Skill 库](../../../../src/main/core/applications/skill-library-service.ts)、[能力执行入口](../../../../src/main/core/applications/capability-execution.ts)。

当前图标也存在宿主固定分支：`AppMark` 主要在信封、手写折线和链接符号间选择；浏览器使用 `mark: link`。专业插件图标应研究由插件声明可追溯资源，统一尺寸、浅深主题和缺失回退，而不是继续增加应用名称判断。

源码：[当前图标](../../../../src/renderer/features/applications/controls.tsx)、[浏览器声明](../../../../src/main/core/applications/modules/browser/index.ts)。

## 3. Codex／ChatGPT：官方文档确认的部分

插件是可发现、安装、分享与发布的组合包，可以包含 Skill、MCP 服务或二者；MCP 服务可选返回 UI。Skill 负责工作流程，MCP 提供真实工具和服务访问；“插件目录／管理页面”与“工具结果中的交互 UI”属于不同层。

官方当前打包文档给出根 `plugin.json`、`skills/`、`mcp.json`、资源等组成，并保留 `.codex-plugin/plugin.json` 兼容格式。目录来源、缓存安装、项目启用与服务认证分别管理。不同客户端、来源和发布渠道有能力差异，不能推导所有插件都能在任意 CLI 或 WillYou 中直接运行。

可借鉴：插件身份与版本、能力组合、目录与包分离、安装与启用分离、展示元数据／品牌图标。官方资料能说明公开协议与机制；截图中的全部内部实现并未据此验证。

## 4. DeepSeek Harness：一手架构资料确认的部分

DeepSeek 官方仓库描述基于 Cordis 的可组合插件架构：插件向上下文提供服务、事件与可回收的注册效果；模型适配、工具、会话及 Agent 循环等也可由插件组成。profile 和 bundle 控制组合，插件管理器处理安装／启停／更新；热生效依赖 HMR，未启用时可能要求重启。不能把“支持插件”概括成所有变化都无需重启。

可借鉴生命周期、服务依赖、卸载清理、更新失败恢复等设计。它的目标覆盖完整 Agent 运行时，WillYou 当前是承载已有 CLI 的桌面宿主；是否引入 Cordis 或重构 Agent 核心需另行论证，不能仅凭架构介绍决定。

## 5. 建议讨论的首期范围（尚未确认）

| 范围 | 建议方向 | 待明确 |
| --- | --- | --- |
| 插件定义 | 统一身份、版本、来源、展示资源，允许 Skill／MCP／CLI 能力组合 | 首版包格式、独立 Skill 的归属、是否兼容外部协议 |
| 插件管理 | 发现、详情、安装／导入、启停、升级、卸载与状态诊断 | 本地目录／压缩包／Git／公开源支持哪些；是否独立于宿主升级 |
| 现有能力迁移 | 禅道、邮件、浏览器及数据库／SSH 标准 Skill 等建立归属清单 | 谁是内置、谁可卸载、MCP 与连接配置归谁管理 |
| 项目与会话 | 区分全局安装、项目授权、Agent 可用及实际加载 | 当前项目页与扫描入口如何收敛；旧会话如何更新 |
| UI 与图标 | 对齐 Codex 插件目录、侧栏、详情、搜索、添加、管理及相关状态 | 完整菜单／弹层／浅深／窄窗需补观察和原型；不把假目录当真实来源 |
| 兼容与迁移 | 保留原项目、连接、凭据、权限与可追溯记录 | ID／路径迁移、失败回退、运行中更新及停用语义 |

首期建议围绕应用与能力插件展开；“整个 Agent／终端／编辑器全部插件化”、完整公共市场运营、直接运行任意 Codex／DeepSeek 插件等先作为待决定的扩展边界，不默认为已确认。

关键待决：是否首版就要求第三方新增插件无需修改 WillYou 源码或重新打包。该项决定安装包协议、执行隔离和生命周期的技术深度，需在后续需求评审前明确。
