# P1 Codex 0.167.1 Skill 目录探针

2026-11-12。依据 R1.0 会话生效规则、T1.0 §4.2／§5.9。该项是生产接入前的补充实验，不替代 P1 验收，也不改写 A2 的原始结果。

## 环境与原始证据

- 当前 CLI／原生二进制 0.167.1；使用安装包内同一个原生 binary，协议由其 `app-server generate-json-schema --experimental` 实际生成。
- 每次新建临时 HOME／CODEX_HOME／项目；没有复制认证文件，没有 model turn，没有使用日常 Agent、MCP 或应用数据。仅调用 stdio app-server 的 initialize、skills/list、skills/extraRoots/set，传 `--disable plugins`、`analytics.enabled=false`。
- [不可变原始请求与结果](../验收/证据/P1-migration-20261112-a1/skill-probe/native-raw.json)、[原生 stderr](../验收/证据/P1-migration-20261112-a1/skill-probe/stderr.log)、[启动条件](../验收/证据/P1-migration-20261112-a1/skill-probe/launch.json)、[退出记录](../验收/证据/P1-migration-20261112-a1/skill-probe/cleanup.json)。过程正常 stdin EOF 退出 0，未调用终止信号。
- 首次尝试驱动使用 npm wrapper，但合成 PATH 只含系统目录，找不到 Node，退出 127，未进入 initialize。该驱动失败的原始证据另存同目录 `skill-probe-attempt-001/`；修正为明确的原生 binary 后重跑。不能将首次失败解释为 Skill 接口不支持。

## 实际结果

| 操作 | 原生结果 | 可得结论 |
| --- | --- | --- |
| 项目 `.agents/skills/inside/SKILL.md`；`-c skills.config` 指向根外的 outside Skill | 列表只含 inside 合成项，不含 outside | 配置路径启用规则没有让本探针的未知根被扫描 |
| `skills/extraRoots/set` 加入根外目录，再 skills/list | inside、outside 都可见且 enabled | 当前 app-server 可以扫描额外 Skill 根 |
| 改 inside 的 description 为 v2，普通 skills/list | 仍为 v1 | 当前缓存未因这一次磁盘修改立即失效；没有验证真实 turn 重载 |
| 清空 extra roots，再 skills/list | outside 消失、inside 为 v2 | 本操作改变根后刷新了本探针的列表缓存 |

本机 CLI help 另外显示 `--remote unix://PATH` 和 app-server `--listen unix://PATH`。独立 server＋每次运行冻结目录因此值得继续验证；本轮没有启动远程 TUI，也没有证明其原生身份、模型恢复、并发与收尾符合 WillYou 既有契约。

官方[配置参考](https://developers.openai.com/codex/config-reference/)把 `skills.config` 定义为按名称或单个 SKILL.md 路径启停；本机生成协议另有 `SkillsExtraRootsSetParams`。线上说明会变化，判断实际版本以本批原生输出为准。

## 下一步与禁止推断

先验证私有 server 是否可与真实 CLI／PTY 的内核身份链、默认 CODEX_HOME、按次配置及停止恢复一致，再决定生产适配。不改全局 CLI 配置，不使用日常 server，不为了目录探针改变产品需求；没有实际模型调用，不能把“列表可见”写成“Skill 已加载执行”，更不能把一个 server 的结果推成跨运行隔离已通过。
