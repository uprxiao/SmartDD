# 补验 A2：Skill 跨 Agent 生命周期（安装→纳管→另一 Agent 使用→更新／卸载／冲突）

日期：2026-11-10。依据：[技研审核](../../../review/review-20261110-1549.md) R06；需求 M13-R03。环境：macOS arm64，Claude Code 2.1.321，Codex 0.166.0。证据：[实验目录](实验/A2_Skill生命周期_20261110/)。

## 边界

全部离线：临时 HOME／项目／`CLAUDE_CONFIG_DIR`／`CODEX_HOME`，合成 Skill（含 frontmatter 与相对路径脚本 `scripts/hello.sh`，脚本只写本轮日志）；模拟模型真实发起 Skill 调用（Claude 经 `Skill` 工具，Codex 经 `exec_command cat`）并执行相对脚本。外网阻断，未接触用户 Skill 目录。Claude 用例的模拟模型以“助手消息条数”判断步骤，在 Claude 中未按预期递增而重复调用脚本直至超时（退出码 143），属驱动缺陷；功能证据（加载、正文版本、脚本输出、工作目录）完整，归档为去重结果。首轮 Claude 正文判定（只查 tool_result）与 Codex `skills.config` 尝试保留为 attempt1。

## 实测加载位置

| Claude Code（独立 `CLAUDE_CONFIG_DIR`） | Codex |
| --- | --- |
| `$CLAUDE_CONFIG_DIR/skills`、`<项目>/.claude/skills`、`--plugin-dir` 插件的 `skills/` | `$CODEX_HOME/skills`、`~/.agents/skills`、`<项目>/.agents/skills`、`<项目>/.codex/skills`（及内置 `.system`） |
| **不加载** `~/.claude/skills`、`~/.agents/skills` | 不加载 `.claude/skills` |

Codex 0.166 **不支持按次加入额外 Skill 路径**：`skills.config=[{path=…}]`（SKILL.md 或目录）、`skills.include=[…]` 多种写法均未加载（`skills` 下未知键静默忽略）。

## 生命周期结果

| 方式 | 加载与调用（v1） | 相对脚本 | 来源更新为 v2 | 来源删除 |
| --- | --- | --- | --- | --- |
| Claude：独立配置目录 `skills/` 下符号链接 → 源 | 列出并 `Launching skill: wydemo`，正文 v1 | 执行成功，cwd 为链接路径 | 新会话即为 v2 | 悬空链接被忽略，调用返回 “Unknown skill”，无崩溃 |
| Claude：`--plugin-dir`（本次会话插件，`skills/` 链接 → 源） | 名称带命名空间 `willyou-run:wydemo`，正文 v1 | 成功 | v2 | 同上 |
| Codex：`~/.agents/skills` 符号链接 → Claude 项目级源 | 列出、`cat` 读到 v1 | 成功 | v2 | 不再列出，无报错 |
| Codex：`<项目>/.agents/skills` 符号链接 → 源 | 同上 | 成功 | v2 | 同上 |

## 冲突与防自循环

| 编号 | 场景 | 结果 |
| --- | --- | --- |
| K1 | Codex 三个根目录各有同名 `dup` | **三项同时列出**，模型无法区分 |
| K2 | Claude `--plugin-dir` 与用户同名 Skill | 插件 Skill 带 `willyou-run:` 命名空间，不冲突 |
| L1 | 纳管链接（逻辑实测） | 首次 linked；重复执行 already；目标已有同名真实目录 → conflict，不覆盖 |
| L2 | 再次扫描目标目录 | 本方建立的链接识别为“已纳管”，不作为新发现；用户真实目录识别为外部候选 |
| L3 | 来源删除后扫描 | 识别为“已纳管·悬空”，应清理链接 |

纳管记录放在目标根目录旁的 `.willyou-managed.json`（不写入链接指向的源目录）；Claude 对目标根目录中的该隐藏文件无异常。

## 结论与方案

1. **单向跟随用符号链接最直接**：链接指向来源原件，来源更新即时生效、删除后悬空链接被两侧 CLI 安全忽略，WillYou 在下次扫描时清理；不复制、不改写源文件，满足“来源 CLI 为准”。
2. **按目标选择落点，避免改写用户目录和扩大作用域**：
   - **Claude（第三方 Provider，独立配置目录）**：链接放入 WillYou 管理的 `$CLAUDE_CONFIG_DIR/skills`；
   - **Claude（原有登录，用户 `~/.claude`）**：用 `--plugin-dir` 本次会话插件承载链接，**不写用户目录**，且带命名空间避免与用户同名 Skill 冲突；
   - **Codex**：无按次注入能力，只能链接到其固定根目录。用户级来源 → `~/.agents/skills`（与终端共享，属用户级作用域，可接受）；项目级来源 → `<项目>/.agents/skills`（写入项目目录，须在 `.git/info/exclude` 中排除以免污染仓库，或由用户选择不同步项目级 Skill）。项目级来源**不得**落到用户级根目录（作用域扩大）。
3. **冲突**：Codex 同名会并列显示，链接前必须检查其**全部**加载根目录，存在同名即标“冲突”交用户处理；Claude 用 `--plugin-dir` 时无此问题，独立目录方式同样需检查。
4. **防自循环**：以目标根目录的纳管记录＋链接真实路径识别本方产物，再次扫描不作为新发现；悬空链接自动清理。
5. 剩余：Claude 插件内 Skill 与 Codex 插件 Skill 的纳管归属（随插件管理，不独立同步）、WillYou 既有统一 Skill 库（M11）与上述落点的合并方式，进技术方案定案。
