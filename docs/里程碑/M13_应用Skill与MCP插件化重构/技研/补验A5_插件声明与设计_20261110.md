日期：2026-11-10。依据：[技研审核](../../../review/review-20261110-1549.md) R03／R10／R11；[插件技研](插件包协议与隔离实验_20261110.md)。证据：[实验目录](实验/A5_插件声明_20261110/)。纯静态声明、语义校验与无界面渲染模型实验；未改 `src/`，未启动 WillYou。

## 依据的现有禅道事实（只读）

- 能力 3 个：`zentao.object.list`（`zentao.work.list`）、`zentao.object.get`、`zentao.resource.read`，均 `zentao.read`／`read`／`safe-read`，槽位 `zentao`；旧工具名 `smartdd_zentao_work_list_v1`、`smartdd_zentao_object_get_v1`、`smartdd_zentao_resource_v1` 须继续可解析（`modules/zentao/index.ts`）。
- 列表输出含 `items[{id,title,status,assignedTo,reference}]`、`nextCursor`、`complete`、`problems`、可选 `presentation{labels,choices}`；详情输出含 `fields`、`body`／`history`／`attachments[]` 资源引用、`complete`、`missing`、`presentation`（`src/shared/application-zentao.ts`）。
- **字段名与枚举文字来自禅道服务器当前语言包**（`parseZentaoPresentation`），不是静态映射。
- 面板（209 行）：项目连接检查与引导、双页签、刷新、游标分页、部分失败提示、行打开详情弹窗（字段、正文、历史、附件预览）、“插入终端”（传对象引用）。
- 宿主迁移 `0017` 中的禅道表：`application_zentao_cursors`、`_files`、`_operation_objects`、`_operation_resources`、`_revisions`，以及共用的 `application_read_receipt_checks`。

## 声明草案 v0-draft2（相对 v0-draft 的新增）

[完整清单](实验/A5_插件声明_20261110/zentao-plugin/.willyou-plugin/plugin.json)与 8 个 Schema。新增：共享 Schema（`ref` 不透明对象引用、`resource` 资源引用）、`projectPolicy`、`legacyToolNames`、`retry`、`agentVisible`；界面声明新增：

| 原面板要素 | 声明方式 |
| --- | --- |
| 项目连接检查与引导 | `requires.projectConnection`＋`emptyAction`（宿主通用） |
| 双页签 | `tabs[]`，每个页签绑定固定输入 |
| 游标分页 | `source.pagination{type:cursor,inputField,nextField,pageSize}` |
| 部分失败 | `source.partial{completeField,problemsField}`／详情 `missingField` |

## 结果

| 编号 | 场景 | 实际结果 |
| --- | --- | --- |
| V1 | 完整禅道声明语义校验：列、rowKey、分页、部分失败、presentation、页签取值、详情输入模板、section 路径、附件字段、read 能力、动作、模板作用域，全部按能力 Schema 解析 | 0 错误 |
| V2 | 6 个反例：列字段拼错、分页字段不存在、详情路径错误、未知动作 `runShell`、模板引用 `{secret.token}`、页签取值不在枚举 | 均被拒绝，错误信息指向具体字段 |
| V3 | 无界面渲染模型（样例数据） | 得到双页签、枚举中文（`active`→“激活”）、下一页输入 `{kind:bug,cursor:c2}`、部分结果提示、详情动态标签（“严重程度：严重”）、正文／历史存在性、附件可预览判定（png 可、zip 否）、“缺少：history”、插入终端载荷为对象引用 |

结论：**禅道现有面板的全部要素可由通用声明组件表达**，宿主只需实现一次通用的列表／详情／资源／动作渲染，不需要禅道专用分支。真实渲染与视觉对齐在原型与 P1 中验证。

## 生命周期与数据设计（供技术方案采用）

| 环节 | 设计 |
| --- | --- |
| 安装 | 目录或 zip → 暂存 → 清单与 Schema、界面语义校验 → 树哈希 → 展示来源与权限、用户确认 → 原子激活（写安装记录与激活代数）；失败保持旧版 |
| 版本与运行中任务 | 任务快照固定插件版本与哈希；升级只影响新任务；旧版本在无引用后由既有资源回收清理 |
| 停用 | 不再注入能力与 Skill；已有连接、授权、历史保留 |
| 卸载 | 用户选择“保留数据”（私有目录与连接、授权记录保留，重装后恢复）或“删除数据”（删除私有目录、连接与密钥；授权与调用账本标记插件已卸载，历史任务仍可查看记录但不可再调用） |
| 禅道迁移 | 插件 ID 沿用 `zentao`，旧连接、凭据引用、项目授权保持原主键；旧工具名经 `legacyToolNames` 解析；宿主中禅道业务表迁入插件私有存储——一次性、幂等（迁移版本号＋逐表校验行数与哈希，成功后宿主表只读保留一个版本周期再清理）；失败回滚到内置实现 |
| 插件数据 | 每插件 `plugin-data/<id>/`（可含 sqlite），沙箱仅允许读写自身目录 |

## P1（正式开发第一步）硬门槛

以下全部通过前，不迁移禅道以外的任何业务，也不宣称插件机制完成；失败保留证据并回到方案调整。

1. 真实宿主端到端：Agent（Claude、Codex 各一）→ 现有 MCP／CLI 链路 → 插件子进程 → 结果，宿主包哈希在安装插件前后不变。
2. 真实签名 Electron 子进程（`ELECTRON_RUN_AS_NODE`）在沙箱下：无法读写 WillYou 数据目录与数据库，无法读取 WillYou safeStorage 钥匙串条目（用测试专属条目与假数据库验证，不读真实密钥）；跨插件私有目录隔离；子孙进程与符号链接／真实路径绕过均被拦截。沙箱不可用时拒绝启动插件并报错，不静默降级。
3. 协议限额：单帧大小、输出总量、并发调用数、进程数、握手版本与超时、取消与收尾均有上限并实测；超限只影响该插件。写操作结果未知时不自动重放。
4. 生命周期：原子激活与失败回滚、运行中任务固定版本、升级失败恢复、卸载保留／删除两路径实测。
5. 禅道迁移：旧数据幂等迁移、原连接与授权连续、旧会话旧工具名可解析、迁移失败可回滚。
6. 原生依赖：首期插件不支持自带原生 `.node` 模块，安装时检测并拒绝（声明支持边界，后续另议）。
