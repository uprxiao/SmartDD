# 补验 A4：Provider 一键接入（DeepSeek 官方直连、协议识别、模型目录与失败回退）

日期：2026-11-10。依据：[技研审核](../../../review/review-20261110-1549.md) R08；需求“Provider 一键接入”补记。环境：macOS arm64，Codex 0.166.0，Claude Code 2.1.321。证据：[实验目录](实验/A4_Provider接入_20261110/)。

## 边界

DeepSeek API Key 由用户在会话中提供，仅存放于仓库外 0600 临时文件、经进程环境传入，实验后删除；证据经检查不含 Key（用户已被提醒在控制台作废该 Key）。真实请求：`GET /models` 1 次、空请求协议探测 5 次（422／404，不计费）、Codex 与 Claude 各 1 次工具调用任务。真实请求经**白名单代理**，只放行 `api.deepseek.com:443`，其余连接记录后拒绝。未使用任何订阅；临时配置目录。

## 结论与方案

1. **DeepSeek 官方直连已实测**：同一个 DeepSeek Provider（地址＋Key）可同时供 Codex（Responses）与 Claude Code（`/anthropic`）使用，工具调用正常；不需要经 Magpie。
2. **一键接入流程**：
   - 预设 Provider（Magpie、DeepSeek）内置地址、协议端点与 Codex 目录来源；
   - 自定义“地址＋Key”：先 `GET {base}/models`（再试 `{base}/v1/models`）；再以空请求探测 `/responses`（Codex 可用）与 `/anthropic/v1/messages`、`/v1/messages`（Claude 可用）——422／400 视为支持、404 视为不支持、401／403 视为 Key 无效；探测不产生费用；
   - 模型列表 401 → “Key 无效”；超时／连接失败 → “服务不可达”；空列表或 404 → 允许手动填写模型 ID；
   - Codex 模型目录：Magpie 用 `/v1/codex/models`；DeepSeek 用内置官方条目；其余由模板＋`/models` 元数据生成，缺字段时使用模板默认值并允许在高级设置调整；
   - 列表成功不代表可用（A 组实验已见上游拒绝的模型），保留逐模型“测试可用性”。
3. **Codex 第三方 Provider 运行时须关闭后台账户相关连接**：默认会向 chatgpt.com／github.com 发起插件、应用同步与统计请求；在用户真实 `~/.codex`（含 ChatGPT 登录）下运行第三方配置时，这些请求可能携带用户订阅身份。WillYou 启动 Codex 第三方配置时加 `--disable plugins` 与 `-c analytics.enabled=false`（实测可消除全部外连）；Codex 自身插件的 Skill／MCP 由 WillYou 能力同步承担。
4. **目录缓存**按 Provider 实体（而非地址）隔离：同一地址不同 Key 可能有不同可用模型；目录与“测试可用性”结果随 Provider 存储，启动前随预检比对刷新（用户已确认“启动前自动＋手动”）。
5. **运行中断开**（启动后服务不可达、Key 失效）：Codex 会无限重连、Claude 会长时间重试（A3-N2），启动前预检无法覆盖；WillYou 需对运行中的任务做连续失败检测并提示用户中断／切换配置，不自动重放写操作。
