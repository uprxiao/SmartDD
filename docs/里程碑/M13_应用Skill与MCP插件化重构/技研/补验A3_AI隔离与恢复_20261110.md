# 补验 A3：AI 运行配置隔离、不回退订阅、并发、恢复模型与旧配置迁移

日期：2026-11-10。依据：[技研审核](../../../review/review-20261110-1549.md) R02／R09。环境：macOS arm64，Claude Code 2.1.321，Codex 0.166.0。证据：[实验目录](实验/A3_AI隔离与恢复_20261110/)。

## 边界

全部使用诱饵令牌与本机模拟模型；临时 `CLAUDE_CONFIG_DIR`／`CODEX_HOME`，`HOME` 保持真实（使钥匙串查找路径与实际一致）；外部连接经**记录代理**（记录 CONNECT 目标主机后拒绝），未使用、未读取任何真实订阅或密钥。前后核对 `~/.claude/settings.json`、`~/.claude/.credentials.json`、`~/.claude.json` SHA256 不变。旧配置分类只读取变量名与选项名，未读取值。

## Claude Code：不回退订阅负例

所有用例的记录代理日志均为空（**没有任何连接 Anthropic／claude.ai 的尝试**）。

| 编号 | 场景（独立配置目录） | 实际结果 |
| --- | --- | --- |
| N1 | 只设 `ANTHROPIC_BASE_URL`，无令牌 | “Not logged in · Please run /login”，退出码 1，无请求 |
| N2 | 失效令牌（模拟 401） | 向配置端点重试 7 次后被 60 s 超时结束；不回退、不外连 |
| N3 | `ANTHROPIC_AUTH_TOKEN`（有效）＋`ANTHROPIC_API_KEY`（诱饵） | 两个请求头**同时**发往配置端点 |
| **N4** | 只有 `CLAUDE_CODE_OAUTH_TOKEN`（诱饵订阅令牌）＋第三方 `BASE_URL` | **诱饵订阅令牌作为 Bearer 发往第三方端点** |
| N5 | `CLAUDE_CODE_OAUTH_TOKEN`＋有效 `ANTHROPIC_AUTH_TOKEN` | 使用 `ANTHROPIC_AUTH_TOKEN` |
| **N6** | 配置目录残留 `settings.json` 的 env（另一端点／令牌） | **残留 env 覆盖进程环境**，请求发往另一端点 |
| **N7** | 配置目录残留 `apiKeyHelper` | 助手输出作为 `x-api-key` 与 Bearer 一并发送 |
| N8 | `--settings` JSON 的 env | 覆盖进程环境（优先级最高） |

用户当前登录 shell 未设置 `CLAUDE_CODE_OAUTH_TOKEN`（只检查是否设置，未读值），已设置的 `ANTHROPIC_API_KEY`／`ANTHROPIC_BASE_URL` 会被 WillYou 现有 `ISOLATED_ENV_PREFIXES`（`ANTHROPIC_`）清除；但该规则**不覆盖** `CLAUDE_CODE_OAUTH_TOKEN`。

## 恢复模型解析

| 编号 | 场景 | 实际结果 |
| --- | --- | --- |
| R1 | 模拟服务端返回的模型名与请求不同（`req-model` → `req-model-srv`） | assistant `message.model` 记录**服务端返回值** `req-model-srv`；同条记录另有 **`requestedModel: "req-model"`**；`api-request.params.model` 与每轮 `attachment.identity.modelId` 也记录请求值 |
| R2 | 恢复时 `--model req-two` | 新一轮 `requestedModel` 为 `req-two` |
| R3 | 恢复后该轮上游持续 500 | 重试至超时，无成功 assistant 记录；`attachment.identity.modelId` 记录 `req-three` |
| R4 | 别名 `--model sonnet`＋`ANTHROPIC_DEFAULT_SONNET_MODEL=mapped-sonnet` | 请求、`requestedModel`、`attachment` 均为 `mapped-sonnet`（不记录别名） |

## Codex 全局模型定点还原（逻辑实测）

实现：启动时记录全局 `config.toml` 顶层 `model`／`model_reasoning_effort`；结束后仅当当前值是本会话 `turn_context` 中出现过的模型时提示还原；点击还原时比较并交换（当前值须仍等于提示时的值），只改这两个顶层键，原无此键则删除。

| 编号 | 场景 | 结果 |
| --- | --- | --- |
| G1 | 会话写入两键 | 提示；还原后与原文件逐字相同 |
| G2 | 期间用户在终端新增其他配置 | 提示；还原保留用户新增内容 |
| G3 | 提示后用户又改了模型 | 放弃还原（值已再次变化） |
| G4 | 改动的模型不是本会话用过的 | 不提示（判定为终端或其他程序修改） |
| G5 | 无变化 | 无动作 |
| G6 | 原本无 `model` 键 | 还原时删除该键 |

## 旧配置迁移分类（只用名称）

规则：Claude 配置在“有 `ANTHROPIC_BASE_URL`＋恰好一个认证变量＋其余均为已知模型映射或已知高级变量＋无未知参数”时拆为“工具＋Anthropic 兼容 Provider＋运行配置（模型映射）＋高级变量”；无 env 与参数时为“Claude 原有登录”；Codex 无 env 且参数仅为已知选项时为“Codex 原有登录”，参数保留为高级参数；其余保留为高级配置，不猜测、不改写凭据。本机 4 个配置的试运行结果：

| 配置 | 结果 |
| --- | --- |
| CC-work、CC-rj | 拆分：Provider（`BASE_URL`＋`API_KEY`），三档模型映射，`API_TIMEOUT_MS`／`DISABLE_NONESSENTIAL_TRAFFIC` 作高级 |
| CC-deepseek | 拆分：Provider（`BASE_URL`＋`AUTH_TOKEN`），主模型／三档／small-fast／子 Agent／推理强度映射，压缩窗口等作高级 |
| Codex | 拆分：Codex 原有登录，`--sandbox` 作高级参数保留（首轮试运行把它误判为不可拆，已改为识别已知选项） |

## 结论与对方案的影响

1. **独立配置目录本身不足以保证“不回退订阅”，还需要两条规则**（N4、N6、N7 为本轮发现）：
   - 启动第三方 Provider 时清除全部 Claude 认证类继承变量：`ANTHROPIC_*`（现有）＋`CLAUDE_CODE_OAUTH_TOKEN`，以及 `CLAUDE_CODE_USE_BEDROCK／VERTEX／FOUNDRY` 等云端切换变量；Provider 必须提供认证，缺失时 WillYou 在启动前拒绝，而不是交给 CLI。
   - WillYou 管理的配置目录内容由 WillYou 生成并在启动前校验：`settings.json` 不得含 env 认证、`apiKeyHelper` 等认证项；发现异常拒绝启动并提示。
   满足以上两条后，N1／N2 证明缺 Key、失效 Key 只报错，记录代理证明无外连。
2. **失效 Key 不会自行退出**（N2，与 Codex 无限重连同类）：WillYou 需检测连续认证失败并提示，而不是让终端长时间无响应。
3. **并发安全**：Claude 各配置独立目录、Codex 共用默认目录加按次 Provider，均已实测互不串用。
4. **恢复模型规则（取代“读 message.model”）**：Claude 取最后一条成功、非 `isSidechain` 的 assistant 记录的 `requestedModel`；无成功记录时取最后一个 `attachment.identity.modelId`；以 `--model` 显式传入。Codex 取最后一个 `turn_context.model`（本来即请求值）。别名已被解析为映射后的实际模型名，可直接恢复。
5. **Codex 全局模型还原**按 G1–G6 的比较并交换规则实现，不覆盖用户在终端的并发修改。
6. **旧配置迁移**：本机 4 个配置均可按规则拆分；迁移须保留原配置 ID 与任务引用，并以迁移版本号保证幂等（实现细节进技术方案）。
