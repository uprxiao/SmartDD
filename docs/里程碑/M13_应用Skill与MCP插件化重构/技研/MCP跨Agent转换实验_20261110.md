# MCP 跨 Agent 转换与按次注入实验

日期：2026-11-10。依据：[需求 R0.3](../需求.md) M13-R03（CLI 安装后能力发现、纳管与跨 Agent 配置）。环境：macOS arm64，Codex `0.166.0`、Claude Code `2.1.321`，分支 `feature/0.1.4`。前置结论：[Codex 实验](T-CFG_T-MODEL_Codex实验_20261110.md)、[Claude Code 实验](T-CFG_T-MODEL_ClaudeCode实验_20261110.md)（第三方 Provider 下 Claude 使用独立配置目录，因此 MCP 必须由 WillYou 配置进去）。

## 方法与边界

- 全部离线：两个自写假 MCP 服务器（stdio：记录工具调用时的 cwd 与若干环境变量是否存在；http：streamable HTTP 的 JSON 响应形态，要求 Bearer 令牌）；模型端为模拟 Anthropic／Responses 服务器，**主动发出 MCP 工具调用**，从而验证到“调用已验证”层，而非仅配置落地。外网经失效代理阻断；无真实模型请求，未使用任何订阅。
- 临时 `CLAUDE_CONFIG_DIR`／`CODEX_HOME`；前后核对 `~/.codex/config.toml`、`~/.claude/settings.json`、`~/.claude.json` SHA256 均不变；无残留进程。
- 用户本机 MCP 只读取名称、传输类型、字段名、命令路径归属与 http 主机名，未读取 env／headers 值。
- 证据：[实验目录](实验/MCP跨Agent_20261110/)（假服务器、三轮驱动与结果、`SHA256SUMS`；临时路径与令牌已替换）。第 1 轮暴露驱动对两种 CLI 行为的错误假设，第 2、3 轮修正，原结果保留。

## 现状（只读）

- WillYou 已有：发现层读取 Claude `.claude.json`／`.mcp.json`／插件 MCP 与 Codex `mcp_servers`（`src/main/core/capabilities/discovery.ts`）；WillYou 自有上下文 MCP 已按次注入——Claude 用 `--mcp-config <文件>`，Codex 用 `-c mcp_servers.<名>.…`（`capability-service.ts`）。
- 用户本机：Codex `config.toml` 有 8 个 MCP（stdio 6、http 2，用到 `env`、`env_vars`、`cwd`、`enabled`、超时字段）；Claude `~/.claude.json` 无顶层或项目级 MCP，另启用 3 个 Claude 插件（插件内 MCP 未展开）。

## 结果

| 编号 | 方向／场景 | 实际结果 |
| --- | --- | --- |
| X1 | Codex 源（stdio：`env`＋`env_vars`＋`cwd`＋超时；http：`bearer_token_env_var`；另 1 个 `enabled=false`）→ 转换为 Claude `--mcp-config` JSON（`env_vars` 转 `${VAR}`，Bearer 转 `headers.Authorization: "Bearer ${VAR}"`），`--strict-mcp-config` 注入 | stdio、http 工具均被真实调用；http 服务器收到正确 Bearer；`WY_STATIC`、`WY_PASS` 正确到达。`enabled=false` 被跳过 |
| X2 | Claude 端写 `cwd` 字段 | **不生效**，服务器 cwd 仍为项目目录；改为包装命令 `/bin/sh -c 'cd "$0" && exec "$@"' <cwd> <原命令…>` 后生效 |
| X3 | Claude 端 `${VAR}` 展开 | env 与 headers 中均展开（`--mcp-config` 文件） |
| X4 | Claude 默认工具列表 | MCP 工具默认不在首个请求的 tools 中（延迟加载，经工具搜索取得）；设 `ENABLE_TOOL_SEARCH=false` 后直接列出 `mcp__<服务器>__<工具>`。两种模式下按名调用均成功 |
| X5 | Claude stdio 服务器的环境 | **继承 Claude 进程全部环境**：未声明的 `WY_PASS`、`WY_HTTP_TOKEN` 以及 **`ANTHROPIC_AUTH_TOKEN`（模型令牌）均到达 MCP 服务器** |
| X6 | Claude 源（stdio：`env`；http：`headers.Authorization: "Bearer ${VAR}"`）→ 转换为 Codex `-c mcp_servers.<名>={…}`（Bearer 转 `bearer_token_env_var`，整值 `${VAR}` 头转 `env_http_headers`） | 首轮被拒：`MCP tool call requires approval, but approval policy is never` |
| X7 | 同上，加 `default_tools_approval_mode="approve"`（合法值 `auto`／`prompt`／`writes`／`approve`，由无效值报错获得） | stdio、http 均真实调用成功，Bearer 正确 |
| X8 | Codex stdio 服务器的环境 | **只含 `env` 与 `env_vars` 列出的变量**：不加 `env_vars` 时 `WY_PASS` 为空；模型 Key 环境变量（`WY_MOCK_KEY`）与 `WY_HTTP_TOKEN` 均未到达 |
| X9 | Codex 工具命名 | Responses 请求中以 namespace 形式出现：`mcp__<服务器>::<工具>`；另有 `list_mcp_resources` 等内置资源工具 |

## 用户本机 MCP 可迁移性（静态）

| 名称 | 类型 | 判断 |
| --- | --- | --- |
| memex、scrapling、rea、clawchat | stdio，通用位置命令 | 可迁移；`rea` 的 5 个 env 值随配置复制，需按敏感信息处理 |
| openaiDeveloperDocs | http（developers.openai.com），无鉴权字段 | 可迁移 |
| firecrawl | http（mcp.firecrawl.dev），无鉴权字段 | 可迁移；凭据可能在 URL 中或走 OAuth——URL 须按敏感值处理，OAuth 需在目标 CLI 单独认证 |
| node_repl | stdio，命令位于 ChatGPT.app，15 个 env 含 CODEX 专用变量 | 宿主专属，不迁移 |
| computer-use | stdio，Codex 专用客户端，`enabled=false` | 不迁移 |

## 结论

1. **按次注入可承载跨 Agent MCP**：Claude 用 `--mcp-config <WillYou 管理的文件>`（是否加 `--strict-mcp-config` 视是否还需加载该配置目录自身 MCP 而定），Codex 用 `-c mcp_servers.<名>={…}`。两侧全局配置均不被改写，与 AI 配置的按次注入一致，也与 WillYou 现有上下文 MCP 注入方式一致。
2. **字段转换规则（已实测部分）：**

   | Codex | Claude | 说明 |
   | --- | --- | --- |
   | `command`／`args`／`env` | 同名 | 直接映射 |
   | `env_vars=[X]` | `env: {X: "${X}"}` | Claude 本就继承全部环境，显式写出便于审计 |
   | `cwd` | 无；用 `/bin/sh -c 'cd "$0" && exec "$@"'` 包装 | Claude 的 `cwd` 字段无效（X2） |
   | `url`＋`bearer_token_env_var=X` | `type:"http"`＋`headers.Authorization:"Bearer ${X}"` | 双向实测 |
   | `env_http_headers={H="X"}` | `headers.H:"${X}"` | 反向实测整值形式；部分插值（如 `"token ${X}"`）Codex 无对应，只能写死或标为不支持 |
   | `http_headers` | `headers`（固定值） | 未单独实测 |
   | `enabled=false` | 不写入 | 实测跳过 |
   | `startup_timeout_sec`／`tool_timeout_sec` | 无逐服务器项（仅全局 `MCP_TIMEOUT` 等） | 有损，需提示 |
   | `default_tools_approval_mode` | Claude 权限规则（`--allowedTools`／settings permissions） | 语义不同，需单独设计 |
   | —— | `type:"sse"` | Codex 不支持 SSE，标不支持 |

3. **审批是必须设计的一环**：Codex 默认要求 MCP 调用审批；WillYou 的交互式 TUI 下会提示用户，非交互或 `approval_policy=never` 下会被拒。同步到 Codex 时应保留来源 CLI 的批准意图，或默认 `prompt` 由用户在终端确认，不默认全部 `approve`。Claude 侧对应其权限规则。
4. **安全：Claude 会把整个进程环境（含模型令牌）交给 stdio MCP 服务器，Codex 不会。** WillYou 向 Claude 注入第三方 stdio MCP 时，建议以包装命令清除模型凭据类变量（如 `env -u ANTHROPIC_AUTH_TOKEN -u ANTHROPIC_API_KEY …`，或只放行白名单），并在界面说明。本项未实测包装后的效果，列入后续用例。
5. **不可迁移项需识别**：命令位于其他应用包内（如 ChatGPT.app）、依赖宿主专用环境变量、已停用、SSE→Codex、需 OAuth 的远程服务，应在纳管列表中标为“宿主专属／需单独认证／不支持”，不静默同步。
6. **敏感信息**：env 值、headers、URL 都可能含密钥，复制到 WillYou 管理的注入文件时须加密存储或仅以 `${VAR}` 引用由 WillYou 在启动时注入，不在磁盘落明文；注入文件放 WillYou 私有目录并限制权限。

## 更正（2026-11-10，技研审核 R01／R07）

- 结论 2 转换表把 `command／args／env` 列为“直接映射”过宽。审核复现：`env.X="${Y}"` 在 Claude 中展开为 Y 的值，在 Codex 中按字面传 `${Y}`（即使已加 `env_vars`），两侧调用均成功、退出码 0。原实验只测固定值 env 与同名 env_vars，未覆盖此差异。修订后的转换规则见补验 A1。
- 结论 3、4 的审批映射与凭据过滤此前只验证了“自动批准”通路与问题存在，最终策略（沿用来源、默认询问、逐工具禁用、过滤后鉴权仍可用）未验证，见补验 A1。
