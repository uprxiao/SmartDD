## WillYou 现状要点

- 安全调用链（Agent → MCP 桥／`willyou-app` CLI → Unix socket → 主进程 → 授权、Schema、审批、账本 → 模块 `execute`）与包校验（逐文件 sha256、拒绝符号链接、内容寻址、安装日志、激活代数、回滚）均为通用宿主代码，可复用。
- `sample-kv` 已以“固定 hash 脚本＋`ELECTRON_RUN_AS_NODE` 子进程＋`UpstreamSessionPool`”承载业务，是最接近插件运行时的现成实现。
- 阻碍外部插件的硬依赖：编译期模块元组与由其生成的 appId／连接配置类型；`retained` 服务后门；业务表在宿主 drizzle 迁移；渲染层写死的面板映射、图标、`appId` 分支与禅道／邮件专用 RPC；`BuiltinPackageRegistry`／`parsePackageManifest` 要求包内模块必须有编译模块对应。
- 禅道：业务约 400 行（数据服务、provider、HTTP 封装）＋面板及相关组件 209 行；表 `application_zentao_*` 在宿主迁移 `0017`。邮件、浏览器按用户决定保持内置。

## 协议草案（v0-draft，供评审）

见示例 [`plugin.json`](实验/插件协议_20261110/demo-tracker/.willyou-plugin/plugin.json)：

```
<plugin>/
  .willyou-plugin/plugin.json  id、version、hostApi、displayName/description/author、icon{light,dark}、
                               permissions、providers[]（config 为 JSON Schema，secret 声明，summaryFields）、
                               capabilities{<id>.<…>: permission/semantics/slots/input/output Schema}、
                               runtime{type:"process", entry, protocol:"jsonrpc-stdio/1"}、skills、ui.panels[]
  runtime/  schemas/  skills/  assets/
```

运行时协议：stdio 换行分隔 JSON-RPC 2.0，方法 `initialize`、`verify`（连接测试）、`execute`（`{capability,input,connection:{config,secret}}`）。宿主保留授权、Schema 校验、审批、账本、超时与重启；插件只收到本次调用绑定连接的配置与凭据。

## 禅道面板声明式评估（静态）

现有面板元素：项目连接检查与引导（通用）、Bug／需求两个标签页、刷新、游标分页列表、部分失败提示、行点击打开详情弹窗（字段列表、枚举中文映射、附件／图片资源预览）、“插入终端”按钮。可用以下通用声明组件表达：带标签页的列表源（每页签绑定能力与固定输入）、游标分页、详情字段（含枚举映射）、资源预览（需插件提供通用“读取资源”能力，对应现 `zentaoResource`）、行动作（打开链接、插入终端）。判断：**禅道面板可以完整声明化**；加载／空态／错误态由宿主统一提供。

## 结论

1. **插件以独立子进程承载业务**，与 Codex／Claude 插件做法一致，并可直接复用 WillYou 现有安全调用链与 sample-kv 子进程机制；宿主保留全部策略检查，插件崩溃、卡死不影响宿主（已验证）。
2. **包格式**沿用 Codex／Claude 的“清单＋skills＋schemas＋runtime＋assets”结构；`plugin.json` 草案已能表达禅道所需的连接、能力、Skill 与声明式面板。
3. **安装**：目录与 zip 两种来源可共用“暂存 → 完整校验 → 树 hash → 原子激活”，规则沿用资源包标准；恶意 zip 均可在解压前拒绝。
4. **隔离强度需定案**：进程隔离只隔开崩溃与环境变量，**不隔开文件访问**（同一用户）。`sandbox-exec` 禁止名单可挡住宿主数据目录，但挡不住用户其他文件；完全白名单沙箱对 node 运行所需系统路径较复杂，`sandbox-exec` 也已被 Apple 标为不推荐（仍可用）。因此需要在“可信插件＋安装授权确认”与“沙箱强度”之间做产品决定。
5. **禅道迁移可行**：业务代码量小，面板可声明化；需要拆除的是宿主对 `zentao` 的写死引用及其迁移表的归属（迁入插件私有存储时须迁移既有数据）。

## 风险与未验证

- 真实宿主以 Electron 可执行文件（`ELECTRON_RUN_AS_NODE`）启动插件时，子进程与 WillYou 同签名身份，理论上可能访问 WillYou 的钥匙串条目（safeStorage 密钥）；需在正式开发中实测，并考虑在沙箱中拒绝相应 mach 服务或改用独立运行时。本轮未验证。
- 插件自带原生 `.node` 模块、npm 依赖体积与许可、插件升级时运行中任务（快照固定旧版本）的切换、卸载时私有数据保留／删除、禅道既有表迁移到插件私有存储、真实宿主端到端（Agent → 插件）——均留待正式开发第一步（P1）验证。

## 用户决定（2026-11-10）

隔离强度采用“可信安装＋保护 WillYou 数据”（禁止名单沙箱保护 WillYou 数据目录与密钥，安装时确认来源与权限）。已记入需求 R0.3 补记。
