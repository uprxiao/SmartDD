# 补验 A1：MCP 值语义、凭据隔离与审批策略

日期：2026-11-10。依据：[技研审核](../../../review/review-20261110-1549.md) R01／R07；修订 [MCP 跨 Agent 转换实验](MCP跨Agent转换实验_20261110.md) 的转换规则。环境：macOS arm64，Codex 0.166.0，Claude Code 2.1.321，Node 22.23.1。

## 边界

全部离线：探针 MCP（记录启动 argv／cwd／指定前缀环境变量与工具调用）、假 http MCP（记录请求头）、模拟模型主动发起工具调用；外网经失效代理阻断；临时 `CODEX_HOME`／`CLAUDE_CONFIG_DIR`；测试密钥为随机值，结果中已替换。无真实模型请求，未使用任何订阅。证据：[实验目录](实验/A1_MCP语义与策略_20261110/)。驱动首轮的正则错误（工具名吞入 JSON 标点）、Claude `--allowedTools` 变参吞掉 prompt、TUI 按键与确认框默认项不符，均保留为 attempt1／attempt2 结果。

## 两侧原生语义（实测）

| 写法 | Claude（`--mcp-config`） | Codex（`mcp_servers`） |
| --- | --- | --- |
| `${X}`、`pre-${X}-post`（env、args） | 展开 | **字面量** |
| `$x`（无大括号） | 字面量 | 字面量 |
| `${MISSING:-d}` | 用默认值 | 字面量 |
| `${MISSING}` | **保留字面量**，不报错 | 字面量 |
| headers 中 `${X}` | 展开，且对展开结果**再次展开**（字面量 `${…}` 无法经 headers 保留） | `http_headers` 字面量；`env_http_headers` 仅整值引用 |
| 改名透传 | 继承全部环境 | `env_vars` 仅同名（含 `{name, source=local|remote}`），**不能改名** |
| 未知字段 | — | 静默忽略（拼错不报错） |
| stdio 子进程环境 | **继承全部**（含 `ANTHROPIC_*`、`WILLYOU_RUN_TOKEN`） | 仅 `env`＋`env_vars` |

## 修订后的转换规则（已实测）

1. **中间表示**：源配置先解析为“字面量 | 模板（文本＋变量引用＋可选默认）”。Claude 源中的 `${X}`／`${X:-d}` 为引用；Codex 源中的 `${…}` 为字面量，`env_vars`、`bearer_token_env_var`、`env_http_headers` 为引用。
2. **启动时求值**：WillYou 按源语义算出最终值；缺少变量且无默认 → 该 MCP 标为“缺少变量 X”，不注入（M3）。
3. **stdio 统一经启动包装** [`wy-mcp-launch.sh`](实验/A1_MCP语义与策略_20261110/wy-mcp-launch.sh)：值放入 CLI 进程环境的私有变量 `WY_MCPV_n`（Codex 侧同时列入该服务器 `env_vars`）；包装脚本 `--set 目标名=WY_MCPV_n` 映射、`--unset` 清除模型凭据与 WillYou 内部令牌、`--unset-prefix WY_MCPV_` 清除私有变量、`--cwd` 切换目录，参数中含 `$` 或来自模板的项以 `@WYARG:WY_MCPV_n` 在包装内替换（避免 Claude 对 args 展开）。
4. **http 请求头**：Codex 用 `env_http_headers={头=WY_MCPV_n}`；Claude 一般用 `headers:{头:"${WY_MCPV_n}"}`，值中含字面量 `${` 时改用 `headersHelper`（读取 `WY_MCPV_n` 原样输出）。`headersHelper` 仅在**已信任工作目录**执行（二进制提示 “headersHelper not run: this workspace has no persisted trust”），WillYou 在其管理的 `CLAUDE_CONFIG_DIR` 中为任务项目写入信任后实测生效。
5. **URL、command 中的 `${}`**：本轮未实测。规则：command 含 `${` 拒绝转换；URL 按源语义求值后写入配置，若来源为 Claude 模板且引用敏感变量，标“URL 含凭据，Codex 侧会出现在启动参数中”提示。

| 编号 | 场景 | 实际结果 |
| --- | --- | --- |
| M1a／M1b | Claude 源原生 vs 转为 Codex | 探针 argv（`arg-SRCVAL`、`lit-$x`、`dflt`）与 env（全值、部分插值、字面 `$`、`$HOME` 文本）**完全一致**；http 收到相同 Bearer 与 `X-Part` |
| M1c／M1d | Codex 源原生 vs 转为 Claude | argv `arg-${SRC}`、env `A_FULL=${SRC}` 字面量一致；**`X-Lit` 头经 `headers` 被 Claude 二次展开为 `SRCVAL`（与源不一致）→ 改 `headersHelper` 后收到字面 `${SRC}`** |
| M2 | 两个服务器同名 `API_KEY` 不同值；cwd 含空格、单引号、`$` | 两侧各自收到正确值；cwd 正确 |
| M3 | 引用不存在的变量 | 生成阶段报“缺少变量 NOT_SET”，不注入 |
| 凭据 | 转换后服务器环境 | 两侧均**不含** `ANTHROPIC_*`、`WILLYOU_RUN_TOKEN`、`WY_MCPV_*`；对照 M1a（Claude 原生）全部可见 |
| 落盘 | `--mcp-config` 文件与 CLI argv | 均不含测试密钥 |

## 审批与工具限制（实测）

| 编号 | 场景 | 实际结果 |
| --- | --- | --- |
| M6c1 | Codex 未设审批，非交互 | 拒绝“requires approval”，**服务器零执行** |
| M6c2 | 服务器级 `default_tools_approval_mode="approve"` | 执行 |
| M6c3／c4 | 服务器 approve＋`tools.wy_write.approval_mode="prompt"` | `wy_echo` 执行；`wy_write` 非交互拒绝、零执行 |
| M6c5 | `disabled_tools=["wy_write"]` | 工具不出现在模型工具列表，调用被拒 |
| M6a1 | Claude 未授权，非交互 `-p` | “requested permissions … haven't granted”，零执行 |
| M6a2／a3 | `--allowedTools mcp__pa__wy_echo` | echo 执行；write 被拒、零执行 |
| M6a4 | `--disallowedTools mcp__pa__wy_write` | 工具不可用 |
| T-cx | Codex TUI 默认 | 弹出 “Allow the pa MCP server to run tool "wy_write"?”（允许／本会话允许／始终允许／取消）；Esc → “cancelled MCP tool call”、零执行；Enter → 执行 |
| T-cc-auto | Claude TUI 默认（auto mode） | 第三方网关下服务端分类器不可用，先弹 auto mode 说明，再弹 “Do you want to proceed? ❯No Yes”（**默认 No**）；回车 → 零执行；选 Yes → 执行 |
| T-cc-default | Claude `--permission-mode default` | 弹 “1. Yes 2. Yes, and don't ask again 3. No”（**默认 Yes**）；Esc、选 3 → 零执行 |

## 结论与对需求的影响

1. **R01 已修复**：按“中间表示＋启动时求值＋包装／headersHelper”转换后，两方向 MCP 实际收到的 argv、env、headers 与源 CLI 原生运行一致（URL／command 中的 `${}` 未实测，按规则 5 处理）。
2. **凭据过滤可行**：包装脚本清除 WillYou 注入的模型凭据与内部令牌，MCP 自身凭据经 `--set` 正常到达。过滤名单应取“本次运行 WillYou 实际注入的 Provider 凭据变量＋WillYou 内部令牌”，而不是固定枚举。
3. **审批映射（落实“沿用来源、默认询问”）**：
   - 默认：Codex 不设审批（TUI 询问）；Claude 不加 `--allowedTools`（TUI 询问）。非交互时两侧均拒绝且零执行。
   - 来源已允许／纳管页“自动批准”：Codex `tools.<工具>.approval_mode="approve"`（或服务器级）；Claude `--allowedTools mcp__<服务器>__<工具>`。
   - 来源禁用：Codex `disabled_tools`；Claude `--disallowedTools`。
4. **Claude 权限模式需定案**：Claude 默认 auto mode 在第三方 Provider 下无法用服务端分类器，每次 MCP 调用都会先弹说明再确认，且确认默认 No；`--permission-mode default` 则直接确认、默认 Yes。技术方案需决定 WillYou 启动 Claude 第三方配置时的权限模式（不改变“默认询问”的产品规则）。
5. Codex 未知字段静默忽略，WillYou 生成配置须自校验字段名。
