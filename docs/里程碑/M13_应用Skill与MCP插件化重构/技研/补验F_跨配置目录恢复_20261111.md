# 补验 F：Claude Code 换智能体恢复时的跨配置目录会话（2026-11-11）

来源：[复核 review-20261111-2119](../../../review/review-20261111-2119.md) F02。技术方案 §3.1 规定 Claude 第三方供应商每个智能体使用独立的 `CLAUDE_CONFIG_DIR`，订阅／API 使用用户 `~/.claude`；需求 5.3「任务记录与恢复」允许换成同一 Code Agent 的其他智能体恢复。补验 B7 只验证了同一目录内的恢复，本补验验证换目录的情况。实验脚本与原始结果见 [实验/F_跨配置目录恢复_20261111](实验/F_跨配置目录恢复_20261111/)（哈希见 `SHA256SUMS`）。

环境：macOS arm64；Claude Code 2.1.322；本机模拟 Anthropic 端点（只监听 127.0.0.1，记录每次请求的 messages 与认证头）；`HOME` 与全部配置目录为本轮临时目录，`HTTPS_PROXY`／`HTTP_PROXY` 指向 127.0.0.1:1 阻断外网；`-p` 非交互、`--setting-sources user`。没有调用真实模型，没有读取或写入用户 `~/.claude`。

## 结论摘要

1. **直接换目录恢复会失败，但失败是安全的**（S2）：在目录 B 用 `--resume <A 中的会话 ID>`，CLI 输出 `No conversation found with session ID: …`、退出码 1，**没有发出模型请求，也没有在 B 中创建会话文件**，不会悄悄开一个新会话。
2. **把会话记录复制到目标目录后可以完整恢复**（S3）：把 A 中 `projects/<项目目录名>/<会话 ID>.jsonl` 复制到 C 的同一相对位置后，在 C 中 `--resume` 成功，会话 ID 不变；请求里带上了全部历史（第一轮暗号、前两轮回复，共 7 条消息），认证头只用 C 的令牌，模型为显式传入的新模型。
3. **源目录不受影响**（S3）：恢复前后 A 中会话文件的 SHA256 完全一致；新的轮次只追加在 C 的副本中。
4. **源材料缺失时同样安全失败**（S4）：与 S2 相同的报错与退出码，无请求、无文件。
5. **项目目录名由工作目录推导**：`projects/` 下的目录名是任务工作目录的绝对路径把 `/` 与 `.` 替换为 `-`，与配置目录无关；同一任务工作目录在任何配置目录下得到同一个名字，所以复制时保持相对路径即可。
6. **Codex 不涉及**：技术方案 §3.1 中 Codex 的订阅／API 与第三方供应商都使用默认 `CODEX_HOME`，会话记录在同一目录，换智能体恢复不需要搬运。

**首次执行的判定错误（attempt-001，保留）**：第一次运行时判定器先把请求文本截成最后 600 个字符再找暗号，而暗号在带长系统提示的首条消息里被截掉，导致对照 S1 与 S3 误判为“未带上下文”。原始数据显示 S1 已有 4 条消息、S3 有 7 条且含前两轮回复，CLI 行为与第二次一致。修正为先在完整文本上判定、再截断保存，重跑一次（新的临时目录与会话 ID）。原失败结果与当时的脚本见 [attempt-001-判定截断](实验/F_跨配置目录恢复_20261111/attempt-001-判定截断/)。

## 对方案的建议（已写入技术方案 §2、§3.4）

1. **TaskSnapshot 记录本次运行的配置目录**：每次启动（新建或恢复）都更新为实际使用的 `CLAUDE_CONFIG_DIR`（订阅／API 为用户默认目录）。会话记录总在最近一次运行的目录中。
2. **换目录时由宿主复制会话记录**：所选智能体的配置目录与快照中的不同时，启动前把 `<最近运行目录>/projects/<项目目录名>/<会话 ID>.jsonl`，以及同名的 `<会话 ID>/` 子目录（如有），复制到目标目录的同一相对位置，然后再 `--resume`。源目录只读、不删除，旧记录保留可回退。
3. **缺材料时不启动、不新建会话**：源文件不存在或复制失败时，恢复前直接报错并保留任务原记录，不改用“新会话”冒充恢复；即使宿主漏查，CLI 也会以退出码 1 拒绝（S2、S4），宿主据此标记恢复失败。
4. **目标已有同名文件**：只可能是此前在目标目录运行过、之后又在别处继续。宿主以最近运行目录中的记录为准覆盖目标中的旧副本（目标副本更旧）；目标是用户默认目录时见下一条。
5. **目标为用户默认目录（第三方供应商 → 订阅／API）**：复制会在用户 `~/.claude/projects/` 下新增一个会话文件。这不是修改配置，但与“WillYou 不写入全局 `~/.claude`”的边界相邻，提交用户决定。**用户 2026-11-11 决定允许**：只新增，已有同名文件时拒绝恢复、不覆盖（技术方案 §3.4）。源为用户默认目录（订阅／API → 第三方供应商）只读取，不涉及写入。

## 边界

- 只验证了纯文本两轮会话。带工具调用、子 Agent 或大工具输出的会话可能在 `<会话 ID>/` 子目录中有附属文件；方案已要求一并复制，但本补验没有生成这类文件，正式开发时补一项带工具调用的复制恢复测试（用例 T064）。
- 使用 `-p` 非交互；交互界面的 `--resume` 走同一会话加载逻辑，按 CLI 版本在开发时复核。
- 结论只适用于 Claude Code 2.1.322 的会话存储布局；CLI 升级后由 T064 的 I 层复核。
