| 代号 | 内容 |
| --- | --- |

| F-MCP | 探针 MCP：stdio 与 http 各一，记录启动 argv、环境变量白名单子集、请求头和工具调用；含只读工具 `wy_echo` 与写工具 `wy_write` |
| F-SKILL | Skill 来源：Claude 用户级、Codex 用户级、项目级（`.claude/skills`、`.agents/skills`）各若干，含相对脚本与 `VERSION` 标记，可改为 v2 或删除 |
| F-PROJ | 项目 P1、P2（Git 仓库）、P3（非 Git 目录）、P4（P1 的 git worktree）；P1 内放项目 `CLAUDE.md`、项目 `.claude/settings.json` 与 `.claude/settings.local.json` 的恶意样本（改地址、改 Key、`apiKeyHelper`） |

| F-LOGIN | 登录检测替身：可执行的 `claude`、`codex` 替身脚本，按场景返回未登录、订阅、API Key 三种 `auth status`／`login status` 输出（已登录的格式在 T088 用真实 Codex 订阅输出校准；Claude 与 API Key 的格式未核实前用合成样本并标注），经“自定义路径”接入测试实例；只用于 I＋A 层，不代替真实登录 |
| F-CFG | 用于全局模型提醒的合成 `config.toml`：单引号、行尾注释、原无 `model` 键、多行字符串四种 |

**环境约束**：不读写用户日常 `~/.claude`、`~/.codex`、钥匙串真实条目或日常 WillYou 数据。涉及保存 Provider Key 等安全存储的打包 App 用例，按 AGENTS“安全存储”规则不把 `HOME` 指向临时目录，登记为 S 层或用户实测；其余用例使用独立 `userData` 与发现根目录。真实 Provider 只用用户授权的 Key 与最小调用。

**统计规则**：按唯一用例编号统计。多次执行、多主题、回归不重复计数。`待执行`、`失败`、`阻塞`、`跳过` 都不计通过。

## 9. 执行条件（已逐项确认）

1. **保存 Provider Key 的打包 App 用例**（T048–T052、T055、T069，以及 T056–T058、T060、T061 中“在界面里接入模拟 Provider”这一步）：Key 走系统钥匙串，按 AGENTS 规则不能把 `HOME` 指向临时目录；测试包签名与已安装版本不同，访问真实钥匙串会弹授权窗口。**用户 2026-11-11 决定采用**：业务逻辑先在 I 层用真实 CLI＋模拟端点验证；打包 App 中的接入与保存步骤，由用户在日常账户下、独立 `userData` 的测试实例弹出钥匙串授权时允许一次，其余步骤仍由 CDP 自动执行；测试实例不读写日常数据与真实 Key。该问题只存在于 macOS：WillYou 经 Electron `safeStorage` 加密，Windows 使用与登录账号绑定的 DPAPI、不弹授权，Linux 使用系统密钥服务；M13 首期只验收 macOS arm64，本稿不含 Windows／Linux 用例。
2. **真实模型用例**（T048、T049、T055、T069、T094、T096 及 T014 中的 R 层）：**用户 2026-11-11 授权 DeepSeek 与本机 Magpie，并授权 SMG（补验 D）**，按每条用例所需的最小调用执行；Key 由用户在测试实例界面内自行填写，不经聊天传递，不写入证据。

4. **CLI 登录与官方 API Key**（用户 2026-11-11 决定）：
