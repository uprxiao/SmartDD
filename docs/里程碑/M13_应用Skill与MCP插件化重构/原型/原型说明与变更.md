# M13 原型说明与变更

版本：**P0.4（2026-11-11，禅道换用官网公开 Logo；P0.3 已获用户认可）**。依据：[需求 R0.3（含补记）](../需求.md)、[技术方案 T1.0 草案](../技研/技术方案.md)。共享原型工程 `prototypes/m6-codex/`；P0.3 于 2026-11-11 用户认可后提交，原型基线提交 `663dc80d2`。

## 访问方式

在 `prototypes/m6-codex` 中运行 `npx vite --port 4176`，打开 `http://127.0.0.1:4176/?preview=m13`。也可以在工作台顶部点击“M13 · 插件与能力”，或点击左侧导航栏的拼图图标。右上角“演示场景”可以切换异常状态，月亮图标切换深浅色。

全部为合成数据，只保存在本次页面的内存里：不读取真实插件、CLI 配置、Skill 目录或密钥，不发网络请求，不启动任何程序。原型显示“演示”的控件和结果都是模拟的。

## 视觉依据与像素对照（P0.2）

P0.1 只做了目视对比，没有测量，插件目录和详情与 Codex 截图存在明显差距（如侧栏行距 33 对 28、标题 26px 对 22px、目录图标 38 对 32、行距约 105 对 61、详情内容列 820 对 648）。P0.2 按以下方法逐项测量后修改：

1. **确定缩放**：参考截图 03／05 是 Codex 在 **90% 缩放**下的画面。依据：所有文字宽度除以 0.9 后都能精确对上标准字号（侧栏“Google Calendar”97→108＝14px，副标题 269→299＝14px，目录描述 130→144＝13px），左侧导航栏 47÷0.9＝52，与原型现有的 52px 一致。因此以“测量值 ÷ 0.9”作为 100% 下的目标值。
2. **测量参考图**：[ink.py](截图/像素对照/ink.py) 扫描深色像素得到文字与图标的上下左右边界，[samp.py](截图/像素对照/samp.py) 取颜色；字号由同字体下的文字宽度标定反推。
3. **同尺寸截图**：原型以 1399×900（对应参考 03）和 1422×903（对应参考 05）、像素密度 1.8 截图，得到与参考图相同尺寸的图片，生成左右对照与半透明叠加图（[目录叠加](截图/像素对照/cmp-cat-blend.png)、[详情叠加](截图/像素对照/cmp-det-blend.png)）。
4. **数值核对**：[verify.mjs](截图/像素对照/verify.mjs) 在浏览器中读取 43 个元素的实际位置与尺寸，与目标值比较，容差 2px：**43/43 通过**（[结果](截图/像素对照/verify-result.txt)）；[verify2.mjs](截图/像素对照/verify2.mjs) 核对详情下半部分的相对间距（[结果](截图/像素对照/verify2-result.json)）。

## 审核修正（review-20261111-0030）

[审核报告](../../../review/review-20261111-0030.md)针对 P0.3 指出 9 项一致性问题与 2 项待补设计。其中属于原型已有部分做错的，先行修正并复核（[复核脚本与结果](截图/审核修正/fix-check.mjs)）：

| 问题 | 修正 | 复核 |
| --- | --- | --- |
| P01 数据只在 M13 组件内，离开即重置；首页拿不到运行配置 | 状态上移到 App（`useM13State`），M13 各页与首页运行配置选择共用；只存内存，刷新重置 | 新建配置 → 首页选择器可选 → 回 M13 仍在 |
| P02 原型误加禅道“添加 Bug 备注（写入）”；浏览器“打开页面”误标只读 | 禅道只保留 A5／生产代码中的三个只读能力；浏览器能力按 M12 命令映射（goto、click、fill 为写，snapshot 为读）；用例 T014 已同步更正 | 禅道 3 项只读，打开页面为写入 |
| P03 连接表单对所有插件固定显示禅道字段，保存不生效 | 连接表单按插件声明渲染（禅道含 Token／密码认证；邮件分读取来源与 SMTP 发件账号），必填与范围校验，保存回写，秘密值不保存原文 | 邮件为 SMTP 字段；禅道改名后重开为新值 |
| P04 “保留数据”实际未保留；插件自带 Skill 不随插件变化 | 卸载时按选择保留或删除连接与项目授权，重装恢复；插件自带 Skill 由插件状态派生（停用、卸载、升级同步） | 保留后重装恢复 1 个连接与 2 个项目；删除后为空；卸载后自带 Skill 消失 |
| P06 预设 Provider 始终不可选 | 未接入的预设可选，已接入的不可重复接入；预设有自己的接入表单（Magpie 未运行时报错） | 删除 DeepSeek 后可重新以预设接入 |
| P07 更换 Provider 后 Claude 档位残留上一家模型 | 更换 Provider 时重建档位；高级设置提供五个档位选择，只列所选 Provider 的可用模型；保存前校验 | 改到 Magpie 后五个档位均为 Magpie 模型 |
| P08 高级设置不保存；旧高级配置只能改名 | 环境变量与启动参数接入状态并回显；旧高级配置可继续维护 | 新增变量与参数保存后重开回显 |
| P09 MCP 取消后重新纳管变为“已配置” | 纳管后的生效方式按类型区分：MCP 一律按次注入，用户级 Skill 链接共用目录，项目级 Skill 按次挂载；原单测错误预期已改 | 模型单测 12/12 |

同时按第 5 项决定改了安装／卸载文案（升级后下一次调用即用新版、卸载后不可再调用）。P05（项目使用插件链路）、P10（禅道声明式业务界面）、P11（异常与维护状态）与七项讨论结论一起在 P0.5 补齐。
