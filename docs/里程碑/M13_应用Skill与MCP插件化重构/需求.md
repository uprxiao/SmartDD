## 第二章 版本概述

### 1. 产品与现状

WillYou 保持通过本机 CLI 执行任务的桌面工作台定位。现有应用已有配置、凭据、权限、资源包与工具路由，但业务模块仍随宿主编译注册；Skill／MCP 页面主要提供静态发现，缺少通用外部纳管。现有 AI 配置把程序、环境变量、启动参数和账号信息混在同一配置，用户需理解过多底层字段。

### 2. 本阶段目标与确认边界

- F28：现有应用改为可扩展插件，常规新增符合现有宿主协议的插件无需修改 WillYou 源码或重打包；插件自身可以编写业务代码。
- F28：用户在 WillYou 内任意 CLI 安装 Skill／配置 MCP，WillYou 自动识别后纳管并配置给其他已适配的 Agent；发现、纳管与同步策略见下表。原先独立 Skill 管理、MCP 管理与 CLI 扫描同步合并为一项，本期不另做面向独立 Skill／MCP 的页面安装器或添加入口。
- F29：扫描本机 CodeAgent 工具，独立配置 Provider，组合成首页可选的 AI 运行配置，降低新手门槛。用户已明确同意一起纳入 M13。
- UI：插件目录、详情与管理以已提供 Codex 截图细粒度对齐，图标专业化；AI 配置参考 Magpie 的功能分层，不自动等同于完整复刻 Magpie 全部界面及能力。

本期明确边界：独立 Skill／MCP 的原始安装、首次连接配置与认证在来源 CLI 或对应工具中完成；WillYou 提供发现、纳管、同步和状态管理。插件作为组合包仍保留页面安装／配置能力，插件自带的 Skill／MCP 随所属插件管理，不属于此次取消的独立安装入口。

| Codex `/model` 写全局默认（R0.3 补记，2026-11-10；同日按第四轮审核修订，用户决定） | 启动前只读记录全局 `config.toml` 的 `model`／`model_reasoning_effort`，会话结束后对比；被改动时提醒“原来是 X，现在是 Y”，提供可复制的还原方法（及打开配置文件入口），由用户自行修改，**WillYou 不自动写回全局配置**；同时在会话处提示“切换模型按 s 仅本会话”。新建任务始终使用运行配置的默认模型；恢复任务按 T-MODEL 使用最后一次实际模型：WillYou 从原生会话记录读取最后一次请求的模型（Claude `requestedModel`，Codex `turn_context.model`）并以 `-m`／`--model` 显式传入（两种 CLI 自行恢复均不可靠）。原“提供一键还原、比较并交换写回”的写法见修订记录 |
| 任务恢复 | 使用任务创建时的配置快照；Provider 已修改或删除时提示用户重新选择，不静默换账号；会话内切换过的模型尽量按最后使用的模型恢复（见技研项） |

尚未定案（由技术方案给出唯一选择）：插件包协议细则与声明式界面组件集；外部插件卸载后对连接、凭据、项目授权与历史任务引用的处理；旧 AI 配置迁移方式；宿主端到端与 Electron 子进程密钥隔离作为正式开发第一步（P1）的通过门槛。完整公共市场运营、全量重构 Agent 内核、直接运行任意 Codex／DSH 插件，以及 Magpie 的全供应商目录、复杂路由、多账号轮换、额度统计和故障自动切换，不因参考截图自动纳入本期。

### 3. 技术路线与模型设计

复用 M11／M12 的宿主服务、授权、统一 Skill 库及 Agent 适配，不另造一套凭据和项目体系。以“工具安装 → Provider → AI 运行配置 → 任务运行”区分实体身份；同一工具可以组合多个 Provider，同一 Provider 可复用于多个兼容工具。不能以此承诺任意组合都兼容。

采用 CLI 原生直连适配，不自建跨协议网关（R0.3）；需要跨服务商路由时可把 Magpie 作为一个 Provider 接入。服务端获取模型列表成功不代表该模型在所选 CLI 中具备完整代码 Agent 能力；必须验证流式、工具调用及必要功能。无需在普通用户流程里暴露这些实现细节，界面给出兼容性与修复动作。

用户在 R0.3 讨论中指定的必做技研（已完成，结论见 [Codex 实验](技研/T-CFG_T-MODEL_Codex实验_20261110.md)、[Claude Code 实验](技研/T-CFG_T-MODEL_ClaudeCode实验_20261110.md)；以下保留原题目作为依据。Claude 订阅登录按用户 2026-11-10 决定不测）：

- **T-CFG 配置载体与订阅登录**：现有实现为“运行器＋按次注入的环境变量／启动参数”，已识别并记录 `CLAUDE_CONFIG_DIR`／`CODEX_HOME`。须实验比较“环境变量／`-c` 参数注入”与“每个运行配置一个独立配置目录／配置文件”两种载体：Codex 的 `model_provider`／`wire_api` 等是否适合以独立 `CODEX_HOME` 或 `-c` 承载；订阅登录在独立目录下是否可用、是否需要重新登录、多个配置能否共享同一登录、是否涉及钥匙串；均须保证终端里直接使用 CLI 不受影响。旧配置（CC-work／CC-rj／CC-deepseek／Codex）的迁移方式依据本结论确定：能可靠识别的拆分为工具＋Provider，无法可靠拆解的保留为高级配置继续可用，不猜测供应商、不重写凭据。
- **T-MODEL 会话内模型切换与恢复**：用户在会话内（如 `/model`）切换模型后，恢复任务时能否沿用最后一次使用的模型。须核对 Claude Code 与 Codex 的会话文件是否记录模型、CLI 恢复时是否自动沿用；不能自动沿用时，评估由 WillYou 读取原生会话记录并在恢复时以启动参数指定。切换模型不改变所选 Provider 与账号身份。

## 第三章 功能性需求及规格说明

### 1. 整体业务流程

插件：发现／导入 → 安装与配置 → 项目选用／授权 → Agent 调用 → 更新或停用卸载。

Skill／MCP：来源 CLI 安装／配置 → WillYou 自动扫描识别 → 纳管与冲突处理 → 各 Agent 配置 → 提示加载／依赖／认证状态 → 跟踪来源更新与卸载并按规则同步。

AI 配置：检测本机工具 → 选择已有登录或配置 Provider → 选择兼容模型或沿用 CLI 默认 → 保存运行配置 → 首页选择并启动 → 查看错误并修复。

### 3. 插件

#### 3.1 扩展与管理

**功能描述**：统一插件身份、版本、来源、依赖和能力组合，支持安装、配置、启停、更新与卸载，将禅道迁为外部插件（后续三方应用模板）；邮件、浏览器保持内置应用并在目录中标“内置”；标准 Skill 归属在技术方案中定案。

**用户角色**：普通本机用户、插件开发者。

**输入**：符合宿主扩展协议的插件包及其声明；首期来源为本地目录与本地压缩包（R0.3）。

**基本事件流**：读取插件元数据 → 校验兼容性与完整性 → 安装并配置 → 项目启用 → 调用能力 → 按生命周期更新或退出。

**输出**：插件及能力状态、明确错误和恢复位置、可追溯的调用与变更依据。

**界面原型**：待制作；关联用户截图 02–06，进入共享原型工程，不复制另一套产品源码。

**插件连接与项目使用（R0.3 补记，2026-11-11，用户决定）**：
- **统一称“插件”**：M13 后界面不再使用“应用”一词，邮件、浏览器称内置插件，禅道等称外部插件；任务顶栏原“应用”按钮、项目页原“应用”分区均改称“插件”。
- 插件装好后所有项目默认可用，单个项目可在项目页关掉。
- 连接统一在插件详情页配置，可配一个或多个；有连接时必须有一个**全局默认**（只配一个时它就是默认，配多个时由用户指定）。
- 每个项目记录自己的状态：**跟随全局默认**（默认状态）或**个性化**（单独选了某个连接，即使选的恰好是当前全局默认）。项目页可随时切回跟随全局。每个项目同一时间只有一个生效连接。
- 全局默认从 A 改为 B：保存前弹窗分两组列出“将同步改为 B 的项目（跟随全局）”与“保持不变的项目（个性化）”，确认后生效。
- 切换连接（全局默认变化或项目改选）时，运行中的任务继续用其启动时的连接直到结束，新建或恢复的任务使用新连接；替换 M10“切换前先停止相关运行”的规则。
- 删除连接：删除全局默认且还有其他连接时，先选新的全局默认，跟随全局的项目按上条同步；个性化选了它的项目弹窗列出，删除后改为跟随全局；有运行中任务正在使用时不允许删除（删除会同时删除凭据），提示等任务结束或先停止；删除唯一的连接后插件暂不可用，直到再配置连接。
- 不另设“项目选用”页：连接在插件详情页管理，项目页“插件”分区只负责关闭插件、在跟随全局与个性化之间选择。
- **插件版本与升级（松耦合）**：界面只显示插件当前版本，不显示旧版本或“版本占用”。插件与宿主、插件与任务松耦合：升级只换插件包，不改宿主代码；新版本须向后兼容老任务，删除或改名能力须用 `legacyToolNames` 映射，安装检查发现删除能力且无映射时提示“老任务调用这些能力会失败”。升级时正在执行的调用按旧版本完成，之后所有任务（含运行中、恢复的任务）的调用都使用新版本，旧版本随即删除；激活失败仍自动回到原版本。卸载时正在执行的调用完成，之后调用提示“插件已卸载”。替换 A5 中“任务快照固定插件版本、旧版本无引用后清理”的设计。
- **不提供调用记录页面**：原应用区“调用记录”移除，也不在任务内另设查看位置；宿主仍保留调用账本，用于授权审批、写操作结果未知时不自动重放等内部用途。邮件附件与发送结果在邮件“草稿”页查看。

**约束规则**：常规新增插件只改插件自身，不改或重打包宿主；新能力超出已支持接口可能需要升级 WillYou。以新示例插件完整走通生命周期，核宿主生产源码／包未变。保留已有项目、连接、凭据、权限和历史；运行中更新、卸载资源回收与失败恢复必须定案。独立 Skill／MCP 不强制冒充完整插件包，外部插件协议兼容性另行核验。

#### 3.2 UI 与资源

**功能描述**：插件目录、侧栏、详情、搜索、添加、管理及相关状态以 Codex 参考细粒度对齐，使用专业图标。

**用户角色**：所有插件用户。

**输入**：真实插件元数据、图标及展示资源，用户搜索与管理动作。

**基本事件流**：浏览目录 → 搜索／筛选 → 查看详情及能力 → 安装／管理 → 列表与详情反映真实状态。

**输出**：真实目录、状态、详情和可执行操作。

**界面原型**：以用户 Codex 截图 03／04／05 为参考；补齐未展示的菜单、弹层、错误、加载、空态与键盘路径后评审。

**入口（R0.3 补记，2026-11-11，用户决定）**：新的“插件”“Skill 与 MCP”“AI 配置”三页替换旧入口——左侧导航只保留一个“插件”入口，移除 M10“应用接入”及设置中的“AI 配置”“Skill 与 MCP”；项目页内的“Skill 与 MCP”分区保留，原“应用”分区保留并改称“插件”。旧入口下的功能（禅道连接与资源、邮件来源／发件账号／草稿／附件／发送结果、项目选用、应用版本与升级、AI 配置编辑与导入、M11 标准 Skill 库）必须在新页面有对应位置，逐项核对不丢失；调用记录按用户决定移除（见“插件连接与项目使用”补记）。

**约束规则**：覆盖布局、尺寸、字体、间距、颜色、图标、悬停、焦点、长文本、浅深主题和窄窗；保持 WillYou 业务及品牌。图标优先使用来源可追溯的合法品牌资源，自有插件采用统一设计，声明浅深资源及缺失回退；不靠宿主新增应用名分支扩展图标。公共／个人来源与分类必须对应真实能力，不制造假目录或假安装状态。

### 4. 能力统一管理

#### 4.1 发现与同步

**功能描述**：在用户通过 WillYou 内的 CLI 安装 Skill／配置 MCP 后，自动发现并纳管，统一为其他已适配的 Agent 配置；页面负责来源、覆盖、生效与异常状态管理。

**用户角色**：普通用户与习惯 CLI 安装的高级用户。

**输入**：所选 AI 配置及实际 HOME／项目路径中已经安装／配置的 Skill、MCP 连接声明与来源变动；插件自带能力由所属插件的安装记录提供。

**基本事件流**：用户在来源 CLI 安装／配置 → WillYou 静态发现 → 区分外部发现项、已纳管项和插件自带能力 → 处理同名与作用域 → 纳管并配置其他已适配 Agent → 展示配置、加载、依赖、认证及调用验证状态 → 跟踪后续来源变化。

**输出**：来源记录、Agent 覆盖状态、需恢复会话／补依赖／认证或不支持等可操作结果。

**界面原型**：截图 01／07 为现状；扫描列表及能力管理视图待原型评审，展示来源、目标 Agent 和同步／生效状态；不设计独立 Skill 安装或 MCP 添加表单。

**WillYou 内置能力（R0.3 补记，2026-11-11，用户决定）**：M11 标准 Skill（数据库诊断、远程 SSH）与 WillYou 项目上下文 MCP 在“Skill 与 MCP”页单列“WillYou 内置”分组，与从 CLI 发现的外部能力分开；显示当前版本（按插件版本规则不显示旧版本）、可停用、随 WillYou 升级，交付方式沿用 M11。

**约束规则**：本期不提供独立 Skill／MCP 的页面安装／导入／新增连接入口；原始安装与首次认证保留在来源 CLI 或对应工具中完成。插件安装及其附带能力配置不受此限制；插件自带项由所属插件维护，避免重复接管。沿用 M11 单份统一库和 Agent 引用方案，但需验证第三方安装器在纳管、链接下的更新与删除行为。纳管前不移动删除原件，不覆盖同名用户文件，不默认改写第三方名称或内部引用。发现在任务／终端会话结束、进入能力页面及手动重新扫描时进行；新发现项经用户确认一键纳管，可开启“以后自动纳管”，同名冲突始终交用户选择（R0.3）。不同 Agent 的 MCP 配置按语义转换，不能直接复制整个配置文件或账号令牌；宿主专属连接和认证不兼容时明确提示。项目级安装不自动扩成全局授权；可见不代表具备项目资源权限。配置成功、会话加载与调用成功分别判断，运行中会话按实际能力刷新或恢复。更新与卸载以来源 CLI 为准，WillYou 单向跟随并只提供取消纳管，不删除来源原件、不反向写回来源（R0.3）；扫描不隐式启动 MCP 或外部脚本。后续用例包含 A 安装→WillYou 纳管→B 实际使用，以及重启、升级、卸载、自定义目录、冲突和失败恢复。

### 5. AI 配置

#### 5.1 本机工具

**功能描述**：扫描本机已安装的 CodeAgent CLI，普通用户选工具即可，无需自行填写可执行路径。

**用户角色**：普通本机用户，重点支持首次使用的新手。

**输入**：本机可执行程序与版本信息；首期工具为 Claude Code 与 Codex（R0.3），自定义路径作为高级能力。

**基本事件流**：进入页面检测 → 显示工具、路径、版本及状态 → 选择工具；找不到时给出安装引导／重新检测，异常时提供可执行的修复提示。

**输出**：可复用的本机工具项及可用状态。

**界面原型**：截图 08 为当前 WillYou 工具检测基础；优化信息层级和后续组合入口。

**约束规则**：检测到目录、检测到程序、程序可启动和模型连接可用分别呈现；不以一个“已检测”代替完整健康验证。多版本、多路径、自定义配置目录及工具升级后的处理待定。以实际所选工具启动任务，不因切换 Provider 替换底层 CLI。

#### 5.2 供应商

**功能描述**：Provider 独立管理并可复用，简化服务地址、协议、认证和模型配置；可选本机 CLI 原有登录模式。

**用户角色**：使用原有账号或自备 API 服务的用户。

**输入**：供应商名称、图标、协议／地址、认证，以及模型列表或手动模型 ID；原生登录的复用方式按对应 CLI 支持实现。

**基本事件流**：选择已有 Provider 或添加 → 选择原生登录／API 连接模式 → 按需填写最少字段 → 获取或手动指定模型 → 进行可判定的连接检查 → 保存并供兼容工具选择。

**输出**：可复用的 Provider 连接、模型与认证／健康状态。

**界面原型**：Magpie 截图 09–11 作为功能分层参考，用户未要求本阶段把其全部供应商或网关功能照搬。

**约束规则**：官方登录／订阅与 API Key 是不同认证方式，不能把订阅登录等同于通用 API Key；不要求用户把现有密码／令牌填进聊天。密钥沿用 WillYou 加密存储与脱敏原则。供应商兼容协议须细分并验证，不能只凭“OpenAI 兼容”判断任意 CLI 都能使用；模型列表请求成功不等于代码工具调用可用。不支持模型枚举时允许的手填规则待定；协议探测、连接测试的请求和错误展示待技研。供应商更新、停用或删除对运行配置和任务的影响需明确。首期类型为 CLI 原生登录、Anthropic 兼容 API、OpenAI Responses 兼容 API（R0.3）；跨协议网关、完整内置供应商列表、多账号与路由不纳入首期。

#### 5.3 运行配置

**功能描述**：选择 CodeAgent 工具＋Provider／账号＋模型或 CLI 默认后保存为命名配置，首页直接选择并运行；常用流程隐藏环境变量与原始启动参数，高级设置仍保留。

**用户角色**：所有任务用户。

**输入**：本机工具、兼容 Provider、模型选择、显示名称、默认选择及可选高级参数。

**基本事件流**：选工具 → 选兼容服务／原有登录 → 选模型或默认 → 自动生成名称供修改 → 保存 → 首页选择该配置并创建任务 → 用所选组合启动真实 CLI。

**输出**：可复用 AI 运行配置、首页清晰可辨的选择项及对应任务记录。

**界面原型**：截图 12 标注的首页入口；例示名称如“Claude Code · 公司服务”“Codex · 原有登录”，不把模型版本写死为当前承诺。

**导入导出（R0.3 补记，2026-11-11，用户决定）**：移除原“从 .zshrc 导入”（只适用于个人 shell 写法，不通用）。AI 配置页提供通用的导入、导出：导出时勾选 Provider 与运行配置（勾选运行配置时自动带上其 Provider），生成 JSON 文件，别人导入后可直接使用；**默认不含 Key**，可勾选“包含 Key”，此时按 M8 项目迁移的做法用口令（至少 8 个字符）加密，导入时输入口令。不导出工具可执行路径与本机目录，原生登录只导出“使用原有登录”这一设定。导入前预览（Key 脱敏），同名不覆盖现有配置、导入项名称加“（导入）”，未带 Key 的 Provider 标“需要填写 Key”。

**约束规则**：同一个 CodeAgent 工具可组合多个 Provider，同一个 Provider 可被多个兼容工具复用；不兼容组合应在配置阶段说明。可执行路径、环境变量、参数生成与优先级由适配层负责，具体实现由技术方案定案，不能让并发配置串用账号或端点。按本次运行注入，WillYou 不写全局 CLI 配置，不采用 Magpie 的全局接管模式（R0.3）。注入载体：Codex 使用默认 `CODEX_HOME`＋按次 `-c`／环境变量（原生 `/model` 写全局按第二章规则处理）；Claude Code 第三方 Provider 使用 WillYou 管理的独立 `CLAUDE_CONFIG_DIR`＋环境变量。现有 Codex／CC-work／CC-rj／CC-deepseek 等配置必须保留，迁移方式依 T-CFG 结论，无法可靠拆解时继续作为高级配置，不猜测供应商或重写凭据。任务恢复使用创建时的配置快照，Provider 已变更或删除时提示重新选择；会话内切换的模型按 T-MODEL 结论尽量恢复为最后使用的模型。历史名称与默认配置迁移须有明确方案。Skill／MCP 的共享按运行器及实际目录适配，与 Provider 解耦；更换模型服务不要求重装一套 Skill。
