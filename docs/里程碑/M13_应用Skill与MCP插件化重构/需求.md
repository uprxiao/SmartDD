## 第二章 版本概述

### 1. 产品与现状

WillYou 保持通过本机 CLI 执行任务的桌面工作台定位。原有应用已有配置、凭据、权限、资源包与工具路由，但业务模块随宿主编译注册；原 Skill／MCP 页面主要提供静态发现，缺少通用外部纳管；原 AI 配置把程序、环境变量、启动参数和账号信息混在同一配置，用户需理解过多底层字段。

### 2. 本阶段目标与确认边界

- F28：现有应用改为插件，常规新增符合宿主协议的插件无需修改 WillYou 源码或重打包；插件自身可以编写业务代码。
- F28：用户在 WillYou 内任意 CLI 安装 Skill／配置 MCP，WillYou 自动识别后纳管，并配置给其他已适配的 Agent。原先独立 Skill 管理、MCP 管理与 CLI 扫描同步合并为一项，本期不做面向独立 Skill／MCP 的页面安装器或添加入口。
- F29：检测本机 Code Agent，独立管理供应商，组合成首页可选的智能体，降低新手门槛。
- F31：首页像 Codex 一样选择本次任务的权限档位（见第三章 5.3）。
- UI：插件目录、详情与管理、首页权限选择按 Codex 截图细粒度对齐，图标专业化；智能体与供应商参考 Magpie 的功能分层，不等同于复刻 Magpie 全部界面与能力。

本期明确边界：独立 Skill／MCP 的原始安装、首次连接配置与认证在来源 CLI 或对应工具中完成，WillYou 提供发现、纳管、同步和状态管理。插件作为组合包保留页面安装与配置能力，插件自带的 Skill／MCP 随所属插件管理。

首期确认：

| 项目 | 确认结论 |
| --- | --- |
| 平台与 Code Agent | 仅验收 macOS arm64；Code Agent 为 Claude Code 与 Codex。OpenCode、Z Code、Pi、DSH 只在新建智能体时显示“暂不支持”。Windows／Linux 维持实验性包，不宣称 M13 能力支持 |
| 模型来源 | CLI 自己的登录（订阅／API）；Anthropic 兼容供应商（供 Claude Code）；OpenAI Responses 兼容供应商（供 Codex）。WillYou 不做协议转换，跨协议网关不纳入首期；需要时把 Magpie 作为一个供应商接入 |
| 插件深度与迁移 | 第三方插件可带业务代码，常规新增无需改宿主源码或重打包。禅道迁为外部插件，作为后续三方应用的模板；邮件、浏览器保持内置（依赖原生组件／Electron 主进程），不迁为插件；sample-kv 作为插件示例评估 |
| 插件安装来源 | 本地目录、本地压缩包；Git 地址、远程目录源与插件市场不纳入首期 |
| 内置与外部插件 | 邮件、浏览器在插件目录与详情中列出并标“内置”，可启用／停用，不可卸载，随 WillYou 升级。外部插件（含禅道）可卸载并重新安装；卸载时由用户选择“保留数据”或“删除数据”，对连接、凭据、项目授权与历史任务引用的处理按技术方案采纳的 A5 生命周期设计执行 |
| 插件运行与隔离 | 可信安装＋保护 WillYou 数据：安装时展示来源与权限声明并由用户确认；插件以独立子进程运行，宿主保留授权、Schema、审批与调用账本，插件只经宿主接口取得本次绑定连接的配置与凭据，只取得宿主白名单环境变量；运行时以沙箱禁止读写 WillYou 数据目录与密钥（插件包只读、插件数据目录可写、可联网）；用户其他文件不在沙箱保护范围，依赖安装确认。依据与未验证项见[插件技研](技研/插件包协议与隔离实验_20261110.md) |
| 插件界面 | 首期仅声明式界面：插件声明连接表单、能力列表、详情及简单数据列表等页面，由 WillYou 统一渲染；禅道现有专用面板改为声明式，能否完整表达由技研评估；不支持插件自带网页面板 |
| 插件数据 | WillYou 数据目录下每个插件一个私有目录（可含 sqlite），卸载时由用户选择保留或删除；宿主数据库只存连接、授权、调用账本等通用记录 |
| 能力发现时机 | 任务／终端会话结束后、进入技能页时自动静态扫描，另保留手动重新扫描；不常驻文件监听 |
| 纳管方式 | 列出新发现项，用户确认后一键纳管；提供“以后自动纳管”开关；同名冲突始终停下由用户选择 |
| 更新与卸载归属 | 以来源 CLI 为准，单向同步：来源更新／卸载后 WillYou 跟随更新已配置到其他 Agent 的副本或链接；WillYou 只提供“取消纳管”，不删除来源原件 |
| 运行注入 | 按次运行注入，只作用于 WillYou 启动的该 CLI 进程；WillYou 自身不写入全局 `~/.claude`、`~/.codex` 等配置，也不提供写入全局入口。CLI 原生交互仍可能写入其所用配置目录：Codex 在默认 `CODEX_HOME` 下 `/model` 回车会写全局，按下方“Codex 全局模型变化”处理；Claude Code 第三方供应商使用独立配置目录，写入限于 WillYou 管理目录 |
| 会话与供应商 | 一个会话绑定一个智能体（一个供应商或订阅／API），不做同一会话内跨供应商切换；不同智能体可同时运行。供应商智能体在会话内可在勾选的模型之间切换（Codex 经 `model_catalog_json` 按次注入，Claude Code 经 WillYou 管理目录的模型菜单设置），按 `s` 只切本次会话 |
| Claude Code 第三方供应商 | 使用 WillYou 管理的独立 `CLAUDE_CONFIG_DIR`，不使用用户 `~/.claude`；Key 缺失或失效时只报错、不退回用户订阅；启动前清除全部 Claude 认证类继承变量（含 `CLAUDE_CODE_OAUTH_TOKEN`），校验管理目录中无残留认证配置；令牌只经进程环境传入；所有档位（含 small-fast、子 Agent）一律等于智能体的默认模型。只加载 WillYou 管理目录中的设置，不应用任务项目及本地的 `.claude/settings*.json`；项目 `CLAUDE.md` 照常加载；独立目录下的 Skill／MCP 由技能（M13-R03）负责配置，项目级 Skill／MCP 经纳管后按次注入；项目设置中的权限规则与钩子在此类运行中不生效（用户已确认可接受）。依据见 [Claude Code 实验](技研/T-CFG_T-MODEL_ClaudeCode实验_20261110.md)、[补验 A3](技研/补验A3_AI隔离与恢复_20261110.md)、[补验 B](技研/补验B_审核二修正_20261110.md) |
| 订阅／API 智能体 | 启动时不注入任何供应商，直接用 CLI 自己的登录，和在终端里直接运行一样：照常继承用户环境（包括 shell 里的 `ANTHROPIC_API_KEY`、`OPENAI_API_KEY` 等），不额外清除，登录检测使用同一套环境。WillYou 拿不到其凭据，不获取模型列表、不测试可用性，模型用 CLI 默认的，可在会话里切换。Claude 订阅的真实验证由用户单独进行；没有 Anthropic、OpenAI 官方 API Key，相关真实调用本期不测 |
| Codex 运行第三方供应商 | 关闭插件同步与统计（`--disable plugins`、`-c analytics.enabled=false`），避免携带用户订阅身份外连 |
| MCP 跨 Agent 同步 | 已纳管 MCP 以按次注入方式配置给目标 Agent（Claude `--mcp-config`，Codex `-c mcp_servers`），不写入目标 CLI 全局配置；按[转换规则](技研/MCP跨Agent转换实验_20261110.md)映射：`env` 中 `${VAR}` 两侧语义不同（Claude 展开、Codex 按字面传递），不得按字段同名直接复制；有损字段（超时、Claude 侧 cwd 用包装实现、SSE→Codex 不支持）须提示；宿主专属、需单独 OAuth 认证、已停用项标示且不静默同步；env、headers、URL 中的敏感值加密保存或以 `${VAR}` 引用、启动时注入，不落明文。URL 含用户名／密码、疑似凭据的查询参数或片段参数，或含变量引用时，该 MCP 标“不支持转换”且不注入，提示改用请求头或环境变量；任一必需变量缺失时整个 MCP 不注入，其他 MCP 照常。**审批**：沿用来源 CLI 的批准设置，未设置时在终端询问，技能页为每个 MCP 提供“自动批准”开关。**凭据隔离**：向 Claude 注入 stdio MCP 时以包装命令清除模型凭据类变量（如 `ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_API_KEY`），其余变量照常传递；MCP 自己明确配置的变量即使与模型凭据同名也照常送达 |
| Codex 全局模型变化 | 启动前只读记录全局 `config.toml` 的 `model`／`model_reasoning_effort`，会话结束后对比；被改动时提醒“原来是 X，现在是 Y”，提供可复制的还原方法与打开配置文件入口，由用户自行修改，**WillYou 不自动写回**；会话处提示“切换模型按 s 只对本次会话生效”。用户在 Claude Code 或 Codex 的 `/model` 菜单里按 Enter 设为默认，不同步回智能体；每次新建任务都以智能体的默认模型为准 |
| 任务记录与恢复 | 见第三章 5.3“任务记录与恢复” |

由技术方案给出唯一选择的事项：插件包协议细则与声明式页面组件集；旧 AI 配置迁移方式；宿主端到端与 Electron 子进程密钥隔离作为正式开发第一步（P1）的通过门槛；工具多版本、多路径、自定义配置目录及升级后的处理；权限档位与浏览器 CLI 临时沙箱的组合（正式开发时核对）。完整公共市场运营、全量重构 Agent 内核、直接运行任意 Codex／DSH 插件，以及 Magpie 的全供应商目录、复杂路由、多账号轮换、额度统计和故障自动切换，不纳入本期。

### 3. 技术路线与模型设计

复用 M11／M12 的宿主服务、授权、统一 Skill 库及 Agent 适配，不另造一套凭据和项目体系。以“Code Agent → 订阅／API 或供应商 → 智能体 → 任务运行”区分实体身份；同一 Code Agent 可组合多个供应商，同一供应商可复用于多个兼容的 Code Agent，但不承诺任意组合都兼容。

采用 CLI 原生直连适配，不自建跨协议网关。供应商返回模型列表成功不代表该模型在所选 CLI 中具备完整代码 Agent 能力，须验证流式、工具调用及必要功能；普通用户流程不暴露这些细节，界面给出兼容性与修复动作。

已完成的必做技研：**T-CFG 配置载体**（Codex 用默认 `CODEX_HOME`＋按次 `-c`／环境变量；Claude Code 第三方供应商用独立 `CLAUDE_CONFIG_DIR`）与 **T-MODEL 会话内模型切换与恢复**（两种 CLI 自行恢复均不可靠，由 WillYou 读取原生会话记录并显式传入），结论见 [Codex 实验](技研/T-CFG_T-MODEL_Codex实验_20261110.md)、[Claude Code 实验](技研/T-CFG_T-MODEL_ClaudeCode实验_20261110.md)；旧配置能可靠识别的拆分为 Code Agent＋供应商，无法可靠拆解的保留为旧配置继续可用，不猜测供应商、不重写凭据。

## 第三章 功能性需求及规格说明

### 1. 整体业务流程

插件：导入安装 → 配置连接 → 项目使用（默认可用，可在项目里关闭）→ Agent 调用 → 更新、停用或卸载。

Skill／MCP：来源 CLI 安装／配置 → WillYou 自动扫描识别 → 纳管与冲突处理 → 各 Agent 配置 → 提示加载／依赖／认证状态 → 跟踪来源更新与卸载并按规则同步。

智能体：添加供应商（填 Key、获取模型、自动测试推荐模型）→ 新建智能体（Code Agent → 订阅或供应商 → 勾选模型）→ 首页选择智能体与权限档位并启动 → 查看错误并修复 → 停止后恢复。

### 3. 插件

#### 3.1 扩展与管理

**功能描述**：统一插件身份、版本、来源、依赖和能力组合，支持安装、配置、启停、更新与卸载；禅道迁为外部插件（后续三方应用模板）；邮件、浏览器保持内置插件并在目录中标“内置”。

**用户角色**：普通本机用户、插件开发者。

**输入**：符合宿主扩展协议的插件包及其声明；首期来源为本地目录与本地压缩包。

**基本事件流**：读取插件元数据 → 校验兼容性与完整性 → 安装并确认权限 → 配置连接 → 项目使用 → 调用能力 → 按生命周期更新或停用卸载。

**输出**：插件及能力状态、明确错误和恢复位置、可追溯的调用与变更依据。

**界面原型**：共享原型工程中的插件目录、详情、安装／更新、卸载、连接与插件页面，页面与状态对应见[原型说明](原型/原型说明与变更.md)；参考用户截图 02–06。

**连接与项目使用**：
- 插件装好后所有项目默认可用，单个项目可在项目页关闭。
- 连接统一在插件详情页配置，可配一个或多个；有连接时必须有一个**全局默认**：只配一个时它就是默认，配多个时由用户指定。
- 每个项目记录自己的状态：**跟随全局默认**（默认状态）或**个性化**（单独选了某个连接，即使选的恰好是当前全局默认）。项目页可随时切回跟随全局。每个项目同一时间只有一个生效连接。
- 全局默认从 A 改为 B：保存前弹窗分两组列出“将同步改为 B 的项目（跟随全局）”与“保持不变的项目（个性化）”，确认后生效；已关闭该插件的项目不列。
- 切换连接（全局默认变化或项目改选）时，运行中的任务继续用其启动时的连接直到结束；新建或恢复的任务使用切换后的连接。不要求切换前先停止相关运行。
- 删除连接：删除全局默认且还有其他连接时，先选新的全局默认，跟随全局的项目按上条同步；个性化选了它的项目弹窗列出，删除后改为跟随全局；有运行中任务正在使用该连接时不允许删除（删除会同时删除凭据），提示等任务结束或先停止，是否“正在使用”按运行中任务本次启动时记录的连接判断，任务停止后不再计入；删除唯一的连接后插件暂不可用，直到再配置连接。
- 项目页“插件”分区只负责关闭插件、在跟随全局与个性化之间选择，不另设“项目选用”页。分区按“内置”“外部”两个页签分开，页签带数量，默认“内置”；没有外部插件时显示“还没有安装外部插件”和“去插件页”；分区不设标题，使用说明（默认对所有项目可用、连接在插件详情配置、切换连接时运行中任务仍用原连接）以底部浅灰小字呈现。
- **不提供调用记录页面**，也不在任务内另设查看位置；宿主仍保留调用账本，用于授权审批、写操作结果未知时不自动重放等内部用途。邮件附件与发送结果在邮件“草稿”页查看。

**插件版本与升级（松耦合）**：界面只显示插件当前版本，不显示旧版本或“版本占用”。插件与宿主、插件与任务松耦合：升级只换插件包，不改宿主代码；新版本须向后兼容老任务，删除或改名能力须用 `legacyToolNames` 映射，安装检查发现删除能力且无映射时提示“老任务调用这些能力会失败”。升级时正在执行的调用按旧版本完成，之后所有任务（含运行中、恢复的任务）的调用都使用新版本，旧版本随即删除；激活失败自动回到原版本。更新后插件的权限、能力、Skill 等元数据全部以新包为准，新包给出空列表表示全部删除，并在更新确认里列出将删除的项。卸载时正在执行的调用完成，之后调用提示“插件已卸载”。

**插件安装与更新**：
- **两个入口**：插件页“添加”用于安装新插件；外部插件的目录卡片与详情页“…”菜单提供“更新…”。内置插件随 WillYou 升级，没有“更新…”。
- **安装页**：标题“安装 <插件名>”，显示说明、能力、自带 Skill、权限与安全提示，按钮“安装”；它也是尚未安装插件的介绍。
- **更新页**：标题“更新 <插件名>”，显示“当前版本 → 新版本”，只列出与当前版本相比的变化：新增或删除的能力、Skill，新增或不再需要的权限；新增权限醒目列出，点“更新”即表示同意；删除能力且无 `legacyToolNames` 映射时提示老任务调用会失败；没有变化时写明。
- **自动识别**：从“添加”选到已安装插件的包时，按更新处理并说明；从“更新…”选到其他插件的包时拒绝，提示“这不是 <插件名> 的插件包”。
- **更新停用中的插件**：更新不改变启用状态。停用的插件更新后仍停用，更新页说明“当前已停用，更新后仍保持停用，启用后才会生效”；新增权限照常在更新页确认，之后启用时不再询问；提示不提运行中会话（如“禅道已更新到 1.1.0，仍为停用状态”）。
- **不允许降级**：所选包版本低于已安装版本时拒绝，提示“不支持安装更低的版本”，不做任何改动；版本相同时提示“已是当前版本，无需更新”。
- **回退办法**：新版本有问题时，用户可以先卸载（选“保留数据”）再安装旧版本，这属于新安装，允许进行；卸载弹窗的“保留数据”说明这一用法，并提示旧版本可能读不了新版本写入的数据。
- **不提醒新版本**：首期没有插件市场或远程来源，WillYou 不检查、不提醒插件新版本，用户拿到新包后通过“更新…”手动更新；自动检查与提醒随以后的插件市场一起做（[需求池 F30](../../需求池.md)）。

**会话生效规则**（统一插件与技能的启用、停用、更新、卸载、纳管）：
- **新建或恢复的会话**：一律按最新状态加载插件、Skill 与 MCP，并按当时生效的连接记录本次运行的插件与连接。
- **运行中的会话**：经 WillYou 转发的插件调用立即按最新状态执行——停用或卸载后拒绝调用并提示“插件已停用／已卸载”，更新后使用新版本（正在执行的调用按旧版完成）；会话启动时已经加载的 Skill 与 MCP（包括插件自带的 Skill）保持不变，重启会话后才变化。Claude Code、Codex 在启动时加载 Skill 列表与 MCP，第三方 MCP 进程由 CLI 启动，WillYou 不能在运行中摘除。
- **切换连接是例外**：运行中的任务继续用其启动时的连接直到结束（见“连接与项目使用”）。
- **项目里关闭插件**：等于只在该项目停用该插件，规则同上，范围限于该项目——本项目运行中会话的插件调用立即被拒绝并提示“本项目已关闭该插件”，已加载的插件自带 Skill 重启后去掉；本项目新建或恢复的会话不加载该插件的能力与自带 Skill；重新启用时反之；其他项目不受影响。插件全局停用时项目开关不起作用，项目页标“插件已停用”，全局启用后按项目设置生效。
- **提示**：每次启用、停用、更新、卸载、纳管、取消纳管或在项目里开关插件后，提示上述生效方式；有受影响的运行中会话时同时提示“N 个运行中的会话重启后完全生效”，为 0 时不提，只显示数量不列名单。只数受影响的会话：插件全局操作数插件可用项目（未在项目里关闭）中的会话；项目开关只数该项目的会话；技能启停数加载了该项的会话（用户级为全部，项目目录自带的只数该项目）；纳管与取消纳管只数“另一个工具”的会话。

**插件页面**：
- 插件的页面（列表、表格、页签、详情、表单等）由插件声明、WillYou 渲染；插件新增功能时，在已支持的组件范围内只需更新插件包即可调整页面，插件自带 Skill 随插件更新；需要 WillYou 尚未支持的组件时须先升级 WillYou。组件集由技术方案定案。
- **停用后的插件页面**：插件全局停用后，它的页面（如禅道“我的工作”、邮件“草稿”）不读取数据、不能插入或发送，显示“<插件>插件已停用”和“启用”按钮；侧栏子页面入口保留但显示为不可用，详情页的页面按钮不可用；已有数据（如草稿）保留，启用后照常显示。页面选到已关闭该插件的项目时显示“该项目已关闭<插件>插件”。
- **禅道“我的工作”**：点一行打开详情（步骤、附件、历史）。“插入到”只列当前所选项目中运行中的会话（这条 Bug 属于该项目所选的禅道，其他项目可能用不同的禅道连接或已关闭禅道）；插入只把引用放进终端输入，不自动回车。该项目没有运行中的会话时，提供“新建会话并插入”：回到首页、选中该项目，并把引用预填进输入框。
- **邮件草稿按项目**：关闭了邮件插件的项目，其草稿只读并标注“本项目已关闭邮件插件”；发件人为该项目实际生效的 SMTP 连接。

**约束规则**：常规新增插件只改插件自身，不改或重打包宿主；新能力超出已支持接口可能需要升级 WillYou。以新示例插件完整走通生命周期，核宿主生产源码／包未变。保留已有项目、连接、凭据、权限和历史；运行中更新、卸载的资源回收与失败恢复由技术方案定案。独立 Skill／MCP 不强制冒充完整插件包，外部插件协议兼容性另行核验。

### 4. 能力统一管理

#### 4.1 发现与同步

**功能描述**：用户通过 WillYou 内的 CLI 安装 Skill／配置 MCP 后，自动发现并纳管，统一为其他已适配的 Agent 配置；技能页负责来源、覆盖、生效与异常状态管理。

**用户角色**：普通用户与习惯 CLI 安装的高级用户。

**输入**：所选智能体及实际 HOME／项目路径（含 `CODEX_HOME`、`CLAUDE_CONFIG_DIR` 等配置目录）中已经安装／配置的 Skill、MCP 连接声明与来源变动；插件自带能力由所属插件的安装记录提供。

**基本事件流**：用户在来源 CLI 安装／配置 → WillYou 静态发现 → 区分外部发现项、已纳管项、插件自带能力与 WillYou 内置能力 → 处理同名与作用域 → 纳管并配置其他已适配 Agent → 展示配置、加载、依赖、认证及调用验证状态 → 跟踪后续来源变化。

**输出**：来源记录、Agent 覆盖状态、需重启会话／补依赖／认证或不支持等可操作结果。

**界面原型**：截图 01／07 为现状；“技能”页（扫描列表、能力详情）见[原型说明](原型/原型说明与变更.md)，展示来源、目标 Agent 和同步／生效状态；不设计独立 Skill 安装或 MCP 添加表单。

**WillYou 内置能力**：M11 标准 Skill（数据库诊断、远程 SSH）与 WillYou 项目上下文 MCP 在技能页单列“WillYou 内置”分组，与从 CLI 发现的外部能力分开；显示当前版本（不显示旧版本）、可停用、随 WillYou 升级，交付方式沿用 M11。

**项目范围**：不提供按项目单独启用／停用技能的开关；技能页中已启用的 Skill 与 MCP 默认对所有项目可用，停用即对所有项目停用。项目目录自带的 Skill／MCP 照常发现，在技能页标明来源项目，只在该项目的任务中生效（项目级安装不自动扩成全局授权）。

**会话生效**：技能的启用、停用、纳管、取消纳管对会话的影响按 3.1“会话生效规则”执行。

**约束规则**：本期不提供独立 Skill／MCP 的页面安装／导入／新增连接入口；原始安装与首次认证保留在来源 CLI 或对应工具中完成。插件安装及其附带能力配置不受此限制；插件自带项由所属插件维护，避免重复接管。沿用 M11 单份统一库和 Agent 引用方案，验证第三方安装器在纳管、链接下的更新与删除行为。纳管前不移动删除原件，不覆盖同名用户文件，不默认改写第三方名称或内部引用。不同 Agent 的 MCP 配置按语义转换（见第二章“MCP 跨 Agent 同步”），不能直接复制整个配置文件或账号令牌；宿主专属连接和认证不兼容时明确提示。可见不代表具备项目资源权限。配置成功、会话加载与调用成功分别判断。扫描不隐式启动 MCP 或外部脚本。验收包含 A 安装→WillYou 纳管→B 实际使用，以及重启、升级、卸载、自定义目录、冲突和失败恢复。

#### 5.1 本机工具

**功能描述**：检测本机已安装的 Code Agent CLI 与其登录状态，普通用户无需自行填写可执行路径。

**用户角色**：普通本机用户，重点支持首次使用的新手。

**输入**：本机可执行程序、版本与登录状态；首期 Code Agent 为 Claude Code 与 Codex，自定义路径作为高级能力。

**基本事件流**：在新建智能体第 1 步查看各 Code Agent 卡片与“本机检测” → 找不到时给出安装引导与“重新检测” → 需要时“自定义路径…”。

**输出**：可用的 Code Agent 及其登录方式。

**界面原型**：截图 08 为原 WillYou 工具检测基础；当前位置见原型说明“新建／编辑智能体”。

**规则**：
- 不设单独的“本机工具”页签。新建智能体第 1 步的卡片显示版本与 CLI 登录状态，没检测到的工具卡片置灰；卡片下一行“本机检测”分别显示各工具的检测到程序、程序可启动、版本已验证（未验证版本提示“可继续使用”），并提供“自定义路径…”和“重新检测”。
- **登录检测**：时机为应用启动、进入智能体页、点“重新检测”、启动任务前；方式为读取 `claude auth status`、`codex login status`，使用与订阅／API 智能体启动相同的环境。按登录方式命名：订阅账号登录为“订阅”，CLI 里用 API Key 登录为“API”；登录来自环境变量或配置里的 Key 时按“API”命名，并写明来源（如“API（来自环境变量 ANTHROPIC_API_KEY）”）。已登录时的输出与区分订阅和 API 的字段须在正式开发第 1 步核实（Codex 订阅用用户的 GPT 订阅核实，Claude 订阅由用户单独核实，API Key 登录的真实输出本期不核实）；无法区分时统一叫“<Code Agent> · 本机登录”。
- **已有的订阅／API 智能体跟随登录变化**：登录方式变化（订阅↔API）时原智能体改名，不生成第二个，用户改过的名称保留；退出登录时智能体保留，标“已退出登录”，不在首页显示、首页开关不可打开，原来是默认时按默认交接处理；重新登录后恢复，但不抢回默认。WillYou 不因检测到登录而自动添加订阅／API 智能体：CLI 登录后只在新建智能体第 2 步出现可选的“订阅”或“API”，并提示用户可以新建。
- 没检测到某个工具时，它的智能体变灰、不在首页显示；重新检测到后不自动补生成智能体。

**约束规则**：检测到目录、检测到程序、程序可启动、版本已验证和模型连接可用分别呈现，不以一个“已检测”代替完整健康验证。以实际所选 Code Agent 启动任务，不因切换供应商替换底层 CLI。多版本、多路径、自定义配置目录及工具升级后的处理由技术方案定案。

#### 5.2 供应商

**功能描述**：供应商独立管理并可复用，简化服务地址、协议、认证和模型配置。

**用户角色**：自备 API 服务或使用网关的用户。

**输入**：目录中的预设或自定义地址、Key，以及模型列表或手动模型 ID。

**基本事件流**：添加供应商（选择目录预设或自定义 → 填 Key 并获取模型 → 完成）→ 自动测试推荐模型 → 在新建智能体时选用。

**输出**：可复用的供应商、模型目录与各模型在各 Code Agent 中的可用性。

**界面原型**：Magpie 截图 09–11 作为功能分层参考，不照搬其全部供应商或网关功能。

**供应商目录**：
- 通用目录，带图标、可搜索，分“供应商”与“自定义供应商”，每家标出“可用于 Codex／Claude Code”；不再有“原有登录”组（订阅／API 来自 CLI 自己的登录，不在目录里接入）。
- 首期内置七家：**Anthropic、OpenAI 官方 API**、**DeepSeek**、**GLM（智谱）**、**SMG**、**UltraCloud**、**Magpie**；目录为可扩展数据，不追求完整。每家的服务地址、协议、模型列表接口与图标来源须在开发时核实，未核实的在原型中用占位数据并标注（UltraCloud 待用户提供资料）。
- 官方 API Key 交给 WillYou 加密保存，可生成“Claude Code · Anthropic”“Codex · OpenAI”智能体，可获取模型、测试可用性；这和 CLI 里登录的“API”是两回事。
- **SMG**（已核实）：内网网关，只提供 Anthropic Messages 与 Chat Completions，没有 Responses，所以**只适用 Claude Code**；模型列表从网关实时获取，ID 带版本后缀，推荐模型按前缀匹配。Magpie 中的“Ultrapwor云”就是 SMG，所以 Codex 可以经 Magpie 使用 SMG 的模型（表现为“Codex · Magpie”智能体勾选 `ultrapwor/*` 模型）。
- **Magpie**：本机网关作为预设直接接入，地址 `http://127.0.0.1:3425/v1`、令牌 `magpie-codex`、Codex 模型目录取自 `/v1/codex/models`；真实 Key 与上游路由留在 Magpie，WillYou 不读取、不改写 Magpie 或 CLI 全局配置；Magpie 未运行时启动前提示（依据 [Codex 实验](技研/T-CFG_T-MODEL_Codex实验_20261110.md) M1–M5）。

**添加供应商**：
- 三步：选择、填 Key 并获取模型、完成。目录预设只需填写 Key，地址与协议已预填；自定义供应商参考 Magpie“自定义供应商”：名称、服务地址与协议页签（OpenAI Responses、Anthropic、OpenAI 兼容）、检测协议、API 密钥、图标、模型（获取列表或手填），高级设置折叠（用于调整 Codex 所需的模型元数据）。
- 自定义地址以 `/models` 与空请求探测得出**候选协议**，最终以一次最小流式＋工具调用确认可用后，该协议才可用于创建智能体（依据[补验 A4](技研/补验A4_Provider接入_20261110.md)、[技术方案 §3.2](技研/技术方案.md)）；不承诺任意第三方服务的探测不计费，确认调用可能产生少量费用，界面须如实提示。模型列表 401 提示 Key 无效、超时提示不可达、空列表或无接口时允许手填。
- Codex 所需的模型元数据：Magpie 由其目录接口提供；DeepSeek 等预设由 WillYou 内置（来源须可追溯）；自定义地址用通用默认值并可在高级设置调整。
- 获取到的模型可勾选接入（默认全选）。接入时自动用推荐模型为每个兼容的 Code Agent 各测试一次（最小的流式加工具调用），并提示可能产生少量费用。
- **不自动生成智能体**。完成页只展示模型表（模型、上下文、各适用 Code Agent 的可用性）；右下角为“创建智能体”和“完成”。“创建智能体”打开新建弹窗并预选这个供应商与适用的 Code Agent；从新建弹窗进入添加供应商时，沿用当时选的 Code Agent。
- **工具搭配**：Codex 只能直接使用 OpenAI Responses 协议，Claude Code 只能直接使用 Anthropic 协议。只提供 OpenAI 兼容等协议的供应商可以保存，但没有“创建智能体”，提示“两个工具都不能直接使用，可经 Magpie 等网关接入”。

**供应商列表与详情**：
- 列表每行显示“适用”的 Code Agent：兼容的打勾，不兼容的显示“—”，悬停时说明原因；导入时未带 Key 的标“需要填写 Key”。
- 详情分“概览”“智能体”两个页签，默认“概览”。概览：适用工具、服务地址、Key（脱敏、更换）、模型目录刷新、模型在各 Code Agent 中的可用性对照表（★ 标出对应智能体的默认模型；“—”表示没有该工具需要的接口；可以单个测试、重测，或“测试全部未测试”）。智能体：使用这个供应商的智能体，以及还没有智能体的适用 Code Agent 的“用它创建 X 智能体”；已有组合不显示创建入口，在设置的现有智能体列表中编辑；都已有时只保留列表与编辑提示。
- 删除供应商前，列出将一起删除的智能体，并提示默认如何交接；使用过这些智能体的历史任务恢复时提示重新选择。

**模型目录与可用性**：
- 同一个模型在 Claude Code 和 Codex 中分别记为“可用”“不可用”或“未测试”。
- 测试请求尽量和 CLI 实际运行一致：要求模型调用一个工具，Claude Code 侧带上与当前 CLI 版本相同的 beta 头和 thinking 参数；失败时自动重试一次，两次都失败才记“不可用”并保留错误原文；“接口不存在”这类明确的失败不重试；“不可用”的模型可随时重测。
- 模型目录在每次启动任务前随可达性预检自动比对刷新（智能体默认模型已下线时提示改选），另提供手动“刷新模型”；服务不可达时启动前提示，不让 CLI 卡在重连。

**约束规则**：订阅登录与 API Key 是不同认证方式，不能把订阅登录等同于通用 API Key；不要求用户把密码／令牌填进聊天。Key 沿用 WillYou 加密存储与脱敏原则，只在启动时注入。供应商兼容协议须细分并验证，不能只凭“OpenAI 兼容”判断任意 CLI 都能使用；模型列表请求成功不等于代码工具调用可用。跨协议网关、多账号与路由不纳入首期。

#### 5.3 智能体与首页

**功能描述**：把一个 Code Agent 和订阅／API 或一个供应商组合成智能体并勾选模型；首页选择智能体与权限档位后启动任务；任务记录启动时的配置并可恢复。

**用户角色**：所有任务用户。

**输入**：本机 Code Agent、兼容的供应商或 CLI 登录、勾选的模型与默认模型、名称、首页显示、权限档位。

**基本事件流**：新建智能体 → 首页选择智能体与权限档位 → 启动前预检 → 用所选组合启动真实 CLI → 停止后恢复。

**输出**：智能体列表（即首页下拉）、任务及其启动记录。

**界面原型**：截图 12 标注的首页入口；智能体页、新建／编辑弹窗、首页权限菜单见[原型说明](原型/原型说明与变更.md)。

**智能体列表**：
- 智能体列表平铺，顺序就是首页智能体下拉的顺序。每行显示：Code Agent 图标（带供应商小角标）、名称、“默认”标记、默认模型（模型“未测试”或“不可用”时标出；勾选了多个模型时写“另 N 个模型可切换”）、“首页”开关和“…”菜单（设为默认、编辑、上移、下移、删除），不提供“复制”。订阅／API 智能体也可以删除，删除后可在新建第 2 步选“订阅”或“API”重新建（用户 2026-11-11 决定）。
- 旧配置放在同一列表里，标“旧配置”。
- **排序与默认**：智能体可以拖动，也可以用菜单上移、下移。默认智能体固定排第一，不能移动，其他智能体不能排到它前面（拖到它上方时放在它后面）；设为默认后自动排到第一位。只有在首页显示的智能体才能设为默认，默认智能体的“首页”开关不能关。
- **默认交接**：默认智能体被删除、退出登录、它的供应商被删除，或因工具不见了等原因不可用时，按当前顺序从上往下第一个在首页显示且可用的智能体设为默认并排到第一；原默认恢复可用后不抢回。
- **首页显示**：首页的智能体下拉只列“首页显示”打开、没有退出登录、工具已安装的智能体。

**新建与编辑智能体**：在智能体页点“新建智能体”，按三步填写，三步之间联动，不填 Key（Key 和模型可用性在添加供应商时已经保存）。
1. **Code Agent**：列出 Claude Code、Codex、OpenCode、Z Code、Pi、DSH；首期只支持 Claude Code、Codex，其余显示官方图标并标“暂不支持”、不可选；检测信息见 5.1。
2. **订阅或供应商**：只列出支持所选 Code Agent 协议的供应商，不兼容的折叠在“不支持 X 的供应商（N）”里并写明原因；CLI 已登录时第一项是“订阅”或“API”（按登录方式），未登录时置灰并提示在终端怎么登录；列表底部有“添加供应商”。
3. **模型与名称**：模型是勾选列表，只列这个供应商在所选 Code Agent 中可用或未测试的模型，不可用的隐藏并说明数量；推荐模型标出并默认勾选（推荐模型在该 Code Agent 中不可用时，依次预选第一个可用的、第一个未测试的模型，用户 2026-11-11 决定），可以多选，至少选一个，并指定一个“默认”，启动时用它，其余在会话里切换；未测试的模型可以当场测试。选订阅／API 时不选模型，使用 CLI 默认模型。名称自动生成为“Code Agent · 供应商”（订阅为“Code Agent · 订阅”），可以修改；首页显示默认打开。
- 切换 Code Agent 时，供应商重新过滤并预选第一个可用的；切换供应商时，模型列表刷新并勾选推荐模型。新建的智能体加到列表末尾。
- **不允许重复**：同一个 Code Agent 加同一个供应商（或同一个 Code Agent 的订阅／API）只能有一个智能体；想用更多模型就编辑已有的那个。第 2 步中已有智能体的选项置灰，写明“已有某某”并提供“编辑它”；打开新建时跳过已有的组合，全都已有时第 3 步提示编辑已有的或添加新供应商；从供应商入口创建时，组合已存在就直接打开已有的智能体。名称不能和其他智能体重复，重名时提示并禁止保存。旧配置不参与这两项判断。
- **编辑**：与新建同一个弹窗，副标题显示智能体名称。Code Agent 不能更换；可以换供应商（同样不能和已有组合重复）、改勾选的模型与默认模型、名称、首页显示。旧配置的编辑只有名称、首页显示、环境变量与启动参数。
- **没有高级设置与运行说明**：新建和编辑弹窗都没有“高级设置”；Claude Code 的各档位（Opus、Sonnet、Haiku、small-fast、子 Agent）一律等于默认模型；环境变量与启动参数只保留在旧配置中；独立配置目录等运行规则照常执行，写在技术方案里，不在弹窗显示。
- **保存时清理模型**：测试不可用或已下线的模型从勾选中去掉，默认模型被去掉时改为第一个保留的模型；Claude Code 的档位写入前一律等于默认模型。
- **会话内切换**（供应商智能体；订阅／API 智能体按 CLI 自己的模型列表切换）：Claude Code 与 Codex 都保持多选，会话里 `/model` 菜单只显示勾选的模型（Claude Code 另有“Default”行），内置模型不出现；按 `s` 只切本次会话；在菜单里按 Enter 设为默认不同步回智能体。

**首页**：
- **智能体选择器**：显示当前智能体的图标与名称，没有可选智能体时显示“选择智能体”；下拉每项使用与智能体列表相同的图标（Code Agent 图标＋供应商角标，旧配置为终端符号）；下拉以选择器为中心弹出，尺寸紧凑（参照 Codex 推理强度弹层）；菜单底部“管理智能体”打开智能体页。
- **输入框**：随内容增高，最多显示 10 行，超过后出现竖向滚动条；清空后回到原高度。
- **权限档位**（F31，依据[补验 E](技研/补验E_智能体权限_20261111.md)，参照 Codex 首页权限选择细粒度复刻）：
  - 位置（原型 P0.17 经用户评审）：首页输入框工具栏“+”右侧的权限按钮（替换原“项目上下文”入口，任务配置仍从输入框上方的齿轮进入），点开后向上弹出菜单，表头“应如何批准 <Code Agent> 操作?”。“设置 › 智能体”不另设权限。
  - 档位与名称照搬 Codex：**Codex 智能体**为请求批准（编辑外部文件和使用互联网时始终询问）、帮我批准（仅对检测到的风险操作请求批准）、完全访问权限（可不受限制地访问互联网和你电脑上的任何文件）三项；**Claude Code 智能体**只有请求批准、完全访问权限两项。两者都不提供“自定义”与“只读”。Claude 暂不提供“帮我批准”：订阅下 auto 尚未实测，第三方供应商下已确认不完整（补验 E 的 E10、E11），以后专门测试后再决定是否开放。
  - 默认档位为请求批准；记住上次的选择，跨重启保留。记住的“帮我批准”在 Claude Code 智能体下按请求批准显示与启动，记住的值不改，切回 Codex 时恢复。
  - 任务运行中改首页的选择，只对之后新建的任务生效；恢复旧任务沿用该任务创建时的档位；用户在终端里用 CLI 自带方式（Shift+Tab、`/permissions`）切换的，WillYou 不跟踪、不显示。
  - 第一次选择完全访问权限时，WillYou 弹一次确认框，说明“可以不经询问修改任何文件、访问网络”，取消则档位不变，确认后记住（跨重启），之后不再询问；WillYou 不替用户预先写入跳过 Claude Code 自身风险警告的配置，Claude Code 首次以完全访问运行时仍由用户在终端确认。
  - 选择完全访问权限后按钮显示为橙红色（照 Codex 参考图，原型 P0.17）。档位只决定 CLI 内置工具（文件、命令、联网）是否询问；插件写操作仍按插件规则由 WillYou 审批，选完全访问权限也照常弹审批（用户 2026-11-11 决定）。各档对应的启动参数见技术方案 §3.8（Codex 的请求批准须同时指定由用户审批，否则用户配置里的自动审查会代批）。

**启动前预检**：新建与恢复共用同一预检。所选智能体的供应商已删除或缺 Key 时拒绝启动，不创建运行中任务；提示中提供“去填写 Key”直接打开该供应商详情（供应商已删除时提示改选智能体），填写后即可启动。首页下拉仍显示该智能体。Magpie 未运行、服务不可达或默认模型已下线时同样在启动前提示。

**运行中服务异常**：运行中服务连续失败时提示“服务异常，是否中断或切换配置”。用户可继续等待，或显式中断后在既有恢复页选择同一 Code Agent 的智能体；不自动切换服务、恢复任务或重放写操作。此项补回已确认技术方案 §3.3 与 T067 的现有约定，非新增范围（2026-11-13）。

**任务记录与恢复**：
- **任务记录**：新建任务时记下所用智能体（Code Agent、订阅或供应商、默认模型、勾选模型、本次使用的模型）、权限档位，以及本次可用的插件和生效连接。终端标题、任务信息、恢复、会话插件按这份记录显示，不回查旧 AI 配置。任务信息不显示凭据、环境变量与旧配置的高级启动参数；权限档位及其固定启动参数照常显示。
- **恢复任务**：只能选同一个 Code Agent 的可用智能体，默认选原智能体；原智能体或它的供应商已修改、删除时提示重新选择，不静默换账号；“已修改”指模型来源改变（订阅与 API 互换、换了供应商、供应商的地址或 Key 被替换），提示中写明原来源与新来源，用户重新选择后才能恢复，继续选原智能体即表示改用新来源；只改名称、排序、默认模型或勾选模型不算修改，按下面的模型规则处理。换成另一个智能体恢复时，旧会话的记录随之带过去，带不过去就不恢复，不能用新会话代替；换成订阅／API 智能体时，WillYou 可以在用户的 Claude 会话目录（`~/.claude/projects`）中新增这份会话记录，但不修改已有文件或配置，已有同名记录时不恢复并提示。恢复使用的模型：WillYou 从原生会话记录读取最后一次实际使用的模型（Claude `requestedModel`，Codex `turn_context.model`）并以 `-m`／`--model` 显式传入；该模型仍在所选智能体的勾选列表里就沿用（即使智能体的默认模型已改），不在时用所选智能体的默认模型并在恢复前提示。恢复时插件与连接按最新状态重新加载（见 3.1“会话生效规则”），权限档位沿用创建时的记录，并同样经过启动前预检。

**导入导出**：智能体页提供通用的导入、导出（不提供“从 .zshrc 导入”）。导出时勾选供应商与智能体（勾选智能体时自动带上其供应商），生成 JSON 文件，别人导入后可直接使用；**默认不含 Key**，可勾选“包含 Key”，此时按 M8 项目迁移的做法用口令（至少 8 个字符）加密，导入时输入口令。导出保留勾选的模型、各协议地址与推荐模型；不导出工具可执行路径与本机目录；订阅／API 智能体跟随本机登录，不导出，导入文件里如果有则跳过并说明。导入前预览（Key 脱敏），同名不覆盖现有配置，名称已存在时依次加“（导入）”“（导入 2）”；未带 Key 的供应商标“需要填写 Key”，填写前该供应商的智能体不能启动（见“启动前预检”）。

**约束规则**：同一个 Code Agent 可组合多个供应商，同一个供应商可被多个兼容的 Code Agent 复用；不兼容组合在新建时说明。可执行路径、环境变量、参数生成与优先级由适配层负责，具体实现由技术方案定案，并发运行的智能体不能串用账号或端点。按本次运行注入，WillYou 不写全局 CLI 配置，不采用 Magpie 的全局接管模式。注入载体：Codex 使用默认 `CODEX_HOME`＋按次 `-c`／环境变量（原生 `/model` 写全局按第二章规则处理）；Claude Code 第三方供应商使用 WillYou 管理的独立 `CLAUDE_CONFIG_DIR`＋环境变量。现有 Codex／CC-work／CC-rj／CC-deepseek 等配置必须保留，迁移方式由技术方案依 T-CFG 结论定案，无法可靠拆解时作为旧配置继续可用，不猜测供应商、不重写凭据；历史任务、名称与默认配置的迁移须有明确方案。Skill／MCP 的共享按 Code Agent 及实际目录适配，与供应商解耦；更换模型服务不要求重装一套 Skill。
