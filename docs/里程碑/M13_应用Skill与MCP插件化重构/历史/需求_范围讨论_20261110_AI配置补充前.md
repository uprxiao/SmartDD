## 插件扩展方向确认（2026-11-10）

用户确认插件可自行包含代码；WillYou 提供通用扩展接口、管理与执行支持，具体业务在插件内实现。在宿主已支持的扩展接口范围内，新增符合协议的插件不需要修改 WillYou 源码或重新打包；超出既有接口的能力可能需要升级宿主。

后续以一个原先不存在的示例插件验证安装、配置、调用、升级和卸载，核对宿主生产源码及安装包未改变。具体包协议、支持的来源、运行中生效与恢复规则尚需技研和用例定稿；不把此方向确认等同于正式开发授权或兼容全部外部插件。

## 独立 Skill 的统一安装讨论（2026-11-10，方案待确认）

用户提出：安装 Skill 后，如何在 WillYou 的所有 Agent 中完成配置。

建议沿用 M11 的单份统一库和 Agent 适配机制，为用户独立安装的 Skill 提供统一入口；按各 Agent／AI 配置的实际发现路径建立引用或配置，并展示配置、加载、生效及依赖状态。当前代码已有标准 Skill 与应用 Skill 的统一库交付，不能据此声称任意用户 Skill 的一键安装管理已实现。

范围以 WillYou 已接入并适配的 Agent 为准；自定义 HOME／配置目录需核对，不能只写默认路径。运行中会话是否需要恢复按实际 Agent 能力判定；Skill 文件可见不代表它依赖的 MCP／CLI 已安装、已认证或具备项目授权。同名冲突、第三方 Skill 的原名与引用保持、依赖适配等仍需细化，不能覆盖用户已有资源。

## 从 CLI 安装后发现与跨 Agent 同步（2026-11-10，范围讨论）

用户提出的使用场景：在任意 WillYou 内的 CLI 中安装 Skill 或配置 MCP，WillYou 从实际目录／配置自动扫描识别，纳入统一管理，再配置给其他已适配的 Agent 使用。保留 CLI 安装习惯；不要求用户必须先从 WillYou 页面安装。

现有扫描结果是实现此流程的基础，目前只有静态发现，不具有通用纳管和跨 Agent 同步功能。页面需要区分外部发现项、WillYou 已纳管项、插件自带能力，以及各 Agent 的配置／加载／验证状态；独立 Skill／MCP 不必强行伪装成完整插件包。

待确认的产品与技术规则：

- 自动发现的触发时机及纳管方式：页面进入、手动重新扫描、后台目录变动监听如何组合；首次一键同步或自动同步策略需明确，不能假定监听能识别所有安装命令的结果。
- 来源与目标：按实际 AI 配置／HOME／项目目录发现，保留来源、资源身份及版本依据；项目安装不能自动变成全局授权，目标 Agent 在其他项目可见不等于允许访问原项目资源。
- Skill：统一资源与各 Agent 引用的实现需验证来源安装器的兼容性；未明确纳管／迁移前不移动或删除原件，不覆盖同名用户文件，不默认改写第三方 Skill 的名称或内部引用。处理专属格式、脚本依赖和不支持的 Agent。
- MCP：转换标准连接声明而非直接复制不同 Agent 的配置文件；区分远程连接与本地进程、参数／环境、依赖及认证。账号认证、宿主专属连接、短期令牌和项目权限不能按配置文本直接复制；不兼容或需重新认证的目标明确标识。
- 外部工具后续更新、卸载与纳管后页面编辑：确定谁是维护方、冲突时如何处理、是否跟随删除，以及防止扫描—同步循环。扫描不得启动外部程序或 MCP 作为隐式安装检查。
- 生效：配置成功、Agent 发现、会话加载及实际调用成功分别报告。新会话与已有会话按各 Agent 支持的刷新／恢复方式处理，不能以文件落盘代替所有会话已可用。

后续验收应包含在 Agent A 真实安装／配置 → WillYou 发现与纳管 → Agent B 实际发现及调用，并覆盖升级、卸载、重启、同名冲突、项目边界、自定义目录、依赖缺失和认证失败；具体用例待需求与技研定稿，不预填通过。
