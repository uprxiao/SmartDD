## 2. 各探针细节

### P1 原生模块

- `pnpm.onlyBuiltDependencies` 放行 better-sqlite3、node-pty、electron、esbuild；postinstall 执行 `electron-rebuild -f --only=better-sqlite3,node-pty`。
- 重建后的二进制按 Electron 的 ABI 编译，普通 Node 下的 vitest 无法加载，所以**单元测试只覆盖纯逻辑**，原生模块交给 Electron 探针验证。
- Node 22.23.1 能完成安装和构建（Yoda 要求 Node ≥24，这里没有强制）。
- 打包后的 `.node` 文件和 node-pty 的 `spawn-helper` 被 electron-builder 自动从 asar 中解包，打包产物中 PTY 执行成功。

### P2 Claude Code

- 会话文件路径：`~/.claude/projects/<真实路径编码>/<sid>.jsonl`。路径会先做 realpath，例如 `/tmp` 会解析为 `/private/tmp`。
- 在新目录首次以交互模式启动时，会弹出“Quick safety check… Yes, I trust this folder”，默认选中的是“No, exit”。**Desktop 不代答**，由用户在内嵌终端中自己确认。
- 待验证：交互模式下用 `--session-id` 启动后，会话文件是否以该 ID 落盘。

### P3 Codex

- `codex exec --json` 的 `thread.started` 事件会给出 `thread_id`；`codex exec resume <id>` 能接上上下文。
- 交互 TUI 启动时不生成 rollout，**第一条用户消息之后**才写入 `~/.codex/sessions/YYYY/MM/DD/rollout-<时间>-<uuid>.jsonl`。文件首行 `type=session_meta`，payload 中有 `id`、`cwd`（真实路径）、`timestamp`。
- 实现方式：启动后轮询当天和启动当天的目录，按“cwd 相同、时间不早于启动时刻减 2 秒、ID 未被认领”筛选，取最早的一条；见 `src/shared/codex-session.ts`，有单测覆盖。
- Codex 没有信任弹窗。

### P5 密钥存储

- 采用 Electron `safeStorage`（与 Yoda 相同）：主密钥由 macOS Keychain 托管，存在名为“SmartDD Safe Storage”的条目里；SQLite 中只存 base64 密文。
- 探针在写入后先做 WAL checkpoint，再直接读取数据库文件搜索原文，确认没有明文。
- safeStorage 不可用时直接抛错，不会降级成明文。

### P7 环境变量注入

- 终端统一用 `$SHELL -l -i -c 'exec "$0" "$@"' <cmd> <args...>` 启动：既能拿到用户终端的 PATH（从 Finder 启动时 PATH 很短），又能绕开 shell 的 alias 和函数。
- 登录 shell 里可以找到 `~/.local/bin/claude` 和 `~/.local/bin/codex`。

## 3. 打包相关的坑

| 问题 | 现象 | 处理 |
| --- | --- | --- |
| GitHub 不可达 | Electron 二进制下载失败（`fetch failed`） | 用 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` 安装；electron-builder 配置 `electronDist: node_modules/electron/dist`，打包时不再重复下载 |
| 自动签名卡死 | electron-builder 自动选中钥匙串里的 Apple Development 证书，`codesign --timestamp` 卡住超过 10 分钟 | 自用阶段设置 `mac.identity: null` 跳过签名，打包只要 3 秒左右。分发前再处理签名和公证 |

## 4. 密钥方案（已确认采用 safeStorage）

PRD 原来的写法是“每条密钥写一条 Keychain 条目，SQLite 只存凭据引用”。M0 验证的是 safeStorage 方案，两者对比如下。用户已于 2026-10-14 确认采用 safeStorage，PRD 已同步修改。

| | 逐条写 Keychain | safeStorage（建议） |
| --- | --- | --- |
| SQLite 内容 | 条目标识 | 密文 |
| Keychain 条目数 | 每个密钥一条 | 整个应用一条主密钥 |
| 授权弹窗 | 每个条目都可能弹 | 只针对主密钥 |
| 需要的依赖 | 额外原生模块或调用 `security` 命令 | Electron 内置 |
| 是否满足 V6（库中无明文） | 满足 | 满足（已验证） |

如果确认采用 safeStorage，需要把 PRD 中“凭据引用”的定义和 F09 的表述改为“SQLite 存密文，主密钥由 Keychain 托管”。
