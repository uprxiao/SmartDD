## 2. 各探针细节

### P1 原生模块

- `pnpm.onlyBuiltDependencies` 放行 better-sqlite3、node-pty、electron、esbuild；postinstall 执行 `electron-rebuild -f --only=better-sqlite3,node-pty`。
- 重建后的二进制按 Electron 的 ABI 编译，普通 Node 下的 vitest 无法加载，所以 M0 时**单元测试只覆盖纯逻辑**，原生模块交给 Electron 探针验证。（M1 起 `pnpm test` 改用 `ELECTRON_RUN_AS_NODE=1 electron` 运行 vitest，单元测试已能直接覆盖 SQLite，见 `M1_骨架说明.md`。）
- Node 22.23.1 能完成安装和构建（Yoda 要求 Node ≥24，这里没有强制）。
- 打包后的 `.node` 文件和 node-pty 的 `spawn-helper` 被 electron-builder 自动从 asar 中解包，打包产物中 PTY 执行成功。

### P2 Claude Code

- 会话文件路径：`~/.claude/projects/<真实路径编码>/<sid>.jsonl`。路径会先做 realpath，例如 `/tmp` 会解析为 `/private/tmp`。
- 在新目录首次以交互模式启动时，会弹出“Quick safety check… Yes, I trust this folder”，默认选中的是“No, exit”。**Desktop 不代答**，由用户在内嵌终端中自己确认。
- 交互模式（已验证，脚本 `scripts/m0/p2_interactive_session.py`）：用伪终端模拟 SmartDD 的启动方式（`env -i` 干净环境 + 登录 shell 包装），在一个已信任的目录里启动 `claude --session-id <uuid>`。刚启动时会话文件**不存在**；发出第一条消息后，`<uuid>.jsonl` 出现，文件内 `sessionId` 与指定值一致。脚本遇到信任弹窗即中止，不代答。
- 由此带来的约束：拉起后没发过消息就关掉的 Claude 会话，`--resume` 会找不到文件。再次打开时应沿用原 ID 用 `--session-id` 新开。
- 目录编码规则是把非字母数字的字符（包括中文）都替换成 `-`，例如 `101.验证` 编码为 `101---`，不同目录可能编码成同一个名字。SmartDD 按 session ID 在 `~/.claude/projects/*/` 下查找，不依赖编码规则。

### P4 跨 AI 配置 resume

- 两个命令都在 `env -i` 起的干净登录 shell 中执行，避免继承当前进程里的 `ANTHROPIC_*` 变量。
- 方向 A：`cdsh -p --session-id A` 新建（模型 `deepseek-flash`）→ `claude -p --resume A` 继续（模型 `anthropic/claude-opus-4.6`）。方向 B 反过来。两个方向的会话里都有对方模型产生的 thinking 块，恢复时均未报错，并且答对了上一轮的暗号和算式。
- 对照：没有历史的新会话回答“不知道”；该目录的记忆目录为空，说明答案来自会话历史，而不是 Claude 的记忆文件。
- 第一次测试时提示词里用了“记住”，触发了 Claude 写记忆文件，结果作废后才改成上面的方式。今后做“能否答出上下文”这类测试，要明确禁止写记忆，并检查记忆目录。
- 局限：`claude` 这套配置的模型名形如 `anthropic/claude-opus-4.6`，像是经过中转服务，未覆盖直连 Anthropic 官方 API 的情况；Codex 没有多套配置，未测。

### P3 Codex

- `codex exec --json` 的 `thread.started` 事件会给出 `thread_id`；`codex exec resume <id>` 能接上上下文。
- 交互 TUI 启动时不生成 rollout，**第一条用户消息之后**才写入 `~/.codex/sessions/YYYY/MM/DD/rollout-<时间>-<uuid>.jsonl`。文件首行 `type=session_meta`，payload 中有 `id`、`cwd`（真实路径）、`timestamp`。
- 实现方式：启动后轮询当天和启动当天的目录，按“cwd 相同、时间不早于启动时刻减 2 秒、ID 未被认领”筛选，取最早的一条；见 `src/shared/codex-session.ts`，有单测覆盖。
- Codex 没有信任弹窗。

### P5 密钥存储

- 采用 Electron `safeStorage`（与 Yoda 相同）：主密钥由 macOS Keychain 托管，存在名为“SmartDD Safe Storage”的条目里；SQLite 中只存 base64 密文。
- 探针在写入后先做 WAL checkpoint，再直接读取数据库文件搜索原文，确认没有明文。
- safeStorage 不可用时直接抛错，不会降级成明文。

### P6 / P8 Skill 与 MCP 装载

测试素材在 `/tmp/smartdd-probe`：一个只含 `smartdd-probe` Skill 的插件（正文写有暗号），以及一个用 node 内联实现的 stdio MCP（工具 `smartdd_secret` 返回暗号）。判定标准是 CLI 能说出暗号，并要求它不去读文件。每种方式都做了不注入的对照。

| | Claude Code 2.1.280 | codex-cli 0.162.1 |
| --- | --- | --- |
| Skill 默认扫描位置 | `~/.claude/skills`、项目 `.claude/skills`、已安装插件 | `~/.codex/skills`、`~/.agents/skills`（`$HOME` 下）、项目 `.agents/skills` |
| 按会话添加 Skill | ✅ `--plugin-dir <目录>`：目录内需有 `.claude-plugin/plugin.json` 和 `skills/<名称>/SKILL.md`；Skill 名带插件前缀，如 `smartdd:smartdd-probe`。对照组（不带该参数）看不到 | ❌ 没有对应参数。`-c skills.config=[{path,enabled}]` 只能开关已发现的 Skill，不能新增路径；插件要经 marketplace 安装，属于全局操作 |
| 按会话停用 Skill | 不装载即可 | ✅ `-c 'skills.config=[{path="<SKILL.md 路径>",enabled=false}]'`，实测停用后列表中不再出现 |
| 按会话注入 MCP | ✅ `--mcp-config <json> --strict-mcp-config`（strict 表示忽略其他来源的 MCP） | ✅ `-c mcp_servers.<名称>.command=…` `-c mcp_servers.<名称>.args=[…]` |
| SVN 污染 | AIS 工作副本中运行，前后 `svn status`（1055 项）无差异，目录下没有新文件，已有的 `.claude/settings.local.json` 未被改动 | 同左 |

结论与建议：

- **Claude**：内置 Skill 打成插件放在 Desktop 数据目录，拉起时传 `--plugin-dir`；MCP 用 `--mcp-config`。全部是会话级，不改全局配置，也不写代码目录。
- **Codex**：Skill 只能落在用户级目录。建议投影到 `~/.agents/skills/`，对该项目未启用的 Skill 用 `-c skills.config` 按会话停用；投影时只增减 Desktop 自己的 Skill，不动用户已有的目录。这会在用户级目录留下文件，在终端里直接用 Codex 时也能看到；**用户已于 2026-10-14 确认采用**。另一条路是给 Codex 会话单独设 `CODEX_HOME`，但登录状态、会话记录和配置会跟着分家，代价更大，不推荐。
- `codex exec` 在非 Git 目录下要加 `--skip-git-repo-check`；交互模式不受影响。
- Claude 的 `--allowedTools` 接收多个值，放在 prompt 前面会把 prompt 吞掉；拼参数时 prompt 放在最前，或用 `--` 隔开。
- 测试 Codex 用户级目录时，为了不碰真实的 `~/.agents/skills`，临时设置了 `HOME=/tmp/...`，同时让 `CODEX_HOME` 仍指向真实目录；这只是测试手段，不作为产品方案。

### P7 环境变量注入

- 终端统一用 `$SHELL -l -i -c 'exec "$0" "$@"' <cmd> <args...>` 启动：既能拿到用户终端的 PATH（从 Finder 启动时 PATH 很短），又能绕开 shell 的 alias 和函数。
- 登录 shell 里可以找到 `~/.local/bin/claude` 和 `~/.local/bin/codex`。

## 3. 打包相关的坑

| 问题 | 现象 | 处理 |
| --- | --- | --- |
| GitHub 不可达 | Electron 二进制下载失败（`fetch failed`） | 用 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` 安装；electron-builder 配置 `electronDist: node_modules/electron/dist`，打包时不再重复下载 |
| 自动签名卡死 | electron-builder 自动选中钥匙串里的 Apple Development 证书，`codesign --timestamp` 卡住超过 10 分钟 | 自用阶段设置 `mac.identity: null` 跳过签名，打包只要 3 秒左右。分发前再处理签名和公证 |

## 4. 密钥方案（已确认采用 safeStorage）

PRD 原来的写法是“每条密钥写一条 Keychain 条目，SQLite 只存凭据引用”。M0 验证的是 safeStorage 方案，两者对比如下。用户已于 2026-10-14 确认采用 safeStorage，PRD 已同步修改。

| | 逐条写 Keychain | safeStorage（建议） |
| --- | --- | --- |
| SQLite 内容 | 条目标识 | 密文 |
| Keychain 条目数 | 每个密钥一条 | 整个应用一条主密钥 |
| 授权弹窗 | 每个条目都可能弹 | 只针对主密钥 |
| 需要的依赖 | 额外原生模块或调用 `security` 命令 | Electron 内置 |
| 是否满足 V6（库中无明文） | 满足 | 满足（已验证） |

PRD 中“凭据引用”的定义和 F09 已改为“SQLite 存密文，主密钥由 Keychain 托管”。

## 5. 竞品 Yoda 对照

源码版本：lovstudio/yoda v0.20.3（960fd32），本地只读副本位于 `~/Documents/ChatGPT/yoda`（不在本仓库内）。

### 5.1 信任弹窗

- Yoda 在启动 CLI 之前**预先写入信任**（`src/main/core/agent-hooks/claude-trust-service.ts`、`codex-trust-service.ts`）：
  - Claude：在 `~/.claude.json` 的 `projects[目录]` 中写入 `hasTrustDialogAccepted: true` 和 `hasCompletedProjectOnboarding: true`。
  - Codex：在 `~/.codex/config.toml` 的 `[projects."目录"]` 中写入 `trust_level = "trusted"`。
- 由设置项 `autoTrustWorktrees` 控制，默认开启。
- 写法：按文件串行加锁，先写临时文件再 rename；原文件损坏或根节点不是对象时放弃写入，只记日志。
- 不足：路径只做 `path.resolve`，不做 realpath；Claude 运行时也会改写 `~/.claude.json`，两边并发写可能互相覆盖。

### 5.2 session ID 与恢复

| | Yoda | SmartDD（M0） |
| --- | --- | --- |
| Claude 新建 | `--session-id <uuid>`，uuid 由 Yoda 会话 ID 推算，结果固定 | `--session-id`，随机生成 |
| Claude 恢复 | `--resume <id>` | 相同 |
| Codex 新建 | 每秒轮询 `<CODEX_HOME>/state_5.sqlite` 的 `threads` 表，按 cwd 和创建时间窗口匹配，并比对首条用户消息确认归属，最长等 5 分钟（`src/main/core/session-title/codex-title-source.ts`） | 轮询 rollout 文件首行，按 cwd 和启动时间匹配 |
| Codex 恢复 | `codex resume --cd <目录> <id>` | `codex resume <id>` |

### 5.3 跨 AI 配置

- Yoda 给每个会话记录会话文件所在目录（`stateRoot`，即 `CLAUDE_CONFIG_DIR` 或 `CODEX_HOME`），恢复时注入同一目录（`src/main/core/conversations/session-state-roots.ts`），还会自动发现 profile 子目录。
- 模型和账号切换由 MaaS 模块负责：Claude 通过改写 `~/.claude/settings.json` 的 `ANTHROPIC_*` 字段实现，改写前做快照、可以回滚，密钥存放在 safeStorage。这是**全局切换**，没有“每个会话各自选一套配置”。MaaS 只读了入口文件，完整流程未细读。
- Yoda 没有回答“换模型后能否接着恢复同一会话”（例如 Claude 的思考块带签名，换成 DeepSeek 后可能报错）；SmartDD 已在 P4 实测 CDSH 与 claude 互相恢复可用。

### 5.4 采纳到后续里程碑的待办

| 待办 | 里程碑 | 说明 |
| --- | --- | --- |
| 预先信任目录 | M2（添加项目时） | 由用户勾选“信任此目录”，不默认开启；路径先做 realpath；只在启动前改写目标目录这一项，并保留原子写和损坏保护 |
