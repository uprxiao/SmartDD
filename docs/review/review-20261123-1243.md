# Review Report

## 摘要

在 `feature/0.1.7`（`e7fc5f57ffc4`）对照 F35-R1～R5、已评审的原型、专项实验和 M13／M14 既有规则，逐条评审 A0.2 的 29 条验收用例。覆盖范围合理，A14 的原生错误正反对照、A23 的目录别名、A27～A29 的真实网关验收值得保留。建议先修订会误判通过的条目，再确认用例定稿和开发范围。[A0.2](../F35_Antigravity测试用例.md) · [需求与实验](../F35_Antigravity验证与评审.md)

## 修改建议

- **H1**。同一供应商下让 Carbon 完成工具回合，Argon 只通过目录和文本，逐格断言可用、不可用和未测试。分别变更 Key、端点并验证旧结果失效，旧在途回执不得覆盖新修订。
- **H2**。从 F35 之前的 M14 统一任务数据开始。原任务先持有随机标记，切到 Antigravity 后只提问、不重发标记，要求续答引用该标记。Antigravity 回合产生新标记，切回时核对原 `sessionId`、新增上下文只补一次以及任务 ID、原历史、草稿和目录保留。Codex、Claude Code 各一条。
- **H3**。让共用目录的父任务持续持有写入权。Antigravity 请求只读时，回执应解释有效访问按写入调度，父释放前子不启动且磁盘无变化。旧修订请求创建零子任务，刷新后的有效请求重试返回同一收据，实际启动和首次回收均为一次。
- **H4**。在同一树内准备活动子任务、排队子任务和待审批子任务，从父界面停止子树，同时保留一条独立任务作对照。另起一树做非正常重启，保留一条已投递和一条等待投递的结果，验证前者不重复、后者不丢。已执行但接收未知的写入核对原回执和磁盘，恢复后同会话新运行能发起一次合法操作。
- **H5**。A27 和 A28 统一要求同一份受控真实请求合同，记录目标模型、档位、实际发送的输出上限和流式回执，并核对真实工具产生的唯一标记出现在工具回传后的回答及追问里。稳定性的复跑次数与超时预算单独约定。A29 用一款已通过的 Gemini 模型执行既定的两组切换和四个委派方向，逐项记录六个动作。只有 A27、A28 均通过且 A29 六个动作均通过，真实网关链路才完成。
- **M1**。在同一个任务用真实 `agy` 走 Carbon → Argon → Carbon，核对每轮实际模型、档位和上下文。用目录仍有旧档位、当前 ACP 会话已移除该档位的夹具验证选模型后按原生选项校验。若缺少有效选择和原生默认，写清界面反馈及参数处理，并检查失效值未发出。另测同一逻辑任务切换两份允许的来源，重启后各续原会话和各自标记。
- **M2**。拆成目标与队列两个子场景，并给 A14 建异常矩阵。目标存在时验证同配置换模型仍可操作，跨执行器或供应商被拦，清除目标且在途回合排空后可切。启动中排两条不同标记，核对归属、顺序、次数。记录已知失败、已知取消、接收未知各自终态，接收未知先查原记录且零自动重发。强制停止按既有时间门槛和原运行身份取证。
- **M3**。给已取消或已失效的 ACP 原生审批明确标注来源和任务、运行、请求修订，在父面板验证来源后处理。单列宿主业务请求的 I 层对照，按是否被取消、内容和权限是否仍有效确认拒绝或重新核验后执行。重放、拒绝和跨任务均核对回执及文件。
- **M4**。保持父回合忙，令第一子完成，确认父端投递数为零。父空闲后收一次，追问复用原子任务及会话。保持第二子活动，关闭新委派后实际尝试再派，新增任务为零，第二子仍能收口。用子任务尝试委派覆盖既有深度限制。
- **M5**。父子各写独立标记。合并前分别核对父 HEAD、父原有未提交内容及本轮允许的父改动，确认父目录无子标记、工作副本无父未提交标记，且只有子分支有宿主自动提交。
- **M6**。父回合结束后仍保持一个在途工具操作，核对子仍等待且磁盘无变化。工具完成、父释放后，子收到重读提示并能读到父最后的改动。把已进入「等待你批准」的持久业务请求用作不占写入权的对照。子完成后，父重获写入权并读取实际文件。
- **L1～L3**。优先在现有 29 条内加子场景和必判结果，引用 M13／M14 具体用例，沿用一个隔离验收包和同一套驱动。A04 从已保存 Key 的 Model Hub 开始，并各跑一条原有 Anthropic、Responses 样本。A06 分别测默认不含 Key 的导出和显式加密导出，核对同名不覆盖、错口令无落盘，导入后 Gemini 地址和模型可用。A17～A20 固定由真实父执行器的宿主 MCP 调用发起委派，按回执、子进程和父时间线取证。A26 继续承担升级回归。

## 风险与待确认点

- 当前真实网关预研中，Carbon 完整请求返回渠道错误，Argon 完整回合超时。两款模型的真实回合仍缺通过证据。打包 App 的 29 条用例均未执行。以当前范围推进正式开发前，应明确上游复验是否为前置。如果确认分批实施，仍按原要求记录 G05 上游阻塞与完整验收缺项。[专项结果](../F35_Antigravity验证与评审.md#开发前专项实验结论) · [评审顺序](../F35_Antigravity测试用例.md#评审与执行顺序)
- 会话可能发起辅助模型请求。验收应把实际外发模型及次数纳入证据，继续使用获准模型和测试数据。辅助模型支持范围和超时标准仍需确认。个人 Google 登录沿用后续安排。[F35 实验约束](../F35_Antigravity验证与评审.md#评审规则)
- 本报告评审用例及既有证据。当前产品测试状态仍以用例表和后续真实 App 执行记录为准。
