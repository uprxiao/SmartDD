## 2. 问题清单

以下未决项按影响阶段列出，避免将“可以开始S1”误解为“方案已全部验证通过”。

### 中｜S1的核心保证仍需真实反例测试，不能直接视为已通过

[需求R03.2](../里程碑/M12_浏览器自动化/需求.md:373)增加持有节点对象的隔离环境动作守卫；E4e两次屏幕内原始结果均显示：原按钮可点击，克隆按钮点击被拦、克隆输入框保持空值。原生helper仍报告成功，宿主必须核查守卫记录。

但E4e仅使用全局CDP和直接宿主客户端，不是最终每页代理。更早注册的窗口捕获监听器、快照A→B→A、跨站iframe／封闭Shadow、动作已经产生部分效果后才被拦截等边界，仍须由[T051](../里程碑/M12_浏览器自动化/验收/测试用例.md:90)及退出码／回执测试判定。当前不能承诺所有拦截均“页面完全未收到事件、未开始”。

这不阻止开发S1，因为S1正是实现并验证这些核心契约；若红测失败，应调整实现路径后复验，不能仅登记“已知限制”就通过门槛。

### 中｜后备路径“失败即列Skill限制”仍与保留范围的要求冲突

[技术方案后备路径](../里程碑/M12_浏览器自动化/技研/技术方案.md:171)仍写红测不过就在Skill列已知限制；[需求R03.2](../里程碑/M12_浏览器自动化/需求.md:380)已明确不能据此缩小R03.3的跨站iframe／封闭Shadow覆盖范围。实施应按需求执行：失败时修方案，涉及缩小范围须另行确认。该文字应同步，不能作为放行S1的豁免。

### 低｜Cookie卸载方案需要在S4前补齐后台写入与请求排空验证

R1.2已把事件来源归因方案改为导入期间卸载相关页面、取消该分区请求，并提示未保存内容丢失。规则变更已由当前阶段文档登记为用户确认。[技术方案](../里程碑/M12_浏览器自动化/技研/技术方案.md:218)仍明确保留无页面／无网络Service Worker通过CookieStore写入的边界；取消新请求也不能直接当作已证明所有在途响应均已排空。

因此，上轮Cookie问题已通过改变规则规避原归因难题，但**导入与恢复的最终隔离性还没有实测证明**。S4实现前需定义后台写入、在途Set-Cookie、页面与子窗口卸载完成、失败恢复顺序的判据。[T081](../里程碑/M12_浏览器自动化/验收/测试用例.md:129)已覆盖页面卸载、脚本计数、重启恢复与“需要处理”入口；上述后台边界需补具体负例。它不阻塞不含Cookie导入的S1。

### 低｜状态摘要与旧故障注入文字尚有残留

- 阶段README标题已为“已批准开发，仅S1”，产物表仍写需求“待评审”、原型“用户评审中”。应区分已确认基线与尚未执行的生产验收。

这些文字不构成S1技术阻塞，不应因它们再次退回整个需求设计阶段。

## 3. 修改建议

按下面顺序推进，沿用当前feature/0.1.1，不另建版本分支：

1. 固定R1.2及S1起点的可恢复基线，保留已有未提交改动；完成时按项目规则只提交本阶段范围。
2. 先实现最小闭环：页面注册表、WebContentsView、停放与挂回、每页CDP代理、helper执行器、引用与动作守卫、前置／执行边界、operation回执和大结果文件。命令先做S1列出的9条。
3. 先攻T051／T053／T112：错节点零误点、跨站与封闭Shadow、代理目标隔离；同时落实错误码及effectState，出现已生效部分时不能一律标成未开始。
4. 完成其余S1门槛：取消、同页串行／跨页并行、helper重建、后台点击实际生效与耗时、长输入块内中断、整页截图、真实Codex读取大结果文件。
5. 每项保留原始输出和独立判定；全部门槛通过后，再按阶段记录进入S2–S6的后续确认。Cookie最终隔离验证安排在S4，不能拿E4e的冻结失败或原型演示代替。
