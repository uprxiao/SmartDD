## 2. 问题清单

### 中优先级

### U01：超限正文仍直接舍弃尾部，与“转 artifact、保留可继续读取来源”的合同不一致

阶段 2；关联 R01／R04、技术方案 §3.1、A45。代码：[itemJson](../../src/main/core/agent/agent-store.ts#L31)、[条目正文读取](../../src/main/core/agent/agent-task-service.ts#L476)。

现行技术方案 §3.1 明确要求：**“超限正文转 artifact，关键请求不截断”**；R04 要求预算不足时列明可继续读取的来源。这些规则没有在本轮变更。回执也声明需求与已确认决定不变。

当前 `itemJson` 超过 1 MiB 后，截短每个长字符串，只保存部分结构、字节数和摘要，没有保存可读取的原文引用。`itemBody` 再读取的仍是截短后的 JSON。因此“显示开头并禁止复制”修好了误报成功，但不能代替原定的超限正文保留合同。

容量反例写入一条新的合成回答，原文 **1,228,816 bytes**；通过实际正文分段 API 读回时，`text` 只剩 **131,072 bytes**，尾部不存在，返回对象只有 `text/model/storedTruncated/bytes/sha256`，没有原文引用。这是新正文的保存／读取测试，不是要求恢复旧版本已经丢掉的数据，也没有宣称真实模型执行了这次超长输出。

证据：[反例 U01a](evidence-20261117-2354/retention.test.tsx#L61)、[观察值 U01a](evidence-20261117-2354/retention-observations.json)。

上轮 T02 的具体关闭条件着重约 600 KiB 的限内计划和残缺内容不能复制。本轮补查确认，更大的正文仍需满足已有 artifact 合同；这里不是新增存储需求，也不应通过修改现行文档来追认舍弃尾部。

应按既定方案保存完整正文／artifact，并让条目持有受任务与修订约束的引用，可按范围继续读取。预览可以截短，原文不能仅剩摘要。现有旧残缺记录仍需保留明确的不可恢复提示，不要求凭空恢复不存在的正文。

### U02：不完整提示只接入普通条目，工作过程展开后仍无提示

阶段 2；关联 R01 工作过程可查看、A45 容量降级可辨识，也与本轮回执“条目上标明只保留开头”不一致。

代码：[普通条目的不完整提示](../../src/renderer/features/agent-tasks/agent-task-view.tsx#L134)、[WorkItem](../../src/renderer/features/agent-tasks/agent-task-view.tsx#L149)。

`ItemRow` 检查 `isIncomplete(p)`，但思考、工具等工作过程使用 `WorkItem`，只判断预览是否需要“展开全文”。读取到 `storedTruncated:true` 的部分正文后，缓存变为有效、展开按钮消失，`WorkItem` 没有显示不完整提示。

实际组件与存储反例：一条超限思考正文展开后，尾部不可见、不完整提示不可见，继续读取的展开按钮也已经消失。观察值为 `completeTailVisible:false`、`incompleteWarningVisible:false`、`expandStillAvailable:false`。界面呈现为已经展开完毕的正文，用户无法知道后半部分缺失。

证据：[反例 U01b](evidence-20261117-2354/retention.test.tsx#L74)、[观察值 U01b](evidence-20261117-2354/retention-observations.json)。本轮直接验证的是思考条目；其他工作条目复用同一个组件。

应统一普通条目和工作条目的完整性展示。若可从 artifact 获取全文，应保留相应读取入口；对于旧记录或读取失败导致的残缺内容，必须明确提示不能完整恢复。即使 U01 修好，旧的部分记录仍需要这一展示保护。
