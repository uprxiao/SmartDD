## 问题清单

### 高：G01　来源字面参数可冒充宿主 `@WYARG:` 指令，读到另一 MCP 的 Key

依据：[生成器第 27–33 行](../里程碑/M13_应用Skill与MCP插件化重构/技研/实验/B_审核二修正_20261110/b3-emit-v2.mjs)、[包装器第 21 行](../里程碑/M13_应用Skill与MCP插件化重构/技研/实验/B_审核二修正_20261110/wy-mcp-launch.sh)。

生成器只把含 `$` 或模板类型的参数放入私有槽，其余字面参数直接传递；包装器却将所有以 `@WYARG:` 开头的参数解释为环境变量引用。二者没有区分“来源数据”与“宿主生成的控制标记”。

本轮反例：

1. MCP alpha 明确配置自己的 `API_KEY=decoy-alpha-key`，生成器分配 `WY_MCPV_1`。
2. MCP beta 没有该凭据，只配置一个应原样传递的字面参数 `@WYARG:WY_MCPV_1`。
3. 按 Claude 目标的投影方式，将生成器返回的 `add` 放入父进程环境，运行生成的 beta 包装命令。
4. beta 实际 argv 为 `["decoy-alpha-key"]`，退出码 0。它本应收到 `["@WYARG:WY_MCPV_1"]`。

这是实际运行生成器＋包装器的结果，未补真实 Claude 整链路；Claude 目标共用父进程槽环境的机制已经使包装器能够取到该值。它既破坏源参数语义，也破坏不同 MCP 的凭据边界。只在 exec 前清除私有槽不足以保护，因为泄露已发生在参数替换阶段。不存在真实 Key 暴露，本例全是诱饵。

建议：将所有来源参数作为数据编码，或至少对来源中以 `@WYARG:` 开头的字面参数再次封装成宿主私有槽，使包装器只解引用一次并原样传递槽里的数据；控制标记只能由生成器产生。添加同名标记、未知标记、两 MCP 不同 Key 的隔离回归；beta 不得得到 alpha 的值，也不能因本应字面传递的标记而报缺变量。

证据：[可执行探针](证据/M13-20261110-1744/literal-marker-probe.mjs)、[实际参数结果](证据/M13-20261110-1744/literal-marker-probe.mjs.stdout.json)。这项是新问题，不代表 F03 同名 Key 修复失败。

### 中：G02　现有还原是“检查后原子替换”，不满足原子 CAS／绝不覆盖并发修改

依据：[B4 第 39–43 行](../里程碑/M13_应用Skill与MCP插件化重构/技研/实验/B_审核二修正_20261110/b4-toml-restore.mjs)、[技术方案 §3.4](../里程碑/M13_应用Skill与MCP插件化重构/技研/技术方案.md)、[需求第 71 行](../里程碑/M13_应用Skill与MCP插件化重构/需求.md)。

合法 TOML、单引号／注释、多行拒绝、编辑前变更检测等原问题已经修好，B4 十个判据复跑通过。这里不重复否定这些结果。

但先读哈希、再 `rename` 不是操作系统原子比较交换：另一程序可以在最后一次哈希校验后保存文件，然后被替换掉。技术方案已诚实注明这一窗口，但仍称“文件级比较并交换”；需求仍承诺“不覆盖用户并发修改”，未同步限制或说明用户接受了该取舍。

本轮用确定性故障注入验证：只在本测试进程的 `renameSync` 入口、真正执行 rename 前，向临时 config 添加 `external_user_change=true`。`restoreFile` 返回 `{ok:true}`，结果文件丢失该外部新增项。没有碰真实配置；这不测自然并发发生概率，只验证所承诺的保证不成立。

建议：不再把该算法称为原子 CAS。如果保留最佳努力写回，需把已知限制、交互提示及验收边界同步到唯一需求并在评审确认；若必须保持“绝不覆盖其他 CLI 并发写入”的强保证，应采用能与所有写入者协调的机制，或避免自动覆盖全局文件。继续增加检查次数、只用临时文件 rename，均不能消除这个窗口。

证据：[故障注入脚本](证据/M13-20261110-1744/cas-window-probe.mjs)、[返回成功但外部修改丢失](证据/M13-20261110-1744/cas-window-probe.mjs.stdout.json)。这是方案已列出的限制与需求未对齐，不是隐藏的新发现。
