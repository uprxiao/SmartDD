### 高：CLI 身份续租与 main 的逐调用即时授权口径不同

main 的 `CurrentApplicationAuthorization` 明确要求：运行令牌只证明调用者身份，应用权限由每次调用时的项目当前设置决定，启动时没有启用应用也可签发可用的 CLI 身份。feature 的 `cli-gateway.ts` 新增固定 `planHash`、`authorizationStamp`、`ttlMs` 与运行期续租，同时其 issue 分支仍检查启动计划含 CLI allowed 能力。这正是试合并中 `Binding` 与 issue 逻辑发生冲突的位置。

以下为基于两侧源码的合并风险判断，尚非已解决合并代码的运行结果：若简单选 feature 一边，可能退回启动快照限制，影响 main 的“开启应用立即可用”规则；若简单选 main 一边，会丢失 M12 已验证的长运行续租、授权变化／停止撤销等保护。应将 M12 续租接到 main 的当前授权视图上，不能以取消任一权限判断来消掉冲突。

依据：[main 当前授权实现](https://github.com/uprxiao/SmartDD/blob/8914e6882fcbc1bd075fc97ccbba9097e90cfa0e/src/main/core/applications/current-authorization.ts#L12)、[feature CLI 网关](https://github.com/uprxiao/SmartDD/blob/a3aed53d4591087a05f17f091b09d7bc8a592eff/src/main/core/applications/cli-gateway.ts#L14)。

### 高：启动与 Skill 交付已改为新架构，不能整文件回退

main 的启动器使用 `CurrentApplicationAuthorization`、`SkillLibraryService` 和新 `configureCli` 流程，并清理旧 Skill 副本／旧启动资源；feature 在旧启动链上增加了浏览器发现、CLI 沙箱 profile 参数适配等逻辑。`task-capability-launcher.ts` 有 3 块冲突，另有不少代码由 Git 自动合并。

`src/main/index.ts` 同一处同时涉及 main 的 Skill 库同步回调和 feature 的 `BrowserService` 创建／注入；两者都要保留，不能选一边覆盖。合并后还要核对 CLI 运行中的 shell 快照保护、恢复／停止及沙箱／审批边界实际落到了新启动路径。

依据：[main 启动器](https://github.com/uprxiao/SmartDD/blob/8914e6882fcbc1bd075fc97ccbba9097e90cfa0e/src/main/core/applications/task-capability-launcher.ts#L24)、[feature 启动器](https://github.com/uprxiao/SmartDD/blob/a3aed53d4591087a05f17f091b09d7bc8a592eff/src/main/core/applications/task-capability-launcher.ts#L348)、[feature 初始化](https://github.com/uprxiao/SmartDD/blob/a3aed53d4591087a05f17f091b09d7bc8a592eff/src/main/index.ts#L200)。

### 中：旧授权函数已在 main 删除，冲突侧仍引用它

main 已删除 `src/main/core/applications/application-run-scope.ts`；feature 的 `tool-service.ts` 仍调用其中的 `assertRunApplication`。试合并结果中该文件不存在，而 tool-service 的冲突侧还保留该调用，不能单纯选中这段便认为完成适配。要按 main 当前授权机制确认浏览器等无连接模块的授权与回执检查。

## 修改建议

1. 先在隔离整合分支／worktree 解决 10 个文件的冲突，以 main 的 M11 R1.0 当前架构为基础接入 M12 的浏览器、CLI 续租、沙箱适配与缓存保护；保留两边有效测试。
2. 逐项对照上面的授权、启动器、BrowserService 初始化、错误码及文档规则；复查 Git 自动合并的共享链路，不仅删除冲突标记。
3. 对整合结果跑类型检查及 M11/M12 受影响的单元／集成测试，再补真实打包 App 与 CLI 的启动、恢复、停止、即时开关应用、无应用／无浏览器授权、续租和快照保护回归。UI 及源码未受影响的已绿矩阵按原哈希／适用范围复用，不因一次合并重跑全部视觉矩阵。
4. 整合分支验证完成再合 main；核验最终 main 提交并准备版本元数据，随后按约定打 `v0.1.3`、推 tag、等待 GitHub Actions、核对 Release。实际合并、版本号与打 tag 仍待用户后续决定。
