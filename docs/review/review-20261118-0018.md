## 2. 问题清单

### 中优先级

### V01：结构化正文无法压缩预览时，artifact 已写出但引用被丢掉

阶段 2；关联技术方案 §3.1、R01、A45。代码：[shortenedJson](../../src/main/core/agent/agent-store.ts#L35)、[artifact 写入及引用生成](../../src/main/core/agent/agent-store.ts#L76)。

`shortenedJson` 只截短长字符串，不减少数组项或对象字段。由大量短字段构成的正文，即使多次缩短字符串也可能无法进入 256 KiB 预览预算。此时文件已经成功写出并改名，但 `ref` 为 null，代码继续降级为无 artifact 引用的截断记录；事务提交后文件也不会被清理。

反例通过实际 Codex MCP 工具结果投影输入 **60,000 行短字段**，原结果约 **1,728,948 bytes**，低于当前 64 MiB artifact 上限。结果：

- 原文文件存在于本任务目录。
- 数据库正文只有 `truncated/bytes/sha256/head`，没有 artifact 引用。
- 正文 API 读不到结果行，原文件成为不可访问的孤儿文件。

证据：[A01](evidence-20261118-0018/artifact-boundaries.test.ts#L29)、[观察值 A01](evidence-20261118-0018/artifact-boundary-observations.json)。夹具已按固定 Codex 0.169.0 [MCP 结果协议](evidence-20261118-0018/Codex-0.169.0-McpToolCallResult.txt)补齐必需字段，不依赖尚未实施的 WillYou 业务桥。

应将完整原文引用与可选预览分开：预览无法缩小时，仍返回一个足够小的引用／摘要，而不是丢掉已成功保存的原文。没有被数据库引用的本次写入，也应按失败／降级路径清理。

### V02：用户消息的接受路径仍调用旧截短函数，没有 artifact 或等价原文读取路径

阶段 2；关联 R01 整份输入冻结与历史读取、R04、A45。代码：[acceptTurn](../../src/main/core/agent/agent-store.ts#L229)、[用户消息入库](../../src/main/core/agent/agent-store.ts#L243)。

原生条目 `upsertItem` 与宿主条目 `addHostItem` 已接入新的 artifact 事务，但本地接受用户消息仍直接调用 `itemJson`。合法的 256 KiB 原始文字，在 JSON 转义后可以超过 1 MiB，因此不能按原始文字长度判断历史条目永远不需要 artifact。

反例使用与本轮草稿回归同类的控制字符边界：原始文字 **262,144 bytes**，序列化后 **1,572,875 bytes**。输入成功接受，`agent_turns.input_ref` 保留全部 **262,144 个字符**；时间线正文 API 却只读到 **131,072 个字符**，标不完整，artifact 目录都没有创建。

证据：[A02](evidence-20261118-0018/artifact-boundaries.test.ts#L40)、[观察值 A02](evidence-20261118-0018/artifact-boundary-observations.json)。这是输入长度与编码边界验证，不是普通业务文本样本。**原投递输入没有丢失，问题是时间线不能读回完整原消息**，不应将它描述为执行器收到了半份输入。

应让用户消息同样获得完整的历史读取路径：可以接入受事务保护的 artifact，也可以按任务／回合归属从已完整保存的输入原文重建正文，不要求重复存一份文件。保留同一 clientInputId 的幂等收据、附件冻结和事务失败清理。

### V03：文件改名失败时，已经创建的临时文件没有删除

阶段 2；关联 A45 文件故障恢复，与回执“写入中途失败不会留下残文件”不一致。

代码：[临时文件写入和改名](../../src/main/core/agent/agent-store.ts#L83)、[事务文件清理](../../src/main/core/agent/agent-store.ts#L96)。

临时路径只定义在 try 内，`written.push(file)` 又在改名成功之后。`writeFileSync` 中途失败或 `renameSync` 失败，catch 不知道要删哪个临时文件，事务清理列表也没有它。

本轮在私有临时目录中制造一个不兼容的目标目录，确定性触发第 2 修订的改名失败。代码正确降级并标记 `storedTruncated:true`，但目录里留下了约 1.1 MiB 的 `*.tmp` 文件。**降级标记是正确的，本项只要求补齐文件生命周期清理**。

证据：[A03](evidence-20261118-0018/artifact-boundaries.test.ts#L48)、[观察值 A03](evidence-20261118-0018/artifact-boundary-observations.json)。这是受控文件系统故障注入，未修改真实用户目录；测试结束后的夹具清理不计作产品清理通过。

应在创建临时文件前记录本次路径，并通过 finally／明确的失败清理处理临时文件；已改名但未最终提交或未被引用的文件也应纳入跟踪。不能仅跟踪成功改名后的最终文件。
