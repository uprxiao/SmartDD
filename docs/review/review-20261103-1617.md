## 2. 问题清单

### 高优先级：现有需求承诺与技术方案尚不闭合

### F01 — 节点编号可区分替换，不等于整个“引用→动作”链路已安全

**依据：**[R1.0 R03.2](../里程碑/M12_浏览器自动化/需求.md:361)、[技术方案引用身份校验](../里程碑/M12_浏览器自动化/技研/技术方案.md:155)、[E4 身份实验](../里程碑/M12_浏览器自动化/技研/实验/E4_旧引用与等待副作用与长输入/ax-identity.mjs:17)。

E4b 明确没有调用 agent-browser，只验证了静态查询中 backendDOMNodeId 在替换前后不同。方案目前仍是“helper snapshot 后再取 AX 绑定，动作前取 AX 比对，然后再让 helper 按角色／名称执行动作”，存在两处窗口：

```text
窗口一：snapshot 看见原节点 A → 页面换成同名 B → AX 绑定到 B
窗口二：AX 比对确认 A → 页面换成同名 B → helper 再定位并点击 B
```

窗口一会从一开始就把旧快照引用绑定到新节点；窗口二会使刚通过的检查与实际动作目标不同。同页命令队列只串行 Agent 命令，不能阻止网页自己的异步渲染。

所以 E4 可以支持“节点身份信号可用”，不能支持 R03.2“绝不能静默操作别的元素”已经由这一方案保证。S1 应加入两个窗口的门闩红测，明确引用从哪里获得可信身份、实际动作如何绑定已校验节点；不能在检查后又无约束地按语义重新定位。

**边界：**这是对拟实现顺序的交错反例，不是声称已复现尚不存在的宿主校验实现。

### F02 — 跨页相同 `@eN` 的来源不可区分，当前设计无法满足 T051

**依据：**[R1.0 页面隔离](../里程碑/M12_浏览器自动化/需求.md:362)、[技研按页面保存原生引用](../里程碑/M12_浏览器自动化/技研/技术方案.md:155)、[T051](../里程碑/M12_浏览器自动化/验收/测试用例.md:90)、[参数反例](review-20261103-1617-evidence/audit-r1-evidence/contract-counterexamples.json)。

T051 要求 A、B 各做 snapshot 后，把 A 的引用传给 `--page B` 也必须拒绝。但两个 helper 会话都可以产生 `@e4`。此时下面两种意图的传输参数完全相同：

```json
{"page":"B","element":"@e4"}
```

它既可以表示“合法使用 B 的 @e4”，也可以表示“误把 A 的 @e4 用到 B”。按 `(page, @eN)` 查 B 的映射，会使两种情况都验证 B 的节点。

需定义对外引用与内部 helper 引用的区别：例如宿主分配全局唯一引用，或把页面／快照代际纳入引用身份，再翻译为内部引用。引用身份还应说明 frame／CDP session／文档代际，不能只依赖一个裸节点编号。补充同页新 snapshot 后旧引用的复用测试。

### 中优先级：规则、方案与验收结果不能同时满足

### F03 — 分块完成后记账，不能保证块内中断时的精确输入字数

**依据：**[R1.0 R03.9](../里程碑/M12_浏览器自动化/需求.md:386)、[技研每块完成后写进度](../里程碑/M12_浏览器自动化/技研/技术方案.md:133)、[T060 精确相等要求](../里程碑/M12_浏览器自动化/验收/测试用例.md:99)。

例如第一块确认输入 2000 字；第二块输入了 333 字后 helper 中断。已确认进度仍为 2000，页面可能已有 2333 字。当前方案没有可靠证据把未回执的尾段精确计入，却要求回执字数与页面实际字数相等。

建议区分 `confirmedChars`、正在执行块及未知尾段；可可靠读回时，另记录观察值及读取时点。测试应分别在块边界和块中间中断，避免只在已回执边界终止后把精确性宣称覆盖全部失败。

### F04 — Cookie 恢复的“比较后再写回”仍可能覆盖期间发生的登录／登出

**依据：**[R1.0 R06.4](../里程碑/M12_浏览器自动化/需求.md:525)、[技研恢复规则与页面写不加锁](../里程碑/M12_浏览器自动化/技研/技术方案.md:194)、[交错反例](review-20261103-1617-evidence/audit-r1-evidence/contract-counterexamples.json)。

完整变更集、删除原本不存在的键、加密日志，已修正上一轮的顺序补偿和磁盘保护缺项。但“不覆盖页面期间改写的 Cookie”仍有并发窗口：

```text
恢复读到 Cookie=B，判定仍为导入值
→ 页面登出，删除 Cookie
→ 恢复操作写回旧值 A，重新带回旧登录态
```

当前值比较和恢复写入不是一个原子操作；“页面写不加锁”也未限定在仅导入阶段。需要明确恢复期间的写入隔离／冲突版本规则和可执行机制，并以这个交错补 T081。不能只测“页面先改，随后恢复”的顺序场景。

### F05 — R1.0 对 Cookie 替换粒度作了无依据的语义选择

**依据：**[历史 R05.4](../里程碑/M12_浏览器自动化/历史/需求_R0.10_20261103.md:304)、[R1.0 R05.4](../里程碑/M12_浏览器自动化/需求.md:448)、[T080](../里程碑/M12_浏览器自动化/验收/测试用例.md:126)。

旧文是“只替换导入内容里出现过的**域名**”，新文变成“只替换导入内容里出现的 **Cookie**”。旧表述本身存在歧义，不能直接当成两者等价。

需要明确同一个域名里，目标 profile 原有但来源 profile 没有的 Cookie 是否保留。按域名整体替换与按 Cookie 键合并，会得到不同登录结果。T080 只检查其他站点不变，不能区分这两种语义。若原意本就是同键更新，应记录勘误依据；若要改规则，应明确变更，不能继续宣称仅改写法。

## 3. 修改建议

建议按以下顺序集中收口，避免再次只追加补记：

1. **明确引用身份与执行机制（F01/F02）**：对外引用具有页面／快照代际；实际动作绑定已校验身份。两段竞态和同串跨页都做 S1 红测。
2. **统一失败结果（F03/F04）**：输入进度诚实区分确认与未知；Cookie 补偿明确并发隔离／冲突处理，加入检查与写回之间的交错测试。
3. **修正 R1.0 合并差异（F05–F07）**：按既有决定补回细则；Cookie 替换边界若原先有歧义，明确更正依据和同域 Cookie 场景。不要把语义选择作为排版合并悄悄完成。
4. **同步用例与原型（F08/F09）**：更新原编号的判据与夹具，补缺失 UI 状态。无需为了本报告单独新增另一份权威结果账，也无需重复已绿原型矩阵。
5. **整理导航与来源（F10）**：保留原历史证据，修导航说明；按真实覆盖结果更新合并声明。最后再核验当前稿、生成映射、用例、原型版本及哈希。

这些问题主要是执行契约和文档收口，不要求重新决定整个产品方向。最终每页代理仍应按 S1 门槛实际验证；本报告不替代用户开发授权，也不把 S1 未执行写成失败或通过。
