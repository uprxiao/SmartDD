## 2. 问题清单

### 高优先级

### D01 — 已实测：旧引用会静默点到替换后的新元素，必须启动需求中的补强分支

**依据：**[需求 R03.2](../里程碑/M12_浏览器自动化/需求.md:226)、[技研引用错误映射](../里程碑/M12_浏览器自动化/技研/技术方案.md:135)、[本轮第二次结果](review-20261103-1542-evidence/native/attempt-002/result.json)、[第三次结果](review-20261103-1542-evidence/native/attempt-003/result.json)。

独立操作：

1. 页面有 `id=original`、名称为 `Action` 的按钮，snapshot 分配 `@e7`。
2. 不重新 snapshot，使用 DOM 替换成另一个 `id=replacement`、名称仍为 `Action` 的按钮；新按钮的事件处理器写入 `replacement`。
3. 对旧 `@e7` 执行 click。

**实际：**helper 返回成功，页面专用回显为 `replacement`。两次使用正确事件处理器的独立实例均得到这个结果，没有 `Unknown ref`，所以匹配错误文字的合同测试拦不住。

这与“只能报旧引用错误或仍操作原元素、绝不静默点其他元素”直接冲突。R03.2 已明确决定“验证发现误点，再追加指纹校验”；本轮已满足触发条件。应在批量接入前明确引用身份／版本校验方案及误点红测，不能只把上述情况记录为 Skill 注意事项。

**证据边界：**这是原始 helper 的确定反例；最终 BrowserService 尚未实现，不能说正式 WillYou 已经误点。首次 attempt-001 的替换按钮 onclick 引号存在夹具错误，其 `staleEffect:none` 不作为安全性证据；原始结果保留，修正后的 attempt-002／003 才用于本结论。

### D02 — 已实测：`wait --fn` 不是只读，observe 授权和 safe-read 重试语义不成立

**依据：**[需求 R04.4](../里程碑/M12_浏览器自动化/需求.md:267)、[read 分类](../里程碑/M12_浏览器自动化/需求.md:327)、[仍把 fn 归为 read](../里程碑/M12_浏览器自动化/需求.md:330)、[observe 只拒绝写能力](../里程碑/M12_浏览器自动化/技研/技术方案.md:227)、[原生实测](review-20261103-1542-evidence/native/attempt-003/result.json)。

在页面点击计数为 0 时调用：

```javascript
wait --fn '(()=>{document.getElementById("count").click();return true})()'
```

**实际：**命令成功，计数变成 2。随后将条件改成 `return false`、超时 300ms，命令超时但计数继续增加到 6。说明条件脚本确实能执行写动作，而且一次等待期间会重复执行。

当前 P4 observe 按能力的 read/write 类别放行，因此即便拒绝 `click/eval/exec`，仍会放行这条 `wait`；`safe-read` 的自动重试也不能作为无副作用保证。这里需要保持“仅观察”的授权承诺，与 D4 已接受的不逐次审批写操作是两个不同约束。

**建议：**把带任意 JS 条件的等待作为写语义单独建能力，或在 observe 下明确禁用 `--fn`，并让实际选用、契约、重试和审计同步。不能靠检测脚本文本里有没有 `click` 来证明纯只读。

**证据边界：**已实测 helper 的页面写入和重复执行；M12 的 observe 入口未实现，越过最终授权的部分是依据现行设计的确定推导，未伪装成已通过真实网关的攻击复现。

### 中优先级

### D03 — 64KB／90 秒的技术保证未成立，本轮已出现部分输入后失败

**依据：**[E3 长文本结论](../里程碑/M12_浏览器自动化/技研/E3_待核实事实_20261103.md:16)、[T060](../里程碑/M12_浏览器自动化/验收/测试用例.md:99)、[本轮长文本原始结果](review-20261103-1542-evidence/native/attempt-003/result.json)。

历史 E3 只实测了 9,000 字符／21,000 UTF-8 字节中文混合文本，耗时 14,269ms；“64KB 约 40 秒”是按字节速率外推，未考虑逐字符输入的字符数量差异。T060 现在又要求 70KB 分两块在同一 90 秒总预算内完成，增加了未经验证的保证。

本轮独立给固定版本 helper 传入 **65,536 个 ASCII 字符**，单次标准输入，外层期限 90 秒。实际约 **72,031ms** 返回：

```text
Failed to send: Resource temporarily unavailable (os error 35)
(after 5 retries - daemon may be busy or unresponsive)
```

专用 textarea 已有 **16,932** 个字符，未完成全量输入。它先遇到 helper 通信／执行失败，而非刚好到达外层 90 秒；不能把它概括成“仅慢了一点”或无副作用的未执行。

**边界：**复验环境为本轮透明、不抢焦点的独立 Electron 停放页面，无 WillYou 网关；根因尚未定位，不能据此断言所有前台页面都会失败。但这个实际反例足以否定当前无条件的时间与完整性保证。应验证输入字符数、分块、helper 通信预算、部分执行的回执和恢复方式；不要盲目重发整段文本。

### D04 — 大写错误码修正了格式，未修正写命令的 effectState 与退出码

**依据：**[需求退出码约定](../里程碑/M12_浏览器自动化/需求.md:200)、[T035](../里程碑/M12_浏览器自动化/验收/测试用例.md:73)、[tool-service 写调用状态](../../src/main/core/applications/tool-service.ts:165)、[错误收尾](../../src/main/core/applications/tool-service.ts:195)、[受信执行器 dispatched 边界](../../src/main/core/applications/capability-execution.ts:87)、[原生 CLI 退出码](../../native/applications/cli.mm:21)。

R0.9 要求未执行的旧引用／暂停等错误退出 2，仅已提交后的未知写结果退出 5。但现有 M11 在进入写 handler 前就设 `effect=unknown`；浏览器模块里的目标、暂停和引用检查已在执行器 `dispatched=true` 之后。普通抛出 `ApplicationError('BROWSER_PAUSED', …)` 并不会自动把状态降为 `not-started`，因此按现有路径仍可能退出 5。

需要明确哪些前置检查可由宿主证明尚未开始、怎样传递这个标记，以及真正发出网页动作后的状态边界。**这是现有代码与拟接入方式的静态冲突，未声称已运行尚不存在的浏览器模块。**

### D05 — 已复现：命令用例“生成器检查通过”可接受根本不存在的用例

**依据：**[技研称已校验](../里程碑/M12_浏览器自动化/技研/技术方案.md:221)、[生成器检查实现](../里程碑/M12_浏览器自动化/技研/命令映射/gen_command_map.py:181)、[独立反例结果](review-20261103-1542-evidence/audit-evidence/result.json)。

在私有生成器副本中，把 snapshot 的映射从真实用例改为不存在的 `T999`，生成器仍退出 0，并输出 `M12-T999`。当前检查只核对硬编码 COVERAGE 表是否非空、数量是否匹配，不读取真实测试用例文档，也不检查步骤或判据。

因此它可以证明“有一份对照表”，不能证明“命令确实有可执行用例”。参数校验也只是 Python 写的 `native_parse` 镜像，不是实际构建的原生 CLI。应收窄验证措辞，并至少校验目标编号真实存在；真实 CLI 与输入 schema 的验证保留在相应层级。

### D06 — 部分“已验证”结论超过原实验实际执行的内容

**依据：**[D6/E1 结论](../里程碑/M12_浏览器自动化/技研/D6_agent-browser核实与E1实验_20261103.md:69)、[E1 host](../里程碑/M12_浏览器自动化/技研/实验/E1_agent-browser驱动Electron/main.cjs:15)、[E1 首次连接](../里程碑/M12_浏览器自动化/技研/实验/E1_agent-browser驱动Electron/run.mjs:44)、[E3 页面](../里程碑/M12_浏览器自动化/技研/实验/E3_快照覆盖与命令行为/pages/frames.html:7)、[E3 回读](../里程碑/M12_浏览器自动化/技研/实验/E3_快照覆盖与命令行为/run.mjs:75)。

- E1 在 READY 之前就完成移入停放窗口，之后才首次连接 helper；未测试“已连接 helper 的页面移窗后会话不丢”，也未测试挂回主窗口。原文却把这件事写成已验证。
- E3 的跨源 iframe 是同一 `127.0.0.1` 不同端口，属于同站跨源，不是跨站 OOPIF。
- E3 的 iframe 输入“回读”只检查整份快照任意位置有相同文本；其他四个输入已填同一文本，不能据此证明目标 iframe 写入。E3 文档披露了未单独回读，但“全部可以／不需补强”仍过宽。

**本轮新增支持：**改用主页面 `127.0.0.1`、iframe `localhost`，CDP target list 确实出现独立 iframe 目标；使用子页面自身 input 事件的专用 postMessage 回显，读到 `frame:VERIFY-cross`。封闭 Shadow DOM 不暴露内部引用，通过内部事件回显读到 `closed:VERIFY-closed`。这支持固定版本在本轮全局 CDP 路径下的这两个场景，仍不能替代最终每页代理验证。

现有实验并非虚构；问题在于记录的验证范围应与实际相符。技术方案已新增 S1 代理门槛，这一点应保留。

### D07 — 重启后的回执查询用例仍与运行身份策略冲突

**依据：**[需求 operation get](../里程碑/M12_浏览器自动化/需求.md:334)、[技研运行范围](../里程碑/M12_浏览器自动化/技研/技术方案.md:240)、[T037](../里程碑/M12_浏览器自动化/验收/测试用例.md:75)。

T037 要求 App 重启后“同一运行仍可查到”。需求和技研却限定只能查本次运行、运行结束返回 `not-found`；退出／重启会使原运行及令牌失效。持久记录还在，不代表原调用身份还活着。

应分别约定同一运行的 CLI 断连查询、App 重启后的历史记录查看、新运行是否允许查询旧运行。不要让一个用例同时要求互斥结果。M12-D03 已明确登记为 S1 待修，没有误当已完成，这部分记录正确。

### 低优先级（设计缺项，不能写成已发生的真实产品故障）

### D09 — Cookie 导入恢复日志仍不足以证明完整回滚

**依据：**[Cookie 导入恢复方案](../里程碑/M12_浏览器自动化/技研/技术方案.md:179)、[静态反例](review-20261103-1542-evidence/audit-contracts/static-probes.json)。

“备份旧 Cookie，再按备份恢复”没有明确删除导入中已经写入、而备份原本不存在的新 name/domain/path 组合。仅恢复旧键会遗留新键。此外方案明确不锁页面 Cookie 写入，回滚可能覆盖同时发生的登录／登出。

需明确恢复目标集合、原先不存在的条目、删除补偿及页面并发策略。当前只是导入恢复算法的反例，不是已运行真实导入；不得记录为真实 Chrome／Edge 导入失败。

### D10 — Cookie 明文恢复日志的存储保护没有定义

**依据：**[分区加密说明](../里程碑/M12_浏览器自动化/技研/技术方案.md:173)、[含原值 JSON 日志](../里程碑/M12_浏览器自动化/技研/技术方案.md:179)。

恢复日志含原始会话值，尚未规定加密、文件权限、原子落盘、恢复前是否阻止 profile 使用及清理失败处理。O11 接受 Agent 可读 Cookie，不自动代表已经确认将会话值以明文恢复文件长期留在磁盘。应把它作为真实持久化路径设计，而非临时实现细节。

### D11 — 新增回执表的初始化与升级契约未补齐

**依据：**[持久化“只新增键”](../里程碑/M12_浏览器自动化/技研/技术方案.md:192)、[新增 browser_operations](../里程碑/M12_浏览器自动化/技研/技术方案.md:240)。

当前“只新增键”描述已不能完整覆盖新表；不需要迁移旧业务数据，也仍需定义新表 schema、创建时机、唯一索引、崩溃后的 accepted/running 状态恢复和七天清理。建议区分“无旧数据迁移”和“有 schema 初始化／升级”，补相应验证。

### D12 — 实验脚本退出 0／测试绿，不等于其业务结论通过

**依据：**[E1 runner](../里程碑/M12_浏览器自动化/技研/实验/E1_agent-browser驱动Electron/run.mjs:44)、[E3 runner](../里程碑/M12_浏览器自动化/技研/实验/E3_快照覆盖与命令行为/run.mjs:45)、[E2 实验测试](../里程碑/M12_浏览器自动化/技研/实验/E2_网关耗时与大结果/gateway-measure.test.ts)。

E1／E3 主要记录 helper 的 `ok` 和结果，没有把关键回读、实际命中目标或预期失败转换成统一的语义断言；脚本能把异常记进 JSON 后正常退出。E2 的大结果测试也主要采样输出。当前原始 JSON 支持若干历史观察，但后续重跑时不能只引用退出码或测试绿。

建议让记录与判据分开：先保存全部原始输出，再用明确的 checker 判断“必须成功”“预期拒绝”“实际内容一致”。本轮同样未把独立脚本退出 0 当作总通过，判定见 verification.json。
