## 问题清单

### 高：R01　MCP `env` 直接映射会改变配置语义，已实测

- 依据：[转换表](../里程碑/M13_应用Skill与MCP插件化重构/技研/MCP跨Agent转换实验_20261110.md#结论)把 `command／args／env` 列为直接映射；[转换器](../里程碑/M13_应用Skill与MCP插件化重构/技研/实验/MCP跨Agent_20261110/run3.mjs)第 51、71 行分别直接复制 env。
- 本次反例：父进程 `WY_PASS=passed-through`，MCP 配置 `env.WY_STATIC="${WY_PASS}"`。Claude 的实际 MCP 收到 `WY_STATIC=passed-through`；Codex 的实际 MCP 收到字面量 `${WY_PASS}`，即使已经传了 `env_vars=["WY_PASS"]` 也如此。两侧 CLI 退出码都是 0，MCP 均确实调用成功。
- 影响：Claude→Codex 会把变量引用变成字面文本，导致认证、路径等配置失效；反向转换也会把 Codex 中原本的字面 `${…}` 变成 Claude 的变量展开。原实验只测固定字符串 env 和同名 env_vars，没有覆盖该差异。不能用“调用成功／退出码 0”判定等价。
- 证据：[变量语义对照](证据/M13-20261110-1549/变量语义对照.json)、[Claude 完整探针输出](证据/M13-20261110-1549/claude-probe.mjs.stdout.json)、[Codex 完整探针输出](证据/M13-20261110-1549/probe.mjs.stdout.json)。保留执行驱动及哈希；这里的完整输出是本次探针直接 stdout，不是 CLI 未裁剪的原始流。
