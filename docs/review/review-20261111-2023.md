## 2. 问题清单

### 中：Q01 恢复任务仍会静默换成智能体现在的默认模型

- **依据**：[需求](../里程碑/M13_应用Skill与MCP插件化重构/需求.md)第二章“Codex `/model` 写全局默认”及补记 7；[技术方案](../里程碑/M13_应用Skill与MCP插件化重构/技研/技术方案.md)§3.4、§3.7；T064、T094：上次模型仍在允许列表时，应恢复上次模型；不在列表时才提示并使用所选智能体默认模型。
- **位置**：`prototypes/m6-codex/src/App.jsx:524`、`src/M13TaskDialogs.jsx:31–36`。对话框只检查旧模型是否存在，确认后却无条件 `agentSnapshot(agent, m13.providers)`，没有把上次模型传给恢复操作。
- **复现**：用 Codex · DeepSeek 的 Pro 新建任务 → 停止 → 编辑该智能体，保留 Pro、勾选 Flash 并把 Flash 设为默认 → 恢复原任务。恢复弹窗没有“旧模型丢失”提示，任务信息却从 Pro 变成 Flash。即使完全没有在原生 CLI 内切换过模型，这个更小的反例也成立。
- **影响**：与“沿用最后模型”的文字及用例预期冲突。上轮 N01 的终端／快照入口修复有效，但恢复模型部分尚未闭环。
- **证据**：[原始结果 resume-model](evidence/m13-20261111-2023/review-flows.json)、[恢复后截图](evidence/m13-20261111-2023/resume-model.png)。

### 中：Q02 恢复后没有重新生成插件与连接快照

- **依据**：需求“插件连接与项目使用”明确“新建或恢复的任务使用新连接”（第 130 行）；“会话生效规则”要求新建或恢复一律按最新状态加载（第 137 行）。运行中继续用旧连接只持续到该次运行结束。
- **位置**：`prototypes/m6-codex/src/App.jsx:524` 仅更新智能体、状态，展开旧任务时保留原 `pluginSnapshot`；`src/M13TaskDialogs.jsx:49` 起的会话插件页面继续读取它；`src/m13-model.mjs:555` 的删除保护也依赖这份快照。
- **复现**：任务使用“公司禅道”启动 → 停止 → 经界面新增“审核连接B”，改为全局默认 → 恢复任务 → 会话插件仍显示“公司禅道（运行中继续用这个连接）”。本轮目标项目跟随全局。
- **影响**：恢复后展示、连接占用和删除保护会依据旧连接；新安装／已停用插件也无法由这份旧快照准确表达恢复后的加载集合。
- **证据**：[原始结果 resume-connection](evidence/m13-20261111-2023/review-flows.json)、[会话插件截图](evidence/m13-20261111-2023/resume-connection.png)。

### 中：Q03 不含 Key 的导入配置仍能从首页直接进入运行中

- **依据**：技术方案 §3.1“Provider 缺认证：启动前拒绝，不交给 CLI”；T060；原型供应商详情自身也写着“填写后才能启动任务和测试模型”。
- **位置**：`prototypes/m6-codex/src/M13AgentSettings.jsx:75–76` 导入时正确设置供应商 `needKey`，但 `src/m13-model.mjs:269` 的首页可用性只检查智能体标记／工具，`src/App.jsx:382–387` 创建任务也不检查供应商缺 Key。
- **复现**：导入“不含 Key”的内置示例 → Codex · Acme 行标明“供应商需要 Key” → 首页仍可选它并启动 → 任务信息显示“运行中”。整个过程没有填写 Key。
- **影响**：错误提示与可执行动作冲突，缺认证的处理流程尚未在原型体现。本轮没有启动真实 CLI，因此这不是已经发生认证泄漏的结论。
- **证据**：[原始结果 missing-key](evidence/m13-20261111-2023/review-flows.json)、[运行中截图](evidence/m13-20261111-2023/missing-key-running.png)。

### 中：Q04 新增权限规则后，旧用例存在相反预期

1. **T055 与 T099 冲突**：T055 要求任务信息“不显示环境变量与启动参数”；T099 明确要求显示权限档位与启动参数，当前原型也显示权限参数。按现文验收，同一画面无法同时满足两条。
2. **T063 缺少请求批准的前置**：它对任意“Claude 第三方运行配置”都要求写文件弹询问。补记 8 与 T100 已允许相同配置选“完全访问”，这时不应弹逐次询问。

位置：[测试用例](../里程碑/M13_应用Skill与MCP插件化重构/验收/测试用例.md)第 130、138、163–164 行。这里不需要重新决定产品规则，应以最新补记 8 同步旧用例。

### 中：Q05 T075 的连接删除步骤无法按当前顺序完整执行

- **位置**：[测试用例](../里程碑/M13_应用Skill与MCP插件化重构/验收/测试用例.md)第 143 行。
- 前置只准备了 P1 使用 A 的运行中任务。步骤先要求“结束运行中任务再删除 A”，随后才追加“另有一个 P2 的运行中任务也用 A 启动”“结束 P1 后再尝试删除 A”。
- 如果前半段已经成功删除 A，后半段无法再建立／验证该连接的占用；如果 P2 的任务本来已存在，前置缺失，前半段“结束运行中任务后可删除”也不成立。
- 同一条还要求验证“第一个连接自动成为默认”，但前置已直接准备好两个连接，没有实际添加第一个的步骤。该断言不能仅靠既有夹具状态算完成。

### 低：Q06 权限验收还有缺项，真实上游故障不宜固定为通过判据

- **权限恢复**：T099 只检查首页改档位后旧任务信息不变，没有实际停止并恢复任务；T100 只检查新启动。映射表却将“恢复沿用原档位”列为已覆盖。应补“完全访问创建 → 停止 → 首页改请求批准 → 重启 App → 恢复旧任务 → 核对真实启动参数”的操作与预期。另须在重启后再次选择完全访问，确认首次确认标记也已持久化，而不仅是首页档位持久化。
- **开发阶段组合门槛**：需求已允许权限参数与浏览器临时沙箱、插件宿主写审批留到正式开发核对，不把它当本轮必须重跑的技研。但用例应显式落下“完全访问仍不能绕过宿主插件写审批”及与临时沙箱组合的判据，避免开发时只跑 T100 就漏掉该门槛。
- **T096 固定真实故障**：当前要求真实 SMG 的 `claude-haiku-5-5` 两次调用必定失败。研究中观察到的上游故障不是稳定测试数据；若上游恢复，正确产品会被判失败。两次失败的展示／重试语义宜用 F-MOCK 确定性验证；真实服务部分依据当次真实响应判断状态是否如实显示，保留本轮研究原结果。

### 低：Q07 现行文档仍需合并与清理少量过时引用

- 需求已明确正在补记、定稿前合并 R1.0，本轮不把保留迭代历史本身当缺陷；但在正式开发前仍须完成该动作。例如需求术语表仍将原生登录列入 Provider，技术方案现行实体已明确不属于 Provider；早期自动生成智能体等表述与补记 5 的手动新建应收敛成唯一现行口径。
- 原型说明开头页面总表（第 24 行）仍描述新建智能体的高级设置／运行说明，P0.15 后已去掉；应更新当前总表，旧描述进入历史。
- 测试用例首部仍标原型 P0.3，当前已 P0.17；T082 使用未定义的 `F-ZENTAO`，夹具表定义的是 `F-ZT`。文件目标链接本轮检查均存在，但上述语义／标识仍需统一。

## 3. 修改建议

| 问题 | 建议的最小处理与回归 |
| --- | --- |
| Q01 | 恢复决策返回显式模型：上次模型仍允许则保留，否则才选默认并提示；实际恢复回调使用该结果。保留创建快照与当前运行模型的含义，避免把所有模型都重新解释为新默认。补“任务 Pro，智能体默认改 Flash，但 Pro 仍允许”的界面回归，另按 T064 补原生会话记录解析。 |
| Q02 | 恢复开始时按当前项目、插件状态及生效连接生成本次运行快照；创建历史若要保留，单独保留，勿混作当前运行连接。补“运行中用 A → 停止 → 全局改 B → 恢复用 B”，并验证删除保护阻止 B、不再把该任务算到 A；再补停用／安装后的恢复集合。 |

| Q04 | T055 明确不显示凭据、环境变量和旧高级参数；权限的固定非敏感参数按 T099 显示。T063 明确选择“请求批准”、隔离既有授权规则；完全访问由 T100 验收。 |

| Q06 | 补齐恢复权限、确认标记跨重启、宿主审批／沙箱组合判据；将真实上游固定失败断言改为受控故障与真实结果如实显示两层。无需因此重开已获用户同意延后到开发的研究。 |
| Q07 | 按 AGENTS 定稿规则整理一份完整 R1.0 现行正文，保留旧稿与修订依据；同步当前页面总表、原型版本与夹具 ID，再核对需求→原型→方案→用例映射。 |

## 5. 风险／待确认点

- 本轮没有发现需要用户重新决定的大方向；上述明确不一致可以按已有决定修正。Codex 三档、Claude 两档、默认请求批准、原生登录继承环境、原生 `/model` 不回写智能体等均沿用最新决定，不重开讨论。

- 本轮未调用真实 Provider、禅道、系统钥匙串或日常 CLI；未重新执行全部历史技研实验，未启动生产开发。完整安全隔离与真实 App 结果不在本轮已证明范围。此次检查覆盖当前主要资料与关键流程，但任意错误组合、全部页面视觉状态可能未穷尽。
