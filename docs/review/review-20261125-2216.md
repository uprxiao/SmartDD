## 3. 修改建议（与问题逐一对应）

| 编号 | 最小改动与验收补充 |
| --- | --- |
| H01 | 手动请求为独立的持久回执判定：同身份请求优先读取原结果，忙碌等已决定结果也须稳定保存，但不得增加虚构的运行/输入记录；另一次用户明确运行才使用新请求身份。A29/A31/A39 加首次忙碌、占用释放、重启、编辑/删除后原请求仍返回原判定，对照新请求正常派发；自动重复到期仍允许原约定的非到期。 |
| H02 | 区分新建计划无历史预览和既有计划按 planId/修订读真实领取账的编辑/详情预览。A08 对相同日程、不同领取史的两计划核前三个实际未来时点与保存/派发一致，特别检查时钟回拨或跟随时区。 |
| H03 | 明确关页受理与持久化逻辑删除、一次关闭历史、新 activeId、物理资源异步结算的关系；对写盘失败给真实回执，不把尚未成功提交当持久接受。B04/B07 补真正受理、实际清理尚未完成时独立异常重启，核旧标签不复活、关闭历史一次、合法新开有新身份。保持 v1 兼容边界，若确需改变持久合同沿原流程处理。 |
| H04 | 成功 ready 才同时等待真实页面就绪及有效展示确认；失败/取消按实际业务结果单独结算，区分壳内错误视图与成功网页显示，不能因缺 UI ack 一直等待。B04/B06 补快失败早于前景确认、取消/壳失效仍准确显示失败或原回执；后台维持原行为。 |
| H05 | A04–A08、A28 明细逐层：固定日期、隔月、闰年、DST、精确 +1ms 用可控 U/I 全覆；打包 A 级用实际可达时点和真实 UI 预览/保存/到期，需真实系统时区和休眠仍归 S。测试精度以该层适当证据达成；若某产品判据确实必须以固定日期真实系统验证，明确独立可校时时钟的设备环境，不把注入时钟当自然到期。 |
| H06 | B12.1 拆两段：主窗可见时 T2 为前景，T1 定时正常执行且不抢 T2；主窗隐藏/最小化时保持其他应用系统焦点，T1 仍正常执行；恢复后核对原 T2 和实际回执。两段都列为同一 B12.1 必须通过。 |
| M01 | 正式结果明确由 run 关联所属工作完成链推导本次对用户的最终父回复（如果实际无最终父回复则诚实展示可用输出）；根回合、子结果、所属续接和随后普通回合分开。A41/A49 以不同唯一标记实际验证最终回复及历史摘要，用户不能看到无关后续回合。 |
| M02 | A39/A41/A50/A51/A52 补充上述未覆盖状态、可读归档与真正删除的差异、无产物时空态、应用内通知先到详情及系统通知精确原回合/请求的独立断言。无真实任务/回合时定位到运行记录或计划错误原因；不虚构任务。保持 P1.1 的布局，不需要新视觉。 |
| M03 | 明确普通提示词文件引用的现行表示、实际工作目录的解析／接受行为、失效提示及必要持久引用，复用已有校验。A23 补具名引用文件与失效情形，不额外引入新附件产品功能或改动已确认的定时任务表单。 |
| M04 | 明确 native 实例代次与 helper 资源所有权交接和清理的一致性；B10/B11 补相同逻辑标签切换 profile/恢复原生实例时旧收尾晚到仍不影响新实例。 |
| M05 | T 和 B10.2 区别正常壳 reload、壳或页渲染进程异常而原生对象仍在、真实原生对象销毁三类；核真实状态、已有请求回执、恢复后旧文档状态与合法新执行，避免承诺异常后未保存表单一定保留。 |
| M06 | B08/B09 将已有兼容面涉及的原项目/Agent 导入导出、插件附件另存、语音录制快捷键及系统焦点复位明确挂入相应检查；使用独立合成数据、沿用原实际权限和已有系统验收，不新增功能。 |
