## 2. 问题清单

### 高优先级

### R01 — 浏览器小写错误码无法直接穿过现有原生 CLI

**依据：**[需求 R02.7](../里程碑/M12_浏览器自动化/需求.md:180)、[技术方案错误码映射](../里程碑/M12_浏览器自动化/技研/技术方案.md:124)、[原生 CLI 错误校验](../../native/applications/cli.mm:21)、[ApplicationError 类型](../../src/shared/applications.ts:75)。

需求和 Skill 依赖 `browser_paused`、`browser_stale_ref`、`browser_timeout` 等小写错误码，但 `ApplicationErrorCode` 目前只包含大写网关错误；原生 CLI 的 `refused()` 明确只接受 `^[A-Z][A-Z0-9_]{0,63}$`。如果按技研把浏览器异常直接交给现有错误通道，小写码会被 CLI 替换为 `INVALID_RESPONSE`，Agent 的暂停和旧引用恢复规则都失效。

把错误放进成功结果的 `data` 也需要明确协议：现有 v2 信封 `status` 固定为 `ok`，不能默认把“HTTP/传输成功”当作“浏览器动作成功”。当前设计没有指定采用哪条路径以及影响哪些公共契约。

### R02 — `exec` 拒绝清单遗漏可改变 CDP 目标的 `connect`

**依据：**[需求 R02.11](../里程碑/M12_浏览器自动化/需求.md:205)、[技术方案拒绝清单](../里程碑/M12_浏览器自动化/技研/技术方案.md:135)、[T039](../里程碑/M12_浏览器自动化/验收/测试用例.md:77)。固定版本的[上游命令解析源码](https://github.com/vercel-labs/agent-browser/blob/v0.27.3/cli/src/commands.rs#L959)把 `connect <port|url>` 解析为带 `cdpPort`／`cdpUrl` 的 `launch` 请求。

当前清单只拒绝若干参数、`chat/dashboard/install/doctor` 和顶层 `tab`，因此 `exec --command "connect <其他端口>"` 不会命中这份清单，却会产生改变连接目标的请求。这与 P2“不能绕开受管页面”的目的冲突。上游另有 `batch`，只检查最外层首词也没有覆盖嵌套命令；[固定版本参考](https://github.com/vercel-labs/agent-browser/blob/v0.27.3/skill-data/core/references/commands.md#L20)可见其批量调用形态。

**证据边界：**已确认策略漏项及上游解析语义，没有尝试连接用户日常浏览器，也没有声称已复现实际越权。必须验证执行器和 CDP 代理能否在下层阻止目标替换；不能把“代理只列一个目标”当成全部证明。

### R03 — 跨任务授权申请会被通用目标解析提前拒绝

**依据：**[技术方案目标解析与授权](../里程碑/M12_浏览器自动化/技研/技术方案.md:205)、[需求 R06.3](../里程碑/M12_浏览器自动化/需求.md:321)、[T095](../里程碑/M12_浏览器自动化/验收/测试用例.md:145)。

目标解析第 2 步规定：只要带 `--task`，本次运行必须已经持有目标任务授权，否则 `SCOPE_DENIED`。但首次获取授权的 `access request --task T2` 正是尚未授权的请求。按此顺序实现，它到不了弹窗。同一规则也没有排除显式传入调用方自身任务 ID 的情况，会把合法的 `--task 自己` 当作需要授权。

应区分“申请授权”和“使用授权”，不能让申请依赖已存在的授权。

### 中优先级

### R04 — “未知写结果按操作编号可查询”尚无可调用的闭环

**依据：**[需求 R06.2](../里程碑/M12_浏览器自动化/需求.md:312)、[技研回执复用](../里程碑/M12_浏览器自动化/技研/技术方案.md:218)、[T037](../里程碑/M12_浏览器自动化/验收/测试用例.md:75)、[T094](../里程碑/M12_浏览器自动化/验收/测试用例.md:144)、[网关接收方法](../../src/main/core/applications/cli-gateway.ts:103)、[CLI 断连输出](../../native/applications/cli.mm:63)。

方案只写“复用 M11 调用记录”。现有 CLI 只提供发现和调用；映射表没有查询浏览器回执的能力。调用账记录状态不等于能返回完整业务结果。尤其断连分支调用 `failure()` 时没有输出操作编号，Agent 可能连需要查询的 ID 都拿不到。M11 也明确存在 `REPLAY_UNAVAILABLE` 分支，不能据此推导浏览器已有持久回执查询。

这不是要求对外部网页实现“恰好一次”。需要能关联原调用、查询已知状态，并诚实返回 `unknown`，同时阻止自动重发。

### R05 — 命令映射仍沿用 Orca 的裸布尔开关和错误的发现命令

**依据：**[映射表](../里程碑/M12_浏览器自动化/技研/命令映射/映射表.generated.md:49)、[CLI 参数解析](../../native/applications/cli.mm:40)、[T030](../里程碑/M12_浏览器自动化/验收/测试用例.md:68)、[T115](../里程碑/M12_浏览器自动化/验收/测试用例.md:165)。

`willyou-app` 每个 `--字段` 都要求紧随一个值，但需求和表格保留 `--focus`、`--reset`、`--secure`、`--httpOnly`、`--mobile` 等裸开关；例如 T115 的 `tab switch --focus` 会在进入业务前失败。T030 的 `willyou-app browser --list` 也不成立：现有发现形态是全局 `willyou-app --list`，并不支持应用内的裸 `--list`。

生成器目前只验证命令段和保留参数，不验证这些最终示例能否被原生 CLI 解析，容易出现“映射检查通过，Agent 照说明运行失败”。

### R06 — 文本数字的转换位置晚于现有 JSON 契约校验

**依据：**[技术方案文本契约](../里程碑/M12_浏览器自动化/技研/技术方案.md:203)、[T031](../里程碑/M12_浏览器自动化/验收/测试用例.md:69)、[第一次输入校验](../../src/main/core/applications/tool-service.ts:149)、[执行器再次校验](../../src/main/core/applications/capability-execution.ts:80)。

设计要求文本字段契约统一为 `string`，同时承诺 `--value 123` 即使解析成数字也能转为字符串写入。但网关在调用模块前就执行输入 schema 校验，受信执行器还会再次校验。如果只在浏览器模块转换，数字已被拒绝，T031 无法通过。需要把转换位置、外层输入契约和内部规范化契约一起设计。

### R07 — 暂停方案没有落实“已排队命令立即拒绝”

**依据：**[需求 R07.6](../里程碑/M12_浏览器自动化/需求.md:363)、[技研队列](../里程碑/M12_浏览器自动化/技研/技术方案.md:118)、[技研暂停](../里程碑/M12_浏览器自动化/技研/技术方案.md:235)、[T113](../里程碑/M12_浏览器自动化/验收/测试用例.md:163)。

需求明确要求“排队中和之后到达”的命令立即返回 `browser_paused`；技研只规定入队前检查、运行中 wait 监听暂停。暂停之前已经入队、尚未执行的写命令没有被取消或在出队时重查的规定。照稿可能在用户暂停后继续提交剩余点击。T113 也没明确先排入多条命令，再暂停并核对后续业务事件为零。

### R08 — 原型重新加载后，任务独立 profile 被恢复成项目 profile

**依据：**[原型序列化与恢复](../../prototypes/m6-codex/src/browser-prototype-model.mjs:253)、[独立 profile 创建](../../prototypes/m6-codex/src/browser-prototype-model.mjs:303)、[T079](../里程碑/M12_浏览器自动化/验收/测试用例.md:125)。

`serialize()` 保存真实 profile ID（如 `profile-…`），`restore()` 却只保留字面值 `'task'`，其他值全部转成 `'project'`。纯模型探针复现：

```text
新建独立 profile → 用于标签 → serialize → restore
before: profile-mw0cryrj-2
after:  project
```

当前是合成原型，不会泄漏真实登录态；但它会展示错误的身份恢复行为，不能作为 T079 或 C1 的确认依据。原型现有 26 个模型测试的历史通过记录没有覆盖这条组合路径。

### R09 — 原型“推荐”顺序并非项目内真实最近访问顺序

**依据：**[需求 R01.11](../里程碑/M12_浏览器自动化/需求.md:145)、[recentSites](../../prototypes/m6-codex/src/browser-prototype-model.mjs:189)、[App 调用顺序](../../prototypes/m6-codex/src/App.jsx:366)、[T025](../里程碑/M12_浏览器自动化/验收/测试用例.md:61)。

算法按任务数组、标签倒序和标签历史遍历，没有访问时间。T1 先访问 A、B，T2 后访问 C，得到 `B、A、C`，而 T025 要求 `C、B、A`。关闭标签会丢掉其历史，重启只恢复当前地址也会进一步改变推荐。原型说明已披露“生产另存访问记录”，但没有指出跨任务时间排序本身不成立；现有入口原型通过记录不能证明这一业务规则。

### R10 — 唯一需求文档保留了互相冲突的现行参数和数值

**依据：**[R04.2](../里程碑/M12_浏览器自动化/需求.md:249)、[R05.7](../里程碑/M12_浏览器自动化/需求.md:298)、[R06.5](../里程碑/M12_浏览器自动化/需求.md:339)、[映射统一规则](../里程碑/M12_浏览器自动化/技研/命令映射/README.md:13)、[M12-D02 已实现规则](../里程碑/M12_浏览器自动化/验收/执行与缺陷记录.md:17)。

历史修订记录可以保留，但当前正文应只有一个可执行口径。否则实现、Skill 和测试很容易各自选了不同版本。

### 低优先级（缺少说明／验证，不等于已经发生产品故障）

### R11 — profile ID 的项目及任务权限校验没有具体设计

**依据：**[项目隔离与 C1](../里程碑/M12_浏览器自动化/需求.md:283)、[profile 全局注册表](../里程碑/M12_浏览器自动化/技研/技术方案.md:152)、[目标解析](../里程碑/M12_浏览器自动化/技研/技术方案.md:205)。

目标解析检查了 `task/page`，没有规定 `--profile` 的所有者检查。`profile list/create/delete/clone` 有的甚至不以页面为目标。需要明确：能列出和使用哪些 profile；能否克隆其他项目 profile；同项目另一任务的独立账号是否需要 P4；删除被其他任务引用的 profile 如何处理。仅靠分区名称白名单只能证明“已登记”，不能证明“属于调用方”。这是隔离需求的重要设计缺项，尚不能据此断言实际实现已越权。

### R12 — E1 没有验证最终选定的每页 CDP 代理和多页停放组合

**依据：**[E1 方法边界](../里程碑/M12_浏览器自动化/技研/D6_agent-browser核实与E1实验_20261103.md:30)、[代理方案](../里程碑/M12_浏览器自动化/技研/技术方案.md:53)、[S1](../里程碑/M12_浏览器自动化/技研/技术方案.md:266)。

E1 使用全局调试端口，未实现每页代理，而且直接能看到宿主目标。它证明 agent-browser 能驱动 Electron 页面，未证明最终代理下的跨源 iframe/OOPIF、会话重连、整页截图、取消和多页同时停放仍成立。S1 应把这一组合设成可判定的门槛；若不通过，先修代理再批量生成其余能力，不把 E1 单独的绿测外推为完整架构已验证。

### R13 — Cookie 导入“失败不破坏已有 Cookie”缺少中途失败设计

**依据：**[需求 R06.4](../里程碑/M12_浏览器自动化/需求.md:329)、[技研 cookie-import](../里程碑/M12_浏览器自动化/技研/技术方案.md:60)、[T080–T082](../里程碑/M12_浏览器自动化/验收/测试用例.md:126)。

### R14 — 用例覆盖声明比实际步骤具体程度更强

**依据：**[T051](../里程碑/M12_浏览器自动化/验收/测试用例.md:90)、[T060](../里程碑/M12_浏览器自动化/验收/测试用例.md:99)、[T095](../里程碑/M12_浏览器自动化/验收/测试用例.md:145)、[T111](../里程碑/M12_浏览器自动化/验收/测试用例.md:161)、[覆盖声明](../里程碑/M12_浏览器自动化/验收/测试用例.md:221)。

- T051 没有显式覆盖“切换标签后旧引用失效”和不同页面中同名 `@eN` 不互用。

### R15 — 打包哈希需区分上游校验与重新签名后的交付校验

**依据：**[可执行文件来源](../里程碑/M12_浏览器自动化/技研/技术方案.md:101)、[重新签名与 SHA 检查](../里程碑/M12_浏览器自动化/技研/技术方案.md:255)、[T140](../里程碑/M12_浏览器自动化/验收/测试用例.md:196)。

### R16 — 进度摘要和证据保留仍有过时／不完整处

**依据：**[M12 README](../里程碑/M12_浏览器自动化/README.md:29)、[执行记录开头](../里程碑/M12_浏览器自动化/验收/执行与缺陷记录.md:3)、[需求池 F25](../需求池.md:787)、[原型 R0.8 红测说明](../里程碑/M12_浏览器自动化/原型/原型说明与变更.md:137)、[M11 当前状态](../里程碑/M11_应用接入标准化/README.md:5)。

M12 README 仍把 M11 T29 写为尚未执行；M11 当前剩余项已是 T12/T21/T22/T28。需求池 F25 仍写 R0.3／P1 待验证；执行记录开头仍写用例未编制，而当前已有 119 条。它们会使后续 Agent 错判前置和下一步。

原型记录也明确承认 R0.8 首次失败的原始结果文件被覆盖，只留下失败文字记录。应保留这个证据缺口，后续使用 attempt 独立路径；不能把后来重跑通过反写成初次执行通过。现有 prototype `source-sha256.txt` 是完整性线索，用户正式确认前仍需可恢复源码快照或 Git 提交，哈希本身不能恢复内容。

### R17 — 独立 OAuth 子窗口尚无页面归属和控制方案

**依据：**[需求 R01.6](../里程碑/M12_浏览器自动化/需求.md:121)、[页面模型](../里程碑/M12_浏览器自动化/技研/技术方案.md:69)、[T013](../里程碑/M12_浏览器自动化/验收/测试用例.md:49)。

需求承诺依赖 opener 的窗口作为独立子窗口保留；架构却只描述按任务持有的 WebContentsView 和单页代理。需要补充子窗口与任务／profile 的绑定、是否进入 tab list、Agent 如何观察／操作、停止任务及删除 profile 时怎样处理、关闭后 OAuth 如何回调原页。T013 目前只验证“打开了子窗口”，不足以证明登录闭环和清理。
