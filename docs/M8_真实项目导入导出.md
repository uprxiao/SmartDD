# M8：真实项目导入、导出需求

更新日期：2026-10-16。需求来源：[需求池 F21](需求池.md)。状态：阶段主题和基本范围已确认；本文为独立需求初稿，详细规则与原型待细化，未批准正式开发。日程和应用版本未指定。

本文是 M8 具体需求的维护入口；原型、技术调研和交付验收均引用本文的需求项与版本，不在其他文件另行维护相冲突的范围。

## 1. 目标与范围

用户已有真实项目，希望导出一份文件，在大版本发布后的测试环境中导入，恢复项目与资源配置，减少手工重复录入，并继续开展真实任务验证。

已确定：项目基本信息、数据库配置、服务器配置、多个代码目录及相关路径、项目与资源之间的关联。数据库实际数据、源码文件、业务文档和任务历史是否打包尚未确定；这些不能由“项目导出”自动推定。

## 2. 需求项与业务流程

| 编号 | 需求 | 已明确的行为／约束 |
| --- | --- | --- |
| M8-R01 | 导出已有项目 | 从已登记项目生成一份可复用文件，涵盖本阶段确定的配置及关联；输出内容应可核对 |
| M8-R02 | 导入项目文件 | 读取和校验文件，将项目、目录、数据库、服务器及关联恢复到当前应用；不能只导入孤立资源 |
| M8-R03 | 处理引用与环境差异 | 导入后能核对本机路径、资源归属和缺少配置；重名、重复导入、AI 配置引用及路径映射规则须在评审前确定 |
| M8-R04 | 凭据处理 | 沿用既有“配置导出默认不含密钥”；导入后明确哪些资源还需补充凭据，补充／复用方式待设计 |
| M8-R05 | 导入结果与失败恢复 | 明确成功、失败和未完成的项目；文件损坏、格式版本不支持、部分数据错误等不能表现为全部成功；写入原子性和回滚方案由技研落实 |
| M8-R06 | 真实项目测试复用 | 同一份文件可用于后续版本测试；导入项目后能通过真实页面新建任务并使用正确的资源配置 |

核心流程：选择已有项目 → 导出文件 → 在目标测试环境选择文件 → 校验并处理差异 → 导入 → 核对项目与资源 → 补齐必要配置 → 发起实际项目任务与资源验证。

建议在原型中提供导入预览及结果摘要；具体入口、是否支持批量、重名时新建／合并／覆盖的选择尚未确认，不能提前作为已批准行为实现。

## 3. 数据与状态要求

按现有项目模型梳理字段，不另建一套资源定义：

| 对象 | 已知字段方向 | 需要确认的处理 |
| --- | --- | --- |
| 项目 | 名称、别名、说明、默认 AI 配置、规则引用 | 本地 ID 重建、重名、外部配置引用缺失 |
| 目录 | 标签、路径、默认目录、版本控制类型 | 多目录关联、路径变更、不存在／不可用目录 |
| 数据库 | 环境、类型、主机、端口、库名／schema、账号、别名、访问级别、默认标记 | 敏感项与凭据引用、支持类型和字段兼容 |
| 服务器 | 环境、主机、端口、账号、认证方式、别名、应用／日志路径、备注 | 凭据补充、密钥路径与本机映射 |
| 导出文件 | 格式版本、来源信息、项目与资源记录 | 文件结构、兼容策略、完整性校验、容量限制 |

页面应能区分待选择、校验中、待处理差异、导入／导出中、成功、失败与取消；具体呈现以本阶段原型定稿。导入成功与数据库／SSH 连接可用是不同结果，须分别展示和验证。

## 4. 验收目标与待定项

验收至少覆盖：完整配置往返、多目录与资源关联、中文和空格路径、重复导入、缺少路径／凭据／AI 配置、损坏文件、不支持版本、写入失败、重启后保留，以及真实页面任务与资源使用。具体前置条件、操作、预期、实际结果和证据写入 M8 交付验收文档，不在本文预填通过。

评审前须确定：单项目或批量、文件格式与向前／向后兼容、导入策略、字段明细、路径与凭据处理、是否包含配置以外的数据、目标平台和真实验收项目。当前记录既有范围，未将这些未决项当作已确认规则。
