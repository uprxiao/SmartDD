文件模块不依赖 BrowserService、浏览器技术选型或 Owl 原生能力。HTML 源码归文件模块；隔离 HTML 文档预览可以作为文件专项能力，但需要单独的受限内容宿主验证；带地址导航的 HTML／localhost 页面归浏览器。PDF 等文档预览同样独立验证，不因使用网页渲染技术就自动并入完整浏览器开发。

需求入口：[需求池 F22-A／F22-B](需求池.md)。文件模块的具体需求维护在 [M9 需求文档](里程碑/M9_文件浏览工作区/需求.md)，F22-A 方案为其技研输入；浏览器尚无 M 需求文档。共同参考：[用户截图](里程碑/M9_文件浏览工作区/调研/证据/codex-file-browser-reference-20261016.png)、[REA 证据索引](design/f22/证据索引.md)。详细证据分别见[文件实现](里程碑/M9_文件浏览工作区/调研/Codex文件工作区实现证据.md)、[浏览器宿主](design/f22/Codex浏览器宿主实现证据.md)及[文件类型路由补查](里程碑/M9_文件浏览工作区/调研/文件类型路由补充证据.md)。

调研表明 SmartDD 可实现两类能力。当前完成的是静态研究与迁移文档，功能尚未开发，运行时等价及跨平台表现仍待验证；本次拆分不触发 M7 扩围、功能实现或发布。当前安排为 M8 项目导入导出 → M9 文件工作区完整复刻 → M10 三方接入（禅道／邮件）→ M11 定时任务；Jenkins 留后续；浏览器不插入这四个阶段，详见 [里程碑规划](里程碑/README.md)。具体上线版本和日程待定。
