## 2. M8：真实项目导入、导出

**目的**：测试新版本时，直接导入保存好的真实项目，减少重复配置，能够继续走实际项目任务和资源验证流程。

已确定范围：

- 导出已有项目的基本信息、数据库配置、服务器配置、多个代码目录及相关路径信息。
- 将项目与资源关联保存在同一份可导入文件中，导入后能在项目页面找到、核对并使用。
- 同一份文件可在后续大版本发布后的隔离测试环境中重复使用。

详细设计时补齐：文件格式与版本兼容、重名／重复导入、导入预览与失败处理、路径映射、资源引用及凭据补充／复用。沿用 PRD 的配置导出默认不含密钥约定；数据库实际数据、源码文件、文档和任务历史是否打包尚未确定，不将“数据库配置”误写为已确认的数据库备份恢复。

验收方向：真实项目导出 → 新版本测试环境导入 → 核对项目、数据库、服务器和路径 → 补齐必要配置 → 通过真实页面发起任务并验证资源使用。仅能解析导入文件，不算此需求完成。

详细需求依据：[PRD §8.8](SmartDD_V0.2_PRD.md)。

## 3. M9：文件浏览工作区完整复刻

**用户目标**：完美复刻此前 ChatGPT／Codex 中的整个文件浏览区域。实施时以已提供截图、已完成 REA 证据及后续实际操作核对为依据，完整对齐功能、视觉细节和微交互。

范围覆盖：文件树与筛选、多目录切换、文件标签与预览／固定语义、路径面包屑、不同文件类型的查看、文档／源码切换、文件工具栏、系统外开、面板调整、文件变化与状态恢复。已在该区域定位的编辑、保存、自动保存、dirty 关闭及冲突处理也按完整功能目标梳理，不能自行将最终交付缩成只读预览。

视觉和交互逐项核对布局、字体、颜色、图标、间距、边框、圆角、阴影、长文本、滚动、焦点、快捷键、菜单、悬停／选中及浅／深色。原型与实际 App 同步验收，未核实的功能或状态先补查；不能把证据缺口当作自动删减范围的依据。

中央任务工作区继续使用现有终端，关闭文件不结束任务。既有明确排除的 Git 管理等业务不因界面复刻被引入。F20 的业务文档管理与 F22-B 完整浏览器仍单独规划；PDF 和隔离 HTML 文档预览按文件区域实际功能核对，不要求先开发完整浏览器。

准备工作：按真实参考形成逐功能、逐状态的对照矩阵；补齐未确认的类型／编辑行为、快捷键和视觉证据；确定实现与测试方案。可以分步实现，但 M9 最终验收按完整文件工作区目标，不以中间子集完成宣称完全一致。确有无法等价的功能或资源须明确记录差异。

已有输入：[F22-A 迁移方案](F22A_文件模块_REA调研与迁移方案.md)、[文件实现证据](design/f22/Codex文件工作区实现证据.md)、[类型路由补查](design/f22/文件类型路由补充证据.md)、[参考截图](design/f22/codex-file-browser-reference-20261016.png)。

## 4. M10：定时任务

承接 F16，将目前的入口和样式推进为实际任务调度能力。已记录的范围包括任务计划（项目／代码目录、AI 配置、任务说明、执行时间／周期与时区）、新建／编辑／暂停／恢复／删除、下次运行时间，以及每次执行的状态、对应任务和结果。

详细设计时明确周期类型、应用退出／电脑睡眠／错过执行时间的处理、重叠执行、重试与通知。复用现有项目、CLI、Skill 和终端体系；当前未决定后台常驻或应用退出后仍运行，不把这些策略写成已实现能力。

验收方向：创建计划 → 按约定时间触发 → 正确选择项目与 AI 配置 → 运行任务 → 查看记录与失败原因；暂停、恢复、重启和错过时间等行为与最终设计一致。详细需求依据：[PRD §8.3](SmartDD_V0.2_PRD.md)。

## 5. M11：邮件、禅道、Jenkins

三类集成都纳入 M11，沿用 F19 对 Claude Code 插件机制的参考方向；具体插件格式、兼容性及内部交付顺序待设计。

| 集成 | 已记录的目标 | 待细化内容 |
| --- | --- | --- |
| 邮件 | 收发邮件，提取需求／待办并关联项目；日报／周报生成与发送沿用 F19 | 邮箱协议与认证、收件范围、附件、收件人、草稿与发送时机、与 M10 的联动 |
| 禅道 | 拉取需求／Bug、关联任务、跟踪并回写结果 | 系统版本、接口、字段和状态映射、现有 Skill 适配、重复处理 |
| Jenkins | 查看 Job／构建结果，按项目衔接构建及部署流程 | 认证、Job／参数映射、SVN revision、执行边界及失败恢复 |

验收方向：三类连接均能配置和按项目使用，各自完成已确定的业务闭环，目标与结果可核对，失败和重试可追溯。此规划不触发连接外部系统、发送邮件、禅道回写或构建部署。

详细需求依据：[PRD §8.6](SmartDD_V0.2_PRD.md)。
