# M7：Typeless 语音输入接入

关联需求：F17-A；自有语音模块已拆至 [F17-B 后续需求](F17B_自有语音输入与本机词库.md)。

## 1. 本阶段目标

按本地 Yoda 的现成方式，默认唤起用户已安装的 Typeless，让 SmartDD 日常开发立即具备语音输入入口。

- 页面上提供麦克风小按钮，点击触发 Typeless。
- 支持可配置的全局快捷键，在其他应用中也可直接唤起 Typeless 语音输入。
- 不再要求用户使用 Option 单键；实际转写、整理、输入和词库能力由 Typeless 提供。

“本机 Typeless”指使用这台 Mac 已安装的客户端，不代表其识别过程离线。用户继续使用自己的 Typeless 登录、权限与服务；SmartDD 不接管这些账号，也不保存其音频或词库。

M7 是里程碑编号，不对应固定的应用 tag。沿用 `feature/0.0.1`；当前请求是梳理范围，不因文档定稿自动触发开发、提交或发版。

## 2. 功能范围

| 编号 | 功能 | 约定 |
| --- | --- | --- |
| M7-F01 | 页面语音按钮 | 新建任务输入区提供麦克风按钮，沿用 M6 视觉；点击前恢复输入框焦点和选区。运行中任务的终端工具栏提供同一入口，触发前聚焦当前终端 |
| M7-F02 | 唤起本机 Typeless | 检查安装情况；未运行时后台启动，已运行时复用；识别合适的听写快捷键并模拟触发，避免抢走输入位置 |
| M7-F03 | 全局快捷键 | SmartDD 运行时，在任意应用按已配置的组合键调用同一唤起服务；不切换到 SmartDD，不移动其他应用的输入焦点；支持设置、禁用和冲突反馈 |
| M7-F04 | 最小设置 | 显示语音提供方为 Typeless、检测结果、实际触发快捷键及来源；提供重新检测和必要的手动覆盖。SmartDD 的全局唤起键与转发给 Typeless 的键明确区分 |
| M7-F05 | 反馈与恢复 | 未安装、启动失败、权限不足、快捷键无法解析或注册失败均提示；防重复触发。仅显示“正在唤起／已触发／触发失败”，未获取真实状态时不显示“正在录音／已转写” |

不做自有录音浮层、音频采集、ASR、模型整理、模型下载、模型服务端、词库 CRUD、自动纠错学习、语音历史、多端同步。Typeless 本身已有的这些能力照常使用，不算 SmartDD 自研交付。

平台范围先为 macOS。Windows／Linux 语音接入未纳入本阶段；已有这些平台的安装包不代表它们支持本功能。

## 3. 两条使用流程

### 3.1 页面按钮

`定位 SmartDD 输入框或终端 → 点击麦克风 → 恢复目标焦点／选区 → 后台唤起 Typeless → 开始口述 → 按 Typeless 的交互结束 → 文字进入原输入位置`

首页写入后保留为草稿，由用户提交；终端保留原有输入和粘贴语义，SmartDD 不额外发 Enter。终端中实际运行的 CLI 对换行和粘贴的处理必须做真实验收。

录音结束、取消和转写进度沿用 Typeless 自身交互。若使用可点击起止的听写快捷键，再次触发的实际行为应实测，不能把“执行快捷键脚本成功”当成“录音已开始／结束”。

### 3.2 全局快捷键

`在任意应用放好光标 → 按 SmartDD 全局唤起键 → 后台触发 Typeless → 使用 Typeless 完成输入`

这是后台可用的全局快捷键，不是只在 SmartDD 窗口内处理的键盘事件。主窗口隐藏但进程仍运行时有效；退出 SmartDD 后该应用注册的快捷键释放，Typeless 自己的快捷键按其规则继续有效。

默认选用非 Option 单键的普通组合键，实施时选定并验证冲突；设置可修改。唤起键应与 Typeless 被模拟的快捷键不同，避免抢占或递归触发；模拟前处理真实修饰键尚未释放的情况，防止意外形成另一个组合键。

## 4. Yoda 已核实的实现与适配点

核查的是同级本地源码，不以网上版本替代。

| 源文件 | 已有行为 | SmartDD 处理 |
| --- | --- | --- |
| `../yoda/src/renderer/app/composer-prompt-input.tsx` | 麦克风按钮、输入框焦点和选区恢复、触发中禁用、失败反馈 | 复用流程，适配当前输入框／终端及样式 |
| `../yoda/src/main/core/app/voice-input.ts` | 检测 Typeless，`open -gj` 后台启动，读取快捷键，`osascript` 模拟按键 | 适配 typed RPC、错误返回和生命周期，保留来源说明 |
| `../yoda/src/main/core/app/voice-input-shortcut.ts` | 读取多种设置字段，解析键名和键码；缺失时以 `Fn+Space` 为回退 | 以本机版本有效设置为准；回退值仅是候选，不保证适配所有版本 |
| `../yoda/src/main/core/app/voice-input-shortcut.test.ts` | 快捷键解析和优先级用例 | 保留有意义的边界测试，补 SmartDD 需要的错误与冲突行为 |

在本次检查的 Yoda 语音链路中，没有看到独立注册全局唤起键的实现；M7-F03 需要在 SmartDD 补齐，可优先使用 Electron 现成的全局快捷键机制。不要把页面按钮支持误写成已经满足“任何地方按键唤起”。

适配时特别核对：

- Yoda 解析器把某些 `askAnythingMode` 字段当作 hands-free 候选，还可能回退到 push-to-talk；不能无条件照搬为普通听写入口。只选本机已验证的语音输入模式，必要时手工指定。
- 固定等待 200 ms 是 Yoda 的启动实现，不是首次启动必定就绪的保证；检查首次启动和已运行两种场景，避免无声失败或重复转发。
- 全局入口不复用页面入口的“聚焦 SmartDD 输入框”动作。公共部分是后台唤起服务，焦点规则由入口决定。
- 设置只读取快捷键相关字段，不复制 Typeless 的账号、令牌或历史；本阶段不修改其配置。
- 页面按钮表示触发入口，SmartDD 未接收实际录音状态时，不据本地布尔值画出假的录音进度。

保留轻量的语音提供方调用边界，本次只实现 Typeless；后续 F17-B 可以接入同样的按钮与快捷键。不提前制作多提供方设置页或完整插件系统。
