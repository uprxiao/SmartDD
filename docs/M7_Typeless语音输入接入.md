## 1. 目标与交付边界

让用户在日常开发中点击麦克风，或在其他应用中按组合键，使用已安装的 Typeless 语音输入。优先复用本地 Yoda 已有实现，再适配 SmartDD 的首页、终端、设置及生命周期。

- 前期依据：Yoda 源码调研、M6 原型上的 M7 交互，以及本文。当前执行生产实现与必要验收，不自动提交或发布。
- M7 正式实现：Mac 上的 Typeless 检测／后台唤起、页面按钮、全局快捷键、设置及错误恢复。
- Typeless 承担录音、结束／取消、识别、文字整理、插入和词库；沿用用户自己的账号与服务。安装在本机不代表离线识别。
- SmartDD 不采集音频、不直接调用模型、不读取其 token 或语音历史，语音模块不另存转写正文（插入任务后的草稿／提交按现有任务流程保存）；自己的录音、ASR、整理和词库属于 [F17-B](F17B_自有语音输入与本机词库.md)。
- 首轮真实验收为 macOS arm64；macOS x64 须单独验证才能声明支持。Windows/Linux 保留既有业务，语音页显示暂不支持，不注册键、不执行 macOS 命令。

参考与事实依据：[Yoda 唤起调研](M7_Yoda语音唤起调研.md)。该文区分源码事实、只读解析验证及尚未完成的真实触发验证。

## 3. 业务流程

### 3.1 首页和试用输入框

1. 用户放好光标或选中文字。鼠标按下 Mic 时不让按钮夺走选区；键盘操作保留最近一次输入选区。
2. 捕获目标与本次页面标识，恢复输入框焦点和合法的选区范围。
3. 共用服务验证平台、开关、安装、权限与听写键，再启动／触发 Typeless。
4. 触发中按钮显示忙碌并禁用，重复请求不排队。
5. 唤起成功不弹提示卡。用户再次点击同一 Mic 结束本次听写，结果由 Typeless 输入回原输入框；Typeless 自身的结束／取消方式也保留。仅收到 `shortcut-sent` 不能证明识别或回填成功。失败时展示具体原因及恢复入口。
6. 用户自行编辑并提交草稿。SmartDD 不捕获正文、不做第二次粘贴、不额外提交。

用户切走页面、打开其他窗口或改变目标后，不在异步回调中强制拉回焦点。原型提供“演示文字回填”验证选区与草稿，正式版删掉该按钮。

### 3.2 运行中的终端

用户于 2026-10-16 确认按 Codex 的会话布局收敛：取消右侧横向任务标签与重复面包屑，窗口顶部仅显示当前会话标题。右上角更多菜单保留结束／启动或恢复、主题切换；任务信息及新建入口仍可达。左侧项目下的会话为主要切换入口，搜索及项目任务列表仍可打开会话。切换不结束进程，也不丢弃各自内存中的输入与终端回滚记录；不增加终端全文持久化。

运行终端不再设置麦克风按钮或独立语音窗口。用户先聚焦当前 CLI，再按已保存且启用的 SmartDD 全局快捷键，沿用 §3.3 的原生前台目标检查。Typeless 自身的录音界面由它管理；SmartDD 不显示唤起中／成功浮卡。

终端历史文字选区不是可编辑选区，输入遵循 CLI 的光标和粘贴规则。保留 bracketed paste、中文、换行以及原有回车处理。SmartDD 不额外发 Enter；这不保证所有 CLI 对 Typeless 多行粘贴都不提交，仍需分别验收 CC / Codex。停止后先通过更多菜单启动／恢复，再聚焦终端使用语音。

### 3.3 全局唤起

1. 用户在目标应用放好光标，按已保存的 SmartDD 全局组合键。
2. 主进程处理回调；不创建、显示或聚焦 SmartDD 窗口，不调用页面的 focus 方法。
3. 等真实修饰键释放，再调用同一后台服务转发 Typeless 听写键。长按不连发；无法确认释放则取消并反馈，不强制释放用户正在按的键。
4. Typeless 完成输入，文字进入当前输入目标。正常唤起无 SmartDD 提示卡；前台失败展示错误卡，后台失败使用不抢焦点的系统通知；语音设置保留最近错误。
5. 应用隐藏时有效；真正退出后释放键。启动失败、权限不足或快捷键冲突不应影响项目和终端使用。

浏览器原型没有系统级快捷键，用独立的“模拟外部应用输入框”演示落点；这不算真实跨应用验收。

### 3.4 听写模式及结束方式

本机配置的明确听写候选为 RightOption；Fn+Space 同时出现在 askAnything 与旧 hands-free 字段。不能把 Yoda 的默认回退直接作为通用答案。

正式实现先做 G1 真机验证：候选必须能满足点击式听写；按一下开始、结束／取消由 Typeless 当前交互完成。只识别到按住说话或字段含义矛盾时，显示“待确认听写键”，让用户在 Typeless 确认后手工指定并试用，不擅自更改其配置。M7 不要求用户按 Option；原有 Typeless 快捷键不被 SmartDD 接管。

2026-10-26 用户补充确认：首页 App 的同一 Mic 应点一次开始、再点一次结束，并将文字输入原框；本机 RightOption 是点按开始／点按结束。此确认不改变 Typeless 承担录音、识别和文字输入的边界，不增加 App 自行录音、读取转写或二次粘贴。当前 M9 回归已发现实际 App 按钮识别后未回填，原型／实现与系统复验尚未闭环，见 [P09 红测](里程碑/M9_文件浏览工作区/验收/证据/P09_真实语音入口未回填红测_20261026.json)。终端继续按 §3.2 使用全局快捷键，不增加终端 Mic。

## 4. 设置与数据

建议默认：语音按钮启用、提供方 Typeless、听写键自动读取、全局唤起关闭。全局键候选 `Command+Shift+Space`，用户可录制或编辑；正式注册以系统结果为准，不能预先声称无冲突。原型按此默认展示，待用户审阅。

复用 `src/shared/app-settings.ts` / `SettingsStore` / SQLite `app_settings`，增加 `voice` key；不新建音频表、模型配置表或词库表。

| 保存字段 | 类型／默认 | 约束 |
| --- | --- | --- |
| provider | `typeless` | 当前唯一值 |
| enabled | boolean / true | 关闭后按钮可解释不可用，全局注册释放 |
| globalEnabled | boolean / false | 不改变 Typeless 自己的键 |
| globalShortcut | string / `Command+Shift+Space` | 规范化后必须为支持的组合键；拒绝单独 Option、现有应用保留键及与转发键相同的键 |
| shortcutOverride | string 或 null / null | null 表示只读探测；只接受已解析的键名，禁止原始脚本 |

派生状态只存在运行时：是否安装／运行、权限状态、候选模式／来源、实际注册成功的全局键、最近错误、in-flight 请求。重新检测不覆盖用户的手工指定。

保存前校验全部字段；注册新全局键成功后持久化，再释放旧键；持久化失败则撤销新注册并保留旧配置。串行处理保存、重置、启停；同键更新不重复注册。启动时注册失败可保留用户意图，但 UI 必须显示“未生效”和错误，不能显示可用。重置和 generic appSettings.update 不得绕过这个事务，统一进入 VoiceService。

原型仅内存保存：跨页面保留，刷新复位。未保存的试用按钮禁用，撤销恢复保存值。原型校验已知保留键和两种键相同；不能探测系统或其他软件占用。

## 5. 状态、文案和错误处理

| 状态／错误 | 页面表现 | 恢复 |
| --- | --- | --- |
| idle | Mic 可用；标题说明 Typeless | 点击或按全局键 |
| launching / dispatching | 页面按钮短暂忙碌，不弹浮卡；全局键静默处理 | 完成、失败或超时退出忙碌 |
| shortcut-sent | 静默成功，不弹浮卡 | 由 Typeless 显示真实录音状态 |
| NOT_INSTALLED | 未找到 Typeless | 安装指引 → 完成首次设置 → 重新检测 |
| ACCESSIBILITY_REQUIRED | 需要辅助功能权限 | 错误提示中的“打开辅助功能设置”直达 macOS 对应页面 → 回来复检；不自动授予权限 |
| AUTOMATION_DENIED | 未允许必要的系统自动化 | System Events 授权指引；仅适用于保留 AppleScript 的实现 |
| SHORTCUT_UNRESOLVED / MODE_UNVERIFIED | 请确认 Typeless 听写键 | 检查其设置或手动覆盖，再试用 |
| GLOBAL_CONFLICT / SAME_SHORTCUT | 快捷键不可用或与转发键相同 | 换键；保留原设置 |
| MODIFIERS_HELD | 请松开快捷键后再试 | 本次不转发，不继续自动重试 |
| TARGET_CHANGED / TASK_STOPPED | 当前输入位置已变化／任务已停止 | 在新目标重试或恢复任务 |
| LAUNCH_FAILED / TIMEOUT / TRIGGER_FAILED | 暂时无法唤起 | 明确失败阶段，手动打开 Typeless 后重试 |
| UNSUPPORTED_PLATFORM / DISABLED | 暂不支持／已关闭 | 说明范围或进入设置 |

错误不清空已有输入，不把全部错误归因于权限。信息中不含本机完整配置、令牌、输入文本或录音。短暂忙碌只覆盖启动与按键转发，不把录音全过程当成 SmartDD 内部状态。触发成功后用户可以再次主动触发，但具体开始／结束行为以 G1 验证为准。

### 6.2 RPC 与事件约定

- `voice.inspect()`：返回 supported、installed、running、accessibility、candidates、shortcut、source、settings、effectiveGlobalShortcut、registrationError 和 lastError；读取权限状态时不自动弹申请框。
- `voice.trigger({ origin: 'home' | 'terminal' | 'settings', requestId, ptyId? })`：严格校验输入、单次请求锁及目标有效性；成功返回 `{ ok: true, phase: 'shortcut-sent' }`，失败返回稳定错误码；`voice.cancel(requestId)` 取消尚未发送的请求。global 入口仅由主进程调用 service，不允许 renderer 冒充外部窗口目标。terminal RPC 参数保留兼容校验，当前界面没有终端按钮调用者。
- `voice.updateSettings(patch)` / `voice.resetSettings()`：完成校验、注册及持久化事务，返回保存值和实际生效状态。
- `voice.openSetupGuide(kind)`：只允许固定的安装／权限目的地；用户点击权限错误提示中的“打开辅助功能设置”，或说明弹窗中的“打开系统设置”后，才调用 Electron 的辅助功能申请并打开 macOS 对应设置。检测和触发不会自动弹申请框；平台不支持时返回稳定错误。其他配置错误继续进入应用内语音设置；系统页面打开失败时保留错误并给出手动路径。
- `voice.setShortcutRecording(active)`：录制前临时注销本应用已注册的语音全局键并暂停菜单快捷键，让系统把按键交给输入框；录制按物理键位识别，捕获有效组合后立即结束页面录制。取消、Esc、失焦、离页、超时均恢复原键，最长 60 秒自动解除。恢复时重新检查注册冲突，并等待物理键松开才接受下一次全局唤起，不自动重放按键；录制期间禁止并发保存或唤起语音。
- `voiceStatusChanged`：供设置页刷新有效状态；事件不把发送脚本成功升级为录音成功。

沿用现有 typed RPC 的校验和错误机制；renderer 只传受限参数。后台全局调用不依赖窗口存在。

### 6.3 Typeless 适配

安装查找优先固定 bundle id `now.typeless.desktop`，再按应用名回退；不要把任意用户字符串拼进 shell。配置只读候选路径 `~/Library/Application Support/{Typeless,typeless,now.typeless.desktop}/app-settings.json`，限制文件大小、解析异常并按实际路径去重。只提取快捷键白名单，缓存不含原配置正文。

优先使用人工确认的覆盖值；自动候选优先明确 dictation 字段，保留来源与语义冲突。askAnything 不作为普通听写自动回退。找不到／无法表达点击模式时提示，不能发送一个猜测的键。

复用 `open -gj` 的后台启动思路，实际通过原生桥的 NSWorkspace 实现不激活启动；设置启动超时与固定路径回退。已运行与冷启动分别处理；用有上限的就绪检查替代“200 ms 一定够”的假定，进程检测只能表示启动状态。首次登录、更新或初始权限未完成时引导用户先手动设置。

### 6.4 系统按键与全局键

复用 Yoda 的键码表、短按时长与后台唤起／选区保留思路，来源记入 NOTICE。Yoda 脚本仅完成编译检查，未以它证明真实触发通过。为实现物理修饰键释放检测和发送前焦点复核，已采用 G2 备选的最小 macOS 按键桥；真实触发和授权仍按 G1–G3 分项验收。

全局注册采用现有 Electron 的 `globalShortcut.register/unregister`，实际生效键由 VoiceService 跟踪。其他应用冲突以 register 返回值处理，不扫描其他应用的系统热键。

全局回调没有 key-up 信号。按键适配层必须确认物理修饰键释放后发送，最长等待 1500 ms，超时取消；同一时刻一条请求、不排队。当前使用 `native/voice/bridge.m` 最小 macOS 按键桥：用 CoreGraphics 读取实体键状态并发送固定键码事件，构建期分别编译 arm64/x64 随包携带，不要求用户安装 Python、Homebrew 或编译器。桥接器分别检查辅助功能与事件发送权限，使用受限 JSON 参数和固定键码，不执行任意脚本。Mac 构建检查随包二进制及其架构；当前 arm64 已构建，x64 未在本机验证。

发送前再检查目标未变；按下和释放必须成对，失败也清理已由本次请求按下的键。不无条件合成释放用户仍按住的键。禁止相同的全局键与转发键，防递归；忽略并发回调、长按重复事件及退出中的请求。

### 6.5 焦点与安装后 App 的系统授权

- 页面捕获输入目标与任务／路由标识，主进程仅确认前台窗口条件，不读取输入正文。转发前目标已失效则取消；发送后不使用 Yoda 的无条件 finally focus。
- 外部入口不激活 SmartDD；不检查或提取外部文档内容。若启动期间目标切换，取消待转发请求，由用户在新位置重试。
- **这里的系统授权是什么**：macOS 允许安装后的 SmartDD 模拟按键所需的“辅助功能”授权；沿用 Yoda 的脚本方案时，可能还需要允许控制 System Events 的“自动化”授权。麦克风授权由 Typeless 使用，M7 的 SmartDD 不负责录音。
- **为何要安装后再测**：开发进程与安装后的 SmartDD 可能具有不同的授权身份，不能把开发运行成功当作安装后也已授权。验收首次提示、拒绝后的错误反馈、授权后重试及升级后的行为。这里讨论的是运行时系统授权，与 Apple 开发者签名／公证分别处理。
- SmartDD 只申请最终按键方案需要的授权；不在原型阶段要求用户配置权限。真正授权由用户在 macOS 系统界面操作。
- 模拟键完成只证明请求发送；真实录音、转写及插入需要人工观察。没有 Typeless 官方状态接口时不轮询其私人数据库或日志获取文本。
- 发布前照 AGENTS.md 完整验证；若新增原生桥，构建产物与架构纳入已有 Mac 包检查。无签名预发布仍按既有安装限制说明，不能把开发运行权限当安装包权限。
