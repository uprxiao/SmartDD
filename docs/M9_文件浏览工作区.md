更新日期：2026-10-16。需求来源：[需求池 F22-A](需求池.md)。状态：用户已确认完整复刻目标；本文为独立需求初稿，已有静态技研，实际行为矩阵、原型及用例待补齐，未批准正式开发。

## 1. 目标与边界

完整、细粒度复刻用户此前提供的 ChatGPT／Codex 文件浏览区域，覆盖功能、视觉和微交互。以[用户截图](design/f22/codex-file-browser-reference-20261016.png)、实际操作和已定位代码为参考。静态代码证明实现结构，不能证明全部运行状态已核对。

中央任务工作区保持现有终端，文件标签不替代任务会话。Git 管理、完整内置浏览器 F22-B、文档业务管理 F20 仍按已有范围单独处理。分步实现可先完成只读浏览，但最终交付不能自行删掉实际参考中的文件编辑、保存等功能。

## 3. 业务与数据规则

- 目录来源为项目已登记目录或任务实际 cwd；任务目录与后来修改的项目配置发生差异时明确展示，不静默改根。
- 文件身份包含目录根与相对路径，不能用文件名去重；主进程负责解析可信目录及权限，前端不能任意指定外部路径。
- 文件树、标签、文档草稿、watch 与终端分别维护生命周期；关闭文件不调用结束任务的动作。
- 文件读取、搜索及保存中的旧异步结果不能覆盖新文件或新根状态；外部修改和本地草稿冲突有明确处理。
- 原型需要表达 loading、ready、dirty、saving、conflict、missing、unreadable、too-large 等适用状态，不只画正常预览页。
- HTML 源码、隔离文档预览和带地址导航的浏览器是不同能力。文档沙箱可能属于文件区域，需独立验证；完整浏览器不作为 M9 前置条件。

具体默认根、跨任务状态共享、格式支持、快捷键、保存策略和恢复字段，按实际参考及 SmartDD 数据映射逐项定稿。技术阈值不能直接照抄某个源码常量后当作已批准产品规则。
