# 发送与失败处理

发件身份确认和具体邮件审批是两项独立条件。项目页面绑定的 SMTP 发件地址必须与来源账号目录规则一致；确认记录随绑定或修订变化失效。枚举、Token、密码、连接参数都由宿主处理，不由 Agent 自报。

- mail.send.prepare 冻结明确的草稿修订和内容摘要，不提交 SMTP。先读取返回的审阅资源；未经宿主观察到的明确用户授权，mail.send.execute 会被拒绝。
- mail.send.execute 只对已有意图执行一次。授权只属于具体收件人、内容、附件及原运行，不允许复用来发送另一封邮件。
- mail.send.get 始终读取同一项目既有结果；mail.send.cancel 只停止未提交动作或等待，已提交邮件不能撤回。
- 结果 unknown 不代表失败。保留 operation、intentId 和 executionId，核对实际记录，不换入口重试，不重建意图规避防重。
- 身份确认失效时回到项目应用页重新确认；邮箱明确不一致时需要改选匹配连接，不能通过确认覆盖。

能力的具体调用名称以 SKILL.md 的当前入口表为准；不要猜测另一个入口或改用旧契约名称。
